# Метки и вложенные циклы

Возьмите таблицу умножения 5×5: строки с 1 по 5, столбцы с 1 по 5, а в
клетке на пересечении строки `i` и столбца `j` стоит произведение `i*j`.
Хранить таблицу не нужно — произведение каждой клетки программа вычисляет на
месте. Две задачи по такой таблице:

- найти первую клетку, где произведение оканчивается цифрой 6, и сразу
  остановиться: остальные клетки ответа уже не изменят;
- отобрать строки, в которых ни одно произведение не оканчивается нулём.
  Как только в строке нашлось такое произведение, остаток строки смотреть
  незачем.

Чтобы обойти таблицу, нужен цикл по строкам, а внутри него — цикл по
столбцам. Из внутреннего цикла нужно уметь закончить оба цикла или только
текущую строку. Один из способов — метка.

Понадобятся цикл `for` из трёх частей и обычные `break` и `continue` в одном
цикле (урок 3.5), `switch` (урок 3.3), `if` (урок 3.1) и остаток от деления
`%` (урок 2.10). Последнюю цифру числа даёт остаток от деления на 10:
`16 % 10` равно 6.

К концу урока вы сможете:

- для обычных `break` и `continue` и для тех же инструкций с меткой назвать

## Цикл внутри цикла

Тело цикла `for` может содержать любые инструкции, в том числе ещё один
`for`. Такой цикл называют **вложенным**. Внешний цикл перебирает строки со
счётчиком `i`, внутренний — столбцы со счётчиком `j`.

Главное в этой конструкции: внутренний `for` — обычная инструкция тела
внешнего цикла. Каждый раз, когда выполняется тело внешнего цикла, программа
доходит до внутреннего `for` и выполняет его с самого начала:

1. инструкция инициализации `j := 1` выполняется снова, и `j` опять равна 1;
2. внутренний цикл проходит столбцы, пока его условие истинно;
3. когда условие стало ложным, выполняются инструкции внешнего тела, стоящие
   после внутреннего цикла;
4. затем выполняется завершающая инструкция внешнего цикла `i++` и
   проверяется его условие.

Переменная `j` объявлена в заголовке внутреннего цикла и видна только в нём
(урок 3.5). В каждой строке внутренний цикл объявляет `j` заново, и
начинается она с 1, а не с того значения, на котором остановилась прошлая
строка.

Программа ниже печатает одну строку вывода на каждую строку таблицы. Сначала
идёт `i=` с номером строки, затем каждая посещённая клетка в виде
«строка×столбец», события разделены чертой `|`. В конце строки вывода стоит
отметка, которую печатает инструкция внешнего тела после внутреннего цикла.
Прежде чем смотреть вывод, скажите: сколько раз выполнится тело внутреннего
цикла, с какой клетки начнётся вторая строка вывода и сколько раз напечатается
отметка после внутреннего цикла.

```go

### Example: `01-rows-cols`

Источник: `examples/01-rows-cols/`

```go
package main

import "fmt"

func main() {
	rows := 3
	cols := 4
	for i := 1; i <= rows; i++ {
		fmt.Printf("i=%d: ", i)
		for j := 1; j <= cols; j++ {
			fmt.Printf("%d×%d | ", i, j)
		}
		fmt.Println("после внутреннего")
	}
	fmt.Println("main: после циклов")
}

```
```

Тело внутреннего цикла выполнилось 12 раз: 3 строки по 4 столбца. Вторая
строка вывода начинается с клетки 2×1: внутренний цикл запустился заново, и
`j := 1` сработала ещё раз. Отметка напечаталась трижды — по одному разу на
строку таблицы, после того как внутренний цикл закончился. Порядок обхода —
по строкам: сначала все клетки первой строки слева направо, потом второй.
Меток в этой программе нет, и они ей не нужны: каждый цикл заканчивается
сам, когда его условие становится ложным.

## Нулевые границы

Если внешний цикл не выполнил ни одного прохода, внутренний не начнётся ни
разу: программа просто до него не дойдёт. Если ноль проходов у внутреннего
цикла, внешний всё равно проходит все строки. В каждой строке выполняются
инструкция инициализации внутреннего цикла и первая проверка его условия;
условие сразу ложно, и выполнение переходит к инструкциям после внутреннего
цикла.

Функция `report` в программе ниже считает, сколько раз началось тело
внешнего цикла и сколько раз — тело внутреннего. Прежде чем смотреть вывод,
назовите оба числа для каждого из трёх вызовов.

```go

### Example: `02-zero-bounds`

Источник: `examples/02-zero-bounds/`

```go
package main

import "fmt"

// report считает, сколько раз началось тело внешнего цикла (строки)
// и сколько раз — тело внутреннего (клетки).
func report(rows int, cols int) {
	started := 0
	cells := 0
	for i := 1; i <= rows; i++ {
		started++
		for j := 1; j <= cols; j++ {
			cells++
		}
	}
	fmt.Printf("rows=%d, cols=%d: начато строк %d, клеток %d\n", rows, cols, started, cells)
}

func main() {
	report(0, 3)
	report(3, 0)
	report(2, 3)
}

```
```

При нуле строк условие `i <= rows` ложно уже при первой проверке: `1 <= 0` —
ложь. При нуле столбцов каждая из трёх строк начинается, но клеток в ней нет.
В общем случае клеток `rows*cols`, и ноль любого из двух множителей даёт ноль
клеток. Оба случая встретятся в упражнении.

## Какой цикл покидает break

Во вложенных циклах правила урока 3.5 уточняются так:

- обычный `break` завершает **самый внутренний** `for` или `switch`, внутри
  которого стоит, и программа переходит к инструкции после него. Если это
  цикл, его завершающая инструкция не выполняется;
- обычный `continue` обрывает текущий проход **самого внутреннего** цикла
  `for`. Оставшиеся инструкции его тела пропускаются, завершающая инструкция
  этого цикла выполняется, затем проверяется его условие.

`break` завершает ещё и `select` — инструкцию из модуля о конкурентности;
здесь она не встретится.

Во вложенных циклах самый внутренний цикл — внутренний. Значит, обычные
`break` и `continue` в его теле внешний цикл не трогают. После `break`
выполняются инструкции внешнего тела, стоящие после внутреннего цикла, а
затем, как обычно, завершающая инструкция внешнего цикла.

Чтобы видеть, когда выполняется завершающая инструкция внешнего цикла, в
следующих программах она записана как присваивание `i = nextRow(i)`. Функция
`nextRow` возвращает `i + 1`, то есть делает то же, что `i++`, но перед этим
печатает новое значение. Если в выводе есть запись `nextRow`, завершающая
инструкция внешнего цикла выполнилась.

В программе ниже обычный `continue` срабатывает в клетке 1×2, а обычный
`break` — в клетке 2×2. Прежде чем смотреть вывод, для строк 1 и 2 скажите:
какие клетки напечатаются, будет ли отметка после внутреннего цикла, будет ли
запись `nextRow` и дойдёт ли обход до строки 3.

```go

### Example: `03-plain-jumps`

Источник: `examples/03-plain-jumps/`

```go
package main

import "fmt"

// nextRow вызывается завершающей инструкцией внешнего цикла. Она печатает
// новое значение i и возвращает его — так видно, что инструкция выполнилась.
func nextRow(i int) int {
	fmt.Printf("nextRow: i = %d\n", i+1)
	return i + 1
}

func main() {
	for i := 1; i <= 3; i = nextRow(i) {
		fmt.Printf("i=%d: ", i)
		for j := 1; j <= 3; j++ {
			if i == 1 && j == 2 {
				fmt.Printf("continue | ")
				continue
			}
			if i == 2 && j == 2 {
				fmt.Printf("break | ")
				break
			}
			fmt.Printf("%d×%d | ", i, j)
		}
		fmt.Printf("после внутреннего | ")
	}
	fmt.Println("main: после циклов")
}

```
```

`continue` в клетке 1×2 пропустил только печать этой клетки: завершающая
инструкция `j++` внутреннего цикла выполнилась, и клетка 1×3 напечаталась.
`break` в клетке 2×2 завершил внутренний цикл: клетка 2×3 не проверялась, а
`j++` не выполнилась. Внешний цикл при этом продолжил работу: отработала
инструкция после внутреннего цикла, затем `nextRow`, и строка 3 прошла
целиком.

## break внутри switch

`switch` — тоже инструкция, которую завершает `break`. Если `break` стоит в
`case`, а сам `switch` — в теле цикла, самой внутренней оказывается `switch`.
`break` завершит только её, и выполнение продолжится с инструкции после
`switch` в том же теле цикла. Цикл не остановится.

У `continue` правило другое: `switch` он не учитывает и действует только на
циклы. `continue` внутри `case` обрывает текущий проход ближайшего цикла
`for` и пропускает инструкции после `switch`.

Тело `case` и так заканчивает `switch`: в следующий `case` выполнение не
переходит (урок 3.3). Поэтому `break` последней строкой `case` ничего не
меняет. Полезен он, чтобы закончить `case` раньше, например внутри `if`.
Частая ошибка — ставить его, чтобы остановить цикл.

Прежде чем смотреть вывод, для каждого `n` от 1 до 5 скажите, какие строки
напечатает тело цикла и что программа напечатает последним.

```go

### Example: `04-switch-in-loop`

Источник: `examples/04-switch-in-loop/`

```go
package main

import "fmt"

func main() {
	for n := 1; n <= 5; n++ {
		switch n {
		case 2:
			fmt.Printf("n=%d: continue\n", n)
			continue
		case 4:
			fmt.Printf("n=%d: break\n", n)
			break
		}
		fmt.Printf("n=%d: после switch\n", n)
	}
	fmt.Println("main: после цикла")
}

```
```

При `n`, равном 2, `continue` пропустил печать после `switch` и перешёл к
следующему проходу цикла. При `n`, равном 4, `break` закончил только
`switch`: печать после него выполнилась, и цикл дошёл до 5. Обычным `break`
остановить цикл изнутри `switch` нельзя. Для этого у цикла должно быть имя.

## Метка — имя инструкции

**Метка** — идентификатор с двоеточием перед инструкцией, например `Outer:`
перед `for`. Она даёт инструкции имя. `break` или `continue` с этим именем
говорит, на какую из охватывающих инструкций он действует. **Охватывающая**
инструкция — та, внутри которой стоит `break` или `continue`, на любой
глубине вложенности. Имя метки обычно называет работу цикла: `Search`,
`Rows`.

`gofmt` ставит метку на отдельной строке, на один отступ левее помеченной
инструкции. Поэтому метка цикла, стоящего прямо в теле функции, прижата к
левому краю.

`break Outer` завершает инструкцию с меткой `Outer`, как бы глубоко он ни
стоял. Все циклы внутри неё заканчиваются вместе с ней. Завершающие
инструкции не выполняются ни у внутренних циклов, ни у самого помеченного,
его условие больше не проверяется, и программа переходит к инструкции после
помеченной. Метка у `break` должна стоять на охватывающем `for` или
`switch` (или `select`).

Программа ниже — тот же обход 3×3 без обычных переходов: внешний цикл помечен
меткой `Outer`, а в клетке 2×2 стоит `break Outer`. Прежде чем смотреть
вывод, скажите, что из этого напечатается после `break Outer`: отметка после
внутреннего цикла, запись `nextRow`, клетки строки 3, последняя строка `main`.

```go

### Example: `05-break-outer`

Источник: `examples/05-break-outer/`

```go
package main

import "fmt"

// nextRow вызывается завершающей инструкцией внешнего цикла. Она печатает
// новое значение i и возвращает его — так видно, что инструкция выполнилась.
func nextRow(i int) int {
	fmt.Printf("nextRow: i = %d\n", i+1)
	return i + 1
}

func main() {
Outer:
	for i := 1; i <= 3; i = nextRow(i) {
		fmt.Printf("i=%d: ", i)
		for j := 1; j <= 3; j++ {
			if i == 2 && j == 2 {
				fmt.Printf("break Outer | ")
				break Outer
			}
			fmt.Printf("%d×%d | ", i, j)
		}
		fmt.Printf("после внутреннего | ")
	}
	fmt.Println("main: после циклов")
}

```
```

После `break Outer` сразу напечаталась последняя строка программы. Не
выполнились ни `j++`, ни инструкция после внутреннего цикла, ни `nextRow`, ни
проверка условия внешнего цикла, и строки 3 в выводе нет.

Каждую метку должна использовать хотя бы одна инструкция. В программе ниже
внешний цикл помечен, а внутри стоит обычный `break`. Соберётся ли она?

```go
@broken unused-label
```

Не соберётся: `label Outer defined and not used` — метка объявлена, но не
используется. Ремонт зависит от замысла. Если нужно закончить только
внутренний цикл, метку убирают. Если оба цикла, пишут `break Outer`.

Метка видна во всём теле функции, а не только в своём блоке. Переменная
устроена иначе (урок 2.3): она видна до конца своего блока, одноимённая
переменная во вложенном блоке законна и затеняет внешнюю, а второе
объявление того же одного имени в том же блоке (ещё один `var x` или
`x :=`) не собирается.

Программа ниже ищет в таблице 3×3 первую клетку с произведением 4, а затем
первую клетку с произведением 6. Второй поиск скопирован с первого вместе с
меткой: оба внешних цикла помечены именем `Search`, и каждый `break Search`
записан внутри своего цикла. Соберётся ли программа? Почему? Ответьте до
сообщения, исходя из того, где действует метка.

```go
@broken duplicate-label
```

Не соберётся. Первое сообщение — `label Search already defined`: метка с
этим именем уже объявлена, а дальше в той же строке компилятор называет
место первой `Search`. Разные циклы не помогают: область метки не
ограничена блоком цикла, это всё тело `main`. Поэтому обе метки объявлены в
одной области, как два одиночных объявления одного имени в одном блоке.

Следом компилятор сообщает `invalid break label Search` о `break` во втором
поиске. Имя `Search` в этом `break` компилятор отнёс к первой метке, а метка
у `break` должна стоять на охватывающем цикле. Первый цикл этот `break` не
охватывает. Это следствие повторной метки, а не отдельная ошибка в коде.

Ремонт по замыслу. Второму поиску метка нужна: без неё `break` закончит
только внутренний цикл, и поиск пойдёт дальше по строкам. Поэтому вторую
метку переименовывают, например в `SearchSix`, и то же имя пишут в `break`
второго поиска. Убрать метку можно, только если она не нужна: например,
если бы второй поиск обходил одну строку и хватало обычного `break`.

Метка останавливает цикл и изнутри `switch`. Чтобы `case 4` остановил цикл,
цикл помечают, а в `case` пишут `break` с этой меткой. Прежде чем смотреть
вывод, скажите, какие строки вывода программы из раздела «break внутри
switch» останутся, а какие исчезнут.

```go

### Example: `06-switch-label`

Источник: `examples/06-switch-label/`

```go

import "fmt"

func main() {
Numbers:
	for n := 1; n <= 5; n++ {

		case 2:

`case 2` остался прежним: метка ему не нужна, он и так действует на цикл.

## continue с меткой

`continue Outer` обрывает текущий проход цикла с меткой `Outer` и переходит к
его следующему проходу. По шагам:

1. оставшиеся инструкции тела внутреннего цикла и оставшиеся клетки строки
   пропускаются, `j++` не выполняется;
2. инструкции внешнего тела после внутреннего цикла тоже пропускаются;
3. выполняется завершающая инструкция внешнего цикла, затем проверяется его
   условие;
4. если условие истинно, тело внешнего цикла начинается снова, доходит до
   внутреннего `for`, и `j := 1` выполняется заново.

Метка у `continue` должна стоять на охватывающем цикле `for`. На `switch` она
стоять не может: `continue` работает только с циклами.

Программа ниже — тот же помеченный обход, но в клетке 2×2 стоит
`continue Outer`.
Прежде чем смотреть вывод, скажите, что напечатается в строке 2 после
`continue Outer`, будет ли запись `nextRow` и с какой клетки начнётся
строка 3.

```go

### Example: `07-continue-outer`

Источник: `examples/07-continue-outer/`

```go
package main

import "fmt"

// nextRow вызывается завершающей инструкцией внешнего цикла. Она печатает
// новое значение i и возвращает его — так видно, что инструкция выполнилась.
func nextRow(i int) int {
	fmt.Printf("nextRow: i = %d\n", i+1)
	return i + 1
}

func main() {
Outer:
	for i := 1; i <= 3; i = nextRow(i) {
		fmt.Printf("i=%d: ", i)
		for j := 1; j <= 3; j++ {
			if i == 2 && j == 2 {
				fmt.Printf("continue Outer | ")
				continue Outer
			}
			fmt.Printf("%d×%d | ", i, j)
		}
		fmt.Printf("после внутреннего | ")
	}
	fmt.Println("main: после циклов")
}

```
```

После `continue Outer` клетка 2×3 и инструкция после внутреннего цикла
пропущены, а `nextRow` выполнилась: при `continue` завершающая инструкция
внешнего цикла срабатывает, как в конце обычного прохода. Строка 3 началась с
клетки 3×1 — `j := 1` выполнилась заново. Сравните с `break Outer`: там не
было ни `nextRow`, ни строки 3.

Четыре инструкции во внутреннем цикле, если внешний помечен `Outer`:

| Инструкция | Что заканчивается | Что выполняется следующим |
|---|---|---|
| `continue` | текущий проход внутреннего цикла | `j++`, затем условие внутреннего цикла |
| `break` | весь внутренний цикл | инструкция внешнего тела после внутреннего цикла |
| `continue Outer` | текущий проход внешнего цикла | завершающая инструкция внешнего цикла, затем его условие |
| `break Outer` | весь внешний цикл | инструкция после внешнего цикла |

## Где метку поставить нельзя

Метка видна во всей функции, но это не разрешение перейти к ней откуда
угодно. `break` и `continue` с меткой должны быть **записаны внутри**
помеченной инструкции — между её фигурными скобками. Это правило о месте в
тексте программы, а не о том, что происходит при запуске: компилятор
проверяет его до запуска, по исходному коду. Метка на соседнем цикле, то есть
на цикле, внутри которого `break` не записан, не подходит.

В программе ниже первый цикл помечен меткой `First`, а `break First` записан
в теле второго цикла, который идёт после первого, а не внутри него.
Замысел такой: второй цикл печатает свои номера и останавливается, когда `j`
становится равной 2. Прежде чем смотреть сообщение, скажите, соберётся ли
программа, и если нет — какая правка сохранит этот замысел.

```go
@broken sibling-label
```

Не соберётся: `invalid break label First`. Инструкция `break First` записана
в теле второго цикла, а не между скобками цикла `First`, и компилятор
отказывает, не запуская программу. Ремонт по замыслу: чтобы остановить второй
цикл, хватит обычного `break` — самый внутренний цикл для него как раз
второй. Если метка всё-таки нужна, её ставят на второй цикл и пишут `break`
с этой меткой.

Вторая частая ошибка — `continue` с меткой на `switch`. Замысел программы
ниже: для чётного `n` пропустить печать и перейти к следующему `n`. Для этого
помечен `switch` меткой `Choice`. Прежде чем смотреть сообщение, скажите,
соберётся ли программа, и если нет — какая правка сохранит замысел.

```go
@broken continue-switch
```

Не соберётся: `invalid continue label Choice`. Метка у `continue` должна
называть цикл `for`, а `Choice` называет `switch`. Ремонт — обычный
`continue`: он пропускает `switch` и продолжает цикл, так что печать для
чётного `n` не выполнится. Если бы циклов было два и продолжить нужно было
внешний, метку поставили бы на внешний цикл.

## Поиск: break с меткой или return

Первая задача урока — найти первую по строкам клетку, где произведение
оканчивается цифрой `digit`. Когда клетка найдена, ответ готов, и оставшиеся
клетки проверять незачем. Оба цикла сразу останавливают две инструкции:

- `break Search` завершает помеченный внешний цикл. Выполнение продолжается
  после циклов в той же функции, поэтому находку сохраняют в переменной,
  объявленной до циклов;
- `return` завершает всю функцию и сразу отдаёт результат вызывающему коду.
  Инструкции функции после циклов при находке не выполняются.

Обычный `break` здесь ошибка: он закончит только внутренний цикл, внешний
перейдёт к следующей строке, и находка в следующих строках перезапишет
первую. `continue Search` тоже не годится: он перейдёт к следующей строке
и продолжит поиск.

В программе ниже обе функции ищут одно и то же и считают проверенные клетки.
`withBreak` печатает счётчик после циклов. `withReturn` печатает его в момент
находки, перед `return`, а если ничего не нашла — после циклов. Прежде чем
смотреть вывод, для цифры 6 в таблице 5×5 назовите находку, число проверенных
клеток и строки, которые напечатает каждая функция. Затем ответьте на те же
вопросы для цифры 7 в таблице 3×3.

```go

### Example: `08-search`

Источник: `examples/08-search/`

```go
package main

import "fmt"

// withBreak ищет по строкам первую клетку, где произведение оканчивается
// цифрой digit, и останавливает оба цикла инструкцией break Search.
func withBreak(rows int, cols int, digit int) string {
	found := "нет"
	checked := 0
Search:
	for i := 1; i <= rows; i++ {
		for j := 1; j <= cols; j++ {
			checked++
			if i*j%10 == digit {
				found = fmt.Sprintf("%d×%d", i, j)
				break Search
			}
		}
	}
	fmt.Printf("withBreak: после циклов, проверено %d\n", checked)
	return found
}

// withReturn ищет то же самое, но при находке сразу возвращает результат.
func withReturn(rows int, cols int, digit int) string {
	checked := 0
	for i := 1; i <= rows; i++ {
		for j := 1; j <= cols; j++ {
			checked++
			if i*j%10 == digit {
				fmt.Printf("withReturn: находка, проверено %d\n", checked)
				return fmt.Sprintf("%d×%d", i, j)
			}
		}
	}
	fmt.Printf("withReturn: после циклов, проверено %d\n", checked)
	return "нет"
}

func main() {
	fmt.Println(withBreak(5, 5, 6))
	fmt.Println(withReturn(5, 5, 6))
	fmt.Println(withBreak(3, 3, 7))
	fmt.Println(withReturn(3, 3, 7))
}

```
```

Первая подходящая клетка — 2×3: `2*3` равно 6. До неё проверены 5 клеток
первой строки и 3 клетки второй, всего 8 из 25. Клетка 2×3 — последняя
полезная: после неё обход остановлен, и 17 клеток не проверялись. После
`break Search` следующей выполнилась печать после циклов, а после `return` —
уже код вызывающей функции `main`. Цифрой 7 не оканчивается ни одно
произведение таблицы 3×3, поэтому обе функции проверили все 9 клеток, дошли
до кода после циклов и вернули `"нет"`.

Какой способ выбрать? `return` короче, если после находки функции больше
нечего делать. `break` с меткой нужен, когда после циклов стоит общий код,
который должен выполниться и при находке, и без неё, — например, итоговая
печать. Есть и третий способ: проверять находку в условиях обоих циклов.
Метка тогда не нужна, но каждое условие становится длиннее.

## Отбор строк: continue с меткой или флаг

Вторая задача урока: отобрать строки, в которых ни одно произведение не
оканчивается цифрой `digit`. Строку отбрасывают на первой же такой клетке —
остальные её клетки решения не изменят. Обход при этом не заканчивается:
нужно перейти к следующей строке и не засчитать текущую. Это ровно работа
`continue` с меткой внешнего цикла.

То же можно сделать без метки. **Флаг** — переменная `bool`, которая
запоминает, случилось ли событие. Флаг `ok` равен `true` до внутреннего
цикла и становится `false` на отбрасывающей клетке. Обычный `break` при этом
заканчивает внутренний цикл, а после него `if ok` решает, засчитывать ли
строку.

В программе ниже оба варианта: `keepLabel` с `continue Rows` печатает решение
по каждой строке, `keepFlag` с флагом только считает строки. Прежде чем
смотреть вывод, для таблицы 5×5 и цифры 0 скажите, какие строки подойдут, на
каком столбце будет отброшена каждая из остальных и какие числа вернут обе
функции.

```go

### Example: `09-row-filter`

Источник: `examples/09-row-filter/`

```go
package main

import "fmt"

// keepLabel отбирает строки, в которых ни одно произведение не оканчивается
// цифрой digit, печатает решение по каждой строке и возвращает число
// подходящих строк.
func keepLabel(rows int, cols int, digit int) int {
	kept := 0
Rows:
	for i := 1; i <= rows; i++ {
		for j := 1; j <= cols; j++ {
			if i*j%10 == digit {
				fmt.Printf("строка %d: отброшена на столбце %d\n", i, j)
				continue Rows
			}
		}
		fmt.Printf("строка %d: подходит\n", i)
		kept++
	}
	return kept
}

// keepFlag отбирает те же строки без метки: флаг ok и обычный break.
func keepFlag(rows int, cols int, digit int) int {
	kept := 0
	for i := 1; i <= rows; i++ {
		ok := true
		for j := 1; j <= cols; j++ {
			if i*j%10 == digit {
				ok = false
				break
			}
		}
		if ok {
			kept++
		}
	}
	return kept
}

func main() {
	fmt.Println("с меткой:", keepLabel(5, 5, 0))
	fmt.Println("с флагом:", keepFlag(5, 5, 0))
}

```
```

Строки 2 и 4 отброшены на пятом столбце: `2*5` и `4*5` оканчиваются нулём.
Строка 5 отброшена уже на втором, потому что `5*2` равно 10, и её столбцы с
третьего по пятый не проверялись. Подходят строки 1 и 3, обе функции
вернули 2.

Какой вариант писать — вопрос ясности, а не правильности. `continue Rows`
одной инструкцией говорит: эта строка не подходит, переходим к следующей.
Флагу нужны переменная, `break` и проверка после цикла, зато он обходится
без метки. Метка имеет смысл только там, где `break` или `continue` должен
подействовать не на ближайший цикл, а на внешний, и даже там её можно
заменить флагом или `return`.

Скрытые тесты упражнения сравнивают только возвращённое число, поэтому
метка, флаг и `return` для них одинаково верны.

## goto: узнать и не использовать

В Go есть ещё инструкция `goto` с меткой: она переносит выполнение к
помеченной инструкции той же функции. У неё свои запреты: нельзя перепрыгнуть
объявление переменной так, чтобы после перехода она оказалась видна, и нельзя
прыгнуть снаружи внутрь блока. В этом курсе `goto` не используется: выйти из
цикла или перейти к следующему проходу позволяют `break`, `continue` и
`return`. Метка сама по себе не превращает `break` в `goto`: `break` и
`continue` с меткой по-прежнему должны стоять внутри помеченной инструкции.

   `CountRowsWithout(4, 0, 1)` и какие — при вызове
   `CountRowsWithout(0, 5, 1)`?
4. Какая инструкция в `CountRowsWithout` бросает остаток строки и какие

## FirstProduct

`FirstProduct` ищет первую клетку, в которой произведение равно `target`.
Клетки просматриваются по строкам: все столбцы строки 1 слева направо, затем
строки 2 и так далее, как в первом примере урока. Если клетка нашлась,
функция возвращает число `100*row + col` для её строки `row` и столбца `col`.
Если подходящей клетки нет, функция возвращает 0.

Почему одно число. В допустимой области `row` и `col` не больше 10, поэтому
`100*row + col` у всех клеток разное: строку восстанавливает целое деление
на 100, а столбец — остаток от деления на 100 (урок 2.10). Например, 203 —
это строка 2 и столбец 3, а 1001 — строка 10 и столбец 1. Нулю не
соответствует ни одна клетка: строки и столбцы начинаются с 1. Это
договорённость упражнения, а не способ вернуть из функции два значения:
несколько результатов функции разбирает урок 5.2.

- `FirstProduct(3, 4, 6)` возвращает 203: в строке 1 произведения от 1 до 4,
  а первая шестёрка — `2*3`;
- `FirstProduct(3, 3, 5)` возвращает 0;
- `FirstProduct(10, 10, 100)` возвращает 1010;
- `FirstProduct(5, 0, 1)` возвращает 0: столбцов нет, значит, нет и клеток;
- `FirstProduct(10, 10, 0)` возвращает 0: произведение чисел от 1 и больше
  не бывает нулём.

## CountRowsWithout

`CountRowsWithout` считает строки, в которых ни одна клетка не равна
`forbidden`. Строку, где такая клетка нашлась, не считают, и её оставшиеся
клетки проверять не нужно.

Строка без столбцов тоже считается: в ней нет ни одной клетки, а значит,
нет и клетки, которая бы её отбросила.

- `CountRowsWithout(3, 3, 4)` возвращает 2: строка 2 отброшена, потому что
  `2*2` равно 4, а строки 1 и 3 подходят;
- `CountRowsWithout(2, 2, 2)` возвращает 0;
- `CountRowsWithout(4, 0, 1)` возвращает 4;
- `CountRowsWithout(10, 10, 0)` возвращает 10: нулю не равно ни одно
  произведение.

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —

## FirstProduct

**Ступень 1.** В каком порядке нужно просматривать клетки, чтобы первая
найденная была первой по строкам: какой цикл внешний, а какой внутренний? С
какого номера начинаются строки и столбцы? Когда клетка найдена, что должно
закончиться — только текущая строка или весь обход? Что функция вернёт, если
оба цикла дошли до конца без находки?

**Ступень 2.** Внешний цикл идёт по строкам от 1 до `rows`, внутренний — по
столбцам от 1 до `cols`, и в каждой клетке сравнивается `row*col` с
`target`. Закончить оба цикла можно `return 100*row + col` прямо во
внутреннем цикле либо `break` с меткой внешнего цикла и переменной
результата, объявленной до циклов. Частая ошибка — обычный `break`: он
заканчивает только внутренний цикл, и находка в следующей строке
перезаписывает первую.

## CountRowsWithout

**Ступень 1.** Когда строка перестаёт подходить? Что после этого нужно
пропустить — только текущую клетку или все оставшиеся клетки строки вместе с
подсчётом? Сколько раз выполнится тело внутреннего цикла в строке без
столбцов и что тогда должно случиться с подсчётом?

**Ступень 2.** Счётчик увеличивается после внутреннего цикла, в теле
внешнего. На отбрасывающей клетке нужен `continue` с меткой внешнего цикла:
он пропускает и остаток строки, и увеличение счётчика. Вариант без метки —
флаг, обычный `break` и проверка флага после внутреннего цикла. Частая
ошибка — обычный `continue`: он продолжает только внутренний цикл, и строка
засчитывается, хотя должна быть отброшена.

## Как закончить поиск

<!-- review:exit-choice -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: какие
клетки проверит `FirstProduct(3, 4, 6)` и что выполнится после находки.
Образец ответа ниже.

Строка 1 проверяется целиком: клетки 1×1, 1×2, 1×3 и 1×4 с произведениями
от 1 до 4. В строке 2 проверяются клетки 2×1, 2×2 и 2×3. На клетке 2×3
произведение равно 6: это последняя полезная клетка. Клетку 2×4 и строку 3
проверять незачем, ответ — 203. Следующей должна выполниться инструкция,
которая отдаёт этот ответ.

Верных способов три, и тест их не различает:

- `return 100*row + col` прямо во внутреннем цикле. Он завершает функцию, и
  `return 0` после циклов срабатывает, только когда подходящей клетки нет.
  Это самая короткая запись: после находки функции делать больше нечего;
- `break` с меткой внешнего цикла. Результат тогда хранится в переменной,
  объявленной до циклов со значением 0, а после циклов стоит `return` этой
  переменной. Так пишут, когда после циклов есть общий код для обоих
  исходов;
- флаг находки, проверяемый в условиях обоих циклов. Метка не нужна, но
  условия длиннее.

Выбор обосновывают ответом на вопрос: что должно выполниться сразу после
находки? Если ничего, кроме возврата ответа, `return` короче всего.

Второй вопрос: `FirstProduct(3, 3, 3)` с обычным `break`. Строка 1 находит
клетку 1×3 и запоминает 103. `break` заканчивает только внутренний цикл, и
внешний переходит к строке 2. В ней произведения 2, 4 и 6, тройки нет.
Строка 3 находит клетку 3×1 и перезаписывает ответ: функция вернёт 301
вместо 103. Первая находка была верной, но потерялась.

## Как бросить строку

<!-- review:row-skip -->

Третий вопрос: что выполнится при вызовах `CountRowsWithout(4, 0, 1)` и
`CountRowsWithout(0, 5, 1)`. При нуле столбцов внешний цикл проходит все
четыре строки. В каждой выполняется инструкция инициализации внутреннего
цикла, условие `col <= cols` при `cols`, равном 0, сразу ложно, и тело
внутреннего цикла не выполняется ни разу. Отбросить строку нечему, поэтому
увеличение счётчика после внутреннего цикла выполняется четыре раза, и
ответ — 4. При нуле строк
ложно уже первое условие внешнего цикла: до внутреннего цикла и до счётчика
выполнение не доходит, ответ — 0.

Четвёртый вопрос: какая инструкция бросает строку. Это `continue` с меткой
внешнего цикла, например `continue Rows`. После него не выполняются
оставшиеся клетки строки и увеличение счётчика после внутреннего цикла, а
выполняются завершающая инструкция внешнего цикла и его условие. Счётчик
тогда стоит в теле внешнего цикла после внутреннего, и строка засчитывается,
только если внутренний цикл дошёл до конца. Вариант без метки: флаг `ok`,
равный `true` до внутреннего цикла, на отбрасывающей клетке — `ok = false` и
обычный `break`, после цикла — увеличение счётчика при `ok`.

## Обычный break в поиске

<!-- review:first-plain-break -->

Решение запоминает находку в переменной и выходит из внутреннего цикла
обычным `break`. Внешний цикл при этом продолжает работу, и каждая следующая
находка перезаписывает предыдущую.

Ловит это `TestFirstProduct`: для `FirstProduct(3, 3, 3)` тест ждёт 103, а
получает 301. Верная запись заканчивает оба цикла — `return` в момент
находки или `break` с меткой внешнего цикла.

## Поиск по столбцам

<!-- review:first-column-major -->

Решение ставит во внешний цикл столбцы, а во внутренний — строки. Число
`100*row + col` оно считает верно, но первой находит клетку, первую по
столбцам, а не по строкам.

Ловит это `TestFirstProduct`: для `FirstProduct(3, 4, 6)` тест ждёт 203, а
получает 302 — в столбце 2 произведение 6 даёт строка 3 раньше, чем обход
дойдёт до столбца 3. Верная запись: внешний цикл по строкам, внутренний по
столбцам.

## Обычный continue в отборе

<!-- review:rows-plain-continue -->

Решение на отбрасывающей клетке пишет обычный `continue`. Он продолжает
только внутренний цикл: следующая клетка проверяется, а после внутреннего
цикла счётчик всё равно увеличивается. Засчитывается каждая строка.

Ловит это `TestCountRowsWithout`: для `CountRowsWithout(2, 2, 2)` тест ждёт
0, а получает 2. Верная запись — `continue` с меткой внешнего цикла или флаг
с обычным `break` и проверкой после цикла.

## Строка засчитана на последнем столбце

<!-- review:rows-last-column -->

Решение увеличивает счётчик внутри внутреннего цикла, когда дошло до
последнего столбца без отбрасывающей клетки. На строках со столбцами ответ
верный. Но в строке без столбцов внутренний цикл не выполняет ни одного
прохода, и до последнего столбца дело не доходит.

Ловит это `TestCountRowsWithout`: для `CountRowsWithout(4, 0, 1)` тест ждёт
4, а получает 0. Строку засчитывают после внутреннего цикла, в теле
внешнего: туда выполнение доходит и тогда, когда столбцов нет.

## Вопрос 2

```go
@quiz _quiz/02-switch-sum
```

Что напечатает программа?

Варианты ответа:

- A. 2.
- B. 3.
- C. 15.
- D. 10.

Прежде чем смотреть ответ, для каждого `n` скажите, что выполнится после

**Правильный ответ: D.**

цикл. Ответ B — если вдобавок считать, что `continue` заканчивает только
`switch`. Ответ C — если ошибиться только в `continue`: тогда складываются
все числа от 1 до 5.

## Вопрос 3

```go
@quiz _quiz/03-continue-outer
```

Что напечатает программа?

Варианты ответа:

- A. 1.
- B. 33.
- C. 3.
- D. 36.

Прежде чем смотреть ответ, для первой строки скажите, что выполнится после
`continue Outer`, выполнится ли `count += 10` и с какого `j` начнётся

**Правильный ответ: C.**

В каждой строке при `j`, равном 1, выполняется `count++`, а при `j`, равном

начинается с `j := 1`. Три строки дают 3. Вариант A путает `continue Outer` с
`break Outer`. Вариант B путает его с обычным `break`: тогда `count += 10`
выполнялось бы в каждой строке. Вариант D путает его с обычным `continue`.

## Вопрос 4

В программе из раздела теории «continue с меткой» инструкцию
`continue Outer` заменили на `break Outer`. Что выполнится сразу после
`break Outer`?

Варианты ответа:

- A. Ни одна инструкция цикла: следующей выполнится инструкция после
  внешнего цикла.
- B. Инструкция внешнего тела после внутреннего цикла, затем завершающая
  инструкция внешнего цикла.
- C. Завершающая инструкция внешнего цикла, затем его условие.
- D. Завершающая инструкция внутреннего цикла `j++`.

Прежде чем смотреть ответ, ответьте на тот же вопрос для `continue Outer` и
объясните, почему ответы различаются.

**Правильный ответ: A.**

`break Outer` завершает весь помеченный цикл. Завершающая инструкция
выполняется в конце прохода, перед следующей проверкой условия, а после
`break Outer` следующего прохода не будет. Для `continue Outer` верен
вариант C: он заканчивает только текущий проход внешнего цикла, поэтому
завершающая инструкция и условие выполняются, а в новой строке снова
выполняется `j := 1`. Вариант B описывает обычный `break`, вариант D —
обычный `continue`.

## Вопрос 5

```go
@quiz _broken/q-inner-label
```

Программа не собирается. Замысел — в строке 2 не печатать итоговую строку с
номером. В чём причина отказа и какая правка сохраняет замысел?

Варианты ответа:

- A. Метка `Inner` видна только внутри помеченного цикла; `continue Inner`
  нужно перенести в тело внутреннего цикла.
- B. Метку нельзя ставить на внутренний цикл; её нужно перенести на внешний
  цикл, остальное оставить как есть.
- C. Одну метку не могут использовать две инструкции; для `continue` нужна
  вторая метка.
- D. `continue Inner` стоит вне цикла `Inner`, а метка у `continue` должна
  называть охватывающий цикл; правка — обычный `continue`, который продолжит
  внешний цикл.

Прежде чем смотреть ответ, назовите циклы, внутри которых стоит
`continue Inner`, и цикл, который по замыслу нужно продолжить.

**Правильный ответ: D.**

`continue Inner` записан в теле внешнего цикла ниже закрывающей скобки
внутреннего, то есть не между скобками цикла `Inner`. Охватывает эту
инструкцию только внешний цикл, а метка `Inner` стоит на внутреннем.
Компилятор проверяет это по тексту программы, не запуская её. Обычный
`continue` пропустит итоговую печать для строки 2 и продолжит внешний цикл.
Вариант A объясняет отказ видимостью, но метка видна во всей функции.
Причина в другом: помеченный цикл не охватывает `continue`. К тому же
`continue Inner` в теле внутреннего цикла лишь перешёл бы к следующему `j`.
Вариант B сделал бы `continue Inner` законным, но и `break Inner` стал бы
завершать внешний цикл — замысел поменяется. Вариант C неверен: на одну
метку могут ссылаться несколько инструкций.
