# Теория

# switch с выражением

Интернет-магазин хранит состояние заказа числом: 0 — заказ создан, 1 —
оплачен, 2 — отправлен. Чтобы показать покупателю подпись, программа
выбирает одно действие по одному числу. Цепочкой `if`-`else` из урока 3.1
такой выбор записывается длинно: каждое условие заново сравнивает код
заказа с очередным числом через `==`. Инструкция `switch` записывает тот же
выбор короче: сравниваемое значение названо один раз, а под ним перечислены
варианты.

К концу урока вы сможете:

- проследить выполнение `switch`: сколько раз вычисляется значение после
  слова `switch`, какая ветка выполнится, какие будут пропущены и что
  выполнится после `switch`;
- объединить несколько значений в одну ветку и отличить такую ветку от
  пустой ветки и от перехода `fallthrough`;
- писать в `case` значения подходящего типа и исправлять неподходящие;
- объявлять переменную в заголовке `switch` и знать, где она перестаёт быть
  видна;
- написать функцию, которая выбирает ответ для группы значений, для
  отдельного значения и для всех остальных, и объяснить, что означает ответ
  для остальных.

## Один выбор по одному значению

Запись `switch` состоит из двух частей. После слова `switch` стоит
выражение — **выбираемое значение**. Ниже, в фигурных скобках, идут
**ветки**. Ветка начинается словом `case`, за ним стоит значение и
двоеточие; строки ниже, до следующей ветки, — **тело ветки**.

Выполняется `switch` по четырём шагам:

1. Программа вычисляет выбираемое значение.
2. Программа сравнивает его оператором `==` со значениями веток по порядку,
   сверху вниз.
3. Первая ветка, чьё значение оказалось равным выбираемому, выполняет своё
   тело. Остальные ветки пропускаются.
4. Когда тело закончилось, закончился и `switch`: программа переходит к
   инструкции, которая стоит после его закрывающей фигурной скобки.

Если ни одно значение ветки не равно выбираемому, ни одно тело не
выполняется, и программа сразу переходит к инструкции после `switch`.

Инструкция `break` в конце ветки в Go не нужна: конец тела ветки и есть
выход из `switch`. В C и похожих на него языках без этой инструкции
выполнение продолжается в следующей ветке, поэтому там её пишут в конце
каждой ветки.

Функция `describe` ниже разбирает код заказа, а после `switch` печатает ещё
одну строку. Прежде чем смотреть вывод, скажите для каждого из трёх
вызовов, какие строки он напечатает. Для кода 7 ветки нет.

```go

### Example: `01-status`

Источник: `examples/01-status/`

```go
package main

import "fmt"

// describe печатает смысл кода состояния заказа, а затем строку,
// которая стоит после switch.
func describe(code int) {
	switch code {
	case 0:
		fmt.Println("код", code, "→ заказ создан")
	case 1:
		fmt.Println("код", code, "→ заказ оплачен")
	case 2:
		fmt.Println("код", code, "→ заказ отправлен")
	}
	fmt.Println("после switch: код", code, "разобран")
}

func main() {
	describe(1)
	describe(2)
	describe(7)
}

```
```

Для кода 1 сработала вторая ветка, и третью программа уже не сравнивала.
Строка после `switch` напечаталась при всех трёх вызовах: и когда ветка
нашлась, и когда код 7 не совпал ни с одним значением.

## Выбираемое значение вычисляется один раз

Выбираемое значение программа вычисляет один раз, до всех сравнений.
Значения веток — тоже выражения. Программа вычисляет их по очереди сверху
вниз, пока не найдёт равное; после совпадения оставшиеся значения не
вычисляются вовсе.

Порядок вычислений виден по двум вспомогательным функциям из примера ниже.
Функция `selected` печатает строку о том, что её вызвали, и возвращает свой
аргумент без изменений. Функция `option` делает то же самое для значения
ветки. Поэтому `case option(1)` сравнивает так же, как `case 1`, но
оставляет в выводе след. Что ещё, кроме чисел, можно писать в `case`,
разобрано ниже, в разделе «Что можно писать в case».

Прежде чем смотреть вывод, ответьте для вызовов `classify(2)` и
`classify(5)`: сколько раз сработает функция `selected`, какие значения
веток будут вычислены и какая ветка выполнит своё тело.

```go

### Example: `02-once`

Источник: `examples/02-once/`

```go
package main

import "fmt"

// selected печатает строку о своём вызове и возвращает n без изменений.
func selected(n int) int {
	fmt.Println("вычислено выбираемое значение", n)
	return n
}

// option печатает строку о своём вызове и возвращает v без изменений.
func option(v int) int {
	fmt.Println("  вычислено значение ветки", v)
	return v
}

// classify выбирает ветку для n и печатает, какая ветка сработала.
func classify(n int) {
	switch selected(n) {
	case option(1):
		fmt.Println("  сработала ветка со значением 1")
	case option(2):
		fmt.Println("  сработала ветка со значением 2")
	case option(3):
		fmt.Println("  сработала ветка со значением 3")
	}
	fmt.Println("конец switch для", n)
}

func main() {
	classify(2)
	classify(5)
}

```
```

Функция `selected` сработала по одному разу на каждый вызов `classify`. Для
2 программа вычислила два значения веток и остановилась: третье значение
так и не понадобилось. Для 5 программа вычислила все три значения, не нашла
равного и перешла к строке после `switch`.

## Несколько значений в одной ветке

Дни недели пронумерованы от 1 (понедельник) до 7 (воскресенье). Пять
номеров означают будний день, два — выходной. Писать по ветке на каждый
номер незачем: значения с общим телом перечисляют в одной ветке через
запятую — `case 1, 2, 3, 4, 5:`.

Ветка со списком срабатывает, если выбираемое значение равно хотя бы одному
значению из списка. Каждое значение списка сравнивается отдельно,
оператором `==`, слева направо. Список — не промежуток: ветка `case 1, 5:`
совпадает с 1 и с 5, но не с 3. И это не одно значение-набор, а несколько
отдельных значений одной ветки.

Функция `dayKind` из примера ниже принимает параметр типа `int`, значит,
в неё можно передать и 0, и 8 — числа, которые номерами дней не являются.
Для таких чисел служит ветка `default`: она выполняется, когда выбираемое
значение не совпало ни с одним значением `case`. Смысл её ответа задаёт
условие задачи. В этом примере дней недели семь, поэтому ответ `default` —
«номера такого дня нет».

Прежде чем смотреть вывод, скажите, какую строку напечатает каждый из
четырёх вызовов.

```go

### Example: `03-grouped`

Источник: `examples/03-grouped/`

```go
package main

import "fmt"

// dayKind печатает вид дня недели по его номеру: 1 — понедельник,
// 7 — воскресенье. Другие числа номерами дней не являются.
func dayKind(day int) {
	switch day {
	case 1, 2, 3, 4, 5:
		fmt.Println("день", day, "→ будний")
	case 6, 7:
		fmt.Println("день", day, "→ выходной")
	default:
		fmt.Println("день", day, "→ такого дня нет")
	}
}

func main() {
	dayKind(3)
	dayKind(7)
	dayKind(0)
	dayKind(8)
}

```
```

Номера 3 и 7 нашлись в списках своих веток. Для 0 и 8 ни одно сравнение не
дало равенства, и выполнилась ветка `default`.

## Пустая ветка не делит тело с соседней

В Go ветка без инструкций — это ветка с пустым телом, и тело следующей
ветки ей не принадлежит. В C и похожих на него языках иначе: выполнение
без `break` продолжается в следующей ветке, поэтому там ветки без тела,
записанные одна под другой, получают тело нижней ветки. В Go при совпадении
с пустой веткой выполнять нечего, и `switch` сразу заканчивается.

Функция `withEmptyCase` ниже записана по привычке C, функция `grouped` —
со списком значений. Прежде чем смотреть вывод, скажите, какие строки
напечатают вызовы с 1 и с 2 для каждой из двух функций.

```go

### Example: `04-empty-case`

Источник: `examples/04-empty-case/`

```go
package main

import "fmt"

// withEmptyCase показывает ветку case 1, в которой нет ни одной инструкции.
func withEmptyCase(n int) {
	switch n {
	case 1:
	case 2:
		fmt.Println("пустая ветка, n =", n, "→ выполнено тело case 2")
	}
	fmt.Println("пустая ветка, n =", n, "→ switch пройден")
}

// grouped перечисляет оба значения в одной ветке.
func grouped(n int) {
	switch n {
	case 1, 2:
		fmt.Println("список, n =", n, "→ выполнено общее тело")
	}
}

func main() {
	withEmptyCase(1)
	withEmptyCase(2)
	grouped(1)
	grouped(2)
}

```
```

Для 1 в `withEmptyCase` совпала ветка `case 1`. Тело у неё пустое, поэтому
напечаталась только строка после `switch`. Тело ветки `case 2` выполнилось
лишь для 2. Чтобы у нескольких значений было общее тело, их перечисляют в
одной ветке, как в функции `grouped`.

## Где стоит default

Ветка `default` в `switch` бывает одна или её нет совсем. Стоять она может
где угодно: первой, между ветками `case` или последней. Место не меняет
смысла: `default` выполняется, только если не совпало ни одно значение
`case`, и программа сравнивает все значения `case`, где бы ни стояла
`default`.

Прежде чем смотреть вывод, скажите, какую ветку выберут вызовы с 2 и с 9,
если `default` записана первой.

```go

### Example: `05-default-first`

Источник: `examples/05-default-first/`

```go
package main

import "fmt"

// level выбирает ветку для n; ветка default записана первой.
func level(n int) {
	switch n {
	default:
		fmt.Println(n, "→ выбрана ветка default")
	case 1:
		fmt.Println(n, "→ выбрана ветка case 1")
	case 2:
		fmt.Println(n, "→ выбрана ветка case 2")
	}
}

func main() {
	level(2)
	level(9)
}

```
```

Ветка `default` стояла выше всех, но 2 досталось ветке `case 2`. В коде
`default` принято ставить последней: так запись читается в том же порядке,
в каком работает, — сначала перечисленные значения, потом «всё остальное».

## return внутри ветки

В функции с результатом ветка часто заканчивается инструкцией `return`.
По уроку 1.7 `return` завершает всю функцию, а не только `switch`: строки
после `switch` уже не выполняются.

Ветки `default` может и не быть. Тогда значение, которое не совпало ни с
одним `case`, проходит `switch` насквозь, и выполнение доходит до строк
после него. Функции с результатом там нужен свой `return`: на этом пути
она тоже обязана вернуть значение.

Прежде чем смотреть вывод, скажите, какие строки напечатает программа для
дней 6 и 9.

```go

### Example: `06-return`

Источник: `examples/06-return/`

```go
package main

import "fmt"

// dayType возвращает тип дня по его номеру от 1 до 7. Строки после
// switch выполняются, только если номер не совпал ни с одним case.
func dayType(day int) string {
	switch day {
	case 6, 7:
		return "выходной"
	case 1, 2, 3, 4, 5:
		return "рабочий"
	}
	fmt.Println("  номер", day, "не совпал ни с одним case")
	return "не день недели"
}

func main() {
	first := dayType(6)
	fmt.Println("день 6:", first)
	second := dayType(9)
	fmt.Println("день 9:", second)
}

```
```

Для 6 функция вернула результат прямо из ветки, и строка после `switch` не
напечаталась. Для 9 ни одна ветка не совпала: выполнение дошло до строк
после `switch`, напечатало пояснение и вернуло последний результат.

Бывает и наоборот: `default` есть, и каждая ветка, включая `default`,
заканчивается `return`. Тогда выполнение никогда не доходит до конца
`switch`, и `return` после него не нужен. Так записана функция в разделе
«Константы как значения case».

## Что можно писать в case

Значение ветки — не обязательно число, записанное в коде. Годится
переменная, параметр функции или выражение, если его можно сравнить с
выбираемым значением оператором `==` (урок 2.6). Выбираемое значение тоже
бывает не только числом: если это строка, в `case` стоят строки.

В функции `compare` ниже в ветках стоят два параметра и произведение.
Значения таких веток становятся известны только во время работы программы.
В последнем вызове оба параметра равны 4. Прежде чем смотреть вывод,
скажите, какую ветку выберет каждый вызов, а для последнего — какую из двух
подходящих.

```go

### Example: `07-case-values`

Источник: `examples/07-case-values/`

```go
package main

import "fmt"

// compare сообщает, с каким значением ветки совпало n. В ветках стоят
// параметры и произведение, а не числа, записанные в коде.
func compare(n int, low int, high int) {
	switch n {
	case low:
		fmt.Println(n, "→ совпало с low =", low)
	case high, high * 2:
		fmt.Println(n, "→ совпало с high =", high, "или с его удвоением")
	default:
		fmt.Println(n, "→ совпадений нет")
	}
}

func main() {
	compare(3, 3, 9)
	compare(18, 3, 9)
	compare(5, 3, 9)
	compare(4, 4, 4)
}

```
```

Значения веток вычислялись при каждом вызове заново. В последнем вызове
подошли обе первые ветки, и сработала верхняя: программа идёт сверху вниз и
останавливается на первом равенстве. Значения, известные только во время
работы, могут совпасть, и ошибки в этом нет.

Сравнение через `==` требует подходящих типов, и здесь действуют два
разных правила.

- Константа без типа — например, число `300` или строка `"1"` в `case` —
  сначала приводится к типу выбираемого значения. Её значение обязано быть
  представимо в этом типе (урок 2.11). Если выбираемое значение имеет тип
  `byte`, ветка `case 300:` не соберётся: 300 в `byte` не помещается.
- Значение, у которого тип уже есть, — переменная или типизированная
  константа — само не приводится. Для чисел и строк, известных вам по
  урокам 2.1–2.11, это значит, что его тип обязан совпасть с типом
  выбираемого значения.

@broken typed-case
```

Сообщение сборки —
`invalid case limit in switch on code (mismatched types int64 and int)`:
значение ветки `limit` имеет тип `int64`, а выбираемое значение `code` —
тип `int`. Исправление — явное преобразование из урока 2.9: ветка
`case int(limit):` сравнивает два значения типа `int`. Если же `limit` и не
должна быть `int64`, проще сразу объявить её с типом `int`.

## Повторённая константа в case

Одна и та же константа в двух ветках — почти всегда опечатка. Вторая ветка
с этим значением не сработала бы никогда: первая забирает его раньше.

```go
@broken duplicate-case
```

Сообщение сборки —
`duplicate case 5 (constant of type int) in expression switch`. Так
поступает текущий компилятор с повторёнными целыми и строковыми
константами; спецификация языка разрешает компилятору такой отказ, но не
требует его. Значения, которые становятся известны только во время работы,
компилятор не сверяет: при их совпадении срабатывает верхняя ветка, как в
последнем вызове `compare` из предыдущего раздела.

## fallthrough: явный переход в следующую ветку

Обычно конец тела — это выход из `switch`. Инструкция `fallthrough`,
поставленная последней в теле ветки, меняет это: управление переходит к
первой инструкции тела следующей ветки. Значения следующей ветки при этом
не сравниваются, и её тело выполняется, даже если выбираемое значение им
не равно. Одна инструкция `fallthrough` — один шаг: чтобы пройти дальше,
следующей ветке нужна своя.

Прежде чем смотреть вывод, скажите, какие тела выполнятся при `n`, равном
1, и при `n`, равном 2. Для 1 учтите, что значение второй ветки — 2.

```go

### Example: `08-fallthrough`

Источник: `examples/08-fallthrough/`

```go
package main

import "fmt"

// steps показывает, тела каких веток выполняются для n.
func steps(n int) {
	switch n {
	case 1:
		fmt.Println("n =", n, "→ тело case 1")
		fallthrough
	case 2:
		fmt.Println("n =", n, "→ тело case 2")
	case 3:
		fmt.Println("n =", n, "→ тело case 3")
	}
}

func main() {
	steps(1)
	steps(2)
}

```
```

При 1 выполнились два тела, хотя 1 не равно 2. Тело третьей ветки не
выполнилось: `fallthrough` стоял только в первой. При 2 выполнилось одно
тело второй ветки.

Три записи, которые легко спутать, при одном и том же выбираемом значении
1:

- `case 1, 2:` — одно общее тело для двух значений, и каждое значение
  сравнивается;
- `case 1:` с пустым телом, под ним `case 2:` — при 1 не выполняется
  ничего;
- `case 1:` с `fallthrough` в конце тела, под ним `case 2:` — при 1
  выполняются оба тела, а значение 2 не сравнивается.

Место у `fallthrough` строго ограничено. Это последняя инструкция тела
ветки, и в последней ветке `switch` её быть не может: переходить некуда.
Если поставить `fallthrough` внутри `if` в теле ветки, последней
инструкцией ветки окажется вся условная инструкция, а не сам переход:

```go
@broken fallthrough-in-if
```

Сообщение сборки — `fallthrough statement out of place`. Условного
перехода `fallthrough` не даёт. В обычном коде эта инструкция нужна
редко; решению упражнения этого урока она не нужна.

## Короткая инструкция в заголовке switch

По уроку 3.2 `if` может начинаться с короткой инструкции:
`if n := count(); n > 0 {`. Заголовок `switch` устроен так же:
`switch step := nextStep(1); step {`. Сначала выполняется короткая
инструкция, потом вычисляется выбираемое значение. Переменная из заголовка
видна в выбираемом значении, в значениях всех веток и во всех телах, но
только до закрывающей фигурной скобки `switch`. Как в уроках 2.3 и 3.2,
переменная с тем же именем снаружи — другая переменная: внутренняя её
затеняет, но не меняет.

В примере ниже функция `nextStep` возвращает код, следующий за переданным:
прибавляет к нему единицу. Прежде чем смотреть вывод, скажите, какое
значение `step` напечатает строка внутри `switch` и какое — строка после
него.

```go

### Example: `09-header`

Источник: `examples/09-header/`

```go
package main

import "fmt"

// nextStep возвращает код, который получит заказ после кода code.
func nextStep(code int) int {
	return code + 1
}

func main() {
	step := 100
	switch step := nextStep(1); step {
	case 1:
		fmt.Println("внутри switch: step =", step, "→ оплачен")
	case 2:
		fmt.Println("внутри switch: step =", step, "→ отправлен")
	}
	fmt.Println("после switch: step =", step)
}

```
```

Внутри `switch` имя `step` означало переменную заголовка со значением 2.
После `switch` эта переменная уже не видна, и то же имя снова означает
внешнюю переменную: её значение 100 не менялось.

Если внешней переменной нет, имя из заголовка после `switch` не найдётся:

```go
@broken header-after
```

Сообщение сборки — `undefined: step`. Если значение нужно и после
`switch`, его вычисляют отдельной строкой до него, например
`step := nextStep(1)`, а заголовок сокращают до `switch step {`.

## У каждой ветки свой блок

Тело каждой ветки — отдельный блок, как тело в фигурных скобках из урока
2.3, хотя самих скобок у ветки нет. Переменная, объявленная в ветке, видна
до конца этой ветки. Поэтому две ветки могут объявить одно и то же имя: это
будут две разные переменные.

Прежде чем смотреть вывод, скажите, что вернёт `label` для кодов 0, 1 и 5.

```go

### Example: `10-case-blocks`

Источник: `examples/10-case-blocks/`

```go
package main

import "fmt"

// label собирает подпись для кода заказа. Обе ветки объявляют своё msg.
func label(code int) string {
	switch code {
	case 0:
		msg := "создан"
		return "заказ " + msg
	case 1:
		msg := "оплачен"
		return "заказ " + msg
	}
	return "код не распознан"
}

func main() {
	fmt.Println("код 0:", label(0))
	fmt.Println("код 1:", label(1))
	fmt.Println("код 5:", label(5))
}

```
```

Обе ветки объявили своё `msg` и вернули свою подпись. Для кода 5 ни одна
ветка не совпала, и сработал `return` после `switch`.

Переменная одной ветки не попадает ни в другую ветку, даже если та стоит
ниже, ни в строки после `switch`:

```go
@broken case-local
```

Сообщение сборки — `undefined: msg`. Если значение нужно нескольким
веткам, его объявляют до `switch`.

## Константы как значения case

В уроке 2.12 единицы длины получили номера через `iota`: миллиметр — 0,
сантиметр — 1, дециметр — 2, метр — 3. Имена констант годятся в `case` так
же, как числа: сравнивается значение константы. Зато ветка `case metre:`
читается как единица длины, а не как голая тройка.

Прежде чем смотреть вывод, ответьте: соберётся ли программа, которая
передаёт функции с параметром `int` числа 42 и −1, и что вернёт `unitName`
в каждом из четырёх вызовов?

```go

### Example: `11-units`

Источник: `examples/11-units/`

```go
package main

import "fmt"

// Единицы длины из урока 2.12: значение константы — номер единицы.
const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

// unitName возвращает название единицы длины по её номеру. Номера вне
// набора тоже приходят сюда: параметр имеет тип int.
func unitName(unit int) string {
	switch unit {
	case millimetre:
		return "миллиметр"
	case centimetre:
		return "сантиметр"
	case decimetre:
		return "дециметр"
	case metre:
		return "метр"
	default:
		return "неизвестная единица"
	}
}

func main() {
	fmt.Println(metre, "→", unitName(metre))
	fmt.Println(centimetre, "→", unitName(centimetre))
	fmt.Println(42, "→", unitName(42))
	fmt.Println(-1, "→", unitName(-1))
}

```
```

Программа собралась, и числа вне набора дошли до функции. Четыре имени —
обычные константы без собственного типа, а параметр имеет тип `int` и
принимает любое значение этого типа. Сам `switch` не проверяет, входит ли
число в набор: он сравнивает число со значениями веток, и всё, что не
совпало, уходит в `default`. Что означает ответ `default` — «неизвестная
единица», пустая строка или что-то ещё, — решает условие задачи, а не язык.

## Группы в MonthDays

<!-- review:month-groups -->

Первый и второй вопросы из раздела упражнения «Что проверяется, а что нет».
Образец ответа ниже.

Если разложить месяцы по числу дней, получатся три группы: 31 день у

результатом 31, `case 4, 6, 9, 11:` с результатом 30 и `case 2:` с
результатом 28. Ветка `default` возвращает 0.

Февралю нужна своя ветка, потому что `default` получает не «оставшийся
месяц», а каждое число, которое не совпало ни с одним значением `case`:
0, 13, −1, 100 и любое другое. Ответ `default` в этой функции означает
«месяца с таким номером нет». Число 0 для этого задано условием задачи:
у настоящего месяца нуля дней не бывает, и спутать такой ответ с числом
дней нельзя. Вместо ветки `default` можно было поставить `return 0` после
`switch`: число, не совпавшее ни с одной веткой, проходит `switch`
насквозь и доходит до этой строки.

Второй вопрос для `TicketStage`: до `default` доходят все числа, кроме 0,
1, 2, 3 и 4, и её ответ «неизвестное состояние» означает, что такого номера
в наборе состояний нет.

## Что означает default в TicketStage

<!-- review:ticket-fallback -->

Третий вопрос из раздела упражнения «Что проверяется, а что нет». Образец
ответа ниже.

Параметр `status` имеет тип `int`, а пять имён в блоке — обычные
константы без собственного типа. Поэтому в функцию законно приходит любое
целое число, и 42 не исключение: ни сборка, ни `switch` не проверяют,
входит ли число в набор. `switch` лишь сравнивает 42 с пятью константами,
не находит равной и выполняет `default`. Какой ответ дать для таких чисел,
решает условие: здесь это «неизвестное состояние».

Три состояния с подписью «в работе» записаны одной веткой —
`case assigned, working, waiting:`. Каждое имя в списке сравнивается
отдельно, и совпадение с любым из них выполняет общее тело.

## Пустые ветки вместо списка

<!-- review:empty-cases -->

Решение записывает каждый месяц отдельной веткой без тела, а результат
ставит только в последнюю ветку группы — как в языке C, где выполнение
проваливается вниз. В Go пустая ветка тела следующей не получает: январь
совпадает с `case 1:`, тело пустое, `switch` заканчивается, и функция
доходит до `return 0` после него.

Такое решение не проходит `TestMonthDays`: для января тест ждёт 31, а
получает 0. Верная запись перечисляет номера группы в одной ветке через
запятую.

## Февраль в default

<!-- review:february-default -->

Решение не заводит ветку для февраля и отдаёт его ветке `default` с
результатом 28. Февраль при этом получает верный ответ, но вместе с ним 28
получает каждое число, которое номером месяца не является.

Такое решение не проходит `TestMonthDays` на числах вне календаря: для 13
тест ждёт 0, а получает 28. Февралю нужна ветка `case 2:`, а `default`
оставляют числам, у которых месяца нет.

## fallthrough по привычке

<!-- review:fallthrough-habit -->

Решение записывает число дней в переменную и ставит `fallthrough` в конец
ветки с 31 днём — по привычке из C завершать каждую ветку отдельной
инструкцией. `fallthrough` передаёт управление телу следующей ветки без
сравнения, и это тело перезаписывает 31 на 30.

Такое решение не проходит `TestMonthDays`: для января тест ждёт 31, а
получает 30. Уберите `fallthrough`: в Go конец тела ветки сам завершает
`switch`.

## Закрытая заявка в default

<!-- review:closed-default -->

Решение не заводит ветку для `closed` и отдаёт подпись «закрыта» ветке
`default`. Состояние 4 получает верный ответ, но «закрыта» получает и любое
число вне набора состояний.

Такое решение не проходит `TestTicketStage` на числах 5, −1 и 42: тест ждёт
«неизвестное состояние», а получает «закрыта». Верная запись — отдельная
ветка `case closed:` и `default` для всего остального.

## Номера с единицы

<!-- review:numbers-from-one -->

Решение пишет в `case` числа вместо имён констант и считает состояния с
единицы. Но первая запись блока — `opened = iota` — получает ноль, поэтому
каждая подпись съехала на одно состояние: 0 уходит в `default`, 1
получает «новая», 4 — «в работе».

Такое решение не проходит `TestTicketStage`: для 0 тест ждёт «новая», а
получает «неизвестное состояние». С именами констант в `case` такой сдвиг
не возникает: номер каждого состояния берётся из блока констант, а не
вспоминается по памяти.

## Вопрос 1

```go
@quiz _quiz/01-trace
```

Что напечатает программа?

Варианты ответа:

- A. Строку о вызове `read` перед каждым сравнением, затем «средне» и
  «готово».
- B. Строку о вызове `read`, затем «вне шкалы» и «готово».
- C. Строку о вызове `read` один раз, затем «средне» и «готово».
- D. Строку о вызове `read`, затем «средне», «много» и «готово».

Прежде чем смотреть ответ, скажите, сколько раз вызовется `read`, какие
значения веток будут сравнены с выбираемым, тело какой ветки выполнится и
что выполнится после `switch`.

**Правильный ответ: C.**

`read` вызывается один раз: выбираемое значение вычисляется до всех
сравнений. Программа сравнивает 4 с 1 и 2, затем с 3 и 4 и на четвёрке
останавливается; значения последней ветки уже не сравниваются. Ветка
`default` в сравнениях не участвует и выполняется, только если не совпало
ни одно значение. После тела совпавшей ветки `switch` закончен, и
выполняется строка после него. Вариант A вычисляет выбираемое значение
заново для каждого сравнения. Вариант B считает, что `default`, записанная
выше подходящей ветки, перехватывает значение. Вариант D продолжает
выполнение в следующей ветке, как в языках, похожих на язык C, хотя в Go
конец тела — это выход из `switch`.

## Вопрос 2

```go
@quiz _quiz/02-three-bodies
```

Что напечатает программа?

Варианты ответа:

- A. «группа», «пустая», «раз», «два».
- B. «группа», «раз», «два».
- C. «группа», «раз».
- D. «группа», «раз», «два», «три».

Прежде чем смотреть ответ, для каждой из трёх функций скажите, какая ветка
совпадёт с 1 и тела каких веток выполнятся. Для `through` отдельно
ответьте: сравнивается ли 1 со значением второй ветки?

**Правильный ответ: B.**

В `grouped` значение 1 есть в списке ветки, и её тело выполняется. В
`empty` совпадает ветка `case 1` с пустым телом: выполнять нечего, `switch`
закончен, а тело `case 2` ей не принадлежит. В `through` выполняется тело
`case 1`, затем `fallthrough` передаёт управление телу `case 2` без
сравнения 1 с 2; дальше перехода нет, потому что во второй ветке своего
`fallthrough` не стоит. Вариант A считает, что пустая ветка получает тело
следующей. Вариант C ждёт, что `fallthrough` сначала сравнит значение
следующей ветки. Вариант D считает, что `fallthrough` продолжает выполнение
до конца `switch`.

## Вопрос 3

```go
@quiz _quiz/03-comma
```

Что напечатает программа?

Варианты ответа:

- A. «край».
- B. Ничего: сборка откажет.
- C. «край», затем «середина».
- D. «середина».

Прежде чем смотреть ответ, выпишите сравнения, которые выполнит `switch`,

**Правильный ответ: D.**

## Вопрос 4

```go
@quiz _broken/string-case
```

Номер пункта меню хранится в `choice` как число, и программа должна
напечатать строку, когда выбран первый пункт. Что произойдёт с этой
программой и какая правка верна?

Варианты ответа:

- A. Сборка откажет; верная правка — `case 1:` без кавычек.
- B. Сборка пройдёт, но ветка не сработает никогда; верная правка —
  `case 1:` без кавычек.
- C. Сборка пройдёт, и ветка сработает; правка не нужна.
- D. Сборка откажет; верная правка — добавить ветку `default`.

Прежде чем смотреть ответ, назовите тип выбираемого значения, тип значения
в `case` и скажите, может ли одно стать другим.

**Правильный ответ: A.**

`choice` объявлена через `:=` с числом 1 и получила тип `int`. В `case`
стоит строковая константа без типа. Перед сравнением она обязана
привестись к типу `int`, а строка в `int` не представима, поэтому сборка
отказывает. Число 1 без кавычек — тоже константа без типа, но оно
представимо в `int`, и сравнение становится законным. Вариант B считает,
что значения разных типов просто оказываются не равны, — на деле такое
сравнение не собирается. Вариант C ждёт, что Go сам превратит текст «1» в
число. Вариант D не трогает ветку с неподходящим значением, а отказ сборки
вызван именно ею.

## Вопрос 5

В функции стоит заголовок `switch level := levelOf(score); level {` с
несколькими ветками, а после закрывающей скобки `switch` — строка
`fmt.Println(level)`. Сборка отказывает: имя `level` после `switch` не
найдено. Какая правка печатает после `switch` то самое значение, по
которому `switch` выбирал ветку?

Варианты ответа:

- A. Объявить `level` строкой `var level int` сразу после `switch`.
- B. Перенести строку с печатью `level` в ветку `default`.
- C. Объявить `level` через `:=` перед `switch`, а в заголовке оставить
  `switch level {`.
- D. Поставить `fallthrough` в конец последней ветки перед печатью.

Прежде чем смотреть ответ, скажите, где начинается и где кончается область
видимости `level`, объявленной в заголовке.

**Правильный ответ: C.**

Переменная из заголовка видна в выбираемом значении, в ветках и в их телах,
но только до закрывающей скобки `switch`. Если значение нужно и после
`switch`, его объявляют до него строкой `level := levelOf(score)`: тогда
переменная видна до конца блока функции, а `switch level {` сравнивает то
же значение. Вариант A объявляет новую переменную с нулевым значением, и
печатается 0, а не выбранное значение. Вариант B печатает только тогда,
когда не совпала ни одна ветка. Вариант D так записать нельзя: в последней
ветке `fallthrough` некуда переходить, и область видимости он всё равно не
меняет.

## Вопрос 6

Две функции получают `n` типа `int`. В первой у `switch n` есть ветка
`case 5:` и ниже ещё одна ветка `case 5:`. Во второй — ветки `case low:` и
`case high:`, где `low` и `high` — параметры функции типа `int`; функцию
вызывают так, что `n`, `low` и `high` равны 5. Что произойдёт?

Варианты ответа:

- A. Обе соберутся, и в каждой выполнятся обе ветки с пятёркой.
- B. Первая функция не соберётся; вторая соберётся, и выполнится ветка
  `case low:`.
- C. Обе не соберутся: одинаковые значения в двух ветках запрещены.
- D. Первая соберётся, и выполнится нижняя ветка `case 5:`; вторая не
  соберётся.

Прежде чем смотреть ответ, для каждой функции скажите, когда становится
известно значение ветки — при сборке или во время работы программы.

**Правильный ответ: B.**

Константа 5 известна при сборке, и текущий компилятор отвергает повторённую
целую константу в двух ветках. Значения `low` и `high` становятся известны
только во время работы, их компилятор не сверяет; при совпадении программа
идёт сверху вниз и выполняет первую подходящую ветку. Вариант A забывает,
что тело выполняется только у одной ветки. Вариант C распространяет запрет
на значения, которые при сборке неизвестны. Вариант D меняет местами обе
функции: повтор константы компилятор замечает при сборке и отвергает, а
значения параметров при сборке неизвестны, поэтому вторая функция
собирается. При совпадении во время работы срабатывает верхняя ветка, а не
нижняя.

## Вопрос 7

В функции `unitName` из раздела «Константы как значения case» ветку
`default` убрали, а после `switch` дописали `return ""`. Что будет при
вызове `unitName(7)`?

Варианты ответа:

- A. Сборка откажет: числа 7 в наборе констант нет.
- B. Сборка пройдёт, и функция вернёт «метр» — ближайшую единицу.
- C. Сборка пройдёт, но программа остановится при вызове с 7.
- D. Сборка пройдёт, и функция вернёт пустую строку.

Прежде чем смотреть ответ, назовите тип параметра и путь, по которому 7
пройдёт через `switch`.

**Правильный ответ: D.**

Параметр имеет тип `int`, а четыре единицы — обычные константы без
собственного типа, поэтому 7 законно попадает в функцию. `switch`
сравнивает 7 с 0, 1, 2 и 3, совпадения нет, ветки `default` тоже нет, и
выполнение доходит до `return ""` после `switch`. Вариант A ждёт от набора
констант проверки, которой язык не делает. Вариант B приписывает `switch`
поиск ближайшего значения, а он проверяет только равенство. Вариант C ждёт
остановки, но останавливать программу нечему. Что означает пустая строка,
решает условие задачи; понятнее вернуть ответ с названием, например
«неизвестная единица».
