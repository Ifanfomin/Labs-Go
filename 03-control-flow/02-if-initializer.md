# Урок: 03-control-flow / 02-if-initializer

# Теория

# if с короткой инструкцией

Интернет-магазин решает, будет ли доставка бесплатной. Для этого он считает
сумму заказа — цену, умноженную на количество, — и сравнивает её с порогом
1000 рублей. Сумма здесь нужна только для решения: после выбора варианта
доставки программа к ней не возвращается. Go позволяет посчитать такое
значение прямо в заголовке `if`, перед условием. Тогда имя этого значения
действует только внутри инструкции `if`, и употребить его по ошибке ниже уже
нельзя.

К концу урока вы сможете:

- сказать, когда выполняется инструкция перед условием, в том числе когда
  условие ложно;
- для каждого употребления имени в заголовке, в ветках `if`, `else if`,
  `else` и после них назвать объявление, к которому оно относится;
- объяснить, чем `if x := …` отличается от `if x = …`, когда снаружи уже
  есть `x`, даже если обе программы входят в одну и ту же ветку;
- починить употребление имени из заголовка после `if` и заголовок с `var`;
- выбрать, где объявить временное значение: в заголовке или перед `if`.

Понадобятся правила трёх уроков. Урок 2.2: `:=` объявляет новую переменную,
`=` меняет уже объявленную. Урок 2.3: имя ищется изнутри наружу, а область
видимости локальной переменной начинается после конца её объявления и
кончается в конце самого внутреннего блока, где она объявлена. Урок 3.1:
`if` выполняет ветку, когда условие истинно, иначе — ветку `else`, если она
есть; цепочка `else if` проверяет условия по порядку. В одном примере
используется `strings.TrimSpace` из урока 2.13.

## Подготовка значения и решение

Сначала обычная запись: переменная `subtotal` объявлена отдельной строкой,
а следующая инструкция `if` принимает по ней решение.

```go

### Example: `01-expanded`

Источник: `examples/01-expanded/`

```go
package main

import "fmt"

func main() {
	price := 400
	qty := 3
	subtotal := price * qty
	if subtotal >= 1000 {
		fmt.Println("сумма", subtotal, "- доставка бесплатно")
	} else {
		fmt.Println("сумма", subtotal, "- доставка 300 рублей")
	}
	fmt.Println("заказ принят")
}

```
```

В этой программе две разные работы. Строка с объявлением суммы готовит
значение — сумму заказа. Инструкция `if` задаёт о нём вопрос «да или нет»:
не меньше ли сумма 1000. Переменная `subtotal` объявлена в теле `main`,
поэтому видна до конца тела. Но программа читает её только внутри
инструкции `if`.

Такое значение можно объявить в заголовке `if`. Между словом `if` и условием
ставится короткая инструкция, за ней — точка с запятой:
`if subtotal := price * qty; subtotal >= 1000 {`. Инструкция до точки с
запятой объявляет `subtotal`, условие после неё читает эту переменную. Имя
из заголовка действует до конца всей инструкции `if`: в условии, в теле ветки
`if` и во всей части `else`. После последней закрывающей скобки оно не
действует.

Прежде чем смотреть следующую программу, вернитесь к программе выше.
Перечислите все места, где она читает `subtotal`. Позволяет ли каждое из них
перенести объявление в заголовок? Следующая программа — перенесённый
вариант, но цена в ней 200 рублей. Скажите также, какая ветка выполнится.

```go

### Example: `02-header`

Источник: `examples/02-header/`

```go
package main

import "fmt"

func main() {
	price := 200
	qty := 3
	if subtotal := price * qty; subtotal >= 1000 {
		fmt.Println("сумма", subtotal, "- доставка бесплатно")
	} else {
		fmt.Println("сумма", subtotal, "- доставка 300 рублей")
	}
	fmt.Println("заказ принят")
}

```
```

В первой программе `subtotal` читали три места: условие и две ветки. Все
три стоят внутри инструкции `if`, поэтому перенос законен, и программа
работает как прежде. Сумма 600 меньше порога, выполнилась ветка `else`, и
`subtotal` в ней видна. Строка после `if` суммы не читает, ей перенос не
мешает.

## Когда выполняется инструкция заголовка

По правилам языка короткая инструкция перед условием выполняется до того,
как вычисляется условие, и её выполнение от исхода этой проверки не
зависит. Когда программа доходит до инструкции `if`, порядок такой:

1. Выполняется инструкция заголовка, один раз.
2. Вычисляется условие.
3. Если оно истинно, выполняется ветка `if`. Если ложно — ветка `else`, а
   если её нет, программа переходит к инструкции после `if`.

Инструкция заголовка не принадлежит ни одной ветке своей инструкции `if`.
Она стоит до выбора ветки и выполняется при любом исходе проверки своего
условия.

Функция `orderSum` ниже печатает строку, когда её вызывают, и возвращает
сумму. В заголовке её вызывают для цены 200 и количества 3, то есть сумма
будет 600, меньше порога. Ветки `else` нет. Прежде чем смотреть вывод,
скажите: напечатает ли программа строку из `orderSum` и сколько раз;
выполнится ли ветка `if`; что будет дальше.

```go

### Example: `03-init-runs`

Источник: `examples/03-init-runs/`

```go
package main

import "fmt"

func orderSum(price int, qty int) int {
	fmt.Println("считаю сумму:", price, "x", qty)
	return price * qty
}

func main() {
	if s := orderSum(200, 3); s >= 1000 {
		fmt.Println("доставка бесплатно, сумма", s)
	}
	fmt.Println("дальше: оформление заказа")
}

```
```

Строка из `orderSum` напечатана один раз: вызов в заголовке выполнился до
проверки. Условие `s >= 1000` оказалось ложным, ветка пропущена. `else` нет,
поэтому программа перешла к последней строке `main`. Ложное условие не
отменяет инструкцию заголовка: к моменту проверки она уже выполнилась.

## Где видно имя из заголовка

Урок 2.3 связывал область видимости с блоками в фигурных скобках. У
инструкции `if` есть ещё один блок — **неявный**. Фигурных скобок у него нет:
он охватывает всю инструкцию `if` целиком. Внутри неявного блока лежат
инструкция заголовка, условие, тело ветки `if` и вся часть `else`. Тела
веток — обычные блоки в фигурных скобках, вложенные в неявный блок.

Объявление из заголовка стоит в неявном блоке. По правилу урока 2.3 имя
действует от конца своего объявления до конца блока, где оно объявлено.
Отсюда ответ для каждого места:

- в условии — действует;
- в теле ветки `if` — действует: это вложенный блок;
- в теле `else` — действует: это тоже вложенный блок;
- после закрывающей скобки последней ветки — не действует: неявный блок
  кончился вместе с инструкцией `if`.

Программа ниже — вариант с ценой 200, к которому после `if` дописали печать
суммы. Прежде чем смотреть сообщение, скажите, соберётся ли она.

```go
@broken after-if
```

Не соберётся: `undefined: subtotal`. Для строки после `if` компилятор ищет
объявление `subtotal` изнутри наружу и не находит его: объявление из
заголовка действовало только внутри неявного блока, а в теле `main` такого
имени нет.

Как чинить, зависит от замысла. Если сумма нужна и после `if`, объявление
возвращается туда, где оно стояло в первой программе: отдельной строкой
`subtotal := price * qty` перед `if`, а заголовок становится обычным условием
`if subtotal >= 1000 {`. Тогда `subtotal` объявлена в теле `main` и видна до
его конца. Заменить в заголовке `:=` на `=` не поможет: `=` ничего не
объявляет, и объявления `subtotal` снаружи по-прежнему не будет.

## Цепочка else if

Запись `else if` — это слово `else`, за которым стоит целая новая инструкция
`if`. У этой вложенной инструкции может быть свой заголовок с короткой
инструкцией. Вложенная инструкция лежит внутри неявного блока первой, поэтому
имя из первого заголовка видно и в её заголовке, и в её условии, и в её
ветках. Имя из второго заголовка видно в её условии, в её ветке и в последнем
`else`: этот `else` принадлежит вложенной инструкции. В первом условии и в
первой ветке второго имени нет: его объявление стоит ниже, во вложенной
инструкции.

Вложенная инструкция вместе со своим заголовком и есть ветка `else` первой
инструкции `if`. Поэтому программа доходит до второго заголовка, только
когда первое условие ложно. Правило из раздела «Когда выполняется
инструкция заголовка» действует для каждой инструкции `if` отдельно: каждый
раз, когда программа доходит до этой инструкции, её заголовок выполняется
один раз, до её собственного условия.

Функция `offer` ниже выбирает сообщение о скидке. От 5000 рублей скидка
есть. Если до неё осталось не больше 1000 рублей, магазин об этом
напоминает. Во втором заголовке `left` — сколько осталось до скидки. Этот
заголовок стоит в ветке `else` первой инструкции, поэтому разность
считается, только когда первое условие ложно. Прежде чем смотреть
вывод, для каждого из трёх вызовов скажите, какая ветка выполнится и какие
значения `sum` и `left` она напечатает.

```go

### Example: `04-else-if`

Источник: `examples/04-else-if/`

```go
package main

import "fmt"

func offer(price int, qty int) {
	if sum := price * qty; sum >= 5000 {
		fmt.Println("сумма", sum, "- скидка 10 процентов")
	} else if left := 5000 - sum; left <= 1000 {
		fmt.Println("сумма", sum, "- до скидки осталось", left)
	} else {
		fmt.Println("сумма", sum, "- скидки нет, до неё", left)
	}
}

func main() {
	offer(1000, 6)
	offer(1000, 4)
	offer(1000, 2)
}

```
```

| Вызов | `sum` | `sum >= 5000` | `left` | `left <= 1000` | Ветка |
|---|---|---|---|---|---|
| `offer(1000, 6)` | 6000 | истинно | не считалась | не проверялось | первая |
| `offer(1000, 4)` | 4000 | ложно | 1000 | истинно | вторая |
| `offer(1000, 2)` | 2000 | ложно | 3000 | ложно | последний `else` |

В первом вызове первое условие истинно, и до второго заголовка программа
не дошла: разность не считалась. Во втором вызове второй заголовок записал в
`left` 1000, и условие `left <= 1000` истинно. Третий вызов дошёл до
последнего `else`. Там видны обе переменные: `sum` из первого заголовка и
`left` из второго.

## Внешняя переменная с тем же именем

Счётчик посещений страницы при каждом просмотре должен увеличиваться на 1,
а после увеличения программа проверяет порог. Две программы ниже
различаются одним знаком в заголовке. В первой стоит `visits := visits + 1`,
во второй — `visits = visits + 1`.

В первой программе заголовок объявляет новую переменную. Справа в этом
объявлении её имя ещё не действует: объявление не кончилось (урок 2.3).
Поэтому `visits` справа называет внешнюю переменную со значением 10.
Прежде чем смотреть вывод, для печати в ветке и печати после `if` назовите
объявление и значение.

```go

### Example: `05-header-declare`

Источник: `examples/05-header-declare/`

```go
package main

import "fmt"

func main() {
	visits := 10
	if visits := visits + 1; visits > 10 {
		fmt.Println("в ветке:", visits)
	}
	fmt.Println("после if:", visits)
}

```
```

| Место | Какое объявление называет `visits` | Значение |
|---|---|---|
| справа в `visits + 1` | внешнее, в теле `main` | 10 |
| `visits := …` в заголовке | объявляет новую переменную в неявном блоке | 11 у новой |
| условие и печать в ветке | из заголовка | 11 |
| печать после `if` | внешнее: неявный блок кончился | 10 |

Увеличение досталось переменной из заголовка и пропало вместе с её
областью видимости: внешний счётчик остался прежним. Компилятор программу
принимает, потому что затенение законно (урок 2.3). Ошибку видно только по
результату.

Теперь вторая программа. Прежде чем смотреть вывод, снова назовите
объявление и значение для обеих печатей.

```go

### Example: `06-header-assign`

Источник: `examples/06-header-assign/`

```go
package main

import "fmt"

func main() {
	visits := 10
	if visits = visits + 1; visits > 10 {
		fmt.Println("в ветке:", visits)
	}
	fmt.Println("после if:", visits)
}

```
```

| Место | Какое объявление называет `visits` | Значение |
|---|---|---|
| справа в `visits + 1` | внешнее | 10 |
| `visits = …` в заголовке | внешнее: `=` ничего не объявляет | внешняя получила 11 |
| условие и печать в ветке | внешнее | 11 |
| печать после `if` | внешнее | 11 |

Обе программы вошли в одну и ту же ветку и напечатали в ней одно и то же.
По строке из ветки их не различить: в первой печать читает переменную из
заголовка, во второй — внешнюю. Разница видна только после `if`.

Заголовок с `=` меняет уже объявленную переменную и нового имени не
создаёт, поэтому изменение остаётся после `if`. Такой заголовок работает,
только если переменная уже объявлена снаружи. Выбирают по замыслу. Счётчик
обязан измениться — нужно присваивание `=`, в заголовке или отдельной
строкой перед `if`. Значение нужно только для проверки — подходит новая
переменная через `:=`, лучше с другим именем, например
`if next := visits + 1; next > 10 {`: тогда читателю не приходится держать в
голове две переменные `visits`.

## Объявление в теле ветки

Тело ветки — блок, вложенный в неявный блок `if`. Поэтому `:=` с тем же
именем в теле ветки законно объявляет ещё одну переменную. Она затеняет имя
из заголовка только в этом теле и только ниже своей строки. Присваивание `=`
в теле ищет ближайшее объявление изнутри наружу. Если выше этой строки в
теле нет своего объявления, находится имя из заголовка, и меняется оно.

Функция `show` ниже вызывается дважды: с 5, когда выполнится ветка `if`, и с
2, когда выполнится `else`. В ней три переменные с именем `x`: внешняя в теле
функции, из заголовка и объявленная в теле ветки `if`. Прежде чем смотреть
вывод, для каждой печати назовите объявление и значение.

```go

### Example: `07-body-shadow`

Источник: `examples/07-body-shadow/`

```go
package main

import "fmt"

func show(a int) {
	x := 1
	if x := a; x > 3 {
		fmt.Println("if, до объявления:", x)
		x := 100
		fmt.Println("if, после объявления:", x)
	} else {
		x = x - 10
		fmt.Println("else:", x)
	}
	fmt.Println("после if:", x)
}

func main() {
	show(5)
	show(2)
}

```
```

| Печать | Какая `x` | `show(5)` | `show(2)` |
|---|---|---|---|
| первая в ветке `if` | из заголовка | 5 | не выполняется |
| вторая в ветке `if` | из тела ветки, после `x := 100` | 100 | не выполняется |
| в `else` | из заголовка, после `x = x - 10` | не выполняется | -8 |
| после `if` | внешняя | 1 | 1 |

В ветке `if` первая печать стоит выше строки `x := 100`, поэтому в ней `x`
называет переменную из заголовка. После этой строки имя называет новую
переменную тела. В ветке `else` своего объявления нет. Присваивание
`x = x - 10` относится к `x` из заголовка и меняет её, а внешнюю не трогает.
После `if` оба вызова печатают внешнюю `x`: её не меняла ни одна строка.

На выходе из фигурных скобок ничего не копируется наружу. У каждой из трёх
переменных своё значение. Закрывающая скобка только заканчивает область
видимости имени, объявленного внутри.

## Какие инструкции можно поставить в заголовок

Перед условием стоит **простая инструкция** — так правила языка называют
инструкции, допустимые в заголовке. Простые инструкции — это, например,
короткое объявление `:=`, присваивание вроде `count = count + 1` или
`count += 2`, увеличение `count++` и вызов функции отдельной инструкцией.
Любая из них выполняется до условия по правилу из раздела «Когда выполняется
инструкция заголовка». Из простых инструкций только `:=` объявляет новое
имя. Самый частый и полезный случай — именно он: новое временное имя,
которое нужно только этому решению.

Объявление через `var` простой инструкцией не является, и в заголовке его
быть не может. Программа ниже пытается объявить сумму так. Прежде чем
смотреть сообщение, скажите, что ответит компилятор.

```go
@broken var-header
```

Сообщение `syntax error: var declaration not allowed in if initializer`
говорит, что объявление `var` в заголовке `if` не допускается. По грамматике
языка перед условием может стоять только простая инструкция, а объявление
`var` к ним не относится, поэтому компилятор сообщает о синтаксической
ошибке. Починка сохраняет и сумму, и порог. Можно написать в заголовке
`subtotal := price * qty`. Можно вынести `var subtotal = price * qty`
отдельной строкой перед `if` — тогда `subtotal` будет видна и после него.

## Где объявить временное значение

Короткая инструкция в заголовке — не обязательная форма, а способ
ограничить имя теми местами, где оно нужно. Место объявления выбирают по
употреблениям значения:

- значение нужно только в условии и в ветках этой инструкции `if` — удобно
  объявить его в заголовке через `:=`: после `if` имени нет, и употребить его
  там по ошибке нельзя;
- значение нужно и после `if` — объявите его отдельной строкой перед `if`;
- нужно изменить переменную, объявленную раньше, — нужно присваивание `=`,
  в заголовке или отдельной строкой; `:=` создал бы новую переменную, и
  изменение пропало бы после `if`.

Отделять подготовку от решения полезно и в заголовке. Короткая инструкция
выдаёт готовое значение, например строку без пробелов по краям. Условие
задаёт о нём вопрос «да или нет». Программа ниже очищает имя через
`strings.TrimSpace` и проверяет, осталось ли что-нибудь. Строка `raw`
состоит из трёх пробелов. Прежде чем смотреть вывод, скажите, какая ветка
выполнится и что окажется в `name`.

```go

### Example: `08-trim-header`

Источник: `examples/08-trim-header/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	raw := "   "
	if name := strings.TrimSpace(raw); name != "" {
		fmt.Println("имя:", name)
	} else {
		fmt.Println("имя пустое, его длина", len(name))
	}
}

```
```

`strings.TrimSpace` выполнился до условия и вернул пустую строку. Условие
`name != ""` ложно, и в `else` имя `name` называет эту пустую строку. В этой
программе `name` нужна только внутри `if`, поэтому заголовок подходит. Если
бы очищенное имя понадобилось после `if`, например для приветствия, его
объявление стояло бы перед `if`.

## Чего этот урок не разбирает

Короткая инструкция бывает и в заголовках других конструкций, но у них свои
правила:

- заголовок `switch` — урок 3.3;
- переменные в заголовке цикла `for` — уроки 3.5 и 3.7;
- строки с несколькими именами слева от `:=` — урок 3.6.

# Разбор неверных решений

## Где объявить очищенный ответ в Reply

<!-- review:reply-where-declared -->

Очищенное значение нужно в двух сравнениях — с `да` и с `нет` — и больше
нигде: результат функции зависит только от того, какое сравнение оказалось
истинным. После `if` очищенная строка не нужна. Поэтому подходит заголовок:
`if clean := strings.TrimSpace(answer); clean == "да" {`, а дальше
`} else if clean == "нет" {`. Имя `clean` из первого заголовка видно и в
условии `else if`: вложенная инструкция `if` лежит в неявном блоке первой.

Так же законно объявить `clean := strings.TrimSpace(answer)` отдельной
строкой перед `if`. Тогда имя видно до конца функции, хотя там оно не нужно.
Оба решения возвращают одно и то же, и проверка их не различает. Результат
удобно держать в переменной `result`, объявленной перед `if` со значением
`ответ не распознан`: ветки меняют её через `=`, а `return result` стоит
после `if`. Можно и вернуть строку прямо из каждой ветки.

Неверные варианты `Reply` ловит `TestReply`; два из них разобраны ниже.

## Второе сравнение по неочищенному ответу

<!-- review:reply-raw-else-if -->

Частая попытка: первое сравнение читает `clean` из заголовка, а второе
написано как `else if answer == "нет"`, будто в `else if` имени `clean` уже
нет. Код собирается, но `Reply(" нет ")` возвращает `ответ не распознан`:
`answer` сохранил пробелы по краям.

Ловит это `TestReply` на ответе с пробелами вокруг `нет`.

Имя из первого заголовка действует во всей цепочке, поэтому второе
сравнение должно читать `clean`: `else if clean == "нет"`. Первый заголовок
выполнился один раз до первого условия, и его результат `clean` виден во
всех условиях цепочки.

## Ответ сравнивают без очистки

<!-- review:reply-no-trim -->

Если сравнивать `answer` с `да` и `нет` напрямую, `Reply("  да\n")`
возвращает `ответ не распознан`. Ловит это `TestReply`. Подготовка значения —

## Почему заготовка AddPoints возвращает старый баланс

<!-- review:starter-lost-update -->

В заготовке заголовок `points := points + purchase/10` объявляет новую
переменную в неявном блоке `if`. Справа её имя ещё не действует, поэтому
`points` справа — параметр. Сумма попадает в переменную из заголовка, и
предел 500 в ветке — тоже в неё. После `if` её имени уже нет, и `return points`
читает параметр, который никто не менял. Поэтому `AddPoints(100, 250)`
возвращает 100, а `AddPoints(480, 500)` — 480. Сборка проходит: переменная из
заголовка прочитана в условии, а затенение параметра во вложенном блоке
законно.

Ловят это `TestAddPointsBelowCap` и `TestAddPointsCapped`: заготовка
возвращает исходный баланс при обоих исходах условия.

Чинить надо задуманную операцию — изменить баланс, который возвращает
`return`. Самый короткий ремонт — присваивание в заголовке:
`if points = points + purchase/10; points > 500 {`. Заголовок перестаёт
объявлять имя, сумма ложится в параметр, и строка `points = 500` в ветке
тоже меняет параметр. Годится и другой законный ремонт: объявить
`total := points + purchase/10` перед `if`, в ветке написать `total = 500` и
вернуть `total`. Не соберётся попытка вернуть после `if` имя, объявленное в
заголовке: там оно уже не действует.

## Имя в заголовке переименовали

<!-- review:addpoints-renamed-header -->

Попытка убрать совпадение имён: `if total := points + purchase/10; total > 500`
с `total = 500` в ветке и прежним `return points`. Сборка проходит, но
функция по-прежнему возвращает исходный баланс.

Ловит это `TestAddPointsBelowCap` на первом же входе: 100 вместо 125.

Переименование убрало затенение, но не причину. Сумма всё так же лежит в
переменной из заголовка, а `return` читает параметр. Ошибка не в
совпадении имён, а в том, что результат попадает не в ту переменную,
которую возвращает функция.

## 500 вернули прямо из ветки

<!-- review:addpoints-return-in-branch -->

В этом варианте ветка написана как `return 500`, а заголовок остался с `:=`.
Когда сумма больше 500, функция действительно возвращает 500: `return` в
ветке заканчивает её сразу. Но когда сумма не больше 500, выполнение доходит
до `return points` после `if`, а там снова параметр без начисленных баллов.

Ловит это `TestAddPointsBelowCap`: `AddPoints(100, 250)` возвращает 100.
`TestAddPointsCapped` этот вариант проходит — поэтому тестов два, по одному
на каждый исход условия.

Ремонт должен работать в обоих исходах. Сумма нужна и после `if`, значит,
её нельзя держать только в переменной из заголовка. Оба ремонта из раздела
«Почему заготовка AddPoints возвращает старый баланс» это выполняют.

## Сумму посчитали перед if, а предел записали в параметр

<!-- review:addpoints-cap-lost -->

Попытка перенести подготовку из заголовка: `total := points + purchase/10`
отдельной строкой, затем `if total > 500 { points = 500 }` и `return total`.
Когда предел не нужен, функция верна. Когда нужен, строка в ветке меняет
параметр, а возвращается `total` — без предела.

Ловит это `TestAddPointsCapped`: `AddPoints(480, 500)` возвращает 530.
`TestAddPointsBelowCap` этот вариант проходит.

Объявление перед `if` здесь уместно: сумма нужна после `if`. Но и ветка, и
`return` должны работать с одной переменной: `total = 500` в ветке и
`return total`.

Что напечатает программа?

Варианты ответа:

- A. Только последнюю строку `main`: при ложном условии заголовок
  пропускается.
- B. Строку из `price`, затем последнюю строку `main`: заголовок выполнился,
  ветка пропущена.
- C. Строку из `price`, строку о скидке и последнюю строку `main`: раз
  заголовок выполнился, выполнится и ветка.
- D. Строку из `price` дважды — для условия и для ветки, — затем последнюю
  строку `main`.

Прежде чем смотреть ответ, выпишите по шагам, что выполняется, и чему равна
`total`.

**Правильный ответ: B.**

Заголовок выполняется один раз до условия при любом исходе: `price(2)`
печатает строку и возвращает 300. Условие `300 > 1000` ложно, `else` нет.
Вариант A делает заголовок частью ветки. Вариант C путает выполнение
заголовка с выбором ветки. Вариант D вызывает функцию заново, хотя условие
читает сохранённую `total`.

## Вопрос 3

Программа должна проверить очищенное имя и после проверки поздороваться по

```go
@quiz _broken/q-after-name
```

Какой ремонт сохраняет замысел?

Варианты ответа:

- A. В заголовке заменить `:=` на `=`, чтобы имя осталось после `if`.
- B. В каждой ветке первой строкой объявить `name := strings.TrimSpace(raw)`.
- C. Перенести последнюю печать в ветку `else`, где `name` видна.

Прежде чем смотреть ответ, назовите места, где нужно очищенное имя, и где

## Вопрос 4

Функции различаются одним знаком в заголовке, входят в ветку `if` и
печатают там одно и то же.

```go
@quiz _quiz/04-stock
```

Что каждая напечатает после `if`?

Варианты ответа:

- A. `withDeclare` — 3, `withAssign` — 2: `:=` объявил новую `stock`, а `=`
  изменил внешнюю.
- B. Обе — 2: в ветке обе напечатали 2, значит, запас уменьшился в обеих.
- C. `withDeclare` — 2, `withAssign` — 3: `:=` меняет переменную, а `=`
  работает с копией внутри `if`.
- D. `withDeclare` не соберётся: `stock` объявлена в функции дважды.

Прежде чем смотреть ответ, скажите, сколько переменных `stock` в каждой
функции и какую читает печать после `if`.

**Правильный ответ: A.**

В `withDeclare` две переменные: 2 легло в переменную заголовка, а после
`if` видна внешняя с прежним 3. В `withAssign` переменная одна, и `=`
записал 2 в неё. Вариант B судит по строке из ветки, а там обе функции
печатают 2 из разных переменных. Вариант C меняет роли знаков. Вариант D
забывает, что заголовок стоит в неявном блоке `if`, вложенном в тело
функции.

## Вопрос 5

```go
@quiz _quiz/05-chain
```

Что будет, если собрать и запустить программу?

Варианты ответа:

- A. Не соберётся: во втором заголовке `t` уже не видна.
- B. Не соберётся: в последнем `else` не видна `d`.
- C. Напечатается строка второй ветки с 12 и 8: `t` видна во втором
  заголовке и во второй ветке.
- D. Не соберётся: короткая инструкция бывает только у первого `if`
  цепочки.

Прежде чем смотреть ответ, назовите для каждого употребления `t` и `d`
заголовок с объявлением и вычислите значения.

**Правильный ответ: C.**

`else if` — это `else` и вложенная инструкция `if` в неявном блоке первой,
поэтому `t` видна в ней всюду, а `d` — в её условии, ветке и `else`.
`14 - 2` даёт 12, условие `12 > 20` ложно, поэтому программа доходит до
вложенной инструкции и выполняет её заголовок: `20 - 12` даёт 8, и `8 > 5`
истинно. Вариант A кончает область `t` на первой ветке. Вариант B не
относит последний `else` к вложенной инструкции. Вариант D неверен: у
вложенной инструкции тоже может быть свой заголовок, и второй заголовок
этой программы — как раз такой.

## Вопрос 6

```go
@quiz _quiz/06-body-shadow
```

Что напечатают вызовы `check(4)` и `check(1)` в ветке и после `if`?

Варианты ответа:

- A. В ветке 108, после `if` 108; в ветке 3, после `if` 3: значения
  выходят наружу, когда закрывается `}`.
- B. В ветке 108, после `if` 0; в ветке 3, после `if` 0: внешнюю `count`
  не меняет ни одна строка.
- C. В ветке 108, после `if` 0; в ветке 3, после `if` 3: `=` в `else`
  меняет внешнюю `count`.
- D. Не соберётся: в ветке `if` имя `count` объявлено второй раз в том же
  блоке, что и в заголовке.

Прежде чем смотреть ответ, назовите для каждого `count` объявление:
внешнее, из заголовка или из тела ветки.

**Правильный ответ: B.**

Тело ветки — вложенный блок, и `count := count + 100` законно объявляет
третью переменную; справа ещё видна `count` из заголовка, 8. В `else`
присваивание находит ближайшее объявление — заголовок: 2 + 1. После
условной инструкции оба вызова печатают внешнюю переменную: 0. Вариант A
придумывает копирование на выходе из блока. Вариант C пропускает заголовок
при поиске объявления. Вариант D считает тело ветки и заголовок одним
блоком.

- B. `if var total int = price * qty; total >= 1000 {`
- C. Убрать объявление из заголовка и первой строкой ветки `if` написать
  `total := price * qty`.

## Вопрос 8

Функция очищает `raw` через `strings.TrimSpace`, проверяет, пуст ли
результат, и в каждой ветке возвращает строку из очищенного значения. После
`if` это значение не нужно. Какое утверждение о месте объявления верно?

Варианты ответа:

- A. Подходят и заголовок `if clean := strings.TrimSpace(raw); clean != "" {`,
  и строка перед `if`; заголовок ограничивает имя местами, где оно нужно.
- B. Только заголовок: значение для условия обязано готовиться короткой
  инструкцией.
- C. Только строка перед `if`: в заголовке допустима арифметика, но не
  вызов функции.
- D. Ни то ни другое: `else` не видит имя из заголовка, а перед `if`
  временное значение объявлять нельзя.

Прежде чем смотреть ответ, перечислите места, где нужно очищенное
значение, и скажите, что изменилось бы, понадобись оно после `if`.

**Правильный ответ: A.**

Значение нужно только в условии и ветках, поэтому законны оба места, а
заголовок не даст употребить имя после `if` по ошибке. Понадобись значение
после `if`, осталось бы только объявление перед ним. Вариант B выдаёт
удобную форму за правило языка. Вариант C неверен: вызов в заголовке
законен, как `strings.TrimSpace` в разделе «Где объявить временное
значение». Вариант D отрезает `else` от неявного блока.
