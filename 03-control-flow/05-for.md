# Цикл for

Сколько цифр в числе 305? Человек отвечает так: отрезает последнюю цифру и
считает её, потом отрезает следующую — и так, пока от числа что-то
остаётся. Одно и то же действие повторяется, а между повторами меняется
состояние: число становится короче, счёт растёт. В Go такую работу
выполняет цикл `for`. Он повторяет блок инструкций — **тело цикла** — и
по условию решает, повторять ли его ещё раз.

Главный навык этого урока — следить за состоянием цикла шаг за шагом:
какие значения лежат в переменных перед каждым повтором и какая инструкция
выполнится следующей. К концу урока вы сможете:

- проследить выполнение цикла, в том числе когда тело не выполняется ни
  разу;
- назвать инструкцию, которая выполнится сразу после `continue` и сразу
  после `break`;
- найти в цикле шаг, который не выполняется или меняет не ту переменную, и
  исправить его;
- объяснить, где виден счётчик цикла и чему он равен после цикла;
- решить, где ставить проверку — до тела или после него, — и обосновать
  выбор;
- объяснить, почему цикл заканчивается на всех допустимых входах.

## Как выполняется трёхчастный for

Самая полная запись цикла — с заголовком из трёх частей, разделённых
точками с запятой: `for i := 0; i < 3; i++ { … }`. У каждой части своя
роль:

- **инструкция инициализации** `i := 0` выполняется один раз, до всего
  остального; обычно она заводит счётчик;
- **условие** `i < 3` вычисляется перед каждым входом в тело: если оно
  `true`, выполняется тело, если `false` — цикл заканчивается, и
  управление переходит к инструкции, которая стоит после цикла;
- **завершающая инструкция** `i++` выполняется после тела, перед следующей
  проверкой условия.

Один вход в тело называется **итерацией**. Итерации считают именно по
входам в тело, а не по напечатанным строкам: тело может выполниться и
ничего не напечатать.

`i++` — инструкция из урока 2.10: она увеличивает `i` на единицу. Значения
у неё нет, поэтому её пишут отдельно, а не внутри выражения. Завершающей
инструкцией может быть и другое простое действие: `i--`, `i += 2` или
присваивание вида `i = next(i)`.

В программе ниже каждая часть заголовка вызывает функцию, которая
печатает, что происходит: инструкция инициализации вызывает `start`,
условие — `check`, завершающая инструкция — `next`. Прежде чем смотреть
вывод, предскажите, сколько строк напечатает условие, сколько — тело и
каким будет результат последней проверки.

```go

### Example: `01-trace`

Источник: `examples/01-trace/`

```go
package main

import "fmt"

// start вызывается из инструкции инициализации.
func start() int {
	fmt.Println("инициализация: i получает 0")
	return 0
}

// check вызывается из условия и возвращает результат сравнения.
func check(i int) bool {
	fmt.Println("условие:", i, "< 3 —", i < 3)
	return i < 3
}

// next вызывается из завершающей инструкции и возвращает новое значение.
func next(i int) int {
	fmt.Println("завершающая инструкция: i становится", i+1)
	return i + 1
}

func main() {
	for i := start(); check(i); i = next(i) {
		fmt.Println("тело при i =", i)
	}
	fmt.Println("[после цикла]")
}

```
```

Условие вычислялось четыре раза, а тело выполнилось три раза. После каждой
из трёх проверок с результатом `true` шли тело и завершающая инструкция.
Четвёртая проверка дала `false`, и управление ушло за цикл, не заходя в
тело. Инструкция инициализации выполнилась один раз — в самом начале.

Порядок целиком: инициализация, а затем по кругу — условие, тело,
завершающая инструкция. Круг обрывается, когда условие ложно.

## Где виден счётчик

Переменная, объявленная через `:=` в инструкции инициализации, видна
только внутри инструкции `for`: в условии, в завершающей инструкции и в
теле. Язык считает каждый `for` отдельным неявным блоком — это те же блоки
и та же область видимости, что в уроке 2.3. За закрывающей фигурной
скобкой цикла такой переменной уже нет:

```go
@broken scope
```

Компилятор печатает `undefined: i` — то же сообщение, что и для имени,
которое не объявлено нигде: для кода после цикла счётчика из заголовка не
существует.

Если значение счётчика нужно после цикла, переменную объявляют до цикла, а
инструкция инициализации только присваивает ей начальное значение: сначала
`var i int`, затем `for i = 0; i < 3; i++`. Такая переменная принадлежит
блоку функции. После цикла в ней лежит значение, которое оставила
последняя выполненная завершающая инструкция. Так счётчик объявлен в
нескольких программах ниже.

У счётчика из заголовка есть ещё одна особенность: на каждой итерации это
отдельная переменная. Первую объявляет инструкция инициализации. Каждую
следующую Go объявляет перед завершающей инструкцией и кладёт в неё
значение, которое было у предыдущей в этот момент. Поэтому значение,
которое тело присвоит счётчику, не теряется: завершающая инструкция
продолжит с него. Прежде чем смотреть вывод, предскажите, при каких
значениях `i` тело напечатает строку.

```go

### Example: `02-body-assign`

Источник: `examples/02-body-assign/`

```go
package main

import "fmt"

func main() {
	for i := 0; i < 6; i++ {
		fmt.Println("тело при i =", i)
		if i == 1 {
			i = 3 // тело меняет счётчик
		}
	}
}

```
```

На второй итерации тело присвоило `i` значение 3, завершающая инструкция
превратила его в 4, и итераций со значениями 2 и 3 не было. В программах
этого урока то, что переменные на каждой итерации разные, на результат не
влияет. Разница видна только в коде, который сохраняет саму переменную,
чтобы использовать её позже, — например, в замыкании; это тема уроков
5.5–5.7.

## Ноль, одна или много итераций

Условие проверяется **до** тела. Если оно ложно с самого начала, тело не
выполнится ни разу. Завершающая инструкция тогда тоже не выполнится: она
идёт только после тела.

Функция `run` в программе ниже проходит цикл до предела `limit`.
Переменная `entries` считает входы в тело. Счётчик `i` объявлен до цикла и
начинается с нуля, поэтому после цикла он равен числу выполнений `i++`.
Прежде чем смотреть вывод, предскажите оба числа для пределов 0, 1 и 3.

```go

### Example: `03-counts`

Источник: `examples/03-counts/`

```go
package main

import "fmt"

// run проходит цикл до предела limit. entries считает входы в тело,
// а i после цикла равно числу выполнений i++.
func run(limit int) string {
	entries := 0
	var i int
	for i = 0; i < limit; i++ {
		entries++
	}
	return fmt.Sprintf("предел %d: входов в тело %d, выполнений i++ %d", limit, entries, i)
}

func main() {
	fmt.Println(run(0))
	fmt.Println(run(1))
	fmt.Println(run(3))
}

```
```

При пределе 0 первая же проверка дала `false`: ноль входов в тело и ноль
выполнений `i++`. При пределе 1 итерация одна, при пределе 3 — три. В
каждой строке оба числа совпали. Они совпадают у любого трёхчастного
цикла, который закончился по ложному условию, без `break` и без `return`:
за каждым входом в тело следует ровно одна завершающая инструкция. Проверок
условия при этом на одну больше, чем входов в тело: последняя проверка,
ложная, и заканчивает цикл.

## continue: к завершающей инструкции

Бывает, что на части итераций остаток тела не нужен. Для этого есть
`continue`: он обрывает текущую итерацию на месте. Инструкции тела,
стоящие ниже `continue`, на этой итерации не выполняются. Управление
переходит в конец тела — туда же, куда приходит тело, выполненное до
конца. Поэтому дальше всё идёт обычным путём: завершающая инструкция,
затем проверка условия.

Прежде чем смотреть вывод, для каждого `i` от 0 до 4 скажите, дойдёт ли
итерация до печати. Затем предскажите три числа после цикла: входы в тело,
итерации, дошедшие до конца тела, и выполнения `i++`.

```go

### Example: `04-continue`

Источник: `examples/04-continue/`

```go
package main

import "fmt"

func main() {
	entries := 0
	finished := 0
	var i int
	for i = 0; i < 5; i++ {
		entries++
		if i%2 == 1 {
			continue
		}
		finished++
		fmt.Println("конец тела при i =", i)
	}
	fmt.Println("[после цикла] входов в тело:", entries)
	fmt.Println("[после цикла] дошло до конца тела:", finished)
	fmt.Println("[после цикла] выполнений i++:", i)
}

```
```

В тело вошли пять раз, и `i++` выполнилась пять раз: на нечётных `i`
сработал `continue`, но завершающая инструкция выполнилась и на этих
итерациях. До конца тела дошли только три итерации. `continue` сокращает
не число итераций и не число выполнений завершающей инструкции, а только
то, сколько раз выполнился остаток тела. Равенство из предыдущего раздела
— входов в тело столько же, сколько выполнений завершающей инструкции, —
для цикла с `continue` сохраняется.

## break: сразу за цикл

`break` заканчивает весь цикл. Управление переходит к первой инструкции
после цикла, а завершающая инструкция на оборванной итерации не
выполняется. Функцию `break` не завершает: инструкции после цикла в той же
функции выполнятся как обычно. Завершает функцию `return` (урок 1.7), и
это другая инструкция.

Прежде чем смотреть вывод, найдите итерацию, на которой сработает `break`,
и предскажите значение `i` после цикла.

```go

### Example: `05-break`

Источник: `examples/05-break/`

```go
package main

import "fmt"

func main() {
	var i int
	for i = 0; i < 5; i++ {
		fmt.Println("вход в тело при i =", i)
		if i == 2 {
			break
		}
		fmt.Println("конец тела при i =", i)
	}
	fmt.Println("[после цикла] i =", i)
}

```
```

В тело вошли три раза, а `i++` выполнилась два раза: на третьей итерации
`break` увёл управление за цикл раньше, чем очередь дошла до завершающей
инструкции. Поэтому после цикла `i` равно 2 — значению, при котором
сработал `break`. Значит, у цикла с `break` входов в тело может быть
больше, чем выполнений завершающей инструкции.

В этом уроке циклы не вложены друг в друга, поэтому `break` и `continue`
относятся к тому циклу, в теле которого стоят. Вложенные циклы и метки
разбирает урок 3.8.

## Цикл с одним условием

Счётчик нужен не всякому циклу. Вернитесь к цифрам числа 305 из начала
урока. Для них пригодятся две операции урока 2.10 над целыми числами:

- `n % 10` — остаток от деления на 10, то есть последняя десятичная
  цифра: `305 % 10` равно 5;
- `n / 10` — деление нацело: дробная часть отбрасывается, и последняя
  цифра пропадает: `305 / 10` равно 30.

Сколько раз повторять, заранее неизвестно: пока от числа что-то осталось,
то есть пока `n > 0`. Для такого случая в заголовке оставляют только
условие: `for n > 0 { … }`. Инструкции инициализации и завершающей
инструкции нет, и точки с запятой не пишут. Условие, как и раньше,
проверяется перед каждым входом в тело. А изменение состояния, которое
когда-нибудь сделает условие ложным, записывают в теле; в подсчёте цифр это
`n /= 10`.

Прежде чем смотреть вывод, для каждой итерации назовите `n`, его последнюю
цифру и число без неё, а затем число цифр.

```go

### Example: `06-digits`

Источник: `examples/06-digits/`

```go
package main

import "fmt"

func main() {
	n := 305
	count := 0
	for n > 0 {
		fmt.Println("n =", n, "последняя цифра", n%10, "без неё", n/10)
		n /= 10
		count++
	}
	fmt.Println("[после цикла] цифр:", count, "n =", n)
}

```
```

На второй итерации последняя цифра — 0: ноль внутри числа такая же цифра,
и цикл её посчитал. После третьей итерации `n` стало нулём, условие
`n > 0` оказалось ложным, и цикл закончился. Переменная `n` объявлена до
цикла, поэтому после цикла видно её последнее значение.

## Почему цикл заканчивается

Цикл заканчивается сам, только если тело меняет состояние так, что
условие когда-нибудь станет ложным. Окончание цикла подсчёта цифр из
раздела «Цикл с одним условием» доказывается в три шага:

1. **Переменная прогресса** — то, что меняется на каждой итерации: в
   подсчёте цифр это `n`.
2. **Направление** — как она меняется. Для положительного `n` частное
   `n / 10` меньше `n`, поэтому `n` строго уменьшается и не становится
   отрицательным.
3. **Условие остановки** — чего она достигнет. Целое число не может
   уменьшаться бесконечно, оставаясь положительным, поэтому `n` дойдёт до
   нуля, и `n > 0` станет ложным.

Такое рассуждение верно на определённой области входов. Для подсчёта цифр
это любое `n`, не меньшее нуля; при нуле тело не выполнится ни разу. Если
ломается хотя бы один шаг — переменная прогресса на какой-то итерации не
меняется или меняется не в ту сторону, — цикл может не закончиться
никогда. Две такие поломки разобраны в разделах «continue пропускает шаг»
и «Затенённый шаг».

Чтобы программы с такими поломками всё же останавливались, в них есть
сторож: переменная `steps` считает итерации, и после заданного предела
цикл обрывается. Сторож нужен только для того, чтобы пример завершился и
показал, что происходило; правильному циклу он не нужен.

## continue пропускает шаг

У цикла с одним условием нет завершающей инструкции. Шаг, который
приближает остановку, стоит в теле. Если `continue` стоит выше шага, он
пропускает шаг вместе с остальным телом. Проверка условия идёт сразу за
`continue`, а состояние осталось прежним.

смотреть вывод, пройдите итерации по порядку. Что произойдёт, когда `i`
станет равным 1? Сработает ли сторож, и каким будет `i` после цикла?

```go

### Example: `07-skipped-step`

Источник: `examples/07-skipped-step/`

```go
package main

import "fmt"

// Цикл должен напечатать числа от 0 до 2, пропустив 1.
// steps — сторож: без него программа не остановилась бы.
func main() {
	i := 0
	steps := 0
	for i < 3 {
		steps++
		if steps > 10 {
			fmt.Println("сторож: больше 10 проходов, цикл прерван")
			break
		}
		if i == 1 {
			continue
		}
		fmt.Println("печатаю", i)
		i++
	}
	fmt.Println("[после цикла] i =", i, "проходов:", steps)
}

```
```

На второй итерации `i` равно 1, срабатывает `continue`, и `i++` ниже него
не выполняется. Условие `i < 3` снова истинно, `i` по-прежнему равно 1 — и
всё повторяется. Переменная прогресса перестала меняться, и цикл сам не
закончился бы: его остановил сторож.

Прежде чем читать дальше, предложите исправление, после которого цикл
напечатает 0 и 2 и закончится сам.

Исправлений два. Первое — перенести шаг в заголовок трёхчастного цикла:
`continue` переходит в конец тела, а за концом тела выполняется
завершающая инструкция. Второе — оставить цикл с одним условием, но
выполнить шаг до `continue`: запомнить текущее значение `i` в отдельной
переменной и сразу увеличить `i`. Обе функции ниже печатают одни и те же
числа:

```go

### Example: `08-step-repaired`

Источник: `examples/08-step-repaired/`

```go
package main

import "fmt"

// inHeader: шаг i++ стоит в заголовке, и continue до него доходит.
func inHeader() {
	for i := 0; i < 3; i++ {
		if i == 1 {
			continue
		}
		fmt.Println("шаг в заголовке: печатаю", i)
	}
}

// beforeContinue: шаг выполняется до continue на каждом проходе.
func beforeContinue() {
	i := 0
	for i < 3 {
		current := i
		i++
		if current == 1 {
			continue
		}
		fmt.Println("шаг до continue: печатаю", current)
	}
}

func main() {
	inHeader()
	beforeContinue()
}

```
```

Что выполняется сразу после конца тела, после `continue` и после `break`:

| Откуда | Трёхчастный цикл | Цикл с одним условием |
|---|---|---|
| конец тела | завершающая инструкция, затем условие | условие |
| `continue` | завершающая инструкция, затем условие | условие |
| `break` | первая инструкция после цикла | первая инструкция после цикла |

Правило одно для обеих записей: `continue` пропускает всё, что стоит ниже
него в теле. Записи отличаются только тем, где стоит шаг. Шаг в заголовке
`continue` не пропускает, а шаг в теле пропускает, если стоит ниже
`continue`.

## Затенённый шаг

Шаг может выполняться и всё равно не двигать цикл, если меняет не ту
переменную. Урок 2.3 показывал: объявление `:=` во внутреннем блоке
создаёт новую переменную, и она **затеняет** внешнюю с тем же именем. Тело
цикла — такой внутренний блок. В инструкции `n := n / 10` правая часть
читает внешнюю `n`, а результат попадает в новую, внутреннюю. Условие в
заголовке проверяет внешнюю переменную, а она не меняется.

Обычно такая программа не собирается, потому что внутренняя переменная
нигде не используется:

```go
@broken shadow-unused
```

Сообщение `declared and not used: n` говорит о внутренней `n`: её
объявили и ни разу не прочитали. Но если внутреннюю переменную где-нибудь
использовать, например напечатать, программа соберётся. Прежде чем
смотреть вывод, предскажите, что напечатает каждая итерация и чему будет
равна внешняя `n` после цикла.

```go

### Example: `09-shadow`

Источник: `examples/09-shadow/`

```go
package main

import "fmt"

// steps — сторож: без него программа не остановилась бы.
func main() {
	n := 123
	steps := 0
	for n > 0 {
		steps++
		if steps > 3 {
			fmt.Println("сторож: больше 3 проходов, цикл прерван")
			break
		}
		n := n / 10 // новая переменная, а не шаг
		fmt.Println("внутреннее n =", n)
	}
	fmt.Println("[после цикла] внешнее n =", n)
}

```
```

Каждая итерация заново делила внешнюю `n`, равную 123, и получала 12.
Внешняя переменная не менялась, и цикл остановил сторож. Исправление —
присвоить, а не объявить: `n /= 10` или `n = n / 10` меняют ту `n`,
которую проверяет условие.

В трёхчастном цикле такое затенение не делает цикл бесконечным:
`i := i * 10` в теле создаёт новую переменную, а завершающая инструкция
по-прежнему увеличивает счётчик из заголовка. Но и там значение,
вычисленное во внутренней переменной, в следующую итерацию не попадёт.

## Какие части заголовка можно опустить

Любую часть трёхчастного заголовка можно оставить пустой, но обе точки с
запятой при этом остаются: `for ; i < 3; i++` — без инструкции
инициализации, `for i := 0; i < 3; {` — без завершающей инструкции. Точки
с запятой не пишут, когда нет ни инструкции инициализации, ни
завершающей инструкции: тогда в заголовке остаётся одно условие — это
цикл с одним условием — или не остаётся ничего — это цикл без условия, о
нём ниже. `gofmt` (урок 1.10) сам переписывает `for ; i < 3; {` в
`for i < 3 {`.

Условие тоже можно опустить. Отсутствующее условие язык считает равным
`true`, поэтому `for { … }` повторяет тело, пока управление не покинет
цикл; из изученного к этому уроку это делают `break` и `return`.
Заголовок `for ;; {` `gofmt` переписывает в `for {`.

Инструкция инициализации может объявить переменную через `:=` или
присвоить значение уже объявленной через `=`, как в программах выше.
Завершающая инструкция объявлять переменные не может:

```go
@broken postdecl
```

Сообщение `syntax error: cannot declare in post statement of for loop`
называет правило целиком: в завершающей инструкции цикла объявлять
нельзя. Для шага нужно присваивание: `i++`, `i += 1` или `i = i + 1`.

В этом уроке три записи цикла: трёхчастная, с одним условием и без
условия. Спецификация Go делит `for` на формы иначе: с условием (в том
числе опущенным), с трёхчастным заголовком и с `range`. Запись с `range` —
отдельная форма, её разбирает урок 3.7. Поэтому три записи этого урока —
не полный список форм `for`.

## Сначала тело, потом проверка

Посчитайте цифры числа 0 циклом из раздела «Цикл с одним условием».
Условие `n > 0` ложно сразу, тело не выполнится ни разу, и ответ будет
ноль цифр. Но ноль записывается одной цифрой. Проверка до тела здесь
мешает: в этой задаче первое действие нужно выполнить раньше, чем решать,
продолжать ли.

Для таких задач проверку переносят в конец тела. Запись такая: `for` без
условия, а последняя инструкция тела — `if` с `break`. В `if` стоит
условие продолжения, перевёрнутое оператором `!` из урока 2.6. Цикл
продолжается, пока `n > 0`, значит, выходить нужно, когда `!(n > 0)`; для
неотрицательного `n` это то же, что `n == 0`. Первое выполнение тела
происходит раньше первой проверки, поэтому тело выполнится хотя бы один
раз.

Функция `before` ниже проверяет условие до тела, `after` — в конце тела.
Прежде чем смотреть вывод, предскажите ответы обеих функций для 0, 7, 10
и 999999999.

```go

### Example: `10-zero-digits`

Источник: `examples/10-zero-digits/`

```go
package main

import "fmt"

// before проверяет условие до тела.
func before(n int) int {
	count := 0
	for n > 0 {
		n /= 10
		count++
	}
	return count
}

// after выполняет тело до первой проверки.
func after(n int) int {
	count := 0
	for {
		n /= 10
		count++
		if !(n > 0) {
			break
		}
	}
	return count
}

func show(n int) {
	fmt.Printf("n = %d: до тела %d, после тела %d\n", n, before(n), after(n))
}

func main() {
	show(0)
	show(7)
	show(10)
	show(999999999)
}

```
```

Ответы разошлись только на нуле. На остальных входах обе функции сделали
одинаковое число итераций: при положительном `n` первая проверка до тела
всё равно даёт `true`. Значит, проверка до тела не ошибочна сама по себе.
Она не подходит задаче, где нулевой вход требует одного действия.

В других языках для «сначала тело, потом проверка» есть `do..while`. В Go
такой конструкции нет, и её заменяет запись с `break` в конце тела.
Полностью совпадает с `do..while` она, только пока в теле нет `continue`:
`continue` в цикле без условия переходит в конец тела мимо проверки и
начинает следующую итерацию без неё. Функция `nonZero` ниже считает
ненулевые цифры и на нулевой цифре делает `continue`. Прежде чем смотреть
вывод, пройдите итерации для 205 и для 0: на какой итерации проверка в
конце тела будет пропущена и что из этого выйдет?

```go

### Example: `11-skip-bottom-check`

Источник: `examples/11-skip-bottom-check/`

```go
package main

import "fmt"

// nonZero считает ненулевые цифры n. Проверка стоит в конце тела, но
// continue на нулевой цифре её пропускает. steps — сторож.
func nonZero(n int) string {
	start := n
	count := 0
	steps := 0
	for {
		steps++
		if steps > 20 {
			return fmt.Sprintf("%d: сторож прервал цикл", start)
		}
		digit := n % 10
		n /= 10
		if digit == 0 {
			continue
		}
		count++
		if !(n > 0) {
			break
		}
	}
	return fmt.Sprintf("%d: ненулевых цифр %d", start, count)
}

func main() {
	fmt.Println(nonZero(205))
	fmt.Println(nonZero(0))
}

```
```

Для 205 пропуск проверки на цифре 0 ничего не испортил: `n` в этот момент
ещё не ноль, и следующая итерация всё равно нужна. Для 0 первая же цифра —
ноль, `continue` пропустил проверку, `n` так и осталось нулём, и цикл не
закончился бы: функцию завершил сторож через `return`. Поэтому в цикле с
проверкой в конце тела и с `continue` убедитесь, что каждая итерация
доходит до проверки или что пропуск проверки безвреден.

## Как выбрать форму цикла

Выбор зависит от того, что известно до входа в цикл и когда нужна первая
проверка:

| Что известно до цикла | Естественная запись | Где проверка |
|---|---|---|
| начало, шаг и предел счётчика | трёхчастная | до тела, шаг в заголовке |
| условие продолжения, а состояние меняет тело | с одним условием | до тела |
| первое действие нужно раньше решения, продолжать ли | без условия, `if` с `break` в конце тела | после тела |

Таблица даёт рекомендации, а не правила языка. Любую запись можно
заменить другой, заново подобрав начальные значения и условие, и тогда
разные записи вернут одинаковые результаты. Тест, который сравнивает
только возвращённые значения, запись не различит. Выбирают ту, в которой
яснее видно, что меняется, где стоит проверка и почему цикл закончится.

## Чего в Go нет

**`while` и `do..while`.** Effective Go говорит прямо: `for` объединяет
`for` и `while`, а `do-while` нет. Почему так решено, ни Effective Go, ни
Go FAQ не объясняют. Распространённое «чтобы ключевых слов было меньше» —
не цитата авторов языка, и повторять его как их позицию не стоит.

Для компилятора `while` — обычное имя, а не ключевое слово. Поэтому
привычная запись даёт сообщение не про отсутствующий цикл, а про следующее
слово:

```go
@broken while
```

`syntax error: unexpected name x at end of statement` — компилятор
прочитал `while` как имя и не ждал за ним второго имени, `x`. Само
сообщение не говорит, что в языке нет `while`; это нужно знать.

**Тернарный оператор `?:`.** Почему его нет, авторы языка объясняют в
Go FAQ: они слишком часто видели, как из `?:` собирают непроницаемо
сложные выражения. Запись через `if`-`else` длиннее, но яснее, а одной
конструкции условного выбора языку достаточно. Компилятор отвергает уже
сам знак вопроса:

```go
@broken ternary
```

`invalid character U+003F '?'` — вне строковых литералов и комментариев
знак `?` не является ни оператором, ни частью имени, поэтому компилятор
называет его недопустимым символом. Внутри строки, например `"Готово?"`,
он законен. Вместо тернарного выражения пишут `if`-`else` из урока 3.1: объявляют
переменную и присваивают ей значение в одной из двух ветвей.

## Что нужно вспомнить до начала

**Факториал.** `n!` — произведение всех целых чисел от 1 до `n`:
4! = 1 · 2 · 3 · 4 = 24. Для нуля 0! = 1. Причина та же, по которой сумма
без слагаемых равна 0: умножение на 1 ничего не меняет, поэтому
произведение без множителей равно 1. Если начать произведение с 1 и не
умножить ни разу, получится ровно 1.

**Цифры числа.** Как в разделе теории «Цикл с одним условием»: `n % 10` —
последняя десятичная цифра `n`, а `n / 10` — число без неё.

**Сборка числа из цифр.** Чтобы дописать цифру `d` справа к числу `r`,
число умножают на 10 и прибавляют цифру: `r*10 + d`. Из 5 и цифры 4
получается 54, из 54 и цифры 3 — 543. Если `r` равно 0, результат — сама
цифра: 0 · 10 + 7 = 7.

**Двоичная запись.** В двоичной записи всего две цифры, 0 и 1: число 6
записывается как 110, а 8 — как 1000. Последнюю двоичную цифру даёт
`n % 2`, а `n / 2` отрезает её — так же, как `% 10` и `/ 10` в десятичной
записи. Ноль записывается одной цифрой 0.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые значения с
ожидаемыми:

- `TestFactorial` — 0, 1, 2, 3, 5, 10 и 12;
- `TestReverse` — 0, 7, 10, 100, 120, 1000, 12345, 199999999 и 999999999;
- `TestBitLength` — 0, 1, 2, 3, 4, 7, 8, 1023, 1024 и 1000000.

Тест получает только то, что функция вернула. Какой записью цикла вы
получили результат, он не видит. Для практики естественны три разные
записи: трёхчастная в `Factorial`, с одним условием в `Reverse` и без
условия, с проверкой в конце тела, в `BitLength`. Но тесты проходит любая
верная запись.

Ошибка в цикле часто даёт не неверное число, а цикл, который не
заканчивается. Тогда тест не дождётся ответа, и проверка оборвётся по
времени. Если так случилось, ищите шаг, который не выполняется или меняет
не ту переменную: разделы теории «continue пропускает шаг» и «Затенённый
шаг».

## Factorial

`Factorial` возвращает `n!` — произведение целых чисел от 1 до `n`; для
нуля результат 1.

- `Factorial(0)` возвращает 1;
- `Factorial(1)` возвращает 1;
- `Factorial(5)` возвращает 120.

## Reverse

`Reverse` возвращает число, записанное цифрами `n` в обратном порядке.
Нули, оказавшиеся в начале перевёрнутой записи, пропадают, как в любой
записи числа.

- `Reverse(123)` возвращает 321;
- `Reverse(120)` возвращает 21;
- `Reverse(7)` возвращает 7;
- `Reverse(0)` возвращает 0.

## BitLength

`BitLength` возвращает число цифр в двоичной записи `n`. У нуля одна
цифра.

- `BitLength(0)` возвращает 1;
- `BitLength(1)` возвращает 1;
- `BitLength(6)` возвращает 3 — запись 110;
- `BitLength(8)` возвращает 4 — запись 1000.

# Подсказки

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не
помогла, — вторая. Первая ступень направляет рассуждение. Вторая называет
запись цикла и строку, на которой чаще всего ошибаются.

## Factorial

**Ступень 1.** Известно ли до цикла, какие множители перебирать: с какого
начать, на каком закончить и как переходить к следующему? С какого
значения должен начинаться результат, чтобы при нуле итераций функция
вернула 1?

**Ступень 2.** Подходит трёхчастный цикл со счётчиком от 2 до `n`
включительно и результатом, начатым с 1; в теле результат умножается на
счётчик. Ошибаются в условии: `i < n` теряет последний множитель, и
`Factorial(2)` возвращает 1.

## Reverse

**Ступень 1.** Что делать с последней цифрой `n` на каждой итерации и как
понять, что цифр больше не осталось? Какой ответ нужен при `n`, равном 0,
и сколько итераций для него должно быть?

**Ступень 2.** Подходит цикл с одним условием `n > 0`. В теле последняя
цифра дописывается к результату справа, как в разделе упражнения «Что
нужно вспомнить до начала», а затем отрезается от `n`. Ошибаются на
отрезании: `n := n / 10` в теле объявляет новую переменную, а внешняя
`n` не меняется. Если новую `n` нигде не читать, сборка откажет с
сообщением `declared and not used: n`; если читать, программа соберётся,
но цикл не закончится. Нужно присваивание `n /= 10`.

## BitLength

**Ступень 1.** Сколько двоичных цифр у нуля и сколько раз должно
выполниться тело для него? Где должна стоять первая проверка — до тела или
после?

**Ступень 2.** Подходит `for` без условия: в теле `n` делится на 2,
счётчик растёт, а последняя инструкция тела — `if` с `break`, когда `n`
стало нулём. Ошибаются, ставя `n > 0` в заголовок при счётчике, начатом с
нуля: тогда `BitLength(0)` возвращает 0.

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Сколько итераций у Factorial

<!-- review:zero-iterations -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: сколько
итераций делает цикл `Factorial` при нуле и единице. Образец ответа ниже.

Верное решение начинает результат с 1 и умножает его на числа от 2 до
`n`: `result := 1`, затем `for i := 2; i <= n; i++` и `result *= i` в
теле. При `n`, равном 0 или 1, условие `2 <= n` ложно с первой проверки, и
тело не выполняется ни разу. Функция возвращает начальное значение 1 —
произведение без множителей. Счётчик можно начать и с 1: тогда при `n`,
равном 1, будет одна итерация с умножением на 1, и ответ тот же.

При нуле и единице верный ответ даёт начальное значение, а не тело цикла.
Результат, начатый с 0, остаётся нулём при любом `n`. Результат, начатый с
`n`, даёт 0 для нуля: цикл не выполняется, и функция возвращает сам ноль.

## Почему Reverse заканчивается

<!-- review:termination -->

Второй вопрос из того же раздела упражнения: переменная прогресса,
направление и условие остановки в `Reverse`.

Верное решение: `result := 0`, затем `for n > 0` с двумя инструкциями в
теле. `result = result*10 + n%10` дописывает последнюю цифру `n` к
результату справа, а `n /= 10` отрезает её от `n`. Переменная прогресса —
`n`. Для положительного `n` частное `n / 10` меньше `n`, поэтому `n`
строго уменьшается и не становится отрицательным. Значит, `n` дойдёт до
нуля, и условие `n > 0` станет ложным. При нуле тело не выполняется ни
разу, и функция возвращает 0 — это верный ответ. На всей допустимой
области, от 0 до 999999999, результат не больше 999999999 и помещается в
`int`.

Рассуждение ломается, если в теле написано `n := n / 10`: новая
переменная затеняет параметр, и внешняя `n` не меняется. Если новую `n`
нигде не читать, сборка откажет с сообщением `declared and not used: n`.
Если читать, программа соберётся, но цикл не закончится: этот случай
разобран ниже, в разделе «Затенённое n». Исправление в обоих случаях —
присваивание `n /= 10`.

## Где проверка у BitLength

<!-- review:choose-loop-form -->

Третий вопрос из того же раздела: почему в `BitLength` проверку удобно
поставить после тела.

У нуля одна двоичная цифра, значит, тело должно выполниться хотя бы раз
ещё до первой проверки. Цикл с проверкой до тела, `n > 0` в заголовке и
счётчиком, начатым с нуля, для нуля не выполнит тело ни разу и вернёт 0.
Верное решение: `length := 0`, затем `for` без условия, в теле `n /= 2` и
`length++`, а последней инструкцией тела — `if !(n > 0)` с `break`. Для
нуля тело выполняется один раз, и функция возвращает 1.

Цикл с проверкой до тела тоже можно заставить возвращать те же ответы,
если заново подобрать начальное значение счётчика и условие; тест,
который видит только результат, такие записи не различит. Запись с
проверкой после тела прямо говорит, что одна цифра есть всегда, и не
требует выводить заново ни начальное значение, ни условие.

Для двух других функций естественна проверка до тела. В `Factorial` до
цикла известны начало, шаг и предел счётчика, поэтому подходит
трёхчастная запись. В `Reverse` известно только условие продолжения —
цифры ещё остались, — поэтому подходит цикл с одним условием, а при нуле
тело и не должно выполняться.

## Последний множитель потерян

<!-- review:factorial-stops-early -->

Решение перебирает множители условием `i < n` вместо `i <= n`. При нуле и
единице ответ верен: цикл не выполняется, и функция возвращает 1. Начиная
с двух, последний множитель `n` теряется.

Ловит это `TestFactorial`: для 2 тест ждёт 2, а получает 1. Предел входит
в произведение, поэтому условие — `i <= n`.

## Результат начат с n

<!-- review:factorial-starts-at-n -->

Решение начинает результат с `n` и умножает его на числа от `n - 1` вниз
до 2. Для всех `n` от единицы ответ верен, а для нуля цикл не выполняется,
и функция возвращает сам ноль.

Ловит это `TestFactorial`: для 0 тест ждёт 1, а получает 0. Произведение,
в котором может не оказаться ни одного множителя, начинают с 1.

## Цифры сложены, а не собраны

<!-- review:reverse-sums-digits -->

Решение прибавляет цифру к результату, не умножая его на 10:
`result += n % 10`. Для однозначных чисел и чисел вида 10, 100 и 1000
ответ случайно верен: у них всего одна ненулевая цифра.

Ловит это `TestReverse`: для 120 тест ждёт 21, а получает 3. Чтобы цифра
встала справа, результат сначала умножают на 10:
`result = result*10 + n%10`.

## Затенённое n

<!-- review:reverse-shadowed-step -->

Решение отрезает цифру инструкцией `n := n / 10` и выходит через `break`,
когда новое `n` стало нулём. `:=` объявляет в теле новую переменную, а
внешняя `n`, которую проверяет условие, не меняется. Программа
собирается, потому что проверка перед `break` читает новую `n`. Для
однозначного числа ответ верен: после первой цифры новое `n` равно нулю,
и `break` заканчивает цикл. На двузначном числе цикл снова и снова берёт
одну и ту же последнюю цифру и не заканчивается.

Ловит это `TestReverse`: на входе 10 тест не дожидается ответа, и проверка
обрывается по времени. Верная запись — присваивание `n /= 10` и условие
`n > 0` в заголовке без отдельного `break`.

## Для нуля ни одной цифры

<!-- review:bitlength-zero-digits -->

Решение ставит проверку `n > 0` в заголовок и начинает счётчик с нуля. Для
всех положительных `n` ответ верен, а для нуля тело не выполняется ни
разу.

Ловит это `TestBitLength`: для 0 тест ждёт 1, а получает 0. Верная запись
переносит проверку в конец тела; другой путь — заново подобрать начальное
значение счётчика и условие так, чтобы нулю досталась одна цифра.

## Шаг забыт

<!-- review:bitlength-missing-step -->

Решение начинает счётчик с 1 и увеличивает его, пока `n > 1`, но не делит
`n` на 2. Для 0 и 1 тело не выполняется, и ответ 1 верен. Начиная с двух,
переменная прогресса не меняется, и цикл не заканчивается.

Ловит это `TestBitLength`: на входе 2 тест не дожидается ответа, и
проверка обрывается по времени. В теле нужен шаг `n /= 2`.

выполняется хотя бы раз. Вариант D считает итерацией только проход,

```

Что напечатает программа?

Варианты ответа:

- A. Печать при `i`, равном 1 и 3; после цикла `i` равно 5.
- B. Печать только при `i`, равном 1; после цикла `i` равно 2.
- C. Печать при `i`, равном 1 и 3; строки после цикла не будет.
- D. Печать при `i`, равном 1 и 3; после цикла `i` равно 4.

**Правильный ответ: D.**

После `continue` выполняется `i++`, затем условие, и цикл продолжается с

инструкции после цикла, а `i++` на этой итерации уже не выполняется,
поэтому `i` остаётся равным 4. Вариант A выполняет завершающую инструкцию

что `break` завершает всю функцию, как `return`.

## Вопрос 4

Функция `sumNonZero` должна сложить ненулевые цифры числа. Если цикл не

## Вопрос 5

Функция должна сложить цифры `n`. В теле цикла `for n > 0` три
инструкции: `sum += n % 10`, `n := n / 10` и `fmt.Println(n)`. Программа
собирается, но при `n`, равном 42, цикл не заканчивается. Какая правка это
исправит?

Варианты ответа:

- A. Добавить `continue` последней инструкцией тела.
- B. Заменить условие `n > 0` на `n >= 0`.
- C. Переставить `fmt.Println(n)` выше `n := n / 10`.
- D. Заменить `n := n / 10` на `n /= 10`.

`n := n / 10` объявляет в теле новую переменную, а условие проверяет

## Вопрос 6

нуля. При каких `n` он заканчивается сам?

Варианты ответа:

- A. При любом `n` от нуля: деление на 2 всегда уменьшает `n`.
- B. При любом `n` от единицы: `n` уменьшается до 1, а при нуле деление

- C. Только когда `n` — степень двойки: иначе деление проскочит мимо 1.

Прежде чем смотреть ответ, назовите переменную прогресса, её направление

последняя завершающая инструкция сделала `i` равным 3, и проверка `3 < 3`
закончила цикл. Вариант A верен только для исправленной программы.
Вариант B забывает последнюю завершающую инструкцию.

## Вопрос 8

Какая запись цикла естественна для каждой задачи?

1. Напечатать номера страниц от 1 до `n`.
2. Делить `n` на 2, пока `n` больше 1, и считать деления.
3. Собрать цифры числа справа налево так, чтобы у числа 0 получилась
   цифра 0.

Варианты ответа:

- A. 1 — трёхчастная, 2 — с одним условием, 3 — без условия, с проверкой
  в конце тела.
- B. 1 — с одним условием, 2 — трёхчастная, 3 — с одним условием.
- C. Все три — трёхчастные: в каждой задаче что-нибудь считают.

Прежде чем смотреть ответ, для каждой задачи скажите, что известно до
входа в цикл и должно ли тело выполниться до первой проверки.

**Правильный ответ: A.**

В первой задаче до цикла известны начало, шаг и предел счётчика. Во
второй известно только условие продолжения, а состояние меняет тело. В
третьей первая цифра нужна даже у нуля, значит, проверка должна стоять
после тела. Вариант B переставляет записи, а в задаче 3 проверка до тела
ничего не соберёт для нуля. Вариант C путает счёт с признаком выбора:
считать можно в любой записи, а выбор зависит от того, что известно до
цикла и где нужна проверка. Любую из этих задач можно решить и другой
записью, если заново подобрать начальные значения и условие; тест, который
видит только результат, записи не различит.

## Вопрос 9

Переменная `i` типа `int` объявлена до цикла. Какие заголовки компилятор
отвергнет?

1. `for ; i < 3; i++ {`
2. `for i := 0; i < 3; i := i + 1 {`
3. `for i < 3 {`
4. `for {`

Варианты ответа:

- A. Только заголовок 2: объявлять в завершающей инструкции нельзя.
- B. Заголовки 1 и 4: пустую часть оставлять нельзя, а условие обязательно.
- C. Только заголовок 3: без точек с запятой условие не отделить.
- D. Заголовки 2 и 4: объявлять в завершающей инструкции нельзя, и без
  условия `for` не собирается.

Прежде чем смотреть ответ, для каждого заголовка назовите пустые части и
скажите, остаются ли точки с запятой. Объясните, сколько раз повторит тело
цикл 4, если в теле нет `break` и `return`.

**Правильный ответ: A.**

В заголовке 1 пуста инструкция инициализации, а завершающая есть, поэтому
обе точки с запятой остаются. В заголовке 3 нет ни инициализации, ни
завершающей инструкции: осталось одно условие, и точки с запятой не пишут.
В заголовке 4 опущено и условие; отсутствующее условие равно `true`, и без
`break` и `return` тело повторяется бесконечно. Заголовок 2 отвергается с
сообщением `syntax error: cannot declare in post statement of for loop`:
для шага нужно присваивание. Вариант B путает пустую часть с ошибкой и не
знает, что опущенное условие равно `true`. Вариант C требует точек с
запятой там, где их пишут только при инициализации или завершающей
инструкции. Вариант D верно отвергает заголовок 2, но не знает правила об
опущенном условии.

При каких значениях `i` тело напечатает строку?

Варианты ответа:

- C. При 0, 3, 4, 7 и 10.

## Вопрос 11

Что сообщит компилятор на запись `while x < 3 { x++ }` и какое
утверждение о причинах подтверждено текстами авторов языка?

Варианты ответа:

- A. `syntax error: unexpected name x at end of statement`; Go FAQ
  объясняет отсутствие `?:`, а для `while` и `do-while` причину не
  называют ни Effective Go, ни Go FAQ.
- B. Сообщение о том, что `while` не поддерживается; авторы убрали
  `while`, чтобы ключевых слов было меньше.
- C. `syntax error: unexpected name x at end of statement`; Go FAQ одной
  причиной, сложными выражениями, объясняет отсутствие и `?:`, и `while`.
- D. Программа соберётся: `while` — другое имя цикла `for` с одним
  условием, и причины здесь объяснять не нужно.

Прежде чем смотреть ответ, объясните, почему сообщение называет `x`, а не
`while`. Затем для `while` и для `?:` скажите, есть ли объяснение авторов в
Go FAQ.

**Правильный ответ: A.**

Для компилятора `while` — обычное имя, и за ним он не ждёт второго имени,
`x`. Go FAQ объясняет только отсутствие `?:`: из него собирают непроницаемо
сложные выражения. Effective Go лишь сообщает, что `for` объединяет `for` и
`while`, а `do-while` нет, и причины не называет. Вариант B придумывает
сообщение компилятора и выдаёт распространённую догадку за слова авторов.
Вариант C переносит объяснение для `?:` на циклы. Вариант D считает
`while` частью языка, хотя в Go это просто имя, и сборка откажет.
