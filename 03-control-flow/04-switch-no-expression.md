# Урок: 03-control-flow / 04-switch-no-expression

# Теория

# switch без условия

Учитель переводит баллы теста в оценку. Баллов бывает от 0 до 100. За 90 и
больше ставится «отлично», за 50 и больше — «зачёт», за меньшее — «незачёт».
В уроке 3.1 такой выбор записывался цепочкой `if`, `else if` и `else`. В уроке
3.3 появился `switch` с выражением: он один раз вычисляет значение и сравнивает
его со значениями в `case`. Для оценки он неудобен. «Отлично» ставится за
любое число от 90 до 100, и в `case` пришлось бы перечислить одиннадцать
значений, а для «зачёта» — сорок.

Для оценки важен другой вопрос: не «чему равно число», а «какое условие
выполняется». Для такого выбора в Go есть `switch` без условия — без
выражения после ключевого слова `switch`. К концу урока вы сможете:

- записать `switch` без условия и объяснить, что стоит в его `case`;
- сказать, какой `case` выполнится, когда истинны сразу два условия;
- найти `case`, который никогда не выполняется, исправить порядок и
  проверить исправление на входе, который отличает старую версию от новой;
- решить, где `switch` заменяет цепочку `else if`, а где нужны независимые
  `if`;
- разобрать по этим правилам високосный год.

Примеры печатают через `fmt.Println`. Код примеров можно изменить и запустить
снова, такие опыты ничем не проверяются.

## Что пропущено в заголовке

В `switch` из урока 3.3 после ключевого слова стоит выражение — селектор.
Значение каждого `case` сравнивается с селектором через `==`. В `switch` без
условия селектора нет: сразу после `switch` открывается фигурная скобка.
Пропущен только селектор, а не условия. Условия переезжают в `case`.

Go выполняет такой `switch` так, как будто селектор равен `true`. Выбирается
`case`, чьё выражение равно `true`, то есть истинно. Поэтому в каждом `case`
стоит выражение типа `bool`: сравнение, сравнения, соединённые `&&` и `||` из
урока 2.6, переменная типа `bool` или вызов функции, которая возвращает
`bool`.

Дальше всё идёт по правилам урока 3.3:

1. Условия `case` проверяются по одному, сверху вниз, в порядке записи.
2. Первое истинное условие выбирает свой `case`, и выполняется его тело.
   Остальные `case` пропускаются.
3. После тела выполнение продолжается за закрывающей скобкой `switch`.
   Автоматического перехода в следующий `case` нет.
4. Если ни одно условие не истинно, выполняется тело `default`. Если
   `default` нет, не выполняется ни одно тело, и программа продолжает работу
   за `switch`.

Функция `grade` ниже переводит баллы в оценку. Каждая ветка, включая
`default`, заканчивается `return`, поэтому функция возвращает оценку на
любом пути. Прежде чем смотреть вывод, предскажите оценку для каждого из
пяти значений: идите по `case` сверху вниз и остановитесь на первом истинном
условии.

```go

### Example: `01-grade`

Источник: `examples/01-grade/`

```go
package main

import "fmt"

// grade переводит баллы теста от 0 до 100 в оценку.
func grade(score int) string {
	switch {
	case score >= 90:
		return "отлично"
	case score >= 50:
		return "зачёт"
	default:
		return "незачёт"
	}
}

func main() {
	fmt.Println("grade(95) =", grade(95))
	fmt.Println("grade(90) =", grade(90))
	fmt.Println("grade(89) =", grade(89))
	fmt.Println("grade(50) =", grade(50))
	fmt.Println("grade(49) =", grade(49))
}

```
```

При 90 баллах истинно уже первое условие: `>=` включает край, как в уроке
2.6. При 89 баллах первое условие ложно, а второе истинно. При 49 ложны оба,
и выполняется `default`. Цепочка
`if score >= 90 { … } else if score >= 50 { … } else { … }` из урока 3.1
проверяет те же условия в том же порядке и даёт ту же оценку. `switch` без
условия записывает такую цепочку столбиком: каждое условие стоит на своей
строке после `case`.

Что будет, если поставить в `case` не условие, а число? Автор программы ниже
хотел проверить, что `x` не ноль, и написал после `case` только имя
переменной. Прежде чем читать дальше, скажите, соберётся ли программа.

```go
@broken int-case
```

Не соберётся:
`invalid case x in switch on true (mismatched types int and bool)`.
Слова `switch on true` напоминают, что пропущенный селектор — это `true`.
Запись `case x` требует сравнить `x` с `true`, а число типа `int` с
логическим значением не сравнивается: типы не совпадают, как в уроке 2.6.
Число условием не является. Исправление — записать задуманное условие
целиком: `case x != 0:`.

## Выбирается первое истинное условие

Для 95 баллов истинны оба условия: и `score >= 90`, и `score >= 50`. Такие
условия **перекрываются**: есть вход, при котором истинны оба. `switch` не
ищет «самое подходящее» условие и не выполняет оба тела. Он берёт первое
истинное в порядке записи.

Условия ниже выбранного `case` даже не вычисляются. Пропуск виден, если
каждое условие при вычислении оставит отметку в выводе, как операнды в уроке
2.6. Функция `check` ниже печатает текст условия и возвращает переданное ей
значение `bool`. В `grade` каждое условие обёрнуто в вызов `check`. Прежде
чем смотреть вывод, для 95, 70 и 30 баллов скажите, какие условия будут
вычислены и что вернёт `grade`.

```go

### Example: `02-trace`

Источник: `examples/02-trace/`

```go
package main

import "fmt"

// check печатает условие cond и возвращает его значение v.
func check(cond string, v bool) bool {
	fmt.Println("  вычислено условие", cond)
	return v
}

// grade — оценка из примера 01-grade; каждое условие оставляет отметку.
func grade(score int) string {
	switch {
	case check("score >= 90", score >= 90):
		return "отлично"
	case check("score >= 50", score >= 50):
		return "зачёт"
	default:
		return "незачёт"
	}
}

func main() {
	fmt.Println("вызов grade(95)")
	g := grade(95)
	fmt.Println("  вернула", g)

	fmt.Println("вызов grade(70)")
	g = grade(70)
	fmt.Println("  вернула", g)

	fmt.Println("вызов grade(30)")
	g = grade(30)
	fmt.Println("  вернула", g)
}

```
```

Для 95 баллов вычислено одно условие. Оно истинно, и второе условие
программа не вычисляет. Для 70 первое условие ложно, второе истинно. Для 30
ложны оба, и `default` получает управление только после того, как проверены
все условия.

Отсюда главное правило урока: **порядок `case` — это порядок приоритета**.
Когда условия перекрываются, решает то, которое стоит выше.

`default` в этом порядке не участвует. Его можно записать в любом месте
`switch`, даже первым, и он всё равно выполнится, только если ложны все
условия. Принято писать `default` последним: так он читается как «во всех
остальных случаях».

## Порядок case — это приоритет правила

Правило оценки говорит: за 90 баллов и больше — «отлично», хотя такие баллы
подходят и под «зачёт». Значит, у «отлично» приоритет выше. Функция
`gradeBroken` ниже проверяет те же условия в обратном порядке, а `grade` — в
порядке правила. Каждая строка вывода показывает число баллов, затем ответ
`gradeBroken` и через косую черту ответ `grade`. Прежде чем смотреть вывод,
предскажите обе колонки и найдите баллы, для которых `gradeBroken` вернёт
«отлично».

```go

### Example: `03-reordered`

Источник: `examples/03-reordered/`

```go
package main

import "fmt"

// gradeBroken проверяет широкое условие раньше узкого.
func gradeBroken(score int) string {
	switch {
	case score >= 50:
		return "зачёт"
	case score >= 90:
		return "отлично"
	default:
		return "незачёт"
	}
}

// grade проверяет условия в порядке правила: сначала «отлично».
func grade(score int) string {
	switch {
	case score >= 90:
		return "отлично"
	case score >= 50:
		return "зачёт"
	default:
		return "незачёт"
	}
}

func main() {
	fmt.Println("100:", gradeBroken(100), "/", grade(100))
	fmt.Println("95:", gradeBroken(95), "/", grade(95))
	fmt.Println("90:", gradeBroken(90), "/", grade(90))
	fmt.Println("89:", gradeBroken(89), "/", grade(89))
	fmt.Println("50:", gradeBroken(50), "/", grade(50))
	fmt.Println("49:", gradeBroken(49), "/", grade(49))
}

```
```

Таких баллов нет. Любой балл не меньше 90 не меньше и 50, поэтому его
забирает первый `case` функции `gradeBroken`. До второго `case` доходят
только баллы меньше 50, а для них условие `score >= 90` ложно. Тело второго
`case` не выполняется ни при каком входе. Такой `case` называют
**недостижимым**: широкое условие выше поглотило узкое.

Ни сборка, ни `go vet` об этой ошибке не сообщают: программа собирается и
работает. Так ведут себя текущие инструменты Go; язык предупреждения о
недостижимом `case` не обещает. Найти недостижимую ветку помогают
рассуждение о перекрытии и проверка на подходящем входе.

Исправление идёт в два шага.

1. Перенесите приоритет из правила в порядок `case`. Правило отдаёт
   перекрытие «отлично», значит, `score >= 90` стоит выше `score >= 50`.
2. Проверьте исправление на **отличающем входе** — на входе, где старая и
   новая функции отвечают по-разному. Для оценки это любой балл от 90 до
   100, то есть вход из зоны перекрытия. Особенно полезна общая граница: 90 —
   наименьший балл, при котором условия перекрываются. Рядом с ней проверяют
   и 89, чтобы убедиться, что граница не сдвинулась.

Входы 89, 50 и 49 ошибку не выдают: на них обе функции отвечают одинаково.
Проверка только на таких значениях пропустила бы неверный порядок.

Часто советуют: «узкое условие — первым». Узким называют условие, из которого
следует другое: каждый балл, подходящий под `score >= 90`, подходит и под
`score >= 50`, но не наоборот. В оценке совет сработал, потому что приоритет
правила совпал с узостью условия. Но совет не заменяет правило. Условия могут
перекрываться лишь частично. Например, контроллер теплицы закрывает окна в
дождь, а в жару выше 26 градусов открывает: `case rain:` и
`case temp > 26:`. Дождь бывает и в прохладу, жара бывает и без дождя,
поэтому ни одно условие не следует из другого. Какое из них выше, говорит
только текст правила: «в дождь окна закрыты, даже в жару» — значит, `rain`
проверяется первым. После этого проверяют вход, на котором истинны оба
условия: дождь при 30 градусах.

## Один выбор или несколько независимых решений

`switch` без условия заменяет цепочку `else if`, когда из нескольких правил
нужен один результат. Независимые `if` из урока 3.1 устроены иначе: каждое
`if` проверяется само по себе, и тело выполняется у каждого истинного
условия. Функция `withIfs` ниже проверяет три условия отдельными `if`, а
`withSwitch` — одним `switch`. Прежде чем смотреть вывод, для 95, 70 и 30
баллов скажите, сколько строк напечатает каждая функция.

```go

### Example: `04-independent`

Источник: `examples/04-independent/`

```go
package main

import "fmt"

// withIfs проверяет три условия отдельными if.
func withIfs(score int) {
	if score >= 90 {
		fmt.Println("  оценка: отлично")
	}
	if score >= 50 {
		fmt.Println("  оценка: зачёт")
	}
	if score < 50 {
		fmt.Println("  оценка: незачёт")
	}
}

// withSwitch проверяет те же условия одним switch без условия.
func withSwitch(score int) {
	switch {
	case score >= 90:
		fmt.Println("  оценка: отлично")
	case score >= 50:
		fmt.Println("  оценка: зачёт")
	default:
		fmt.Println("  оценка: незачёт")
	}
}

func main() {
	fmt.Println("withIfs(95):")
	withIfs(95)
	fmt.Println("withSwitch(95):")
	withSwitch(95)

	fmt.Println("withIfs(70):")
	withIfs(70)
	fmt.Println("withSwitch(70):")
	withSwitch(70)

	fmt.Println("withIfs(30):")
	withIfs(30)
	fmt.Println("withSwitch(30):")
	withSwitch(30)
}

```
```

Для 70 и 30 баллов функции напечатали одно и то же: из трёх условий истинно
только одно. Для 95 баллов истинны два условия. Независимые `if` выполнили
оба тела, а `switch` — только первое.

Когда тела только печатают, как в примере выше, набор независимых `if`
выполняет те же тела, что `switch`, при двух требованиях.

1. При любом допустимом входе истинно не больше одного из условий. Тогда
   первое истинное условие — единственное истинное, и набор тоже выполнит
   только его тело.
2. Тело `default` переходит в последний `if`. У `default` нет своего
   условия, поэтому этому `if` нужно условие, которое истинно ровно тогда,
   когда ложны все остальные условия.

В `withIfs` второе требование выполнено: `score < 50` истинно ровно тогда,
когда ложны `score >= 90` и `score >= 50`. А первое нарушено: для 95 баллов
истинны сразу `score >= 90` и `score >= 50`.

Бывает, что несколько действий сразу и нужны. Программа-напоминание перед
выходом из дома советует шапку, если холоднее 5 градусов, и зонт, если идёт
дождь. В холодный дождь нужны оба совета. Два независимых `if` дадут оба, а
`switch` с этими двумя `case` выполнит только первое тело и потеряет зонт.
Отсюда правило выбора:

- нужен один результат из правил с приоритетом — `switch` без условия или
  цепочка `else if`;
- нужны все подходящие действия — независимые `if`.

## default, пустой выбор и fallthrough

Остальное устроено так же, как у `switch` с выражением из урока 3.3.

Если `default` нет и ни одно условие не истинно, не выполняется ни одно
тело. `switch` просто заканчивается, и выполнение идёт дальше. Функция `warn`
ниже предупреждает только об опасной температуре, а после `switch` печатает
строку о своём завершении. Прежде чем смотреть вывод, для −30, 15 и 40
градусов скажите, какие строки напечатает `warn`.

```go

### Example: `05-no-match`

Источник: `examples/05-no-match/`

```go
package main

import "fmt"

// warn предупреждает только об опасной температуре t в градусах.
func warn(t int) {
	switch {
	case t <= -25:
		fmt.Println("  сильный мороз")
	case t >= 35:
		fmt.Println("  сильная жара")
	}
	fmt.Println("  warn завершилась")
}

func main() {
	fmt.Println("warn(-30):")
	warn(-30)
	fmt.Println("warn(15):")
	warn(15)
	fmt.Println("warn(40):")
	warn(40)
}

```
```

При 15 градусах оба условия ложны, `default` нет, и тела `switch` ничего не
напечатали. Строка о завершении `warn` появилась во всех трёх случаях:
`switch` без совпадения завершается обычным образом.

Перед `switch` без условия можно поставить короткую инструкцию, как в уроке
3.3: `switch r := year % 4; {`. Точка с запятой отделяет инструкцию, а
селектора после неё нет. Переменная `r` видна только внутри `switch`. В этом
уроке такая инструкция не нужна.

Инструкция `fallthrough` из урока 3.3 работает и без селектора, но выбору
одного ответа она вредит. `fallthrough` в конце тела передаёт
управление в тело следующего `case` и **не проверяет** его условие. В
функции `describe` ниже первое тело кончается `fallthrough`. Прежде чем
смотреть вывод, для 30, 70 и 95 баллов скажите, какие тела выполнятся.

```go

### Example: `06-fallthrough`

Источник: `examples/06-fallthrough/`

```go
package main

import "fmt"

// describe печатает, какие тела switch выполнены для баллов score.
// Первое тело кончается инструкцией fallthrough.
func describe(score int) {
	switch {
	case score < 50:
		fmt.Println("  выполнено тело 1: незачёт")
		fallthrough
	case score >= 90:
		fmt.Println("  выполнено тело 2: отлично")
	default:
		fmt.Println("  выполнено тело default: зачёт")
	}
}

func main() {
	fmt.Println("describe(30):")
	describe(30)
	fmt.Println("describe(70):")
	describe(70)
	fmt.Println("describe(95):")
	describe(95)
}

```
```

Для 30 баллов выполнено первое тело, а за ним второе, хотя 30 меньше 90:
условие второго `case` не вычислялось. Функция, которая должна дать одну
оценку, дала две. В правилах, где каждому входу положен ровно один ответ,
`fallthrough` не пишут.

## Високосный год: правило как данные задачи

Календарю из мини-проекта 3.9 понадобится правило високосного года: от него
зависит число дней в феврале. Это правило григорианского календаря. Его не
выводят, а берут готовым, как данные задачи, и применяют к годам от 1 до
9999:

1. год, кратный 400, — високосный;
2. остальные годы, кратные 100, — не високосные;
3. остальные годы, кратные 4, — високосные;
4. все остальные годы — не високосные.

В задаче правило — вычисление над номером года, а не история календаря:
когда и где этот календарь начали применять, для ответа не важно. Пакет
`time` для такого вычисления не нужен; даты и время через него разбирают
уроки 14.18 и 14.19.

«Год кратен 4» значит «остаток от деления года на 4 равен нулю». Из урока
2.10 это запись `year%4 == 0`. Так же записываются кратность 100 и кратность
400.

Три условия правила вложены друг в друга. Каждое число, кратное 400, кратно
и 100, потому что 400 = 4 · 100. Каждое число, кратное 100, кратно и 4,
потому что 100 = 25 · 4. Значит, 2000 подходит под все три условия, а 1900 —
под «кратен 100» и «кратен 4». Слово «остальные» в правиле задаёт приоритет:
часть правила применяется только к годам, которые не забрали части выше.
Такой приоритет и есть порядок `case` в `switch` без условия.

Функция `leapFourFirst` ниже проверяет те же части правила, но кратность 4
стоит первой. Прежде чем смотреть вывод, для 2023, 2024, 1900, 2000 и 2100
назовите первое истинное условие этой функции и её ответ. Затем сравните
ответы с правилом.

```go

### Example: `07-leap-four-first`

Источник: `examples/07-leap-four-first/`

```go
package main

import "fmt"

// leapFourFirst проверяет части правила високосного года в неверном
// порядке: кратность 4 стоит первой.
func leapFourFirst(year int) bool {
	switch {
	case year%4 == 0:
		return true
	case year%100 == 0:
		return false
	case year%400 == 0:
		return true
	default:
		return false
	}
}

func main() {
	fmt.Println("leapFourFirst(2023) =", leapFourFirst(2023))
	fmt.Println("leapFourFirst(2024) =", leapFourFirst(2024))
	fmt.Println("leapFourFirst(1900) =", leapFourFirst(1900))
	fmt.Println("leapFourFirst(2000) =", leapFourFirst(2000))
	fmt.Println("leapFourFirst(2100) =", leapFourFirst(2100))
}

```
```

Для 1900 и 2100 функция ошиблась. Эти годы кратны 4, и их забрал первый
`case`, хотя по правилу решает часть 2: год кратен 100 и не кратен 400,
значит, он не високосный. До `case` с кратностью 100 не доходит ни один год:
каждый год, кратный 100, уже забрал первый `case`. По той же причине
недостижим `case` с кратностью 400. Два `case` из четырёх не выполняются
никогда.

Для 2000 ответ верный, но причина неверная: год забрала кратность 4, а по
правилу решает кратность 400. Проверка только на 2000 и 2024 этой ошибки не
заметит. Ошибку показывают отличающие входы — годы, кратные 100, но не
кратные 400, например 1900 и 2100.

Порядок частей уже задан в правиле словом «остальные», и `switch` должен
проверять их в том же порядке. Функцию `IsLeap` с таким порядком вы напишете
в упражнении. Перед этим упражнение попросит проследить пять лет этого
раздела по частям правила.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые значения с
ожидаемыми:

- `TestSign` — `Sign` в первый и последний час суток, на обоих краях каждого
  правила и в часы, которым подходят два правила сразу;
- `TestIsLeap` — `IsLeap` на годах, кратных 400, на других годах, кратных
  100, на других годах, кратных 4, на остальных годах и на краях области
  значений, 1 и 9999.

Тест получает только то, что функция вернула. Текста решения он не видит.
Поэтому проверка не различает, записали вы выбор через `switch`, цепочкой
`if` и `else if` или одним логическим выражением. В каком порядке решение
проверяет условия, тест тоже не показывает: это показывает ваша трассировка.

Ответ проверки бывает двух видов. Если код не собрался, тесты не
запускаются, и проверка показывает сообщение сборки с местом в файле. Если
код собрался, но функция вернула не то, проверка печатает строку `--- FAIL:`
с именем теста и сообщение: какой аргумент передан, что функция вернула и
что должна была вернуть.

Прежде чем писать тела, выпишите две вещи:

1. для `Sign` — час, которому подходят сразу два правила, какое правило

2. для `IsLeap` — для 2023, 2024, 1900, 2000 и 2100 первую подходящую часть
   правила и ответ.

После попытки сверьте свои записи с разбором неверных решений, разделы
«Какой час подходит двум правилам» и «Пять лет по правилу».

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла,
— вторая. Готового решения нет ни в одной из них.

## Sign

**Ступень 1.** Найдите часы, которым подходят сразу два правила: сначала
правила 1 и 2, потом правила 1 и 3. Что должна показать табличка в 7 часов и

**Ступень 2.** Нужен `switch` без условия: три `case` в порядке списка и
`default` для «дня». Условие «закрыто» состоит из двух сравнений, по одному

Первое — порядок: «утро» или «вечер» выше «закрыто» забирают ночные часы.
Сюда же относится «закрыто», разбитое на два `case`, где `hour >= 21` стоит
ниже `hour >= 18`: такой `case` недостижим. Второе — края: в 9, 12, 18 и 21
час надпись уже меняется, поэтому для каждого края решите, нужен `<` или
`<=`, `>` или `>=`.

«остальные» в правиле говорит, какая часть проверяется раньше. Проверьте
выбранный порядок на 1900 и на 2000.

**Ступень 2.** Четыре ветки `switch` в порядке правила: кратность 400,

кратности 100 объявляет високосными 1900 и 2100, а кратность 100 выше
кратности 400 объявляет невисокосным 2000.

## Какой час подходит двум правилам

<!-- review:sign-overlap -->

Постановка просила до написания `Sign` найти час, которому подходят два
правила. Таких часов две группы. Часы от 0 до 8 меньше 9 и меньше 12: им
подходят правила 1 и 2. Часы от 21 до 23 не меньше 21 и не меньше 18: им
подходят правила 1 и 3. Правила применяются по порядку, поэтому в обоих
случаях решает правило 1, и табличка показывает «закрыто».

Отсюда порядок `case` в верном решении: сначала `hour < 9 || hour >= 21` с
ответом `"закрыто"`, затем `hour < 12` с ответом `"утро"`, затем
`hour >= 18` с ответом `"вечер"`, и `default` с ответом `"день"`.

Отличающие входы для неверного порядка лежат в зонах перекрытия. Если
«утро» стоит выше «закрыто», ошибку покажет любой час от 0 до 8. Если
«вечер» стоит выше «закрыто», ошибку покажет любой час от 21 до 23. Края
правил проверяются отдельно: 8 и 9, 11 и 12, 17 и 18, 20 и 21. `TestSign`
проверяет все эти часы, а также первый и последний час суток.

## Пять лет по правилу

<!-- review:leap-trace -->

Постановка просила проследить пять лет по частям правила сверху вниз.

- 2023 не кратен 400, 100 и 4. Решает часть 4: год не високосный.
- 2024 не кратен 400 и 100, но кратен 4. Решает часть 3: год високосный.
- 1900 не кратен 400, но кратен 100. Решает часть 2: год не високосный. До
  кратности 4 дело не доходит.
- 2000 кратен 400. Решает часть 1: год високосный. Остальные части не
  проверяются.
- 2100, как и 1900, кратен 100 и не кратен 400. Решает часть 2: год не
  високосный.

Верное тело `IsLeap` проверяет части в том же порядке: `year%400 == 0` с
ответом `true`, `year%100 == 0` с ответом `false`, `year%4 == 0` с ответом
`true` и `default` с ответом `false`. Зелёный `TestIsLeap` подтверждает
ответы на своих годах. Что порядок верен для любого года от 1 до 9999,

который задаёт слово «остальные» в правиле. Здесь этот приоритет совпадает с
вложением кратностей: условие каждой следующей части истинно и для всех лет
предыдущей, поэтому при другом порядке более ранний `case` забрал бы годы,
которые правило отдаёт части выше.

<!-- review:sign-morning-first -->

Решение проверяет `year%4 == 0` первым, как функция `leapFourFirst` из

<!-- review:leap-default-true -->

Решение проверяет кратность 400 и кратность 100, а в `default` возвращает
`true`: часть 3 правила пропущена. Тогда високосным считается любой год, не
кратный 100, например 2023.

Ловит это `TestIsLeap` на входе `IsLeap(2023)`: тест ждёт `false`, а
получает `true`. У частей 3 и 4 разные ответы, поэтому кратности 4 нужен
свой `case` с ответом `true`, а `default` возвращает `false`.

## Вопрос 1

Функция `weather` называет погоду по температуре `t` в градусах.

```go
@quiz _quiz/01-overlap
```

Что напечатает программа?

Варианты ответа:

- A. Для 35 — тепло, для 20 — тепло, для −5 — мороз.
- B. Для 35 — жара, для 20 — прохладно, для −5 — мороз.
- C. Для 35 — жара, для 20 — тепло, для −5 — мороз.
- D. Программа не соберётся: при 35 градусах истинны два условия `case`.

Прежде чем смотреть ответ, назовите все условия, истинные при 35 градусах, и
объясните, какое из них выбирает `switch` и почему тело другого не
выполняется.

**Правильный ответ: C.**

При 35 градусах истинны `t >= 30` и `t >= 20`. `switch` проверяет условия
сверху вниз и выбирает первое истинное, поэтому ответ — жара, а условие ниже
даже не вычисляется. Для 20 градусов `t >= 30` ложно, а `t >= 20` истинно:
`>=` включает край. Вариант A считает, что решает последнее подходящее
условие. Вариант B теряет край 20. Вариант D принимает перекрытие за ошибку,
но Go его допускает: перекрытие решает порядок `case`.

## Вопрос 2

Объявлены `n := 7` и `ok := true`. Какие строки можно поставить в `switch`
без условия?

1. `case n > 0 && n < 10:`
2. `case n:`
3. `case n%2 == 0:`
4. `case ok:`

Варианты ответа:

- A. Первую, третью и четвёртую.
- B. Только первую и третью.
- C. Все четыре.

Прежде чем смотреть ответ, для каждой строки назовите тип выражения после
`case` и скажите, с каким значением `switch` его сравнивает.

**Правильный ответ: A.**

Пропущенный селектор равен `true`, поэтому выражение каждого `case`
сравнивается с `true` и должно иметь тип `bool`. Первая и третья строки —
сравнения, четвёртая — переменная `bool`. Во второй строке стоит `int`, и
сборка остановится с тем же `mismatched types int and bool`, что в разделе
«Что пропущено в заголовке». Вариант B исходит из того, что переменную
`bool` нужно ещё с чем-то сравнить, но `ok` уже истинна или ложна.
Вариант C считает число условием.

## Вопрос 3

Функция `discount` должна возвращать скидку в процентах: для покупки от 5000
рублей — 10, от 1000 рублей — 5, для меньшей суммы — 0. Автор проверил её на
двух суммах и получил верные ответы.

```go
@quiz _quiz/02-discount
```

В чём ошибка, как её исправить и на какой сумме проверить исправление?

Варианты ответа:

- A. Ошибки нет: обе проверки дали верный ответ, а `case`, который никогда не
  выполняется, не пропустила бы сборка.
- B. Условие `sum >= 5000` недостижимо. Поставить его выше `sum >= 1000` и
  проверить на сумме 3000: до правки и после функция должна вернуть 5.
- C. Заменить `sum >= 1000` на `sum > 1000` и проверить на сумме 1000: до
  правки функция вернёт 5, после — 0.
- D. Условие `sum >= 5000` недостижимо. Поставить его выше `sum >= 1000` и
  проверить на сумме 5000: до правки функция вернёт 5, после — 10.

Прежде чем смотреть ответ, найдите сумму, при которой истинны оба условия,
запишите исправленный порядок `case` и назовите сумму, на которой старая и
новая функции ответят по-разному.

**Правильный ответ: D.**

Любая сумма от 5000 не меньше и 1000, поэтому её забирает первый `case`, и до
`sum >= 5000` не доходит ни одна сумма. Правило отдаёт перекрытие скидке
10 %, значит, её условие стоит первым. Отличающий вход лежит в зоне
перекрытия, а 5000 — её общая граница; рядом проверяют 4999, где скидка
остаётся 5 %. Вариант A полагается на сборку, а она эту программу
пропустила: программа собралась и работает. Вариант B исправляет порядок, но
на 3000 обе версии отвечают одинаково, и ошибка не видна. Вариант C двигает
край: 1000 рублей теряют скидку, а суммы от 5000 по-прежнему получают 5 %.

## Вопрос 4

```go
@quiz _quiz/03-advice
```

Функции `adviceIfs` и `adviceSwitch` проверяют условия в одном порядке, а
вместо последнего `if` у `adviceSwitch` стоит `default`. Что напечатает
программа и одинаково ли действуют функции?

Варианты ответа:

- A. Одинаково при любой температуре: условия те же и стоят в том же порядке.
  Каждая функция напечатает по одному совету для −5, 5 и 15 градусов.
- B. При −5 градусах `adviceIfs` советует шапку и куртку, а `adviceSwitch` —
  только шапку. При 5 и 15 градусах обе функции дают один и тот же совет.
- C. При −5 и 5 градусах функции совпадают, а при 15 градусах различаются:
  `default` срабатывает не так, как `if t >= 10`.
- D. При −5 градусах `adviceIfs` советует шапку, куртку и футболку, а
  `adviceSwitch` — только шапку.

Прежде чем смотреть ответ, для −5, 5 и 15 градусов перечислите советы каждой
функции и назовите условие, при котором набор независимых `if` выполняет те
же тела, что `switch`.

**Правильный ответ: B.**

При −5 градусах истинны `t < 0` и `t < 10`. Независимые `if` выполняют тело
каждого истинного условия, а `switch` — только первого. При 5 градусах
истинно одно `t < 10`, при 15 — одно `t >= 10`, и функции совпадают. Набор
`if` выполнял бы те же тела, если бы при любом входе было истинно не больше
одного условия; здесь условия перекрываются при отрицательной температуре.
Какая версия верна, решает правило: нужны все подходящие советы — `if`, нужен
один — `switch`. Вариант A смотрит на запись условий, а не на то, сколько из
них истинно сразу. Вариант C не замечает, что `t >= 10` истинно ровно тогда,
когда ложны два первых условия, — как `default`. Вариант D выполняет тело
`t >= 10`, хотя при −5 оно ложно.

## Вопрос 5

Функция `sizeName` называет партию по числу деталей `n`.

```go
@quiz _quiz/04-default-first
```

Что напечатает программа?

Варианты ответа:

- A. Для 5, 50 и 500 — средняя.
- B. Программа не соберётся: `default` обязан стоять последним.
- C. Для 5 — малая, для 50 — средняя, для 500 — большая.

Прежде чем смотреть ответ, скажите, когда выполняется тело `default` и
зависит ли это от места, где он записан.

**Правильный ответ: C.**

`default` выполняется, только когда ложны все условия `case`, где бы он ни

так читать проще.

## Вопрос 6

Правило високосного года из урока: год, кратный 400, — високосный; остальные
годы, кратные 100, — не високосные; остальные годы, кратные 4, —
високосные; все остальные — не високосные. Какой ответ верно называет для
2023, 2024, 1900, 2000 и 2100 и результат, и часть правила, которая его
решает?

Варианты ответа:

- A. 2023 — нет, не подошла ни одна кратность; 2024 — да, кратен 4; 1900 —
  да, кратен 4; 2000 — да, кратен 4; 2100 — да, кратен 4.
- B. 2023 — нет, не подошла ни одна кратность; 2024 — да, кратен 4; 1900 —
  нет, кратен 100, но не 400; 2000 — да, кратен 400; 2100 — нет, кратен 100,
  но не 400.
- C. 2023 — нет, не подошла ни одна кратность; 2024 — да, кратен 4; 1900 —
  нет, кратен 100, но не 400; 2000 — да, кратен 4; 2100 — нет, кратен 100,
  но не 400.
- D. 2023 — нет, не подошла ни одна кратность; 2024 — да, кратен 4; 1900 —

Прежде чем смотреть ответ, для каждого года пройдите части правила сверху

Части правила проверяются по порядку, как `case`. 2023 не кратен ни 400, ни

раньше кратности 400 и теряет 2000.
