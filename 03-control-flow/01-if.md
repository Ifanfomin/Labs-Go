# Ветвление if

Служба доставки считает плату за посылку по нескольким правилам. Доставка
стоит 300 рублей, а за посылку тяжелее 5 кг берут ещё 200 рублей. Посылку до
20 кг включительно везёт курьер, более тяжёлую — грузовое такси. Заказ от
3000 рублей доставляют бесплатно. В каждом правиле есть слово «если»: часть
расчёта выполняется только при определённом условии.

Записать само условие вы умеете с урока 2.6: `weight > 5` — сравнение, его
значение `true` или `false`. Но сравнение ничего не выполняет и ничего не
пропускает, оно только даёт значение. Чтобы это значение решало, выполнится
ли часть кода, нужна инструкция `if`.

Понадобится то, что вы уже знаете: сравнения и операции `!`, `&&`, `||`
(урок 2.6), объявление через `var` и `:=` и присваивание `=` (уроки 2.1 и
2.2), блоки и затенение имён (урок 2.3), функция с одним результатом и
`return` (урок 1.7), проверка с `t.Errorf` в тесте (урок 1.12).

Примеры печатают через `fmt.Println`. Строка со знаками `==` по краям
отделяет один вызов функции от другого. Строки с отступом печатает сама
функция изнутри: пометка в квадратных скобках говорит, в каком месте кода
стоит печать, и по этим строкам видно, какие инструкции выполнились.

## Условие решает, выполнится ли блок

Инструкция `if` состоит из слова `if`, условия и блока в фигурных скобках —
тела `if`. Условие — логическое выражение, то есть выражение со значением
`true` или `false`, например сравнение. Выполняется `if` так:

1. Программа вычисляет условие.
2. Если оно истинно, выполняются инструкции тела, от `{` до `}`.
3. Если оно ложно, тело пропускается целиком: ни одна его инструкция не
   выполняется.
4. В обоих случаях дальше выполняется инструкция, которая стоит после
   закрывающей `}`.

Тело `if` — блок в смысле урока 2.3: переменные, объявленные снаружи, в нём
видны, а объявленные внутри перестают действовать после `}`.

Функция `deliveryFee` ниже считает плату по первому правилу: 300 рублей, а за
посылку тяжелее 5 кг на 200 рублей больше. Значение сравнения `weight > 5`
сохранено в переменной `heavy`, и `if` проверяет эту переменную: условием
может быть и сравнение прямо после `if`, и переменная типа `bool`. `main`
вызывает функцию для посылок в 8 и в 3 кг. Прежде чем смотреть вывод, для
каждого вызова скажите, какие строки напечатает функция и чему будет равна
`fee` после `if`.

```go

### Example: `01-optional`

Источник: `examples/01-optional/`

```go
package main

import "fmt"

// deliveryFee считает плату за доставку посылки весом weight килограммов:
// 300 рублей, а за посылку тяжелее 5 кг — ещё 200.
func deliveryFee(weight int) int {
	fee := 300
	heavy := weight > 5
	fmt.Println("  heavy =", heavy)
	if heavy {
		fmt.Println("  [тело if] fee = fee + 200")
		fee = fee + 200
	}
	fmt.Println("  [после if] fee =", fee)
	return fee
}

func main() {
	fmt.Println("== 8 кг ==")
	fmt.Println("итог:", deliveryFee(8))
	fmt.Println("== 3 кг ==")
	fmt.Println("итог:", deliveryFee(3))
}

```
```

Для 8 кг `heavy` истинна, и тело выполнилось: напечатана пометка тела, а
присваивание увеличило `fee` до 500. Для 3 кг `heavy` ложна. Пометки тела в
выводе нет, потому что тело пропущено, и присваивание в нём тоже не
выполнилось: `fee` осталась равной 300. Строку после `if` функция напечатала в
обоих вызовах.

Посмотрите и на строку с `heavy`. Сравнение вычислилось в обоих вызовах, но
само ничего не изменило: `heavy` просто хранит ответ. Выполнить тело или
пропустить его, решает инструкция `if`, когда проверяет это значение.

Условием может быть только логическое значение. В уроке 2.6 после `if`
стояло число, и программа не собралась. Со строкой так же. Программа ниже
хочет передать курьеру комментарий, если он есть. Прежде чем читать дальше,
скажите, соберётся ли она.

```go
@broken string-condition
```

Не соберётся: `non-boolean condition in if statement` — условие в инструкции
`if` не логическое. Строка не бывает ни истиной, ни ложью, и Go не решает за
вас, что значит «комментарий есть». Правило записывают сравнением:
`comment != ""` истинно, когда строка не пустая.

## else: одна ветвь из двух

Второе правило выбирает одно из двух: посылку до 20 кг включительно везёт
курьер, а более тяжёлую — грузовое такси. Для такого выбора к `if` добавляют
слово `else` и второй блок:

- если условие истинно, выполняется первый блок — ветвь `if`;
- если ложно, выполняется второй блок — ветвь `else`.

Выполняется ровно одна из двух ветвей, а пропущенная ветвь не делает ничего.
Когда выполненная ветвь доходит до своей `}`, программа переходит к
инструкции после всей конструкции `if`-`else`, а не ко второй ветви.

Функция `method` объявляет переменную `way` через `var` без значения — по
уроку 2.1 она получает пустую строку — и присваивает ей способ доставки в той
ветви, которая выполнится. Прежде чем смотреть вывод, для 20 и для 21 кг
скажите, какая ветвь выполнится, какую пометку напечатает функция и что она
вернёт.

```go

### Example: `02-else`

Источник: `examples/02-else/`

```go
package main

import "fmt"

// method выбирает способ доставки посылки весом weight килограммов:
// до 20 кг включительно — курьер, тяжелее — грузовое такси.
func method(weight int) string {
	var way string
	if weight <= 20 {
		fmt.Println("  [ветвь if]")
		way = "курьер"
	} else {
		fmt.Println("  [ветвь else]")
		way = "грузовое такси"
	}
	fmt.Println("  [после if-else] way =", way)
	return way
}

func main() {
	fmt.Println("== 20 кг ==")
	fmt.Println("итог:", method(20))
	fmt.Println("== 21 кг ==")
	fmt.Println("итог:", method(21))
}

```
```

20 кг — край правила. Условие `weight <= 20` на нём истинно, потому что `<=`
включает край, и выполнилась ветвь `if`, а ветвь `else` пропущена. Для 21 кг
условие ложно, и выполнилась только ветвь `else`. В обоих вызовах после ветви
выполнилась строка, стоящая после всей конструкции, и `way` к этому моменту
уже хранила выбранный способ.

## return в ветви завершает функцию

Не каждая ветвь доходит до своей `}`. В уроке 1.12 вы видели ветвь, в которой
стоит `return`: функция `Sign` при пустом имени сразу возвращала подпись без
двоеточия. `return` не просто выходит из ветви — он завершает всю функцию.
Инструкции после `if` в этом вызове уже не выполняются.

Функция `fee` ниже применяет третье правило: от 3000 рублей доставка
бесплатна. Прежде чем смотреть вывод, для заказов на 3500 и на 1200 рублей
скажите, какие пометки напечатает функция и что она вернёт.

```go

### Example: `03-return`

Источник: `examples/03-return/`

```go
package main

import "fmt"

// fee возвращает плату за доставку заказа на сумму total рублей:
// от 3000 рублей доставка бесплатна, иначе она стоит 300 рублей.
func fee(total int) int {
	if total >= 3000 {
		fmt.Println("  [тело if] return 0")
		return 0
	}
	fmt.Println("  [после if] return 300")
	return 300
}

func main() {
	fmt.Println("== заказ 3500 ==")
	fmt.Println("итог:", fee(3500))
	fmt.Println("== заказ 1200 ==")
	fmt.Println("итог:", fee(1200))
}

```
```

Для 3500 рублей условие истинно: ветвь напечатала свою пометку, `return 0`
вернул ноль, и функция закончилась. Пометки после `if` в этом вызове нет. Для
1200 рублей условие ложно, тело пропущено, и выполнились инструкции после
`if`, включая `return 300`.

Когда стоит писать функцию с таким ранним возвратом, а когда с одной `return`
в конце, разбирает урок 5.3.

## Цепочка if-else: выполняется первое истинное условие

Теперь правило из трёх вариантов: служба делит посылки по размеру. Крупная —
от 20 кг, средняя — от 5 кг, остальные мелкие. Условия пересекаются: посылка
в 25 кг весит и не меньше 20, и не меньше 5 кг. По смыслу правила она
крупная: «средняя» относится только к посылкам, которые не попали в крупные.

Первая попытка — две отдельные инструкции `if` одна под другой. Функция
`atLeast` в этом и следующем примере печатает, какое условие проверяется, и
возвращает значение сравнения; так видно, какие условия программа вычислила.
Прежде чем смотреть вывод, для 25, 12 и 3 кг скажите, какие условия будут
проверены, какие тела выполнятся и что вернёт `size`.

```go

### Example: `04-two-ifs`

Источник: `examples/04-two-ifs/`

```go
package main

import "fmt"

// atLeast печатает, какое условие проверяется, и возвращает weight >= limit.
func atLeast(weight int, limit int) bool {
	result := weight >= limit
	fmt.Println("  проверка weight >=", limit, "→", result)
	return result
}

// size определяет размер посылки двумя отдельными инструкциями if.
func size(weight int) string {
	label := "мелкая"
	if atLeast(weight, 20) {
		label = "крупная"
	}
	if atLeast(weight, 5) {
		label = "средняя"
	}
	return label
}

func main() {
	fmt.Println("== 25 кг ==")
	fmt.Println("итог:", size(25))
	fmt.Println("== 12 кг ==")
	fmt.Println("итог:", size(12))
	fmt.Println("== 3 кг ==")
	fmt.Println("итог:", size(3))
}

```
```

Отдельная `if` не связана с соседней: когда выполнение доходит до неё, она
проверяет своё условие, даже если тело соседней уже выполнилось. Здесь ни
одно тело не завершает функцию, поэтому обе `if` проверяются при каждом
вызове. Для 25 кг истинны оба условия, выполнились оба тела, и второе
присваивание перезаписало первое: функция вернула «средняя». Для 12 и 3 кг
ответ верный, потому что там истинно не больше одного условия. Ошибка видна
только на входе, где условия пересекаются.

Ровно один вариант выбирает цепочка `if`-`else`: после `else` вместо блока
стоит ещё одна инструкция `if`. Отдельного слова для этого в Go нет:
`else if` — это `else`, в ветви которого записана следующая `if`. Цепочка
`if atLeast(weight, 20) { … } else if atLeast(weight, 5) { … } else { … }`
выполняется так:

1. Проверить первое условие. Если оно истинно, выполнить первую ветвь, и
   цепочка закончена.
2. Иначе выполняется ветвь `else`, а в ней следующая `if`: проверить второе
   условие. Если оно истинно, выполнить вторую ветвь.
3. Если ложны все условия, выполнить последнюю ветвь `else`. Её может и не
   быть — тогда при всех ложных условиях не выполнится ни одна ветвь.

Условия проверяются сверху вниз до первого истинного. Выполняется ветвь этого
условия, а условия ниже него даже не вычисляются. Прежде чем смотреть вывод,
для тех же трёх посылок скажите, какие условия проверит цепочка и что вернёт
`size`.

```go

### Example: `05-chain`

Источник: `examples/05-chain/`

```go
package main

import "fmt"

// atLeast печатает, какое условие проверяется, и возвращает weight >= limit.
func atLeast(weight int, limit int) bool {
	result := weight >= limit
	fmt.Println("  проверка weight >=", limit, "→", result)
	return result
}

// size определяет размер посылки цепочкой if-else.
func size(weight int) string {
	var label string
	if atLeast(weight, 20) {
		label = "крупная"
	} else if atLeast(weight, 5) {
		label = "средняя"
	} else {
		label = "мелкая"
	}
	return label
}

func main() {
	fmt.Println("== 25 кг ==")
	fmt.Println("итог:", size(25))
	fmt.Println("== 12 кг ==")
	fmt.Println("итог:", size(12))
	fmt.Println("== 3 кг ==")
	fmt.Println("итог:", size(3))
}

```
```

Для 25 кг цепочка проверила одно условие: оно истинно, выполнилась ветвь
«крупная», а второе условие уже не вычислялось. Для 12 кг первое условие
ложно, второе истинно. Для 3 кг ложны оба, и выполнилась последняя ветвь
`else`.

Раз цепочка останавливается на первом истинном условии, при пересекающихся
условиях важен их порядок. Здесь узкое условие `weight >= 20` стоит выше
широкого `weight >= 5`. Если поставить широкое первым, для 25 кг оно окажется
истинным, цепочка остановится на варианте «средняя», и ветвь «крупная» не
выполнится ни при каком весе. Компилятор такую цепочку принимает, и
стандартный набор проверок `go vet` о ней не предупреждает: порядок
проверяете вы.

Условия цепочки не обязаны пересекаться. Каждый вариант можно записать
интервалом из урока 2.6: `weight < 5`, `5 <= weight && weight < 20` и
`20 <= weight`. Из таких условий при любом весе истинно ровно одно, поэтому от
перестановки ветвей ответ не меняется. Но цепочка и тогда проверяет условия
сверху вниз и останавливается на первом истинном.

## Края: под краем, на краю и над ним

Где проходит граница, решает правило задачи, а записать её нужно точно. Слова
правила подсказывают знак:

- «от 3000», «не меньше 3000», «3000 и больше» — край входит:
  `total >= 3000`;
- «больше 3000», «дороже 3000», «свыше 3000» — край не входит:
  `total > 3000`;
- «до 20 включительно», «не больше 20» — край входит: `weight <= 20`;
- «меньше 20», «легче 20 кг» — край не входит: `weight < 20`.

Если в правиле край не назван явно, как в «до 20 кг», уточните, входит ли он,
прежде чем писать условие.

Функции `feeFrom3000` и `feeOver3000` ниже записывают правило бесплатной
доставки знаками `>=` и `>`. Прежде чем смотреть вывод, предскажите обе платы
для заказов на 2999, 3000 и 3001 рубль.

```go

### Example: `06-endpoints`

Источник: `examples/06-endpoints/`

```go
package main

import "fmt"

// feeFrom3000 записывает правило «от 3000 рублей доставка бесплатна»:
// край 3000 входит в условие.
func feeFrom3000(total int) int {
	fee := 300
	if total >= 3000 {
		fee = 0
	}
	return fee
}

// feeOver3000 — та же функция со строгим знаком: край 3000 не входит.
func feeOver3000(total int) int {
	fee := 300
	if total > 3000 {
		fee = 0
	}
	return fee
}

// show печатает обе платы для заказа на сумму total.
func show(total int) {
	fmt.Println("заказ", total, "| с >=:", feeFrom3000(total), "| с >:", feeOver3000(total))
}

func main() {
	show(2999)
	show(3000)
	show(3001)
}

```
```

Две записи расходятся только на 3000 — на самом краю. Под краем обе берут
плату, над краем обе доставляют бесплатно. Отсюда способ проверки: для
каждого края берут вход сразу под ним, на нём и сразу над ним. Вход вдали от
края, например заказ на 10000 рублей, ошибку в знаке не заметит. У правила
размеров два края, поэтому входов шесть: 4, 5 и 6 кг, 19, 20 и 21 кг.

## Какую переменную меняет ветвь

Ветвь часто меняет переменную, объявленную до `if`, как `fee = fee + 200` в
`deliveryFee`. Присваивание `=` ничего не объявляет, поэтому компилятор ищет
переменную `fee` по правилу изнутри наружу из урока 2.3 и находит внешнюю.
После `if` видно новое значение. Если условие ложно, тело пропущено, и
переменная сохраняет прежнее значение.

Одиночный `:=` в ветви действует иначе. Он объявляет новую переменную в
блоке ветви, даже если снаружи уже есть переменная с тем же именем. Новая
переменная затеняет внешнюю до `}`, а внешнюю не меняет. Программа ниже
должна добавлять 150 рублей за срочную доставку, но в ветви стоит `:=`, и
новую переменную больше никто не читает. Прежде чем читать дальше, скажите,
что ответит компилятор.

```go
@broken unused-inner
```

Сообщение `declared and not used: cost` относится к строке в ветви: там
объявлена переменная `cost`, которую никто не читает. Это как раз новая
переменная, созданная `:=`.

Опаснее случай, когда новую переменную внутри ветви всё-таки читают,
например печатают для проверки. Тогда программа собирается. Функция `price`
ниже считает ту же плату: 300 рублей, срочная доставка на 150 рублей дороже.
Прежде чем смотреть вывод, для срочной и для обычной доставки назовите, какую
переменную называет `cost` в каждой строке функции, и скажите, что
напечатается.

```go

## Что компилятор требует от записи

Кроме логического условия, запись `if` требует фигурных скобок вокруг тела и
переносов строк только в разрешённых местах.

Фигурные скобки нужны всегда, даже если в теле одна инструкция. Программа
ниже их пропускает. Прежде чем смотреть сообщение, скажите, соберётся ли она
и в каком месте строки с `if` компилятор заметит ошибку.

```go
@broken no-braces
```

`syntax error: unexpected name fmt, expected {` — после условия компилятор
ждал `{`, а встретил имя `fmt`. Вслед за этим он печатает ещё одно или
несколько сообщений о синтаксисе. Они вызваны той же пропущенной скобкой,
поэтому чинить надо место из первого сообщения.

Круглые скобки вокруг всего условия, наоборот, не нужны. Запись
`if (weight > 5) {` законна и работает так же, но `gofmt` из урока 1.10
уберёт эти скобки: принято писать `if weight > 5 {`. Скобки внутри условия,
например `(a > 0) && (b > 0)` или `!(a > 0)`, `gofmt` оставляет: они
группируют операнды, как в уроке 2.6.

Переносы строк важны из-за точки с запятой. Инструкции Go разделяются точкой
с запятой, но в коде её почти не пишут: компилятор сам ставит её в конце
строки, если последний знак строки — имя, литерал, закрывающая скобка `)`,
`]` или `}`, знак `++` или `--` либо одно из ключевых слов `return`, `break`,
`continue` и `fallthrough`. Обычно это незаметно, но в `if` даёт два отказа.

Первый отказ — `else` на новой строке после `}`. Прежде чем смотреть
сообщение, найдите в программе ниже строку, в конце которой компилятор
поставит точку с запятой.

```go
@broken else-newline
```

Строка с одной `}` кончается скобкой, и после неё встала точка с запятой:
инструкция `if` на этом закончилась. Следующая строка начинается с `else`, а
с `else` инструкция начинаться не может:
`syntax error: unexpected keyword else, expected }`. Починка — писать
`} else {` на одной строке. Так же `gofmt` располагает и `} else if`.

Второй отказ — `{` на строке после условия.

```go
@broken brace-newline
```

Строка условия кончается литералом `5`, и после него компилятор поставил
точку с запятой. Заголовок `if` закончился, а открывающей скобки в нём нет:
`syntax error: unexpected newline, expected { after if clause`. Слово
`newline` в сообщении указывает на конец строки, где компилятор поставил
невидимую точку с запятой. Починка — `{` в конце строки с условием.

Эти два отказа не означают, что перенос строки внутри `if` запрещён вообще.
Их причина — точка с запятой, которая появляется только после знаков из
списка выше.

## if — инструкция, а не выражение

В Go `if` — инструкция: она выполняет одну из ветвей, но значения не даёт.
Поэтому её нельзя поставить справа от `:=`. Прежде чем смотреть сообщение,
скажите, соберётся ли программа ниже, и объясните почему.

```go
@broken if-expression
```

`syntax error: unexpected keyword if, expected expression` — справа от `:=`
компилятор ждал выражение, а встретил инструкцию. Тернарного оператора `?:`
из других языков в Go тоже нет:

```go
@broken ternary
```

Знака `?` в синтаксисе Go нет совсем, поэтому компилятор отвергает его как
недопустимый символ: `invalid character U+003F '?'`.

Результат выбора получают одним из двух способов:

- объявить переменную до `if` и присвоить ей значение в каждой ветви, как
  `way` в функции `method`. После `if`-`else` переменная хранит выбранное
  значение: его можно напечатать, использовать дальше или вернуть одной
  `return`;
- вернуть результат прямо из каждой ветви, как `return 0` в функции `fee`.

Функции ниже записывают правило бесплатной доставки обоими способами.
Прежде чем смотреть вывод, скажите, одинаково ли они ответят для 3500 и для
1200 рублей и какую строку напечатает `feeAssign`.

```go

### Example: `09-result-forms`

Источник: `examples/09-result-forms/`

```go
package main

import "fmt"

// feeAssign объявляет результат до if-else и присваивает его в каждой ветви.
func feeAssign(total int) int {
	var fee int
	if total >= 3000 {
		fee = 0
	} else {
		fee = 300
	}
	fmt.Println("  [feeAssign после if-else] fee =", fee)
	return fee
}

// feeReturn возвращает результат прямо из каждой ветви.
func feeReturn(total int) int {
	if total >= 3000 {
		return 0
	} else {
		return 300
	}
}

func main() {
	fmt.Println("== заказ 3500 ==")
	fmt.Println("итог:", feeAssign(3500), feeReturn(3500))
	fmt.Println("== заказ 1200 ==")
	fmt.Println("итог:", feeAssign(1200), feeReturn(1200))
}

```
```

Оба способа дали одинаковые ответы. `feeAssign` после выбора выполнила ещё и
печать: значение уже лежало в переменной. `feeReturn` заканчивается прямо в
ветви, поэтому инструкция после `if`-`else` в ней не выполнилась бы.

У возврата из ветвей есть условие сборки. Тело функции с результатом обязано
заканчиваться инструкцией, после которой функция точно не продолжится, —
например, `return`. Компилятор проверяет это по форме кода, а не по
значениям. Инструкция `if` подходит на эту роль, только если у неё есть
`else` и обе ветви заканчиваются так же; в цепочке это относится и к
последней ветви `else`. `if` без последнего `else` на эту роль не подходит,
даже когда её условия вместе покрывают все значения. Программа ниже проверяет
`weight >= 5` и `weight < 5`: при любом весе одно из двух истинно. Прежде чем
читать дальше, скажите, соберётся ли она.

```go
@broken missing-return
```

Не соберётся: `missing return` — после цепочки нет `return`, а цепочка без
последнего `else` функцию не завершает. Возможные значения веса компилятор
не перебирает. Починка — заменить `else if weight < 5` на `else` или добавить
`return` после всей цепочки.

## Проверка в тесте — та же инструкция if

Теперь проверку из урока 1.12 можно прочитать целиком. В тесте
`if Sign("Иван") != "Подпись: Иван" { t.Errorf(...) }` условие говорит
«получено не то, что ожидалось»:

- функция вернула ожидаемую строку — условие ложно, тело пропущено,
  `t.Errorf` не вызывается, и тест переходит к следующей инструкции;
- функция вернула другое — условие истинно, выполняется тело: `t.Errorf`
  записывает сообщение и помечает тест проваленным.

После `t.Errorf` тест продолжается. Это обычный вызов в теле `if`, а не
`return`: тело доходит до своей `}`, и выполняется следующая инструкция
теста, например следующая проверка. Поэтому один прогон сообщает обо всех
разошедшихся проверках, а не только о первой.

Проверка с допуском из урока 2.5 — та же инструкция. Для конечных чисел
условие «значения достаточно близки» — `math.Abs(got-want) <= eps`, а в
уроке 2.6 его отрицание стало условием провала:
`if !(math.Abs(got-want) <= eps) { t.Errorf(...) }`. В уроке 2.5 то же
условие провала записано как `math.Abs(got-want) > eps`; для конечных чисел
эти записи совпадают.

- Значения близки: условие близости истинно, `!` даёт ложь, тело
  пропускается, сообщения нет.
- Значения далеки: условие близости ложно, `!` даёт истину, `t.Errorf`
  сообщает о провале, и тест продолжается со следующей инструкции.

## Какая ветвь выполнилась

<!-- review:branch-trace -->

Постановка просила проследить `BikeSize` для 175, 145 и 100 см. Для цепочки
`if height >= 160 { … } else if height >= 130 { … } else { … }`:

- 175 см: первое условие истинно, выполняется ветвь «взрослый». Второе
  условие не вычисляется, а последняя ветвь `else` пропущена: цепочка
  остановилась на первом истинном условии.
- 145 см: первое условие ложно, поэтому выполняется его ветвь `else`, а в ней
  проверяется второе условие. Оно истинно, выполняется ветвь «подростковый»,
  последняя ветвь пропущена.
- 100 см: ложны оба условия, выполняется последняя ветвь `else` — «детский».

Если вы записали цепочку снизу вверх —
`if height < 130 { … } else if height < 160 { … } else { … }`, — условия
проверяются в другом порядке, но ответы те же. Для 175 см ложны оба условия,
и выполняется последняя ветвь; для 145 см первое ложно, второе истинно; для
100 см истинно первое, и дальше цепочка не идёт. Здесь тоже важен порядок:
условие `height < 160` истинно и при 100 см, поэтому оно обязано стоять ниже
`height < 130`.

Две отдельные `if` без `else`, которые сначала присваивают «взрослый» при
`height >= 160`, а потом «подростковый» при `height >= 130`, для 175 см
проверят оба условия: ни одно их тело не завершает функцию, и выполнение
доходит до второй `if`. Оба условия истинны, выполнятся оба тела, и второе
присваивание оставит «подростковый». Если поставить вторую `if` в ветвь
`else` первой, получится цепочка, и при пересекающихся условиях выполнится
одна ветвь.

## Надбавка осталась в ветви

<!-- review:fare-lost-update -->

Решение объявляет `fare := 60`, а в ветви пишет `fare := fare + 40` и
печатает результат для проверки. Сборка проходит, печать показывает 100, но

ложном условии тело пропускается, и цена остаётся 60.

  затем `return fee`.
- D. `fee := total >= 3000`, затем `return fee`.

Прежде чем смотреть ответ, для каждого тела скажите, соберётся ли оно, а для
того, что соберётся, — что оно вернёт для 3000 и для 2999 рублей и почему.

**Правильный ответ: C.**

`if`-`else` выполняет ровно одну ветвь, и эта ветвь присваивает объявленной
заранее `fee` нужное значение: для 3000 условие истинно, и `fee` равна 0, для
2999 ложно, и `fee` равна 300. `return` после `if`-`else` отдаёт это значение.
Годится и возврат прямо из каждой ветви. Вариант A ставит инструкцию `if`
туда, где нужно выражение, и не соберётся. Вариант B использует тернарный
оператор, которого в Go нет. Вариант D тоже не соберётся: `fee` получит тип
`bool`, а функция возвращает `int`, и логическое значение не заменяет число.

## Вопрос 8

В тесте подряд стоят две проверки:

1. `if !(math.Abs(got-want) <= eps) { t.Errorf("масса: получено %v, ожидалось %v", got, want) }`;
2. `if Size(3) != "мелкая" { t.Errorf("Size(3): неверный размер") }`.

`got` равно 12.5, `want` — 12.0, `eps` — 0.25, а `Size(3)` возвращает
`"мелкая"`. Что сообщит тест?

Варианты ответа:

- A. Ничего: после `!` тело первой проверки выполняется, только когда
  значения близки, а здесь они далеки; тест проходит.
- B. Первая проверка сообщает о провале массы и помечает тест проваленным;
  затем выполняется вторая проверка, её условие ложно, и от неё сообщения
  нет.
- C. Первая проверка сообщает о провале массы, и на этом тест заканчивается:
  вторая проверка не выполняется.
- D. Сообщают обе проверки: после первого провала тест считает проваленными
  и все следующие проверки.

Прежде чем смотреть ответ, вычислите условие близости, затем условие после
`!`, и скажите, какая инструкция выполнится после тела первой проверки.

**Правильный ответ: B.**

Разница 0.5 больше допуска 0.25, поэтому условие близости ложно, `!`
превращает его в истину, и выполняется `t.Errorf`: сообщение записано, тест
помечен проваленным. `t.Errorf` — обычный вызов в теле `if`, а не `return`:
тело доходит до `}`, и тест продолжается со второй проверки. Её условие
ложно, тело пропущено. Вариант A путает, когда `!` даёт истину: это
происходит, когда условие близости ложно, то есть когда значения далеки.
Вариант C приписывает `t.Errorf` действие `return`. Вариант D считает, что
провал меняет следующие проверки, а каждая `if` вычисляет своё условие
заново.
