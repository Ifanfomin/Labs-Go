# Множественное присваивание

В очереди стоят два заказа: первым — заказ с номером 3, вторым — с номером 8.
Номера лежат в переменных `first` и `second`. Заказы нужно поменять местами,
чтобы первым стал заказ 8. Кажется, хватит двух присваиваний: положить в
`first` значение `second`, а потом в `second` значение `first`. Но первое же
присваивание стирает старое значение `first`, и обмена не получается.

В Go такой обмен записывают одной строкой: `first, second = second, first`.
Слева от знака `=` стоит список переменных, справа — список значений. Такая
строка называется **множественным присваиванием**. Она сначала читает все
значения справа и только потом записывает их в переменные слева. Из-за этого
порядка обмен не теряет значений. Тот же порядок помогает, когда несколько
переменных должны измениться согласованно.

К концу урока вы сможете:

- объявить и изменить несколько переменных одной строкой и сказать, какое
  значение и какой тип получит каждая;
- предсказать результат обмена, сдвига трёх значений по кругу и шага пары
  связанных чисел и объяснить, почему две отдельные строки дают другой
  результат;
- по сообщению компилятора понять, что не совпало: число переменных и
  значений или тип значения;
- различить строку `:=`, которая даёт новое значение уже объявленной
  переменной, отказ `no new variables` и новую переменную во внутреннем
  блоке;
- вести два счётчика в заголовке цикла `for` и починить завершающую
  инструкцию `i++, j--`.

Понадобятся уроки 2.1–2.3: `var`, `:=` и `=`, типы литералов по умолчанию,
блоки и затенение имён. Из урока 2.10 — то, что `i++` и `i--` являются
инструкциями, а не выражениями. Из урока 3.5 — цикл `for` с инструкцией
инициализации, условием и завершающей инструкцией.

## Одна строка — несколько переменных

Короткое объявление может завести сразу несколько переменных. Слева от `:=`
пишут имена через запятую, справа — столько же выражений через запятую:
`i, j := 0, 10`. Первое имя слева получает первое значение справа, второе —
второе: `i` становится равной 0, а `j` — 10. Обе переменные — обычные
переменные, как если бы их объявили двумя отдельными строками. Тип каждая
получает от своего значения по правилам урока 2.1. Имён может быть и больше
двух.

Программа ниже объявляет так две целые переменные, а потом три переменные с
литералами разного вида. Прежде чем смотреть вывод, назовите значение и тип
каждой из пяти переменных.

```go

### Example: `01-pair-declare`

Источник: `examples/01-pair-declare/`

```go
package main

import "fmt"

func main() {
	i, j := 0, 10
	fmt.Printf("i = %d (%T), j = %d (%T)\n", i, i, j, j)

	count, ratio, title := 3, 2.5, "Go"
	fmt.Printf("count: %v (%T)\n", count, count)
	fmt.Printf("ratio: %v (%T)\n", ratio, ratio)
	fmt.Printf("title: %v (%T)\n", title, title)
}

```
```

Переменные `i` и `j` получили тип `int`: оба значения — целые литералы.
Переменные `count`, `ratio` и `title` тоже объявлены одной строкой, но общего
типа у них нет: каждая получила тип своего литерала. Целый литерал снова дал
`int`, литерал с точкой — `float64`, строка в кавычках — `string`.

Запятая здесь только разделяет элементы двух списков: имена слева и выражения
справа. Она не собирает несколько значений в одно составное значение, которое
можно было бы положить в одну переменную. Программа ниже пробует записать два
значения в одну переменную. Прежде чем читать дальше, скажите, соберётся ли
она.

```go
@broken tuple-value
```

Не соберётся. Компилятор сравнивает число имён и значений и сообщает, что они
не совпали:

`assignment mismatch: 1 variable but 2 values`

По-русски: в присваивании одна переменная, а значений два. Слово `assignment`
(присваивание) компилятор употребляет и для `:=`: объявление с начальным
значением тоже кладёт значения в переменные.

## Обмен двух значений

Знак `=` принимает такие же списки. Строка `first, second = second, first`
ничего не объявляет: обе переменные уже есть, и строка кладёт в них новые
значения. Выполняется она в два шага:

1. Сначала вычисляются все выражения справа. Каждое читает переменные такими,
   какими они были до этой строки.
2. Потом полученные значения записываются в переменные слева по порядку, слева
   направо: первое значение — в первую переменную, второе — во вторую.

Первый шаг заканчивается целиком до первой записи. Поэтому ни одно выражение
справа не видит того, что запишет эта же строка.

Примените два шага к обмену. Пусть `first` равна 3, а `second` равна 8. Какие
два значения получит первый шаг, что второй шаг запишет в `first` и что — в
`second`? Предскажите обе строки вывода.

```go

### Example: `02-swap`

Источник: `examples/02-swap/`

```go
package main

import "fmt"

func main() {
	// Номера двух заказов в очереди: сейчас первым стоит заказ 3.
	first, second := 3, 8
	fmt.Printf("до обмена: first = %d, second = %d\n", first, second)

	first, second = second, first
	fmt.Printf("после обмена: first = %d, second = %d\n", first, second)
}

```
```

Вот оба шага по порядку:

| Момент | Что происходит | `first` | `second` |
|---|---|---|---|
| до строки | — | 3 | 8 |
| шаг 1 | справа прочитаны `second` и `first`: получены 8 и 3 | 3 | 8 |
| шаг 2, первая запись | 8 записано в `first` | 8 | 8 |
| шаг 2, вторая запись | 3 записано в `second` | 8 | 3 |

Две записи идут одна за другой: сначала 8 ложится в первую переменную, потом
3 — во вторую. Между этими записями обе переменные на миг равны 8. Тройка
при этом не теряется: её прочитали на первом шаге, до первой записи. Обмен
удаётся именно поэтому — оба правых значения прочитаны раньше, чем началась
запись.

## Две строки вместо одной

Теперь та же задача двумя обычными присваиваниями: `first = second`, затем
`second = first`. Каждая из этих строк — отдельная инструкция. Она выполняется
целиком, прежде чем начнётся следующая, и следующая читает то, что оставила
предыдущая (урок 2.1). Прежде чем смотреть вывод, запишите значения `first` и
`second` после каждой строки.

```go

### Example: `03-sequential`

Источник: `examples/03-sequential/`

```go
package main

import "fmt"

func main() {
	first, second := 3, 8

	first = second
	fmt.Printf("после первой строки: first = %d, second = %d\n", first, second)

	second = first
	fmt.Printf("после второй строки: first = %d, second = %d\n", first, second)
}

```
```

Первая строка записала 8 в `first`, и значение 3 больше не хранится ни в одной
переменной. Вторая строка читает `first` и получает уже 8. Старое значение
`first` потеряно на первой же строке, поэтому обе переменные равны 8, а обмена
нет.

Двумя строками обмен сделать можно, если сначала сохранить старое значение в
третьей переменной: `old := first`, `first = second`, `second = old`.
Множественное присваивание обходится без лишнего имени: все правые значения
прочитаны до первой записи, и ни одно из них не теряется.

## Сдвиг трёх значений по кругу

Списки бывают длиннее двух. Строка `a, b, c = c, a, b` сдвигает три значения
на одну позицию вправо: значение `a` переходит в `b`, значение `b` — в `c`, а
значение `c` уходит в начало, в `a`. Правило то же: сначала читаются все три
старых значения, потом они записываются слева направо.

Пусть `a`, `b` и `c` равны 1, 2 и 3. Прежде чем смотреть вывод, назовите три
значения, которые прочитает первый шаг, и то, что окажется в каждой
переменной после строки.

```go

### Example: `04-rotate-right`

Источник: `examples/04-rotate-right/`

```go
package main

import "fmt"

func main() {
	a, b, c := 1, 2, 3
	fmt.Printf("до сдвига: a = %d, b = %d, c = %d\n", a, b, c)

	a, b, c = c, a, b
	fmt.Printf("после сдвига: a = %d, b = %d, c = %d\n", a, b, c)
}

```
```

Первый шаг прочитал `c`, `a` и `b` — это 3, 1 и 2, — и только потом эти числа
легли в `a`, `b` и `c`. Если разбить тот же сдвиг на три отдельных
присваивания, первая же строка затрёт одно из старых значений, как при
обмене.

## Пара, которая шагает вместе

Множественное присваивание особенно полезно, когда новое значение одной
переменной вычисляется из старого значения другой. Возьмём последовательность
чисел, которая начинается с 0 и 1, а каждое следующее число в ней равно сумме
двух предыдущих: 0, 1, 1, 2, 3, 5, 8 и так далее. Пусть переменные `left` и
`right` держат два соседних числа этой последовательности. Шаг вперёд — это
переход к следующей паре соседей: новое `left` равно старому `right`, а новое
`right` равно сумме старых `left` и `right`. Одной строкой:

`left, right = right, left+right`

Оба выражения справа читают старую пару, поэтому строку удобно проверять
таблицей «старое — новое». Вот два первых шага от пары 0 и 1:

| Шаг | старое `left` | старое `right` | новое `left` | новое `right` |
|---|---|---|---|---|
| 1 | 0 | 1 | 1 | 0 + 1 = 1 |
| 2 | 1 | 1 | 1 | 1 + 1 = 2 |

Каждая строка таблицы начинается с пары, которой закончилась предыдущая.
Программа ниже повторяет шаг шесть раз в цикле `for` из урока 3.5; счётчик
`step` нужен только для печати номера шага. Прежде чем смотреть вывод,
продолжите таблицу до шестого шага.

```go

### Example: `05-pair-step`

Источник: `examples/05-pair-step/`

```go
package main

import "fmt"

func main() {
	left, right := 0, 1
	fmt.Printf("старт: left = %d, right = %d\n", left, right)

	for step := 1; step <= 6; step++ {
		left, right = right, left+right
		fmt.Printf("шаг %d: left = %d, right = %d\n", step, left, right)
	}
}

```
```

После шестого шага пара равна 8 и 13 — это снова два соседних числа
последовательности.

Теперь пара шагает двумя отдельными строками: `left = right`, затем
`right = left + right`. Прежде чем смотреть вывод, пройдите первый шаг от пары
0 и 1: какое значение `left` прочитает вторая строка и чему станет равно
`right`?

```go

### Example: `06-pair-sequential`

Источник: `examples/06-pair-sequential/`

```go
package main

import "fmt"

func main() {
	left, right := 0, 1

	for step := 1; step <= 4; step++ {
		left = right
		right = left + right
		fmt.Printf("шаг %d: left = %d, right = %d\n", step, left, right)
	}
}

```
```

Вторая строка читает `left`, которую первая строка уже заменила старым
`right`. Поэтому `right = left + right` складывает старое `right` с самим собой,
и `right` удваивается на каждом шаге: 2, 4, 8, 16. Сумма двух предыдущих чисел
не получается ни разу. Ошибку легко пропустить: `left` на первом шаге верна, и
отличие видно только в `right`.

Не всякая пара переменных связана. В строке `i, j = i+1, j-1` выражение для
`i` читает только `i`, а выражение для `j` — только `j`. Две отдельные строки
`i = i + 1` и `j = j - 1` дали бы здесь тот же результат: ни одна из них не
читает переменную, которую уже изменила другая. Такую строку пишут по другой
причине: завершающая инструкция цикла `for` может быть только одной. Этот
случай разобран в разделе «Два счётчика в заголовке for».

## Что должно совпасть: число и типы

Строка множественного присваивания собирается при двух условиях:

1. Переменных слева столько же, сколько выражений справа, и каждое выражение
   даёт одно значение. Значение с номером n идёт в переменную с номером n.
2. Каждое значение подходит к типу своей переменной — так же, как в обычном
   присваивании из урока 2.1.

В программе ниже строка присваивания меняет две переменные, но справа
осталось одно значение. Прежде чем читать дальше, скажите, что сообщит
компилятор.

```go
@broken arity-assign
```

Компилятор снова сравнивает число переменных и значений:

`assignment mismatch: 2 variables but 1 value`

Здесь две переменные и одно значение — обратный случай к `x := 1, 2`.
Сообщение называет только два числа и не указывает, какой переменной не
хватило значения. Строку чинят по замыслу: дописывают недостающее значение или
убирают лишнюю переменную.

В следующей программе `count` — целое число, а `label` и `title` — строки.
Правая часть присваивания по ошибке начинается с `title`. Прежде чем читать
дальше, найдите значение, которое не подходит своей переменной.

```go
@broken wrong-type
```

`cannot use title (variable of type string) as int value in multiple assignment`

По-русски: переменную `title` типа `string` нельзя использовать как значение
типа `int` в множественном присваивании. Компилятор проверяет каждую пару
«переменная — значение» отдельно. Первая пара — `count` и `title`, и в ней
строка стоит на месте целого числа. То, что `title` подошла бы ко второй
переменной, `label`, ничего не меняет: пару задаёт позиция в списке.

## Короткое объявление с уже объявленным именем

По уроку 2.2 одиночный `:=` с именем, уже объявленным в том же блоке, не
собирается. Строку с несколькими именами слева урок 2.2 оставил на потом: для
неё правило точнее. Строка `:=` с несколькими именами собирается, если:

1. хотя бы одно имя слева новое для этого блока; особое имя `_` из урока 4.10
   новым не считается;
2. остальные имена объявлены раньше в этом же блоке, а если строка стоит на
   внешнем уровне тела функции, это могут быть и параметры функции;
3. значение для каждой уже объявленной переменной подходит к её типу: тип у
   неё остаётся прежним.

Для новых имён такая строка — объявление. Для уже объявленных — обычное
присваивание: вторая переменная с тем же именем не появляется, существующая
получает новое значение.

Программа ниже объявляет `total`, а потом пишет `total, note := 20, "обновлено"`.
Прежде чем смотреть вывод, скажите, какое имя в этой строке новое, какое уже
объявлено, и какие типы напечатаются.

```go

### Example: `07-mixed-reuse`

Источник: `examples/07-mixed-reuse/`

```go
package main

import "fmt"

func main() {
	total := 10
	fmt.Printf("до: total = %v (%T)\n", total, total)

	total, note := 20, "обновлено"
	fmt.Printf("после: total = %v (%T), note = %v (%T)\n", total, total, note, note)
}

```
```

`note` — новая переменная типа `string`. `total` уже была объявлена в этом
блоке, поэтому строка только положила в неё 20, а тип остался `int`. В блоке
по-прежнему одна переменная `total`.

Такая строка не собирается в двух случаях. Первый: новых имён слева нет.
Прежде чем читать дальше, скажите, что ответит компилятор на вторую строку
программы ниже.

```go
@broken no-new-pair
```

`no new variables on left side of :=`

Это тот же отказ, что у одиночного `:=` в уроке 2.2: слева от `:=` нет ни
одной новой переменной. Обе уже объявлены в этом блоке, объявлять нечего. Если
задумано обновить обе, нужен знак `=`: `a, b = 3, 4`.

Второй случай: уже объявленной переменной достаётся значение другого типа. В
программе ниже `n` объявлена как `int`, а строка `:=` кладёт в неё строку.
Имя `s` новое, так что первое условие выполнено. Прежде чем читать дальше,
скажите, появится ли новая переменная `n` строкового типа.

```go
@broken retype-pair
```

Не появится:

`cannot use "two" (untyped string constant) as int value in multiple assignment`

Компилятор не заводит вторую `n`, а присваивает значение существующей, и
строковое значение не подходит к её типу `int`. Слова `untyped string constant`
означают строковый литерал, у которого тип ещё не выбран (урок 2.2). Если нужна
строковая переменная, дайте ей новое имя.

## Во внутреннем блоке — новая переменная

Правило о повторно используемых именах касается только того же блока. Имя,
объявленное во внешнем блоке, во внутреннем блоке не считается «уже
объявленным здесь». Поэтому во внутреннем блоке `:=` объявит новую переменную
с тем же именем, и она затенит внешнюю до конца блока (урок 2.3). Внешняя
переменная при этом не меняется.

Вторая деталь тоже из урока 2.3: новое имя начинает действовать только после
конца строки, которая его объявляет. Поэтому в правой части этой строки то же
имя ещё называет внешнюю переменную.

Программа ниже объявляет `level` в теле `main`, а во внутреннем блоке пишет
`level, bonus := level+10, 5`. Прежде чем смотреть вывод, для трёх
употреблений `level` — справа от `:=`, в печати внутри блока и в печати после
блока — скажите, какую переменную называет имя, и предскажите обе строки
вывода.

```go

### Example: `08-inner-block`

Источник: `examples/08-inner-block/`

```go
package main

import "fmt"

func main() {
	level := 1
	{
		level, bonus := level+10, 5
		fmt.Println("в блоке: level =", level, "bonus =", bonus)
	}
	fmt.Println("после блока: level =", level)
}

```
```

| Где стоит `level` | Какую переменную называет | Значение |
|---|---|---|
| справа от `:=`, в `level+10` | внешнюю: внутренняя ещё не объявлена | 1 |
| в печати внутри блока | внутреннюю, объявленную этой строкой | 11 |
| в печати после блока | внешнюю: внутренняя кончилась на `}` | 1 |

Обе переменные в строке внутреннего блока новые, поэтому это объявление, а не
повторное использование внешней `level`. Компилятор принимает такую программу
молча, и `go vet` с настройками по умолчанию о ней тоже не предупреждает. Если
во внутреннем блоке задумано изменить внешнюю переменную, её меняют знаком
`=`, а новую переменную объявляют отдельной строкой.

## Одно имя дважды слева

Имена слева от `:=` не должны повторяться. Прежде чем читать дальше, скажите,
что ответит компилятор на строку `a, a := 1, 2`.

```go
@broken repeated-name
```

`a repeated on left side of :=`

По-русски: имя `a` повторено слева от `:=`. Одна строка не объявляет одно имя
дважды.

Со знаком `=` та же запись собирается: он ничего не объявляет, а только
записывает. По второму шагу правила записи идут слева направо, поэтому
последней в переменную ляжет двойка.

```go

### Example: `09-same-target`

Источник: `examples/09-same-target/`

```go
package main

import "fmt"

func main() {
	var a int
	a, a = 1, 2
	fmt.Println("a =", a)
}

```
```

Писать так незачем: первая запись сразу теряется. Пример показывает только
одно — записи действительно идут по порядку, слева направо.

## Два счётчика в заголовке for

В ряду шесть мест с номерами от 0 до 5. Их нужно разбить на пары от краёв к
середине: первое с последним, второе с предпоследним и так далее. Понадобятся
два счётчика: `i` идёт слева и растёт, `j` идёт справа и уменьшается. Цикл
продолжается, пока `i < j`.

Инструкция инициализации цикла может объявить оба счётчика одной строкой
`:=`, как в первом разделе урока. Менять оба счётчика удобно в завершающей
инструкции, а она состоит ровно из одной простой инструкции. Оба изменения
укладываются в одну инструкцию в виде множественного присваивания:

`for i, j := 0, 5; i < j; i, j = i+1, j-1 {`

Прежде чем смотреть вывод, составьте таблицу проверок условия: значения `i` и
`j` перед каждой проверкой и результат `i < j`. Сколько пар напечатается?

```go

### Example: `10-two-ends`

Источник: `examples/10-two-ends/`

```go
package main

import "fmt"

func main() {
	// Шесть мест в ряду, номера от 0 до 5. Пары: первое с последним,
	// второе с предпоследним и так далее к середине.
	for i, j := 0, 5; i < j; i, j = i+1, j-1 {
		fmt.Printf("пара мест: %d и %d\n", i, j)
	}
}

```
```

| Проверка | `i` | `j` | `i < j` | Что дальше |
|---|---|---|---|---|
| 1 | 0 | 5 | true | тело, затем `i, j = i+1, j-1` |
| 2 | 1 | 4 | true | тело и завершающая инструкция |
| 3 | 2 | 3 | true | тело и завершающая инструкция |
| 4 | 3 | 2 | false | цикл закончен |

Завершающая инструкция каждый раз вычисляет оба новых значения из старых.
Здесь ни одно выражение не читает другой счётчик, так что порядок записей на
результат не влияет. Важно другое: оба изменения стоят в одной инструкции.

Запись `i++, j--` выглядит короче, но такая завершающая инструкция не
собирается. Прежде чем читать дальше, вспомните, чем в Go является `i++`, и
скажите, почему.

```go
@broken post-comma
```

`syntax error: unexpected comma, expected { after for clause`

Компилятор разобрал `i++` как завершающую инструкцию и ждал за ней `{`, а
встретил запятую. В Go нет операции «запятая», которая склеивала бы две
инструкции в одну. А `i++` и `j--` — инструкции, а не выражения (урок 2.10),
поэтому поставить их в список справа от `=` тоже нельзя. Замена одна:
`i, j = i+1, j-1`.

Объявление в завершающей инструкции запрещено, и множественная форма
исключением не становится. Прежде чем читать дальше, скажите, что ответит
компилятор, если в завершающей инструкции заменить `=` на `:=`.

```go
@broken post-declare
```

`syntax error: cannot declare in post statement of for loop`

По-русски: в завершающей инструкции цикла `for` объявлять нельзя. Объявить
счётчики может инструкция инициализации, а завершающая инструкция меняет их
присваиванием или инструкциями `++` и `--`.

## Похожая запись — другой механизм

Во всех строках этого урока справа стоит список отдельных выражений, и каждое
даёт одно значение. Позже вы встретите строки, которые выглядят так же, но
получают несколько значений другим способом:

- функция может вернуть сразу несколько результатов, и тогда справа стоит один
  её вызов (урок 5.2);
- чтение из map может вернуть значение и признак того, нашёлся ли ключ
  (урок 4.12);
- перебор набора значений может давать номер элемента и сам элемент
  (урок 4.10).

Запятые слева там те же, но откуда берутся значения и сколько их, объясняют
эти уроки. Условие «сколько переменных, столько выражений» из этого урока
относится к списку отдельных значений.

И ещё одна граница. Правило двух шагов показано здесь на переменных и
выражениях, которые только читают значения. Когда слева стоят элементы
массива или справа — вызовы функций, которые что-то меняют, возникают вопросы
о порядке отдельных вычислений. Их разбирают позже, и переносить на них выводы
этого урока без проверки не стоит.

## RotateLeft

`RotateLeft` сдвигает три значения на одну позицию влево: второе значение
становится первым, третье — вторым, а первое уходит в конец. Результат — три
числа после сдвига, записанные через один пробел, без пробелов в начале и в
конце. Отрицательное число записывается со знаком минус.

- `RotateLeft(1, 2, 3)` возвращает `"2 3 1"`;
- `RotateLeft(-1, 0, 4)` возвращает `"0 4 -1"`;
- `RotateLeft(5, 5, 5)` возвращает `"5 5 5"`.

## Fibonacci

Последовательность начинается с чисел 0 и 1, а каждое следующее число равно
сумме двух предыдущих. Числа нумеруются с нуля:

| Номер | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| Число | 0 | 1 | 1 | 2 | 3 | 5 | 8 | 13 |

Например, число с номером 5 равно 5: это сумма чисел с номерами 3 и 4, то есть
2 + 3. Такие числа называют числами Фибоначчи, но знать это название для
задачи не нужно.

`Fibonacci(n)` возвращает число последовательности с номером `n`.

- `Fibonacci(0)` возвращает 0;
- `Fibonacci(1)` возвращает 1;
- `Fibonacci(7)` возвращает 13.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Порядок при сдвиге

<!-- review:rotation-order -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет». Если тело
двигает значения строками `a = b`, `b = c`, `c = a`, то `RotateLeft(1, 2, 3)`
вернёт `"2 3 2"`. Первая строка записала 2 в `a`, исходная единица больше
нигде не хранится, и третья строка кладёт в `c` уже новое `a`.

Такие три строки всегда кладут в конец второе исходное число вместо первого.
Поэтому ошибка не видна, когда первое и второе числа равны: на входе 7, 7, 2
верный сдвиг и ошибочный дают одну и ту же строку `"7 2 7"`. На входе 2, 7, 7
ответы расходятся: верный — `"7 7 2"`, ошибочный — `"7 7 7"`. Поэтому в наборе
тестов есть входы, где первые два числа различаются.

Верное решение читает все три старых значения до записи: `a, b, c = b, c, a`,
а затем `return fmt.Sprintf("%d %d %d", a, b, c)`. Работает и запись с
временной переменной: `first := a`, потом `a = b`, `b = c`, `c = first`. Тест
эти решения не различает.

## Таблица пары

<!-- review:pair-table -->

Второй вопрос. Пара начинается с чисел 0 и 1 — это числа с номерами 0 и 1.
Каждый шаг заменяет пару следующей: новое первое число — прежнее второе, новое
второе — сумма прежних.

| `k` | первое число | второе число |
|---|---|---|
| 0 | 0 | 1 |
| 1 | 1 | 1 |
| 2 | 1 | 2 |
| 3 | 2 | 3 |
| 4 | 3 | 5 |

После `k` шагов первое число пары — это число с номером `k`. Значит, для номера
`n` нужно ровно `n` шагов и вернуть первое число пары. При `n`, равном 0, цикл
не выполняется ни разу, и возвращается стартовое 0. Верное решение:
`prev, cur := 0, 1`, цикл `for i := 0; i < n; i++` с телом
`prev, cur = cur, prev+cur` и затем `return prev`.

Третий вопрос. Если менять пару строками `prev = cur` и `cur = prev + cur`,
вторая строка читает уже новое `prev`, и `cur` удваивается. `Fibonacci(2)`
тогда вернёт 2 вместо 1: после первого шага пара равна 1 и 2, после второго —
2 и 4.

## Три строки вместо одной

<!-- review:rotate-sequential -->

Решение двигает значения строками `a = b`, `b = c`, `c = a`. Ловит это
`TestRotateLeft`: для `RotateLeft(1, 2, 3)` тест ждёт `"2 3 1"`, а получает
`"2 3 2"`. На входах с равными первыми двумя числами ответ совпадает с верным,
поэтому набор тестов их не ограничивается. Верная запись — одна строка
множественного присваивания или временная переменная для первого значения.

## Сдвиг не в ту сторону

<!-- review:rotate-right -->

Решение пишет `a, b, c = c, a, b` — это сдвиг вправо из теории, а не влево.
Ловит это `TestRotateLeft`: для `RotateLeft(1, 2, 3)` тест ждёт `"2 3 1"`, а
получает `"3 1 2"`. При сдвиге влево на первое место встаёт второе значение,
поэтому справа от `=` идут `b`, `c` и `a`.

## Пара меняется двумя строками

<!-- review:fib-sequential -->

Решение меняет пару строками `prev = cur` и `cur = prev + cur`. Ловит это
`TestFibonacci`: для номера 2 тест ждёт 1, а получает 2. На номерах 0 и 1
ответ случайно верен, поэтому тест проверяет и следующие номера. Верная
запись — `prev, cur = cur, prev+cur`: обе правые части читают старую пару.

## Возвращено второе число пары

<!-- review:fib-returns-cur -->

Решение ведёт пару верно, но возвращает `cur`. Ловит это `TestFibonacci`: для
номера 0 тест ждёт 0, а получает 1. После `n` шагов номер `n` у первого числа
пары, а у второго числа номер на единицу больше.

## На один шаг меньше

<!-- review:fib-short-loop -->

Решение начинает счётчик цикла с 1 и делает на один шаг меньше, чем нужно.
Ловит это `TestFibonacci`: для номера 1 тест ждёт 1, а получает 0. На номере 0
цикл не выполняется ни в одном из решений, а на номере 2 выручает совпадение:
числа с номерами 1 и 2 оба равны 1. Верный цикл — `for i := 0; i < n; i++`:
ровно `n` шагов.

# Проверочные вопросы

## Вопрос 1

Автор хотел поменять значения `first` и `second` местами двумя строками, но
записал их в другом порядке, чем в теории.

```go
@quiz _quiz/01-copy-order
```

Какие значения `first` и `second` напечатает программа?

Варианты ответа:

- A. 8 и 3.
- B. 3 и 3.
- C. 8 и 8.
- D. 3 и 8.

Прежде чем смотреть ответ, запишите значения `first` и `second` после каждой
строки присваивания и назовите старое значение, которое программа потеряла.

**Правильный ответ: B.**

Первая строка кладёт в `second` значение `first`, то есть 3, и восьмёрка
больше нигде не хранится. Вторая строка читает `second` и получает уже 3.
Вариант A приписывает двум строкам правило одной строки: все правые значения
заранее читает только `first, second = second, first`. Вариант C — итог
программы из теории, где первой идёт строка `first = second`. Вариант D
забывает, что первая строка изменила `second`.

## Вопрос 2

Автор хотел сдвинуть три значения влево: значение `b` — в `a`, значение `c` —
в `b`, значение `a` — в `c`. Сдвиг записан тремя строками.

```go
@quiz _quiz/02-rotate-steps
```

Какие значения `a`, `b` и `c` напечатает программа?

Варианты ответа:

- A. 2, 3 и 1.
- B. 3, 1 и 2.
- C. 2, 2 и 2.
- D. 2, 3 и 2.

Прежде чем смотреть ответ, проследите значения `a`, `b` и `c` после каждой
строки. Затем скажите, при каких исходных значениях эти три строки случайно
дали бы верный сдвиг.

**Правильный ответ: D.**

После `a = b` в `a` лежит 2, и исходная единица потеряна. `b = c` даёт 3.
`c = a` читает уже новое `a` и кладёт 2. Вариант A — верный сдвиг влево: его
даёт одна строка, которая читает все три старых значения до записи. Вариант B
— сдвиг вправо из теории. Вариант C не замечает, что `b = c` читает `c`, а не
`a`.

Ответ на второй вопрос: три строки всегда кладут в `c` второе исходное
значение вместо первого. Ошибка не видна, когда первое и второе значения
равны, например 7, 7 и 2. Поэтому сдвиг проверяют на входе, где первые два
значения различаются.

## Вопрос 3

```go
@quiz _quiz/03-pair-table
```

Какие значения `left` и `right` напечатает программа?

Варианты ответа:

- A. 20 и 40.
- B. 7 и 12.
- C. 12 и 19.
- D. 19 и 31.

Прежде чем смотреть ответ, заполните таблицу из трёх строк: старое `left`,
старое `right`, новое `left`, новое `right`. Каждая строка начинается с пары,
которой закончилась предыдущая.

**Правильный ответ: C.**

От пары 2 и 5 шаги дают 5 и 7, потом 7 и 12, потом 12 и 19: новое `left` —
старое `right`, новое `right` — сумма старых. Вариант A получится, если
`right` читает уже новое `left`, как при двух отдельных строках: тогда `right`
удваивается. Вариант B останавливается после двух шагов, а цикл делает три.
Вариант D делает лишний, четвёртый шаг.

## Вопрос 4

Границы отрезка ввели в обратном порядке, и автор хотел поменять их местами.
Программа не собирается.

```go
@quiz _broken/quiz-arity
```

Какая строка вместо `low, high = high` соберётся и поменяет значения местами?

Варианты ответа:

- A. `low = high`
- B. `low, high := high, low`
- C. `high, low = high`
- D. `low, high = high, low`

Прежде чем смотреть ответ, скажите, что не совпало в строке
`low, high = high`, и для каждого варианта решите, соберётся ли он и что
окажется в `low` и `high`.

**Правильный ответ: D.**

Сейчас слева две переменные, а справа одно значение:
`assignment mismatch: 2 variables but 1 value`. Вариант D дописывает второе
значение, и обмен проходит: `low` получает 3, `high` — 8. Вариант A
собирается, но теряет восьмёрку: обе переменные станут равны 3. Вариант B не
соберётся: обе переменные уже объявлены в этом блоке, и компилятор отклонит
`:=` с сообщением `no new variables`. Вариант C переставляет имена, но
значение справа по-прежнему одно.

## Вопрос 5

```go
@quiz _quiz/05-param-reuse
```

Что программа напечатает как результат `grow` и как значение `score`?

Варианты ответа:

- A. 105 и 5.
- B. 105 и 4.
- C. 101 и 4.
- D. Не соберётся: имя `n` уже занято параметром.

Прежде чем смотреть ответ, для строки `n, step := n+1, 100` скажите, какое
имя слева новое, какое уже объявлено и где, и какую переменную читает `n+1`.

**Правильный ответ: B.**

`step` — новое имя, поэтому строка собирается. `n` — параметр, а строка стоит
на внешнем уровне тела `grow`, поэтому для `n` это присваивание: параметр
получает 5, `step` — 100, и функция возвращает 105. Вариант A забывает, что
параметр — копия аргумента: `score` в `main` остаётся 4. Вариант C считает
`n` справа новой переменной с нулевым значением, но правая часть читает
параметр, равный 4. Вариант D применяет правило одиночного `:=`, а здесь
хватает одного нового имени.

## Вопрос 6

Программа должна сделать один шаг: `done` вырастает на единицу, `left`
уменьшается на единицу.

```go
@quiz _broken/quiz-no-new
```

Что ответит компилятор?

Варианты ответа:

- A. Ничего: вторая строка объявит новые `done` и `left`, и программа
  напечатает 1 и 4.
- B. Не соберётся: имя `done` повторено, оно уже стояло слева в первой
  строке.
- C. `no new variables on left side of :=`: обе переменные уже объявлены в
  этом блоке.
- D. Не соберётся: `done+1` читает переменную, которую объявляет эта же
  строка.

Прежде чем смотреть ответ, для каждого имени слева во второй строке скажите,
объявлено ли оно раньше в этом же блоке. Затем назовите ремонт, после которого

**Правильный ответ: C.**

Обе переменные объявлены первой строкой в том же блоке, и новых имён во второй
строке нет. Ремонт — `=` вместо `:=` во второй строке: это множественное
присваивание, и переменные получат 1 и 4. Вариант A верен только для
внутреннего блока, а здесь блок один. Вариант B путает правила: повтором
называется одно имя, записанное дважды в одной строке, как `a, a := 1, 2`.
Вариант D не видит, что `done` и `left` объявлены строкой выше, и правая часть
читает их.

## Вопрос 7

Автор хотел, чтобы цена дальше хранилась строкой, и добавил переменную для

Что произойдёт?

- A. Появится новая строковая `price`, и программа напечатает «сто руб.».

- C. Не соберётся: слева нет ни одного нового имени.
- D. Соберётся, и `price` станет строковой переменной.

## Вопрос 8

```go
@quiz _quiz/08-inner-trace
```

Какие значения `count` и `total` напечатает программа?

Варианты ответа:

- A. `count` равна 1, `total` равна 12.
- B. `count` равна 2, `total` равна 12.
- C. `count` равна 1, `total` равна 0.
- D. Не соберётся: `count` уже объявлена в `main`.

Прежде чем смотреть ответ, для каждого употребления `count` и `total` в блоке
и после него назовите объявление, которое оно называет: внешнее или
внутреннее.

**Правильный ответ: A.**

Во внутреннем блоке `count` и `extra` — новые имена: внешняя `count` объявлена

меняет внешнюю `total`: 2 + 10 = 12. После блока `count` снова называет
внешнюю переменную, а она осталась 1. Вариант B применяет правило того же
блока к внутреннему блоку. Вариант C считает внутренней и `total`, хотя `=`
ничего не объявляет. Вариант D забывает, что во внутреннем блоке `:=`
объявляет новую переменную.

## Вопрос 9

```go
@quiz _quiz/09-seven-seats

Сколько строк напечатает программа и какая пара мест будет последней?

Варианты ответа:

- A. Четыре строки, последняя пара — 3 и 3.
- B. Две строки, последняя пара — 2 и 4.
- C. Семь строк, по одной на каждое место.
- D. Три строки, последняя пара — 2 и 4.

Прежде чем смотреть ответ, составьте таблицу проверок условия: значения `i` и

## Вопрос 10

```go
@quiz _broken/quiz-post
```

Какая завершающая инструкция вместо `left++, right--` соберётся и сдвинет оба
счётчика?

Варианты ответа:

- A. `left, right := left+1, right-1`
- B. `left, right = left+1`
- C. `left, right = left+1, right-1`
- D. `left = left+1, right-1`

Прежде чем смотреть ответ, объясните, почему `left++, right--` не собирается.
Затем для каждого варианта проверьте две вещи: объявляет ли он переменные и
совпадает ли число переменных и значений.

**Правильный ответ: C.**

Завершающая инструкция — одна простая инструкция, а операции «запятая» в Go
нет. Поэтому после `left++` компилятор ждёт `{` и встречает запятую. Вариант C
— одно множественное присваивание: оба новых значения вычисляются из старых.
Вариант A объявляет переменные, а в завершающей инструкции объявлять нельзя.
В варианте B две переменные и одно значение, в варианте D — одна переменная и
два значения, и сборка откажет по числу.
