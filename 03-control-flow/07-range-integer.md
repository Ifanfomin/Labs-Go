# for range по целому числу

Программа разминки печатает шаги с номерами — первый, второй, третий, — а
потом несколько раз повторяет одно и то же напоминание о дыхании. В уроке 3.5
такие повторы записывали трёхчастным циклом `for i := 0; i < n; i++`: счётчик
заводят, сравнивают с границей и увеличивают сами. Когда задача звучит как
«сделай это n раз», в Go есть запись короче — `for i := range n`.

Чтобы писать такой цикл уверенно, нужно знать, какие числа получает его тело,
как повторять без переменной, когда цикл узнаёт границу, чем он отличается от
трёхчастного, чем знак `=` в заголовке отличается от `:=` и какого типа
получаются числа.

Код примеров можно изменить и запустить снова.

## Числа от нуля до n

Заголовок `for i := range n` объявляет переменную `i` и выполняет тело по
одному разу для каждого числа ряда 0, 1, …, n−1 — по возрастанию, с шагом
один. Одно выполнение тела дальше называется проходом, а число `n` —
границей. Сама граница в ряд не входит: при `n`, равном 3, тело выполнится три
раза и увидит в `i` числа 0, 1 и 2. Людям привычнее номера с единицы, поэтому
номер шага получают из `i` арифметикой: `i+1`.

Прежде чем смотреть вывод, запишите три строки, которые напечатает программа:
на каждом проходе — значение `i` и номер шага.

```go

### Example: `01-steps`

Источник: `examples/01-steps/`

```go
// Три шага разминки. Номер шага для человека получается из i.
package main

import "fmt"

func main() {
	for i := range 3 {
		fmt.Printf("i = %d, шаг %d\n", i, i+1)
	}
}

```
```

Крайние случаи следуют из того же правила. При `n`, равном 1, ряд состоит из
одного нуля. При нуле и при отрицательной границе ряд пуст: тело не
выполняется ни разу, и программа сразу переходит к инструкции после цикла.
Отрицательная граница — не ошибка и не счёт вниз, а просто ноль проходов.

Функция `show` в следующей программе печатает границу и все числа, которые
получило тело. Прежде чем смотреть вывод, предскажите четыре строки для
границ −3, 0, 1 и 5.

```go

### Example: `02-bounds`

Источник: `examples/02-bounds/`

```go
// Какие числа получает тело при разных границах.

import "fmt"

// show печатает границу n и все числа, которые range n отдал телу цикла.
func show(n int) {
	fmt.Printf("range %d:", n)
	for i := range n {
		fmt.Printf(" %d", i)
	}
	fmt.Println()
}

func main() {
	show(-3)
	show(0)
	show(1)
	show(5)
}

```
```

У такого заголовка не больше одной переменной: цикл выдаёт только числа ряда,
второго значения на проходе нет. Прежде чем читать дальше, решите, соберётся ли
программа, в заголовке цикла которой два имени.

```go
@broken two-vars
```

Сборка остановится с сообщением
`range over 5 (untyped int constant) permits only one iteration variable`.
Форма `range` с двумя переменными существует для наборов значений, и её
разбирает урок 4.10; к счёту до `n` она не относится.

## Повтор без номера

Напоминанию о дыхании номер не нужен: достаточно выполнить тело нужное число
раз. Тогда переменную в заголовке просто не пишут: `for range n`. Ряд
остаётся тем же, от нуля до n−1, и тело выполняется столько же раз, только
числа ряда никуда не записываются. При нуле и отрицательной границе проходов
по-прежнему нет.

Прежде чем смотреть вывод, скажите, сколько строк напечатает программа и какая
из них последняя.

```go

### Example: `03-repeat`

Источник: `examples/03-repeat/`

```go
// Напоминание повторяется три раза. Номер повтора телу не нужен.
package main

import "fmt"

func main() {
	for range 3 {
		fmt.Println("вдох и выдох")
	}
	fmt.Println("готово")
}

```
```

Почему бы не оставить `i` на всякий случай? Компилятор Go не принимает
переменную, объявленную внутри функции, если её значение нигде не читают.
Переменная из заголовка цикла тоже объявлена внутри функции, и правило
действует на неё так же. Прежде чем читать дальше, решите, соберётся ли та же
программа с заголовком `for i := range 3`.

```go
@broken unused-var
```

Не соберётся: `declared and not used: i`. Лишнее имя здесь не запас, а ошибка
сборки. Ни имя-заглушка, ни подчёркивание вместо имени не нужны: заголовок
`for range n` полон и без них.

## Граница выбирается один раз

Пока тело не трогает ни `n`, ни `i`, записи `for i := range n` и
`for i := 0; i < n; i++` дают один и тот же ряд. Разница появляется, когда
тело меняет границу.

Трёхчастный цикл проверяет условие `i < n` перед каждым проходом, как в уроке
3.5, и каждый раз читает текущее значение `n`. Цикл `range` получает значение
границы один раз, до первого прохода, и дальше выдаёт ряд для этого числа.
Запись в переменную `n` внутри тела меняет переменную, но не ряд, который уже
начался.

В программе ниже `n` сначала равно 3, а тело каждого прохода записывает в `n`
число 5. Прежде чем смотреть вывод, предскажите для каждого цикла числа,
которые получит `i`, и значение `n` после цикла.

```go

### Example: `04-changed-bound`

Источник: `examples/04-changed-bound/`

```go
// Тело каждого прохода записывает в n число 5.
package main

import "fmt"

func main() {
	n := 3
	fmt.Print("[range n]")
	for i := range n {
		fmt.Printf(" %d", i)
		n = 5
	}
	fmt.Printf("; после цикла n = %d\n", n)

	n = 3
	fmt.Print("[i < n]")
	for i := 0; i < n; i++ {
		fmt.Printf(" %d", i)
		n = 5
	}
	fmt.Printf("; после цикла n = %d\n", n)
}

```
```

Цикл `range` сделал три прохода: до начала в `n` было 3. Трёхчастный цикл
после первого прохода сравнивал `i` уже с пятёркой и сделал пять проходов —
от нуля до четырёх. После обоих циклов в `n` одинаково лежит 5: переменную
меняли оба тела, а различается только то, перечитывает ли её заголовок.

Когда тело границу не меняет, ряды совпадают:

```go

### Example: `05-same-bound`

Источник: `examples/05-same-bound/`

```go
// Тело не трогает n: оба цикла выдают один и тот же ряд.
package main

import "fmt"

func main() {
	n := 4
	fmt.Print("[range n]")
	for i := range n {
		fmt.Printf(" %d", i)
	}
	fmt.Println()

	fmt.Print("[i < n]")
	for i := 0; i < n; i++ {
		fmt.Printf(" %d", i)
	}
	fmt.Println()
}

```
```

Правило «один раз» касается и вызова функции в границе. Функция `limit` в
следующей программе считает свои вызовы в переменной пакета `calls` и всегда
возвращает 3. Прежде чем смотреть вывод, посчитайте вызовы для каждого цикла.
Учтите, что трёхчастный цикл проверяет условие и перед проходом, который уже
не состоится.

```go

### Example: `06-call-count`

Источник: `examples/06-call-count/`

```go
// Сколько раз цикл вызывает функцию, которая задаёт границу.
package main

import "fmt"

// calls — сколько раз была вызвана limit.
var calls int

// limit считает свои вызовы и всегда возвращает 3.
func limit() int {
	calls++
	return 3
}

func main() {
	fmt.Print("[range limit()]")
	for i := range limit() {
		fmt.Printf(" %d", i)
	}
	fmt.Printf("; вызовов: %d\n", calls)

	calls = 0
	fmt.Print("[i < limit()]")
	for i := 0; i < limit(); i++ {
		fmt.Printf(" %d", i)
	}
	fmt.Printf("; вызовов: %d\n", calls)
}

```
```

В `range limit()` функция вызвана один раз. Условие `i < limit()` вызвало её
четыре раза: три проверки дали `true` перед проходами, а четвёртая дала
`false` и остановила цикл. Если граница — константа, например `range 10`,
число известно уже при сборке, и во время работы перед циклом вычислять нечего.

У `range n` нет места для своего начала и шага: ряд всегда начинается с нуля и
растёт на единицу. Номер с единицы или другой порядок показа получают из `i`
арифметикой в теле. Если же начало и шаг должен задавать сам заголовок —
например, считать от 10 вниз через два, — пишут трёхчастный цикл.

## Запись в переменную цикла

Что будет, если тело запишет в `i` новое значение? Запись меняет переменную до
конца текущего прохода, а следующий проход получает следующее число ряда: ряд
от записей в `i` не зависит. У трёхчастного цикла иначе — там `i` и есть
счётчик. Завершающая инструкция `i++` прибавляет единицу к тому, что оставило
тело, а условие проверяет результат.

Прежде чем смотреть вывод, для каждого цикла решите, сколько проходов он
сделает и какое число увидит тело в начале каждого прохода.

```go

### Example: `07-body-write`

Источник: `examples/07-body-write/`

```go
// Тело каждого прохода прибавляет к i десять.
package main

import "fmt"

func main() {
	fmt.Println("[range 3]")
	for i := range 3 {
		fmt.Printf("получено %d", i)
		i += 10
		fmt.Printf(", после записи %d\n", i)
	}

	fmt.Println("[i := 0; i < 3; i++]")
	for i := 0; i < 3; i++ {
		fmt.Printf("получено %d", i)
		i += 10
		fmt.Printf(", после записи %d\n", i)
	}
}

```
```

Цикл `range` выдал телу 0, 1 и 2, хотя каждый проход прибавлял к `i` десять.
Трёхчастный цикл после первого прохода получил в `i` десятку, `i++` сделал из
неё 11, и условие `i < 3` остановило цикл.

`break` и `continue` в цикле `range` работают так же, как в уроке 3.5: `break`
заканчивает цикл сразу, `continue` заканчивает текущий проход, и следующий
проход получает следующее число ряда.

## Новая переменная или существующая

Заголовок `for i := range n` объявляет `i`, как короткое объявление урока 2.2.
Область видимости этой переменной — сам цикл: после закрывающей скобки она
недоступна, а внешняя переменная с тем же именем внутри цикла заслонена (урок
2.3). По правилам языка каждый проход получает собственную переменную `i`. В
программах этого урока от этого ничего не зависит; случаи, где собственная
переменная прохода важна, разбирает урок 5.7 о замыканиях.

Заголовок `for i = range n` со знаком `=` ничего не объявляет. Переменная `i`
должна существовать до цикла, и каждый проход записывает в неё очередное число
ряда, как обычное присваивание. После цикла переменная остаётся на месте.

Правило для её значения одно: после цикла в переменной лежит последняя запись в
неё. Обычно эту запись делает `range` на последнем проходе, но не всегда:

- граница положительна, цикл дошёл до конца и тело в переменную не писало — в
  ней n−1, а не `n`, потому что граница в ряд не входит;
- проходов не было, потому что граница равна нулю или отрицательна, — в
  переменной осталось значение, которое было до цикла;
- цикл прерван `break` — в ней число того прохода, на котором он прервался;
- тело само писало в переменную — в ней то, что было записано последним.

Прежде чем смотреть вывод, предскажите значение переменной после каждого из
трёх циклов.

```go

### Example: `08-assign`

Источник: `examples/08-assign/`

```go
// Знак = пишет в переменную, объявленную до цикла; := объявляет новую.
package main

import "fmt"

func main() {
	last := 99
	fmt.Print("[last = range 4]")
	for last = range 4 {
		fmt.Printf(" %d", last)
	}
	fmt.Printf("; после цикла last = %d\n", last)

	last = 99
	fmt.Print("[last = range 0]")
	for last = range 0 {
		fmt.Printf(" %d", last)
	}
	fmt.Printf("; после цикла last = %d\n", last)

	outer := 99
	fmt.Print("[outer := range 3]")
	for outer := range 3 {
		fmt.Printf(" %d", outer)
	}
	fmt.Printf("; после цикла outer = %d\n", outer)
}

```
```

После цикла с границей 4 в `last` осталась тройка — последнее число ряда. Цикл с
нулевой границей не сделал ни одного прохода, и в `last` осталось 99. В третьем
цикле `:=` объявил новую переменную `outer`: тело печатало её, а внешняя
`outer` так и осталась равна 99.

## Какого типа числа ряда

Тип чисел ряда зависит от границы и от знака в заголовке; для констант
действуют правила урока 2.11:

- граница целого типа передаёт ряду свой тип: при `var small uint8 = 3`
  переменная `i` в `for i := range small` получает тип `uint8`;
- у целой константы без типа, например в `for i := range 2`, со знаком `:=`
  работает тип по умолчанию — `int`;
- у той же константы со знаком `=` тип берётся у существующей переменной; эта
  переменная должна быть целого типа, и константа должна быть в нём
  представима, как при обычном присваивании;
- если у границы тип уже есть, а в заголовке стоит `=`, переменная должна
  быть того же типа: ряд границы `int8` в переменную `int` без преобразования
  `int(...)` не записать.

Прежде чем смотреть вывод, назовите имя типа, которое напечатает `%T` в каждой
строке.

```go

### Example: `09-types`

Источник: `examples/09-types/`

```go
// Какого типа числа ряда в трёх заголовках.
package main

import "fmt"

func main() {
	var small uint8 = 3
	fmt.Print("[i := range small]")
	for i := range small {
		fmt.Printf(" %d:%T", i, i)
	}
	fmt.Println()

	fmt.Print("[i := range 2]")
	for i := range 2 {
		fmt.Printf(" %d:%T", i, i)
	}
	fmt.Println()

	var b uint8
	fmt.Print("[b = range 2]")
	for b = range 2 {
		fmt.Printf(" %d:%T", b, b)
	}
	fmt.Println()
}

```
```

Граница обязана быть целым числом — значением целого типа или целой
константой без типа. Дробное число не подходит, даже когда дробной части нет.
Прежде чем читать дальше, решите, соберётся ли цикл `for i := range 3.0`, и
если нет — какой должна быть граница.

```go
@broken float-bound
```

Не соберётся: `cannot range over 3.0 (untyped float constant 3)`. Запись
`3.0` — дробная константа, хотя значение у неё целое; исправление — написать
`3`. Если граница хранится в дробной переменной `x`, её явно преобразуют, как
в уроке 2.9: `range int(x)`.

У `range` есть и перебор строки, но это другая форма со своими правилами, и её
разбирает урок 9.2.

Второе условие — граница должна помещаться в тип чисел ряда. Прежде чем читать

## Когда выбирать range

`for range n` и `for i := range n` подходят, когда число повторов известно до
входа в цикл. Если момент остановки зависит от того, что происходит в теле,
нужен цикл с условием, которое проверяется заново перед каждым проходом.

| Задача | Запись |
|---|---|
| Повторить действие `n` раз, номер не нужен | `for range n` |
| Пронумеровать `n` строк с единицы | `for i := range n`, в теле номер `i+1` |
| Показать номера в другом порядке | `for i := range n`, в теле выражение от `i` и `n` |
| Задать в заголовке своё начало или шаг | трёхчастный цикл |
| Повторять, пока тело не изменит значение до нужного | цикл с одним условием |

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Какой функции нужен номер

<!-- review:which-needs-value -->

Вопросы из постановки: какой функции нужно число из ряда, каким выражением
получаются числа отсчёта и что будет при −3. Образец ответа ниже.

`Ticks` на каждом проходе добавляет к строке одно и то же `"тик\n"`. Число из
ряда телу не нужно, поэтому заголовок — `for range n`, без переменной. Имя в
этом заголовке было бы не просто лишним: `for i := range n` с телом, которое
не читает `i`, не соберётся. Решение целиком: до цикла `s := ""`, в теле
`s += "тик\n"`, после цикла `return s`.

`Countdown` на каждом проходе показывает своё число, поэтому ей переменная
нужна: `for i := range n`. Для `n`, равного 3, `i` принимает значения 0, 1 и 2,
а показать нужно 3, 2 и 1. На каждом проходе `i` и нужное число в сумме дают
`n`, значит нужное число — `n-i`. Тело: `s += fmt.Sprintf("%d\n", n-i)`.

При −3 ряд пуст: тело не выполняется ни разу, и обе функции возвращают пустую
строку, с которой начали. Отдельная проверка знака `n` не нужна — пустой ряд
даёт ровно этот результат. Она нужна только решению через `strings.Repeat`,
о нём следующий раздел.

## Repeat с отрицательным числом

<!-- review:ticks-repeat -->

Решение `return strings.Repeat("тик\n", n)` верно для `n` от 0 до 20: `Repeat`
повторяет строку целиком, а при нуле возвращает пустую. Но при отрицательном
`n` он вызывает панику `strings: negative Repeat count` (урок 2.14).

Ловит это `TestTicks` на входах −3 и −1: тест сообщает о панике вместо
строки. Исправление — `for range n` из раздела выше. Можно и оставить
`Repeat`, заранее вернув пустую строку при отрицательном `n`: тест примет и
это решение, но упражнение тренирует на этой задаче именно заголовок `range`.

## Лишний тик

<!-- review:ticks-inclusive -->

Решение с заголовком `for i := 0; i <= n; i++` выполняет тело на один раз
больше, чем нужно: условие `<=` пропускает и проход, на котором `i` равно `n`.
При нуле получается один тик вместо пустой строки, при 3 — четыре.

Ловит это `TestTicks` на входе 0. У `for range n` такой ошибки не бывает:
граница в ряд не входит, и при положительном `n` тело выполняется ровно `n`
раз, а при остальных — ни разу.

## Отсчёт в обратную сторону

<!-- review:countdown-ascending -->

Решение с `fmt.Sprintf("%d\n", i+1)` показывает номера проходов с единицы:
для 3 это 1, 2, 3. Строк столько, сколько нужно, но порядок обратный.

Ловит это `TestCountdown` на входах 2, 3 и 20; на входе 1 ошибка не видна,
потому что единственное число совпадает. `i+1` отвечает на вопрос «какой по
счёту проход», а табло показывает, сколько секунд осталось, — `n-i`.

## Лишний ноль

<!-- review:countdown-with-zero -->

Решение с трёхчастным заголовком `for i := n; i >= 0; i--` считает вниз и
доходит до нуля включительно: для 3 табло покажет 3, 2, 1 и 0. При
отрицательном `n` первое же сравнение ложно, и строка пустая, как и нужно. А
при нуле цикл делает один проход и возвращает строку с нулём вместо пустой.

Ловит это `TestCountdown` на входах 0, 1, 2, 3 и 20. Трёхчастный цикл
исправило бы условие `i >= 1`. В решении с `range` лишнего нуля нет:
`n-i` при `i` от 0 до n−1 даёт числа от `n` до 1.

## Что говорят и чего не говорят тесты

<!-- review:tests-observe -->

Скрытые тесты вызвали каждую функцию на семи входах и сравнили строки. На
этих входах результат принят — и это всё, что тесты установили. Текст
решения тест не читает: `for range n`, трёхчастный цикл и `strings.Repeat` с
проверкой знака дают одинаковые строки. Поэтому вопрос «есть ли в заголовке
`Ticks` переменная и нужна ли она» проверяете вы сами, читая свой код.

Прежде чем смотреть ответ, выпишите значения `i` для `n`, равного 3, и
подставьте их в каждое выражение.

**Правильный ответ: A.**

`i` принимает значения 0, 1 и 2, и `n-1-i` даёт 2, 1 и 0. Вариант D печатает
те же числа в обратном порядке. Вариант B даёт номера попыток с единицы: 1, 2,
3. Вариант C даёт 3, 2, 1 — сколько попыток осталось вместе с текущей, а не
после неё.

## Вопрос 8

Какие задачи естественно записать через `range` по целому числу?

1. Напечатать «ещё раз» пять раз.
2. Пронумеровать с единицы семь строк отчёта.
3. Делить число пополам, пока оно больше 1.
4. Складывать цены покупок, пока сумма не превысит бюджет.

Варианты ответа:

- A. Все четыре.
- B. 1 и 2.
- C. Только 1: номер с единицы `range` не даёт.
- D. 1, 2 и 3.

Прежде чем смотреть ответ, для каждой задачи скажите, известно ли число
повторов до входа в цикл.

**Правильный ответ: B.**

В задачах 1 и 2 число повторов известно заранее: в первой номер не нужен, и
подходит `for range 5`, во второй номер `i+1` получается из ряда. В задачах 3
и 4 остановку решает значение, которое меняет тело, и нужен цикл с условием,
которое проверяется заново. Вариант C забывает, что номер с единицы выводится
из `i`. Варианты A и D берут `range` там, где число проходов заранее
неизвестно.

## Вопрос 9

Два цикла не собираются:

1. `var b uint8`, затем `for b = range 300 {}`;
2. `x := 2.0`, затем `for i := range x { fmt.Println(i) }`.

Какие правки исправят оба?

Варианты ответа:

- A. В первом — граница 200, во втором — `range 2.0`.
- B. В первом — `range uint8(300)`, во втором — `range 2.0`.
- C. В первом — граница 200, во втором — `range int(x)`.
- D. В первом — `range uint8(300)`, во втором — `range int(x)`.

Прежде чем смотреть ответ, для каждого цикла назовите нарушенное условие —
граница не целая или не помещается в тип — и предложите свою правку.

**Правильный ответ: C.**

В первом цикле 300 не помещается в `uint8`; граница 200 помещается. Годится и
переменная `b` более широкого целого типа. Во втором граница — дробная
переменная, и `int(x)` превращает её значение в целое. Запись `uint8(300)` не
спасает: константу, которая не помещается в тип, не преобразовать (урок 2.11).
Запись `2.0` — дробная константа, как `3.0` в разделе «Какого типа числа
ряда», хотя значение у неё целое.
