# iota и наборы констант

Длины в программе бывают записаны в разных единицах: миллиметр, сантиметр,
дециметр, метр. Чтобы перевести длину из одной единицы в другую, программе
нужно не название единицы, а число — во сколько раз единица крупнее
миллиметра. Шкала десятичная, поэтому удобно хранить не сам множитель, а
показатель степени десяти: у миллиметра 0, у сантиметра 1, у дециметра 2, у
метра 3. Разность двух показателей сразу даёт степень нужного множителя, и
никакой таблицы переводов заводить не приходится.

Такой ряд номеров можно выписать руками. Но ряд, выписанный руками, легко
сбить: достаточно вставить строку в середину и забыть поправить остальные.
В Go для этого есть `iota` — имя, которое внутри объявления констант
обозначает номер текущей записи. К концу урока вы сможете:

- посчитать значение каждой константы в блоке, где есть повтор выражения,
  явное значение и смещение, и назвать, что именно двигает номер;
- зарезервировать нулевое значение или начать нумерацию не с нуля;
- объяснить, почему набор имён-констант не защищает функцию от постороннего
  числа и почему порядок записей — это данные, а не оформление;
- перевести длину между единицами через разность показателей и объяснить оба
  направления перевода;
- назвать случай, в котором `iota` даёт неверную шкалу.

## Таблица единиц и их номера

Объявление констант из урока 2.11 состоит из **спецификаций**. Спецификация —
одна запись объявления: имя, необязательный тип и необязательное выражение.
В этом уроке в каждой спецификации ровно одно имя.

`iota` — предопределённое имя, а не ключевое слово. Внутри объявления констант
оно обозначает номер текущей спецификации, и номера идут с нуля. Второе
правило работает в паре с первым: если у спецификации нет выражения,
компилятор берёт ближайшее предыдущее непустое выражение и подставляет его
в эту спецификацию ещё раз — уже с новым номером.

Этих двух правил хватает, чтобы прочитать всю таблицу единиц. Прежде чем
смотреть вывод, назовите значение каждой из четырёх констант.

```go

### Example: `01-units`

Источник: `examples/01-units/`

```go
package main

import "fmt"

// Единицы десятичной шкалы длин. Значение константы — номер десятичного
// шага от миллиметра; множитель равен десяти в этой степени.
const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

func main() {
	fmt.Println("миллиметр:", millimetre)
	fmt.Println("сантиметр:", centimetre)
	fmt.Println("дециметр:", decimetre)
	fmt.Println("метр:", metre)
}

```
```

Показатели получились подряд от нуля, потому что первая спецификация задала
выражение `iota`, а три следующих повторили его со своими номерами. Слово
«показатель» в этой таблице не украшение, но и не множитель: константа считает
десятичные шаги от миллиметра, а множитель получается из неё возведением
десяти в эту степень. Один шаг по таблице — десять раз. Как из двух
показателей получают множитель перевода, разобрано ниже, в разделе «Перевод
длины через разность показателей».

## iota — номер спецификации

Значение `iota` — не счётчик, который растёт во время работы программы.
Значения констант компилятор вычисляет при сборке и подставляет в места
использования, так что увеличивать во время работы уже нечего. `iota` —
это просто номер той спецификации, в которой она написана.

Из этого следуют два отдельных факта, которые легко спутать.

Первый: имя `iota` видно во всей программе — как `true` и `false`, оно
объявлено самим языком. Ограничено не то, где имя видно, а то, где им можно
пользоваться: только внутри объявления констант. Попытка взять его в другом
месте — ошибка сборки, а не «неизвестное имя»:

```go
@broken iota-outside-const
```

Сообщение сборки — `cannot use iota outside constant declaration`.

Второй: нумерация принадлежит одному объявлению. Новое объявление `const`
начинает счёт заново с нуля, даже если стоит сразу под предыдущим.

## Что двигает номер

Номер растёт ровно в одном случае: при переходе к следующей спецификации. Всё
остальное его не трогает.

- Комментарий и пустая строка спецификациями не являются и номер не двигают.
- Несколько упоминаний `iota` внутри одной спецификации дают одно и то же
  значение: номер у спецификации один.
- Спецификация, которая `iota` вообще не упоминает, номер всё равно занимает;
  что из этого следует, показано в разделе «Явное значение посреди блока».

Прежде чем смотреть вывод, посчитайте по этим правилам все шесть констант
программы ниже. Особенно вторую: в её выражении `iota` стоит дважды.

```go

### Example: `02-index`

Источник: `examples/02-index/`

```go
package main

import "fmt"

const (
	a = iota

	// Комментарий и пустая строка стоят между спецификациями.
	b = iota*100 + iota
	c = iota
	d = iota
)

const (
	e = iota
	f = iota
)

func main() {
	fmt.Println("a =", a)
	fmt.Println("b =", b)
	fmt.Println("c =", c)
	fmt.Println("d =", d)
	fmt.Println("e =", e)
	fmt.Println("f =", f)
}

```
```

Вторая константа получила трёхзначное число, потому что оба упоминания `iota`
в её спецификации равны единице: сто плюс один. Комментарий и пустая строка
перед ней номер не сдвинули. А во втором объявлении счёт пошёл заново, и
первое имя там снова получило ноль.

Распространённое неверное правило звучит так: «номер растёт на каждой строке»
или «на каждом упоминании `iota`». Первая половина программы выше — прямой
контрпример к обеим формулировкам.

## Пропущенное выражение повторяется

Выражение можно опустить у любой спецификации, кроме первой. У первой
повторять нечего. Прежде чем читать дальше, решите: соберётся ли программа
ниже, у которой первая спецификация объявляет только имя и тип?

```go
@broken missing-init
```

Не соберётся. Сообщение сборки — `missing init expr for First`.

Что именно повторяется, стоит прочитать буквально: повторяется **выражение**,
а не посчитанное значение. Компилятор подставляет текст ближайшего
предыдущего непустого выражения в новую спецификацию и вычисляет его заново —
с новым номером. Правило «прибавить единицу к предыдущему значению» даёт тот
же ответ только у самых простых блоков и расходится с настоящим, как только
выражение перестаёт быть просто `iota`.

Прежде чем смотреть вывод, посчитайте оба блока программы ниже. Во втором
выражение сдвигает единицу влево на `iota` позиций — сдвиг разобран в уроке
2.10.

```go

### Example: `03-repeat`

Источник: `examples/03-repeat/`

```go
package main

import "fmt"

// У первой спецификации выражение есть, у остальных — нет.
const (
	offsetA = iota + 1
	offsetB
	offsetC
	offsetD
)

// То же самое, но выражение со сдвигом из урока 2.10.
const (
	maskA = 1 << iota
	maskB
	maskC
	maskD
	maskE
)

func main() {
	fmt.Println("смещение:", offsetA, offsetB, offsetC, offsetD)
	fmt.Println("маски:", maskA, maskB, maskC, maskD, maskE)
}

```
```

Первый блок дал ряд со смещением на единицу; по правилу «предыдущее плюс один»
он получился бы такой же, и различить два правила на нём нельзя. Второй блок
их различает: значения удваиваются, потому что каждый раз заново считается
сдвиг, а «предыдущее плюс один» дало бы ряд подряд идущих чисел.

## Вместе с выражением повторяется тип

Если у первой спецификации указан тип, он тоже повторяется: пропущенная
спецификация получает и выражение, и тип. Если тип не написан, константа
получает тот тип, который имеет само повторённое выражение. У выражений с
`iota`, показанных в этом уроке, своего типа нет, поэтому такие константы
остаются нетипизированными — разбор нетипизированных констант в уроке 2.11.

Прежде чем смотреть вывод, назовите значения и тип в каждом из двух блоков.

```go

### Example: `04-typed-repeat`

Источник: `examples/04-typed-repeat/`

```go
package main

import "fmt"

// Тип указан у первой спецификации.
const (
	rateA float64 = iota
	rateB
	rateC
)

const (
	countA int = iota * 3
	countB
	countC
)

func main() {
	fmt.Printf("доли: %v %v %v, тип %T\n", rateA, rateB, rateC, rateA)
	fmt.Printf("счётчики: %v %v %v, тип %T\n", countA, countB, countC, countA)
}

```
```

В первом блоке все три константы имеют тип `float64`, хотя в выражении стоит
одна только `iota`: тип из первой спецификации повторился вместе с
выражением. Во втором повторилось выражение с умножением, поэтому значения
идут через три.

## Явное значение посреди блока

Спецификация со своим выражением прерывает повтор: дальше повторяется уже
она. Номер при этом продолжает расти — он привязан к положению записи, а не к
тому, упоминает она `iota` или нет.

Отсюда самая частая ошибка чтения такого блока: читатель считает, что раз
имена идут подряд, то и значения идут подряд. Это неверно в двух местах
сразу — там, где стоит явное значение, и там, где его молча повторяют.

Прежде чем смотреть вывод, выпишите все шесть значений программы ниже. Для
каждой спецификации сначала назовите её номер, потом — какое выражение в ней
работает.

```go

### Example: `05-override`

Источник: `examples/05-override/`

```go
package main

import "fmt"

const (
	v0 = iota
	v1
	v2 = 100
	v3
	v4 = iota
	v5
)

func main() {
	fmt.Println("v0 =", v0)
	fmt.Println("v1 =", v1)
	fmt.Println("v2 =", v2)
	fmt.Println("v3 =", v3)
	fmt.Println("v4 =", v4)
	fmt.Println("v5 =", v5)
}

```
```

Третья константа получила своё явное число. Четвёртая выражения не имеет и
повторила ближайшее предыдущее — то самое явное число, а не свой номер.
В пятой снова написана `iota`, и она дала четвёрку: номера третьей и
четвёртой записей израсходованы, хотя в их значениях не видны.

## Как зарезервировать ноль и начать с другого числа

Ноль — особенное значение: это то, что окажется в переменной, объявленной
без начального значения (урок 2.1). Иногда нулю и нужно дать отдельное имя —
«единица не задана». Тогда первая спецификация отдаётся такому имени, а
полезные значения начинаются с единицы.

Если же нумерация должна начинаться с другого числа, смещение ставят прямо в
первое выражение: пропущенные спецификации повторят его вместе со смещением.

Прежде чем смотреть вывод, назовите значения обоих блоков ниже.

```go

### Example: `06-reserved`

Источник: `examples/06-reserved/`

```go
package main

import "fmt"

// Нулевое значение занято именем, которое означает «единица не задана».
const (
	unitUnset = iota
	unitFirst
	unitSecond
)

// Нумерация начинается не с нуля: смещение стоит в первом выражении.
const (
	codeBase = iota + 10
	codeNext
	codeLast
)

func main() {
	fmt.Println("не задано:", unitUnset)
	fmt.Println("первая единица:", unitFirst)
	fmt.Println("вторая единица:", unitSecond)
	fmt.Println("коды:", codeBase, codeNext, codeLast)
}

```
```

В первом блоке нулевое значение занято именем, которое означает «не задано»,
и настоящие единицы начинаются с единицы. Во втором выражение со смещением
повторилось трижды, поэтому коды идут от десяти.

Есть и третий способ отдать нулевую запись — через пустой идентификатор. Его
разбор — урок 4.10. Здесь нулевую запись занимает именованная константа: она
читается не хуже и сразу говорит, что означает ноль.

## Набор констант — не проверяемое множество

Четыре имени с номерами похожи на перечислимый тип из других языков. В Go это
не перечислимый тип. Это четыре обычные числовые константы, и функция,
которая принимает параметр типа `int`, примет и значение, уже имеющее тип
`int`, и нетипизированную константу, представимую в `int`, — в том числе
число вне набора.

Правило, из которого это следует, — правило присваиваемости из урока 2.11.
Нетипизированная константа годится там, где её значение представимо в нужном
типе; значение, у которого тип уже есть, годится, когда это тот же тип.
Представимость сама по себе не помогает: типизированная константа `float64`
со значением 3 и переменная `float64`, хранящая 3, в параметр `int` не
подставятся без явного преобразования (урок 2.9). Константы шкалы
нетипизированные и целые, параметр — `int`, поэтому имена подходят. Но так
же подходит и любое другое целое число вне набора: тип параметра не
ограничивает допустимые значения четырьмя номерами шкалы.

Прежде чем смотреть вывод, ответьте: соберётся ли программа ниже и что она
напечатает в трёх последних строках?

```go

### Example: `07-membership`

Источник: `examples/07-membership/`

```go
package main

import "fmt"

const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

// steps сообщает, на сколько десятичных шагов единица unit крупнее
// миллиметра. Допустимые значения unit — от millimetre до metre; других
// значений функция не проверяет.
func steps(unit int) int {
	return unit - millimetre
}

func main() {
	fmt.Println("метр:", steps(metre))
	fmt.Println("сантиметр:", steps(centimetre))
	fmt.Println("сорок два:", steps(42))
	fmt.Println("минус семь:", steps(-7))
	other := 99
	fmt.Println("из переменной:", steps(other))
}

```
```

Программа собралась, ни одного сообщения не появилось, и посторонние числа
прошли наравне с именами — в том числе число, взятое из переменной типа
`int`, о значении которой компилятор при сборке не знает ничего.

Вывод для практики такой: допустимые значения — это **условие задачи**,
которое пишут в документации функции, а не проверка, которую делает язык.
Так же записана допустимая область в упражнении — раздел «Что сдать».

## Порядок значений — это данные

Пока значения набора никому не важны, порядок записей — дело вкуса. Как
только значения означают что-то во внешнем мире — номер в протоколе, код в
базе, ступень шкалы, — порядок записей становится данными.

Последствие зависит от того, что именно изменили в блоке, и две похожие
правки действуют по-разному. Пример — блок из четырёх имён, где выражение
`iota` написано в первой спецификации, а три остальные его повторяют:
значения идут 0, 1, 2, 3.

- **Вставка** новой записи на второе место даёт 0, 1, 2, 3, 4: первое имя
  осталось с нулём, вставленное получило единицу, а три прежних имени
  сдвинулись и держат теперь 2, 3 и 4 вместо 1, 2 и 3.
- **Перестановка** второй и третьей записей местами меняет значения только
  этих двух имён: они обмениваются номерами, а первое и четвёртое остаются на
  прежних числах.

А вот первую запись такого блока переставлять нельзя: выражение написано
только в ней. После переноса первая спецификация останется без начального
значения, и блок перестанет собираться — как в разделе «Пропущенное
выражение повторяется».

Если же в блоке есть явное значение, считать приходится по правилам повтора
из разделов выше, и обе правки перестают быть предсказуемыми «на глаз». Пока
первая спецификация сохраняет своё выражение, код собирается, тесты, которые
сравнивают только вычисленные значения, могут ничего не заметить, а
записанные раньше данные начинают читаться как другие имена.

Поэтому блок констант читают целиком: не только имена, но и то, какое число
получает каждое имя и что это число означает. Если значение задано снаружи —
протоколом, форматом файла, чужой системой, — его пишут явным числом, а не
получают нумерацией.

## Готовая функция для степеней десяти

Разность показателей даёт степень, а для перевода нужен множитель. Оператора
возведения в степень в Go нет. Нужное действие выполняет готовая функция
стандартной библиотеки — `math.Pow10`.

Её объявление — `func Pow10(n int) float64`: показатель — значение типа
`int`, результат — значение типа `float64`. Тип результата не обещает, что
число окажется с дробной частью: десять в третьей степени — ровная тысяча,
просто хранится она в дробном типе. Документация описывает результат как
десять в степени `n` и называет два крайних случая: при `n` меньше −323
результат равен нулю, при `n` больше 308 — бесконечности. Показатели шкалы
лежат между −3 и 3, так что до этих краёв дело не доходит.

Показатель — обычное значение типа `int`, и нетипизированная константа из
блока подходит ему по тому же правилу присваиваемости. Типизированная
константа `float64` не подойдёт: её пришлось бы преобразовывать явно (урок
2.9).

Прежде чем смотреть вывод, назовите семь значений от минус третьей степени до
третьей и тип результата.

```go

### Example: `08-pow10`

Источник: `examples/08-pow10/`

```go
package main

import (
	"fmt"
	"math"
)

const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

func main() {
	fmt.Println("десять в степени -3:", math.Pow10(-3))
	fmt.Println("десять в степени -2:", math.Pow10(-2))
	fmt.Println("десять в степени -1:", math.Pow10(-1))
	fmt.Println("десять в степени 0:", math.Pow10(0))
	fmt.Println("десять в степени 1:", math.Pow10(1))
	fmt.Println("десять в степени 2:", math.Pow10(2))
	fmt.Println("десять в степени 3:", math.Pow10(3))
	fmt.Printf("тип результата: %T\n", math.Pow10(3))
	fmt.Println("множитель метр в миллиметр:", math.Pow10(metre-millimetre))
	fmt.Println("множитель миллиметр в метр:", math.Pow10(millimetre-metre))
}

```
```

Отрицательный показатель дал долю единицы, нулевой — единицу, положительный —
число с нулями. Две последние строки — уже шкала длин: разность показателей
метра и миллиметра, поданная в `math.Pow10`, даёт множитель в одну сторону,
обратная разность — в другую.

## Что можно поставить в объявление константы

Начальное значение константы обязано быть **константным выражением** —
выражением, все операнды которого язык считает константами. Такое выражение
вычисляется при компиляции. Перечень константных операндов задаёт
спецификация языка, а не сообразительность компилятора: переменная в этот
перечень не входит, даже если её значение написано строкой выше и любой
оптимизатор его вывел бы. Вызов `math.Pow10` в перечень тоже не входит: это
обычная функция библиотеки, и она выполняется во время работы программы.

```go
@broken pow10-in-const
```

Сообщение сборки называет причину прямо:
`math.Pow10(2) (value of type float64) is not constant`.

Правило «в константе не бывает вызовов» из этого не следует, и заучивать его
не надо. Спецификация языка прямо называет встроенные функции, результат
которых на подходящих аргументах — тоже константа: среди них `len`, `cap`,
`min` и `max`. Значит `len` от строкового литерала и `min` от двух чисел в
объявлении константы законны. Прежде чем смотреть вывод, назовите все три
значения программы ниже; для первого пригодится урок 2.7, где сказано,
сколько байт занимает кириллическая буква.

```go

### Example: `09-const-boundary`

Источник: `examples/09-const-boundary/`

```go
package main

import "fmt"

// Все три значения посчитаны при сборке: len от строкового литерала,
// встроенные min и max от констант.
const (
	nameBytes = len("миллиметр")
	smaller   = min(3, 5)
	larger    = max(1, 2)
)

func main() {
	fmt.Println("байт в имени:", nameBytes)
	fmt.Println("меньшее:", smaller)
	fmt.Println("большее:", larger)
}

```
```

Имя из девяти кириллических букв занимает восемнадцать байт, а `min` и `max`
вернули меньший и больший аргументы — все три значения посчитаны при сборке.
Граница проходит не по слову «вызов» и не по тому, о чём компилятор мог бы
догадаться: язык перечисляет, что считается константой. Литерал и названные
встроенные функции на константных аргументах в перечень входят, переменная и
вызов обычной библиотечной функции — нет. Умножение констант, кстати, тоже
константная работа, и множители-степени можно было бы выписать константами
вручную; `math.Pow10` избавляет от такой ручной таблицы, но считается во
время работы программы, а не при сборке.

## Перевод длины через разность показателей

Перевод собирается из двух шагов. Пусть длина задана в единице `from`, а
нужна в единице `to`. Показатель — это не множитель, а число десятичных
шагов: единица крупнее миллиметра в десять в степени показателя раз. Отсюда:

1. Длина в миллиметрах — это значение, умноженное на десять в степени `from`.
2. Чтобы выразить её в единице `to`, миллиметры делят на десять в степени
   `to`.
3. Оба действия вместе — умножение на десять в степени `from − to`.

Одна запись обслуживает оба направления. Перевод в более мелкую единицу даёт
положительную разность и множитель больше единицы: длина выражается бо́льшим
числом. Перевод в более крупную даёт отрицательную разность и множитель
меньше единицы. Одинаковые единицы дают нулевую разность и множитель, равный
единице, то есть значение не меняется.

Прежде чем смотреть вывод, посчитайте шесть первых строк программы ниже.
Последняя строка — та же длина, что и в первой, но показатели в ней
переставлены местами: решите заранее, что получится.

```go

### Example: `10-convert`

Источник: `examples/10-convert/`

```go
package main

import (
	"fmt"
	"math"
)

const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

// convert переводит длину value из единицы from в единицу to.
func convert(value float64, from int, to int) float64 {
	return value * math.Pow10(from-to)
}

func main() {
	fmt.Println("2500 мм в метрах:", convert(2500, millimetre, metre))
	fmt.Println("2.5 м в миллиметрах:", convert(2.5, metre, millimetre))
	fmt.Println("7 см в миллиметрах:", convert(7, centimetre, millimetre))
	fmt.Println("12.5 дм в сантиметрах:", convert(12.5, decimetre, centimetre))
	fmt.Println("15 дм в метрах:", convert(15, decimetre, metre))
	fmt.Println("3.3 мм в миллиметрах:", convert(3.3, millimetre, millimetre))
	fmt.Println("показатели переставлены:", convert(2500, metre, millimetre))
}

```
```

Шесть первых строк идут по правилу: множители 0.001, 1000, 10, 10, 0.1 и 1.
Последняя — самое неприятное, что бывает с этой формулой: переставленные
показатели не дают ни ошибки сборки, ни остановки. Программа печатает число,
которое отличается от верного в миллион раз, и заметить это можно только
сравнив результат с ожидаемым.

## Точно и почти точно

`math.Pow10` возвращает `float64`, а `float64` хранит десятичные дроби
приближённо — это разбор урока 2.5. Отсюда два вопроса, которые стоит
разделить.

Первый: отличается ли `math.Pow10(-3)` от записанного в исходнике литерала
`0.001`? Сам по себе литерал `0.001` — нетипизированная константа, и как
константа он равен ровно одной тысячной, без всякого округления (урок 2.11).
Округление появляется только там, где значению нужен конкретный тип. В этой
программе таких мест два: сравнение с результатом `math.Pow10`, у которого
тип `float64`, и печать через `fmt.Printf`, где нетипизированная константа
берёт свой тип по умолчанию — для дробного литерала это тоже `float64`. В
обоих местах литерал превращается в ближайшее представимое значение `float64`.

Второй: всегда ли перевод даёт ровно ожидаемое число? Нет. Округление может
войти и через саму исходную длину, записанную неточной десятичной дробью, и
через промежуточный результат — даже когда исходное число хранится точно.

Ни первое, ни второе из одного лишь правила «дроби хранятся приближённо» не
выводится: нужно посмотреть. Поэтому сначала прочитайте вывод программы ниже,
а потом объясните своими словами первые три строки — что именно они говорят о
хранимом числе. Разбор идёт следом.

```go

### Example: `11-precision`

Источник: `examples/11-precision/`

```go
package main

import (
	"fmt"
	"math"
)

const (
	millimetre = iota
	centimetre
	decimetre
	metre
)

func convert(value float64, from int, to int) float64 {
	return value * math.Pow10(from-to)
}

func main() {
	fmt.Println("Pow10(-3) равен литералу 0.001:", math.Pow10(-3) == 0.001)
	fmt.Printf("двадцать значащих цифр литерала: %.20g\n", 0.001)
	fmt.Printf("двадцать значащих цифр Pow10: %.20g\n", math.Pow10(-3))
	fmt.Println("1234 мм в метрах:", convert(1234, millimetre, metre))
	fmt.Println("999 мм в метрах:", convert(999, millimetre, metre))
	fmt.Println("0.07 м в сантиметрах:", convert(0.07, metre, centimetre))
	back := convert(convert(7, centimetre, metre), metre, centimetre)
	fmt.Println("7 см в метры и обратно:", back)
}

```
```

Сравнение вернуло истину, и двадцать значащих цифр у литерала и у результата
функции одни и те же: в обоих местах получилось одно значение `float64`, и
оно чуть больше одной тысячной. Дальше видно, что оба перевода из
миллиметров в метры дали ровно ожидаемые числа. Две последние строки
расходятся с ожидаемым в последнем разряде, но по разным причинам: у семи
сотых метра неточна уже сама исходная длина, а в круговом переводе исходные
семь сантиметров хранятся точно — неточным оказывается промежуточное
значение в метрах, и обратный шаг приходит к тому же числу с лишней
единицей.

Что из этого можно обещать, а что нет. Разобранные выше расхождения —
наблюдения на конкретных числах, а не правило про все входы: другой круговой
перевод может вернуться и ровно к исходной длине. Поэтому результат перевода
сравнивают не на точное равенство, а с допуском в единицах задачи — приёмом
из урока 2.5. Точное равенство остаётся законным там, где обе стороны
приходят к одному и тому же хранимому числу, — как в первой строке этой
программы.

## Когда iota не подходит

`iota` выдаёт номера подряд. Это ровно то, что нужно, когда значения и должны
идти подряд, — как ступени десятичной шкалы. И это ловушка, когда соседние по
записи имена не соседи по смыслу.

Километр — привычная единица длины, и приписать его пятой строкой в блок
шкалы кажется естественным. Но в километре миллион миллиметров, то есть его
показатель — шесть, а не четыре. Прежде чем смотреть вывод, посчитайте, какой
показатель получит километр и во сколько раз ошибётся перевод.

```go

### Example: `12-kilometre`

Источник: `examples/12-kilometre/`

```go
package main

import (
	"fmt"
	"math"
)

// Километр приписан следующей спецификацией — и получает показатель 4,
// хотя в километре десять в шестой степени миллиметров.
const (
	millimetre = iota
	centimetre
	decimetre
	metre
	kilometre
)

func convert(value float64, from int, to int) float64 {
	return value * math.Pow10(from-to)
}

func main() {
	fmt.Println("показатель километра из блока:", kilometre)
	fmt.Printf("1 км по этому показателю, мм: %.0f\n",
		convert(1, kilometre, millimetre))
	fmt.Println("верный показатель километра:", 6)
	fmt.Printf("1 км по верному показателю, мм: %.0f\n", math.Pow10(6))
}

```
```

Ошибка вышла в сто раз, и никакого сообщения при этом не было: блок
синтаксически безупречен, а неверен смысл. Между метром и километром в
десятичной шкале стоят ещё две ступени, которых в наборе нет.

Четыре числа шкалы отличаются от условных кодов единиц. Код — это метка,
которую расшифровывают по отдельной таблице соответствий; числа шкалы прямо
участвуют в вычислении, и именно поэтому приписанный километр даёт не
«неизвестную единицу», а неверный ответ. Нумерация подряд имеет право стоять
в блоке только тогда, когда подряд идут и сами величины.

Отсюда правило выбора. `iota` годится, когда значения — это положение в
равномерном ряду и ряд записан целиком. Если значения заданы снаружи,
идут с пропусками или нерегулярно, их пишут явными числами: тогда запись
говорит правду о данных, а не о порядке строк.

## Что сдать

Заготовка — пакет `scale`: файл `go.mod` и два файла с кодом. В каждом файле
с кодом объявлена одна экспортируемая функция:

- `func Factor(from int, to int) float64` — в файле `factor.go`;
- `func InMetres(value float64, unit int) float64` — в файле `inmetres.go`.

В файле `inmetres.go` над функцией стоит ещё и блок констант с единицами
шкалы. Его тоже нужно дописать: сейчас три константы из четырёх держат
заглушку 99.

Тела обеих функций — заглушки: они возвращают 0. Допишите их так, чтобы
каждая возвращала значение, описанное в разделе её задачи ниже. Комментарии
`// TODO` можно удалить.

Не меняйте `go.mod`, строку `package scale`, имена функций, списки параметров
и типы результатов: скрытые тесты вызывают функции именно в таком виде.
Функции только возвращают значения, печатать ничего не нужно. Имена констант
менять тоже не нужно — они уже написаны.

Обеим задачам нужна функция `math.Pow10`: оператора возведения в степень в
языке нет, а множители шкалы — это степени десяти. Поэтому в каждый из двух
файлов с кодом добавляется строка `import "math"` — сразу под строкой
`package scale`. Других импортов не требуется.

Единицы шкалы задаются номерами: 0 — миллиметр, 1 — сантиметр, 2 — дециметр,
3 — метр. Это и есть значения, которые обязан выдать блок констант.

Допустимые значения:

- `Factor` — `from` и `to` от 0 до 3;
- `InMetres` — `unit` от 0 до 3, `value` от 0 до 10000.

Другие значения никто не передаёт, и проверять их не нужно: в параметр типа
`int` Go пропускает любое значение этого типа и любую нетипизированную
константу, представимую в `int`, — принадлежность набору единиц он не
проверяет. Допустимая область этих функций — условие задачи, а не свойство
языка.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые значения с
ожидаемыми:

- `TestFactor` — все семь разностей показателей от −3 до 3: одинаковые
  единицы, перевод в более мелкую единицу и перевод в более крупную;
- `TestInMetres` — перевод в метры из каждой единицы шкалы, нулевая длина,
  целые и дробные значения и верхний край допустимой области.

Результаты дробные, поэтому сравнение идёт с допуском: значение принимается,
если оно конечно и отличается от ожидаемого не больше чем на одну
миллиардную долю ожидаемого. Для нулевой длины ожидается ровно ноль. `NaN` и
бесконечности проверка отвергает отдельной строкой, до сравнения ошибки. Так
надёжнее: проверка, написанная как «провалить, если ошибка больше допуска»,
на `NaN` не сработала бы — сравнение `>` с `NaN` не истинно, и неверный
ответ прошёл бы. Ошибки, названные в разборе после попытки, либо меняют
ответ не меньше чем в десять раз, либо делают его не числом, так что допуск
их не прячет.

Тест получает только то, что функция вернула. Текста решения он не видит и
блок констант не читает: если вы выпишете множители числами, тест этого не
заметит. Значит зелёная проверка не доказывает, что блок написан через
`iota`, — это вы доказываете себе сами, читая собственный код.

Прежде чем писать тела, ответьте себе на три вопроса. Какое значение получит
каждая из четырёх констант вашего блока и что именно заставляет номер расти?
Почему показатель множителя — это разность показателей двух единиц, а не их
сумма или частное? И какой случай из списка проверок заметит перестановку
`from` и `to` местами, а какой её пропустит? Сверьте ответы с разбором после
попытки, разделы «Как читается блок констант» и «Какие случаи ловят ошибку».

## Factor

`Factor` возвращает множитель перевода: число, на которое умножают длину,
заданную в единице `from`, чтобы получить ту же длину в единице `to`.

Единицы — номера от 0 до 3. Шкала десятичная: соседние единицы отличаются в
десять раз.

- `Factor(3, 0)` возвращает 1000: в метре тысяча миллиметров;
- `Factor(0, 3)` возвращает 0.001;
- `Factor(1, 0)` возвращает 10;
- `Factor(2, 2)` возвращает 1: единицы одинаковы, длина не меняется.

## InMetres

`InMetres` возвращает длину `value`, заданную в единице `unit`, выраженную в
метрах.

Блок констант в этом же файле должен получить показатели 0, 1, 2 и 3 —
миллиметр, сантиметр, дециметр, метр. В выражении функции стоит писать имя
единицы результата из этого блока, а не число 3: имя говорит, какая это
единица, а одинокая тройка в выражении — нет. Та же шкала целиком
используется и в мини-проекте 2.15. Тест этого не различает — он сравнивает
только возвращённые значения.

- `InMetres(2500, 0)` возвращает 2.5;
- `InMetres(15, 2)` возвращает 1.5;
- `InMetres(2.5, 3)` возвращает 2.5;
- `InMetres(0, 1)` возвращает 0.

# Подсказки

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## Factor

**Ступень 1.** Возьмите пару «метр → миллиметр» и назовите множитель словами:
во сколько раз число миллиметров больше числа метров? Теперь запишите рядом
показатели обеих единиц и найдите действие над ними, которое даёт показатель
множителя. Проверьте это же действие на паре «миллиметр → метр» и на паре
одинаковых единиц: у третьей ответ обязан быть единицей.

**Ступень 2.** Нужное действие — вычитание, и порядок в нём важен: из
показателя исходной единицы вычитают показатель единицы результата. Дальше
остаётся превратить показатель в множитель функцией `math.Pow10`, которая
принимает `int` и возвращает `float64`. Ошибаются на порядке вычитания: тогда
перевод метров в миллиметры уменьшает число вместо того, чтобы увеличить.

## InMetres

**Ступень 1.** Сначала блок констант. Что получает спецификация, у которой
выражения нет? Посмотрите ещё раз раздел теории «Пропущенное выражение
повторяется» и решите, что нужно сделать с заглушками, чтобы номера пошли
подряд от нуля. Затем назовите словами, что делает сама функция: длина в
единице `unit`, а нужна в метрах — какая единица здесь исходная, а какая
целевая?

**Ступень 2.** Пропущенное выражение повторяет ближайшее предыдущее
непустое. В восстановленном блоке предыдущее выражение — одна только `iota`,
поэтому строка с одним именем даёт номер своей спецификации; при другом
повторяемом выражении номер пришлось бы в него подставить. В самой функции
исходная единица — `unit`, а единица результата — метр, и длину умножают на
множитель этой пары. Ошибаются, беря в качестве единицы результата
миллиметр: тогда `InMetres(2500, 0)` возвращает исходные 2500.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Как читается блок констант

<!-- review:const-block -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: какое
значение получит каждая из четырёх констант и что именно заставляет номер
расти. Образец ответа ниже.

Первая спецификация написана с выражением `iota` и имеет номер ноль, поэтому
миллиметр получает ноль. У трёх следующих выражения нет, и каждая повторяет
ближайшее предыдущее непустое выражение — то же самое `iota`, но уже со своим
номером. Номер растёт при переходе к следующей спецификации и только из-за
этого перехода: ни комментарий, ни пустая строка, ни повторное упоминание
`iota` внутри одной записи его не двигают. Так сантиметр получает единицу,
дециметр — двойку, метр — тройку.

Заглушки 99 в заготовке стояли отдельными выражениями, и каждая из них
прерывала повтор. Убрав их, вы вернули блок к одному выражению, записанному
один раз.

Второй вопрос: почему показатель множителя — это разность показателей двух
единиц. Показатель единицы — не множитель, а число десятичных шагов: единица
крупнее миллиметра в десять в степени показателя раз. Чтобы выразить длину в
миллиметрах, её умножают на десять в степени показателя исходной единицы;
чтобы перейти от миллиметров к целевой единице, делят на десять в степени её
показателя. Умножение и деление на степени одного основания дают одну степень
с разностью показателей. Сумма означала бы, что обе единицы увеличивают
число, а частное показателей в переводе длины смысла не имеет.

## Какие случаи ловят ошибку

<!-- review:test-design -->

Третий вопрос из раздела упражнения «Что проверяется, а что нет»: какой
случай заметит перестановку `from` и `to`, а какой её пропустит.

Пара с одинаковыми единицами перестановку не заметит никогда: разность равна
нулю при любом порядке вычитания, а десять в нулевой степени — единица. Такая
пара проверяет ровно один факт — что одинаковые единицы длину не меняют.

Перестановку различает любая пара с разными показателями, и чем дальше
единицы друг от друга, тем заметнее расхождение: у пары «метр → миллиметр»
верный ответ и переставленный отличаются в миллион раз. Поэтому в наборе
проверок есть обе стороны шкалы, а не только перевод в мелкую единицу.

Сбитый блок констант — другая ошибка, и ловится она в другом месте: `Factor`
констант не читает вовсе, а `InMetres` берёт из блока показатель метра. Набор
проверок `InMetres` поэтому переводит в метры из каждой единицы шкалы, а не
только из миллиметров.

И общая оговорка. Тесты сравнивают числа с допуском в одну миллиардную долю
ожидаемого и отвергают `NaN` и бесконечности до сравнения. Прошедший набор
подтверждает ответы на своих входах; что решение верно на всей допустимой
области, показывает рассуждение о показателях, а не число прогонов.

## Показатели переставлены местами

<!-- review:factor-reversed -->

Решение вычитает показатель исходной единицы из показателя целевой, то есть в
обратном порядке. Ошибки сборки нет, остановки нет: функция возвращает число,
обратное верному.

Ловит это `TestFactor` на парах с разными единицами: для перевода из метров в
миллиметры тест ждёт тысячу, а получает одну тысячную. На парах с одинаковыми
единицами ошибка не видна. Верная запись вычитает показатель целевой единицы
из показателя исходной: `math.Pow10(from - to)`.

## Вторая единица забыта

<!-- review:factor-one-exponent -->

Решение берёт только показатель исходной единицы и не вычитает показатель
целевой. Для перевода в миллиметры ответ случайно верен — показатель
миллиметра равен нулю, и вычитать нечего, — поэтому ошибка держится дольше,
чем кажется.

Ловит это `TestFactor` на паре «миллиметр → сантиметр»: тест ждёт одну
десятую, а получает единицу. Множитель задаётся обеими единицами, и обе
обязаны попасть в выражение.

## Результат перестал быть числом

<!-- review:nan-result -->

В решении вместо возведения в степень стоит `math.Sqrt` — квадратный корень.
Для отрицательной разности показателей корень не определён, и функция
возвращает `NaN` — «не число» из урока 2.5.

Ловят это `TestFactor` и `TestInMetres`. Важна не только сама подмена
функции, но и то, как устроена проверка: `NaN` и бесконечности она отвергает
отдельной строкой, до сравнения ошибки. Проверка, написанная как «провалить,
если ошибка больше допуска», на `NaN` не сработала бы: сравнение `>` с `NaN`
не истинно, и неверный ответ прошёл бы. Обещание, что на вход приходят
конечные числа, результат конечным не делает.

## Перевод в обратную сторону

<!-- review:metres-reversed -->

Решение вычитает номер единицы из показателя метра, а не наоборот. Миллиметры
оно увеличивает в тысячу раз вместо того, чтобы уменьшить.

Ловит это `TestInMetres` на переводе из миллиметров: тест ждёт две с
половиной, а получает два с половиной миллиона. Исходная единица здесь —
`unit`, целевая — метр, и вычитают из первой вторую.

## Перевод не в ту единицу

<!-- review:metres-to-millimetres -->

Решение вычитает показатель миллиметра вместо показателя метра. Показатели
вычтены в верном порядке, но целевая единица выбрана не та, и функция
переводит в миллиметры.

Ловит это `TestInMetres` на переводе из миллиметров: длина возвращается такой
же, какой пришла, а тест ждёт метры. Имя единицы результата в выражении
обязано совпадать с тем, что обещает имя функции.

## Явное число сбило нумерацию

<!-- review:scale-override -->

Сама функция написана верно, неверен блок: дециметру приписано явное число
10, и метр, у которого выражения нет, повторил это же число вместо своего
номера. В блоке оказались показатели ноль, один, десять и десять.

Ловит это `TestInMetres` — но не на любом случае: нулевая длина и с неверным
показателем даёт ноль, потому что множитель всё равно умножается на ноль.
Сработает первый же ненулевой перевод. Показатель метра стал 10 вместо 3, то
есть на семь больше, поэтому множитель оказывается в десять миллионов раз
меньше нужного: для 2500 миллиметров тест ждёт 2.5, а получает две с
половиной десятимиллионных. Разбор этой ошибки — раздел теории «Явное
значение посреди блока»: явная запись прерывает повтор, а дальше повторяется
уже она.

не вставляет вовсе. Вариант B приписывает языку перечислимый тип, которого
здесь нет. Вариант C ждёт, что программа остановится на постороннем номере,
но останавливать её нечему: проверки принадлежности нет, а тело этой
функции — одно вычитание, которое считается при любом номере. Вариант D
различает литерал и переменную: литерал — нетипизированная константа, тип
`int` он получает от контекста, то есть от самого параметра, и после этого
от значения переменной того же типа уже неотличим. Допустимая область
остаётся условием задачи, записанным в документации функции.

## Вопрос 6

В блоке четыре имени: выражение `iota` написано в первой спецификации, три
остальные его повторяют, явных значений в блоке нет. Значения этих имён уже
записаны числами в файл отчёта. Позже в блок добавили пятую спецификацию —
тоже без выражения — и поставили её сразу после первого имени. Что
изменилось?

Варианты ответа:

- A. Ничего: имена прежние, а значения — дело внутреннее.
- B. Три прежних имени ниже вставки получили значения на единицу больше, и
  старые записи файла теперь означают другие имена.
- C. Сборка откажет, пока файл отчёта не перезаписан.
- D. Сдвинулось значение только вставленного имени.

Прежде чем смотреть ответ, выпишите старый ряд значений и новый и сравните
их имя за именем.

**Правильный ответ: B.**

Значение зависит от положения записи. Было 0, 1, 2, 3; стало 0, 1, 2, 3, 4,
где единицу занял вставленный, а три прежних имени держат 2, 3 и 4 вместо 1,
2 и 3. Первое имя не тронуто, потому что стоит выше вставки. Код при этом
собирается, а записанные раньше числа читаются как другие имена. Вариант A
не замечает, что отображение «имя — значение» уже изменилось: три имени
получили другие числа, и вместе с ними изменятся вычисления, которые
используют эти имена. У записанных наружу чисел есть и второе последствие:
старые строки файла теперь называют другие имена. Вариант C ждёт от
компилятора знания о чужом файле. Вариант D оставляет прежние имена на их
старых числах: так вставка не работает. Ограниченная правка в таком блоке —
перестановка второй и третьей записей местами: она меняет значения только
этих двух имён. Первую запись переставлять нельзя — выражение написано
только в ней, и без него блок не соберётся. Значение, заданное снаружи,
пишут явным числом, а не получают нумерацией.

## Вопрос 7

Длина задана в сантиметрах, а нужна в метрах. Показатели шкалы: сантиметр —
1, метр — 3. На что умножают длину?

Варианты ответа:

- A. На десять в степени 1 − 3, то есть на 0.01.
- B. На десять в степени 3 − 1, то есть на 100.
- C. На десять в степени 1 + 3, то есть на 10000.
- D. На десять в степени 3, то есть на 1000.

Прежде чем смотреть ответ, скажите, станет ли число больше или меньше при
переходе к более крупной единице, и только потом выбирайте запись.

**Правильный ответ: A.**

Метр крупнее сантиметра, поэтому одна и та же длина выражается меньшим
числом, и множитель обязан быть меньше единицы. Из показателя исходной
единицы вычитают показатель единицы результата: получается минус два и
множитель в одну сотую. Вариант B вычитает в обратном порядке и увеличивает
длину в сто раз вместо того, чтобы уменьшить. Вариант C складывает
показатели, хотя перевод — это умножение на одну степень и деление на другую.
Вариант D берёт только показатель единицы результата и забывает исходную.

## Вопрос 8

Какие из четырёх объявлений соберутся?

1. `const f = math.Pow10(2)`
2. `const n = len("метр")`
3. `const s = min(3, 5)`
4. `var g = math.Pow10(2)`

Варианты ответа:

- A. Второе, третье и четвёртое.
- B. Только четвёртое: в начальном значении константы вызовов не бывает.
- C. Все четыре.
- D. Первое, второе и третье.

Прежде чем смотреть ответ, для каждой строки скажите, обязан ли компилятор
посчитать значение сам и может ли он это сделать.

**Правильный ответ: A.**

Начальное значение константы обязано быть константным выражением, а перечень
константных операндов задаёт язык. Строковый литерал и встроенные `len`,
`min` и `max` на константных аргументах в перечень входят, поэтому второе и
третье объявления — законные константы. Первое не собирается: `math.Pow10` —
обычная функция библиотеки, в перечень она не входит и выполняется во время
работы. Четвёртое объявляет переменную, а её начальное значение считается при
запуске, и вызов там допустим. Вариант B выводит из одного отказа общий
запрет на вызовы. Вариант C не различает константное выражение и обычное.
Вариант D принимает несобираемое первое объявление и отбрасывает законную
переменную. Правило не в том, что «компилятор знает значение»: переменная со
значением 99 константой не станет, даже если её значение очевидно и любой
оптимизатор его вывел бы.

## Вопрос 9

В блок единиц шкалы пятой спецификацией без выражения приписали `kilometre`.
Что получится?

Варианты ответа:

- A. Километр получит показатель 4, перевод ошибётся в сто раз, и сообщений
  при сборке не будет.
- B. Километр получит показатель 6: компилятор выведет его из названия.
- C. Сборка откажет: между метром и километром пропущены ступени.
- D. Километр получит показатель 4, и это верно.

Прежде чем смотреть ответ, назовите номер пятой спецификации и отдельно —
сколько миллиметров в километре.

**Правильный ответ: A.**

Пятая спецификация имеет номер четыре, и километр получает четвёрку. В
километре миллион миллиметров, то есть его настоящий показатель — шесть:
между метром и километром стоят ещё две десятичные ступени, которых в наборе
нет. Разница между четвёртой и шестой степенью — сто раз. Вариант B
приписывает компилятору знание названий. Вариант C ждёт отказа, но блок
синтаксически безупречен, неверен только смысл. Вариант D путает соседство
записей с соседством ступеней шкалы. Нерегулярную шкалу задают явными
числами.

## Вопрос 10

В наборе проверок `Factor` есть только пары `(0, 0)`, `(2, 2)` и `(3, 3)`.
Коллега считает, что их достаточно. Что такой набор пропустит?

Варианты ответа:

- A. Ничего: если множитель верен на одинаковых единицах, он верен и на
  разных.
- B. Перестановку `from` и `to` местами.
- C. Наоборот: одинаковые единицы — самый строгий случай, а пары с разными
  единицами ничего нового не добавляют.
- D. Перестановку — но лишь потому, что пар мало; десяти одинаковых пар
  хватило бы.

Прежде чем смотреть ответ, посчитайте разность показателей для пары `(2, 2)`
в обоих порядках и сравните полученные множители.

**Правильный ответ: B.**

У пары с одинаковыми единицами разность равна нулю при любом порядке
вычитания, а десять в нулевой степени — единица. Значит перестановка на таких
парах даёт тот же ответ, что и верная запись, и проверка молчит. Чтобы её
заметить, нужна хотя бы одна пара с разными единицами. Вариант A обобщает
совпадение в частном случае до совпадения всюду. Вариант C переворачивает
отношение: пара с одинаковыми единицами проверяет ровно один факт — нулевая
разность даёт единицу, — а порядок вычитания виден только там, где показатели
различаются. Вариант D надеется на количество одинаковых случаев, хотя дело в
их виде, а не в числе.
