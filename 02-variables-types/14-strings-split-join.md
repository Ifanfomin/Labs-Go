# strings: разбиение и сборка

Таблицу выгрузили в текст, и каждая её строка выглядит так: `Анна;;Москва;`.
Поля разделены точкой с запятой, а пустое поле означает «не заполнено».
Другая программа ждёт запятые вместо точек с запятой. Пустые поля терять
нельзя: без них «Москва» переедет из третьего поля во второе. А подписи,
которые люди набирают руками, приходят в виде `"  Отчёт   ЗА март "`:
лишние пробелы, разный регистр. Такую подпись нужно привести к одному виду.

Для этих задач в пакете `strings` есть функции, которые разбивают строку на
части и собирают части обратно: `Split`, `Fields` и `Join`. Рядом с ними —
`Replace` для замены текста, `Repeat` для повтора строки и операторы,
которые сравнивают строки. К концу урока вы сможете:

- предсказать, сколько частей даст разбиение и какая строка получится при
  сборке, в том числе для пустой строки, отсутствующего и повторённого
  разделителя и русских букв;
- объяснить, когда разбиение и сборка возвращают исходную строку, а когда
  стирают пробелы так, что вернуть их нельзя;
- выбрать число замен для `Replace` и допустимое число повторов для
  `Repeat`;
- предсказать результат `<` для двух строк и объяснить, почему это не
  алфавитный порядок;
- собрать цепочку операций под требование и найти вход, на котором похожее,
  но неверное решение ошибётся.

## Split делит строку на части

`strings.Split(s, sep)` находит в строке `s` все вхождения разделителя `sep`
и возвращает то, что лежит между ними, — **части** строки, по порядку слева
направо. Результат — не одна строка, а упорядоченный набор строк. В Go
такой набор называется slice. Как устроен slice, как записывается его тип,
как взять из него отдельную часть по номеру и как перебрать все части,
разбирает модуль 4.

В этом уроке с результатом делают ровно три вещи, и каждая работает с
набором целиком:

1. сохраняют его в переменную через `:=`, как любой другой результат
   функции;
2. узнают число частей встроенной функцией `len`;
3. передают весь набор в `strings.Join(parts, sep)`: она склеивает части
   обратно в одну строку и ставит `sep` между соседними частями.

Обратите внимание на `len`. Для строки она возвращает число байтов (урок
2.7), а для набора частей — число частей. Функция одна, а считает она то, из
чего состоит её аргумент.

Прежде чем смотреть вывод, предскажите три строки: сколько частей даст
разбиение по запятой, сколько байтов в исходной строке и что получится, если
склеить части через `" | "`.

```go

### Example: `01-parts`

Источник: `examples/01-parts/`

```go

import (
	"fmt"
	"strings"
)

func main() {
	line := "Анна,Москва,латте"
	parts := strings.Split(line, ",")
	fmt.Println("частей:", len(parts))
	fmt.Println("байтов в строке:", len(line))
	fmt.Println("снова вместе:", strings.Join(parts, " | "))

```
```

Частей три: две запятые отделяют три куска. Байтов 32: в строке пятнадцать
русских букв по два байта и две запятые по одному. Склейка вернула те же три
слова в том же порядке, но между ними теперь стоит `" | "`, а не запятая:
`Join` вставляет тот разделитель, который ей передали.

Дальше в уроке результат разбиения наблюдают так же: число частей и склейка
через заметный разделитель `|`. В такой склейке видна каждая часть, даже
пустая: два `|` подряд окружают пустую часть.

## Разделитель — точная подстрока

`Split` ищет разделитель как точную подстроку: все его байты подряд и в том
же порядке. Разделитель — не набор символов и не «любой пробел». Поиск идёт
слева направо, и вхождения не перекрываются: найденный разделитель
забирается целиком, а следующий ищется только после его конца. Из этих
правил следуют четыре случая, которые легко угадать неверно:

- два разделителя подряд дают между собой пустую часть;
- разделитель в начале или в конце строки даёт пустую часть с этой стороны;
- если разделителя в строке нет, результат — одна часть, равная всей строке;
- у пустой строки при непустом разделителе ровно одна часть, и она пустая.

Общий счёт при непустом разделителе: частей на одну больше, чем найдено
неперекрывающихся вхождений разделителя.

Функция `describe` в программе ниже разбивает строку и возвращает одной
строкой вход и разделитель через `%q`, число частей и склейку через `|`.
Прежде чем смотреть вывод, для каждой из семи строк назовите число частей и
склейку. В пятой и шестой строках разделители разные: `", "` — запятая с
пробелом, `","` — одна запятая. В последней строке `"aaa"` делится по
`"aa"`: сначала решите, сколько вхождений найдёт поиск слева направо.

```go

### Example: `02-separator`

Источник: `examples/02-separator/`

```go
package main

import (
	"fmt"
	"strings"
)

// describe разбивает s по sep и возвращает одной строкой вход, число
// частей и части, склеенные через |.
func describe(s string, sep string) string {
	parts := strings.Split(s, sep)
	return fmt.Sprintf("%q по %q: %d, %q", s, sep, len(parts), strings.Join(parts, "|"))
}

func main() {
	fmt.Println(describe("a,,b", ","))
	fmt.Println(describe(",a,", ","))
	fmt.Println(describe("abc", ","))
	fmt.Println(describe("", ","))
	fmt.Println(describe("a, b", ", "))
	fmt.Println(describe("a, b", ","))
	fmt.Println(describe("aaa", "aa"))
}

```
```

Посмотрите на пятую и шестую строки. С разделителем `", "` пробел ушёл вместе
с запятой. С разделителем `","` пробел остался в начале второй части: `Split`
не знает, что пробел после запятой «не важен», и отрезает ровно то, что ей
передали.

В последней строке первое вхождение `"aa"` занимает первые две буквы `a`.
Второе вхождение могло бы начаться со второй буквы, но оно перекрывалось бы
с первым, поэтому его нет. Вхождение одно, частей две: пустая перед ним и
`"a"` после него. Три части получились бы, только если бы поиск считал
перекрывающиеся вхождения, а функция их не считает.

## Пустой разделитель и пустая строка

Если разделитель пустой, искать в строке нечего, и для этого случая у
`Split` своё правило. По документации она режет строку после каждой
последовательности байтов UTF-8. В правильном тексте UTF-8 — а в этом уроке
весь текст такой — каждая такая последовательность записывает одну кодовую
точку (урок 2.7). Частей тогда столько же, сколько кодовых точек, — не
байтов и не знаков на экране. Если пуста и сама строка, частей нет вовсе:
ноль, а не одна пустая часть.

Прежде чем смотреть вывод, предскажите при пустом разделителе число частей
для `"abc"`, для `"жук"` и для пустой строки, а также число байтов в
`"жук"`. Затем вспомните пару из урока 2.7: `composed` — буква é одной
кодовой точкой, `combined` — латинская `e` и знак ударения, то есть две
кодовые точки. В программе обе строки записаны экранированиями байтов `\x`, а
комментарии называют их кодовые точки. На экране они могут выглядеть
одинаково. Сколько частей даст каждая?

```go

### Example: `03-empty-sep`

Источник: `examples/03-empty-sep/`

```go
package main

import (
	"fmt"
	"strings"
)

// describe разбивает s по sep и возвращает одной строкой вход, число
// частей и части, склеенные через |.
func describe(s string, sep string) string {
	parts := strings.Split(s, sep)
	return fmt.Sprintf("%q по %q: %d, %q", s, sep, len(parts), strings.Join(parts, "|"))
}

func main() {
	fmt.Println(describe("abc", ""))
	fmt.Println(describe("жук", ""))
	fmt.Println("байтов в жук:", len("жук"))
	fmt.Println(describe("", ""))

	composed := "\xc3\xa9"  // é одной кодовой точкой U+00E9: байты c3 a9
	combined := "e\xcc\x81" // e и знак ударения U+0301: байты 65, cc 81
	fmt.Println("частей в composed:", len(strings.Split(composed, "")))
	fmt.Println("частей в combined:", len(strings.Split(combined, "")))
}

```
```

В слове «жук» три кодовые точки и шесть байтов, и частей три: русскую букву
`Split` не разрывает. У `combined` две части, хотя на экране это может быть
один знак: `Split` считает кодовые точки, а не то, что видит читатель.
Подсчёт знаков на экране — отдельная задача, и `Split` её не решает.

Сравните два случая с пустой строкой: `Split("", ",")` даёт одну пустую
часть, а `Split("", "")` — ни одной.

## Fields делит по пробельным промежуткам

В тексте, который набирают люди, граница между словами — не один символ, а
сколько угодно пробелов, табуляций и переводов строк подряд. Для такого
текста есть `strings.Fields(s)`. Она делит строку в местах, где стоит один
или несколько **пробельных символов** подряд, и возвращает части между
ними. Пробельные символы — это пробел, табуляция `\t`, перевод строки `\n` и
другие символы, которые Unicode относит к пробельным, например неразрывный
пробел U+00A0.

Три свойства отличают `Fields` от `Split`:

- промежуток из нескольких пробельных символов — одна граница, а не
  несколько;
- промежутки в начале и в конце строки отбрасываются;
- пустых частей не бывает: у пустой строки и у строки из одних пробельных
  символов частей ноль.

Поэтому `Fields(s)` — не то же самое, что `Split(s, " ")`. Функция `compare`
в программе ниже разбивает одну и ту же строку обоими способами. Последняя
строка программы проверяет неразрывный пробел: в исходном коде он записан
двумя байтами `\xc2\xa0`, как экранирования байтов в уроке 2.7, и для него
печатаются только числа частей. Прежде чем смотреть вывод, для каждой строки
предскажите оба числа частей и, где они печатаются, обе склейки.

```go

### Example: `04-fields`

Источник: `examples/04-fields/`

```go
package main

import (
	"fmt"
	"strings"
)

// compare разбивает s двумя способами — Split по одному пробелу и Fields —
// и возвращает для каждого число частей и части, склеенные через |.
func compare(s string) string {
	bySpace := strings.Split(s, " ")
	byFields := strings.Fields(s)
	return fmt.Sprintf("%q: Split %d %q, Fields %d %q",
		s, len(bySpace), strings.Join(bySpace, "|"), len(byFields), strings.Join(byFields, "|"))
}

func main() {
	fmt.Println(compare("Мир Go"))
	fmt.Println(compare("Мир  Go"))
	fmt.Println(compare("  a  b  "))
	fmt.Println(compare("a\tb\nc"))
	fmt.Println(compare("   "))
	fmt.Println(compare(""))

	nbsp := "a\xc2\xa0b" // между a и b неразрывный пробел: байты c2 a0
	fmt.Println("неразрывный пробел: Split", len(strings.Split(nbsp, " ")), "Fields", len(strings.Fields(nbsp)))
}

```
```

На `"Мир Go"` с одним пробелом ответы совпали. На `"Мир  Go"` с двумя
пробелами `Split` нашла между ними пустую часть, а `Fields` — нет. Для
`Split(s, " ")` табуляция, перевод строки и неразрывный пробел вовсе не
разделители, а для `Fields` это такие же границы, как пробел. Из трёх
пробелов `Split` сделала четыре пустые части, `Fields` — ни одной.

Части `Fields` удобно считать словами, но это не разбор языка: `"ну-ка"` для
неё одна часть, потому что дефис не пробельный символ.

## Join собирает части

`strings.Join(parts, sep)` берёт части по порядку и склеивает их, ставя
`sep` только между соседними частями: ни перед первой, ни после последней
разделителя нет. Содержимое частей не меняется. Значит, при `k` частях, где
`k` не меньше единицы, `Join` вставляет `k − 1` разделителей. Если в самих
частях уже есть такие же символы, они остаются, и всего их в результате
окажется больше. Если частей нет, результат — пустая строка. Если часть
одна, результат — сама эта часть, без разделителя.

Прежде чем смотреть вывод, предскажите склейку через `"-"` в каждой строке
программы.

```go

### Example: `05-join-edges`

Источник: `examples/05-join-edges/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	noParts := strings.Fields("")
	fmt.Printf("Fields(\"\"): частей %d, Join %q\n", len(noParts), strings.Join(noParts, "-"))

	oneEmpty := strings.Split("", ",")
	fmt.Printf("Split(\"\", \",\"): частей %d, Join %q\n", len(oneEmpty), strings.Join(oneEmpty, "-"))

	oneFull := strings.Split("a", ",")
	fmt.Printf("Split(\"a\", \",\"): частей %d, Join %q\n", len(oneFull), strings.Join(oneFull, "-"))

	twoEmpty := strings.Split(",", ",")
	fmt.Printf("Split(\",\", \",\"): частей %d, Join %q\n", len(twoEmpty), strings.Join(twoEmpty, "-"))

	three := strings.Split("x,y,z", ",")
	fmt.Printf("Split(\"x,y,z\", \",\"): частей %d, Join %q\n", len(three), strings.Join(three, "-"))
}

```
```

Первые две строки дали одну и ту же пустую строку, хотя частей в них разное
число: ноль и одна пустая. По склейке эти случаи не различить — различает
`len`. Две пустые части дали один дефис: разделитель стоит между частями,
даже если обе они пустые.

## Когда разбиение и сборка обратимы

Если склеить части, которые вернула `Split`, тем же непустым разделителем,
получится в точности исходная строка. `Split` выбрасывает разделитель ровно в
тех местах, куда `Join` вставит его обратно, а пустые части хранят места
повторённых и крайних разделителей. Если склеить те же части другим
разделителем, изменятся только разделители. Так запятые меняют на точки с
запятой.

С `Fields` иначе. Она выбрасывает пробельные промежутки целиком и не
запоминает, какими они были. `Join(Fields(s), " ")` ставит ровно по одному
пробелу только между соседними частями; на месте промежутков в начале и в
конце строки не остаётся ничего. Так подпись приходит к одному виду.
Такое приведение называют **нормализацией**. Её цена — потеря: сколько
пробелов стояло между
словами, была ли среди них табуляция и были ли пробелы по краям, по
результату уже не узнать.

Прежде чем смотреть вывод, ответьте на три вопроса. Вернётся ли `"a,,b,"`
после разбиения и сборки запятой? Во что превратится `"x--y----z"`, если
разбить её по `"--"` и склеить через `"+"`? Сколько байтов было в набранной
подписи и сколько останется после нормализации?

```go

### Example: `06-round-trip`

Источник: `examples/06-round-trip/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	csv := "a,,b,"
	back := strings.Join(strings.Split(csv, ","), ",")
	fmt.Printf("%q: после Split и Join %q, совпало %v\n", csv, back, back == csv)

	line := "x--y----z"
	parts := strings.Split(line, "--")
	fmt.Printf("%q: частей %d, через -- %q, через + %q\n",
		line, len(parts), strings.Join(parts, "--"), strings.Join(parts, "+"))

	typed := "  Мир   Go\tкурс "
	tidy := strings.Join(strings.Fields(typed), " ")
	fmt.Printf("было %q, байтов %d\n", typed, len(typed))
	fmt.Printf("стало %q, байтов %d\n", tidy, len(tidy))
	fmt.Println("совпадает с исходной:", tidy == typed)
}

```
```

Первые две строки показывают обратимое разбиение. В `"x--y----z"` четыре
дефиса подряд — это два разделителя `"--"`, и между ними пустая часть,
поэтому через `"+"` получилось два плюса подряд.

Нормализация сократила подпись с 23 байтов до 18. Но по `"Мир Go курс"`
нельзя узнать, что между «Мир» и «Go» стояли три пробела, а перед «курс» —
табуляция. Это не ошибка функции, а суть нормализации. Выбирайте её, когда
исходные пробелы ничего не значат, и не выбирайте, когда строку нужно
сохранить байт в байт.

## Replace: сколько замен

`strings.Replace(s, old, new, n)` возвращает копию `s`, в которой вхождения
`old` заменены на `new`. Исходная строка не меняется: строки неизменяемы
(урок 2.7). Последний аргумент `n` ограничивает число замен:

- вхождения ищутся слева направо и не перекрываются: найденное вхождение
  заменяется целиком, а поиск продолжается после его конца;
- заменяются первые `n` вхождений; если вхождений меньше, заменяются все;
- `n`, равное нулю, — ни одной замены;
- отрицательное `n` снимает ограничение: заменяются все вхождения.

Для «заменить все» есть более ясная запись — `strings.ReplaceAll(s, old,
new)`. Она делает то же, что `Replace` с отрицательным `n`, и читателю не
нужно помнить, что значит минус единица. Если `old` в строке нет, обе функции
возвращают строку без изменений.

Прежде чем смотреть вывод, предскажите все восемь строк. Для двух последних
проследите слева направо, где начинается каждое следующее вхождение `"aa"`.

```go

### Example: `07-replace-count`

Источник: `examples/07-replace-count/`

```go

	"fmt"
	"strings"
)

func main() {
	s := "a-b-c"
	fmt.Printf("n = 0: %q\n", strings.Replace(s, "-", "+", 0))
	fmt.Printf("n = 1: %q\n", strings.Replace(s, "-", "+", 1))
	fmt.Printf("n = 2: %q\n", strings.Replace(s, "-", "+", 2))
	fmt.Printf("n = -1: %q\n", strings.Replace(s, "-", "+", -1))
	fmt.Printf("ReplaceAll: %q\n", strings.ReplaceAll(s, "-", "+"))
	fmt.Printf("нет вхождений: %q\n", strings.ReplaceAll("abc", "x", "y"))
	fmt.Printf("aaaa: %q\n", strings.ReplaceAll("aaaa", "aa", "b"))
	fmt.Printf("aaa: %q\n", strings.ReplaceAll("aaa", "aa", "b"))
}

```
```

Первые пять строк следуют правилу о числе замен. В `"aaaa"` нашлось два
вхождения `"aa"` подряд, и получилось две `b`. В `"aaa"` после первого
вхождения осталась одна `a`. Второе вхождение перекрывалось бы с первым,
поэтому его нет, и результат — `b`, а за ней `a`.

## Сравнение строк: равенство и порядок

`==` и `!=` сравнивают строки побайтово (урок 2.7): строки равны, когда
совпадают все байты. Неважно, как строка получена — из литерала, склейкой
или через `Join`: сравниваются значения, а не место, где они появились.

Операторы порядка `<`, `<=`, `>` и `>=` тоже работают со строками. Правило
называется **лексикографическим сравнением по байтам**. Это порядок как в
словаре, только вместо букв сравниваются байты:

1. байты двух строк сравниваются по очереди, начиная с первого;
2. на первом месте, где байты различаются, меньше та строка, у которой байт
   меньше; дальше не смотрят;
3. если одна строка — начало другой, меньше более короткая; поэтому пустая
   строка меньше любой непустой.

Чтобы применить правило, нужны значения байтов. В ASCII (урок 2.7) цифры
`0`–`9` — байты от 0x30 до 0x39, заглавные латинские буквы `A`–`Z` — от 0x41
до 0x5a, строчные `a`–`z` — от 0x61 до 0x7a. Внутри каждого ряда байты
растут по порядку: `0` меньше `1`, `a` меньше `b`. Значит, любая цифра меньше
любой латинской буквы, а любая заглавная латинская буква меньше любой
строчной. Для русских букв ниже понадобятся три записи UTF-8: «е» — байты
d0 b5, «я» — d1 8f, «ё» — d1 91.

Прежде чем смотреть вывод, предскажите каждую строку программы. Для каждого
сравнения назовите первое место, где байты различаются, или скажите, что одна
строка — начало другой.

```go

## Как выбрать цепочку операций

Операции урока решают разные задачи. Выбор начинается с вопроса: что из
исходной строки обязано сохраниться?

| Требование | Операция | Что сохраняется | Что теряется |
|---|---|---|---|
| сохранить пустые поля | `Split` по точному разделителю | все части, включая пустые | ничего: `Join` с тем же разделителем вернёт строку |
| привести пробелы к одному виду | `Fields`, затем `Join` с `" "` | слова и их порядок | число и вид пробельных символов, пробелы по краям |
| сменить разделитель | `ReplaceAll` или `Split`, затем `Join` с новым разделителем | поля, включая пустые | старый разделитель |
| заменить часть текста | `Replace` с числом замен или `ReplaceAll` | всё, кроме заменённого | заменённые вхождения |

Каждый шаг цепочки можно проследить словами: после него назовите число
частей или получившуюся строку. Программа ниже меняет разделитель в строке
таблицы из начала урока двумя способами, а затем пробует для той же строки
`Fields`. Прежде чем смотреть вывод, предскажите число ячеек, обе строки с
запятыми и число частей у `Fields`.

```go

### Example: `12-pipeline`

Источник: `examples/12-pipeline/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	row := "Анна;;Москва;"
	cells := strings.Split(row, ";")
	fmt.Println("ячеек:", len(cells))
	fmt.Printf("Split и Join: %q\n", strings.Join(cells, ","))
	fmt.Printf("ReplaceAll: %q\n", strings.ReplaceAll(row, ";", ","))
	fmt.Println("частей у Fields:", len(strings.Fields(row)))
}

```
```

`Split` нашла четыре ячейки, из них две пустые, и `Join` через запятую
сохранила их места. `ReplaceAll` дала ту же строку за один шаг. `Fields`
вернула одну часть — всю строку: пробельных символов в ней нет, а точку с
запятой `Fields` разделителем не считает. Для полей таблицы это неверный
инструмент, а для подписи, набранной человеком, — верный.

## Какой вход различает похожие решения

Два решения могут давать одинаковые ответы на удобных входах и расходиться
на остальных. Сравните два способа посчитать слова:
`len(strings.Fields(s))` и `len(strings.Split(s, " "))`. В разделе «Fields
делит по пробельным промежуткам» на `"Мир Go"` оба способа дали 2. Проверка
только на таком входе второй способ пропустит. Каждый из следующих входов
сам по себе различает способы: пустая строка (1 против 0), два пробела
подряд в `"Мир  Go"` (3 против 2), пробел в начале `" Мир"` (2 против 1),
табуляция вместо пробела в `"Мир\tGo"` (1 против 2).

Складывать эти отличия в один вход опасно: они могут погасить друг друга. В
`"a  b\tc"` оба способа насчитают 3 части, хотя части разные: у `Split` это
`"a"`, пустая и `"b\tc"`, у `Fields` — `"a"`, `"b"` и `"c"`. Совпавшее число
частей ещё не значит, что совпали сами части. Поэтому каждое отличие
проверяют отдельным входом.

Отсюда способ проверить, что требование записано точно:

1. Запишите, что функция обязана вернуть на пустой строке, на повторённом
   разделителе и на разных пробельных символах.
2. Для каждого правдоподобного неверного решения найдите вход, на котором
   его ответ отличается от верного.
3. Сделайте этот вход отдельной проверкой.

Вход, на котором верное и неверное решения совпадают, эту ошибку не поймает,
сколько бы таких входов ни было.

Сверьте ответы с разбором после попытки: первые два вопроса разобраны в
разделе «Как считать части и приводить подпись», два последних — в разделе
«Какие входы ловят ошибку».

## CountFields

`CountFields` возвращает число частей строки `s`, разделённых промежутками
пробельных символов. Промежуток из нескольких символов подряд — одна
граница. Промежутки в начале и в конце строки частей не дают. Если частей
нет, результат 0. Это подсчёт частей, а не разбор языка: `"ну-ка"` — одна
часть.

- `CountFields("кот пёс")` возвращает 2;
- `CountFields("  кот   пёс ")` возвращает 2;
- `CountFields("")` возвращает 0;
- `CountFields("a\tb\nc")` возвращает 3.

## NormalizeLabel

`NormalizeLabel` приводит подпись к одному виду. В результате:

- все буквы строчные — так, как их делает `strings.ToLower`;
- части подписи разделены ровно одним обычным пробелом `" "`;
- в начале и в конце нет пробельных символов.

Если частей в подписи нет, результат — пустая строка.

- `NormalizeLabel("  Отчёт   ЗА\tмарт ")` возвращает `"отчёт за март"`;
- `NormalizeLabel("A  B")` возвращает `"a b"`;
- `NormalizeLabel("   ")` возвращает `""`.

## ReplaceDelimiter

`ReplaceDelimiter` возвращает `s`, в которой каждое вхождение разделителя
`from` заменено на `to`. Вхождения ищутся слева направо и не перекрываются.
Всё, кроме разделителей, остаётся как было, включая пробелы внутри полей.
Пустые поля остаются на своих местах: два разделителя подряд дают два новых
разделителя подряд.

- `ReplaceDelimiter("a,b,c", ",", ";")` возвращает `"a;b;c"`;
- `ReplaceDelimiter("id;;город;", ";", ",")` возвращает `"id,,город,"`;
- `ReplaceDelimiter("x--y----z", "--", "+")` возвращает `"x+y++z"`;
- `ReplaceDelimiter("abc", ",", ";")` возвращает `"abc"`.

## Ruler

`Ruler` возвращает текстовую линейку из `n` делений. Деление — строка
`"|----"`; после всех делений стоит одна закрывающая черта `"|"`.

- `Ruler(3)` возвращает `"|----|----|----|"`;
- `Ruler(1)` возвращает `"|----|"`;
- `Ruler(0)` возвращает `"|"`.

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Как считать части и приводить подпись

<!-- review:fields-and-normalization -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: на каком
входе `len(strings.Split(s, " "))` совпадает с `CountFields`. Образец ответа
ниже.

Способы дают один ответ, когда каждая граница между словами — ровно один
пробел и пробелов по краям нет: на `"кот пёс"` оба дают 2, на `"кот"` оба
дают 1. Каждый из следующих входов сам по себе даёт разные ответы. На пустой
строке `Split` находит одну пустую часть, а частей нет: 1 против 0. Два
пробела подряд в `"кот  пёс"` дают лишнюю пустую часть: 3 против 2. Пробел в
начале `" кот"` даёт пустую часть перед словом: 2 против 1. Табуляция вместо
пробела в `"кот\tпёс"` для `Split` по пробелу вообще не граница: 1 против 2.

Если собрать несколько таких отличий в одном входе, они могут погасить друг
друга. На `"a  b\tc"` оба способа отвечают 3, хотя части разные: лишняя
пустая часть у `Split` возмещает пропущенную табуляцию. Совпавшее число ещё
не значит, что совпали части, поэтому каждое отличие проверяют отдельным
входом. Верное решение — `len(strings.Fields(s))`.

Второй вопрос: почему не годится `strings.ToLower(strings.TrimSpace(s))`.
`TrimSpace` убирает пробельные символы только по краям, а промежутки между
словами оставляет: из `"A  B"` получится `"a  b"` с двумя пробелами.
Промежутки выбрасывает `strings.Fields`, а `strings.Join` с `" "` ставит
ровно один пробел только между соседними частями; на месте промежутков по
краям не остаётся ничего. Регистр меняет `strings.ToLower`, и порядок двух
шагов здесь неважен. Верное решение —
`strings.Join(strings.Fields(strings.ToLower(s)), " ")`.

Нормализация при этом теряет сведения: сколько пробелов стояло между
словами, были ли среди них табуляции и переводы строк, были ли пробелы по
краям и какими были заглавные буквы. По результату этого не восстановить.
Для подписи это нормально — ради этого её и нормализуют. Для поля таблицы,
где пустое значение что-то значит, нормализация была бы ошибкой.

## Какие входы ловят ошибку

<!-- review:test-design -->

Третий вопрос из раздела упражнения «Что проверяется, а что нет»: какие
входы ловят неверные решения `ReplaceDelimiter`.

Замену только первого разделителя ловит вход, в котором `from` встречается
больше одного раза, а `to` отличается от `from`: на `"a,b,c"` с заменой `","`
на `";"` она вернёт `"a;b,c"`. Строка с одним разделителем эту ошибку не
заметит. Не заметит её и вызов, где `to` равен `from`: замена одного
вхождения и замена всех дают тогда одну и ту же строку.

Решение, которое превращает разделители в пробелы и нормализует строку через
`Fields` и `Join`, на `"a,b,c"` отвечает верно. Его ловят входы двух видов.
Первый — пустые поля: разделители подряд, как в `"a,,b"`, и разделитель по
краю, как в `",a,"`; пустое поле пропадает. Второй — пробельный символ внутри
поля: пробел, табуляция или другой символ, который `Fields` считает
границей. Из `"a b,c"` должно получиться `"a b;c"`, а это решение делит
`"a b"` на два поля и возвращает `"a;b;c"`; так же оно разрежет поле с
табуляцией. Поэтому такие входы стоят в наборе отдельными проверками, а не
заменяются ещё одним «обычным» случаем. Обычный случай эту
ошибку не поймает, сколько бы раз его ни повторили.

Четвёртый вопрос: `Ruler(0)` возвращает `"|"` — ноль делений и одна
закрывающая черта. Этот случай ловит решение, которое забыло черту: на нуле
у него пустая строка. Отрицательных `n` в допустимой области нет, потому что
`strings.Repeat` на отрицательном числе повторов вызывает панику, а не
возвращает пустую строку. Граница «от 0 до 20» записана в условии задачи, и
тесты за её пределы не выходят.

И общая оговорка. Пройденный набор тестов подтверждает ответы только на
своих входах. Что решение верно на любой строке, показывает рассуждение о
правилах
`Split`, `Fields` и `Replace`, а не число прогонов.

## Вопрос 4

Подпись `"  Мир   Go\tкурс "` нормализовали записью
`strings.Join(strings.Fields(s), " ")` и получили `"Мир Go курс"`. Можно ли
по результату восстановить исходную подпись?

Варианты ответа:

- A. Да: `strings.Split` по пробелу вернёт части вместе с пробелами.
- B. Нет: пробелы между словами, табуляция и края в результат не попали.
- C. Да, если запомнить, сколько байтов было в исходной подписи.
- D. Нет: `Fields` изменила буквы слов, и их не вернуть.

ни в одну часть `Fields`.

**Правильный ответ: B.**

`Fields` выбрасывает пробельные промежутки целиком. `Join` ставит ровно один
пробел только между соседними частями, а на месте промежутков в начале и в
конце не ставит ничего. Сколько пробелов было и какими символами, в

не меняет. Если строку нужно сохранить байт в байт, берут `Split` по точному
разделителю и `Join` с тем же разделителем.

  повторов.
- D. `Repeat` вернёт `"-"`: знак числа отбрасывается.

Прежде чем смотреть ответ, назовите результат `Repeat` при нуле повторов и
скажите, существует ли строка из минус одной копии. Затем ответьте на второй
вопрос: что сделает `Repeat`, если число повторов неотрицательно, но
произведение `len(s) * count` не помещается в `int` — вернёт укороченную
строку или нет?

**Правильный ответ: C.**

Ноль повторов — законный случай, он даёт пустую строку. Минус одной копии не
бывает, и `Repeat` не подбирает ответ, а останавливает программу паникой.
Вариант A переносит правило для нуля на отрицательные числа. Вариант B ждёт
от компилятора знания значения, которое появится только во время работы:
`width` — обычная переменная `int`. Вариант D придумывает правило, которого у
`Repeat` нет.

Ответ на второй вопрос: укороченной строки не будет. Длина результата —
`len(s) * count` байтов, и если это произведение не помещается в `int`,
`Repeat` тоже вызывает панику. Обрезать результат «чтобы влезло» она не
умеет. Поэтому число повторов, пришедшее извне, входит в условие функции:
от нуля до разумного предела задачи.

## Вопрос 7

```go
@quiz _quiz/07-order
```

Что напечатает программа?

Варианты ответа:

- A. true, true, false и true.
- B. false, false, true и true.
- C. true, false, false и true.
- D. false, true, false и false.

Прежде чем смотреть ответ, для каждого сравнения назовите первое место, где
байты различаются, или скажите, что одна строка — начало другой. Значения
байтов даны в разделе теории «Сравнение строк: равенство и порядок».

**Правильный ответ: A.**

Заглавная `Z` — байт 0x5a, строчная `a` — 0x61, поэтому `"Zebra"` меньше.
В `"100"` и `"25"` решает первый байт: `1` меньше `2`. У «ё» и «я» первый

`"код"` — начало `"кодекс"`, и короткая строка меньше. Вариант B следует
алфавиту и числовым значениям. Вариант C сравнивает `"100"` и `"25"` как
числа. Вариант D не различает регистр и считает, что начало строки не меньше
всей строки.

## Вопрос 8

Строку таблицы `"Анна;;Москва;"` нужно передать программе, которая ждёт
`"Анна,,Москва,"`. Пустые поля терять нельзя. Какие записи дают нужную
строку?

Варианты ответа:

- A. `strings.Replace(s, ";", ",", 1)`.
- B. Только `strings.ReplaceAll(s, ";", ",")`.
- C. Только `strings.Join(strings.Split(s, ";"), ",")`.
- D. Обе записи из вариантов B и C.

Прежде чем смотреть ответ, для записи через `Split` назовите части и их
число, а для `Replace` — сколько замен она сделает.

**Правильный ответ: D.**

`Split` даёт четыре части, из них две пустые, и `Join` через запятую ставит
запятые ровно туда, где стояли точки с запятой. `ReplaceAll` заменяет каждое
вхождение сразу и приходит к той же строке. Вариант A разрешает одну замену,
и две точки с запятой остаются на месте. Варианты B и C отвергают один из
двух верных способов.

## Вопрос 9

Коллега считает слова через `len(strings.Split(s, " "))` и проверяет это на
входе `"кот пёс"`: ответ 2, верно. Какой вход покажет, что этот способ
неверен для подсчёта частей, разделённых пробельными символами?

Варианты ответа:

- A. `"кот"` — одно слово без пробелов.
- B. `"кот  пёс"` — с двумя пробелами подряд.
- C. `"Кот Пёс"` — с заглавными буквами.
- D. Тот же `"кот пёс"`, но проверенный десять раз подряд.

Прежде чем смотреть ответ, для каждого входа посчитайте ответ коллеги и
ответ `len(strings.Fields(s))` и сравните их.

**Правильный ответ: B.**

На двух пробелах подряд `Split` находит пустую часть и отвечает 3, а
`Fields` — 2. Вариант A даёт одну часть при обоих способах. Вариант C меняет
регистр, а граница между словами осталась одним пробелом. Вариант D
повторяет вход, на котором способы совпадают, и ничего нового не узнаёт.
Каждый из трёх других входов тоже различил бы способы сам по себе: пустая
строка, пробел в начале строки, табуляция вместо пробела.
