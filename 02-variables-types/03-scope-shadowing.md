# Область видимости и затенение

Представьте функцию, которая собирает подпись: заводит переменную `result` со
значением по умолчанию, потом во внутренних фигурных скобках кладёт в неё
приветствие с именем и возвращает `result`. Программа собирается, но функция
возвращает значение по умолчанию, будто приветствия не было. Одна строка
внутри скобок записана через `:=` вместо `=`, и из-за этого имя `result` в ней
означает уже другую переменную.

Чтобы находить такие ошибки, нужно уметь по любому месту кода ответить: какое
объявление здесь называет это имя? Участок кода, на котором имя называет
определённое объявление, называют **областью видимости** этого объявления.

К концу урока вы сможете:

- для каждого употребления имени во вложенных блоках назвать объявление, к
  которому оно относится, и его текущее значение;
- объяснить, чем `:=` и `=` во внутреннем блоке различаются, даже когда
  программы печатают одинаковую строку;
- сказать, какие имена видны в правой части объявления и в теле функции с
  параметрами, и починить имя, неизвестное компилятору или объявленное дважды
  в одном блоке;
- объяснить, почему строка импорта действует только в своём файле и почему
  локальная переменная может сломать вызов `fmt.Println` или имя типа `int`;
- найти и починить затенение, которое компилятор пропускает, а результат
  портит.

Понадобятся правила уроков 2.1 и 2.2: `var` и `:=` объявляют переменную, `=`
меняет уже объявленную, а одиночный `:=` с именем, уже объявленным в том же
блоке, не собирается. Все примеры работают со строками.

## Блок — участок между фигурными скобками

**Блок** — это последовательность объявлений и инструкций между парой фигурных
скобок. Тело функции — блок: оно начинается после `{` в строке `func main() {`
и кончается парной `}`. Внутри тела можно открыть ещё один блок — просто
написать `{`, инструкции и `}`. Такой вложенный блок — обычная инструкция
функции.

Не путайте его с объявлением функции. У функции есть слово `func`, имя,
скобки с параметрами, и её тело выполняется только при вызове. У вложенного
блока нет ни имени, ни параметров. Его нельзя вызвать: программа выполняет
его инструкции в тот момент, когда доходит до `{`, один раз и по порядку, а
после `}` продолжает со следующей строки.

Программа ниже объявляет `city` в теле `main`, а `street` — во вложенном
блоке. Прежде чем смотреть вывод, скажите, в каком порядке напечатаются три
строки и видна ли `city` внутри блока.

```go

### Example: `01-plain-block`

Источник: `examples/01-plain-block/`

```go
package main

import "fmt"

func main() {
	city := "Казань"
	fmt.Println("до блока:", city)
	{
		street := "Лесная"
		fmt.Println("в блоке:", city, street)
	}
	fmt.Println("после блока:", city)
}

```
```

Строки идут в порядке записи: блок выполнился на своём месте. Внутри блока
программа прочитала обе переменные. Переменная `city` объявлена снаружи, но
внешнее имя видно и во всех вложенных блоках.

Обратное неверно. Программа ниже пытается прочитать `street` после
закрывающей скобки. Скажите до сообщения, соберётся ли она.

```go
@broken after-block
```

Не соберётся: `undefined: street` — имя `street` не объявлено. Область
видимости локальной переменной кончается там, где кончается самый внутренний
блок, в котором она объявлена. После `}` имени `street` для компилятора нет.

Область видимости — свойство текста программы. Она говорит, в каких строках
имя можно употребить и что оно там означает. Компилятор проверяет её до
запуска. Сколько живёт значение переменной в памяти во время работы программы
— отдельный вопрос, и область видимости на него не отвечает. В этом уроке он не
нужен.

## Какое объявление называет имя

Одно и то же имя может быть объявлено в нескольких вложенных блоках. Тогда
для употребления имени компилятор ищет объявление по правилу изнутри наружу:

1. Сначала самый внутренний блок, в котором стоит употребление. Подходит
   объявление из этого блока, которое закончилось раньше употребления, то есть
   стоит выше него.
2. Если такого нет, следующий блок снаружи, и так до тела функции.
3. Дальше — имена из строк импорта этого файла, имена уровня пакета и имена,
   которые Go объявил заранее, вроде `int` и `string`. Они разобраны в
   разделах про файлы и про имена типов.
4. Если объявления не нашлось нигде, компилятор отвечает `undefined`.

Первое найденное объявление и есть ответ. Если внутренний блок объявил имя,
которое уже объявлено снаружи, внешнее объявление внутри этого блока не
находится: поиск до него не доходит. Про внешнее объявление говорят, что
внутреннее его **затеняет**. Затенение законно: внутренний блок — другой
блок, и правило урока 2.2 о повторном `:=` к нему не относится.

## Затенение или присваивание

Две программы ниже различаются одним знаком внутри блока. В первой там
`name := "Борис"`, во второй — `name = "Борис"`. Обе печатают `name` до
блока, в блоке и после блока.

Прежде чем смотреть вывод первой программы, для каждого из трёх вызовов
`fmt.Println` скажите, какое объявление называет `name` и что напечатается.

```go

### Example: `02-inner-declare`

Источник: `examples/02-inner-declare/`

```go
package main

import "fmt"

func main() {
	name := "Аня"
	fmt.Println("до блока:", name)
	{
		name := "Борис"
		fmt.Println("в блоке:", name)
	}
	fmt.Println("после блока:", name)
}

```
```

Восстановим каждое значение по правилу изнутри наружу:

| Строка кода | Какое объявление называет `name` | Значение |
|---|---|---|
| печать до блока | внешнее, `name := "Аня"` в теле `main` | `"Аня"` |
| `name := "Борис"` | объявляет новую, внутреннюю переменную | `"Борис"` у внутренней |
| печать в блоке | внутреннее: оно в этом блоке и стоит выше | `"Борис"` |
| печать после блока | внешнее: внутреннего после `}` нет | `"Аня"` |

В программе две разные переменные с одним именем. Внутренняя строка создала
вторую переменную и ничего не сделала с первой. Внешняя `name` всё время
хранила `"Аня"`: пока шёл блок, её просто не было видно под этим именем. На
выходе из блока ничего не «восстанавливается» — внешнюю переменную никто не
трогал.

Теперь вторая программа. Прежде чем смотреть вывод, снова назовите объявление
и значение для каждой печати. Особенно для последней.

```go

### Example: `03-inner-assign`

Источник: `examples/03-inner-assign/`

```go
package main

import "fmt"

func main() {
	name := "Аня"
	fmt.Println("до блока:", name)
	{
		name = "Борис"
		fmt.Println("в блоке:", name)
	}
	fmt.Println("после блока:", name)
}

```
```

| Строка кода | Какое объявление называет `name` | Значение |
|---|---|---|
| печать до блока | внешнее, `name := "Аня"` | `"Аня"` |
| `name = "Борис"` | внешнее: `=` ничего не объявляет | внешняя получила `"Борис"` |
| печать в блоке | внешнее: другого объявления нет | `"Борис"` |
| печать после блока | внешнее | `"Борис"` |

Во второй программе переменная одна. Строка `name = "Борис"` — присваивание, а не
объявление, поэтому компилятор ищет для неё уже существующую `name` по тому же
правилу изнутри наружу и находит внешнюю. Её значение и меняется.

Строка, напечатанная внутри блока, в обеих программах одинакова. По ней одной
программы не различить: в первой её печатает внутренняя переменная, во второй
— внешняя. Различие видно только после блока. Поэтому, читая код, смотрите не
на напечатанное значение, а на то, какое объявление называет имя.

## С какого места имя начинает действовать

Область видимости локальной переменной начинается **после конца её
объявления**, а не с начала блока. Это решает два вопроса: что видно в блоке
выше объявления и что видно в правой части самого объявления.

Программа ниже печатает `name` во внутреннем блоке до объявления, потом
объявляет там `name := name + "!"` и печатает снова. Прежде чем смотреть
вывод, скажите, какую переменную называет `name` в правой части этой строки и
что напечатают три вызова.

```go

### Example: `04-rhs-outer`

Источник: `examples/04-rhs-outer/`

```go
package main

import "fmt"

func main() {
	name := "Аня"
	{
		fmt.Println("до объявления:", name)
		name := name + "!"
		fmt.Println("после объявления:", name)
	}
	fmt.Println("после блока:", name)
}

```
```

Первая печать в блоке стоит выше внутреннего объявления, поэтому внутреннее
имя там ещё не действует, и `name` называет внешнюю переменную. В строке
`name := name + "!"` правая часть вычисляется, пока внутреннего имени ещё нет:
объявление не кончилось. Значит, `name` справа — внешняя переменная со
значением `"Аня"`. Результат склейки становится начальным значением новой,
внутренней переменной. Её и печатает вторая печать. После блока снова видна
внешняя переменная, и она не изменилась.

А если внешнего имени нет? Программа ниже — тот же блок без внешнего
объявления. Предскажите ответ компилятора.

```go
@broken rhs-undefined
```

Сообщение `undefined: name` указывает на правую часть. Справа поиск идёт
изнутри наружу, внутреннее имя ещё не действует, а снаружи объявления нет.
Новая переменная не может получить начальное значение из самой себя.
Починка — объявить исходное значение до этой строки, в блоке снаружи, как в
примере выше.

## Повтор имени: тот же блок или вложенный

Правило урока 2.2 о повторном объявлении зависит от границ блоков. Одиночный
`:=` с именем, уже объявленным **в том же блоке**, не собирается. Во **вложенном**
блоке та же строка законна и объявляет новую переменную, как в программе с
`name := "Борис"`.

Блок задают только фигурные скобки. Отступ — лишь оформление. Программа ниже
сдвигает две строки вправо, будто начался новый блок, но скобок не ставит.
Что ответит компилятор?

```go
@broken indent-only
```

Ответ — `no new variables on left side of :=`. Обе строки с `status` стоят в
одном блоке, в теле `main`, и второй `:=` пытается объявить то же имя ещё
раз. Починка зависит от замысла. Нужно новое значение той же переменной —
пишите `status = "готово"`. Нужна отдельная переменная — дайте ей другое имя.
Если же отдельная переменная нужна только на участке кода, её можно
объявить во вложенном блоке в фигурных скобках. Но тогда после `}` снова будет
видна прежняя `status`.

## Параметр функции и вложенный блок

Параметр — переменная, объявленная в заголовке функции. Его область видимости
— всё тело функции, включая вложенные блоки. Для правила о повторном
объявлении параметр считается объявленным в том же блоке, что и переменные
внешнего уровня тела. Поэтому одиночный `:=` с именем параметра на этом
уровне не собирается:

```go
@broken param-redeclare
```

Сообщение то же, что для строк, сдвинутых без скобок:
`no new variables on left side of :=`.

Во вложенном блоке эта строка законна. Программа ниже переносит её в блок
внутри `shout`. Прежде чем смотреть вывод, скажите, что называет `s` в правой
части, в печати внутри блока и в `return s`.

```go

### Example: `05-param-inner`

Источник: `examples/05-param-inner/`

```go
package main

import "fmt"

func shout(s string) string {
	{
		s := s + "!"
		fmt.Println("в блоке:", s)
	}
	return s
}

func main() {
	fmt.Println("результат:", shout("привет"))
}

```
```

В правой части `s` — параметр: внутреннее имя действует только после конца
объявления. Внутренняя `s` получает склейку, и печать в блоке видит её. На
строке `return s` блок уже закрыт, и `s` снова называет параметр, а его никто
не менял. Поэтому функция вернула исходную строку без восклицательного знака.
Если задумано изменить значение, которое вернёт функция, внутри блока нужно
присваивание параметру: `s = s + "!"`. Тогда функция вернёт строку со знаком.

## Файлы пакета и строка импорта

Имена, объявленные вне всех функций, — имена уровня пакета. Они видны во всех
файлах пакета, как вы видели в уроке 1.8. Программа ниже состоит из двух
файлов пакета `main`, и на странице показан только `main.go`. Файл `names.go`
целиком такой: строка `package main`, объявление `var greeting = "привет"` и
функция `func shout(word string) string` с одной инструкцией
`return word + "!"`. Импортов в `names.go` нет.

```go

### Example: `06-two-files`

Источник: `examples/06-two-files/`

```go
// В каталоге два файла пакета main: этот main.go и names.go.
// names.go ничего не импортирует и объявляет вне функций
// переменную greeting и функцию shout.
package main

import "fmt"

func main() {
	fmt.Println("из соседнего файла:", shout(greeting))
}

```
```

`main.go` читает переменную `greeting` и вызывает функцию `shout` из соседнего
файла без импорта и без имени пакета перед точкой. Для имён уровня пакета
граница файла ничего не значит.

У строки импорта правило другое. Имя пакета, которое даёт строка
`import "fmt"`, действует только в том файле, где эта строка записана. В
сломанной программе ниже тоже два файла. `title.go` импортирует `fmt` и
вызывает `fmt.Println` в функции `printTitle` — функции без параметров и без
результата, как `main`. `main.go` строки импорта не содержит, но тоже вызывает
`fmt.Println`. Соберётся ли программа?

```go
@broken import-other-file
```

Не соберётся: `undefined: fmt`. Импорт в `title.go` дал имя `fmt` только
файлу `title.go`. В `main.go` имени `fmt` никто не объявлял. Починка — своя
строка `import "fmt"` в каждом файле, который вызывает `fmt`: здесь — и в
`main.go`, и в `title.go`. Если бы импорт просто перенесли из `title.go` в
`main.go`, отказ `undefined: fmt` перешёл бы в `title.go`: он ведь тоже
вызывает `fmt.Println`.

Другой случай — файл импортирует `fmt`, но сам его не вызывает. Такой файл
получает свой отказ «пакет импортирован, но не используется» — так же, как
неиспользованная локальная переменная в уроке 2.1. Если перенести
импорт из файла, который вызывает `fmt`, в соседний файл, который `fmt` не
вызывает, отказов станет два: первый файл не найдёт `fmt`, а второй получит
отказ о неиспользованном импорте.

Получается четыре уровня, на которых ищется имя, от внешнего к внутреннему:

- имена, которые Go объявил заранее: `int`, `string`, `bool`, `float64`,
  `true`, `false` и другие; они видны везде;
- имена уровня пакета: видны во всех файлах пакета;
- имена из строк импорта: видны только в своём файле;
- локальные имена: видны от конца объявления до конца своего блока.

Поиск по правилу изнутри наружу проходит эти уровни от последнего к первому.

## Локальное имя поверх имени пакета или типа

Имя из строки импорта и заранее объявленное имя ищутся тем же правилом, что и
переменные. Значит, их тоже может затенить локальная переменная.

Программа ниже сначала вызывает `fmt.Println`, потом объявляет локальную
переменную `fmt` и снова пишет `fmt.Println`. Первый вызов в порядке. Что
случится со вторым?

```go
@broken fmt-shadow
```

Компилятор отвечает:
`fmt.Println undefined (type string has no field or method Println)`.
Прочитайте сообщение по частям. Во втором вызове `fmt` называет локальную
переменную типа `string`: её объявление ближе, чем имя из импорта. Слова
`has no field or method Println` значат, что у строки нет ничего с именем
`Println`. Пакет `fmt` никуда не делся, и строка импорта на месте. Первый
вызов, выше объявления, работает. Если бы такую переменную объявили во
вложенном блоке, вызов после закрывающей скобки этого блока снова работал
бы. Починка — переименовать переменную, например в `mode`, чтобы имя `fmt`
снова называло пакет.

Так же ведёт себя заранее объявленное имя типа. В программе ниже локальная
переменная названа `int`. Потом в том же блоке объявляется переменная типа
`int`. Прочитайте код и предскажите сообщение.

```go
@broken int-shadow
```

Сообщение: `int (local variable) is not a type` — `int` здесь локальная
переменная, а не тип. Строка `int := "целое"` и печать сами по себе законны:
`int` — не ключевое слово языка, а заранее объявленное имя, и его, как любое
имя, можно объявить заново во внутренней области. Но после этого до конца
блока имени целого типа под рукой нет. Законно, но вредно. Починка — другое
имя переменной, например `kind`.

Ключевые слова устроены иначе. `func`, `var`, `package`, `import`, `return` и
остальные ключевые слова вообще нельзя использовать как имена. Попытка
ломается раньше всякого поиска объявлений — при разборе текста:

```go
@broken keyword-name
```

Сообщение `syntax error: unexpected keyword func, expected name` говорит, что
после `var` ожидалось имя, а стоит ключевое слово. Отличайте два случая:
переменная с именем `int` собирается и мешает дальше, а переменная с именем
`func` не собирается никогда.

## Когда законное затенение — ошибка в программе

Вернёмся к функции из начала урока. Функция `label` заводит `result` со
значением `"гость"` и в блоке собирает приветствие с именем. Прежде чем
смотреть вывод, скажите, что напечатает строка внутри блока и что вернёт
функция.

```go

### Example: `07-lost-update`

Источник: `examples/07-lost-update/`

```go
package main

import "fmt"

func label(name string) string {
	result := "гость"
	{
		result := "друг " + name
		fmt.Println("внутри:", result)
	}
	return result
}

func main() {
	fmt.Println("результат:", label("Аня"))
}

```
```

Внутри блока `result := "друг " + name` объявил новую переменную и затенил
внешнюю. Печать в блоке показала внутреннюю. После `}` имя `result` снова
называет внешнюю, а её никто не менял. `return` отдал значение по умолчанию.
Компилятор программу принимает. Команда `go vet` в обычном запуске тоже
ничего не сообщает: проверки затенения в её стандартном наборе нет.

Замысел был обновить внешнюю переменную, значит, нужно присваивание. Ремонт —
заменить во внутренней строке `:=` на `=`:

```go

### Example: `08-update-fixed`

Источник: `examples/08-update-fixed/`

```go
package main

import "fmt"

func label(name string) string {
	result := "гость"
	{
		result = "друг " + name
		fmt.Println("внутри:", result)
	}
	return result
}

func main() {
	fmt.Println("результат:", label("Аня"))
}

```
```

Теперь строка в блоке не объявляет новую переменную, а меняет ту, которую
вернёт `return`. Печать в блоке совпадает с первой программой, а результат
функции — нет. Переименовать внутреннюю переменную недостаточно: ошибка не в
совпадении имён, а в том, что изменение не попадает в переменную, которую
возвращает функция.

С повторяющимися именами бывают три разных случая, и действовать в них нужно
по-разному:

- **ошибка компилятора** — повторный одиночный `:=` в одном блоке, имя без
  объявления, переменная `int` на месте имени типа. Программа не собирается,
  и сообщение называет место;
- **законная программа с неверным результатом** — как `label`. Сборка
  проходит, ошибку показывает только результат. Её ищут трассировкой: какое
  объявление называет имя в каждой строке;
- **вопрос именования** — затенение законно и результат верен, как в
  `shout` с внутренней `s`, если так и задумано. Читателю приходится держать в
  голове две переменные с одним именем, и отдельное имя обычно понятнее. Но
  это выбор стиля, а не правило языка: затенение не запрещено.

## Чего этот урок не разбирает

Правила выше описывают простые блоки из фигурных скобок, тело функции и
параметры, файлы пакета и строку импорта. Есть места, где имена
объявляются по особым правилам, и знание простых блоков их не заменяет:

- короткое объявление в заголовке `if` и его область видимости — урок 3.2;
- переменные циклов — уроки 3.5 и 3.7;
- строки с несколькими именами слева от `:=` — урок 3.6;
- переменные, которые использует функция, объявленная внутри другой функции,
  — уроки 5.5–5.7.

# Упражнение: почтовые надписи

## Что сдать

Заготовка — пакет `post`: файл `go.mod` и два файла с кодом, `envelope.go` и
`mark.go`. В каждом файле уже написана экспортируемая функция:

- `func Envelope(name string, city string) string` — в файле `envelope.go`;
- `func Mark(address string) string` — в файле `mark.go`.

В отличие от прошлых упражнений, тела функций не пустые. Каждая функция
собирает строку по шагам во вложенном блоке и собирается без ошибок. Но
возвращает она не то, что обещает её описание ниже. Причина в обеих функциях
связана с тем, какую переменную называет имя в каждой строке.

Найдите причину и исправьте каждую функцию так, чтобы она возвращала строку из
раздела её задачи. Прежде чем править, для каждой строки тела назовите
объявление, которое там называет имя переменной, и значение, которое вернёт
`return`.

Не меняйте `go.mod`, строку `package post`, имена функций, типы параметров и
типы результатов: скрытые тесты вызывают функции именно в таком виде.
Функции только возвращают строки; печатать ничего не нужно. Импорты не нужны.
Вложенный блок можно оставить или убрать, а тело можно переписать короче —
важен возвращённый результат.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые строки с
ожидаемыми:

- `TestEnvelope` — `Envelope` на двух разных парах имени и города;
- `TestMark` — `Mark` на обычном адресе и на пустой строке.

Тест получает только то, что функция вернула. Текста решения он не видит:
остался ли блок, стоит ли там `=` или тело переписано одной строкой, проверка
не различает. Понимание того, какое объявление называет имя, проверяют
вопросы урока и разбор после попытки.

Ответ проверки бывает двух видов. Если код не собрался, тесты не
запускаются, и проверка показывает сообщение сборки с местом в файле —
например, `no new variables on left side of :=` или `undefined`. Если код
собрался, но функция вернула не ту строку, проверка печатает строку `--- FAIL:`
с именем теста и сообщение: какие аргументы переданы, что функция вернула и
что должна была вернуть. Строки в сообщении показаны в кавычках. С
заготовкой вы увидите именно такие сообщения: код собирается, а результат
неверный.

## Envelope

`Envelope` возвращает надпись на конверте: слово `кому`, двоеточие и пробел,
затем значение `name`, затем запятая и пробел, затем значение `city`.

- `Envelope("Анна", "Казань")` возвращает `кому: Анна, Казань`;
- `Envelope("Пётр", "Омск")` возвращает `кому: Пётр, Омск`.

## Mark

`Mark` возвращает переданный адрес с пометкой в начале и знаком в конце:
слово `СРОЧНО`, двоеточие и пробел, затем значение параметра `address` без
изменений, затем восклицательный знак.

- `Mark("Казань, Лесная 5")` возвращает `СРОЧНО: Казань, Лесная 5!`;
- `Mark("")` возвращает `СРОЧНО: !` — пометку с пробелом и сразу знак.

Пустая строка — обычный аргумент: пометка и знак обязаны появиться и для неё.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Почему заготовка возвращает не то

<!-- review:inner-short-declaration -->

В заготовке `Envelope` сначала объявляет `text := "кому: "`, а в блоке пишет
`text := text + name`. Справа `text` ещё называет внешнюю переменную: внутреннее
имя действует только после конца объявления. Поэтому внутренняя переменная
получает `"кому: "` с именем, а следующая строка дописывает к ней город. Всё
это время внешняя `text` хранит только `"кому: "`. После `}` имя `text` снова
называет внешнюю, и `return` отдаёт её. Сборка проходит, потому что внутренняя
переменная прочитана в правой части следующей строки, а затенение законно.

В `Mark` то же самое с параметром. `address := "СРОЧНО: " + address` в блоке
объявляет новую переменную и затеняет параметр. Пометка и знак попадают в
неё, а `return address` после блока возвращает параметр без изменений.

Ловят это `TestEnvelope` и `TestMark`: код собирается, а функции возвращают
только `"кому: "` и исходный адрес.

Чинить надо задуманную операцию. Задумано обновить внешнюю переменную или
параметр, значит, в первой строке блока нужен знак `=`:
`text = text + name` и `address = "СРОЧНО: " + address`. Тогда все строки блока
меняют ту переменную, которую возвращает `return`. Годятся и другие законные
ремонты с тем же результатом: убрать блок и оставить присваивания, или сразу
вернуть готовое выражение, например `return "кому: " + name + ", " + city`.
Не каждый ремонт соберётся. Например, если убрать блок, но оставить
`text := text + name`, на внешнем уровне тела окажутся два объявления `text`
в одном блоке, и сборка ответит `no new variables on left side of :=`; то же
будет с `address := …` рядом с параметром `address`. Другой отказ — вернуть
после блока переменную, объявленную внутри него: её имя там уже не действует.

## Внутреннюю переменную переименовали

<!-- review:envelope-renamed-inner -->

Естественная попытка: раз проблема в двух переменных с одним именем, дать
внутренней другое имя — `full := text + name`, затем
`full = full + ", " + city` — и оставить `return text`. Сборка проходит, но
`Envelope` по-прежнему возвращает только `"кому: "`.

Ловит это `TestEnvelope` на первом же входе: имени и города в результате нет.

Переименование убрало затенение, но не причину. Склейки по-прежнему попадают в
отдельную переменную, а `return` отдаёт внешнюю `text`, которую никто не менял.
Ошибка не в совпадении имён, а в том, что изменения идут не в ту переменную,
которую возвращает функция. Верное решение направляет изменения в
возвращаемую переменную: `text = text + name`. Можно было бы вернуть ту
переменную, в которую легла надпись. Но `full` объявлена в
блоке, и после `}` её имени нет, поэтому `return full` после блока не
соберётся: `undefined: full`.

## Параметр переименовали

<!-- review:mark-renamed-parameter -->

Та же мысль в `Mark`: переименовать параметр в `addr`, в блоке оставить
`address := "СРОЧНО: " + addr` и `address = address + "!"`, а вернуть `addr`.
Сборка проходит, но функция возвращает адрес без пометки и без знака.

Ловит это `TestMark`: на обычном адресе нет пометки, а на пустой строке
функция возвращает пустую строку вместо пометки со знаком.

Имена больше не совпадают, но пометка по-прежнему попадает во внутреннюю
переменную, имя которой после `}` уже не действует. Функция возвращает
параметр, а в него ничего не присваивали. Верное решение меняет сам
параметр через `=` и возвращает его, как в разборе заготовки выше.

Употребление 1 стоит выше внутреннего объявления, и поиск уходит наружу.
Употребление 2 находит внутреннее объявление. После `}` внутреннего имени нет.
Вариант B забывает, что имя действует только после конца объявления.
Вариант C считает `:=` присваиванием. Вариант D применяет правило одного блока
к двум разным блокам.

## Вопрос 2

Та же программа, но внутри блока стоит `=`.

```go
@quiz _quiz/02-trace-assign
```

Что напечатается и почему вторая строка совпадает с вопросом 1, а третья — нет?

Варианты ответа:

- A. Как в вопросе 1: `=` во внутреннем блоке меняет только его копию `city`.
- B. `"Казань"`, `"Омск"`, `"Омск"`: `=` ничего не объявляет и меняет внешнюю
  `city`, а во всех трёх местах имя называет её.
- C. `"Казань"`, `"Омск"`, `"Омск"`: `=` объявил внутреннюю `city`, а на
  выходе из блока её значение скопировалось во внешнюю.
- D. Не соберётся: во внутреннем блоке `city` не объявлена.

Прежде чем смотреть ответ, скажите, сколько переменных `city` в этой
программе и в программе вопроса 1.

**Правильный ответ: B.**

В этой программе переменная одна, и все три употребления называют её.
Вторая строка совпала с вопросом 1 случайно: там её печатала внутренняя
переменная.
Вариант A выдумывает «копию» в блоке. Вариант C прав в выводе, но не в
причине: `=` не объявляет и ничего не копирует. Вариант D забывает, что
внешнее имя видно во вложенном блоке.

## Вопрос 3

Программа должна напечатать приветствие «привет» с дописанным «, мир», но не
собирается: компилятор сообщает, что имя `message` не объявлено.

```go
@quiz _broken/q-rhs-repair
```

Какой ремонт сохраняет замысел?

Варианты ответа:

- A. Перед блоком, в теле `main`, добавить `message := "привет"`.
- B. В строке внутри блока заменить `:=` на `=`.
- C. Внутри блока, прямо перед этой строкой, добавить `message := "привет"`.
- D. После блока добавить `message := "привет"`.

Прежде чем смотреть ответ, скажите, какие имена видны в правой части
`message := message + ", мир"` и почему.

**Правильный ответ: A.**

Справа внутреннее имя ещё не действует, поэтому нужна переменная, видимая
снаружи. После ремонта A правая часть находит внешнюю `message`, а новая
внутренняя получает склейку. Вариант B оставляет имя без объявления. Вариант C
даёт два `:=` одного имени в одном блоке — `no new variables`. Вариант D
объявляет имя ниже: выше объявления оно не действует.

## Вопрос 4

Функция `tag` должна вернуть слово с `#` в начале.

```go
@quiz _broken/q-param-tag
```

Какой ремонт сохраняет задачу функции?

Варианты ответа:

- A. Заменить `word := "#" + word` на `word = "#" + word`.
- B. Взять строку `word := "#" + word` в фигурные скобки.
- C. Заменить её на `var word = "#" + word`.
- D. Переименовать параметр в `w`, а строку `word := "#" + word` оставить.

Прежде чем смотреть ответ, скажите, какое объявление называет `word` справа
после каждой правки.

**Правильный ответ: A.**

Параметр считается объявленным на внешнем уровне тела, поэтому одиночный `:=`
там — повторное объявление, а присваивание меняет сам параметр. Вариант B
объявляет внутреннюю переменную, которую никто не читает, — сборка ответит
`declared and not used`; `return` всё равно вернул бы параметр. Вариант C —
то же повторное объявление. В варианте D имени `word` справа уже нет: `undefined`.

## Вопрос 5

Автор перенёс строку `import "fmt"` из `main.go` в соседний файл `names.go`
того же пакета. `names.go` объявляет только переменную `greeting` и `fmt` не
вызывает.

```go
@quiz _broken/q-moved-import
```

Что скажет компилятор?

Варианты ответа:

- A. Ничего: пакет один, импорт в любом его файле действует во всех.
- B. В `main.go` имя `fmt` не объявлено, а в `names.go` импорт не
  используется; импорт надо вернуть в файл, который вызывает `fmt`.
- C. Отказ только в `names.go`; `main.go` видит `fmt`, как видит `greeting`.
- D. Отказ только в `main.go`: `names.go` вправе держать импорт про запас.

Прежде чем смотреть ответ, объясните, чем имя `greeting` отличается от имени
`fmt` по тому, где оно видно.

**Правильный ответ: B.**

`greeting` объявлена на уровне пакета и видна во всех его файлах. Имя из строки
импорта видно только в своём файле, поэтому `main.go` получает `undefined: fmt`.
`names.go` импортирует пакет и не пользуется им — это тоже отказ сборки.
Варианты A и C путают уровень пакета с уровнем файла. Вариант D забывает, что
неиспользованный импорт не собирается.

## Вопрос 6

Первая печать работает, а вторая, внутри блока, — нет.

```go
@quiz _broken/q-fmt-block
```

Почему, и как починить?

Варианты ответа:

- A. После `fmt := …` импорт перестал действовать; внутри блока нужна своя
  строка `import "fmt"`.
- B. В блоке `fmt` называет локальную строку, у которой нет `Println`;
  переименовать переменную, например в `mode`.
- C. Во вложенном блоке нельзя вызывать функции пакетов; вынести печать
  после блока.
- D. Заменить `fmt := "краткий"` на `var fmt = "краткий"`.

Прежде чем смотреть ответ, для обоих `fmt.Println` скажите, какое объявление
называет `fmt`.

**Правильный ответ: B.**

В первой печати поиск доходит до строки импорта. Во второй он раньше находит
локальную переменную в блоке. Пакет и импорт на месте, иначе первая печать
тоже не собралась бы. Вариант A считает, что затенение удаляет импорт. Вариант C
выдумывает запрет: внешние имена видны во вложенных блоках. Вариант D
объявляет ту же переменную `fmt` другой записью.

## Вопрос 7

Программа не собирается: компилятор сообщает, что имя `string` здесь —
локальная переменная, а не тип.

```go
@quiz _broken/q-string-type
```

Какое утверждение верно?

Варианты ответа:

- A. `string` — ключевое слово, и объявлять переменную с таким именем нельзя
  нигде; ошибка в первой строке.
- B. `string` — заранее объявленное имя, переменная затенила тип; её надо
  переименовать. Имя `var` не собралось бы вовсе: это ключевое слово.
- C. Затенить можно любое имя, и ключевое слово `var` тоже, если объявить
  его во вложенном блоке.
- D. Ошибка в строке `fmt.Println(string)`: переменную с именем типа нельзя
  печатать; достаточно удалить эту печать.

Прежде чем смотреть ответ, объясните, почему строка `string := "Анна"` сама
по себе законна, а строка `var title string` ниже — нет.

**Правильный ответ: B.**

Имя типа `string` объявлено заранее, на самом внешнем уровне, и локальная
переменная затеняет его, как любое имя. Сломана строка, которой нужен тип;
переименование, например в `name`, возвращает его. Вариант A путает заранее
объявленное имя с ключевым словом. Вариант C неверен: ключевое слово не бывает
именем ни в каком блоке. Вариант D ищет ошибку не в той строке: печать
законна, а тип останется затенённым.

## Вопрос 8

Функция `caption` должна вернуть город с подписью.

```go
@quiz _quiz/03-caption
```

Что напечатает программа, к какому виду относится проблема и как её
починить?

Варианты ответа:

- A. В блоке — подпись с городом, результат — только `"город"`; программа
  законна, но результат неверен; внутри блока заменить `:=` на `=`.
- B. Не соберётся: `text` объявлена дважды в одной функции.
- C. Оба раза подпись с городом: внутренний `:=` обновил внешнюю `text`.
- D. В блоке — подпись с городом, результат — только `"город"`; программа
  законна, но результат неверен; переименовать внутреннюю переменную в
  `full`.

Прежде чем смотреть ответ, назовите объявление для `text` справа во
внутренней строке, в печати и в `return text` и объясните, почему `return`
не видит подпись.

**Правильный ответ: A.**

Внутренний `:=` объявил новую `text`, а `return` после блока называет внешнюю,
которую никто не менял. С `=` склейка ляжет во внешнюю переменную. Вариант D
не чинит причину: после переименования `return text` по-прежнему возвращает
внешнюю. Вариант B забывает, что блоки разные. Вариант C считает `:=`
присваиванием.

## Вопрос 9

Какой вывод из правил этого урока верен?

Варианты ответа:

- A. На `}` значение внутренней переменной удаляется из памяти: область
  видимости и есть время жизни значения.
- B. Затенение — ошибка языка, и `go vet` в обычном запуске сообщает о
  каждом таком случае.
- C. Урок описал видимость имён в простых блоках, параметрах и файлах;
  заголовок `if`, переменные циклов и функции внутри функций подчиняются
  своим правилам.
- D. Переменная из заголовка `if` или цикла подчиняется ровно правилам
  простого блока, так что отдельно их изучать не нужно.

Прежде чем смотреть ответ, объясните, на какой вопрос отвечает область
видимости: «где имя можно употребить» или «сколько живёт значение».

**Правильный ответ: C.**

Область видимости — свойство текста: где имя называет объявление. Вариант A
смешивает её со временем жизни значения, а о нём область видимости ничего
не говорит.
Вариант B неверен дважды: затенение законно, а проверки затенения в
стандартном наборе `go vet` нет. Вариант D переносит правило простых блоков на
конструкции, которые разбираются отдельно.
