# Короткое объявление :=

В уроке 2.1 вы объявляли переменные словом `var`. Внутри функций у Go есть
для этого запись короче — `:=`. Представьте функцию, которая собирает надпись
для посылки: заводит локальную переменную с началом надписи, дописывает к ней
имя получателя и возвращает результат. Через `var` первая строка такой функции
выглядит как `var label = "кому: "`, а короткой записью — `label := "кому: "`.
Обе строки делают одно и то же. Короткую запись вы будете видеть в коде на Go
постоянно, поэтому стоит точно знать, что она делает и где на ней ошибаются.

Ошибаются обычно в одном месте: принимают `:=` за «присваивание покороче» и
пишут `count := …`, чтобы обновить переменную `count`, уже объявленную в этом же
блоке кода. Компилятор такую строку не пропускает; причину разбирает раздел
«Объявить или обновить».

К концу урока вы сможете:

- переписать объявление `var` с начальным значением через `:=` и назвать тип и
  значение переменной;
- объяснить, почему у объявления без значения, например `var total float64`,
  нет такой же короткой формы;
- сказать, где `:=` разрешён, а где нет, в том числе когда имя — параметр
  функции;
- выбрать между `var`, `:=` и `=` и объяснить выбор;
- по сообщению компилятора понять, какую операцию он не принял, и починить
  строку так, чтобы сохранились её результат и тип.

Примеры печатают через `fmt.Println` и `fmt.Printf` с глаголами `%v`, `%q` и
`%T` из урока 2.1: `%T` печатает имя типа своего аргумента. Код примеров на
странице урока можно изменить и запустить снова. Такой запуск ни на что не
влияет: изменённый пример ничем не проверяется.

## Объявление, а не присваивание

Запись `name := выражение` делает две вещи сразу: объявляет новую локальную
переменную `name` и кладёт в неё значение выражения справа. Тип новой переменной
берётся из того же выражения — по правилам урока 2.1. Поэтому `:=` читается как
«объявить и задать начальное значение», а не как «присвоить».

Главное слово здесь — «объявить». Знак `=` из урока 2.1 меняет значение
переменной, которая уже есть. Знак `:=` заводит новую переменную. Записи похожи
на вид, но выполняют разные операции, и это различие понадобится во всех
следующих разделах.

Внутри функции короткая запись равносильна объявлению `var` с начальным
значением и без имени типа. Строки `var count = 3` и `count := 3` обе объявляют
переменную `count` типа `int` со значением 3. Строки `var title = "Go"` и
`title := "Go"` обе объявляют переменную типа `string`.

Программа ниже объявляет четыре пары переменных. В каждой паре одно и то же
значение записано дважды: слева через `var`, справа через `:=`. Затем для каждой
пары печатается значение и имя типа обеих переменных. Прежде чем смотреть
вывод, назовите тип каждой пары и скажите, будет ли хоть одна пара различаться.

```go

### Example: `01-same-meaning`

Источник: `examples/01-same-meaning/`

```go
package main

import "fmt"

func main() {
	var titleA = "Go"
	titleB := "Go"

	var countA = 3
	countB := 3

	var ratioA = 2.5
	ratioB := 2.5

	var readyA = true
	readyB := true

	// Слева от черты — переменная из var, справа — из :=.
	fmt.Printf("строка: %v %T | %v %T\n", titleA, titleA, titleB, titleB)
	fmt.Printf("целое: %v %T | %v %T\n", countA, countA, countB, countB)
	fmt.Printf("дробное: %v %T | %v %T\n", ratioA, ratioA, ratioB, ratioB)
	fmt.Printf("логическое: %v %T | %v %T\n", readyA, readyA, readyB, readyB)
}

```
```

Все четыре пары совпали и по значению, и по типу. Тип выбран по тому же правилу
урока 2.1: целый литерал даёт `int`, литерал с точкой — `float64`, строка в
кавычках — `string`, `true` — `bool`. Короткая запись не изобретает своих
правил выбора типа, она лишь не требует писать слово `var`.

## Короче — не значит подвижнее

Раз в короткой записи нет ни слова `var`, ни имени типа, легко решить, что
переменная получилась «попроще» — например, что её тип можно потом поменять.
Это не так. Тип выбирается один раз, в момент объявления, ровно как у
`var count = 3`. Пропущено только его написание в исходном коде, а не сам
выбор.

Программа ниже объявляет `count := 3`, а потом пытается положить в `count`
строку. Прежде чем читать дальше, скажите, соберётся ли она и почему.

```go
@broken keeps-type
```

Не соберётся. Компилятор отвечает так:

`cannot use "42" (untyped string constant) as int value in assignment`

Слова `untyped string constant` означают здесь строковый литерал, у которого
конкретный тип ещё не выбран, — так компилятор называет `"42"`. Остальное
сообщение говорит, что такое значение не годится на роль значения типа `int` в
присваивании. Такой же отказ вы видели в уроке 2.1 у переменной, объявленной
через `var`: у `count` постоянный тип `int`, и объявившая её короткая запись
ничего в этом не меняет.

## Без значения короткой записи нет

У `var` есть форма без начального значения: `var total float64`. Переменная
получает нулевое значение своего типа. У `:=` такой формы нет. Справа от `:=`
обязательно стоит выражение, потому что именно оно даёт переменной и тип, и
значение. Без выражения типу неоткуда взяться.

Программа ниже обрывает короткую запись на полуслове: после `total :=` сразу
идёт закрывающая скобка функции.

```go
@broken no-initializer
```

Компилятор разбирает запись слева направо, после `:=` ждёт выражение, а видит
закрывающую фигурную скобку: `syntax error: unexpected }, expected expression`.
Точный текст этой ошибки зависит от того, что стоит следом за `:=`, поэтому
запоминать его не нужно. Полезно другое: ошибка про синтаксис, и причина — в
пропущенной правой части.

Короткой записи с нулевым значением это не запрещает: значение можно написать
руками. `count := 0` объявляет переменную типа `int` со значением ноль,
`title := ""` — переменную типа `string` с пустой строкой. Но тип здесь снова
берётся из записи значения, и вот где это важно. Допустим, в функции нужна сумма
типа `float64`, которая начинается с пяти. Запись `total := 5` даст `int`,
потому что целый литерал без точки даёт `int`. Нужный тип задаёт объявление
`var` с именем типа.

Программа ниже объявляет `var total float64 = 5` и рядом `count := 5`. Прежде чем
смотреть вывод, назовите тип и напечатанное значение каждой переменной.

```go

### Example: `03-typed-literal`

Источник: `examples/03-typed-literal/`

```go
package main

import "fmt"

func main() {
	var total float64 = 5
	count := 5

	fmt.Printf("total: %v %T\n", total, total)
	fmt.Printf("count: %v %T\n", count, count)
}

```
```

Значения напечатались одинаково, а типы разные. У `total` тип написан рукой, и
целый литерал 5 встал в переменную `float64` — так было и в уроке 2.1 у
`var ratio float64 = 2`. У `count` тип выбран по записи значения.

Совет «нужен другой тип — объявляйте переменную с именем типа» касается
литерала справа. Если справа стоит выражение, у которого тип уже есть,
например другая переменная, `:=` возьмёт ровно этот тип, как третья форма
`var` в уроке 2.1. Есть и способ получить из литерала нужный тип
явным преобразованием, так что «нужный тип требует `var`» — не общее правило
языка. Преобразования разбирает урок 2.9. В этом уроке достаточно простого
правила выбора: хотите литерал другого типа, чем выбирается по его записи, —
напишите `var` с именем типа.

Когда начальное значение неважно и переменную заполнят позже, запись
`var total float64` выражает это точнее, чем `total := 0.0` или
`var total float64 = 0`. Все три строки дают один тип и одно значение, но только
первая прямо говорит читателю: начинаем с нулевого значения, настоящее придёт
потом.

## Только внутри функции

Короткую запись можно поставить только внутри тела функции. Программа ниже
пробует объявить через `:=` переменную уровня пакета — вне всех функций. Прежде
чем читать дальше, скажите, что ответит компилятор: сообщит о лишнем
объявлении, о неиспользованной переменной или о чём-то третьем?

```go
@broken package-level
```

Ни о первом, ни о втором. Компилятор сообщает о синтаксической ошибке:
`syntax error: non-declaration statement outside function body`. По-русски:
инструкция, которая не является объявлением, стоит вне тела функции.

Причина в том, из чего по грамматике Go состоит файл. Сначала строка
`package`, потом строки `import`, а дальше на уровне пакета могут стоять только
объявления: объявления со словом `var`, объявления функций и ещё два вида
объявлений — `const` и `type`, до которых вы дойдёте позже. Всё прочее —
присваивание, вызов функции, короткое объявление — это **инструкции**, то есть
действия, которые программа выполняет по порядку. Инструкции живут внутри тела
функции. Короткое объявление грамматика относит к инструкциям. Поэтому, когда
компилятор разбирает текст файла и встречает `:=` на уровне пакета, он не
находит такой записи среди допустимых там объявлений и останавливается ещё на
разборе текста, до проверки типов.

Это правило записи языка, а не следствие того, как программа работает или
оптимизируется. Чинится оно так: переменная уровня пакета объявляется словом
`var` — в этой программе `var limit = 3`. Если же переменная нужна только одной
функции, её объявление переносят в тело этой функции, и там `:=` законен.

## Объявить или обновить

Переменная объявляется один раз, а обновляется сколько угодно раз. Программа
ниже объявляет `title` короткой записью, а потом дописывает к ней кусок
обычным присваиванием. Прежде чем смотреть вывод, назовите значение и тип
`title` после каждого из двух шагов.

```go

### Example: `02-declare-then-update`

Источник: `examples/02-declare-then-update/`

```go
package main

import "fmt"

func main() {
	title := "Go"
	fmt.Printf("после объявления: %q %T\n", title, title)

	title = title + " и тесты"
	fmt.Printf("после присваивания: %q %T\n", title, title)
}

```
```

Первая строка вывода показывает то, что положила короткая запись. Вторая — то,
что положило присваивание: правая часть `title + " и тесты"` сначала прочитала
текущее значение, а потом собранная строка легла обратно в ту же переменную. Тип
на обоих шагах один и тот же. Переменная осталась одна, изменилось только её
значение.

Теперь то же самое, но вторая строка тоже написана через `:=`. Прежде чем
читать дальше, скажите, что сделает вторая строка: соберётся ли программа, и
если да, то что она напечатает?

```go
@broken same-block
```

Программа не собирается: `no new variables on left side of :=`. Дословно: слева
от `:=` нет ни одной новой переменной. Вторая строка — это попытка объявить
`count` ещё раз в том же блоке, где `count` уже объявлена. Повторный `:=` не
«перезапускает» переменную и не заводит её заново с другим типом: компилятор
просто отвергает строку. Если задумано обновить значение, нужен знак `=`:
`count = 2`.

**Блок** здесь — это тело функции между фигурными скобками. Пока у вас был
только один такой блок, тело функции. Что происходит во вложенных блоках,
показывает раздел «Внутренний блок: заглядываем в урок 2.3».

## Параметр — уже объявленное имя

Параметр функции — тоже переменная, и объявлен он в заголовке функции. Хотя
параметр записан вне фигурных скобок, для правила о повторном объявлении он
считается объявленным в том же блоке, что и переменные, объявленные на внешнем
уровне тела функции. Значит, на этом внешнем уровне имя параметра уже занято.
Вложенные блоки — другой случай; его показывает раздел «Внутренний блок».

Программа ниже пытается дописать приветствие к параметру `name` короткой
записью. Прежде чем читать дальше, скажите, чем это кончится.

```go
@broken parameter-redeclare
```

Тот же отказ, что в предыдущем разделе: `no new variables on left side of :=`.
Для компилятора `name := …` в теле этой функции — повторное объявление имени,
которое уже объявил параметр. Слева опять нет ни одной новой переменной.

Если задумано изменить значение параметра, нужен знак `=`. Программа ниже так и
делает: функция `greet` присваивает параметру приветствие и возвращает его. В
`main` строка `guest` печатается до вызова, затем печатается результат вызова,
затем снова `guest`. Прежде чем смотреть вывод, предскажите все три строки — и
особенно третью.

```go

### Example: `04-parameter-update`

Источник: `examples/04-parameter-update/`

```go
package main

import "fmt"

func greet(name string) string {
	name = "привет, " + name
	return name
}

func main() {
	guest := "Анна"
	fmt.Println(guest)
	fmt.Println(greet(guest))
	fmt.Println(guest)
}

```
```

Внутри `greet` присваивание изменило параметр, и функция вернула изменённое
значение. А переменная `guest` в `main` после вызова осталась прежней. Функция
получает копию значения аргумента: параметр `name` — отдельная переменная
функции `greet`, и присваивание меняет только эту копию. Вызывающий код видит
результат функции только через `return`, как в уроке 1.7.

Второй законный путь — завести для результата новую локальную переменную с
другим именем, например `greeting := "привет, " + name`, и вернуть её. Незаконен
только одиночный `:=` с именем самого параметра на внешнем уровне тела функции.

## Внутренний блок: заглядываем в урок 2.3

Правило о совпадающих именах в разных блоках полностью, с разбором по шагам,
разбирает урок 2.3. Ниже — только первое знакомство с ним на одном примере.

Внутри тела функции можно открыть ещё один блок — просто пару фигурных скобок
`{ … }` с инструкциями внутри. Такой **блок** — законная инструкция Go.
Имя, объявленное внутри него, действует после объявления и до закрывающей
скобки этого блока: только на этом участке кода оно называет внутреннюю
переменную.

Правило «слева от `:=` должна быть новая переменная» касается одного блока. Во
внутреннем блоке строка `level := 2` объявляет новую переменную, даже если
снаружи уже есть `level`. Программа ниже так и делает. Прежде чем смотреть
вывод, скажите, что напечатает строка внутри блока и что — строка после него.

```go

### Example: `05-inner-block`

Источник: `examples/05-inner-block/`

```go
package main

import "fmt"

func main() {
	level := 1
	{
		level := 2
		fmt.Println("внутри блока:", level)
	}
	fmt.Println("после блока:", level)
}

```
```

Внутри блока напечаталось значение новой, внутренней переменной `level`. До
строки `level := 2` имя `level` называет внешнюю переменную. После этой строки и
до закрывающей скобки оно называет внутреннюю, а внешняя переменная с тем же
именем скрыта. После скобки объявление внутренней переменной больше не
действует, и имя снова называет внешнюю. Внешняя переменная всё это время
хранила своё значение: строка внутри блока её не меняла, потому что это было
объявление, а не присваивание.

Из этого примера следуют два практических вывода. Во-первых, такая программа
собирается без единого замечания, хотя человек, писавший её, мог хотеть
обновить внешнюю переменную. Во-вторых, знак `=` на том же месте ничего не
объявляет, поэтому ищет уже существующую переменную — ту, что снаружи, — и
меняет именно её. А если внутреннюю переменную из `:=` ни разу не прочитать,
сборка остановится на знакомом по уроку 2.1 отказе `declared and not used`.

Правило этого урока и правило вложенных блоков говорят о разных случаях.
Одиночный `name := …` с именем, уже объявленным **в этом же блоке**, не
собирается; на внешнем уровне тела функции это относится и к имени параметра.
С именем из **внешнего** блока — в том числе с именем параметра внутри
вложенного блока — он собирается и объявляет новую переменную, которая скрывает
внешнюю. Ни в одном из двух случаев одиночный `:=` не меняет уже существующую
переменную.

## Правило точнее, чем «все имена новые»

Из правил выше легко вывести формулу «слева от `:=` все имена обязаны быть
новыми». Для строки с одним именем слева она верна: такая строка либо объявляет
новую переменную, либо не собирается. Но как правило языка эта формула неточна.

Слева от `:=` может стоять не одно имя, а несколько через запятую. Тогда часть
этих имён может быть уже объявлена в том же блоке — при двух условиях. Первое:
хотя бы одно имя слева действительно новое, а особое имя-заглушка `_` в этот
счёт не идёт (его разбирает урок 4.10). Второе: переменная с уже объявленным
именем сохраняет свой тип. Уже объявленные переменные в такой строке не
создаются заново: они просто получают новые значения, а новые имена
объявляются.

Такие строки с несколькими именами разбирает урок 3.6, и до него они не
понадобятся. Пока достаточно точной границы. В строке с одним именем слева
напарника, который был бы новым, нет. Поэтому одиночный `:=` с именем, уже
объявленным в этом блоке, всегда даёт отказ `no new variables`.

## Как выбрать: var, := или =

Выбирают не по привычке и не по лозунгу вроде «всегда пиши `:=`», а по четырём
вопросам. Задавайте их по порядку:

1. Где стоит строка — внутри тела функции или на уровне пакета?
   На уровне пакета выбор уже сделан: только `var`.
2. Нужна новая переменная или новое значение для переменной, которая уже есть?
   Если новое значение для уже объявленной переменной, в том числе для
   параметра функции, пишите `=`, и выбор закончен. Если нужна отдельная
   переменная, дайте ей новое имя и переходите к следующему вопросу.
3. Есть ли у новой переменной осмысленное начальное значение?
   Если нет и начать с нулевого значения — именно то, что нужно, пишите
   `var name T`.
4. Подходит ли тип, который выберется по записи значения?
   Если да, пишите `name := значение` или `var name = значение` — внутри
   функции это одно и то же. Если нужен другой тип, пишите
   `var name T = значение`.

Внутри функции для новой переменной с подходящим значением обычно выбирают
`:=`. Но цель выбора — чтобы строка точнее сказала читателю о вашем намерении:
«начинаем с нуля, значение придёт позже» или «вот значение, с которого всё
начинается».

## Что говорит сообщение об ошибке

Отказы из разделов выше легко слить в один «что-то не так с `:=`». Различать их
стоит по вопросу «какая операция задумана и почему компилятор её не принял»:

- `non-declaration statement outside function body` — короткая запись стоит на
  уровне пакета. Нужна переменная уровня пакета — пишите `var`; нужна
  локальная — перенесите строку в тело функции.
- `no new variables on left side of :=` — имя уже объявлено в этом блоке или,
  на внешнем уровне тела функции, это параметр. Если задумано обновить
  значение, нужен `=`; если нужна отдельная переменная, дайте ей новое имя.
- `cannot use … as … value in assignment` — тип переменной уже выбран и
  значение ему не подходит. Решите, какой тип задуман: либо объявите переменную
  с нужным типом, либо присвойте значение подходящего типа.
- `declared and not used` — локальная переменная объявлена, но ни разу не
  прочитана. Либо используйте её значение там, где собирались, либо уберите
  объявление.

Отдельно стоит пропущенная правая часть у `:=`: сообщение о синтаксической
ошибке там зависит от того, что написано следом, поэтому узнают этот случай по
самой строке, а не по тексту сообщения.

Чините задуманную операцию, а не сообщение. Механически заменить все `:=` на
`=` — плохой ремонт: тогда первая строка, которая объявляла переменную, её уже
не объявляет, и имя становится неизвестным компилятору. Сначала решите, где
переменная должна появиться, а где только получить новое значение, и уже по
этому ставьте `:=`, `var` или `=`.

Заготовка — пакет `parcel`: файл `go.mod` и три файла с кодом, `address.go`,

Тела функций — заглушки: каждая возвращает пустую строку, которая не подходит
под её задачу. В каждой функции допишите тело так, чтобы функция возвращала
строку, описанную в разделе её задачи ниже. Комментарии `// TODO` можно
удалить.

Не меняйте `go.mod`, строку `package parcel`, имена функций, списки параметров и
типы результатов: скрытые тесты вызывают функции именно в таком виде. Функции
только возвращают строки; печатать ничего не нужно. Пакета `fmt` и других
импортов в упражнении не нужно: строки собираются склейкой через `+` из урока
1.7.

Собирать строку можно по частям в локальной переменной, а можно вернуть готовое
выражение сразу после `return`. Если заводите локальную переменную, решите для
каждой строки тела, что она делает: объявляет новую переменную или обновляет
уже существующую. Помните, что параметр функции — уже объявленное имя.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые строки с
ожидаемыми:

- `TestAddress` — `Address` на двух разных парах имени и города;
- `TestUrgent` — `Urgent` на обычном адресе и на пустой строке;
- `TestRoute` — `Route` на одной паре городов и на той же паре в обратном
  порядке.

Тест получает только то, что функция вернула. Текста решения он не видит.
Поэтому **какой записью вы объявили переменную — `var` или `:=` — проверка не
различает**, как и то, заводили ли вы переменную вообще. Выбор между `var`, `:=`
и `=` спрашивают проверочные вопросы и разбирает `review.md`; тесты отвечают
только за результат.

Ответ проверки бывает двух видов. Если код не собрался, тесты не запускаются, и
проверка показывает сообщение сборки с местом в файле — например, знакомое по
уроку `no new variables on left side of :=`. Если код собрался, но функция
вернула не ту строку, проверка печатает строку `--- FAIL:` с именем теста и
сообщение: какие аргументы переданы, что функция вернула и что должна была
вернуть. Строки в сообщении показаны в кавычках.

## Address

`Address` возвращает адрес: сначала значение `name`, затем запятая и один
пробел, затем значение `city`.

- `Address("Анна", "Казань")` возвращает `Анна, Казань`;
- `Address("Пётр", "Омск")` возвращает `Пётр, Омск`.

## Urgent

`Urgent` возвращает переданный адрес с пометкой в начале: слово `СРОЧНО`,
двоеточие и один пробел, затем значение параметра `address` без изменений.

- `Urgent("Анна, Казань")` возвращает `СРОЧНО: Анна, Казань`;
- `Urgent("")` возвращает `СРОЧНО: ` — пометку с пробелом и ничего после неё.

Пустая строка — обычный аргумент, а не пропущенный: пометка вместе с пробелом в
конце обязана остаться на месте.

## Route

`Route` возвращает строку маршрута: слово `маршрут`, двоеточие и пробел, затем
город отправления `from`, затем пробел, стрелка `→` и пробел, затем город
назначения `to`.

- `Route("Казань", "Омск")` возвращает `маршрут: Казань → Омск`;
- `Route("Омск", "Казань")` возвращает `маршрут: Омск → Казань`.

Порядок городов задают параметры: первый — откуда, второй — куда.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Короткая запись с именем параметра

<!-- review:parameter-short-declaration -->

Естественная первая попытка в `Urgent` — одна строка
`address := "СРОЧНО: " + address` и затем `return address`. Замысел понятен:
взять адрес, приклеить пометку, вернуть. Но до тестов дело не доходит: сборка
останавливается на `no new variables on left side of :=`.

Причина в том, что `address` — параметр. На внешнем уровне тела функции его
имя уже объявлено, и одиночная короткая запись с этим именем пытается объявить
его второй раз. Повторный `:=` ничего не «перезаписывает» — компилятор
отвергает строку.

Чинить надо задуманную операцию. Задумано обновить значение, которое функция
уже получила, — значит, нужен знак `=`: `address = "СРОЧНО: " + address`, а
затем `return address`. Присваивание меняет только копию внутри функции;
вызывающий код получит результат через `return`. Другой законный ремонт — новое
имя для результата, например `label := "СРОЧНО: " + address` и `return label`.
Незаконна только одиночная короткая запись с именем самого параметра на
внешнем уровне тела функции.

## Надпись собрана, а вернули пометку

<!-- review:urgent-wrong-target -->

`Urgent` объявляет `label := "СРОЧНО: "`, затем присваивает склейку параметру
`address = label + address`, а возвращает `label`. Сборка проходит: `label`
прочитана в правой части, параметру присваивать разрешено. Но функция
возвращает одну пометку без адреса.

Ловит это `TestUrgent` на первом же входе: он ждёт пометку вместе с адресом, а
получает только пометку. На втором входе, с пустой строкой, такое решение
случайно даёт верный ответ, потому что адреса там и не должно быть видно.
Поэтому тест и проверяет два входа, а не один.

Диагноз читается по двум строкам. Присваивание кладёт новое значение в
переменную, названную **слева** от `=`: здесь это `address`. А `return` отдаёт
`label`, которая после объявления не менялась. Верное решение возвращает ту
переменную, в которую легла собранная надпись: либо `return address` после
этого присваивания, либо `label = label + address` и `return label`.

## Город первым

<!-- review:address-swapped -->

`Address` собирает `city + ", "`, а потом дописывает `name`. Объявление и
присваивание здесь в порядке: переменная объявлена один раз, дальше только
обновляется. Ошибка в порядке частей.

Ловит это `TestAddress`: он ждёт сначала имя, потом город, а получает наоборот.
В сообщении теста видны переданные аргументы и полученная строка — по ним сразу
видно, что части переставлены.

Верное решение начинает с `name`: `address := name + ", "`, затем
`address = address + city`, затем `return address`. Можно и одной строкой
`return name + ", " + city` — тест проверяет результат, а не число строк.

## Присваивание заменило собранное

<!-- review:route-overwritten -->

`Route` объявляет `route := "маршрут: "`, дописывает город отправления строкой
`route = route + from`, а следующей строкой пишет `route = " → " + to`. Сборка
проходит, но функция возвращает только стрелку и город назначения.

Ловит это `TestRoute` на первом же входе. В полученной строке нет ни слова
«маршрут», ни города отправления, хотя обе части в переменную уже клали.

Причина в том, что присваивание заменяет значение целиком. Оно дописывает к
прежнему значению, только если это значение прочитано в правой части. В
строке `route = " → " + to` переменной `route` справа нет, поэтому всё собранное
раньше пропало. Верное решение читает `route` в правой части каждого
дописывания: `route = route + " → "`, затем `route = route + to`.

В теле функции стоит `var limit = 10`. Какая короткая запись даёт ту же

- B. `limit = 10`.
- C. `limit := 10.0`.
- D. `limit := 10`, но тип выберется позже, по первому присваиванию.

Прежде чем смотреть ответ, назовите тип и значение `limit` и объясните, откуда
`:=` берёт тип.

**Правильный ответ: A.**

`:=` объявляет переменную и берёт тип из выражения справа: литерал 10 даёт
`int`, как и в `var limit = 10`. Вариант B ничего не объявляет: `=` меняет
только уже существующую переменную. Вариант C меняет тип на `float64`. Вариант D
делает тип подвижным, хотя он выбирается один раз, при объявлении.

## Вопрос 2

Функция начинается со строки `var total float64`: сумма стартует с нуля, а
значения придут потом. Есть ли у этой строки короткая форма?

Варианты ответа:

- A. `total :=` без правой части — значение будет нулевым, как у `var`.
- B. `total := 0` — а `float64` выберется, когда придёт дробное значение.
- C. Формы без значения нет; `total := 0.0` даёт тот же тип и ноль, но `var`
  точнее говорит, что значение пока неважно.
- D. Нет: `:=` не умеет объявлять переменные `float64`, им всегда нужен `var`.

Прежде чем смотреть ответ, объясните, откуда `:=` берёт тип и что получится,
если справа написать просто `0`.

**Правильный ответ: C.**

Справа от `:=` обязано стоять выражение: из него берутся и тип, и значение.
Вариант A даёт синтаксическую ошибку. Вариант B ждёт подстройки типа, но `0`
даёт `int` сразу и навсегда. Вариант D обобщает слишком широко: `0.0` даёт
`float64`, а значение с уже готовым типом передаёт `:=` свой тип.

## Вопрос 3

Счётчик посещений должны видеть две функции пакета, и автор объявил его вне
всех функций.

```go
@quiz _broken/package-counter
```

Что скажет компилятор и как объявить счётчик?

Варианты ответа:

- A. `no new variables` — нужно другое имя.
- B. Синтаксическая ошибка: `:=` — инструкция, а не объявление уровня пакета;
  нужно `var visits = 0` или `var visits int`.
- C. Программа соберётся: вне функций `:=` работает как `var`.
- D. `declared and not used` — счётчик надо прочитать в `main`.

Прежде чем смотреть ответ, назовите, где стоит строка с `:=`, и предскажите вид
ошибки: синтаксис, повторное имя, тип или неиспользованная переменная.

**Правильный ответ: B.**

На уровне пакета грамматика допускает только объявления, а короткая запись —
инструкция, поэтому компилятор останавливается на разборе текста. Вариант A
описывает повторное объявление, а `visits` объявлен впервые. Вариант C
переносит правило тела функции на уровень пакета. Вариант D применяет правило
о локальных переменных, да и `show` счётчик читает.

## Вопрос 4

Параметр функции `mark` и переменная в `main` оба называются `word`.

```go
@quiz _quiz/01-param-same-name
```

Что напечатает программа?

Варианты ответа:

- A. Две строки с восклицательным знаком: `mark` изменила `word` из `main`.
- B. Первая строка с восклицательным знаком, вторая — без него.
- C. Не соберётся: `word` объявлено дважды — в `main` и в параметре.
- D. Не соберётся: параметру нельзя присваивать.

Прежде чем смотреть ответ, скажите, какую переменную называет `word` внутри
`mark` и какую — внутри `main`.

**Правильный ответ: B.**

Параметр — отдельная переменная `mark` с копией аргумента; присваивание меняет
копию, `return` отдаёт её в `main`, а `word` в `main` не меняется. Вариант A
считает параметр переменной вызывающего кода. Вариант C смешивает две функции:
это не один блок. Вариант D запрещает законное: нельзя только одиночный `:=` с
именем параметра на внешнем уровне тела функции.

## Вопрос 5

Автор хотел, чтобы `count` дальше хранила строку, и написал вторую строку
тоже через `:=`.

```go
@quiz _broken/retype
```

Что произойдёт?

Варианты ответа:

- A. Появится новая строковая `count`, и программа напечатает строку.
- B. Не соберётся: `count` уже есть в этом блоке, повторный `:=` отвергается и
  тип не меняет.
- C. Соберётся, и прежняя `count` станет строковой.
- D. Не соберётся только потому, что первая `count` не используется.

Прежде чем смотреть ответ, предскажите вид ошибки и объясните, почему повторный
`:=` не переводит переменную на другой тип.

**Правильный ответ: B.**

Это повторное объявление в том же блоке: компилятор отвечает
`no new variables` и добавляет отказ по типу. Вариант A путает случай с
внутренним блоком — только там появилась бы новая переменная. Вариант C делает тип
подвижным. Вариант D выдумывает причину: `count` печатается.

## Вопрос 6

Программа устроена как пример из раздела про внутренний блок, но внутри блока
стоит `=`, а не `:=`.

```go
@quiz _quiz/02-inner-assign
```

Что напечатают две строки вывода?

Варианты ответа:

- A. Внутри блока 2, после блока 1.
- B. Обе строки напечатают 2.
- C. Не соберётся: внутри блока `level` не объявлена.
- D. Не соберётся: внутренняя `level` не используется.

Прежде чем смотреть ответ, скажите, объявляет ли строка внутри блока новую
переменную или меняет существующую, и какую именно.

**Правильный ответ: B.**

`=` ничего не объявляет и меняет уже существующую внешнюю `level`; после блока
печатается она же. Вариант A верен для `:=` внутри блока. Вариант C забывает,
что внешняя переменная видна и внутри блока. Вариант D говорит о внутренней
переменной, которой здесь нет.

## Вопрос 7

Какое утверждение о короткой записи верно?

Варианты ответа:

- A. `:=` с уже существующим именем всегда меняет прежнюю переменную.
- B. Одиночный `:=` с именем из этого же блока (на внешнем уровне тела
  функции — и с именем параметра) не собирается, а во внутреннем блоке
  объявляет новую переменную.
- C. Слева от `:=` все имена обязаны быть новыми в любой записи, без
  исключений.
- D. Во внутреннем блоке `:=` не собирается, если снаружи есть такое же имя.

Прежде чем смотреть ответ, объясните, что делает `level := 2` во внутреннем
блоке и что делает `count := 2` во втором случае раздела «Объявить или
обновить».

**Правильный ответ: B.**

В одном блоке одиночный `:=` не объявит занятое имя, а внутренний блок — другой
блок. Вариант A неверен в обоих случаях: в том же блоке отказ, во внутреннем —
новая переменная. Вариант C верен для одного имени, но не для строки с
несколькими именами, где часть может быть уже объявлена, если хотя бы одно
новое и типы не меняются. Вариант D запрещает законное скрытие имени.

## Вопрос 8

Программа должна напечатать «заказ принят», но не собирается.

```go
@quiz _broken/repeat-update
```

Какой ремонт сохраняет результат и тип `message`?

Варианты ответа:

- A. Во второй строке заменить `:=` на `=`.
- B. В обеих строках заменить `:=` на `=`.
- C. Взять вторую строку в фигурные скобки — во внутренний блок.
- D. Во второй строке написать `var` перед именем и `=` вместо `:=`.

Прежде чем смотреть ответ, скажите, что автор задумал во второй строке —
объявить или обновить, — и что сообщит компилятор до ремонта.

**Правильный ответ: A.**

Сейчас отказ `no new variables`: `message` объявляют второй раз, а задумано
обновление, и его делает `=`. Вариант B убирает единственное объявление — имя
станет неизвестным. Вариант C даёт внутреннюю переменную, которую не читают:
будет `declared and not used`. Вариант D — снова повторное объявление.

## Вопрос 9

По замыслу `ratio` хранит дробное число: сначала 2, потом 2.5. Сборка не

```go
@quiz _broken/float-into-int
```

Какой ремонт сохраняет значение 2.5 в переменной дробного типа?

- A. Первую строку заменить на `var ratio float64 = 2`.
- B. Вторую строку заменить на `ratio := 2.5`.
- C. Вторую строку заменить на `ratio = 2`.
- D. Первую строку заменить на `var ratio = 2`.

Литерал 2 дал тип `int`, и дробное значение ему не подходит; нужный тип
