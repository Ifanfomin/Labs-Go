# strings: поиск и регистр

Трекер задач получает заголовки вроде «Docs: исправить опечатку» или
«  сборка: обновить зависимости». До двоеточия стоит раздел, после него —
текст задачи. Программе трекера нужны ответы на вопросы трёх видов. Да или
нет: встречается ли в заголовке кусок текста, начинается ли заголовок с
раздела, кончается ли знаком вопроса. Где: с какого места начинается
совпадение. И как привести заголовок к одному виду, чтобы «Docs», «DOCS» и
« docs» считались одним разделом.

Эти вопросы решают функции стандартного пакета `strings`. Их вызывают, как
в уроке 1.6: пакет импортируют и пишут его имя перед именем функции,
например `strings.Contains(title, "docs")`. Исследуемую строку функции урока
получают первым аргументом, а то, что в ней ищут или убирают, — вторым.
Результат функция возвращает, как в уроке 1.7.

Примеры печатают через `fmt.Printf` с глаголами `%q`, `%v` и `%d` из уроков
1.9 и 2.4. `%q` показывает строку в кавычках, поэтому пробелы по краям в
выводе видны.

## Вопрос «да или нет»

Три функции отвечают значением `bool` на вопрос о строке `sub` внутри строки
`s`:

- `strings.Contains(s, sub)` — встречается ли `sub` где-нибудь в `s`;
- `strings.HasPrefix(s, sub)` — начинается ли `s` с `sub`;
- `strings.HasSuffix(s, sub)` — кончается ли `s` на `sub`.

Функцию выбирают по вопросу задачи. «Встречается ли в описании текст go» —
вопрос о вхождении в любом месте, это `Contains`. «Относится ли заголовок к
разделу go» — вопрос о начале, это `HasPrefix`. «Файл ли это с кодом на Go» —
вопрос о конце имени, это `HasSuffix` со строкой `".go"`.

Ищется буквальный текст. Звёздочка или знак вопроса во втором аргументе —
обычные символы, а не шаблон; поиск по шаблону делает пакет `regexp` (урок
9.9). Границ слов функции не знают: `Contains` найдёт go и внутри «gopher».

Программа ниже задаёт все три вопроса для четырёх пар строк. Прежде чем
смотреть вывод, предскажите для каждой пары три ответа. Для второй пары
отдельно объясните, почему два первых ответа разные.

```go

### Example: `01-yes-no`

Источник: `examples/01-yes-no/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("%q в %q: Contains %v, HasPrefix %v, HasSuffix %v\n", sub, s,
		strings.Contains(s, sub), strings.HasPrefix(s, sub), strings.HasSuffix(s, sub))
}

func main() {
	show("go build", "go")
	show("run go build", "go")
	show("привет, мир", "мир")
	show("go", "go build")
}

```
```

В «run go build» текст go стоит внутри, но не в начале: `Contains` ответила
«да», а `HasPrefix` — «нет». Ровно эта разница отделяет «заголовок упоминает
раздел» от «заголовок относится к разделу». В последней паре искомая строка
длиннее исследуемой и поместиться в ней не может, поэтому все три ответа
отрицательные, а сообщения об ошибке нет.

## Совпадение — это те же байты

Поиск, как сравнение `==` из урока 2.7, требует точного совпадения байтов.
Регистр к одному виду не приводится, пробелы поиск не пропускает, а «е» и «ё»
— разные буквы с разными байтами.

Прежде чем смотреть вывод, предскажите ответы для четырёх пар ниже и для
каждой назовите символ, который решил дело.

```go

### Example: `02-exact`

Источник: `examples/02-exact/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("%q в %q: Contains %v, HasPrefix %v, HasSuffix %v\n", sub, s,
		strings.Contains(s, sub), strings.HasPrefix(s, sub), strings.HasSuffix(s, sub))
}

func main() {
	show(" go build", "go")
	show("Go build", "go")
	show("привет, мир", "Мир")
	show("ёлка", "елка")
}

```
```

В первой паре пробел сдвинул go с начала строки. Во второй и третьей
заглавная буква не совпала со строчной. В четвёртой «ёлка» и «елка»
различаются первой буквой. Чтобы не замечать регистра или пробелов по
краям, строку сначала явно приводят к одному виду — разделы «Регистр:
ToLower и ToUpper» и «TrimSpace убирает края».

## Пустая строка находится всегда

Пустая строка поиска находится в любой строке; так показывают и официальные
примеры пакета `strings`. `Contains` с пустым вторым аргументом отвечает
«да» даже для пустой первой строки, и `HasPrefix` с `HasSuffix` отвечают так
же. Помогает картина: пустая строка — кусок длиной ноль байтов, а такой
кусок есть в начале, в конце и внутри любой строки.

Следствие для практики: если второй аргумент может оказаться пустым,
проверка «начинается ли заголовок с раздела» ответит «да» на любой
заголовок. Поэтому в описании функции пишут, что она делает с пустым входом,
а в тестах проверяют этот случай отдельно.

Прежде чем смотреть вывод, предскажите три строки по этому правилу. В
последней пуста первая строка, а искомая — нет.

```go

### Example: `03-empty`

Источник: `examples/03-empty/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("%q в %q: Contains %v, HasPrefix %v, HasSuffix %v\n", sub, s,
		strings.Contains(s, sub), strings.HasPrefix(s, sub), strings.HasSuffix(s, sub))
}

func main() {
	show("go build", "")
	show("", "")
	show("", "go")
}

```
```

Пустой второй аргумент нашёлся и в «go build», и в пустой строке. Непустое go
в пустой строке не нашлось: в строке без единого байта нет двух нужных
байтов.

## Где совпадение: Index

`strings.Index(s, sub)` возвращает число типа `int` — **смещение** первого
вхождения `sub` в `s`, то есть сколько байтов стоит в `s` перед этим
вхождением. Если `s` начинается с `sub`, перед совпадением ноль байтов, и
результат — 0. Если вхождений несколько, `Index` сообщает только о первом.

Прежде чем смотреть вывод, посчитайте для каждой строки, сколько байтов
стоит перед первым вхождением. В этих строках только символы ASCII, по
одному байту на символ.

```go

### Example: `04-index`

Источник: `examples/04-index/`

```go

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("Index(%q, %q) = %d\n", s, sub, strings.Index(s, sub))
}

func main() {
	show("go build", "go")
	show("run go build", "go")
	show("go build", "build")
	show("go go go", "go")
	show("abcabc", "bc")

```
```

В «go go go» слово встречается трижды, но ответ — ноль: первое вхождение
стоит в самом начале. Ноль здесь — успех, а не «ничего не нашлось».

## Промах и пустой поиск

Если `sub` в `s` нет, `Index` возвращает −1. Настоящее смещение
отрицательным не бывает, поэтому −1 нельзя спутать ни с одним местом в
строке. Совпадение есть, когда результат не равен −1, — или, что то же
самое, не меньше нуля. Ошибка — условие «результат больше нуля»: оно
теряет совпадение в самом начале, у которого смещение 0.

Пустая строка поиска и здесь находится сразу: перед куском длиной ноль в
начале стоит ноль байтов, поэтому ответ — 0.

Прежде чем смотреть вывод, предскажите шесть результатов. Там, где ответ —
не −1, назовите место совпадения.

```go

Источник: `examples/05-miss/`

```go

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("Index(%q, %q) = %d\n", s, sub, strings.Index(s, sub))
}

func main() {

	show("Go build", "go")

Первые три строки — промахи: слова rust в строке нет, заглавное Go не

`Contains`: сначала строка, в которой ищут, затем то, что ищут. Оба
аргумента имеют тип `string`, поэтому компилятор перестановку не заметит; на
этих строках она дала тихий промах. Пустой поиск дал 0 и в пустой строке,
а непустое go в ней не нашлось.

Результат `Index` в этом уроке только сравнивают и возвращают. Как
безопасно брать часть строки по смещению, разбирает урок 9.2.

## Смещение считают в байтах

Смещение — число байтов, а не букв. По правилу урока 2.7 русская буква,
включая «ё», занимает в UTF-8 два байта, а символ ASCII — один. Значит,
смещение совпадения — сумма байтов всего, что стоит перед ним.

Прежде чем смотреть вывод, посчитайте так все шесть чисел программы ниже.
Первое число — длина всей строки.

```go

### Example: `06-offset`

Источник: `examples/06-offset/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string, sub string) {
	fmt.Printf("Index(%q, %q) = %d\n", s, sub, strings.Index(s, sub))
}

func main() {
	fmt.Printf("len(%q) = %d\n", "привет, мир", len("привет, мир"))
	show("привет, мир", "мир")
	show("привет, мир", ",")
	show("go: привет", "привет")
	show("код: go", "go")
	show("ёж и еж", "еж")
}

```
```

Перед словом «мир» стоят шесть букв «привет» — двенадцать байтов, — затем
запятая и пробел: итого 14, хотя знаков перед совпадением восемь. В «go:
привет» перед русским словом только символы ASCII, и числа совпали. В «код:
go» три русские буквы дали шесть байтов, и перед go стоят восемь байтов при
пяти знаках. В последней строке «ёж» начинается с другой буквы, чем «еж»,
поэтому совпадение нашлось только во втором слове.

Если и строка, и искомый текст — правильный UTF-8, найденное совпадение
всегда начинается и кончается на границах символов: полная запись одного
символа не встречается внутри записи другого символа или на стыке соседних.
Но единица результата — всё равно байты. Номер буквы из смещения делением на
два не получить, если в строке смешаны русские буквы и ASCII; как пройти по
строке символ за символом, разбирает урок 9.2.

## Регистр: ToLower и ToUpper

`strings.ToLower(s)` возвращает копию `s`, в которой все буквы Unicode
заменены строчными, а `strings.ToUpper(s)` — копию с заглавными. Всё, что не
буква, — цифры, знаки, пробелы, табуляции — остаётся как было.

У латинских букв a–z и A–Z и у русских букв каждая заглавная буква имеет
ровно одну строчную пару, и наоборот. Пара «Е» — «е», пара «Ё» — «ё».
Поэтому из «Е» функция никогда не сделает «ё».

Прежде чем смотреть вывод, предскажите обе копии каждой строки. В четвёртой
строке есть цифры, двоеточие и табуляция, которую `%q` показывает как `\t`.

```go

### Example: `07-case`

Источник: `examples/07-case/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string) {
	fmt.Printf("%q: ToLower %q, ToUpper %q\n", s, strings.ToLower(s), strings.ToUpper(s))
}

func main() {
	show("Привет, Мир")
	show("Ёлка")
	show("ЕЛКА")
	show("Код 42: OK\tда")
	show("   ")
}

```
```

Строчная копия «ЕЛКА» — «елка», а не «ёлка». Строка из пробелов вернулась
прежней: `ToLower` меняет буквы и пробелов не убирает. У этих строк длина в
байтах после смены регистра та же: у букв a–z и A–Z и у русских букв обе
формы занимают одинаковое число байтов. Для других символов это не
обязательно так — пример ниже, в разделе о границе сравнения.

## Результат нужно сохранить

Строки в Go неизменяемы (урок 2.7). `ToLower` не может переписать байты
переданной строки: результат она возвращает как строковое значение.
Переменная, из которой взяли аргумент, от вызова не меняется. Чтобы
воспользоваться результатом, его кладут в новую переменную или присваивают
прежней.

Прежде чем смотреть вывод, предскажите три строки программы. В первой части
результат вызова никуда не записан.

```go

### Example: `08-result`

Источник: `examples/08-result/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	s := "ПРИВЕТ, Go"

	strings.ToLower(s)
	fmt.Printf("вызов без присваивания: s = %q\n", s)

	lower := strings.ToLower(s)
	fmt.Printf("результат в lower: lower = %q, s = %q\n", lower, s)

	s = strings.ToLower(s)
	fmt.Printf("результат в s: s = %q\n", s)
}

```
```

Вызов без присваивания ничего не изменил: возвращённое значение никуда не
записано и потеряно. Во второй части результат оказался в `lower`, а `s`
по-прежнему заглавная. Только присваивание `s = strings.ToLower(s)` положило
в `s` новое значение.

Компилятор принимает вызов без присваивания, и рассчитывать на
предупреждение нельзя. Так же ведут себя `TrimSpace`, `Trim` и `TrimPrefix`:
переданную строку они не меняют.

## Сравнение без учёта регистра и его граница

Раз `==` различает регистр, для меток часто пишут рецепт: перевести обе
строки в нижний регистр и сравнить, то есть
`strings.ToLower(a) == strings.ToLower(b)`. Для меток из символов ASCII и
русских букв рецепт работает: у каждой буквы здесь одна пара другого
регистра.

За пределами этих букв правила регистра сложнее, в том числе у латинских
букв вне ASCII, и простой перевод в нижний регистр их не повторяет. Для
правил конкретного языка, например турецкого, в пакете есть особые функции,
а `ToLower` таких правил не знает. В программе ниже граница видна на
немецкой букве ß и на греческой сигме, у которой две строчные формы —
обычная σ и конечная ς.

Прежде чем смотреть вывод, предскажите ответ `sameLower` для первых трёх
пар: в них только русские буквы. Остальные строки вывода прочитайте после и
объясните своими словами, что каждая из них говорит о рецепте.

```go

### Example: `09-limits`

Источник: `examples/09-limits/`

```go
package main

import (
	"fmt"
	"strings"
)

// sameLower сравнивает две строки после перевода обеих в нижний регистр.
func sameLower(a string, b string) bool {
	return strings.ToLower(a) == strings.ToLower(b)
}

func show(a string, b string) {
	fmt.Printf("%q и %q -> %q и %q, sameLower %v\n", a, b, strings.ToLower(a), strings.ToLower(b), sameLower(a, b))
}

func main() {
	show("ПРИВЕТ", "привет")
	show("Ёлка", "ёЛКА")
	show("ёлка", "елка")
	show("ß", "SS")
	show("ς", "Σ")

	// Три байта знака кельвина U+212A: на экране он похож на латинскую K,
	// поэтому строка записана экранированиями \x из урока 2.7.
	kelvin := "\xe2\x84\xaa"
	lower := strings.ToLower(kelvin)
	fmt.Printf("знак кельвина U+212A: len %d, после ToLower %q, len %d\n", len(kelvin), lower, len(lower))

```
```

Первые три строки — рецепт в своей области: регистр не помешал, а разные
буквы «ё» и «е» остались разными. `ToLower` оставила ß как есть, а SS
превратила в ss — строки разные. Заглавная Σ стала обычной σ, а конечная ς
осталась собой — снова разные строки. Последняя строка — знак кельвина,
похожий на латинскую K: `ToLower` превратила его в латинскую k, и длина
уменьшилась с трёх байтов до одного. Значит, за пределами букв ASCII и
русских букв смена регистра может менять длину строки, и смещение, которое
вернёт `Index` до перевода и после него, перестаёт совпадать.

Отсюда граница рецепта. Сравнение через `ToLower` обеих сторон годится для
меток из символов ASCII и русских букв — эту область и указывают в описании
функции, которая сравнивает метки. Более общее сравнение без учёта регистра,
`strings.EqualFold`, разбирает урок 9.4.

## TrimSpace убирает края

`strings.TrimSpace(s)` возвращает строку без пробельных символов в начале и
в конце. Пробельные символы — те, которые Unicode считает пробелами: обычный
пробел, табуляция `\t`, перевод строки `\n`, возврат каретки `\r`,
вертикальная табуляция `\v`, перевод страницы `\f`, а также, например,
неразрывный пробел U+00A0. Внутри строки функция не трогает ничего: два
пробела между словами останутся двумя. Если строка пуста или состоит только
из пробельных символов, результат — пустая строка.

Прежде чем смотреть вывод, предскажите первые пять строк. Для строки с
неразрывным пробелом по краям скажите, станет ли она короче. Последнюю
строку вывода прочитайте после.

```go

### Example: `10-trimspace`

Источник: `examples/10-trimspace/`

```go
package main

import (
	"fmt"
	"strings"
)

func show(s string) {
	fmt.Printf("%q -> %q\n", s, strings.TrimSpace(s))
}

func main() {
	show("\r\n go build \t\n")
	show("  два  слова  ")
	show("")
	show(" ")
	show(" \t\n\r\v\f ")

	// Оба символа на экране не видны, поэтому записаны байтами через \x:
	// неразрывный пробел U+00A0 — два байта, пробел нулевой ширины U+200B — три.
	nbsp := "\xc2\xa0go\xc2\xa0"
	zwsp := "\xe2\x80\x8bgo"
	fmt.Printf("неразрывный пробел по краям: len %d -> %d\n", len(nbsp), len(strings.TrimSpace(nbsp)))
	fmt.Printf("пробел нулевой ширины в начале: len %d -> %d\n", len(zwsp), len(strings.TrimSpace(zwsp)))
}

```
```

Двойной пробел внутри сохранился, а пустая строка и строки из одних
пробельных символов дали пустую строку. Неразрывный пробел по краям снят. А
пробел нулевой ширины U+200B остался: на экране он невидим, но Unicode не
относит его к пробельным символам. Поэтому `TrimSpace` — не «убрать всё
невидимое», а ровно пробельные символы по краям. Слов она не разбирает и
знаки препинания не удаляет; сжать пробелы внутри строки или разбить её на
слова — работа урока 2.14.

## Trim: набор символов, а не приставка

`strings.Trim(s, cutset)` тоже обрезает оба края, но снимает символы,
перечисленные во втором аргументе. Второй аргумент — не текст, который
ищут, а **набор** кодовых точек (кодовая точка — номер символа Unicode, урок
2.8). Функция идёт от левого края и снимает символ за символом, пока
очередной символ входит в набор; первый символ не из набора её
останавливает. Затем то же делается с правого края.

Отсюда три следствия:

- порядок символов в наборе не важен: `"cab"` и `"abc"` — один набор;
- повтор символа в наборе ничего не добавляет: `"aab"` и `"ab"` — тоже;
- набор не описывает последовательность: `"-="` снимает и дефисы, и знаки
  равенства в любом порядке и количестве.

Прежде чем смотреть вывод, пройдите каждую строку с обоих краёв и
предскажите результат.

```go

### Example: `11-trim`

Источник: `examples/11-trim/`

```go

import (
	"fmt"
	"strings"
)

func show(s string, cutset string) {
	fmt.Printf("Trim(%q, %q) = %q\n", s, cutset, strings.Trim(s, cutset))
}

func main() {
	show("xxhixx", "x")
	show("--==title==--", "-=")
	show("abcHELLOcba", "cab")
	show("aabHELLObaa", "ab")
	show("ааБукваяя", "ая")
	show("Xhix", "x")
	show("  hello  ", "")
}

```
```

С «--==title==--» набор снял по четыре знака с каждого края, хотя справа
они стоят в обратном порядке. У русского слова слева сняты две «а», справа
— две «я» и «а», а буква «в» остановила обрезку. Заглавная X не входит в
набор из строчной x. Пустой набор не снимает ничего.

## TrimPrefix: одна точная приставка

`strings.TrimPrefix(s, prefix)` убирает одну определённую приставку. Если
`s` начинается с `prefix`, функция возвращает остаток строки после
приставки; если не начинается — `s` без изменений. Приставка сравнивается
точно, как в `HasPrefix`, и снимается не больше одного раза. Внутри строки
функция приставку не ищет. Результат у неё один — строка: ошибки, если
приставки нет, функция не сообщает.

Прежде чем смотреть вывод, предскажите все восемь результатов.

приставку — значит ничего не изменить. Была ли приставка, `TrimPrefix` не
сообщает: это отдельный вопрос к `HasPrefix`.

## Нормализация и поиск: порядок шагов

«Почистить текст» — ещё не задача, пока не сказано, какие входы допустимы и
что должно получиться. Для меток трекера правило такое. Вход — строка из
символов ASCII (букв a–z и A–Z, цифр, знаков, пробела, табуляции и
переводов строки) и русских букв. На выходе — та же строка без пробельных
символов по краям, в которой все буквы, в том числе в середине, стали
строчными, а пробелы, цифры и знаки внутри остались на местах. Такое
приведение к одному виду называют **нормализацией**. После неё в метке ищут.

Программа ниже показывает каждое промежуточное значение и задаёт одни и те
же вопросы до обработки и после. Прежде чем смотреть вывод, выпишите все
семь строк.

```go

### Example: `15-pipeline`

Источник: `examples/15-pipeline/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	s := "  Go: Сборка  "
	trimmed := strings.TrimSpace(s)
	label := strings.ToLower(trimmed)

	fmt.Printf("исходная: %q\n", s)
	fmt.Printf("после TrimSpace: %q\n", trimmed)
	fmt.Printf("после ToLower: %q\n", label)

	fmt.Println("HasPrefix до обработки:", strings.HasPrefix(s, "go:"))
	fmt.Println("HasPrefix после обработки:", strings.HasPrefix(label, "go:"))
	fmt.Println("Index до обработки:", strings.Index(s, ":"))
	fmt.Println("Index после обработки:", strings.Index(label, ":"))
}

```
```

До обработки `HasPrefix` ответила «нет» по двум причинам: строка начинается
с пробелов, а раздел записан с заглавной буквы. `Index` до обработки дала 4,
а после — 2: два пробела в начале сдвигали смещение. Поэтому сначала
нормализация, потом вопрос к строке: поиск до нормализации отвечает на
вопрос об исходной строке, а не о метке.

Для входов из описанной выше области сами два шага можно переставить:
`ToLower` не трогает пробельные символы, а `TrimSpace` не трогает буквы.
Но нужен каждый шаг.

Прежде чем смотреть вывод, для четырёх первых строк предскажите три ответа
и назовите вход, который показывает, что без `ToLower` не обойтись, и вход,
который показывает то же для `TrimSpace`. Две последние строки ставят
`TrimPrefix` до и после `ToLower` — предскажите и их.

```go

### Example: `16-steps`

Источник: `examples/16-steps/`

```go

	"fmt"
	"strings"
)

func label(s string) string {
	return strings.ToLower(strings.TrimSpace(s))
}

func show(s string) {
	lowerOnly := strings.HasPrefix(strings.ToLower(s), "go:")
	trimOnly := strings.HasPrefix(strings.TrimSpace(s), "go:")
	both := strings.HasPrefix(label(s), "go:")
	fmt.Printf("%q: только ToLower %v, только TrimSpace %v, оба шага %v\n", s, lowerOnly, trimOnly, both)

	show("\tgo:\n")

	show("   ")

приставки в них нет. Две последние строки — снова порядок относительно
поиска: `TrimPrefix` до `ToLower` не нашла строчной приставки в «GO:», а
после `ToLower` приставка снялась, и остался текст с пробелом в начале.

## Какие входы проверяют функцию

Удачный ответ на одной метке ничего не говорит о других. Функцию поиска или
нормализации проверяют входами, каждый из которых ловит свою ошибку:

- пустая строка и строка из пробельных символов — поведение на пустом входе;
- вход без совпадения — отличает −1 от 0 и «нет» от «да»;
- совпадение в самом начале — ловит условие «больше нуля»;
- повтор, как «go go go» для `Index` или «--flag» для `TrimPrefix`, —
  первое ли вхождение и один ли раз снята приставка;
- другой регистр и пробелы по краям — пропущенный шаг нормализации;
- русские буквы перед совпадением — байты против букв;
- для `Trim` — строка, где после нужных символов идут символы из того же
  набора, как «admin_adam».

Набор входов зависит от функции: у `TrimSpace` нет смещения, у `Index` нет
набора. А тесты на метках из символов ASCII и русских букв ничего не
доказывают про любой текст.

Сверьте ответы с разбором после попытки, разделы «Как нормализуется
заголовок», «Граница раздела» и «Смещение двоеточия».

## Normalize

`Normalize` возвращает заголовок без пробельных символов в начале и в конце,
в котором все буквы, в том числе в середине, стали строчными. Пробелы, знаки
и цифры внутри остаются на своих местах.

- `Normalize("  Docs: Ссылки  ")` возвращает `"docs: ссылки"`;
- `Normalize("\tСборка:  Тест\n")` возвращает `"сборка:  тест"` — двойной
  пробел внутри сохранён;
- `Normalize("")` и `Normalize(" \t\n")` возвращают `""`.

## InSection

`InSection` возвращает `true` ровно тогда, когда нормализованный заголовок
начинается с `section`, за которым сразу стоит двоеточие. Что идёт после
двоеточия, неважно, в том числе ничего.

- `InSection("  DOCS: ссылки", "docs")` возвращает `true`;
- `InSection("docs:", "docs")` возвращает `true`;
- `InSection("docsite: поиск", "docs")` возвращает `false`: раздел лишь
  начинает другое слово;
- `InSection("поправить docs: ссылки", "docs")` возвращает `false`: раздел
  стоит не в начале;
- `InSection("docs ссылки", "docs")` возвращает `false`: после раздела нет
  двоеточия;
- `InSection("", "docs")` возвращает `false`.

## ColonIndex

`ColonIndex` возвращает смещение в байтах первого двоеточия в
нормализованном заголовке или −1, если двоеточия в нём нет. Смещение
считается так же, как у `strings.Index`: сколько байтов стоит перед
двоеточием.

- `ColonIndex("docs: ссылки")` возвращает 4;
- `ColonIndex("   docs: ссылки")` возвращает 4: пробелы в начале убрала
  нормализация;
- `ColonIndex(":x")` возвращает 0;
- `ColonIndex("go:go: x")` возвращает 2: важно первое двоеточие;
- `ColonIndex("Код: 42")` возвращает 6: три русские буквы занимают шесть
  байтов;
- `ColonIndex("")` и `ColonIndex("без двоеточия")` возвращают −1.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Как нормализуется заголовок

<!-- review:normalize-trace -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»:
промежуточные значения `Normalize` для `"\r\n  Сборка: Тест\t"`. Образец
ответа ниже.

После `strings.TrimSpace` по краям не остаётся ни `\r\n`, ни пробелов, ни
табуляции: получается «Сборка: Тест». После `strings.ToLower` буквы
становятся строчными: «сборка: тест». Пробел после двоеточия внутри строки
остаётся на месте.

Если поменять шаги местами, итог тот же. `ToLower` оставит пробельные
символы по краям как есть, а `TrimSpace` потом снимет их. Для строк из
области упражнения эти два шага друг другу не мешают: `ToLower` не трогает
пробельные символы, а `TrimSpace` не трогает буквы. Важен другой порядок —
относительно поиска: `InSection` и `ColonIndex` ищут в уже нормализованной
строке, поэтому обе вызывают `Normalize` до `HasPrefix` и до `Index`.
Верное тело — `return strings.ToLower(strings.TrimSpace(title))`.

## Граница раздела

<!-- review:section-boundary -->

Второй вопрос: почему начало заголовка сравнивают с именем раздела и
двоеточием и почему это `HasPrefix`.

Двоеточие — граница раздела. Без него приставка docs совпадает с началом
любого слова, которое с неё начинается: «docsite: поиск» оказался бы в
разделе docs. `Contains` вместо `HasPrefix` засчитывает раздел в любом месте
заголовка: «поправить docs: ссылки» упоминает раздел, но к нему не
относится. Поиск в исходном заголовке вместо нормализованного пропускает
«  DOCS: ссылки»: пробелы и заглавные буквы не совпадают с приставкой. Верное
тело — `return strings.HasPrefix(Normalize(title), section+":")`.

## Смещение двоеточия

<!-- review:colon-offset -->

Третий вопрос: что вернёт `ColonIndex` для `"  Ёж: x"`.

Нормализация даёт «ёж: x». Перед двоеточием стоят две русские буквы — два
знака, но четыре байта, поэтому ответ 4. Ноль для заголовка без двоеточия
вернуть нельзя: ноль означает двоеточие в самом начале, как у «:x», и тогда
два разных случая дали бы один ответ. `strings.Index` уже возвращает −1 при
промахе, поэтому верное тело — `return strings.Index(Normalize(title), ":")`.

## Какие входы ловят ошибку

<!-- review:test-inputs -->

Каждый из девяти неверных вариантов в разделах ниже ловится своим входом,
выбранным под эту ошибку. Окончание строки `\r\n` ловит набор символов вместо
`TrimSpace`. Заглавные буквы ловят пропущенный `ToLower`, пробелы по краям —
пропущенный `TrimSpace`. «docsite: поиск» ловит раздел без двоеточия,
«поправить docs: ссылки» — `Contains` вместо `HasPrefix`. Пробелы в начале
ловят поиск двоеточия до нормализации, заголовок без двоеточия — ноль вместо
−1, два двоеточия — последнее вхождение вместо первого. Уже нормализованный
заголовок `"docs:x"` с разделом docs не ловит ничего: на нём все девять
вариантов отвечают так же, как верное решение.

- D. Для `Trim` — « мыл», для `TrimPrefix` — «ма мыла».

Прежде чем смотреть ответ, пройдите строку с обоих краёв, проверяя каждую
букву по набору из «м» и «а», и объясните, почему второй аргумент `Trim` —
не приставка.

**Правильный ответ: D.**

Для `Trim` второй аргумент — набор букв «м» и «а». Слева сняты все четыре
буквы слова «мама», пробел не входит в набор и останавливает обрезку.
Справа снята «а», а «л» останавливает обрезку. `TrimPrefix` снимает ровно
одну приставку «ма». Вариант B снимает в `Trim` одну приставку, как будто
это `TrimPrefix`. Вариант C снимает в обеих функциях все повторы приставки,
и только слева. Вариант A верно считает `Trim`, но приписывает
`TrimPrefix` повторное снятие.

## Вопрос 9

Функция отвечает, относится ли заголовок к разделу go. Её написали тремя
способами:

1. `strings.HasPrefix(strings.ToLower(strings.TrimSpace(s)), "go:")`;
2. `strings.HasPrefix(strings.TrimSpace(s), "go:")`;
3. `strings.HasPrefix(strings.ToLower(s), "go:")`.

Какие входы показывают, что способ 2 неверен и что способ 3 неверен?

Варианты ответа:

- A. Оба ошибаются на `"go: тест"`.
- B. Способ 2 ошибается на `"\tgo: тест"`, способ 3 — на `"GO: тест"`.
- C. Способ 2 ошибается на `"GO: тест"`, способ 3 — на `"\tgo: тест"`.
- D. Никакие: число и порядок шагов обработки на ответ не влияют.

Прежде чем смотреть ответ, выпишите для обоих входов промежуточные
значения в каждом способе.

**Правильный ответ: C.**

В способе 2 нет `ToLower`: «GO: тест» после `TrimSpace` так и начинается с
заглавных букв, и приставка go: не совпадает. В способе 3 нет `TrimSpace`:
после `ToLower` строка по-прежнему начинается с табуляции. Вариант B
приписывает каждому способу чужой пропущенный шаг. Вариант A берёт вход,
который уже нормализован: на нём все три способа отвечают «да», и ошибки не
видно. Вариант D не замечает, что каждый шаг убирает своё отличие входа
от метки: перевод в нижний регистр убирает разницу в регистре, обрезка —
пробельные символы по краям. Поиск до обработки задаёт вопрос об исходной
строке, а не о метке.

## Вопрос 10

Функция должна отвечать «да» ровно тогда, когда нормализованная строка
начинается с `go:`. Коллега написал её через
`strings.Contains(label(s), "go:")`, где `label(s)` возвращает
`strings.ToLower(strings.TrimSpace(s))`, как в разделе теории «Нормализация
и поиск: порядок шагов», и проверил на двух входах:
`"go: сборка"` и `"  GO: тест"` — оба ответа верны. Какой дополнительный
вход покажет ошибку?

Варианты ответа:

- A. `"fix go: тест"` — ожидается «нет».
- B. `"GO: тест"` — ожидается «да».
- C. `""` — ожидается «нет».
- D. Никакой: два верных ответа уже доказывают, что функция верна.

Прежде чем смотреть ответ, для каждого входа сравните ответ `Contains` с
ответом `HasPrefix`.

**Правильный ответ: A.**

В «fix go: тест» приставка стоит не в начале, поэтому верный ответ «нет»,
а `Contains` найдёт её внутри и ответит «да». Варианты B и C не отличают
поиск в любом месте от проверки начала: на «GO: тест» обе функции ответят
«да», на пустой строке обе ответят «нет». Вариант D выдаёт два удачных
случая за доказательство: тест подтверждает только те входы, на которых
он запущен, а ошибку ловит вход, на котором неверная версия отвечает иначе.
