## Какие операции к каким значениям

Полный набор арифметических операций:

| Операция | Целые | `float64` | `string` |
|---|---|---|---|
| `+` | сумма | сумма | склейка |
| `-` | разность | разность | нет |
| `*` | произведение | произведение | нет |
| `/` | частное без дробной части | частное | нет |
| `%` | остаток от деления | нет | нет |

Правило урока 2.4 действует для всех строк: операнды одного типа, литерал
принимает тип переменной, результат того же типа. Логические `!`, `&&` и `||`
из урока 2.6 работают только со значениями `bool`, а арифметика к `bool` не
применяется.

## Целое деление: частное и остаток

Для целых `a` и `b` Go определяет два правила:

1. Частное `a / b` — математическое частное с отброшенной дробной частью.
   Отбрасывание идёт к нулю: 3.5 становится 3, а −3.5 становится −3, а не −4.
2. Остаток `a % b` равен `a - (a/b)*b`. Поэтому `(a/b)*b + a%b` всегда даёт
   `a`.

Из второго правила следует: остаток либо равен нулю, либо имеет знак делимого
`a`. Знак делителя на него не влияет. По модулю остаток меньше модуля
делителя.

Функция `show` в программе ниже печатает частное, остаток и проверку для
четырёх сочетаний знаков у 7 и 2. Прежде чем смотреть вывод, посчитайте четыре
строки по двум правилам. Затем решите, какое из двух последних сравнений
признает −7 нечётным.

```go

### Example: `02-signs`

Источник: `examples/02-signs/`

```go
package main

import "fmt"

// show печатает частное, остаток и проверку q*b + r для a и b.
func show(a int, b int) {
	q := a / b
	r := a % b
	fmt.Printf("%3d / %2d = %2d   %3d %% %2d = %2d   q*b+r = %3d\n", a, b, q, a, b, r, q*b+r)
}

func main() {
	show(7, 2)
	show(-7, 2)
	show(7, -2)
	show(-7, -2)

	n := -7
	fmt.Printf("n%%2 == 1: %v\n", n%2 == 1)
	fmt.Printf("n%%2 != 0: %v\n", n%2 != 0)
}

```
```

Во второй строке −3.5 стало −3, и остаток равен −7 − (−3) × 2 = −1. В третьей
делитель отрицателен, а остаток положителен: делимое 7 положительно.

`n%2 == 1` верно только для положительных нечётных чисел: у −7 остаток −1.
Нечётность при любом знаке проверяет `n%2 != 0`.

## Деление на ноль и край диапазона

Кто заметит деление на ноль, зависит от того, где стоит ноль.
Если делитель — литерал 0, деление находит компилятор, и программа не
собирается, как на литерале вне диапазона в уроке 2.4. У `%` правило то же.
Прежде чем читать дальше, ответьте: напечатает ли программа ниже хоть что-то?

```go
@broken const-zero-divisor
```

Не напечатает: `invalid operation: division by zero`. Несобранная программа
не выполняет ни одной строки, даже стоящей выше деления.

Ноль в переменной компилятор не видит. Программа ниже собирается, а делит уже
во время работы:

```go

### Example: `03-zero-divisor`

Источник: `examples/03-zero-divisor/`

```go
package main

import "fmt"

func main() {
	items := 17
	boxes := 0 // ноль лежит в переменной, а не в записи деления
	fmt.Println("делим", items, "на", boxes)
	fmt.Println(items / boxes)
}

```
```

Первая строка напечаталась, а деление остановило программу **паникой** —
аварийной остановкой во время работы. В уроке 2.5 деление переменных
`float64` на ноль дало бесконечность или NaN. У целых типов таких значений
нет, поэтому целое деление на ноль либо не собирается, либо паникует.

Вторая граница — переполнение. Умножение целых переменных переворачивается
так же, как сложение в уроке 2.4. У деления такой случай один: наименьшее
значение знакового типа, делённое на −1. Для `int8` частное 128 в тип не
помещается, и язык определяет результат: частное равно −128, остаток — 0,
паники нет.

Прежде чем смотреть вывод, посчитайте первую строку по правилу урока 2.4 —
математический результат, затем ±256, пока число не войдёт в диапазон `int8`.
Для двух других строк примените правило предыдущего абзаца.

```go

### Example: `04-edge`

Источник: `examples/04-edge/`

```go
package main

import "fmt"

func main() {
	var pallets int8 = 64
	var two int8 = 2
	fmt.Println("64 * 2 в int8:", pallets*two)

	var low int8 = -128
	var minusOne int8 = -1
	fmt.Println("-128 / -1 в int8:", low/minusOne)

```

Произведение и частное перевернулись и отличаются от математических, а
остаток 0 совпал с математическим. Сообщений нет ни в одной строке: не каждое

частное одними литералами в переменную `int8`, его посчитает компилятор,
точно, как в уроке 2.4, и сборка остановится: 128 не помещается в `int8`.

## Приоритет: как группируется выражение

**Приоритет** решает, какая операция раньше других забирает свои операнды в
группу. Полный список операций с двумя операндами, от сильного уровня к
слабому:

- уровень 5: `*`, `/`, `%`, `<<`, `>>`, `&`, `&^`;
- уровень 4: `+`, `-`, `|`, `^`;
- уровень 3: сравнения `==`, `!=`, `<`, `<=`, `>`, `>=`;
- уровень 2: `&&`;
- уровень 1: `||`.

Унарные операции — минус перед операндом, `!` и `^` из второй части урока —
сильнее всех уровней. Операции одного уровня группируются слева направо:
`6 / 2 * 3` значит `(6 / 2) * 3`.

Прежде чем смотреть вывод, расставьте скобки в шести выражениях и посчитайте.

```go

### Example: `05-precedence`

Источник: `examples/05-precedence/`

```go
package main

import "fmt"

func main() {
	fmt.Println("2 + 3*4 →", 2+3*4)
	fmt.Println("(2 + 3) * 4 →", (2+3)*4)
	fmt.Println("6 / 2 * 3 →", 6/2*3)
	fmt.Println("10 - 4 - 3 →", 10-4-3)
	fmt.Printf("17 %% 5 * 2 → %v\n", 17%5*2)
	fmt.Println("-7 / 2 * 2 →", -7/2*2)
}

```
```

В последней строке унарный минус сильнее деления: частное −3.5 становится −3,
и умножение даёт −6, а не −7. Если группировка не очевидна, ставьте скобки:
они показывают замысел и не меняют результат верной записи.

## Группировка — не очередь вычисления

Приоритет решает, что с чем соединяется, но не порядок вычисления операндов.
Для вызовов функций правило есть: вызовы в выражении выполняются по тексту,
слева направо. Функция `value` ниже печатает имя операнда и возвращает число.
Прежде чем смотреть вывод, ответьте: в каком порядке появятся имена и каким
будет итог?

```go

### Example: `06-order`

Источник: `examples/06-order/`

```go
package main

import "fmt"

// value печатает имя операнда и возвращает его значение.
func value(name string, v int) int {
	fmt.Println("вычислен операнд", name)
	return v
}

func main() {
	total := value("a", 2) + value("b", 3)*value("c", 4)
	fmt.Println("итог:", total)
}

```
```

Умножение сгруппировано раньше, но первым вызван операнд a: он левее.
Группировка решила другое: перемножаются b и c, и к произведению прибавляется
a.

В каком порядке программа читает обычные переменные относительно вызовов,
язык не задаёт. Поэтому не пишите в одном выражении вызов, который меняет
переменную, и чтение той же переменной. Отдельный случай — `&&` и `||` из
урока 2.6: у них правый операнд может не вычисляться вовсе.

## Составное присваивание

**Составное присваивание** `x += y` обновляет переменную её же значением и
даёт тот же результат, что `x = x + (y)`. Такие формы есть у всех операций
уровней 4 и 5: `+=`, `-=`, `*=`, `/=`, `%=` и формы для битов `&=`, `|=`, `^=`,
`&^=`, `<<=`, `>>=`. Для строк работает `+=`: `title += "!"`.

Слева стоит уже объявленная переменная: составное присваивание её не
объявляет. Левая часть вычисляется один раз, поэтому `x op= y` — отдельная
инструкция, а не текстовая подстановка; для простой переменной результат тот
же, что у полной записи. Правая часть берётся в скобки целиком: `x *= 2 + 1`
умножает `x` на 3. Короткие записи `x++` и `x--` делают то же, что `x += 1` и
`x -= 1`.

Прежде чем смотреть вывод, проследите значение `stock` после каждой строки.

```go

### Example: `07-compound`

Источник: `examples/07-compound/`

```go
package main

import "fmt"

func main() {
	stock := 10
	stock += 5
	fmt.Printf("после += 5: %v\n", stock)
	stock -= 3
	fmt.Printf("после -= 3: %v\n", stock)
	stock *= 2
	fmt.Printf("после *= 2: %v\n", stock)
	stock /= 5
	fmt.Printf("после /= 5: %v\n", stock)
	stock %= 3
	fmt.Printf("после %%= 3: %v\n", stock)
	stock *= 2 + 1
	fmt.Printf("после *= 2 + 1: %v\n", stock)
	stock++
	fmt.Printf("после ++: %v\n", stock)
	stock--
	fmt.Printf("после --: %v\n", stock)
}

```
```

`/= 5` дало 4, а не 4.8: переменная целая. После `%= 3` осталась единица, и
`*= 2 + 1` умножило её на 3.

## Инкремент и декремент — только инструкции

`x++` называют **инкрементом**, `x--` — **декрементом**. В Go это
**инструкции**, как присваивание: они меняют переменную, но значения не дают.
Поэтому `x++` стоит отдельной строкой и не может стоять там, где нужно
значение. И пишут их только после переменной: записи `++x` в Go нет. Прежде
чем читать дальше, решите по этим двум правилам, соберутся ли три программы
ниже.

```go
@broken inc-in-assignment
```

`syntax error: unexpected ++ at end of statement`: справа от `:=` нужно
значение, а `count++` его не даёт.

```go
@broken inc-in-call
```

`syntax error: unexpected ++ in argument list`: аргумент вызова — тоже
значение.

```go
@broken prefix-inc
```

`syntax error: unexpected ++`: `++` перед переменной не пишут.

Починка одна: увеличить переменную отдельной инструкцией `count++`, а на
следующей строке использовать её новое значение.

## min и max: меньшее и большее

Встроенные функции `min` и `max` возвращают наименьший и наибольший из
аргументов. Как `len` из урока 2.7, они не требуют импорта. Аргументов один
или больше, но не ноль.

Аргументы — **упорядоченного** типа, у которого есть `<`: целые, дробные
числа, строки. У `bool` порядка нет (урок 2.6), и `min(true, false)` не
соберётся. Правило типов то же, что у `+`: `min(x, y)` собирается, когда
собирается `x + y`, и результат того же типа. Литерал принимает тип
переменной, если такое значение в типе есть: `min(count, 2.0)` с `count` типа
`int` даёт `int`, а `min(count, 2.5)` не соберётся.

Прежде чем смотреть вывод, предскажите каждую строку, а в двух последних — и
тип.

```go

### Example: `08-min-max`

Источник: `examples/08-min-max/`

```go
package main

import "fmt"

func main() {
	a := -5
	b := 2
	c := -2
	fmt.Println("min(a, b):", min(a, b))
	fmt.Println("max(a, c):", max(a, c))
	fmt.Println("min(b, b):", min(b, b))
	fmt.Println("min(b, a, c):", min(b, a, c))

	price := 1.5
	fmt.Printf("max(price, 2): %v, тип %T\n", max(price, 2), max(price, 2))
	count := 7
	fmt.Printf("min(count, 2.0): %v, тип %T\n", min(count, 2.0), min(count, 2.0))
}

```
```

При равных аргументах вернулось это же значение. Из отрицательных меньше то,
что дальше от нуля: −5 меньше −2. В `max(price, 2)` литерал 2 стал `float64`,
в `min(count, 2.0)` литерал 2.0 стал `int`.

Переменные разных типов `min` не выравнивает, а вызов без аргументов —
ошибка:

```go
@broken min-mixed-types
```

`invalid argument: mismatched types int (previous argument) and int64 (type of b)`
— то же правило, что для `a + b` в уроке 2.4.

```go
@broken min-no-args
```

`invalid operation: not enough arguments for min() (expected 1, found 0)`.

Главное применение — **ограничить** значение отрезком. `min(want, 8)`
заменяет всё, что больше 8, на 8, а `max(1, ...)` — всё, что меньше 1, на 1.
Вместе `max(1, min(want, 8))` держит число на отрезке от 1 до 8 без единого
`if`. Функция `shelfLevel` ниже так ограничивает ярус стеллажа из восьми
ярусов. Прежде чем смотреть вывод, предскажите ответы за краями отрезка и на
самих краях.

```go

### Example: `09-clamp`

Источник: `examples/09-clamp/`

```go
package main

import "fmt"

// shelfLevel ограничивает номер яруса отрезком от 1 до 8.
func shelfLevel(want int) int {
	return max(1, min(want, 8))
}

func main() {
	want := -3
	fmt.Println("ярус для -3:", shelfLevel(want))
	fmt.Println("ярус для 1:", shelfLevel(1))
	fmt.Println("ярус для 5:", shelfLevel(5))
	fmt.Println("ярус для 8:", shelfLevel(8))
	fmt.Println("ярус для 12:", shelfLevel(12))
	fmt.Println("want после вызова:", want)
}

```
```

Края и числа между ними прошли без изменений, −3 стало 1, 12 стало 8.
Переменная `want` осталась −3: `min` и `max` возвращают новое значение и не

## Понятное выражение и что видят тесты

Сколько коробок нужно для 17 товаров по 5 штук? Три полные и одна для остатка
— 4. Короткая запись — `(items + perBox - 1) / perBox`, но зачем прибавлять
`perBox - 1`, читателю приходится угадывать. Запись с промежуточными именами
идёт по шагам: `full` — полные коробки, `rest` — штуки сверх них, а
`min(rest, 1)` даёт 1, если что-то осталось, и 0, если нет.

Прежде чем смотреть вывод, посчитайте обе функции для четырёх входов.
Совпадут ли они для −3?

```go

### Example: `10-readable`

Источник: `examples/10-readable/`

```go
package main

import "fmt"

// boxesShort считает коробки одним выражением.
func boxesShort(items int, perBox int) int {
	return (items + perBox - 1) / perBox
}

// boxesNamed считает коробки через промежуточные имена.
func boxesNamed(items int, perBox int) int {
	full := items / perBox // полные коробки
	rest := items % perBox // штуки сверх полных коробок
	extra := min(rest, 1)  // 1, если что-то осталось
	return full + extra
}

func main() {
	fmt.Println("17 по 5:", boxesShort(17, 5), boxesNamed(17, 5))
	fmt.Println("15 по 5:", boxesShort(15, 5), boxesNamed(15, 5))
	fmt.Println("0 по 5:", boxesShort(0, 5), boxesNamed(0, 5))
	fmt.Println("-3 по 5:", boxesShort(-3, 5), boxesNamed(-3, 5))
}

```
```

Для 17, 15 и 0 записи совпали, для −3 разошлись: у −3 остаток −3. Обе функции
рассчитаны на число товаров от нуля, и равенство записей держится только на
этой области значений. Есть и различие, невидимое на маленьких числах: если
`items` близко к верхней границе `int`, сумма `items + perBox - 1`
перевернётся (урок 2.4), хотя сам ответ в тип помещается.

Тест вызывает функцию на выбранных входах и сравнивает результат с
ожидаемым. Текста решения он не видит: две записи с одинаковыми ответами для
него неразличимы. О входах, которых он не передавал, тест не говорит ничего.
Что выражение верно на всей области значений и не переполняется, доказывает
рассуждение о границах.

## Биты и глагол %b

Литерал `0b` из урока 2.4 записывает число двоичными цифрами. Биты нумеруют
справа налево с нуля: бит номер k весит 2ᵏ, у `uint8` номера от 0 до 7.

Глагол `%b` печатает целое двоичными цифрами. В `%08b` стоит ширина поля 8 из
урока 2.4, а ноль перед ней дописывает слева нули вместо пробелов: видны все
восемь бит. Глагол `%x` печатает шестнадцатеричные цифры, `%04x` — не меньше
четырёх, с нулями слева.

## Операции над битами

Четыре операции с двумя операндами обрабатывают каждую позицию отдельно: бит
результата номер k зависит только от битов номер k обоих операндов.

- `a & b` — И: бит равен 1, только если он равен 1 в обоих операндах;
- `a | b` — ИЛИ: бит равен 1, если он равен 1 хотя бы в одном операнде;
- `a ^ b` — исключающее ИЛИ: бит равен 1, если биты операндов разные;
- `a &^ b` — сброс: бит `a` остаётся там, где у `b` стоит 0, и обнуляется
  там, где у `b` стоит 1.

Унарная `^a` — **дополнение**: она переворачивает каждый бит. У `uint8`
получается 255 − a, у знаковых типов −a − 1. Двухместная `^` — не степень:
`2^3` равно 1, это исключающее ИЛИ чисел 010 и 011. Операции возведения в
степень в Go нет.

Прежде чем смотреть вывод, вычислите строки с третьей по седьмую: сравнивайте
`a` и `b` столбец за столбцом.

```go

### Example: `11-bits`

Источник: `examples/11-bits/`

```go
package main

import "fmt"

func main() {
	var a uint8 = 0b1100_1100
	var b uint8 = 0b1010_1010
	fmt.Printf("a      %08b\n", a)
	fmt.Printf("b      %08b\n", b)
	fmt.Printf("a & b  %08b\n", a&b)
	fmt.Printf("a | b  %08b\n", a|b)
	fmt.Printf("a ^ b  %08b\n", a^b)
	fmt.Printf("a &^ b %08b\n", a&^b)
	fmt.Printf("^a     %08b\n", ^a)

	var s int8 = 5
	fmt.Println("^s для int8 5:", ^s)
	fmt.Println("2 ^ 3 =", 2^3)
}

```
```

`&&` и `||` из урока 2.6 соединяют значения `bool`, а `&` и `|` работают с
битами целых чисел. Соединить числа через `&&` нельзя:

```go

```

`invalid operation: operator && not defined on a (variable of type int)`.
Нужен результат по битам — пишите `&`; нужно условие — сравнения, например
`a != 0 && b != 0`.

## Сдвиги

**Сдвиг влево** `x << n` передвигает биты `x` на n позиций влево: справа
входят нули, биты за левым краем типа пропадают. **Сдвиг вправо** `x >> n`
передвигает биты вправо, и n правых бит пропадают; у беззнакового `x` слева
входят нули. Счётчик n — значение любого целого типа, не меньше нуля. Счётчик
больше ширины типа при сдвиге переменной — не ошибка, и язык не урезает его:
сдвиг идёт так, будто биты n раз сдвинули на одну позицию, и у `uint8` после
восьми позиций не остаётся ни одной единицы.

Прежде чем смотреть вывод, выпишите `u` двоичными цифрами и получите строки со
второй по пятую. Счётчик 9 лежит в переменной `nine`, как если бы его
вычислили во время работы.

```go

### Example: `12-shifts`

Источник: `examples/12-shifts/`

```go
package main

import "fmt"

func main() {
	var u uint8 = 0b1011_0001
	nine := 9 // счётчик сдвига хранится в переменной
	fmt.Printf("u      %08b\n", u)
	fmt.Printf("u << 1 %08b\n", u<<1)
	fmt.Printf("u >> 3 %08b\n", u>>3)
	fmt.Printf("u << 9 %08b\n", u<<nine)
	fmt.Printf("u >> 9 %08b\n", u>>nine)
}

```
```

У знакового `x` сдвиг вправо заполняет позиции слева копией самого левого
бита — **знакового**. Каков этот бит у отрицательного числа, следует из
переворота в уроке 2.4: значение v < 0 типа `int8` хранится теми же битами,
что значение v + 256 типа `uint8`. Поэтому −16 хранится битами числа 240,
`11110000`, и левый бит равен 1. `s >> 1` даёт `11111000`, то есть
248 − 256 = −8. У `uint8` с теми же битами слева вошёл бы ноль: `01111000`,
то есть 120.

Прежде чем смотреть вывод, сверьте со своим расчётом строки со сдвигом на 1 и
предскажите две строки со счётчиком 100; помните, что знаковый сдвиг
размножает левый бит.

## Маски: флаги посылки

Байт посылки хранит три свойства в трёх битах: хрупкое — бит 0, срочное — бит
1, негабарит — бит 2. Бит равен 1, если свойство есть. Число с единицами ровно
в нужных битах называют **маской**. Маска бита номер k — `1 << k`: `1 << 2` —
это `00000100`.

С маской `m` делают четыре действия:

- поставить бит: `flags |= m` — ИЛИ с единицей даёт 1, другие биты не
  меняются;
- проверить бит: `flags&m != 0` — И оставляет только бит маски; скобки не
  нужны, потому что `&` сильнее `!=`;
- снять бит: `flags &^= m` — сброс обнуляет бит маски;
- переключить бит: `flags ^= m` — исключающее ИЛИ с единицей переворачивает
  бит.

Прежде чем смотреть вывод, ведите байт `parcel` бит за битом после каждой
строки. Что сделает повторное снятие того же флага?

```go

### Example: `16-flags`

Источник: `examples/16-flags/`

```go
package main

import "fmt"

func main() {
	var fragile uint8 = 1 << 0  // 00000001 — хрупкое
	var urgent uint8 = 1 << 1   // 00000010 — срочное
	var oversize uint8 = 1 << 2 // 00000100 — негабарит

	var parcel uint8 // все флаги сняты
	parcel |= fragile
	parcel |= oversize
	fmt.Printf("хрупкое и негабарит: %08b\n", parcel)
	fmt.Println("срочное?", parcel&urgent != 0)
	fmt.Println("негабарит?", parcel&oversize != 0)
	parcel &^= fragile
	fmt.Printf("сняли хрупкое:       %08b\n", parcel)
	parcel &^= fragile
	fmt.Printf("сняли ещё раз:       %08b\n", parcel)
	parcel ^= urgent
	fmt.Printf("переключили срочное: %08b\n", parcel)
}

```
```

Повторное снятие ничего не изменило: бит уже был нулём. `|=` и `&^=` задают
нужное состояние бита, и прежнее знать не нужно; результат `^=` от него
зависит.

## Упаковка двух байтов в одно число

Ярлык стеллажа хранит ряд и полку в одном 16-битном числе: ряд в старших
восьми битах, полку в младших. Запись `uint16(row)<<8 | uint16(shelf)`
читается так:

1. `uint16(row)` — преобразование из урока 2.9: значение ряда в 16-битном
   числе, старшие восемь бит которого равны нулю.
2. `<<8` уводит ряд в старшие восемь бит, младшие заполняются нулями.
3. `| uint16(shelf)` кладёт полку в младшие биты. Биты ряда и полки не
   пересекаются, и ИЛИ просто соединяет их.

Скобки не нужны: `<<` сильнее `|`. Распаковка обратная: `label >> 8`
возвращает ряд в младшие биты, а `label & 0xFF` сохраняет младшие восемь бит,
потому что `0xFF` — восемь единиц, `11111111`. Оба результата лежат от 0 до
255, и `byte(...)` переводит их в байт без потерь.

Последняя строка программы сдвигает ряд до преобразования: `row<<eight`
считается в типе `byte`. Прежде чем смотреть вывод, решите, что останется от
ряда.

```go

### Example: `17-pack`

Источник: `examples/17-pack/`

```go
package main

import "fmt"

func main() {
	var row byte = 0x12   // ряд стеллажа
	var shelf byte = 0x34 // полка в ряду
	label := uint16(row)<<8 | uint16(shelf)
	fmt.Printf("ярлык: %04x\n", label)
	fmt.Printf("ряд: %02x, полка: %02x\n", byte(label>>8), byte(label&0xFF))

	eight := 8 // счётчик в переменной, как в примере 12-shifts
	wrong := uint16(row<<eight) | uint16(shelf)
	fmt.Printf("сдвиг до преобразования: %04x\n", wrong)
}

```
```

`%04x` показал ярлык: 12 — ряд, 34 — полка. В последней строке ряд пропал: у
`byte` восемь бит, и сдвиг на 8 вытолкнул их все, как сдвиг на 9 в примере
`12-shifts`. Сначала расширяют тип, потом сдвигают.

## CarouselCell

Карусель склада — кольцо из `size` ячеек с номерами от 0 до `size − 1`.
Указатель стоит на ячейке 0. Команда поворачивает карусель на `steps` ячеек:

грузоподъёмности. Табло умеет показывать только числа от 0 до 100, поэтому
процент меньше 0 оно показывает как 0, а больше 100 — как 100. Замечать ошибку
датчика здесь не нужно: табло требует именно ограничения.

- `FillPercent(25, 50)` возвращает 50;
- `FillPercent(1, 3)` возвращает 33;
- `FillPercent(75, 50)` возвращает 100;
- `FillPercent(-10, 50)` возвращает 0.

## PackCell

Ячейка стеллажа задаётся рядом и местом в ряду, оба от 0 до 15. Номер ячейки
хранится в одном байте: ряд — в старших четырёх битах, место — в младших
четырёх. `PackCell` получает ряд и место и возвращает этот байт.

- `PackCell(1, 2)` возвращает `0x12`, то есть `00010010`;
- `PackCell(15, 15)` возвращает `0xFF`;
- `PackCell(15, 0)` возвращает `0xF0`;
- `PackCell(0, 0)` возвращает 0.

## CellSlot

`CellSlot` получает байт ячейки и возвращает место — число из его младших
четырёх бит, от 0 до 15. Старшие четыре бита, ряд, в ответ не входят.

- `CellSlot(0x12)` возвращает 2;
- `CellSlot(0xFF)` возвращает 15;
- `CellSlot(0xF0)` возвращает 0;
- `CellSlot(0)` возвращает 0.

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## CarouselCell

**Ступень 1.** Посчитайте `steps % size` для `steps` = 12, −1 и −5 при
`size` = 5. Какие ответы уже годятся как номер ячейки? Каким числом от 0 до 4
должен стать отрицательный остаток, и на сколько он отличается от нужного
номера?

**Ступень 2.** Отрицательный остаток лежит от −(size − 1) до 0, и прибавление
`size` переводит его в нужный отрезок. Но у положительного остатка то же
прибавление выводит ответ за `size − 1`, поэтому сумму ещё раз берут по
модулю `size` операцией `%`. Ошибаются, останавливаясь на `steps%size + size`:
для `steps` = 5 и `size` = 5 получится 5, а не 0.

## FillPercent

**Ступень 1.** Для `load` = 25 и `capacity` = 50 посчитайте по правилам целого
деления `load / capacity * 100` и `load * 100 / capacity`. Какая запись теряет
дробную часть раньше времени? Затем назовите два края, которые не должно
переходить табло.

**Ступень 2.** Сначала умножение, потом деление: у `*` и `/` один уровень, и
группировка идёт слева направо. Процент затем ограничивают отрезком от 0 до 100
парой `min` и `max`, как ярус в разделе «min и max: меньшее и большее».
Ошибаются, забывая один из краёв: без `max` груз −10 кг из 50 даст −20, без
`min` груз 75 кг из 50 даст 150.

## PackCell

**Ступень 1.** Выпишите `0x12` двоичными цифрами. В каких битах стоит ряд 1, а
в каких — место 2? На сколько позиций ряд сдвинут относительно своего обычного
места?

**Ступень 2.** Ряд сдвигают влево на 4 и соединяют с местом через `|`, как ряд
и полку ярлыка в разделе «Упаковка двух байтов в одно число». Преобразование
здесь не нужно: ряд до 15 после сдвига на 4 помещается в `byte`. Ошибаются,
меняя ряд и место ролями: тогда `PackCell(1, 2)` вернёт `0x21`.

## CellSlot

**Ступень 1.** Какие биты байта хранят место? Какое число, записанное
двоичными цифрами, имеет единицы ровно в этих битах и нули во всех остальных?

**Ступень 2.** Нужна маска младших четырёх бит, `0x0F`, то есть `00001111`, и
операция `&`: она сохраняет биты под единицами маски и обнуляет остальные.
Ошибаются, беря сдвиг `>> 4`: он возвращает ряд, а не место.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Что видят тесты

<!-- review:tests-observe -->

Вопросы из постановки: почему умножение стоит до деления, чем ответ карусели
отличается от остатка и что тесты скажут о двух записях одной функции.
Образец ответа ниже.

В `FillPercent` целое деление отбрасывает дробную часть сразу. Если сначала
разделить 25 на 50, получится 0, и умножение на 100 уже ничего не вернёт.
Умножение первым сохраняет сотые доли: `25 * 100 / 50` даёт 50. Произведение
при этом не переполняется: по постановке оно не больше 1 000 000 000.

В `CarouselCell` остаток `steps % size` при отрицательном `steps` либо
отрицателен, либо равен нулю. Для `steps` = −1 и `size` = 5 он равен −1, а
ячейки с таким номером нет: шаг назад от ячейки 0 ведёт на ячейку 4. Поэтому
остаток сдвигают на `size` и снова берут по модулю:
`(steps%size + size) % size`.

Если `FillPercent` записать одной строкой, а коллега заведёт промежуточную
переменную `percent`, тесты не отличат эти решения: они сравнивают только
возвращённые значения. Тест не скажет, какая запись понятнее, и не проверит
входы, которых не передавал. Что решение верно на всей области допустимых
значений, показывает рассуждение о границах, а прошедшие тесты подтверждают
его на своих входах.

## Остаток вместо номера ячейки

<!-- review:carousel-plain-remainder -->

Решение `return steps % size` верно для `steps` от нуля: 12 даёт 2. Для
отрицательного `steps` остаток отрицателен или равен нулю: −5 даёт верный 0,
но шаг назад на одну ячейку даёт −1.

Ловит это `TestCarouselCell` на входе `CarouselCell(-1, 5)`: тест ждёт 4, а
получает −1. Отрицательный остаток сдвигают на `size`, а затем берут по модулю
ещё раз: `return (steps%size + size) % size`.

## Сдвинули, но не вернули в отрезок

<!-- review:carousel-no-second-remainder -->

Решение `return steps%size + size` чинит отрицательные остатки, но портит
остальные: для `steps` = 0 оно возвращает 5, а ячейки 5 у карусели из пяти
ячеек нет.

Ловит это `TestCarouselCell` на входе `CarouselCell(0, 5)`: тест ждёт 0, а
получает 5. Сумма лежит от 1 до `2*size − 1`, и второй `% size` возвращает её в
отрезок от 0 до `size − 1`.

## Деление раньше умножения

<!-- review:fill-divide-first -->

Решение считает `load / capacity * 100`. `/` и `*` стоят на одном уровне и
группируются слева направо, поэтому сначала выполняется целое деление, и
дробная часть пропадает до умножения: 25 / 50 даёт 0.

Ловит это `TestFillPercent` на входе `FillPercent(25, 50)`: тест ждёт 50, а
получает 0. Умножение ставят первым: `load * 100 / capacity`.

## Забыт нижний край

<!-- review:fill-no-lower -->

Решение `return min(load*100/capacity, 100)` не пропускает перегруз, но не
ограничивает процент снизу: −10 кг при грузоподъёмности 50 кг дают −20. Не
каждый отрицательный груз это покажет: −1 кг из 1 000 000 после отбрасывания
дробной части даёт 0.

Ловит это `TestFillPercent` на входе `FillPercent(-10, 50)`: тест ждёт 0, а
получает −20. Нижний край добавляют через `max`:
`max(0, min(load*100/capacity, 100))`.

## Забыт верхний край

<!-- review:fill-no-upper -->

Решение `return max(0, load*100/capacity)` отсекает отрицательные значения, но
не ограничивает процент сверху: 75 кг при грузоподъёмности 50 кг дают 150.
Небольшой перегруз может этого не показать: 1 000 001 кг из 1 000 000 дают
ровно 100.

Ловит это `TestFillPercent` на входе `FillPercent(75, 50)`: тест ждёт 100, а
получает 150. Верхний край добавляют через `min`.

## Ряд и место поменялись ролями

<!-- review:pack-swapped -->

Решение `return slot<<4 | row` кладёт место в старшие биты, а ряд — в
младшие. На ряде и месте, равных друг другу, ошибка не видна: `PackCell(15, 15)`
вернёт `0xFF`, как и нужно.

Ловит это `TestPackCell` на входе `PackCell(1, 2)`: тест ждёт `0x12`, а
получает `0x21`. Постановка отдаёт старшие биты ряду: `return row<<4 | slot`.

## И вместо ИЛИ

<!-- review:pack-and -->

Решение `return row<<4 & slot` сдвигает ряд верно, но соединяет половины через
`&`. После сдвига у ряда единицы только в старших битах, у места — только в
младших, общих единиц нет, и И даёт ноль.

Ловит это `TestPackCell` на входе `PackCell(15, 15)`: тест ждёт `0xFF`, а
получает 0. Непересекающиеся половины соединяет `|`.

## Ряд вместо места

<!-- review:slot-high -->

Решение `return cell >> 4` сдвигает байт вправо на 4: младшие биты, в которых
лежит место, пропадают, а на их место приходит ряд.

Ловит это `TestCellSlot` на входе `CellSlot(0x12)`: тест ждёт 2, а получает 1.
Место не надо сдвигать, его надо вырезать маской: `return cell & 0x0F`.

## Маска не той половины

<!-- review:slot-mask-high -->

Решение `return cell & 0xF0` берёт маску `11110000`: она сохраняет старшие
биты, то есть ряд, и обнуляет место.

Ловит это `TestCellSlot` на входе `CellSlot(0xFF)`: тест ждёт 15, а получает
240. Единицы маски ставят над битами, которые нужно сохранить: для места это
`0x0F`, `00001111`.

## Вопрос 3

Как Go сгруппирует выражения `base + count*4<<1` и `flags&mask == 0`?

Варианты ответа:

- A. `base + ((count*4) << 1)` и `(flags&mask) == 0`.
- B. `(base + count*4) << 1` и `flags & (mask == 0)`.
- C. `((base + count) * 4) << 1` и `(flags&mask) == 0`.
- D. `base + (count * (4 << 1))` и `flags & (mask == 0)`.

Прежде чем смотреть ответ, назовите уровень приоритета каждой операции в обоих
выражениях и вспомните, как группируются операции одного уровня.

**Правильный ответ: A.**

`*` и `<<` стоят на уровне 5, `+` — на уровне 4. Поэтому сначала
группируется `count*4<<1`, слева направо: `(count*4) << 1`, и только потом
прибавляется `base`. `&` тоже на уровне 5, а `==` — на уровне 3, поэтому с
нулём сравнивается `flags&mask`. Вариант B берёт правило некоторых других
языков, где сдвиг слабее сложения; в Go сдвиг и `&` сильнее и сложения, и
сравнения. Вариант C группирует всё
строго слева направо, не глядя на уровни. Вариант D группирует операции одного
уровня справа налево.

## Вопрос 7

Объявлены `var a int = 4`, `var b int64 = 9` и `level := 12`. Какие из вызовов
соберутся?

1. `max(1, min(level, 8))`
2. `min(a, b)`
3. `min()`
4. `min(level, 2.5)`
5. `max(a, -a)`

Варианты ответа:

- A. Первый и пятый. Первый вернёт 8, а при `level`, равном −3, вернул бы 1;
  пятый вернёт 4.
- B. Первый, второй и пятый: `min` сама приведёт `int` к `int64`. Первый
  вернёт 8, пятый — 4.
- C. Все, кроме третьего. Первый вернёт 8, четвёртый — 2, пятый — 4.

Прежде чем смотреть ответ, для каждого вызова назовите типы аргументов и
решите, собралось бы с теми же операндами выражение через `+`. Затем почините
второй и третий вызовы так, чтобы они собрались.

поэтому 12 становится 8, а −3 стало бы 1. `max(a, -a)` сравнивает 4 и −4 одного
типа `int`. `a + b` не собирается из-за разных типов, значит и `min(a, b)` не
соберётся. Чинят его преобразованием из урока 2.9, которое приводит оба
аргумента к одному типу: `min(int64(a), b)`. `min()` требует хотя бы один
аргумент: починка передаёт те значения, из которых нужно выбрать, например
`min(a, level)`. Литерал 2.5 не может стать
значением `int`, поэтому четвёртый вызов не соберётся. Вариант B приписывает
`min` приведение типов, которого нет. Вариант C считает, что 2.5 округлится.
Вариант D ждёт дробного результата от вызова, чей тип задаёт переменная `int`.

## Вопрос 8

```go
@quiz _quiz/03-bits
```

Что напечатает программа?

Варианты ответа:

- A. `00000111`, `00000001` и `00000011`.
- B. `00000111`, `00000010` и `00000011`.
- C. `00000100`, `00000001` и `00000011`.
- D. `00000111`, `00000001` и `00000100`.

Прежде чем смотреть ответ, запишите `flags` и `mask` друг под другом и
вычислите каждую из трёх операций столбец за столбцом.

**Правильный ответ: A.**

`flags` — `00000101`, `mask` — `00000110`. ИЛИ ставит 1 там, где единица хотя

и 1. Вариант B сбрасывает биты не в `flags`, а в `mask`. Вариант C путает `|`
с `&`: И дало бы только общий бит 2. Вариант D путает `^` с `&`.

## Вопрос 9

```go
@quiz _quiz/04-shifts
```

Что напечатает программа?

Варианты ответа:

- A. −4, 60 и 0.
- B. 60, 60 и 0: у `s` и `t` одинаковые биты, значит одинаков и сдвиг.
- C. −4, 60 и 256.
- D. −4, 60, а затем паника: счётчик 8 не меньше ширины `uint8`.

Прежде чем смотреть ответ, выпишите биты `s` и `t` и для каждого сдвига
скажите, что входит слева или справа и что пропадает.

**Правильный ответ: A.**

У `s` и `t` одни и те же биты `11110000`. Знаковый `s` при сдвиге вправо
получает слева копии единицы: `11111100`, то есть 252 − 256 = −4. Беззнаковый
`t` получает нули: `00111100`, то есть 60. Единица в `uint8`, сдвинутая на 8
позиций, выходит за левый край, и остаётся 0. Вариант B не различает знаковый
и беззнаковый сдвиг. Вариант C забывает, что у `uint8` восемь бит. Вариант D
считает большой счётчик ошибкой, хотя паникует только отрицательный.

## Вопрос 10

Коллега заменил `(items + perBox - 1) / perBox` записью с промежуточными
именами `full`, `rest` и `min(rest, 1)`, как в примере `10-readable`. Тесты
передают пары 17 и 5, 15 и 5, 0 и 5 и проходят для обеих записей. Что
доказывает этот результат?

Варианты ответа:

- A. Записи равны для любых целых `items` и `perBox`, раз совпали на трёх
  входах.
- B. Записи дали ожидаемые ответы на трёх входах; об остальных входах и о
  тексте решений тесты ничего не говорят.
- C. Тесты подтвердили, что вторая запись вызывает `min`, а первая — нет.
- D. Промежуточные суммы не переполнятся ни на каком входе, раз тесты прошли.

Прежде чем смотреть ответ, назовите, что тест передаёт функции и что получает
обратно, и скажите, чего он при этом не видит.

**Правильный ответ: B.**

Тест видит только возвращённые значения на своих входах. Для −3 товаров записи
уже расходятся, а короткая запись при `items` у верхней границы `int`
переполнит сумму `items + perBox - 1`. Равенство на области `items` от нуля и
отсутствие переполнения доказывает рассуждение о границах, а не три прогона.
Вариант A обобщает три входа на все. Вариант C приписывает тесту чтение кода.
Вариант D выводит из прошедших тестов обещание о входах, которых тесты не
передавали.
