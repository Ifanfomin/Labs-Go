# Строки: первое знакомство

Кофейня печатает на каждом стакане этикетку: имя гостя, двоеточие, пробел и
напиток, например «Анна: латте». Со строкой этикетки программа делает три
вещи. Собирает её из кусков. Проверяет, поместится ли она в поле принтера, а
принтер меряет поле не буквами, а байтами. И сверяет код заказа, который назвал
гость, с кодом в системе. Для всех трёх действий нужно знать, что на самом деле
лежит в значении типа `string`.

Строки вы уже встречали: литералы в двойных кавычках (урок 1.3), параметры типа
`string` и склейку `+` (урок 1.7), экранирование и глагол `%q` (урок 1.9),
переменные и присваивание (уроки 2.1 и 2.2), сравнение `==` (урок 2.6). Этот
урок показывает, как строка устроена внутри. К концу урока вы сможете:

- объяснить, почему переменная со строкой меняется, хотя сама строка
  неизменяема;
- предсказать результат склейки `+` и число, которое вернёт `len`;
- сказать, какие байты даёт литерал в двойных и в обратных кавычках;
- отличить пустую строку от строки из пробела или перевода строки;
- предсказать, равны ли две строки, и объяснить ответ через байты;
- объяснить, когда склейка обходится дорого и почему строку не режут по байтам.

Примеры печатают через `fmt.Println` и `fmt.Printf` с глаголами `%q`, `%d` и
`%T` из уроков 1.9, 2.1 и 2.4. Код примеров можно изменить и запустить снова;
такие опыты ничем не проверяются.

## Что лежит в строке

Значение типа `string` — это последовательность байтов. **Байт** — восемь
битов, то есть целое число от 0 до 255, как значение восьмибитного беззнакового
целого из урока 2.4. Текст в строке обычно записан такими числами по правилу,
которое называется **UTF-8**: каждая буква, цифра, пробел и знак становятся
одним или несколькими байтами. Исходный код на Go хранится в UTF-8, поэтому
строка из литерала с русскими буквами хранит их байты UTF-8. Правильным UTF-8
строка быть не обязана: она может хранить любые байты, и как такая строка
получается, показывает раздел об экранировании байта.

Сколько байтов в строке, сообщает встроенная функция `len`. Встроенная —
значит, её объявил сам язык: её не импортируют и вызывают без имени пакета,
например `len(word)`. Результат — число типа `int`. У пустой строки `""` он
равен нулю.

Программа ниже печатает несколько строк через `%q` и для каждой — результат
`len`. Прежде чем смотреть вывод, посчитайте в каждой строке видимые знаки —
буквы и пробелы — и запишите эти числа. Потом сравните их с тем, что вернула
`len`.

```go

### Example: `01-len`

Источник: `examples/01-len/`

```go
package main

import "fmt"

func main() {
	latin := "Go"
	phrase := "a b"
	cyrillic := "Го"
	word := "Привет"
	mixed := "Go и Го"

	fmt.Printf("%q — байтов: %d\n", latin, len(latin))
	fmt.Printf("%q — байтов: %d\n", phrase, len(phrase))
	fmt.Printf("%q — байтов: %d\n", cyrillic, len(cyrillic))
	fmt.Printf("%q — байтов: %d\n", word, len(word))
	fmt.Printf("%q — байтов: %d\n", mixed, len(mixed))
	fmt.Printf("тип результата len: %T\n", len(word))
}

```
```

Для `"Go"` и `"a b"` ваш счёт совпал с выводом: латинская буква и пробел
занимают по одному байту. В строках с русскими буквами байтов больше, чем
видимых знаков: в `"Го"` две буквы и четыре байта, в `"Привет"` шесть букв и
двенадцать байтов. Последняя строка вывода называет тип результата `len`.

Значит, `len` считает не буквы, а байты. Это разные величины: на латинице они
совпали, а на русских словах разошлись. Поле принтера меряется байтами,
поэтому для него `len` — верная мера. А вот сколько букв увидит гость на
стакане, по `len` не узнать.

## Почему русская буква занимает два байта

У каждого символа Unicode есть номер — **кодовая точка**. Её записывают как
`U+` и номер в шестнадцатеричной системе: у заглавной русской П это U+041F.
UTF-8 — правило, по которому кодовая точка записывается байтами. Маленьким
номерам хватает одного байта, большим нужно от двух до четырёх:

| Что | Байтов в UTF-8 |
|---|---|
| символ ASCII: латинская буква, цифра, пробел, знаки вроде `,` `.` `:` `!` `"` `\`, перевод строки, табуляция | 1 |
| буква русского алфавита, включая «ё» | 2 |
| некоторые другие символы, например знак евро € | 3 |
| символы с самыми большими номерами | 4 |

**ASCII** — старая таблица из 128 символов: латинские буквы, цифры, пробел,
знаки препинания с латинской клавиатуры и несколько управляющих символов вроде
перевода строки. UTF-8 записывает каждый из них одним байтом, как и сама
таблица. Всё, чего в ASCII нет, занимает больше одного байта: русские буквы,
кавычки-ёлочки, длинное тире.

Отсюда правило подсчёта для текста из латиницы и русских букв: один байт на
символ ASCII, два — на русскую букву. Для строки `"Go и Го"` из первой
программы это 2 + 1 + 2 + 1 + 4 = 10.

Слово «символ» здесь легко понять неоднозначно. На деле речь о трёх разных
вещах:

- байты — то, что хранит строка и считает `len`;
- кодовые точки — номера Unicode; каждая записана одним или несколькими
  байтами;
- знак, который читатель видит на экране. Обычно за ним стоит одна кодовая
  точка, но не всегда: в разделе о равенстве встретится знак из двух кодовых
  точек.

Для этого урока нужны байты. Тип `rune` для одной кодовой точки разбирает урок
2.8, а перебор кодовых точек строки и их подсчёт — уроки 9.1–9.3.

## Значение не меняется, переменная — меняется

Строки в Go **неизменяемы**: созданное значение типа `string` поменять нельзя —
ни байт внутри него, ни его длину. Но переменную со строкой вы меняли ещё в
уроке 2.1: `title = title + "!"`. Противоречия нет, потому что это разные вещи.
Присваивание кладёт в переменную другое значение. Прежнее значение при этом не
меняется: если его хранит ещё какая-то переменная, там оно и остаётся.

Программа ниже проделывает это с двумя парами переменных. В первой паре `b`
объявлена от `a`, а потом `a` получает другое слово. Во второй паре `c`
получает склейку своего значения с буквой. Прежде чем смотреть вывод,
предскажите обе строки: что окажется в `b` и в `d`?

```go

### Example: `02-reassign`

Источник: `examples/02-reassign/`

```go
package main

import "fmt"

func main() {
	a := "кот"
	b := a
	a = "пёс"
	fmt.Printf("a = %q, b = %q\n", a, b)

	c := "кот"
	d := c
	c = c + "ы"
	fmt.Printf("c = %q, d = %q\n", c, d)
}

```
```

Первая пара по шагам:

1. `a := "кот"` — в `a` строка из трёх русских букв, шесть байтов.
2. `b := a` — `b` получает то значение, которое сейчас лежит в `a`.
3. `a = "пёс"` — в `a` кладётся другое значение. Значение `"кот"` от этого не
   изменилось, и в `b` оно осталось.

Во второй паре правая часть `c + "ы"` строит новую строку: сначала байты
`"кот"`, затем байты `"ы"`. Присваивание кладёт её в `c`. Значение `"кот"`,
которое хранит `d`, склейка не трогает: `+` создаёт новое значение, а не
дописывает байты в старое.

Изменить байт внутри строки язык не даёт вовсе. Программа ниже пытается это
сделать. Запись `s[0]` обозначает байт строки с номером 0, самый первый;
номера байтов разбирают уроки 9.2–9.3. `'x'` в одинарных кавычках — литерал
одного символа, его разбирает урок 2.8. Здесь важен только ответ компилятора.
Прежде чем читать сообщение, скажите, соберётся ли программа.

```go
@broken assign-byte
```

Не соберётся: записать байт в строку язык не позволяет. Компилятор сообщает
об этом, например, так:
`cannot assign to s[0] (neither addressable nor a map index expression)` —
«нельзя присвоить `s[0]`». Байт строки можно прочитать, но записать в него
нельзя. Чтобы в переменной оказался другой текст, программа строит новое
значение и присваивает его переменной.

## Склейка + копирует байты как есть

В уроке 1.7 оператор `+` склеивал строки: сначала символы левой части, затем
правой. Теперь это правило можно сказать точно: `+` создаёт новую строку, в
которой сначала идут все байты левого операнда, затем все байты правого. Больше
ничего в неё не попадает: ни пробела, ни перевода строки. Поэтому длина
результата равна сумме длин частей.

Программа ниже склеивает `"Привет,"` и `"мир"` дважды: вплотную и через
литерал с пробелом. Прежде чем смотреть вывод, предскажите обе склеенные строки
и четыре числа байтов — для каждой части и для каждого результата. Запятая и
пробел занимают по одному байту.

```go

### Example: `03-concat`

Источник: `examples/03-concat/`

```go
package main

import "fmt"

func main() {
	left := "Привет,"
	right := "мир"
	glued := left + right
	spaced := left + " " + right

	fmt.Printf("%q\n", glued)
	fmt.Printf("%q\n", spaced)
	fmt.Println("байтов:", len(left), len(right), len(glued), len(spaced))
	fmt.Printf("left по-прежнему %q\n", left)
}

```
```

Первая склейка поставила слова вплотную: пробел в результате появляется только
тогда, когда он есть в одной из частей. Во второй склейке пробел пришёл из
среднего литерала `" "`. Числа сходятся: 13 + 6 = 19, и ещё один байт пробела
даёт 20. Последняя строка вывода показывает, что `left` после обеих склеек
хранит прежнее значение.

В программе ниже к строке прибавляют переменную типа `int`. Прежде чем читать
сообщение, скажите, соберётся ли программа и почему.

```go
@broken concat-number
```

Программа не соберётся: строку и `int` оператор `+` не складывает. Компилятор
сообщает, например:
`invalid operation: "n=" + k (mismatched types untyped string and int)`.
Это сообщение говорит, что у операндов разные типы: строковый литерал и
`int`. Как и в уроке 2.1, строка и число не склеиваются: `+` соединяет строку
только со строкой и число в текст не превращает. Чтобы вставить число в текст,
строку собирают через `fmt.Sprintf` из урока 1.9 с глаголом `%d` из урока 2.4:
`fmt.Sprintf("n=%d", k)`.

## Две записи строкового литерала

Строковый литерал в Go записывают двумя способами.

**Интерпретируемый литерал** стоит в двойных кавычках; такие вы пишете с урока
1.3. Обратная косая черта в нём начинает экранирование: `\n` — перевод строки,
`\t` — табуляция, `\"` — двойная кавычка, `\\` — сама обратная косая черта.
Каждая из этих четырёх записей занимает в исходном коде два знака, а в значении
даёт один байт. Настоящий перевод строки внутри двойных кавычек поставить
нельзя: такой литерал обязан уместиться в одну строку исходного кода. Обратная
косая черта перед знаком, для которого экранирования нет, — ошибка сборки.

**Сырой литерал** стоит в обратных кавычках, например `` `C:\new` ``. Обратная
косая черта в нём ничего особого не значит: знаки между кавычками попадают в
значение как написаны. Сырой литерал может занимать несколько строк исходного
кода, и переводы строк становятся байтами значения. Одно исключение касается
самого файла: если между обратными кавычками стоит настоящий невидимый символ
возврата каретки, в значение сырого литерала он не попадает, где бы он ни
стоял. Чаще всего такой символ оказывается в файле с окончаниями строк CRLF:
там он стоит перед каждым переводом строки. Запись `\r`, набранная внутри
обратных кавычек двумя знаками, — это обратная косая черта и `r`. Она
остаётся двумя байтами, как `\n` в `` `a\nb` ``. Обратную кавычку внутрь
сырого литерала не поставить: она его закончила бы.

Запись литерала — это исходный код, а не значение. Одно значение можно
записать по-разному, и тогда `%q` покажет одно и то же: он печатает любую
строку как интерпретируемый литерал. Перевод строки `%q` пишет как `\n`,
табуляцию — как `\t`, обратную косую черту — как `\\`.

Программа ниже ставит рядом запись в исходном коде, значение через `%q` и
длину. Прежде чем смотреть вывод, для каждой переменной перечислите байты,
которые даёт её запись, и предскажите строку вывода. Для `mixed` отдельно
ответьте: превратит ли `+` сырое `\t` в табуляцию?

```go

### Example: `04-literals`

Источник: `examples/04-literals/`

```go
package main

import "fmt"

func main() {
	interpreted := "a\nb"
	raw := `a\nb`
	fmt.Printf("%q, байтов: %d\n", interpreted, len(interpreted))
	fmt.Printf("%q, байтов: %d\n", raw, len(raw))

	path := `C:\new`
	escaped := "C:\\new"
	fmt.Printf("%q, байтов: %d\n", path, len(path))
	fmt.Println("path == escaped:", path == escaped)

	lines := `one
two`
	fmt.Printf("%q, байтов: %d\n", lines, len(lines))

	mixed := "a\tb" + `\t`
	fmt.Printf("%q, байтов: %d\n", mixed, len(mixed))
}

```
```

Сравните по строкам:

- `"a\nb"` в двойных кавычках — три байта: `a`, перевод строки, `b`. `` `a\nb` ``
  в обратных — четыре: `a`, обратная косая черта, `n`, `b`. Похожие записи
  дали разные значения.
- `` `C:\new` `` и `"C:\\new"` — две записи одного значения из шести байтов, и
  `==` подтверждает равенство.
- Сырой литерал на двух строках исходного кода дал перевод строки внутри
  значения — тот же байт, что `\n`.
- `mixed` склеен из трёх байтов `"a\tb"` и двух байтов `` `\t` ``. `+` копирует
  байты и не читает их как запись литерала, поэтому обратная косая черта и `t`
  остались двумя байтами.

## Экранирование байта и экранирование символа

Кроме `\n` и `\t`, у интерпретируемого литерала есть экранирования, которые
задают байт или кодовую точку числом:

- `\x` и две шестнадцатеричные цифры задают **один байт** с этим значением:
  `\x41` — байт 0x41, то есть латинская `A`, а `\xff` — байт 255;
- `\u` и четыре шестнадцатеричные цифры задают **кодовую точку**, и в строку
  попадает её запись в UTF-8 — от одного до трёх байтов.

Спецификация Go приводит такую пару: `\xFF` — один байт 0xFF, а `\u00FF` —
буква ÿ, чья запись в UTF-8 — два байта, 0xc3 и 0xbf. Ещё одна пара байтов
понадобится ниже: слово «Привет» начинается байтами 0xd0 и 0x9f, и эти два
байта — запись буквы П, кодовой точки U+041F.

Программа ниже сравнивает такие записи. Прежде чем смотреть вывод, предскажите
`len` каждой строки и результаты двух сравнений и объясните каждый ответ через
байты. Как `%q` показывает байт, который не складывается в букву, сказано после
вывода.

```go

### Example: `05-escapes`

Источник: `examples/05-escapes/`

```go
package main

import "fmt"

func main() {
	byteEsc := "\xff"
	unicodeEsc := "\u00ff"
	fmt.Printf("%q, байтов: %d\n", byteEsc, len(byteEsc))
	fmt.Printf("%q, байтов: %d\n", unicodeEsc, len(unicodeEsc))
	fmt.Println("byteEsc == unicodeEsc:", byteEsc == unicodeEsc)

	bytesP := "\xd0\x9f"
	unicodeP := "\u041f"
	fmt.Printf("%q, байтов: %d\n", bytesP, len(bytesP))
	fmt.Println("bytesP == unicodeP:", bytesP == unicodeP)

	firstByte := "\xd0"
	fmt.Printf("%q, байтов: %d\n", firstByte, len(firstByte))
}

```
```

Разбор:

1. `byteEsc` — один байт 255, `unicodeEsc` — два байта буквы ÿ. Число байтов
   разное, значит, и строки разные. Одинаковые цифры `ff` не делают записи
   равными: `\x` задаёт байт, `\u` — кодовую точку.
2. `bytesP` записана двумя байтами, `unicodeP` — кодовой точкой, но байты у них
   одни и те же, поэтому строки равны. `%q` показал букву П: эти два байта — её
   правильная запись в UTF-8.
3. `firstByte` — один байт 0xd0, первая половина буквы П. Сам по себе он не
   складывается ни в одну кодовую точку, и `%q` печатает его экранированием
   `\xd0`, а не буквой.

Отсюда важная граница. Строка Go — последовательность любых байтов, и
правильным UTF-8 она быть не обязана. Литерал без `\x` (и без восьмеричных
экранирований вида `\377`, которые в уроке не нужны) даёт правильный UTF-8. А
через `\x` можно законно записать байт, который буквой не является. `\u` такого
не позволяет: номер, недопустимый для кодовой точки, например `\uD800`, сборка
отвергает.

## Пустая строка и строка из пробела

Пустая строка `""` — значение без единого байта, её `len` равна нулю. Строка
`" "` — один байт пробела, `"\n"` — один байт перевода строки. Пробел на
экране невидим, поэтому по выводу его легко не заметить, хотя это другое
значение, чем пустая строка.

Программа ниже печатает пустую строку и строку из пробела через `fmt.Println`
между меткой и чертой `|`, затем те же значения в квадратных скобках, через
`%q`, их длины и результат сравнения. Как и в уроке 2.1, `fmt.Println` ставит
по пробелу между аргументами. Прежде чем смотреть вывод, предскажите каждую
строку: сколько пробелов окажется перед чертой в первых двух строках? И легко
ли глаз заметит эту разницу?

```go

### Example: `06-empty`

Источник: `examples/06-empty/`

```go
package main

import "fmt"

func main() {
	empty := ""
	space := " "
	newline := "\n"

	fmt.Println("пустая:", empty, "|")
	fmt.Println("пробел:", space, "|")
	fmt.Println("[" + empty + "]")
	fmt.Println("[" + space + "]")
	fmt.Printf("%q %q %q\n", empty, space, newline)
	fmt.Println("байтов:", len(empty), len(space), len(newline))
	fmt.Println("empty == space:", empty == space)
}

```
```

В первой строке перед чертой два пробела: оба поставил `fmt.Println` между
аргументами, а пустая строка ничего не добавила. Во второй строке пробелов три:
третий — байт самой строки `space`. Разница в один невидимый пробел, и на экране
её легко пропустить. Скобки и `%q` делают границы значения видимыми, а `len` и
`==` дают ответ, не глядя на экран.

Строка, в которой есть только пробелы, табуляции или переводы строк, не пустая:
её длина больше нуля, и с `""` она не равна. Если пробелы по краям нужно
убрать, это делают отдельной операцией — например, функцией `strings.TrimSpace`
из урока 2.13. Ни печать, ни сравнение строку не меняют.

## Равенство — это совпадение байтов

Операторы `==` и `!=` из урока 2.6 сравнивают строки побайтово: строки равны,
когда у них одинаковая длина и на каждом месте стоит один и тот же байт. Это
точное совпадение: перед сравнением Go не приводит буквы к одному регистру и не
делает похожие на вид символы одинаковыми. Если байты различаются, строки не
равны, как бы похоже они ни выглядели. Отсюда три следствия:

- заглавная и строчная буква — разные байты, поэтому `"Go"` и `"go"` не равны;
- пробел в конце — лишний байт, поэтому `"Go"` и `"Go "` не равны;
- русская «С» и латинская «C» во многих шрифтах выглядят одинаково, но это
  разные кодовые точки и разные байты.

Программа ниже проверяет эти случаи и ещё один. Прежде чем смотреть вывод,
предскажите первые пять строк. Последняя пара, `composed` и `combined`,
записана экранированиями `\u`: по исходному коду видно, что в первой строке
одна кодовая точка, а во второй — латинская `e` и ещё одна. Сколько байтов
занимают эти кодовые точки, таблица урока не говорит. Поэтому ответьте на
другие вопросы: сколько кодовых точек в каждой строке и может ли `==` вернуть
`true`, если `len` двух строк различаются?

```go

### Example: `07-equality`

Источник: `examples/07-equality/`

```go
package main

import "fmt"

func main() {
	fmt.Println(`"Go" == "go":`, "Go" == "go")
	fmt.Println(`"Go" != "go":`, "Go" != "go")
	fmt.Println(`"Go" == "Go ":`, "Go" == "Go ")

	// русские буквы С и о
	cyrillic := "Со"
	// латинские буквы C и o
	latin := "Co"
	fmt.Println("cyrillic == latin:", cyrillic == latin)
	fmt.Println("байтов:", len(cyrillic), len(latin))

	// одна кодовая точка U+00E9: буква e с ударением
	composed := "\u00e9"
	// две кодовые точки: латинская e и знак ударения U+0301
	combined := "e\u0301"
	fmt.Printf("%q %q\n", composed, combined)
	fmt.Println("байтов:", len(composed), len(combined))
	fmt.Println("composed == combined:", composed == combined)
}

```
```

Первые строки подтверждают правило, а строка с длинами объясняет третье
следствие: в `cyrillic` четыре байта, в `latin` два. Последняя пара интереснее.
`composed` — одна кодовая точка U+00E9, буква é. `combined` — две кодовые
точки: латинская `e` и U+0301, знак ударения, который обычно рисуется над
предыдущей буквой. В зависимости от шрифта и от того, как программа выводит
текст, обе строки могут выглядеть как один и тот же знак é, в том числе в
выводе `%q`. Но `%q` ничего не приводит к одному виду: значение `composed`
хранит два байта, значение `combined` — три, и `%q` печатает эти разные байты
знака как есть, только добавляет вокруг свои кавычки. От вида на экране не
зависят ни байты, ни `len`, ни `==`. Длина значений разная — строки разные, и
`==` ответило «нет».

Так выглядят три уровня из раздела о кодовых точках: знак, который на экране
может выглядеть одним и тем же, одна или две кодовые точки, два или три байта.
Сравнение строк работает на уровне байтов. Если нужно считать равными «Go» и
«go» или не замечать пробелов по краям, текст сначала явно приводят к одному
виду. Такие функции разбирают уроки 2.13 и 9.4. Какая из двух строк «меньше»
при сравнении через `<`, разбирает урок 2.14.

## Во что обходится склейка

Каждая склейка создаёт новую строку, и в новую строку попадают все байты обоих
операндов. Для одной-двух склеек это дёшево, и запись вроде
`first + " " + last` — нормальная практика.

Иначе обстоит дело, когда результат растёт шаг за шагом. Пусть программа
собирает строку из кусков по 10 байтов и на каждом шаге пишет
`s = s + piece`. В простой модели каждый шаг строит новое значение и
переписывает в него все байты, накопленные раньше, вместе с новым куском:

| Шаг | Длина нового значения | Байтов переписано на шаге | Всего переписано |
|---|---|---|---|
| 1 | 10 | 10 | 10 |
| 2 | 20 | 20 | 30 |
| 3 | 30 | 30 | 60 |
| 4 | 40 | 40 | 100 |
| 5 | 50 | 50 | 150 |

Строка из 50 байтов потребовала переписать 150 байтов, и разрыв растёт: при ста
шагах результат занимает 1000 байтов, а переписано 50 500. Каждый шаг заново
обрабатывает всё, что уже собрано.

Это модель, а не обещание. Спецификация Go не говорит, сколько раз копируются
байты и сколько времени займёт склейка, а компилятор может часть работы
сократить. Модель объясняет, почему для длинной сборки есть другие
инструменты:

- если куски уже собраны в готовый набор, например в список слов, их соединяет
  функция `strings.Join`: она ставит разделитель между элементами; её разбирает
  урок 2.14;
- если результат строится по кусочку в много шагов, есть `strings.Builder`: по
  документации он собирает строку, сводя копирование памяти к минимуму; его
  разбирает урок 9.5.

В этом уроке ни то, ни другое не нужно: этикетке хватает одной склейки.

## Почему строку не режут по байтам

Пусть поле принтера вмещает 9 байтов, а этикетка `"Ли: какао"` занимает 16.
Напрашивается простое решение — оставить первые 9 байтов. Посчитайте, где
пройдёт граница: «Ли» — 4 байта, двоеточие и пробел — ещё 2, «к» — 7-й и 8-й
байты, а 9-й байт — первый из двух байтов буквы «а». Строка оборвётся посреди
буквы, и её последний байт, как `firstByte` в разделе об экранировании, буквой
не будет.

Номер байта совпадает с номером кодовой точки, только пока все кодовые точки до
этого места однобайтовые, то есть символы ASCII. После первой русской буквы
номера расходятся. Поэтому обрезать строку по числу байтов, брать «первую
букву» по номеру байта или заменять букву по номеру — не рецепт работы с
текстом. Язык позволяет прочитать байт по номеру и взять часть строки по
номерам байтов; как делать это, не разрывая символы, разбирают уроки 9.2–9.3.
А пока текст не помещается в поле, выбирают более короткий текст, а не режут
байты.

# Упражнение: этикетка на стакан

## Что сдать

Программа кофейни печатает на стакане этикетку «имя: напиток», проверяет её
размер в байтах и сверяет коды заказов. Заготовка — пакет `cup`: файл `go.mod`
и три файла с кодом, `label.go`, `labelbytes.go` и `samecode.go`. В каждом файле
с кодом объявлена одна экспортируемая функция:

- `func Label(name, drink string) string` — в файле `label.go`;
- `func LabelBytes(name, drink string) int` — в файле `labelbytes.go`;
- `func SameCode(entered, stored string) bool` — в файле `samecode.go`.

Тела функций — заглушки: `Label` возвращает `""`, `LabelBytes` — `0`,
`SameCode` — `false`. Допишите тела так, чтобы каждая функция возвращала
значение, описанное в разделе её задачи ниже. Комментарии `// TODO` можно
удалить.

Не меняйте `go.mod`, строку `package cup`, имена функций, списки параметров и
типы результатов: скрытые тесты вызывают функции именно в таком виде. Функции
только возвращают значения, печатать ничего не нужно. Импорты не нужны: хватит
склейки `+`, встроенной функции `len` и сравнения `==`. Одна функция может
вызвать другую функцию пакета, как в уроке 1.7. Тогда её результат зависит и от
вызванной функции, поэтому сначала допишите ту, которую вызываете.

Допустимые значения: все параметры — любые строки, в том числе пустые. В
тестах встречаются латинские и русские буквы, цифры, дефис, пробелы в середине
и по краям, табуляция, двойная кавычка и обратная косая черта. Строки в
примерах ниже записаны литералами Go: `\t` — один байт табуляции, `\"` — один
байт кавычки, `\\` — один байт обратной косой черты.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые значения с
ожидаемыми:

- `TestLabel` — `Label` на русских и латинских именах, с пробелами внутри и по
  краям, с пустым именем или пустым напитком, с табуляцией, кавычками и
  обратной косой чертой;
- `TestLabelBytes` — `LabelBytes` на тех же видах строк: только латиница,
  русские буквы, пустые параметры, табуляция, кавычки и обратная косая черта;
- `TestSameCode` — `SameCode` на совпадающих кодах, на кодах, которые
  отличаются регистром, пробелом в начале или в конце, на пустых строках и на
  коде, где латинская буква заменена похожей русской.

Тест получает только то, что функция вернула. Текста решения он не видит,
поэтому не различает, вызывает ли `LabelBytes` функцию `Label` или считает
байты сама.

Ответ проверки бывает двух видов. Если код не собрался, тесты не запускаются,
и проверка показывает сообщение сборки с местом в файле. Если код собрался, но
функция вернула не то, проверка печатает строку `--- FAIL:` с именем теста и
сообщение: какие аргументы переданы, что функция вернула и что должна была
вернуть. Строки в сообщениях напечатаны через `%q`, поэтому пробелы по краям и
табуляция в них видны.

Прежде чем писать `LabelBytes`, посчитайте байты этикетки вручную для двух
вызовов: `LabelBytes("Мария", "чай")` и `LabelBytes("Ася\t", "какао \"XL\"")`.
Для каждого запишите, из каких частей складывается число и сколько байтов даёт
каждая часть. Сверьте свой счёт с разбором после попытки, раздел «Как
считаются байты этикетки».

## Label

`Label` возвращает этикетку: значение `name`, затем двоеточие и один пробел,
затем значение `drink`. Все байты `name` и `drink` попадают в результат как
есть: пробелы по краям не убираются, ничего не добавляется, перевода строки в
конце нет.

- `Label("Анна", "латте")` возвращает `"Анна: латте"`;
- `Label("Ли", "")` возвращает `"Ли: "` — с пробелом в конце;
- `Label("Ася\t", "какао \"XL\"")` возвращает `"Ася\t: какао \"XL\""` —
  табуляция осталась после имени, кавычки — вокруг XL.

## LabelBytes

`LabelBytes` возвращает, сколько байтов займёт этикетка, которую `Label`
собрала бы из тех же `name` и `drink`. Это число байтов, а не букв: принтер
меряет поле байтами.

- `LabelBytes("Bob", "tea")` возвращает `8`;
- `LabelBytes("Анна", "латте")` возвращает `20`;
- `LabelBytes("", "")` возвращает `2`: в этикетке остались двоеточие и пробел.

## SameCode

`SameCode` сообщает, совпадает ли код заказа, который назвал гость
(`entered`), с кодом в системе (`stored`). Совпадение точное, байт в байт:
регистр букв важен, пробел по краям — тоже, русская и латинская буквы разные,
даже если выглядят одинаково. Никакой обработки перед сравнением функция не
делает: привести ввод к одному виду — отдельная задача, и в этой функции её
нет.

- `SameCode("A17", "A17")` возвращает `true`;
- `SameCode("a17", "A17")` возвращает `false`;
- `SameCode("A17 ", "A17")` возвращает `false`;
- `SameCode("", "")` возвращает `true`.

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## Label

**Ступень 1.** Из каких трёх частей состоит этикетка? Какая часть — постоянный
текст, а какие приходят в параметрах? Для вызова `Label("Ли", "")` сосчитайте,
сколько пробелов должно оказаться в результате и откуда каждый из них берётся.

**Ступень 2.** Нужна склейка `+` трёх частей: параметр, литерал с двоеточием и
пробелом, параметр — как в разделе «Склейка + копирует байты как есть». `+`
пробела не ставит, поэтому пробел должен стоять внутри литерала. Обрабатывать
`name` и `drink` не нужно: табуляция, кавычки и пробелы по краям — их законные
байты. `fmt.Sprintln` здесь не подходит: он добавляет в конец перевод строки.

## LabelBytes

**Ступень 1.** Что считает `len` — буквы или байты? Какие байты войдут в
этикетку, кроме байтов `name` и `drink`? Проверьте свой ответ на вызове
`LabelBytes("", "")`.

**Ступень 2.** Число можно получить двумя путями: взять `len` от готовой
этикетки, вызвав `Label`, или сложить `len` каждого параметра и число байтов
разделителя `": "`. Ошибаются в двух местах: забывают двоеточие и пробел или
считают буквы вместо байтов — тогда для `("Анна", "латте")` получается 11, а
не 20.

## SameCode

**Ступень 1.** Какие различия должны давать `false`: регистр, пробел по краям,
похожие буквы из разных алфавитов? Какой оператор из урока 2.6 сравнивает
строки ровно так — байт в байт?

**Ступень 2.** Достаточно сравнить параметры оператором `==` и вернуть
результат сравнения, как предикат из урока 2.6. Ошибаются, когда пытаются
«помочь» гостю: убирают пробелы по краям или не различают регистр. Такая
обработка меняет контракт, и тест её ловит.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Как считаются байты этикетки

<!-- review:label-bytes-count -->

Постановка просила до написания `LabelBytes` посчитать байты двух этикеток
вручную. Вот этот счёт.

Для `LabelBytes("Мария", "чай")`:

- «Мария» — пять русских букв, по два байта: 10;
- двоеточие и пробел — символы ASCII, по байту: 2;
- «чай» — три русские буквы: 6;
- всего 18.

Для `LabelBytes("Ася\t", "какао \"XL\"")`:

- «Ася» — три русские буквы, 6 байтов, и табуляция `\t` — ещё один: 7;
- двоеточие и пробел: 2;
- «какао» — 10 байтов, пробел — 1, две кавычки `\"` — по байту, буквы X и L —
  по байту: 15;
- всего 24.

Запись `\t` и `\"` занимает в литерале два знака, но в значении даёт один байт.
`TestLabelBytes` проверяет оба вызова. Верное тело —
`return len(Label(name, drink))` или
`return len(name) + len(": ") + len(drink)`. Первое берёт длину готовой
этикетки, второе складывает длины частей. Оба дают одно число, потому что
длина склейки `+` равна сумме длин её частей.

## Слова слиплись

<!-- review:label-no-space -->

Решение `return name + ":" + drink` рассчитывает, что пробел после двоеточия
появится сам. Но `+` ничего не вставляет между операндами: в результат
попадают только байты частей.

Ловит это `TestLabel` на первом же входе: `Label("Анна", "латте")` возвращает
строку без пробела после двоеточия. Пробел должен стоять внутри литерала:
`return name + ": " + drink`.

## Лишний перевод строки

<!-- review:label-sprintln -->

Решение `return fmt.Sprintln(name+":", drink)` перенесло привычку к
`fmt.Println`. `fmt.Sprintln` ставит пробел между аргументами — это совпало с
нужным пробелом, — но в конце добавляет перевод строки. Напечатанная этикетка
выглядит верно: лишний перевод строки на экране не заметен.

Ловит это `TestLabel`: в сообщении `%q` показывает `\n` в конце полученной
строки. Возвращённое значение сравнивается байт в байт, и лишний байт перевода
строки делает его другим. Склейка `name + ": " + drink` даёт ровно нужные байты.

## Разделитель не посчитан

<!-- review:labelbytes-no-separator -->

Решение `return len(name) + len(drink)` складывает байты имени и напитка, но
этикетка — это ещё двоеточие и пробел.

Ловит это `TestLabelBytes` на входе `("Bob", "tea")`: тест ждёт 8, а получает
6. Проще всего не пересчитывать части, а взять длину готовой этикетки:
`return len(Label(name, drink))`.

## Посчитаны буквы, а не байты

<!-- review:labelbytes-letters -->

Решение `return utf8.RuneCountInString(name) + 2 + utf8.RuneCountInString(drink)`
взяло функцию из пакета `unicode/utf8`, которая считает кодовые точки. На
латинице ответ совпадает с числом байтов, и вход `("Bob", "tea")` ошибку не
показывает.

Ловит это `TestLabelBytes` на входе `("Анна", "латте")`: тест ждёт 20, а
получает 11. Каждая русская буква — два байта, а поле принтера меряется
байтами. Это ровно то, что возвращает `len`.

## Регистр не учитывается

<!-- review:samecode-ignore-case -->

Решение `return strings.EqualFold(entered, stored)` сравнивает строки без учёта
регистра. Для гостя это кажется удобным, но контракт требует совпадения байт в
байт: `a` и `A` — разные байты.

Ловит это `TestSameCode` на входе `("a17", "A17")`: тест ждёт `false`, а
получает `true`. Точное сравнение — это `return entered == stored`.

## Пробелы убраны

<!-- review:samecode-trimmed -->

Решение `return strings.TrimSpace(entered) == strings.TrimSpace(stored)`
убирает пробельные символы по краям и только потом сравнивает. Такая обработка
меняет вопрос: функция отвечает уже не «совпали ли коды», а «совпали ли коды
после очистки».

Ловит это `TestSameCode` на входе `("A17 ", "A17")`: тест ждёт `false`, потому
что пробел в конце — лишний байт. Если очистка ввода когда-нибудь понадобится,
это будет отдельная задача с отдельной функцией, а `SameCode` остаётся
сравнением `entered == stored`.

## Похожая буква

<!-- review:samecode-lookalike -->

Отдельного неверного решения для этого случая нет, но проверка его содержит:
`SameCode` получает код, где первая буква — русская «А», а в системе код с
латинской «A». Любое решение через `==` здесь верно отвечает `false`. Значения
кодов содержат разные байты первой буквы, и `%q` печатает их как есть, только
добавляет кавычки, поэтому во многих шрифтах коды на экране выглядят одинаково.
Сообщение теста выводит ещё и длины обеих строк: 4 и 3, а они от шрифта не
зависят.

## Вопрос 1

```go
@quiz _quiz/01-reassign
```

Что окажется в `first` и в `second`, когда программа дойдёт до печати?

Варианты ответа:

- A. В обеих переменных «чай с мятой»: `second` следит за значением `first`.
- B. В `first` — «чай с мятой», в `second` — «чай».
- C. В обеих переменных «чай»: строка неизменяема, и присваивание в `first`
  ничего не меняет.
- D. Программа не соберётся: неизменяемую строку нельзя дополнить.

Прежде чем смотреть ответ, опишите, какие строковые значения существуют после
третьей строки `main` и какая переменная какое из них хранит.

**Правильный ответ: B.**

`second := first` кладёт в `second` значение «чай». Выражение
`first + " с мятой"` строит новое значение, и присваивание кладёт его в
`first`. Старое значение «чай» не изменилось и осталось в `second`. Вариант A
считает, что переменная ссылается на другую переменную, а присваивание в Go
передаёт значение. Вариант C путает неизменяемость значения с неизменяемостью
переменной. Вариант D думает, что `+` дописывает байты в старую строку, а он
создаёт новую, и программа собирается.

## Вопрос 2

```go
@quiz _quiz/02-lengths
```

В литерале `"ok ок"` первое слово набрано латинскими буквами, второе —
русскими. В литерале `" \t"` стоят пробел и табуляция. Какие три числа
напечатает программа?

Варианты ответа:

- A. 5, 0 и 2: `len` считает видимые знаки.
- B. 7, 0 и 2.
- C. 7, 1 и 2: в конце пустой строки хранится завершающий байт.
- D. 7, 0 и 0: пробел и табуляция — это пустота.

Прежде чем смотреть ответ, разложите каждую строку на части и назовите, сколько
байтов даёт каждая часть и что именно считает `len`.

**Правильный ответ: B.**

`len` возвращает число байтов. В `"ok ок"` две латинские буквы и пробел дают по
байту, две русские буквы — по два: всего 7. У пустой строки байтов нет. Пробел
и табуляция — символы ASCII, по байту каждый. Вариант A считает буквы вместо
байтов. Вариант C переносит в Go завершающий нулевой байт строк языка C, а в Go
его нет. Вариант D принимает невидимые символы за отсутствие байтов.

## Вопрос 3

```go
@quiz _quiz/03-escape-concat
```

Что напечатает программа?

Варианты ответа:

- A. `%q` покажет `"\n\n"`, длина 2: `+` превратил сырое `\n` в перевод
  строки.
- B. `%q` покажет `"\\n\n"`, длина 3.
- C. `%q` покажет `"\\n\\n"`, длина 4: обе записи остались двумя знаками.
- D. `%q` покажет `"\\n\n"`, длина 4: обратная косая черта удвоена, значит, в
  строке она занимает два байта.

Прежде чем смотреть ответ, для каждого литерала назовите байты, которые он
даёт, затем скажите, что с ними делает `+` и как их запишет `%q`.

**Правильный ответ: B.**

Сырой литерал `` `\n` `` даёт два байта: обратную косую черту и `n`.
Интерпретируемый `"\n"` даёт один байт перевода строки. `+` копирует байты как
есть, итого три. `%q` записывает обратную косую черту как `\\`, а перевод
строки как `\n`. Вариант A считает, что `+` заново читает байты как запись
литерала. Вариант C не замечает, что в двойных кавычках `\n` — один байт.
Вариант D путает запись `%q` с содержимым строки: удвоенная черта есть только в
напечатанной записи.

## Вопрос 4

```go
@quiz _quiz/04-escape-bytes
```

Что напечатает программа?

Варианты ответа:

- A. Длину 2 и `true`: каждое экранирование — один символ.
- B. Длину 3 и `true`.
- C. Длину 3 и `false`: строка, записанная байтами, не равна букве, набранной
  как есть.
- D. Длину 10 и `false`: `len` считает знаки записи в исходном коде.

Прежде чем смотреть ответ, выпишите байты каждого литерала
шестнадцатеричными числами.

**Правильный ответ: B.**

`\xff` — один байт 0xff, `\u00ff` — буква ÿ, два байта 0xc3 и 0xbf: всего три.
`"\xc3\xbf"` — те же два байта, и буква ÿ, набранная в исходном коде, хранится
в UTF-8 ими же, поэтому строки равны. Вариант A не различает байт и кодовую
точку. Вариант C думает, что `==` сравнивает запись литерала, а сравниваются
байты значения. Вариант D меряет исходный код, а `len` меряет значение.

## Вопрос 5

Какие из выражений дают `true`?

1. `"" == " "`
2. `len("\n") == 1`
3. `"Да" == "да"`
4. `"код " == "код"`
5. `len("") == 0`

Варианты ответа:

- A. Второе и пятое.
- B. Первое, второе и пятое.
- C. Второе, третье и пятое.
- D. Только пятое.

Прежде чем смотреть ответ, для каждого сравнения строк скажите, одинаковы ли
длины сторон и есть ли место, где байты различаются, а для каждого `len` —
сколько байтов в строке.

**Правильный ответ: A.**

Перевод строки — один байт, у пустой строки байтов нет. Пустая строка и
строка из пробела различаются одним байтом. «Д» и «д» — разные байты, а у
`"код "` на один байт пробела больше. Вариант B считает строку из пробела
пустой. Вариант C сравнивает строки без учёта регистра. Вариант D считает
запись `\n` двумя знаками или не считает перевод строки вовсе.

## Вопрос 6

Кассир набрал код заказа `А17`, но первую букву случайно ввёл русской «А». В
системе код записан латинской «A»: `A17`. На экране коды выглядят одинаково.
Что вернёт сравнение набранного кода с кодом в системе через `==`, и что
подтвердит ответ?

Варианты ответа:

- A. `true`: знаки на экране одинаковые.
- B. `false`; `len` вернёт для этих строк 4 и 3.
- C. `false`; `len` вернёт 3 и 3, а различие есть только внутри байтов.
- D. Программа не соберётся: русские и латинские буквы нельзя сравнивать в
  одном выражении.

Прежде чем смотреть ответ, посчитайте байты обеих строк по таблице из раздела
«Почему русская буква занимает два байта».

**Правильный ответ: B.**

Русская «А» занимает два байта, латинская «A» — один, цифры — по байту: 4
против 3. Строки разной длины не равны. Вариант A сравнивает вид на экране, а
`==` сравнивает байты. Вариант C верно отвечает `false`, но забывает, что
русская буква занимает два байта. Вариант D ищет запрет, которого нет: любые
две строки можно сравнить.

## Вопрос 7

Программа собирает отчёт из 1000 строк по одной за шаг записью
`report = report + line`. Коллега говорит, что каждая склейка копирует только
новую строку `line`. Что точнее описывает работу в простой модели из раздела
«Во что обходится склейка»?

Варианты ответа:

- A. Коллега прав: `+` дописывает байты `line` в конец значения, которое уже
  хранит `report`.
- B. Каждый шаг строит новое значение и переписывает в него весь накопленный
  `report` вместе с `line`.
- C. Каждый шаг переписывает весь будущий отчёт из 1000 строк, поэтому все
  шаги одинаково дороги.
- D. Программа не соберётся: `report` хранит неизменяемую строку, и присвоить
  ей новое значение нельзя.

Прежде чем смотреть ответ, объясните, что происходит на втором и на сотом шаге
с байтами, собранными раньше.

**Правильный ответ: B.**

`+` создаёт новую строку со всеми байтами обоих операндов, а старое значение
`report` не меняется. Поэтому на сотом шаге переписываются байты девяноста
девяти прежних строк, и работа каждого шага растёт вместе с отчётом. Точное
число копий язык не обещает, но модель показывает, почему длинную сборку делают
другими инструментами. Вариант A считает строку изменяемой. Вариант C
приписывает шагу байты, которых ещё нет. Вариант D путает неизменяемое значение
с переменной, которой можно присвоить новое.

## Вопрос 8

Есть три задачи:

1. один раз склеить имя и напиток для этикетки;
2. соединить через запятую готовый набор из 50 названий напитков;
3. собрать длинный отчёт по кусочку за тысячу шагов.

Что подходит к каждой из них?

Варианты ответа:

- A. 1 — `+`; 2 — `strings.Join`; 3 — `strings.Builder`.
- B. 1 — `strings.Builder`; 2 — `+`; 3 — `strings.Join`.
- C. Везде `+`: компилятор сам сделает любую склейку дешёвой.
- D. 1 — `+`; 2 — `strings.Builder`; 3 — `strings.Join`.

Прежде чем смотреть ответ, для каждой задачи скажите, что это: одна небольшая
склейка, соединение уже готового набора кусков или сборка по кусочку в много
шагов.

**Правильный ответ: A.**

Одна склейка через `+` дёшева и понятна. Готовый набор кусков с разделителем
соединяет `strings.Join`. Для сборки в много шагов предназначен
`strings.Builder`, который сводит копирование к минимуму. Вариант B берёт
инструмент для многих шагов там, где склейка одна, и `+` для целого набора.
Вариант C принимает возможную работу компилятора за обещание языка. Вариант D
меняет местами инструмент для готового набора и инструмент для сборки по шагам.

## Вопрос 9

Поле принтера вмещает 11 байтов, а этикетка `"Анна: латте"` занимает 20.
Коллега предлагает оставить первые 11 байтов этикетки. Что получится?

Варианты ответа:

- A. Первые 11 букв этикетки: номера байтов совпадают с номерами букв.
- B. «Анна», двоеточие, пробел и первый байт буквы «л»: строка оборвётся
  посреди буквы.
- C. Сборка откажет: строка неизменяема, и получить из неё более короткую
  нельзя.
- D. «Анна: л» целиком: Go сам сдвинет границу к концу буквы.

Прежде чем смотреть ответ, посчитайте байты каждой части этикетки и найдите, на
что придётся 11-й байт.

**Правильный ответ: B.**

«Анна» — 8 байтов, двоеточие и пробел — ещё 2, и 11-й байт — первый из двух
байтов буквы «л». Такой последний байт буквой не является. Вариант A забывает,
что номер байта совпадает с номером кодовой точки, только пока все кодовые
