# Таблица данных вместо цепочки условий

Программа расписания показывает название дня недели по его номеру: 1 —
понедельник, 7 — воскресенье. После урока 3.3 такой выбор пишут через
`switch`: семь веток `case` и ветка `default` для номеров, которых нет.
Каждая ветка делает одно и то же — возвращает строку. Ветки различаются
только данными: какому номеру какое название соответствует.

Такие данные можно вынести из кода в коллекцию — массив, slice или map.
Коллекцию, которая хранит ответы вместо веток, называют таблицей данных.
Код тогда не перебирает варианты, а делает один поиск: берёт элемент по
номеру или запись по ключу. Выбор переезжает из кода в данные.

Понадобится пройденное:

- уроки 3.3 и 3.4: `switch` с выражением-селектором, ветка `default`,
  `switch` без условия и порядок `case` как приоритет;
- урок 2.12: коды из набора констант через `iota`, идущие подряд от нуля;
- урок 2.3: переменная, объявленная вне функций, — имя уровня пакета, её
  видят все функции пакета;
- урок 4.1: массив и его литерал, в котором элементов может быть меньше
  длины, индекс с нуля, `len`, отказ сборки на индексе-константе за
  границей и паника на индексе-переменной;
- уроки 4.2 и 4.3: slice, его литерал и чтение по индексу;
- урок 4.10: цикл `for _, v := range s`;
- уроки 4.11 и 4.12: map и её литерал, нулевое значение при чтении
  отсутствующего ключа и форма `v, ok := m[k]`;
- урок 1.9: глагол `%q` печатает строку в кавычках, поэтому пустая строка
  видна как пара кавычек.

К концу урока вы сможете:

- переписать `switch`, ветки которого различаются только данными, таблицей
  на массиве или slice и таблицей на map и предсказать ответ для значения,
  которого в таблице нет;
- защитить поиск по индексу проверкой границ и объяснить, от чего
  проверка через `len` защищает, а от чего нет;
- найти и исправить пропущенный элемент таблицы;
- выбрать для задачи таблицу или `switch` и объяснить, какую форму проще
  читать и править.

## Ветки, которые отличаются только данными

Функция `weekdayName` ниже написана так, как её написали бы после урока
3.3. Значение, по которому делается выбор, дальше называется выбираемым
значением. У функции дня недели это номер дня `d` — селектор `switch`. Для
номеров вне 1–7 срабатывает `default` и возвращает пустую строку. `main`
вызывает функцию для пяти номеров.

Прежде чем смотреть вывод, назовите пять строк.

```go

### Example: `01-weekday-switch`

Источник: `examples/01-weekday-switch/`

```go
// Название дня недели по номеру: switch, ветки которого отличаются
// только строкой.
package main

import "fmt"

// weekdayName возвращает название дня с номером d от 1 до 7 и пустую
// строку для любого другого номера.
func weekdayName(d int) string {
	switch d {
	case 1:
		return "понедельник"
	case 2:
		return "вторник"
	case 3:
		return "среда"
	case 4:
		return "четверг"
	case 5:
		return "пятница"
	case 6:
		return "суббота"
	case 7:
		return "воскресенье"
	default:
		return ""
	}
}

func main() {
	for _, d := range []int{1, 3, 7, 0, 8} {
		fmt.Printf("%d → %q\n", d, weekdayName(d))
	}
}

```
```

Посмотрите на ветки: в каждой стоит `case`, номер и `return` строки. Семь
веток различаются только парами «номер → название». Эти пары и станут
таблицей.

## Таблица на массиве: номер становится индексом

Номера дней идут подряд, от 1 до 7. Индексы массива тоже идут подряд,
только от 0 (урок 4.1). Поэтому названия можно выписать в массив по
порядку: понедельник под индексом 0, вторник под индексом 1 и так далее.
Переход от `switch` к таблице делается в четыре шага.

1. **Выписать ответы по порядку номеров.** Литерал
   `[7]string{"понедельник", "вторник", …}` кладёт название дня 1 первым
   элементом, а дня 7 — последним.
2. **Перевести номер в индекс.** Индекс на единицу меньше номера: день `d`
   лежит под индексом `d-1`. Если бы номера начинались с нуля, как коды
   через `iota` в уроке 2.12, номер сам был бы индексом, и сдвиг не
   понадобился бы.
3. **Заменить `default` проверкой границ.** Условие
   `d < 1 || d > len(weekdays)` отбирает номера, для которых элемента нет.
   Для них функция возвращает пустую строку — тот же ответ, что давал
   `default`.
4. **Оставить одну строку поиска:** `return weekdays[d-1]`.

Таблица объявлена вне функций: `var weekdays = [7]string{…}`. Это
переменная уровня пакета (урок 2.3). Её видит каждая функция пакета, а
значение ей даёт литерал, поэтому функции читают уже заполненную таблицу.

Прежде чем смотреть вывод, ответьте: совпадут ли пять строк с выводом
программы `01-weekday-switch`, и какая часть функции теперь отвечает за
номера 0 и 8?

```go

### Example: `02-weekday-array`

Источник: `examples/02-weekday-array/`

```go
// Тот же выбор, но ответы переехали из веток в массив-таблицу.
package main

import "fmt"

// weekdays — названия дней по порядку: день с номером d лежит под
// индексом d-1.
var weekdays = [7]string{
	"понедельник", "вторник", "среда", "четверг",
	"пятница", "суббота", "воскресенье",
}

// weekdayName возвращает название дня с номером d от 1 до 7 и пустую
// строку для любого другого номера.
func weekdayName(d int) string {
	if d < 1 || d > len(weekdays) {
		return ""
	}
	return weekdays[d-1]
}

func main() {
	for _, d := range []int{1, 3, 7, 0, 8} {
		fmt.Printf("%d → %q\n", d, weekdayName(d))
	}
}

```
```

Ответы те же. Для 0 и 8 их дала проверка границ: она сработала раньше, чем
чтение по индексу. Семь веток превратились в семь элементов литерала, а
выбор — в одну строку `weekdays[d-1]`.

## Номер за границей таблицы

Без проверки границ функция читает `weekdays[d-1]` при любом `d`. Номер
приходит в параметре, значит индекс — не константа, а значение, известное
только во время работы. По уроку 4.1 такой индекс за границей
останавливает программу паникой.

Прежде чем смотреть вывод, решите: сколько строк программа напечатает до
остановки и какие индекс и длину назовёт сообщение паники?

```go

### Example: `03-no-guard`

Источник: `examples/03-no-guard/`

```go
// Поиск в таблице без проверки границ.
package main

import "fmt"

var weekdays = [7]string{
	"понедельник", "вторник", "среда", "четверг",
	"пятница", "суббота", "воскресенье",
}

// weekdayName не проверяет границы: вызывающий код обязан передать номер
// от 1 до 7.
func weekdayName(d int) string {
	return weekdays[d-1]
}

func main() {
	for _, d := range []int{7, 8, 1} {
		fmt.Printf("%d → %q\n", d, weekdayName(d))
	}
}

```
```

Для 7 индекс 6 допустим, и название напечаталось. Для 8 индекс равен 7 —
длине массива, и программа остановилась; до номера 1 дело не дошло.
Сообщение называет индекс и длину. Точный текст сообщения выбирает среда
исполнения Go; язык обещает саму панику, а не её слова.

Индекс-константу за концом массива, например `weekdays[7]`, до запуска не
допустит сборка, как `temps[3]` в уроке 4.1. Такой отказ сборки — правило
массива: константу за концом таблицы-slice сборка пропускает, и ошибка
проявится паникой при запуске.

С номером, для которого в таблице нет элемента, функция может обойтись
двумя способами:

- проверить границы и вернуть заранее оговорённый ответ, как
  `weekdayName` из программы `02-weekday-array`;
- записать в комментарии к функции условие: вызывающий код передаёт только
  номера от 1 до 7. Проверки тогда нет, и нарушение условия кончается
  паникой, как в программе без проверки выше.

В упражнении этого урока выбран первый способ.

## Таблица на map: ключ вместо номера

Номер дня годится в индекс: он маленький, и номера идут подряд.
Обозначение единицы длины — `"мм"`, `"см"`, `"м"`, `"км"` — строка, и
индексом оно быть не может. Для таких выбираемых значений таблицей служит
map (урок 4.11): ключ — обозначение, значение — ответ.

Программа ниже переводит обозначение в множитель: сколько метров в одной
единице. `factorSwitch` делает это через `switch`, `factorMap` — одним
чтением из map `factors`. Для обозначения, которого нет, `switch`
возвращает 0 из `default`, а map — нулевое значение `float64`, тоже 0 (урок
4.12). Прежде чем смотреть вывод, назовите для каждого из трёх обозначений
оба множителя.

```go

### Example: `04-units-switch-map`

Источник: `examples/04-units-switch-map/`

```go
// Множитель единицы длины: switch и таблица-map дают одно и то же.
package main

import "fmt"

// factorSwitch возвращает, сколько метров в одной единице, и 0 для
// неизвестного обозначения.
func factorSwitch(unit string) float64 {
	switch unit {
	case "мм":
		return 0.001
	case "см":
		return 0.01
	case "м":
		return 1
	case "км":
		return 1000
	default:
		return 0
	}
}

// factors — те же ответы данными: обозначение → метров в одной единице.
var factors = map[string]float64{
	"мм": 0.001,
	"см": 0.01,
	"м":  1,
	"км": 1000,
}

// factorMap делает то же одним чтением по ключу.
func factorMap(unit string) float64 {
	return factors[unit]
}

func main() {
	for _, unit := range []string{"см", "км", "миля"} {
		fmt.Println(unit, factorSwitch(unit), factorMap(unit))
	}
}

```
```

Обе функции дали одно и то же, включая неизвестную милю. Проверка границ
для map не нужна: чтение отсутствующего ключа не останавливает программу, а
возвращает нулевое значение. В версии на map роль `default` играет само
нулевое значение.

Map подходит и для целых чисел, если они разрежены — стоят далеко друг от
друга. Коды ответов сервера 200, 404 и 500 удобно хранить в
`map[int]string`: slice пришлось бы делать длиной 501 ради трёх значений
(урок 4.11).

## Когда ноль — настоящее значение

В таблице множителей 0 означает «такой единицы нет». Ноль годится для этой
роли, потому что ни у одной настоящей единицы множитель не равен нулю.
Значение, которое не бывает настоящим ответом и потому отмечает особый
случай, называют значением-меткой.

Бывает, что ноль — законный ответ. В таблице уровней доступа у гостя
уровень 0. Обычное чтение даст 0 и для гостя, и для роли, которой в таблице
нет. Тогда отсутствие ключа проверяют формой `level, ok := levels[role]`
(урок 4.12) и для отсутствующей роли возвращают ответ, которого нет среди
настоящих, например −1.

Прежде чем смотреть вывод, назовите три строки: роль, результат обычного
чтения и результат проверки присутствия.

```go

### Example: `05-comma-ok`

Источник: `examples/05-comma-ok/`

```go
// Таблица, где 0 — настоящее значение: уровень доступа по роли.
package main

import "fmt"

// levels — уровень доступа каждой роли; у гостя он равен 0.
var levels = map[string]int{
	"гость":    0,
	"автор":    1,
	"редактор": 2,
}

// levelPlain читает таблицу обычным чтением.
func levelPlain(role string) int {
	return levels[role]
}

// levelChecked возвращает -1 для роли, которой в таблице нет.
func levelChecked(role string) int {
	level, ok := levels[role]
	if !ok {
		return -1
	}
	return level
}

func main() {
	for _, role := range []string{"редактор", "гость", "робот"} {
		fmt.Println(role, levelPlain(role), levelChecked(role))
	}
}

```
```

У гостя и у робота обычное чтение дало одинаковый 0. Различил их только
признак `ok`: гость в таблице есть, робота нет.

## Когда меняются данные

Таблица удобна тем, что правка данных не трогает код. Исправить написание
названия — значит поменять одну строку в литерале. Поддержать новую
единицу — добавить одну пару. Функция поиска остаётся прежней.

В программе ниже в таблицу множителей добавлена одна пара —
`"миля": 1609.344`. Функция `factorMap` та же, что в программе
`04-units-switch-map`. Прежде чем смотреть вывод, назовите множители для
километра, мили и ярда.

```go

### Example: `06-add-unit`

Источник: `examples/06-add-unit/`

```go
// В таблицу добавлена одна пара; функция поиска не изменилась.
package main

import "fmt"

var factors = map[string]float64{
	"мм":   0.001,
	"см":   0.01,
	"м":    1,
	"км":   1000,
	"миля": 1609.344,
}

// factorMap возвращает, сколько метров в одной единице, и 0 для
// неизвестного обозначения.
func factorMap(unit string) float64 {
	return factors[unit]
}

func main() {
	for _, unit := range []string{"км", "миля", "ярд"} {
		fmt.Println(unit, factorMap(unit))
	}
}

по-прежнему 0.

соберётся ли программа ниже, из `switch` которой при правке выпала ветка

Повторённые данные обнаружить проще, чем пропущенные. Повтор ключа в
литерале map отвергает сборка (урок 4.11), повтор константы в `case` —
текущий компилятор (урок 3.3). Пропуск не замечают ни сборка, ни `go vet` — ни в
таблице, ни в `switch`. Его находит проверка на значениях, которые должны
быть в ответе, или внимательное чтение данных.

## Пропуск в таблице и проверка через len

В таблице месяцев при правке выпал май. Что будет дальше, зависит от того,
массив это или slice.

- Массив `[12]string` с литералом из 11 названий собирается. По уроку 4.1
  элемент, которого литерал не задал, получает нулевое значение — пустую
  строку. Явная длина в типе отвергает лишний элемент, но не недостающий.
  `len` массива — длина из его типа, то есть 12, сколько бы названий ни
  записали.
- Slice из 11 названий имеет длину 11 (урок 4.3): `len` slice считает
  элементы, которые в нём действительно есть.

В обоих случаях названия после пропуска сдвигаются на одну позицию: под
индексом 4, где должен быть май, оказывается июнь.

Программа ниже держит обе таблицы без мая и ищет в каждой с проверкой
через `len`. Прежде чем смотреть вывод, назовите обе длины и то, что обе
функции вернут для 4, 5, 11 и 12.

```go

### Example: `08-missing-month`

Источник: `examples/08-missing-month/`

```go
// Таблица месяцев, из которой выпал май: массив и slice.
package main

import "fmt"

// monthsArr — массив на 12 названий, а в литерале их 11.
var monthsArr = [12]string{
	"январь", "февраль", "март", "апрель", "июнь", "июль",
	"август", "сентябрь", "октябрь", "ноябрь", "декабрь",
}

// monthsSl — те же 11 названий в slice.
var monthsSl = []string{
	"январь", "февраль", "март", "апрель", "июнь", "июль",
	"август", "сентябрь", "октябрь", "ноябрь", "декабрь",
}

func fromArray(m int) string {
	if m < 1 || m > len(monthsArr) {
		return ""
	}
	return monthsArr[m-1]
}

func fromSlice(m int) string {
	if m < 1 || m > len(monthsSl) {
		return ""
	}
	return monthsSl[m-1]
}

func main() {
	fmt.Println("длины:", len(monthsArr), len(monthsSl))
	for _, m := range []int{4, 5, 11, 12} {
		fmt.Printf("%d: %q %q\n", m, fromArray(m), fromSlice(m))
	}
}

```
```

Для 5 обе таблицы вернули июнь, для 11 — декабрь: названия сдвинулись. Для
12 обе вернули пустую строку, но по разным причинам. Массив пропустил 12
через проверку, потому что его `len` равна 12, и отдал незаданный
последний элемент. Slice не прошёл проверку: его `len` равна 11.

У массива `[12]string` условия `m > 12` и `m > len(months)` равносильны:
`len` массива — та же константа из типа. У slice они различаются. Если
вместо `len(months)` написать число 12, короткий slice больше не защищён.
Прежде чем смотреть вывод, решите, чем кончится вызов для 12 при той же
таблице-slice из 11 названий.

```go

### Example: `09-literal-guard`

Источник: `examples/09-literal-guard/`

```go
// Проверка числом 12 вместо len при таблице из 11 названий.
package main

import "fmt"

// months — 11 названий: мая нет.
var months = []string{
	"январь", "февраль", "март", "апрель", "июнь", "июль",
	"август", "сентябрь", "октябрь", "ноябрь", "декабрь",
}

func nameOf(m int) string {
	if m < 1 || m > 12 {
		return ""
	}
	return months[m-1]
}

func main() {
	for _, m := range []int{11, 12} {
		fmt.Printf("%d: %q\n", m, nameOf(m))
	}
}

```
```

Условие `m > 12` пропустило 12, и чтение `months[11]` остановило
программу: индекс равен длине. Поэтому в проверке границ таблицы-slice
пишут `len` таблицы, а не число, которое программист держит в голове.

Ни одна проверка границ пропуск не находит: она сравнивает номер с
длиной, а не проверяет данные. Пропущенный май видно по неверному ответу
для 5 и по пустой строке для 12. Поэтому таблицу проверяют на краях —
первом и последнем номере — и на значениях посередине, а при правке
перечитывают данные. Исправление — вставить `"май"` на его место между
апрелем и июнем. Функция поиска при этом не меняется.

## Когда switch понятнее таблицы

Таблица хороша, когда выбираемое значение само указывает на ответ: номер —
на элемент, ключ — на запись. Оценка из урока 3.4 устроена иначе. За 90
баллов и больше ставится «отлично», за 50 и больше — «зачёт», за меньшее —
«незачёт». Ответ зависит от того, в какой промежуток попал балл.

Оценки можно записать и таблицей: баллов от 0 до 100 всего 101, и для
каждого можно заранее положить оценку в массив `[101]string`. Программа
ниже заполняет такой массив в функции `buildGrades`: три цикла заполняют
три промежутка. Переменную `grades` уровня пакета инициализирует вызов
этой функции —
начальным значением переменной может быть и такое выражение. Рядом стоит
`switch` без условия из урока 3.4 с одной новой первой веткой: для баллов
вне 0–100 обе функции возвращают пустую строку. Прежде чем смотреть
вывод, предскажите обе оценки для каждого из семи баллов.

```go

### Example: `10-grade-two-ways`

Источник: `examples/10-grade-two-ways/`

```go
// Оценка из урока 3.4 двумя способами: switch без условия и таблица на
// каждый балл от 0 до 100.
package main

import "fmt"

// gradeSwitch проверяет условия сверху вниз, как в уроке 3.4.
func gradeSwitch(score int) string {
	switch {
	case score < 0 || score > 100:
		return ""
	case score >= 90:
		return "отлично"
	case score >= 50:
		return "зачёт"
	default:
		return "незачёт"
	}
}

// buildGrades заполняет таблицу: по элементу на каждый балл от 0 до 100.
func buildGrades() [101]string {
	var t [101]string
	for s := 0; s < 50; s++ {
		t[s] = "незачёт"
	}
	for s := 50; s < 90; s++ {
		t[s] = "зачёт"
	}
	for s := 90; s <= 100; s++ {
		t[s] = "отлично"
	}
	return t
}

var grades = buildGrades()

// gradeTable находит оценку одним чтением по индексу.
func gradeTable(score int) string {
	if score < 0 || score > 100 {
		return ""
	}
	return grades[score]
}

func main() {
	for _, s := range []int{-1, 49, 50, 89, 90, 100, 101} {
		fmt.Printf("%d: %q %q\n", s, gradeSwitch(s), gradeTable(s))
	}
}

```
```

Ответы совпали на всех семи баллах, включая края промежутков. Обе функции
дают один результат на любом целом балле, и тест, который сравнивает
результаты, их не различит. Значит, выбор между ними — не вопрос
правильности, а вопрос того, что проще прочитать и поправить.

Сравните правку. Пусть граница «отлично» сдвигается с 90 на 85.

- В `switch` меняется одно число в одном `case`.
- В таблице, заполненной циклами, граница записана дважды: там, где
  кончается второй цикл, и там, где начинается третий. По сути циклы
  повторяют те же условия, что и `switch`, только длиннее.
- В таблице, записанной литералом из 101 элемента, нужно переписать пять
  элементов, от 85 до 89, и каждый найти по его месту в литерале.

Отсюда выбор, которого держится этот курс. Язык его не требует, а
компилятор и тесты не проверяют: это соглашение о ясности кода.

- Выбираемое значение — небольшие целые числа подряд, от нуля или со
  сдвигом на константу: таблица на массиве или slice с проверкой границ.
- Выбираемое значение — строка или разреженные коды: таблица на map, а для
  отсутствующего ключа — нулевое значение или форма с `ok`.
- Ответ зависит от промежутка или от условий с приоритетом, как дождь и
  жара в уроке 3.4: `switch`. Три условия читаются как правило задачи, а
  сотня элементов таблицы — нет.
- Ветки делают разную работу, а не возвращают разные значения: одна
  печатает, другая удаляет запись из map. Таблица этого модуля хранит
  значения, а не действия, поэтому для такой задачи нужен `switch`.
  Таблицу, где по ключу лежит действие, разбирает урок 5.5.

## Где живёт таблица

Таблицу обычно объявляют на уровне пакета, как `weekdays` и `factors` в
примерах выше: `var`, имя и литерал. Объявленную вне функций таблицу видят
все функции пакета, а литерал заполняет её один раз.

Хочется объявить таблицу через `const`, чтобы её нельзя было изменить. Но
константа в Go может быть только логическим значением, числом, руной или
строкой. Массив, slice и map в этот перечень не входят. Соберётся ли по
этому правилу программа ниже?

```go
@broken const-table
```

Не соберётся: `[7]string{…} (value of type [7]string) is not constant`.
Сообщение того же вида вы видели в уроке 2.12 у `math.Pow10`: значение,
которое не является константой, стоит там, где нужна константа.

Значит, таблица — обычная переменная, и любая функция пакета может в неё
записать. Функция `shorten` в программе ниже записывает сокращённое
название в первый элемент общей таблицы. Прежде чем смотреть вывод,
назовите обе строки.

```go

### Example: `11-mutable-table`

Источник: `examples/11-mutable-table/`

```go
// Таблица уровня пакета — обычная переменная: её может изменить любая
// функция пакета.
package main

import "fmt"

var weekdays = [7]string{
	"понедельник", "вторник", "среда", "четверг",
	"пятница", "суббота", "воскресенье",
}

func weekdayName(d int) string {
	if d < 1 || d > len(weekdays) {
		return ""
	}
	return weekdays[d-1]
}

// shorten хотела сократить название для себя, но записала его в общую
// таблицу.
func shorten() {
	weekdays[0] = "пн"
}

func main() {
	fmt.Printf("до: %q\n", weekdayName(1))
	shorten()
	fmt.Printf("после: %q\n", weekdayName(1))
}

```
```

После вызова `shorten` все функции пакета видят сокращённое название.
Объявить переменную неизменяемой в Go нельзя, а других способов уберечь
таблицу от записи этот модуль не разбирает. Таблица держится на
договорённости: её заполняет литерал, а функции пакета её только читают.

`Factor` возвращает, сколько граммов в одной единице массы с обозначением

| Обозначение | Граммов в единице |
|---|---|

| `"г"` | 1 |
| `"кг"` | 1000 |
| `"т"` | 1000000 |

Для любого другого обозначения функция возвращает 0. Ноль здесь —

отдаёт следующий месяц, а на 12 останавливает программу паникой. Без
проверки нижней границы 0 и отрицательные номера доходят до чтения по
индексу: 0 читает индекс −1, −1 — индекс −2. Перечитайте литерал:
пропущенное название проверка границ не найдёт.

## Factor

**Ступень 1.** Обозначение — строка, индексом массива она быть не может.
Какая коллекция хранит ответ по строковому ключу? Что она даёт для ключа,
которого нет, и подходит ли это значение как ответ для неизвестной единицы?

**Ступень 2.** Подойдёт map из обозначения в число граммов и обычное
чтение: для отсутствующего ключа оно даёт 0, а ноль здесь и есть
значение-метка. Форма с `ok` не нужна. Частые ошибки: возврат 1 или
другого числа для неизвестного обозначения и пара, пропущенная в литерале:
для такой единицы функция тоже вернёт 0.

## Category

**Ступень 1.** Указывает ли балл на один элемент данных или на промежуток?
Сколько чисел придётся поменять, если граница категории сдвинется? С чего
начать, чтобы баллы вне 0–100 не получили категорию?

**Ступень 2.** По соглашению урока для промежутков подходит `switch` без
условия из урока 3.4: первым `case` отсечь баллы вне 0–100, затем проверять
промежутки сверху вниз через `>=`. Таблица на 101 балл тоже даст верные
ответы, и тесты её примут, но ей нужна проверка границ массива, а при
заполнении в ней снова записываются границы промежутков. Частые ошибки:
`>` вместо `>=` отправляет край промежутка в соседнюю категорию, а без
первого `case` отрицательный балл станет «низким».

## Выбор таблицы: MonthName и Factor

<!-- review:tables-choice -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: какая
таблица подходит каждой функции и что она вернёт для значения, которого в
таблице нет. Образец ответа ниже.

- `MonthName` — slice или массив из двенадцати названий. Номера месяцев —
  небольшие целые числа подряд, поэтому номер указывает на элемент: месяц
  `m` лежит под индексом `m-1`. Для номера вне 1–12 ответ даёт проверка
  границ `m < 1 || m > len(months)`: она возвращает пустую строку раньше,
  чем чтение по индексу. Без неё номер 0 или 13 остановил бы программу
  паникой.
- `Factor` — map из обозначения в число граммов. Обозначение — строка, и
  индексом оно быть не может. Для неизвестного обозначения ответ даёт само
  чтение map: отсутствующий ключ даёт нулевое значение `float64`, то есть 0.
  Проверка границ не нужна, а форма с `ok` не нужна потому, что ни одна
  настоящая единица не весит ноль граммов: 0 — значение-метка.

Решение `MonthName`: `var months = []string{"январь", …, "декабрь"}` уровня
пакета, в теле — проверка границ и `return months[m-1]`. Решение `Factor`:
`var grams = map[string]float64{"мг": 0.001, "г": 1, "кг": 1000,
"т": 1000000}` и `return grams[unit]`. Правило то же, что в разделе теории
«Когда switch понятнее таблицы»: номера подряд — массив или slice, строки —
map.

## Форма Category

<!-- review:category-form -->

Второй вопрос: какую форму выбрать для `Category` и почему. Образец ответа
ниже.

Балл указывает не на один элемент, а на промежуток, поэтому по соглашению
курса категорию выбирает `switch` без условия. Первый `case` отсекает
баллы вне 0–100 и возвращает пустую строку. Дальше идут `score >= 90`,
`score >= 70` и `score >= 40`, а `default` возвращает «низкий». Порядок
`case` — порядок приоритета, как в уроке 3.4: балл 95 подходит и под
`score >= 70`, но его забирает условие выше.

Таблицу на 101 балл составить можно: область конечна, и массив `[101]string`
с проверкой границ даст те же ответы. Если граница «высокого» сдвинется с
70 на 75, в `switch` поменяется одно число в одном `case`. В таблице,
заполненной циклами, граница записана дважды, в конце одного цикла и в
начале другого. В таблице-литерале нужно переписать пять элементов, от 70
до 74. Поэтому для категорий `switch` проще читать и править.

Тесты этот выбор не различают. Они сравнивают только результаты, а у
`switch` и у таблицы с проверкой границ результаты на любом балле
одинаковы. Выбор формы — вопрос ясности и цены правки, а не правильности.

## Пропуск в таблице месяцев

<!-- review:missing-entry -->

Третий вопрос: что сделает с `MonthName` пропущенный май. Образец ответа
ниже.

Если таблица — slice, в нём остаётся 11 названий, и все названия после
апреля сдвигаются на одну позицию. Для 5 функция читает индекс 4 и
возвращает «июнь». Для 12 проверка видит, что номер больше длины 11, и
возвращает пустую строку. Если таблица — массив `[12]string` с тем же
литералом, названия сдвигаются так же, а незаданный последний элемент
пустой. Проверка пропускает 12, потому что `len` массива равна 12, и
функция возвращает этот пустой элемент.

Проверка через `len` сравнивает номер с длиной таблицы, а содержимое не
проверяет. Она защищает таблицу-slice от паники, но пропуск не находит ни в
slice, ни в массиве. Пропуск видно по неверному ответу для 5 и по пустой
строке для 12. Исправление — вставить `"май"` между апрелем и июнем.
Функцию поиска менять не нужно.

## MonthName читает months[m]

<!-- review:month-index-m -->

Решение проверяет границы верно, но читает `months[m]` без сдвига. Январь
лежит под индексом 0, поэтому для 1 функция возвращает февраль, для 11 —
декабрь, а для 12 читает индекс 12, равный длине, и останавливается
паникой.

Сдвиг индекса находит `TestMonthName`. Для 1 он сообщает
`MonthName(1) вернула "февраль", а должна вернуть "январь"`, а для 12 —
что функция вызвала панику. Исправление — читать `months[m-1]`.

## MonthName проверяет одну границу

<!-- review:month-no-lower-guard -->

Решение отсекает только номера больше длины таблицы. Для 1–12 ответы
верные. Для 0 функция читает индекс −1, для −1 — индекс −2, и программа
останавливается паникой: отрицательный индекс недопустим всегда (урок
4.1).

Недостающую нижнюю границу показывает `TestMonthName`: в его сообщении
`MonthName(0)` вызвала панику. Исправление — проверять обе границы:
`m < 1 || m > len(months)`.

## В таблице месяцев нет мая

<!-- review:month-missing-entry -->

Решение защищено проверкой через `len`, и паники нет. Но в литерале 11
названий: май пропущен. Для 1–4 ответы верные, для 5 функция возвращает
июнь, для 11 — декабрь, а для 12 — пустую строку.

Пропуск мая `TestMonthName` замечает на номере 5:
`MonthName(5) вернула "июнь", а должна вернуть "май"`. Проверка границ в
этой ошибке ни при чём: исправление — вставить `"май"` на его место в
литерале.

## Проверка сравнивает номер с числом 12

<!-- review:month-literal-guard -->

В таблице-slice 11 названий: декабрь пропущен. Проверка написана числом:
`m > 12` вместо `m > len(months)`. Для 1–11 ответы верные. Номер 12
проверку проходит, функция читает индекс 11, равный длине, и программа
останавливается паникой.

При границе, записанной числом, `TestMonthName` сообщает о панике: её
вызвала `MonthName(12)`. Исправлений два: дописать `"декабрь"` и
сравнивать номер с `len(months)`. Проверка через `len` не вернула бы
декабрь, но убрала бы панику: для 12 функция вернула бы пустую строку, и
тест назвал бы уже неверный ответ.

## Factor возвращает 1 для неизвестной единицы

<!-- review:factor-unknown-one -->

Решение читает map с признаком `ok` и для отсутствующего обозначения
возвращает 1. Для четырёх единиц таблицы ответы верные. Но договор требует
для неизвестного обозначения 0, а ответ 1 выдаёт «фунт» за грамм.

Неверный ответ для неизвестной единицы показывает `TestFactor`:
`Factor("фунт") вернула 1, а должна вернуть 0`. Исправление — вернуть
обычное чтение `grams[unit]`: нулевое значение и есть нужный ответ.

## В таблице единиц нет тонны

<!-- review:factor-missing-unit -->

В литерале map три пары: тонна пропущена. Для неизвестных обозначений
ответ верный, 0. Но и для `"т"` чтение даёт 0: пропавшая пара неотличима от
неизвестной единицы.

Пропавшую тонну находит `TestFactor`: он называет вызов `Factor("т")` и
сообщает, что вызов вернул 0 вместо множителя тонны из таблицы условия.
Исправление — дописать пару `"т": 1000000`.

## Граница «высокого» сдвинута

<!-- review:category-edge-shift -->

Решение проверяет `score > 70` вместо `score >= 70`. Баллы от 71 до 89
получают верный ответ, а сам край 70 уходит в следующий `case` и
становится «средним».

Сдвинутый край виден в сообщении `TestCategory`:
`Category(70) вернула "средний", а должна вернуть "высокий"`. Исправление —
`>=`: оба края промежутка входят в него.

## Category не отсекает баллы вне 0–100

<!-- review:category-no-range-check -->

В `switch` нет первого `case` для баллов вне 0–100. Отрицательный балл
проходит все условия и попадает в `default` — «низкий». Балл больше 100
забирает `score >= 90` — «отличный».

Пропущенную проверку диапазона `TestCategory` находит уже на −100:
`Category(-100) вернула "низкий", а должна вернуть ""`. Исправление —
первым `case` вернуть пустую строку для `score < 0 || score > 100`.

## Таблица категорий без проверки границ

<!-- review:category-table-no-guard -->

Решение заполняет массив `[101]string` четырьмя циклами и возвращает
`bands[score]`. Для баллов от 0 до 100 ответы верные. Для −100, −1, 101 и
1000 индекс выходит за границу, и программа останавливается паникой.

О панике сообщает `TestCategory`: её вызвала `Category(-100)`, и так же
каждый другой балл вне 0–100. Исправление —
проверка границ `score < 0 || score >= len(bands)` перед чтением. Сравните
и цену правки: чтобы сдвинуть границу, в таблице нужно менять два цикла, а
в `switch` — одно число.

## Что показали тесты

<!-- review:tests-observe -->

Остаётся понять, что установили скрытые тесты. Если тесты прошли, значит,
каждая функция дала верный ответ на каждом значении из списка раздела «Что
проверяется, а что нет», и ни одна не остановилась паникой. Тесты не
установили, какую форму вы выбрали: таблица и `switch` с одинаковыми

разделы разбора выше.

Если какой-то тест не прошёл, он назвал функцию и аргумент. Сверьте этот
аргумент с разделами выше: сдвиг индекса, одна граница, пропуск в таблице,
граница `>` вместо `>=`. Исправьте названную ошибку и запустите проверку
снова.

**Правильный ответ: C.**

Три разреженных кода удобнее хранить в map, чем в slice из 501 элемента.
Ветер задан промежутками: таблицу из 41 элемента составить можно, но сдвиг
границы перепишет в ней два элемента, а в `switch` — одно число. Этажи —
номера подряд, для них slice со сдвигом `floor-1` и проверкой через `len`.
Вариант A меняет формы местами: slice для разреженных кодов, map для
промежутков и ветвление для номеров подряд. Вариант B отказывается от
таблиц там, где данные читаются списком. Вариант D выдаёт соглашение курса
за правило корректности: обе формы дают одинаковые ответы.

## Вопрос 6

```go
@quiz _quiz/06-mutate
```

Что напечатает программа и защитит ли таблицу объявление через `const`?

Варианты ответа:

- A. 1, затем снова 1: `setCentimetres` изменила свою копию таблицы.
- B. 1, затем 100; объявить map через `const` нельзя, сборка это отвергнет.
- C. 1, затем 100; с `const` запись в `setCentimetres` перестанет
  собираться.
- D. Не соберётся: писать в переменную уровня пакета может только `main`.

Прежде чем смотреть ответ, скажите, сколько таблиц `factors` в программе и
чем может быть константа в Go.

**Правильный ответ: B.**

`factors` — одна переменная уровня пакета, её видят все функции (урок 2.3),
поэтому второе чтение вернуло 100. Константа бывает только логическим
значением, числом, руной или строкой, так что map через `const` не
объявить, как и массив в программе `const-table`. Вариант A ищет копию,
которой нет. Вариант C обещает защиту, которой язык не даёт. Вариант D
опирается на правило, которого в Go нет: в переменную уровня пакета может
записать любая функция пакета. Таблицу бережёт договорённость: функции её
только читают.

## Вопрос 7

Программа списка покупок получает команду строкой: «добавить» записывает
товар в map, «удалить» вызывает `delete`, «показать» печатает список. Какую
форму выбора взять?

Варианты ответа:

- A. Map из команды в название действия: поиск по ключу короче трёх
  `case`.
- B. Slice из трёх команд и цикл, который сравнивает команду с каждой.
- C. `switch`, потому что таблица в Go бывает только с числовыми ключами.
- D. `switch`: ветки делают разную работу, а таблицы урока хранят значения.

Прежде чем смотреть ответ, скажите, что делает каждая ветка: выдаёт
значение или выполняет работу.

**Правильный ответ: D.**

Таблица заменяет `switch`, когда ветки различаются только данными. У трёх
команд списка покупок три разные работы, и название действия их не
выполнит: после поиска понадобится тот же `switch` (вариант A). Цикл по
slice только длиннее повторяет сравнение (вариант B). Map со строковыми
ключами — обычное дело, как таблица множителей (вариант C). Таблицу, где по
ключу лежит действие, разбирает урок 5.5.
