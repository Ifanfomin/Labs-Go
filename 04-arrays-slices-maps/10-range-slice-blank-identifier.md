# Теория

# range по slice и пустой идентификатор

Индексный цикл даёт доступ к каждому элементу по номеру. Когда нужно читать
значения, `range` позволяет связать номер и значение в заголовке цикла.
Выбор формы зависит от того, какие из них нужны в теле. Для замены числа в slice
нужно записать новое значение в элемент по индексу.

## Формы range по slice

Для slice `s` с длиной три двухзначная форма `for i, v := range s` выполняет три
прохода. `i` получает 0, 1, 2 по порядку; `v` получает значение соответствующего
элемента для этого прохода. После последнего индекса цикл завершается. Эти два
значения даёт конструкция `range`; это не вызов функции, возвращающей два
результата.

В примере известная индексная сумма сначала переписана с `i, v`. Затем тело
перестаёт читать индекс. В форме `for _, v := range s` знак `_` — пустой
идентификатор: он принимает и отбрасывает индекс. Использовать его как значение в
выражении нельзя. Он не объявляет переменную и не считается новым именем, которого
требует `:=`; новым именем здесь служит `v`.

Если нужен только индекс, пишите `for i := range s`: `i` получит номера, а
значение элемента не создаётся для тела. Не нужно писать `for i, _ := range s`.
Если не нужен ни номер, ни элемент, `for range s` просто повторяет тело столько
раз, сколько элементов было при начале обхода. Запись `for v := range s` часто
ошибочно принимают за обход значений: единственная переменная в этой форме
получает **индекс**.

Прочитайте код примера. До чтения блока «Вывод» под ним назовите индекс и значение
на втором проходе и объясните, почему в последней сумме можно отбросить индекс.

```go

### Example: `01-forms`

Источник: `examples/01-forms/`

```go
package main

import "fmt"

func main() {
	s := []int{4, 5, 6}
	sum := 0
	for i := 0; i < len(s); i++ {
		sum += s[i]
	}
	fmt.Println("Индексная сумма:", sum)

	sum = 0
	for i, v := range s {
		fmt.Println("Пара:", i, v)
		sum += v
	}
	fmt.Println("Сумма по парам:", sum)

	sum = 0
	for _, v := range s {
		sum += v
	}
	fmt.Println("Сумма без индекса:", sum)

	for i := range s {
		fmt.Println("Индекс:", i)
	}
	count := 0
	for range s {
		count++
	}
	fmt.Println("Повторов:", count)
}

```
```

На втором проходе `i` равен 1, а `v` равен 5. Сумме нужен только `v`, поэтому `_`
получает ненужный индекс. Если тело читает лишь номера, достаточно одноимённой
формы без второго значения. Для `nil`-slice и другого slice длины ноль все эти
формы дают ноль проходов: у них нет индекса ноль, который можно было бы посетить.

Здесь `range` работает с коллекцией. В уроке 3.7 `for i := range n` по целому
числу давал один номер прохода, а не пару. Вид значения зависит от операнда. Позже
`range` по map даст ключ и значение (4.14), а обход строки будет отдельной темой
(9.2). Номера сегодняшнего slice нельзя объявлять позициями символов Unicode в
строке.

## Копия числа и запись по индексу

Значение `v` в двухзначном обходе slice чисел — отдельная переменная с копией
текущего числа. Присваивание `v = 99` меняет эту переменную, а не ячейку `s[i]`.
Для замены элемента запишите `s[i] = 99`. Копия `v` уже получена в начале текущего
прохода; запись в неё не меняет число, которое будет получено на следующем
индексе.

Прочитайте код и, прежде чем смотреть блок «Вывод», проследите оба цикла: каким
будет исходный slice после присваивания `v`, и каким после записи `s[i]`? Назовите
причину различия.

```go

### Example: `02-scalar`

Источник: `examples/02-scalar/`

```go
package main

import "fmt"

func main() {
	s := []int{1, 2}
	for _, v := range s {
		v = 99
		fmt.Println("Копия:", v)
	}
	fmt.Println("После записи в копию:", s)
	for i := range s {
		s[i] += 10
	}
	fmt.Println("После записи по индексу:", s)
}

```
```

Первый цикл менял только `v`, поэтому исходные числа остались прежними. Второй
записал новые числа по текущему индексу, и эти изменения видны через исходный
slice. Когда нужна замена элемента, индекс нужен в левой части присваивания.

## Когда элемент сам slice

Слово «копия» относится к **значению элемента**. Если элемент таблицы сам является
slice типа `[]int`, его значение — дескриптор строки, как в уроке 4.9. Копия
дескриптора `row` ведёт к тем же числам, что и строка в таблице. Поэтому запись
`row[j] = 7` меняет число в таблице. Присваивание `row = []int{9, 9}` связывает
лишь местную переменную с другой строкой; чтобы заменить строку таблицы,
понадобилось бы `rows[i] = ...`.

Прочитайте код и, прежде чем смотреть блок «Вывод», отдельно предскажите состояние
`rows[0]` после записи `row[0]` и после переназначения `row`. Объясните каждую
часть через копию дескриптора.

```go

### Example: `03-row`

Источник: `examples/03-row/`

```go
package main

import "fmt"

func main() {
	rows := [][]int{{1, 2}}
	for _, row := range rows {
		row[0] = 7
		fmt.Println("После записи в элемент:", rows)
		row = []int{9, 9}
		fmt.Println("Новая местная строка:", row)
	}
	fmt.Println("Таблица после обхода:", rows)
}

```
```

Первое действие записывает 7 в исходную строку; второе меняет только переменную
`row`. Присваивание копии числа не меняет исходный элемент, а запись через копию
дескриптора меняет число в строке.

## Новые и существующие переменные

Заголовок с `:=` объявляет переменные итерации в области цикла. На каждом проходе
они являются новыми переменными, как при `range` по целому числу в уроке 3.7.
Одноимённые внешние переменные при этом остаются отдельными. Заголовок с `=`
ничего не объявляет: существующие `i` и `v` получают очередные значения. Пустой
идентификатор новой переменной не добавляет.

Для `=` при нуле проходов присваиваний нет, поэтому прежние значения внешних
переменных сохраняются. При полном обходе непустого slice без записи в эти
переменные внутри тела в них останется последняя пара. `break` может оставить
более раннюю пару, а присваивание в теле может оставить другое значение. Это
правило о последней фактической записи, а не о магическом «последнем элементе».

Прочитайте код и, прежде чем смотреть блок «Вывод», назовите значения внешних `i`
и `v` после обоих циклов. В одном случае цикл использует `:=`, в другом — `=` и
пустой вход.

```go

### Example: `04-bindings`

Источник: `examples/04-bindings/`

```go
package main

import "fmt"

func main() {
	i, v := 17, 19
	for i, v := range []int{4, 5} {
		fmt.Println("Внутри:", i, v)
	}
	fmt.Println("Снаружи после :=:", i, v)

	var empty []int
	for i, v = range empty {
		fmt.Println("Этот проход отсутствует:", i, v)
	}
	fmt.Println("Снаружи после =:", i, v)
}

```
```

Цикл с `:=` объявил свои `i` и `v`, поэтому внешняя пара не изменилась. Во втором
цикле использованы внешние переменные, но пустой slice не дал ни одного
присваивания. Пустой идентификатор не дал бы читаемой переменной; с одним `_` в
заголовке `:=` не получило бы нового имени.

## Длина фиксирована, элементы читаются позже

Для обычной переменной slice `range` берёт значение slice при входе в цикл: его
начальную длину и дескриптор текущего хранилища. Число проходов поэтому
фиксировано. `append` к исходной переменной не добавляет проход для нового
элемента. При этом второе значение `v` считывается из хранилища, по которому
начался обход, когда соответствующий индекс достигнут. Если ранний проход меняет
ещё не посещённый элемент **того же** хранилища, поздний `v` увидит изменение.

Нужно различать два случая `append`. Если новая длина не превышает ёмкость,
`append` использует прежний массив; если превышает — результат получает новый
массив. В примере исходная ёмкость задана явно. Присваивание результата `append`
переменной `reused` или `moved` не меняет сохранённый дескриптор обхода; если
выделен новый массив, обход остаётся на старом. Не требуется угадывать, какой
станет новая ёмкость.

Прочитайте код и, прежде чем смотреть блок «Вывод», предскажите два вторых
значения `v` и число проходов в каждом из двух циклов. Укажите, из какого
хранилища пришло каждое второе значение.

```go

### Example: `05-saved-slice`

Источник: `examples/05-saved-slice/`

```go
package main

import "fmt"

func main() {
	reused := make([]int, 2, 4)
	reused[0], reused[1] = 10, 20
	for i, v := range reused {
		if i == 0 {
			reused[1] = 70
			reused = append(reused, 30)
		}
		fmt.Println("Есть место:", i, v)
	}
	fmt.Println("После первого обхода:", reused)

	moved := make([]int, 2, 2)
	moved[0], moved[1] = 10, 20
	for i, v := range moved {
		if i == 0 {
			moved = append(moved, 30)
			moved[1] = 80
		}
		fmt.Println("Места нет:", i, v)
	}
	fmt.Println("После второго обхода:", moved)
}

```
```

В первом случае запись `reused[1] = 70` меняет хранилище обхода до второго
прохода; второе значение равно 70. Во втором `append` при заполненной ёмкости
выделяет новый массив, и запись `moved[1] = 80` через переменную `moved`, уже
связанную с ним, не меняет старый элемент: второе значение равно 20. В обоих
случаях начальная длина была два, поэтому третий, добавленный элемент не
посещается.

## Массив-значение и явное чтение

Двухзначный `range` по значению массива получает копию массива для значений
элементов. Если тело меняет исходный массив, будущий `v` в этом обходе остаётся
значением из копии. В цикле только с индексом тело может само читать `a[i]`; такое
чтение обращается к **текущему исходному массиву**. Это различие касается
показанных форм и не требует правила «любое выражение range всегда копируется».

Прочитайте код и, прежде чем смотреть блок «Вывод», назовите второе число в первом
обходе и второе число, явно прочитанное как `a[i]` во втором. Почему ответы
различаются?

Источник: `examples/06-array/`

func main() {
	a := [2]int{1, 2}
	for i, v := range a {

		}

Первый обход уже имел копию массива со вторым числом 2. Второй читает изменённый

указателя на массив не рассматривается.

## Управление и изменение длины

`continue` завершает текущий проход тела и переходит к следующему индексу; `break`
завершает цикл. Эти значения уже известны из урока 3.5. На пустом и `nil`-slice
тело не запускается, поэтому обе инструкции просто не выполняются.

Прочитайте код и, прежде чем смотреть блок «Вывод», определите число проходов
отдельно для `nilSlice` и `empty`, затем назовите следующий индекс после
`continue` на первом элементе и скажите, будет ли проход после `break` на втором.
Объясните ответы через длину и управление циклом.

```go

### Example: `07-control`

Источник: `examples/07-control/`

```go
package main

import "fmt"

func main() {
	var nilSlice []int
	empty := []int{}
	n := 0
	for range nilSlice {
		n++
	}
	for range empty {
		n++
	}
	fmt.Println("Проходов по пустым:", n)

	for i, v := range []int{4, 5, 6} {
		if v == 4 {
			continue
		}
		fmt.Println("После continue:", i, v)
		if v == 5 {
			break
		}
	}
	fmt.Println("После цикла")
}

```
```

У `nilSlice` и `empty` длина ноль, поэтому оба обхода дали ноль проходов. После
`continue` на индексе 0 цикл берёт следующий индекс 1. После `break` на индексе 1
цикл завершён; индекс 2 не посещается.

Удаление, вставка или фильтрация меняют длину последовательности, а `range` уже
зафиксировал число проходов. Даже если переменная `s` стала короче, цикл не
пересчитывает предел. Если затем без проверки читать `s[i]`, поздний индекс может
выйти за текущую длину.

Прочитайте код и, прежде чем смотреть блок «Вывод», назовите число проходов после
уменьшения длины `s` и объясните, почему оно не совпадает с текущей длиной.

```go

### Example: `08-shrink`

Источник: `examples/08-shrink/`

```go

	s := []int{1, 2, 3}
	for i := range s {
		if i == 0 {

```

Цикл выполнил три прохода, хотя после первого длина `s` стала два: число проходов

алгоритм из 4.8, который управляет текущими индексами и длиной, либо собирайте
подходящие значения в отдельный результат. Для замены значения
**без изменения длины** форма `for i := range s` удобна: запись `s[i] = ...`
обращается к существующему элементу. Для чтения значений без изменения входа
удобна форма `for _, v := range s`.

## CountPositive

`CountPositive(s []int) int` возвращает количество элементов строго больше нуля.
Ноль и отрицательные числа не считаются. Пустой или `nil`-slice даёт ноль.
Исходный slice остаётся без изменений.

## ClampNegative

`ClampNegative(s []int) []int` заменяет каждое отрицательное число на ноль,
сохраняя остальные значения и их порядок. Замены должны быть видны вызывающему
коду через переданный slice; результат содержит эти же значения и имеет ту же
длину. Для пустого и `nil`-slice длина результата равна нулю. Не требуется
сохранять различие между `nil` и другим пустым slice в результате.

## IndexOf

`IndexOf(s []int, target int) int` возвращает индекс **первого** элемента, равного
`target`. Если совпадений нет, возвращает −1. На пустом или `nil`-slice совпадений
нет. Исходный slice остаётся без изменений.

## Как проверить себя

Перед запуском проверки придумайте случаи с первым совпадением на индексе 0, с
двумя совпадениями и без совпадений. Для замены проверьте не только возвращённые
значения, но и исходную переменную вызывающего кода. После попытки сравните
рассуждение с `review.md`. Собственный тест можно написать рядом с заготовкой
обычным `go test`; достаточно проверять выбранные случаи, не требуется
проектировать набор на все возможные реализации.

# Разбор после попытки

## Счётчик ошибочно берёт номера

Если использовать единственную переменную `for v := range s` как число элемента,
программа считает номера 0, 1, 2, … . На входе, где положительное число стоит на
индексе 0, результат может оказаться нулём. Это ловит `TestCountPositive`.
Исправьте заголовок так, чтобы тело получало значение элемента; ненужный индекс
отбросьте через `_`. Отдельно проверьте условие: ноль не положителен.

## Замена остаётся только в копии

Присваивание `v = 0` внутри обхода меняет местную переменную итерации. Исходный
элемент не изменяется; `TestClampNegative` проверяет и возвращённые числа, и
переменную вызывающего кода. Для замены записывайте ноль в `s[i]`. Если вместо
этого создать новый slice с правильными числами, вызывающий код всё равно не
увидит требуемую замену в переданном хранилище.

## Поиск возвращает последнее совпадение

Если запоминать каждый подходящий индекс и возвращать его после цикла, повторные
совпадения дадут последний индекс. `TestIndexOf` проверяет первое совпадение,
включая индекс ноль. Верните индекс сразу при первом равенстве; −1 оставьте для
полного обхода без совпадений. Такой ранний выход завершает функцию, а не только
текущий проход цикла.

Для `s := []int{4, 5}` подберите заголовок для четырёх задач: (а) получить только

прочитать и почему оно не заменяет новое имя при `:=`. Почему ответ про значения
нельзя переносить с `range s` на `range 2` и на позиции символов Unicode в строке?

- А. Одна переменная всегда получает элемент; `_` хранит отброшенный индекс.

- В. Одна переменная получает индекс slice; `_` создаёт вторую переменную,

**Ответ: Б.** Для (а) подходит `for i := range s`; для (б) —

объявляет имя; в форме (в) новое имя — `v`. Целое число в уроке 3.7 давало только
номера, а slice даёт индекс и необязательную копию элемента. Обход строки
изучается в 9.2: индексы slice из этого урока нельзя принимать за позиции символов
Unicode.

отдельный результат; объясните выбор через фиксированную длину обхода.

- А. Следующим будет индекс 1; после `break` обход окончен; для удаления нужна

- В. `continue` завершит весь цикл; удалять элементы можно в любом обходе без
