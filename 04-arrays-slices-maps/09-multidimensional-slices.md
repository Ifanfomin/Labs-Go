# Многомерные срезы

Цикл с двумя счётчиками из урока 3.8 вычислял значения ячеек, но не сохранял
строки. Теперь каждая строка — срез чисел, а внешний срез хранит строки.
Так можно держать результаты нескольких дней: в одном дне два измерения,
в другом три. Число дней и число измерений в каждом дне становятся
независимыми. Для доступа к измерению понадобятся два индекса и две
проверки границ.

## Два уровня

Тип `[][]int` читается снаружи внутрь: внешний slice содержит элементы типа
`[]int`; каждый такой элемент — строка целых чисел. Выражение `grid[i]` выбирает
**значение строки**, то есть дескриптор slice. Выражение `grid[i][j]` выбирает
число в этой строке. Первый индекс должен быть меньше `len(grid)`, второй —
меньше `len(grid[i])`. Наличие строки само по себе не обещает наличия в ней
столбца с индексом `j`.

Дескриптор строки содержит длину, ёмкость и связь с массивом её элементов — ту же
модель, что у обычного slice из урока 4.2. Внешний slice хранит
последовательность таких дескрипторов. Его элементы — не сами числа.
Схема показывает отдельное хранение двух строк:

- внешний slice `grid` → [дескриптор строки 0, дескриптор строки 1];
- дескриптор строки 0 → массив с числами [2, 4];
- дескриптор строки 1 → другой массив с числами [3, 5, 7].

В этой схеме строки выделены отдельно. Запись числа в строку 0 не затрагивает
строку 1. Два дескриптора могут вести и к одному массиву, как показано ниже.
Одинаковый тип `[][]int` допускает оба случая. Он также не требует
одинаковой длины строк и не обещает, что все строки лежат подряд в одном массиве.

Полный литерал показывает оба уровня типа:
`[][]int{[]int{2, 4}, []int{3, 5, 7}}`. Снаружи стоят элементы `[]int`, внутри —
числа. Вложенный тип в литерале можно опустить: `[][]int{{2, 4}, {3, 5, 7}}`
создаёт те же значения строк. Пользуйтесь полным написанием, пока различие
уровней не станет привычным.

## Длины и создание

У внешнего slice свои `len` и `cap`; у каждой строки — свои. `len(grid)` считает
строки, `len(grid[i])` — числа в конкретной строке. `cap(grid)` не определяет
ёмкость ни одной строки, а `cap(grid[i])` не говорит о числе строк. Нельзя
вывести длину второй строки из длины первой. В примере первые две строки имеют
разные длины, и обход складывает все пять чисел:

```go

### Example: `01-ragged`

Источник: `examples/01-ragged/`

```go
package main

import "fmt"

func main() {
    grid := [][]int{[]int{2, 4}, []int{3, 5, 7}}
    total := 0
    for row := 0; row < len(grid); row++ {
        for col := 0; col < len(grid[row]); col++ {
            total += grid[row][col]
        }
    }
    fmt.Println(len(grid), len(grid[0]), len(grid[1]), total)
}

```
```

Вызов `make([][]int, rows)` создаёт внешний slice длины `rows`. Его элементы
имеют нулевое значение типа `[]int`, то есть каждый слот пока содержит nil-slice.
Этот вызов **не создаёт числа внутри строк**. Например, при `rows == 2` можно
выбрать `grid[0]` и `grid[1]`, но пока у каждой строки длина ноль и `grid[0][0]`
недопустим. Чтобы получить прямоугольник с `cols` числами в каждой строке,
присвойте каждому слоту результат отдельного `make([]int, cols)`. Каждый такой
вызов даёт строку нужной длины, заполненную нулями. Отдельные строки с
положительной длиной получают независимые элементы.

Внешняя ёмкость тоже не резервирует столбцы. Например, `make([][]int, 2, 5)` даёт
длину внешнего slice 2 и ёмкость 5: в длину уже входят две ячейки для
дескрипторов строк, а ещё три внешние ячейки доступны для возможного роста.
Каждая из двух видимых строк при этом всё равно nil и имеет собственные нулевые
длину и ёмкость. Чтобы у строки появилась длина 3, нужно отдельно присвоить ей
`make([]int, 3)`. Получится строка с тремя нулевыми числами, но это никак не
изменит ни длину второй строки, ни число внешних строк. Так различайте три
величины при отладке: число внешних строк, длину выбранной строки и резерв
выбранной строки.

Нулевые размеры отвечают на два разных вопроса. При `rows == 0` внешняя длина
ноль: строки `grid[0]` нет независимо от `cols`. При `rows > 0` и `cols == 0`
строки есть, но в каждой ноль чисел. Пустая строка может быть nil или не nil; её
нулевая длина одинакова для индексного обхода. Представление пустоты здесь не
часть договора. Пример сначала показывает nil-строку после внешнего `make`, затем
создаёт две строки нулевой длины явно. Последняя строка вывода показывает
отдельные ёмкости внешнего slice и строки:

```go

### Example: `02-zero`

Источник: `examples/02-zero/`

```go
package main

import "fmt"

func main() {
    noRows := make([][]int, 0)
    noColumns := make([][]int, 2)
    fmt.Println(noColumns[0] == nil, len(noColumns[0]))
    for row := 0; row < len(noColumns); row++ {
        noColumns[row] = make([]int, 0)
    }
    fmt.Println(len(noRows), len(noColumns), len(noColumns[0]), noColumns[0] == nil)
    fmt.Println(cap(noColumns), cap(noColumns[0]))
}

```
```

У `var grid [][]int` внешний slice сам nil и имеет длину ноль. Для обхода и суммы
это тот же случай с нулём строк: внешний цикл не входит в тело. У
`make([][]int, 0)` внешний slice не nil, но длина тоже ноль. Договор `Grid` и
`CloneRows` здесь говорит о длинах и элементах, поэтому не требует сохранять один
из этих двух способов представления пустоты.

Не пытайтесь различать пустые строки по адресам или числу выделений. Для задачи
существенны длины и независимость **непустых** элементов. У двух строк с нулём
столбцов нет элементов, изменение которых могло бы проверить независимость.

## Обход неровных строк

В уроке 3.8 внешний цикл выбирал строку таблицы, а внутренний начинал столбец
заново. С хранимыми строками эта схема сохраняется. Внешний цикл идёт от `0` до
`len(grid)`, внутренний каждый раз идёт от `0` до `len(grid[row])`. При переходе
к следующей строке переменная столбца создаётся и начинает с нуля; граница заново
берётся у **текущей** строки. Такой обход работает для длинной, короткой, пустой
и nil-строки без особой ветки. При нуле строк внешнее тело не выполняется.

Можно было бы однажды вычислить `len(grid[0])` и использовать его в каждом
внутреннем цикле. Для нуля строк такое чтение сразу выходит за границу. Для
неровных строк оно тоже неверно: если следующая строка короче, обращение к
отсутствующему элементу вызовет панику; если длиннее, часть чисел будет
пропущена. Число, которое изменяется от строки к строке, должно вычисляться от
выбранной строки. Итог примера выше получается из двух слагаемых первой строки и
трёх второй. Значения в пустых строках не добавляются, потому что внутренний цикл
делает ноль проходов.

Для функции `Total` складывайте элементы именно в таком порядке обхода. Если
вызывающий код передаёт две строки со ссылкой на один и тот же массив, функция
прочитает значения **обеих** строк: наличие общего хранения не отменяет две
внешние ячейки. Задача суммы не изменяет элементы. Для значений из договора
упражнения обычное целое `int` вмещает итог; алгоритму не нужен отдельный буфер.

## Общая строка и замена ячейки

Отдельный `make` для каждой непустой строки — простой способ построить
независимые строки. Пример сперва создаёт две строки с одинаковыми начальными
числами и отдельно копирует числа в каждую. После изменения одного элемента
видно, что другая строка осталась прежней. Затем пример записывает один
`row := []int{1, 2}` в два внешних слота. Присваивание копирует дескриптор, а не
числа. Оба слота теперь ведут к одному массиву. Изменение `grid[0][0]` запишет
число в этот массив, поэтому через `grid[1][0]` видно то же число:

```go

### Example: `03-alias`

Источник: `examples/03-alias/`

```go
package main

import "fmt"

func main() {
    row := []int{1, 2}
    independent := make([][]int, 2)
    for i := 0; i < len(independent); i++ {
        independent[i] = make([]int, len(row))
        copy(independent[i], row)
    }
    fmt.Println(independent[0][0], independent[1][0])
    independent[0][0] = 8
    fmt.Println(independent[0][0], independent[1][0])

    grid := make([][]int, 2)
    grid[0] = row
    grid[1] = row
    grid[0][0] = 9
    fmt.Println(grid[0][0], grid[1][0])
    grid[0] = []int{5}
    fmt.Println(grid[0][0], grid[1][0])
}

```
```

При этом `grid[0] = []int{5}` заменяет **дескриптор во внешнем слоте 0**. Слот 1
остаётся с прежним дескриптором. Поэтому после замены в строке 0 видно новое
число, а в строке 1 остаётся прежнее изменённое число. Это два разных действия:
запись `grid[0][0]` меняет число по дескриптору; запись `grid[0]` меняет сам
дескриптор, лежащий во внешнем slice.

Одинаковые значения двух строк не доказывают независимости. Строки `[]int{1, 2}`
и `[]int{1, 2}`, созданные как два отдельных литерала, сначала выглядят так же,
как два слота с одним `row`. Отличие проявится после записи числа. При ремонте
кода, который кладёт один `row` в каждую внешнюю ячейку, создавайте новую строку
**внутри** цикла для каждого слота. Повторное присваивание того же `row` лишь
повторяет общий дескриптор.

## Копирование на двух уровнях

Вызов `copy(dst, grid)` с внешним `dst := make([][]int, len(grid))` создаёт новые
внешние слоты. Он копирует в них **значения элементов внешнего slice** —
дескрипторы строк. Замена `dst[0]` теперь не заменит `grid[0]`, но запись
`dst[0][0]` может изменить число, видимое через `grid[0][0]`. Это полезное
частичное разделение, но для независимых чисел его недостаточно. В примере
исходные два слота ещё и повторяют один `row`:

```go

### Example: `04-copy`

Источник: `examples/04-copy/`

```go
package main

import "fmt"

func main() {
    row := []int{1, 2}
    original := [][]int{row, row}
    outer := make([][]int, len(original))
    copy(outer, original)
    outer[0][0] = 7
    fmt.Println(original[0][0], original[1][0])
    separate := make([][]int, len(original))
    for i := 0; i < len(original); i++ {
        separate[i] = make([]int, len(original[i]))
        copy(separate[i], original[i])
    }
    separate[0][0] = 4
    original[1][1] = 8
    fmt.Println(separate[0][0], separate[1][0], separate[1][1], original[0][0])
}

```
```

Для независимых чисел нужны два уровня действий. Сначала создайте внешний
результат нужной длины. Затем для **каждой** исходной строки создайте
`make([]int, len(grid[i]))` и скопируйте в неё числа через `copy`. Даже если две
исходные строки содержат один и тот же дескриптор, двум итерациям соответствуют
две новые строки. Исходные значения сохраняются, но изменение элемента результата
не меняет вход; изменение элемента входа не меняет уже созданный результат.
Пустую строку можно представить nil или ненулевым пустым slice — договор требует
длину, а не точную форму пустоты.

Сравнение чисел сразу после копирования не проверяет независимость. Внешнего
`copy` хватит для равенства значений, и ошибка останется незаметной: общий массив
в этот момент содержит те же значения. Первая последующая запись в результат
проверяет, не испорчен ли вход. Запись во вход после получения результата
проверяет, не изменится ли уже выданный результат. Когда исходные слоты повторяют
одну строку, нужна ещё запись в одну строку результата с проверкой другой: обе
результирующие строки должны получить свои числа. Именно эти наблюдения выражают
обещание `CloneRows`, а не число внутренних вызовов выделения памяти.

Эту процедуру нельзя заменить одним `copy` внешнего slice. У `copy` нет особого
знания о двух уровнях: его элементом в этом вызове служит `[]int`, а не `int`.
Называйте результат «независимой копией элементов строк», а не общей операцией
глубокого копирования произвольной структуры. Здесь элементы строк — скалярные
`int`, для которых отдельная строка решает задачу.

## Добавление в строку

`append` возвращает новый дескриптор строки. Чтобы выросла строка
**внутри `grid`**, результат нужно присвоить обратно:
`grid[i] = append(grid[i], value)`.
Если сохранить результат только в локальной переменной, внешний слот останется со
старой длиной. Если не сохранить результат вовсе, вызов `append` нельзя
использовать как отдельную инструкцию.

Старый дескриптор и новый могут вести к общему массиву, когда у исходной строки
хватает ёмкости; тогда запись в общий индекс видна через оба. Если ёмкости для
добавления не хватает, `append` выделяет другой массив; дальнейшие записи через
новый результат не меняют старый. Старый дескриптор сохраняет прежнюю длину в
обоих случаях. Для строки литерала с одним элементом ёмкость равна одному,
поэтому добавление второго элемента в примере требует другого массива:

```go

### Example: `05-append`

Источник: `examples/05-append/`

```go
package main

import "fmt"

func main() {
    grid := [][]int{[]int{1}}
    old := grid[0]
    grid[0] = append(grid[0], 2)
    fmt.Println(len(old), len(grid[0]), grid[0][1])
    grid[0][0] = 9
    fmt.Println(old[0])
}

```
```

Нельзя по одному только `append` обещать, что старый псевдоним всегда отделился.
Результат зависит от ёмкости до вызова. Для обычного создания сетки проще заранее
выделять строки отдельно: тогда запись одного числа не затронет другую строку.
Если же намеренно используется общий `row`, следите отдельно за записью элемента,
заменой слота и сохранением результата добавления.

одной строки. Для `Total` берите границу внутреннего цикла от текущей строки, а
не от первой. Для `CloneRows` помните, что копирование внешних слотов сохраняет
дескрипторы строк; числа становятся независимыми только после создания и
копирования каждой строки. Эти три функции используют одну модель, но проверяют
разные действия: построить, прочитать и скопировать.

# Упражнение: построить, обойти и скопировать строки

В пакете `grid` дополните три готовые функции в `starter/`. Имена и сигнатуры уже

−1000 до 1000. Вход может быть nil или пустым внешним slice, содержать nil и
пустые строки, неровные строки и два слота с одной исходной строкой.

## Grid

`Grid(rows, cols int) [][]int` возвращает `rows` строк, каждая длины `cols` и
заполнена нулями. При положительном `cols` изменение одного элемента результата
не должно изменить элемент другой строки. Если `rows` или `cols` равно нулю,
сохраняются соответствующие длины: ноль строк или указанное число пустых строк.
Конкретное представление пустых строк не задано.

## Total

`Total(grid [][]int) int` возвращает сумму всех чисел во всех строках. Не
изменяйте вход. Считайте каждую внешнюю строку, даже если две строки разделяют
массив чисел. Пустой внешний slice и пустые строки дают нулевой вклад.
Используйте границу текущей строки, чтобы обработать неровный вход.

## CloneRows

`CloneRows(grid [][]int) [][]int` возвращает столько же строк и в том же порядке,
с теми же числами в каждой строке. Для каждой непустой строки элементы результата
должны храниться отдельно от элементов входа и от других строк результата. Это
действует и когда две исходные строки повторяют один дескриптор. После возврата
изменение числа в результате не меняет вход, а изменение числа во входе не меняет
результат. Вход не меняйте. Для нулевой длины строк различие nil и пустого slice
не требуется.

## Как проверить себя

Сначала проверьте размеры 0 и 1, затем неровный вход и повторяющуюся строку. Для
независимости недостаточно сравнить только значения сразу после вызова: запишите
число в одну строку и посмотрите на другую сторону. Свои тесты можно писать
обычным `go test` с ограниченными входами из постановки; специальные значения и
проверка реализации не нужны.

# Повторение

# Разбор типичных ошибок

## Одна строка для всех слотов

Если один `row` создаётся до цикла и записывается в каждый слот, все слоты
получают копии одного дескриптора. Значения сразу после построения выглядят
правильно, но запись `grid[0][0]` меняет тот же массив, который видит
`grid[1][0]`. Создавайте строку в каждой итерации. При нуле столбцов проверяйте
длины; независимость элементов имеет смысл только при наличии элемента.

## Граница первой строки

У `Total` использование `len(grid[0])` сначала требует существования строки 0, а
затем предполагает равную длину всех строк. Нулевой внешний размер вызывает
недопустимый индекс; короткая следующая строка вызывает такой же сбой во
внутреннем цикле; длинная следующая строка остаётся посчитанной не полностью.
Берите `len(grid[row])` при каждом значении внешнего индекса.

## Копия только внешних слотов

`copy(out, grid)` делает замену слота `out[i]` независимой от слота `grid[i]`, но
оба слота пока содержат дескрипторы общих чисел. Проверяйте запись числа в обе
стороны после копирования. Для `CloneRows` каждой итерации нужна новая строка
нужной длины и перенос её элементов. Если два входных слота содержат один
дескриптор, две отдельные строки результата всё равно обязательны.

## Потерянный результат добавления

`append` возвращает дескриптор с новой длиной. Для роста строки, сохранённой во
внешнем slice, присвойте результат в тот же слот. Старый псевдоним сохраняет
прежнюю длину и может разделять массив с новым результатом при достаточной
прежней ёмкости; само добавление не даёт общего обещания об отделении.

# Проверьте модель строк

## Вопрос 1

У `grid := [][]int{[]int{4, 6}, []int{9}}` назовите тип `grid[0]` и тип `grid[0][1]`. Какое число даёт второе выражение? Объясните, какой индекс выбирает строку. Можно ли записать этот же литерал как `[][]int{{4, 6}, {9}}`?

- А. `grid[0]` имеет тип `int` и равно 4; второй индекс уже не нужен.
- Б. `grid[0]` имеет тип `[]int`, `grid[0][1]` имеет тип `int` и равно 6.
- В. Оба выражения имеют тип `[]int`; второе содержит единственное число 6.

**Ответ: Б; компактная запись равнозначна.** Первый индекс выбирает элемент
внешнего slice — дескриптор строки `[]int`. Второй индекс выбирает число с
индексом 1 внутри этой строки. Во вложенном литерале тип строки разрешено
опустить, но она остаётся `[]int`. Вариант А пропускает внутренний уровень, а В
переносит тип всей строки на её скалярный элемент.

## Вопрос 2

Пусть `a := make([][]int, 0)`, а `b := make([][]int, 2)`; затем `b[0] = make([]int, 0)`, `b[1] = make([]int, 3)`. Нарисуйте внешние слоты и длину каждой имеющейся строки. Чем была `b[0]` сразу после внешнего `make`, до присваивания? Чему равны `len(a)`, `len(b)`, `len(b[0])` и `len(b[1])` после присваиваний? Какие отдельные ёмкости покажут `cap(b)`, `cap(b[0])` и `cap(b[1])`? Можно ли читать `a[0]` и `b[0][0]`? Какой предел нужен внутреннему циклу для `b[1]`? Если объявить `var c [][]int`, сколько строк и проходов внешнего цикла у `c`? Объясните.

- А. Длины 0, 2, 0, 3; оба чтения недопустимы; для `b[1]` предел `len(b[1])`.
- Б. Длины 0, 2, 0, 3; оба чтения допустимы; предел каждой строки равен `len(b)`.
- В. Длины 0, 2, 3, 3; оба чтения допустимы; предел каждой строки равен 3.

**Ответ: А; до присваивания `b[0]` была nil-строкой.** У `a` нет внешнего слота
0. У `b` два слота с нулевыми значениями типа `[]int`; присваивания заменили их
дескрипторы. После них отдельные ёмкости `b`, `b[0]` и `b[1]` равны 2, 0 и 3: у
каждого `make` без третьего аргумента ёмкость равна заданной длине. Строка 0
имеет ноль элементов, поэтому индекс 0 в ней недопустим. Строка 1 имеет три
элемента и собственную границу `len(b[1])`. У `c` внешний slice nil, его длина
ноль, поэтому внешний цикл делает ноль проходов. Вариант Б принимает внешнюю
длину за границу всех строк, а В переносит длину последней строки на каждую.

## Вопрос 3

`row := []int{1, 2}`; `g := [][]int{row, row}`; затем выполняются `g[0][0] = 7` и `g[0] = []int{5}`. Назовите `g[0][0]` и `g[1][0]` после обеих инструкций, а также объясните, какое действие изменило общий массив. Как исправить создание `g`, если изменение одной непустой строки не должно менять другую?

- А. Получатся 5 и 1; достаточно скопировать внешний slice.
- Б. Получатся 7 и 7; замена слота меняет обе строки.
- В. Получатся 5 и 7; создать каждую строку отдельно.

**Ответ: В.** Первая инструкция пишет 7 в массив, общий для двух дескрипторов;
вторая заменяет только слот 0 новым дескриптором. Поэтому слот 1 по-прежнему
показывает 7, а слот 0 — 5. Для независимых чисел каждой строке нужен свой
литерал или отдельный `make` внутри цикла. Вариант А ошибочно считает копию
внешних дескрипторов копией чисел; Б не различает слот и число.

## Вопрос 4

У `row := make([]int, 1, 2)` есть одна видимая ячейка и место ещё для одной. `g := [][]int{row}` и `old := g[0]`. Затем выполняется `g[0] = append(g[0], 8)` и `g[0][0] = 9`. Чему равны длины `old` и `g[0]`, чему равно `old[0]`? Почему результат `append` записан именно в `g[0]`?

- А. Обе длины 2, `old[0]` равно 9; `append` меняет все старые дескрипторы.
- Б. Длины 1 и 2, `old[0]` равно 9; внешний слот должен получить новый дескриптор длины 2.
- В. Длины 1 и 2, `old[0]` равно 0; `append` всегда отделяет массив.

**Ответ: Б.** Ёмкости два хватает для одного добавленного числа, поэтому новый и
старый дескрипторы используют общий массив. Запись существующего элемента видна
через `old`. Но длина `old` осталась равной одному: `append` возвращает новый
дескриптор, а не переписывает старый. Присваивание сохраняет новую длину в слоте
`g[0]`. Вариант А ошибочно меняет длину старого дескриптора, а В подменяет
условие выделения массива безусловным правилом.

## Вопрос 5

`source := [][]int{[]int{2}}`; `outer := make([][]int, len(source))`; `copy(outer, source)`. Предскажите `source[0][0]` после `outer[0][0] = 6`, затем `outer[0][0]` после `source[0][0] = 4`. Объясните обе стороны наблюдения. Как получить результат, в котором обе записи больше не пересекаются? Для нового входа `[][]int{[]int{2}}` выполните описанное в теории двухуровневое копирование. Предскажите число во входе после записи 6 в результат и число в результате после последующей записи 4 во вход; объясните каждое.

- А. Сначала 6, затем 6; запись через исходную строку не достигает копии.
- Б. Сначала 2, затем 6; внешнего `copy` уже достаточно для независимых чисел.
- В. Сначала 6, затем 4; создать для каждого слота результата строку нужной длины и скопировать в неё элементы.

**Ответ: В.** Внешний `copy` отделил слоты, но скопировал дескриптор строки.
Поэтому обе записи действуют на одно число. Отдельный
`make([]int, len(source[i]))` и `copy` для каждой строки разрывают общность чисел
в обоих направлениях. В новом опыте после записи 6 во вновь созданную строку вход
остаётся равен 2; после записи 4 во вход результат остаётся равен 6. Варианты А и
Б игнорируют связь скопированных дескрипторов с массивом строки.

## Вопрос 6

Внешний slice содержит строки длин 2, 0 и 3. Назовите число проходов внутреннего цикла для каждой строки и итог суммы, если числа равны соответственно `[]int{1, 2}`, `[]int{}`, `[]int{4, 5, 6}`. Почему нельзя использовать `len(grid[0])` для всех трёх строк?

- А. Проходов по 2 для каждой строки; сумма 12.
- Б. Проходов 2, 0 и 3; сумма 18.
- В. Проходов 2, 0 и 3; сумма 9, потому что третья строка не входит во внешнюю длину.

**Ответ: Б.** Внешняя длина равна трём, внутренний цикл при каждом переходе
начинает счёт заново и берёт длину выбранной строки. Сумма равна
1 + 2 + 4 + 5 + 6. Общая граница 2 вызвала бы обращение за пределы пустой
строки и пропустила бы последний элемент длинной строки. Варианты А и В
смешивают два уровня длины.
