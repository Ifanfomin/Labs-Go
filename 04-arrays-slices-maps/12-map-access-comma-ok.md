# Работа с картой и comma-ok

Программа хранит телефонную книгу в map: ключ — имя, значение — номер,
тип `map[string]string`. Ей приходится отвечать на два вопроса. Какой номер
у Бориса? Есть ли Борис в книге вообще? Пока у каждого записанного человека
есть настоящий номер, вопросы совпадают. Но человека могут внести в книгу
раньше, чем узнают его номер, — с пустой строкой вместо номера. Тогда ответ
«номер — пустая строка» подходит и к «Борис записан без номера», и к
«Бориса в книге нет». В этом уроке вы научитесь различать эти случаи, а
заодно записывать, менять и удалять записи map.

Понадобится пройденное:

- урок 4.11: тип `map[K]V`, создание map литералом и вызовом `make`,
  `len(m)`, чтение значения по ключу, который в map есть, `nil` как нулевое
  значение map и печать map через `fmt.Println`, где записи идут
  упорядоченными по ключам;
- урок 2.1: нулевые значения `0`, `""` и `false`;
- урок 2.10: `++` и `+=` для переменной;
- урок 3.2: короткая инструкция в заголовке `if` и область видимости её
  имён;
- урок 3.6: множественное присваивание;
- урок 4.10: пустой идентификатор `_`;
- урок 1.9: глагол `%q` у `fmt.Printf` печатает строку в кавычках, поэтому
  пустая строка видна как `""`.

К концу урока вы сможете:

- предсказать, что даёт чтение `m[k]` для отсутствующего ключа, и
  объяснить, почему такое чтение не отличает отсутствие ключа от
  записанного нулевого значения;
- проверить присутствие ключа формой `v, ok := m[k]` или `_, ok := m[k]`,

- выбрать для задачи обычное чтение или проверку присутствия и обосновать

## Чтение отсутствующего ключа

Выражение `m[k]` с ключом, который есть в map, даёт значение этой записи
(урок 4.11). Если ключа в map нет, выражение тоже даёт значение, а не
ошибку: нулевое значение типа значений map. Для `map[string]string` это
пустая строка `""`, для `map[string]int` — `0`, для `map[string]bool` —
`false`. Чтение ничего не добавляет в map: после него `len(m)` прежняя.

Программа ниже заводит книгу из двух записей. У Анны номер есть, Борис
записан с пустой строкой вместо номера, Веры в книге нет. Прежде чем
смотреть вывод, по правилу выше назовите, что напечатается для каждого из
трёх имён, чем закончится сравнение значений Бориса и Веры и сколько записей
будет в книге после трёх чтений.

```go

### Example: `01-phone-book`

Источник: `examples/01-phone-book/`

```go
package main

import "fmt"

func main() {
	// Телефонная книга: имя → номер.
	// Борис записан, но его номер пока неизвестен: пустая строка.
	phones := map[string]string{
		"Анна":  "555-01",
		"Борис": "",
	}
	fmt.Println("записей до чтения:", len(phones))

	anna := phones["Анна"]
	boris := phones["Борис"]
	vera := phones["Вера"] // Веры в книге нет
	fmt.Printf("Анна: %q\n", anna)
	fmt.Printf("Борис: %q\n", boris)
	fmt.Printf("Вера: %q\n", vera)
	fmt.Println("Борис и Вера неотличимы:", boris == vera)

	fmt.Println("записей после чтения:", len(phones))
}

```
```

Для Анны чтение дало её номер. Для Бориса — пустую строку, которая записана
в книге. Для Веры — тоже пустую строку: ключа нет, и чтение дало нулевое
значение типа `string`. Два значения равны, и по ним программа не может
решить, записан ли человек. Чтение Веры новой записи не создало: длина
книги осталась 2.

С числами и логическими значениями происходит то же. В следующей программе
склад хранит остатки товаров: яблоки записаны с остатком 0 — их распродали,
а слив в списке нет совсем. Вторая map хранит дни, когда магазин открыт, и
про воскресенье в ней ничего не записано. Прежде чем смотреть вывод,
назовите три напечатанных значения и длины обеих map.

```go

### Example: `02-zero-values`

Источник: `examples/02-zero-values/`

```go
package main

import "fmt"

func main() {
	// Остатки на складе: яблоки распроданы, груш осталось 7.
	stock := map[string]int{"яблоки": 0, "груши": 7}
	// Дни, когда магазин открыт.
	openDays := map[string]bool{"пн": true}

	fmt.Println("яблоки:", stock["яблоки"])
	fmt.Println("сливы:", stock["сливы"])

```
```

Остатки яблок и слив напечатаны одинаково, хотя яблоки в списке есть, а
слив нет. Для воскресенья чтение дало `false`: «магазин закрыт» и «про
воскресенье ничего не записано» выглядят одинаково. Обе map после чтений
сохранили прежнюю длину.

Такая неразличимость мешает не всегда. Если нулевое значение и есть
правильный ответ для отсутствующего ключа, обычного чтения хватает; этот
выбор разобран в разделе «Когда нужна проверка присутствия». Но в
телефонной книге пустой номер Бориса и отсутствие Веры — разные ответы, и
для них нужен второй вопрос к map.

## Значение и признак присутствия

Когда важно, есть ли ключ, чтение записывают с двумя именами слева:
`v, ok := m[k]`.

- `v` получает то же, что дало бы обычное чтение: значение записи, а если
  ключа нет, — нулевое значение.
- `ok` получает логическое значение (тип `bool`): `true`, если запись с
  ключом `k` в map есть, и `false`, если её нет. Какое значение хранит
  запись, на `ok` не влияет.

Имена выбираете вы; второе чаще всего называют `ok`, а саму форму — comma-ok
(«запятая-ok»). Если обе переменные уже объявлены, чтение записывают знаком
`=`: `v, ok = m[k]`. Такое чтение, как и обычное, map не меняет.

Если нужен только ответ «есть ли ключ», значение отбрасывают пустым
идентификатором из урока 4.10: `_, ok := m[k]`. Новым именем для `:=` здесь
служит `ok`.

Программа ниже читает ту же книгу с признаком присутствия. Переменные
названы по именам людей: `boris, borisOK`, `vera, veraOK`. Прежде чем
смотреть вывод, назовите значение и признак для Бориса и для Веры и признак
для Анны.

```go

### Example: `03-comma-ok`

Источник: `examples/03-comma-ok/`

```go
package main

import "fmt"

func main() {
	phones := map[string]string{
		"Анна":  "555-01",
		"Борис": "",
	}

	boris, borisOK := phones["Борис"]
	fmt.Printf("Борис: значение %q, ", boris)
	fmt.Println("есть в книге:", borisOK)

	vera, veraOK := phones["Вера"]
	fmt.Printf("Вера: значение %q, ", vera)
	fmt.Println("есть в книге:", veraOK)

	// Значение Анны не нужно: пустой идентификатор его отбрасывает.
	_, annaOK := phones["Анна"]
	fmt.Println("Анна: есть в книге:", annaOK)

	fmt.Println("записей:", len(phones))
}

```
```

Значения Бориса и Веры по-прежнему одинаковы — пустые строки. Различаются
признаки: запись Бориса в книге есть, записи Веры нет. У Анны программа
спросила только о присутствии, и её номер отбросил пустой идентификатор.

Вся картина — в одной таблице:

| Ключ | Что хранит map | Обычное чтение | `v` | `ok` |
|---|---|---|---|---|
| есть, значение не нулевое | номер `"555-01"` | этот номер | этот номер | `true` |
| есть, значение нулевое | пустая строка `""` | `""` | `""` | `true` |
| нет | ничего | `""` | `""` | `false` |

Два нижних ряда различаются только признаком `ok`. Обычное чтение для них
одинаково, поэтому различить их может только проверка присутствия.

## Одно выражение — два значения

Форма `v, ok := m[k]` похожа на строки урока 3.6, но устроена иначе. В
строке `a, b := 1, 2` справа стоит список из двух выражений, и каждое даёт
одно значение. Справа от `v, ok :=` стоит одно выражение — `m[k]`. Язык
разрешает этому выражению дать второе значение, признак присутствия, только
в особой форме: когда его результат присваивают или объявляют сразу в двух
переменных. В любом другом месте `m[k]` даёт одно значение: `v := m[k]` —
обычное чтение, и `fmt.Println(m[k])` печатает одно значение. Поэтому
правило урока 3.6 «сколько переменных, столько выражений» к этой форме не
относится: выражение одно, переменных две.

Эта форма — и не вызов функции. В уроке 5.2 вы встретите функции, которые
возвращают несколько результатов, и строки вида `a, b := f()`. Там оба
значения возвращает вызванная функция. В `m[k]` никакой функции не
вызывается: второе значение даёт само чтение map.

## Проверка в заголовке if

Признак присутствия обычно сразу проверяют, и удобнее всего — в заголовке
`if` (урок 3.2): `if num, ok := phones["Анна"]; ok {`. Короткая инструкция
до точки с запятой читает map и объявляет `num` и `ok`, условие после неё
проверяет `ok`. По правилу урока 3.2 оба имени действуют в условии, в ветке
`if` и во всей части `else`, а после инструкции `if` их нет.

Программа ниже проверяет двух людей. Прежде чем смотреть вывод, для каждой
инструкции `if` скажите, какая ветка выполнится, и назовите значение `num` в
той ветке, которая выполнится.

```go

### Example: `04-if-lookup`

Источник: `examples/04-if-lookup/`

```go
package main

import "fmt"

func main() {
	phones := map[string]string{
		"Анна":  "555-01",
		"Борис": "",
	}

	if num, ok := phones["Анна"]; ok {
		fmt.Println("звоним Анне:", num)
	} else {
		fmt.Println("Анны нет в книге")
	}

	if num, ok := phones["Вера"]; ok {
		fmt.Println("звоним Вере:", num)
	} else {
		fmt.Printf("Веры нет в книге, num = %q\n", num)
	}
}

```
```

Анна в книге есть: `ok` истинна, и ветка `if` напечатала её номер. Веры
нет: `ok` ложна, и выполнилась ветка `else`. `num` видна и там, но равна
нулевому значению — пустой строке. Во втором `if` имена `num` и `ok` новые:
имена первого заголовка кончились вместе с первой инструкцией `if`.

После `if` имён из заголовка нет. В следующей программе признак нужен и
после проверки. Прежде чем читать дальше, скажите, соберётся ли она.

```go
@broken after-if
```

Не соберётся: `undefined: ok`. Имя `ok` объявлено в заголовке и действует
только внутри инструкции `if`. Если признак нужен и после `if`, объявите
обе переменные отдельной строкой перед ней: `num, ok := phones["Анна"]`, а
в заголовке оставьте условие `if ok {`.

## Запись и перезапись

Запись в map выглядит как присваивание: `m[k] = v`. Если ключа `k` в map
нет, появляется новая запись, и `len(m)` вырастает на 1. Если ключ есть,
прежнее значение заменяется, а число записей не меняется. Записанное
значение 0 или `""` — полноценная запись: после `m["сливы"] = 0` проверка
`_, ok := m["сливы"]` даёт `true`.

`++` и `+=` работают с записью map так же, как с переменной (урок 2.10):
`m[k]++` значит `m[k] = m[k] + 1`, а `m[k] += n` значит `m[k] = m[k] + n`.
Сначала значение читается, потом результат записывается. Для отсутствующего
ключа чтение даёт 0, поэтому `m[k]++` создаёт запись со значением 1. Этим
они отличаются от обычного чтения: `++` и `+=` записывают, и после них ключ
в map есть.

Программа ниже начинает с пустой map и после каждой операции печатает длину
и саму map. Прежде чем смотреть вывод, для каждой из пяти операций назовите
число записей после неё и значение каждого ключа.

```go

### Example: `05-writes`

Источник: `examples/05-writes/`

```go
package main

import "fmt"

func main() {
	// Пустая map: записей нет.
	stock := map[string]int{}

	// Ключа «яблоки» нет: появляется новая запись.
	stock["яблоки"] = 5
	fmt.Println(len(stock), stock)

	// Ключ уже есть: прежнее значение заменяется.
	stock["яблоки"] = 3
	fmt.Println(len(stock), stock)

	// Груш не было: прочитан 0, записана 1.
	stock["груши"]++
	fmt.Println(len(stock), stock)

	// Прочитана 1, записано 11.
	stock["груши"] += 10
	fmt.Println(len(stock), stock)

	// Значение 0 — тоже запись.
	stock["сливы"] = 0
	fmt.Println(len(stock), stock)
}

```
```

| Операция | Что произошло | `len(stock)` |
|---|---|---|
| `stock["яблоки"] = 5` | ключа не было: новая запись | 1 |
| `stock["яблоки"] = 3` | ключ был: 5 заменено на 3 | 1 |
| `stock["груши"]++` | ключа не было: прочитан 0, записана 1 | 2 |
| `stock["груши"] += 10` | прочитана 1, записано 11 | 2 |
| `stock["сливы"] = 0` | ключа не было: новая запись со значением 0 | 3 |

Записи в выводе идут упорядоченными по ключам, как в уроке 4.11, а не в
порядке добавления.

Для записи нужен знак `=`. Знак `:=` объявляет новые переменные, и слева от
него могут стоять только имена. Программа ниже пытается создать запись
через `:=`. Прежде чем читать дальше, скажите, что ответит компилятор.

```go
@broken index-declare
```

Сообщение `non-name m["a"] on left side of :=` говорит, что слева от `:=`
стоит не имя. `m["a"]` обозначает запись map, а не новую переменную.
Замена — `m["a"] = 1`: запись появится, если ключа не было, и перезапишется,
если он был.

## Удаление записи

Встроенная функция `delete(m, k)` удаляет из `m` запись с ключом `k`. После
удаления существующего ключа `len(m)` уменьшается на 1, а `_, ok := m[k]`
даёт `false`. Если ключа `k` в map нет, `delete` ничего не делает: длина
остаётся прежней, и ошибки нет.

`delete` ничего не возвращает: ни удалённое значение, ни признак того,
была ли запись. Программа ниже пытается сохранить результат `delete` в
переменной. Прежде чем читать дальше, скажите, соберётся ли она.

```go
@broken delete-value
```

Сообщение `delete(m, "a") (no value) used as value` значит: у вызова
`delete` нет значения, а его используют как значение. Если нужно знать, была
ли запись, проверьте присутствие **до** удаления: сначала `_, ok := m[k]`,
потом `delete(m, k)`. После удаления такая проверка всегда даёт `false` и о
прошлом не говорит ничего.

Программа ниже удаляет из склада три ключа. У слив значение 0, вишни в map
нет. Прежде чем смотреть вывод, после каждого удаления назовите длину map и
признак присутствия удалённого ключа, а в конце — оставшиеся записи.

```go

### Example: `06-delete`

Источник: `examples/06-delete/`

```go
package main

import "fmt"

func main() {
	stock := map[string]int{"груши": 11, "сливы": 0, "яблоки": 3}
	fmt.Println("записей в начале:", len(stock))

	delete(stock, "яблоки")
	_, hasApples := stock["яблоки"]
	fmt.Println("после удаления яблок:", len(stock), hasApples)

	// У слив значение 0, но запись есть.
	delete(stock, "сливы")
	_, hasPlums := stock["сливы"]
	fmt.Println("после удаления слив:", len(stock), hasPlums)

	// Вишни в map нет.
	delete(stock, "вишня")
	fmt.Println("после удаления вишни:", len(stock), stock)
}

```
```

Удаление яблок и слив уменьшило длину на 1 каждое. Сливы хранили 0, но
удалила их та же операция: `delete` ищет запись по ключу, а значение не
проверяет. Вишни в map не было, поэтому `delete(stock, "вишня")` ничего не
изменил, и длина осталась прежней.

Чтобы удалить сразу все записи, есть встроенная функция `clear(m)`: после
неё `len(m)` равна 0. В этом уроке она только названа.

## nil-map: читать можно, записывать нельзя

Переменная `var prices map[string]int` без начального значения равна `nil`
(урок 4.11). В nil-map нет ни одной записи, и операции, которые только
смотрят в map, работают так же, как на пустой map: `len` даёт 0, обычное
чтение — нулевое значение, `v, ok` — нулевое значение и `false`, а `delete`
ничего не делает. Прежде чем смотреть вывод следующей программы, назовите
каждое значение, которое она напечатает.

```go

### Example: `07-nil-map-reads`

Источник: `examples/07-nil-map-reads/`

```go
package main

import "fmt"

func main() {
	// make не вызывали: это nil-map.
	var prices map[string]int
	fmt.Println("prices == nil:", prices == nil)
	fmt.Println("записей:", len(prices))
	fmt.Println("цена хлеба:", prices["хлеб"])

	_, hasBread := prices["хлеб"]
	fmt.Println("хлеб есть:", hasBread)

	delete(prices, "хлеб")
	fmt.Println("после delete записей:", len(prices))
}

```
```

Сравнение с `nil` истинно, а `len`, оба чтения и `delete` отработали без
аварии: в этих операциях nil-map вела себя как пустая map.

Запись — другое дело. По правилам языка присваивание элементу nil-map —
ошибка времени выполнения. Программа с такой записью компилируется, но при
записи аварийно завершается. То же с `++` и `+=`: они тоже записывают.
Прежде чем смотреть вывод программы ниже, скажите, на какой строке она
остановится и напечатает ли она цену хлеба.

```go

### Example: `08-nil-map-write`

Источник: `examples/08-nil-map-write/`

```go
package main

import "fmt"

func main() {
	// make не вызывали: это nil-map.
	var prices map[string]int

	// Запись в nil-map.
	prices["хлеб"] = 50

	fmt.Println("цена хлеба:", prices["хлеб"])
}

```
```

Программа остановилась на строке записи, и цена хлеба не напечаталась. В
выводе программы есть строка

`panic: assignment to entry in nil map`

По-русски: присваивание записи в nil-map. Слово `panic` в начале — так Go
называет такое аварийное завершение; как оно устроено, разбирает урок 5.17.
Компилятор эту программу принимает, поэтому ошибка видна только при
запуске.

Починка — создать map до первой записи: `prices := make(map[string]int)`
или литералом `map[string]int{}`. Такая map пустая, но не равна `nil`, и
запись в неё работает. Прежде чем смотреть вывод, назовите результат
сравнения с `nil`, длину и значение для хлеба после записи и `++`.

```go

### Example: `09-make-repair`

Источник: `examples/09-make-repair/`

```go
package main

import "fmt"

func main() {
	// make создаёт пустую map, которая не равна nil.
	prices := make(map[string]int)
	fmt.Println("prices == nil:", prices == nil)

	prices["хлеб"] = 50
	prices["хлеб"]++
	fmt.Println("записей:", len(prices), prices)
}

```
```

Вызов `make` создал пустую map, которая не равна `nil`. Первая запись
добавила ключ «хлеб», а `++` увеличил его значение с 50 до 51.

Отсюда правило для функций, которые получают map параметром. Функция, которая
только читает, проверяет присутствие и удаляет, работает и с nil-map. Функция,
которая записывает, требует от вызывающего кода map, которая не равна `nil`,
и её документация говорит об этом прямо.

## Когда нужна проверка присутствия

Обычное чтение и проверка присутствия отвечают на разные вопросы. Выбирайте
по тому, что должна сделать программа, когда ключа нет.

Проверка присутствия `v, ok := m[k]` нужна, если:

- нулевое значение может быть настоящей записью: пустой номер Бориса,
  нулевой остаток яблок;
- сам вопрос — есть ли ключ: записан ли человек в книге;
- при отсутствии ключа нужен ответ, отличный от нулевого значения,
  например сообщение «такого товара нет» или число −1.

Обычного чтения хватает, если нулевое значение и есть правильный ответ для
отсутствующего ключа. Так бывает при подсчёте и суммировании: за кандидата,
которого ещё никто не назвал, подано ноль голосов, и `votes[name]++` сам
начинает счёт с нуля. Проверка присутствия здесь ничего не добавила бы и
только удлинила бы код. Подробнее счётчики и множества на map разбирает
урок 4.13.

## Has

`Has` возвращает `true`, если в `m` есть запись с ключом `key`, и `false`,
если такой записи нет. Какое значение хранит запись, на ответ не влияет.
`m` после вызова не меняется.

Для `m := map[string]int{"Анна": 0, "Борис": 12}`:

- `Has(m, "Анна")` возвращает `true`: Анна в таблице, хотя очков у неё 0;
- `Has(m, "Вера")` возвращает `false`, и записи «Вера» после вызова в `m`
  нет;
- для nil-map `Has` возвращает `false`.

## GetOr

`GetOr` возвращает значение записи с ключом `key`, если запись есть, — в
том числе 0. Если записи нет, `GetOr` возвращает `fallback`. `m` после
вызова не меняется: `fallback` в map не записывается.

Для той же `m`:

- `GetOr(m, "Анна", 7)` возвращает 0: запись есть, запасное значение не
  нужно;
- `GetOr(m, "Борис", 7)` возвращает 12;
- `GetOr(m, "Вера", 7)` возвращает 7, и записи «Вера» после вызова нет;
- для nil-map `GetOr` возвращает `fallback`.

## Remove

`Remove` удаляет из `m` запись с ключом `key`, если она есть, и возвращает
число записей в `m` после этого. Если записи нет, `m` не меняется, и
результат равен текущему числу записей. Для nil-map результат 0.

Для `m := map[string]int{"Анна": 0, "Борис": 12}`:

- `Remove(m, "Анна")` возвращает 1, и записи «Анна» в `m` больше нет;
- следующий вызов `Remove(m, "Вера")` тоже возвращает 1: Веры не было;
- для nil-map `Remove` возвращает 0.

## Bump

`Bump` увеличивает на 1 значение записи с ключом `key` и возвращает новое
значение. Новое значение должно оказаться в `m`. Если записи нет, `Bump`
создаёт её со значением 1. Вызывающий код передаёт map, которая не равна
`nil`; поведение на nil-map тесты не проверяют.

Для `m := map[string]int{"Анна": 0, "Борис": 12}`:

- `Bump(m, "Анна")` возвращает 1, и в `m` для Анны записано 1;
- `Bump(m, "Борис")` возвращает 13;
- `Bump(m, "Вера")` возвращает 1, и в `m` появляется запись «Вера».

# Подсказки

## Has

**Ступень 1.** Что должна ответить `Has` для игрока с нулём очков? Что даст
обычное чтение `m[key]` для этого игрока и для игрока, которого в таблице

**Ступень 2.** Ответ функции — признак присутствия, а само значение не

идентификатор, а наружу уходит признак. Частая ошибка — `m[key] != 0`: такое
условие объявляет отсутствующим игрока, у которого записан 0.

## GetOr

**Ступень 1.** Когда должно сработать запасное значение: когда записано 0
или когда записи нет? Что вернёт обычное чтение в каждом из этих случаев?

**Ступень 2.** Прочитайте значение и признак одной строкой `v, ok := m[key]`,
например в заголовке `if`, и возвращайте `fallback` только при ложном
признаке. Частые ошибки: проверка `v != 0` вместо признака и запись
`fallback` в map — функция должна только читать, а на nil-map запись
завершила бы программу аварийно.

## Remove

**Ступень 1.** Что делает `delete` с ключом, которого нет, и с nil-map?
Нужна ли тогда проверка перед удалением? Какое число записей нужно вернуть —
до удаления или после?

**Ступень 2.** `delete` безопасен для любого ключа и для nil-map, поэтому
проверка присутствия перед ним не нужна; длину читайте после вызова. Частые
ошибки: условие `m[key] != 0` перед удалением оставляет запись с нулём, а
длина, запомненная до `delete`, на единицу больше нужной.

## Bump

**Ступень 1.** Что даёт чтение отсутствующего ключа и почему это удобное

значения в отдельной переменной?

**Ступень 2.** Операция `++` применима прямо к записи map: она читает
значение (0 для отсутствующего ключа) и записывает результат в map, так что
проверка присутствия здесь не нужна. Результат функции — значение, которое
теперь записано в map. Частая ошибка — скопировать значение в переменную и
увеличить её: map при этом не меняется.

## Где нужна проверка присутствия

<!-- review:choose-reads -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: какой
функции нужна проверка присутствия. Образец ответа ниже.

- `Has` — нужна. Вопрос функции и есть вопрос о присутствии. Для игрока с
  нулём очков обычное чтение даёт 0, для отсутствующего игрока — тоже 0, а
  ответы должны быть `true` и `false`. Решение: `_, ok := m[key]`, затем
  вернуть `ok`.
- `GetOr` — нужна. Ноль здесь законное значение, которое надо вернуть, а
  `fallback` нужен только при отсутствии ключа, и он может быть не нулём.
  Решение: `if v, ok := m[key]; ok { return v }`, после `if` —
  `return fallback`.
- `Remove` — не нужна. `delete` с отсутствующим ключом ничего не делает,
  поэтому проверять перед ним нечего. Решение: `delete(m, key)`, затем
  `return len(m)`.
- `Bump` — не нужна. Для отсутствующего ключа чтение даёт 0, и это
  правильное начало счёта: после увеличения получится 1, как требует
  договор. Решение: `m[key]++`, затем `return m[key]`.

Правило то же, что в разделе теории «Когда нужна проверка присутствия»:
проверка нужна, если сам вопрос — есть ли ключ, или если для отсутствующего
ключа нужен ответ, отличный от записанного нуля. Первый случай — у первой
функции списка, второй — у второй. `delete` и `++` сами правильно обходятся
с отсутствующим ключом, поэтому функциям `Remove` и `Bump` проверка не нужна.

## Какие функции работают с nil-map

<!-- review:nil-map-contract -->

Второй вопрос: почему `Has`, `GetOr` и `Remove` обязаны работать с nil-map,
а `Bump` получает map, которая не равна `nil`. Образец ответа ниже.

`Has` и `GetOr` только читают, а `Remove` читает длину и вызывает `delete`.
Все эти операции законны для nil-map: чтение даёт нулевое значение и
`false`, `len` — 0, `delete` ничего не делает. Поэтому договор этих функций
может обещать правильный ответ и для nil-map. `Bump` записывает: операция
`m[key]++` на nil-map завершила бы программу аварийно с сообщением
`panic: assignment to entry in nil map`. Поэтому её договор требует от
вызывающего кода map, созданную через `make` или литерал.

## Has сравнивает значение с нулём

<!-- review:has-zero-read -->

Решение возвращает `m[key] != 0`. Для игрока с ненулевым счётом ответ
верный, для отсутствующего — тоже. Но у Анны записан 0, и функция объявляет
её отсутствующей.

Ловит это `TestHas`: тест сообщает
`Has(m, "Анна") вернула false, а должна была вернуть true`. Исправление —
проверка присутствия `_, ok := m[key]` вместо сравнения значения с нулём.

## GetOr возвращает fallback для нуля

<!-- review:getor-zero-fallback -->

Решение возвращает прочитанное значение, только если оно не 0, а иначе —
`fallback`. Для отсутствующего ключа ответ верный. Но у Анны записан 0, и
функция возвращает запасное значение вместо настоящего.

Ловит это `TestGetOr`: тест сообщает
`GetOr(m, "Анна", 7) вернула 7, а должна была вернуть 0`. Решать, нужен ли
`fallback`, должен признак `ok`, а не значение.

## GetOr записывает fallback в map

<!-- review:getor-stores-fallback -->

Решение проверяет присутствие верно, но для отсутствующего ключа
записывает `fallback` в map и только потом возвращает его. Первый ответ
выглядит правильным. Однако в map появляется запись, которой там не было, и
следующий вызов с тем же ключом и другим запасным значением получает старый
`fallback`. На nil-map такая запись завершает функцию аварийно.

Ловит это `TestGetOr`: после вызовов тест сообщает, что в map 4 записи, а
должно остаться 3, а для nil-map — что `GetOr` завершилась аварийно.
`GetOr` только читает: запасное значение возвращается, но в map не
записывается.

## Remove удаляет только ненулевые записи

<!-- review:remove-zero-guard -->

Решение удаляет запись, только если `m[key] != 0`. Для ненулевых значений
и для отсутствующего ключа ответ верный. Но запись Анны хранит 0: условие
ложно, запись остаётся, и длина не уменьшается.

Ловит это `TestRemove`: тест сообщает
`Remove(m, "Анна") вернула 3, а должна была вернуть 2`. Проверка перед
`delete` не нужна вовсе: для отсутствующего ключа `delete` ничего не делает.

## Remove возвращает длину до удаления

<!-- review:remove-len-before -->

Решение запоминает `len(m)` до вызова `delete` и возвращает это число. Для
отсутствующего ключа оно совпадает с правильным. После удаления
существующего ключа результат на единицу больше настоящего числа записей.

Ловит это `TestRemove`: тест сообщает
`Remove(m, "Анна") вернула 3, а должна была вернуть 2`. Длину читают после
`delete`.

## Bump меняет только копию

<!-- review:bump-no-write -->

Решение копирует значение в переменную `v`, увеличивает её и возвращает.
Первый вызов для Анны возвращает 1, как и нужно. Но в map ничего не
записано: у Анны по-прежнему 0, а отсутствующий ключ так и не появился.

Ловит это `TestBump`: тест сообщает
`после Bump(m, "Анна") в map записано 0 (запись есть: true), а должно быть 1`.
Увеличивать нужно саму запись: `m[key]++`.

```

Что произойдёт при запуске и как починить программу?

Варианты ответа:

- A. Программа завершится аварийно на `len(visits)`: у nil-map нет длины.
