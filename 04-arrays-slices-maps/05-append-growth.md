# Теория

# append и рост среза

Датчик присылает показания температуры по одному, и сколько их придёт за
день, заранее неизвестно. Slice из `make` (урок 4.4) получает длину при
создании, а запись по индексу `s[i]` работает только внутри этой длины.
Чтобы дописать новое показание в конец, нужна встроенная функция `append`.
Она возвращает slice, который описывает удлинённую последовательность.

К концу урока вы сможете:

- дописать в slice одно или несколько значений и целый другой slice;
- сохранить результат `append` в переменной или вернуть его из функции,
  чтобы удлинённый slice не потерялся;
- предсказать, запишет ли `append` новые значения в тот же массив или в
  новый, и какие slice увидят эту запись;
- собрать результат, длина которого заранее неизвестна, без лишних нулей в
  начале.

Что понадобится из уроков 4.2–4.4. Значение slice — дескриптор: он называет
массив, лежащий в основе, место в этом массиве, где начинается slice, длину
`len` и ёмкость `cap`. Длина — сколько элементов видно через slice. Ёмкость
— сколько ячеек массива есть от начала slice до конца массива. Присваивание
`t := s` и передача slice в функцию копируют дескриптор, а не элементы: обе
копии дают доступ к одним и тем же ячейкам. Взять `s[:k]` можно, когда
`0 <= k <= cap(s)`, даже если `k` больше длины.

## Что дописывает append

Вызов `append(s, x)` получает slice `s` и значение `x` и возвращает slice,
в котором после всех элементов `s` стоит `x`. Новое значение встаёт на
позицию `len(s)`, сразу за последним видимым элементом: не в начало и не
на место уже существующих элементов. Значений можно передать несколько:
`append(s, x, y)` дописывает их по порядку. Тип значений совпадает с типом
элементов: к `[]int` дописывают `int`.

Результат — дескриптор, длина которого больше на число дописанных
значений. Обычно его присваивают той же переменной: `s = append(s, x)`.

Прежде чем смотреть вывод, предскажите содержимое и длину `readings` после
каждого вызова.

```go

### Example: `01-append-values`

Источник: `examples/01-append-values/`

```go
package main

import "fmt"

func main() {
	readings := []int{12, 15}
	fmt.Println("было:", readings, "len", len(readings))

	readings = append(readings, 14)
	fmt.Println("после одного значения:", readings, "len", len(readings))

	readings = append(readings, 18, 11)
	fmt.Println("после двух значений:", readings, "len", len(readings))
}

```
```

Одно значение увеличило длину на единицу, два значения — на два. Новые
значения стоят в конце, в том порядке, в каком их передали.

`append` работает со slice. Массив из урока 4.1 так не растёт: его длина
задана при объявлении и не меняется.

## Результат append нужно сохранить

`append` не меняет дескриптор, который получил. После вызова переменная `s`
описывает прежнюю длину, а удлинённую последовательность описывает только
возвращённое значение. Поэтому вызов `append` отдельной инструкцией, без
использования результата, компилятор не принимает:

```go
@broken bare-call
```

Сообщение `append(s, 1) (value of type []int) is not used` говорит, что
значение типа `[]int`, которое вернул вызов, никуда не попало. Спецификация
запрещает писать отдельной инструкцией и некоторые другие встроенные
функции, например `len` и `cap`.

Возвращать результат в ту же переменную не обязательно. Его можно
сохранить в новой переменной или сразу вернуть из функции:
`return append(s, x)`. Требование одно: там, где нужна удлинённая
последовательность, используйте возвращённый slice.

Функция `withTotal` ниже возвращает результат `append(readings, sum)`, а
`main` сохраняет результат второго вызова `append` в новой переменной
`extra`. Прежде чем смотреть вывод, предскажите `day`, `report` и `extra`
вместе с их длинами. Программа печатает и ёмкость `day`: по ней видно,
есть ли за длиной `day` свободные ячейки.

```go

### Example: `02-result`

Источник: `examples/02-result/`

```go
package main

import "fmt"

// withTotal возвращает показания и их сумму последним элементом.
func withTotal(readings []int) []int {
	sum := 0
	for i := 0; i < len(readings); i++ {
		sum += readings[i]
	}
	return append(readings, sum)
}

func main() {
	day := []int{3, 4}
	report := withTotal(day)
	extra := append(day, 9)

	fmt.Println("day:", day, "len", len(day), "cap", cap(day))
	fmt.Println("report:", report, "len", len(report))
	fmt.Println("extra:", extra, "len", len(extra))
}

```
```

У `day` длина осталась 2 после обоих вызовов. `append` вернул удлинённые
slice, а дескриптор в переменной `day` остался прежним. Ёмкость `day`
равна длине 2, то есть свободных ячеек за длиной нет. В какие ячейки легли
новые значения `report` и `extra` в таком случае, объясняет раздел
«Ёмкости не хватает: новый массив».

## Дописать весь slice: три точки

Вечерние показания уже собраны в отдельный slice, и их нужно дописать к
утренним. Вызов `append(dst, src)` не собирается: после первого
аргумента `append` ждёт значения элементов, а `src` — один slice, а не
несколько чисел `int`.

```go
@broken no-dots
```

Сообщение
`cannot use src (variable of type []int) as int value in argument to append`
значит: весь `src` стоит на месте, где нужно одно значение `int`, и типы
не совпадают.

Нужна запись `append(dst, src...)`. Три точки после последнего аргумента
означают: дописать по порядку каждый элемент `src`. Элементы `src` должны
быть того же типа, что элементы `dst`. В этом месте точки обязательны.
Почему язык записывает вызов именно так, объясняет урок 5.4 о вариативных
функциях.

Прежде чем смотреть вывод, предскажите `day`, `evening` после вызова и
`twice` — результат дописывания `evening` к самому себе.

```go

### Example: `03-spread`

Источник: `examples/03-spread/`

```go
package main

import "fmt"

func main() {
	morning := []int{12, 15}
	evening := []int{11, 9, 10}

	day := append(morning, evening...)
	fmt.Println("day:", day, "len", len(day))
	fmt.Println("evening:", evening, "len", len(evening))

	twice := append(evening, evening...)
	fmt.Println("twice:", twice, "len", len(twice))
}

```
```

`evening` не изменился, потому что `append` пишет новые значения только за
длиной `dst`: в свободные ячейки его массива или в новый массив. В
`append(morning, evening...)` запись идёт за длиной `morning`, а видимых
ячеек `evening` там нет, и вывод показывает его прежним. В
`append(evening, evening...)` приёмник — сам `evening`, но запись идёт за
его длиной, а три видимых элемента лежат до неё. Результат — `evening` с
дописанными к нему его же тремя элементами. Такой вызов законен:
спецификация гарантирует, что результат `append` не зависит от того,
пересекаются ли в памяти `dst` и `src`.

Но `append` может изменить и сам `src`. Если часть видимых ячеек `src`
лежит в том же массиве за длиной `dst`, `append` запишет в них новые
значения, и `src` изменится. Результат при этом всё равно верный. Как такое
получается и как этого избежать, разбирает урок 4.6.

## Ёмкости хватает: тот же массив

Через slice видны только первые `len` ячеек от его начала. Ячейки между
длиной и ёмкостью в массиве есть, но через этот slice не видны. `append`
пользуется ими: если за последним видимым элементом хватает свободных ячеек
для всех новых значений, `append` записывает значения в эти ячейки того же
массива. Переиспользование массива при достаточной ёмкости гарантирует
спецификация. Ёмкость результата тогда та же, что у `s`, а длина больше.

В программе ниже `s` создан через `make([]int, 3, 5)`: три видимых элемента
и ещё две ячейки, в которых лежат нули. `alias := s` копирует дескриптор.
Прежде чем смотреть вывод, предскажите:

- длину и ёмкость `s` и `r` после `r := append(s, 40)`;
- что покажет `s[:cap(s)]` до `append` и после него;
- что увидят `s`, `alias` и `r` после записи `r[0] = 99`.

```go

### Example: `04-room`

Источник: `examples/04-room/`

```go
package main

import "fmt"

func main() {
	s := make([]int, 3, 5)
	s[0] = 10
	s[1] = 20
	s[2] = 30
	alias := s
	fmt.Println("s[:cap(s)] до append:", s[:cap(s)])

	r := append(s, 40)
	fmt.Println("s:", s, "len", len(s), "cap", cap(s))
	fmt.Println("r:", r, "len", len(r), "cap", cap(r))
	fmt.Println("s[:cap(s)] после append:", s[:cap(s)])

	r[0] = 99
	fmt.Println("--- r[0] = 99 ---")
	fmt.Println("s:", s, "alias:", alias, "r:", r)
}

```
```

Схема массива до `append` и после него:

```схема
до append

           |  10  |  20  |  30  |   0  |   0  |
           +------+------+------+------+------+
индекс:       0      1      2      3      4
s, alias:  |<----- len=3 ------>|
           |<------------- cap=5 ------------>|
```

```схема

           +------+------+------+------+------+

           +------+------+------+------+------+

```

`append` записал 40 в ячейку 3 массива — первую свободную за длиной `s`.
`r` получил длину 4 и ту же ёмкость 5. Дескрипторы `s` и `alias` `append` не
менял: их длина по-прежнему 3, поэтому 40 через них не видно, пока не взять
`s[:cap(s)]`. Запись `r[0] = 99` изменила ячейку 0 общего массива, и её
увидели все три slice.

## Ёмкости не хватает: новый массив

Если свободных ячеек меньше, чем новых значений, `append` выделяет новый
массив. Он достаточно велик, чтобы вместить прежние элементы и новые
значения. `append` переносит в него элементы `s`, дописывает значения и
возвращает slice, который описывает новый массив. `s` и все копии его
дескриптора по-прежнему описывают старый массив.

Ниже та же программа, изменена только ёмкость: `make([]int, 3, 3)`.
Свободных ячеек нет. Прежде чем смотреть вывод, предскажите содержимое `r`
и то, увидят ли `s` и `alias` запись `r[0] = 99`.

```go

### Example: `05-no-room`

Источник: `examples/05-no-room/`

```go
package main

import "fmt"

func main() {
	s := make([]int, 3, 3)
	s[0] = 10
	s[1] = 20
	s[2] = 30
	alias := s

	r := append(s, 40)
	fmt.Println("s:", s, "len", len(s), "cap", cap(s))
	fmt.Println("r:", r, "len", len(r))
	fmt.Println("ёмкость r не меньше его длины:", cap(r) >= len(r))

	r[0] = 99
	fmt.Println("--- r[0] = 99 ---")
	fmt.Println("s:", s, "alias:", alias, "r:", r)
}

```
```

```схема
старый массив: s и alias до append и после него
           +------+------+------+
           |  10  |  20  |  30  |
           +------+------+------+
индекс:       0      1      2
s, alias:  |<----- len=3 ------>|
           |<----- cap=3 ------>|

новый массив: r после append и записи r[0] = 99
           +------+------+------+------+- - - +
           |  99  |  20  |  30  |  40  | ...? |
           +------+------+------+------+- - - +
индекс:       0      1      2      3
r:         |<--------- len=4 --------->|
           |<------------- cap=? ------------>|
```

`r` описывает новый массив, поэтому запись `r[0] = 99` через `s` и `alias`
не видна.

Какой будет ёмкость нового массива, язык не определяет. Он обещает только,
что ёмкость не меньше новой длины. Поэтому программа печатает не `cap(r)`, а
сравнение `cap(r) >= len(r)`. Конкретное число выбирает реализация Go, и в
разных версиях оно может быть разным; корректность программы от него
зависеть не должна. На схеме такая ёмкость подписана `cap=?`, а хвост
нового массива, о котором программа ничего не печатала, обозначен ячейкой
с многоточием.

## Точное правило

Оба случая сводятся к одной проверке. Пусть `append` дописывает к `s` k
значений. Тот же массив переиспользуется ровно тогда, когда
`len(s) + k <= cap(s)`. Иначе `append` выделяет новый массив. После любого
`append` ёмкость результата не меньше его длины, а при переиспользовании
равна `cap(s)`.

Из правила следуют два случая, которые легко пропустить:

- одной свободной ячейки мало для двух значений: при длине 3 и ёмкости 4
  вызов с двумя значениями требует пяти ячеек, и массив будет новый;
- k может быть нулём, если дописать пустой slice через три точки. Условие
  `len(s) + 0 <= cap(s)` верно всегда: длина slice не бывает больше его
  ёмкости. Поэтому такой вызов возвращает slice той же длины на том же
  массиве, даже когда свободных ячеек нет.

Функция `base` ниже создаёт slice из трёх элементов с заданной ёмкостью.
Функция `report` пишет 1 в `r[0]` и печатает, увидел ли эту запись
исходный slice. Прежде чем смотреть вывод, для каждой строки сложите длину
3 и число значений, сравните сумму с ёмкостью и предскажите `len(r)` и ответ
«общий массив».

```go

### Example: `06-rule`

Источник: `examples/06-rule/`

```go
package main

import "fmt"

// base возвращает slice из трёх элементов с заданной ёмкостью.
func base(capacity int) []int {
	s := make([]int, 3, capacity)
	s[0] = 10
	s[1] = 20
	s[2] = 30
	return s
}

// report пишет 1 в r[0] и сообщает, увидел ли эту запись исходный s.
func report(label string, s []int, r []int) {
	r[0] = 1
	fmt.Println(label, "len(r) =", len(r), "общий массив:", s[0] == 1)
}

func main() {
	a := base(5)
	report("cap 5, два значения:", a, append(a, 40, 50))

	b := base(4)
	report("cap 4, два значения:", b, append(b, 40, 50))

	c := base(5)
	report("cap 5, три значения:", c, append(c, 40, 50, 60))

	d := base(3)
	none := make([]int, 0)
	report("cap 3, ноль значений:", d, append(d, none...))
}

```
```

Короткая проверка «есть свободная ячейка, если `len(s) < cap(s)`» верна
только для одного значения. Для нескольких значений складывайте длину с их
числом.

## append внутри функции

Функция получает копию дескриптора (урок 4.2). `append` внутри функции
может записать значения в ячейки общего массива, но длину переменной
вызывающего кода не изменит: в этой переменной лежит свой дескриптор.
Поэтому функция, которая удлиняет slice, возвращает результат `append`, а
вызывающий код сохраняет его: `base = add(base, 30)`.

`addLost` в программе ниже выполняет `s = append(s, v)` и ничего не
возвращает, а `add` возвращает результат. У `base` длина 3 и ёмкость 5.
Прежде чем смотреть вывод, предскажите длину `base` после `addLost`,
содержимое `base[:4]` и `base` после `base = add(base, 30)`.

```go

### Example: `07-caller`

Источник: `examples/07-caller/`

```go
package main

import "fmt"

// addLost дописывает v и ничего не возвращает.
func addLost(s []int, v int) {
	s = append(s, v)
}

// add дописывает v и возвращает результат append.
func add(s []int, v int) []int {
	return append(s, v)
}

func main() {
	base := make([]int, 3, 5)
	base[0] = 1
	base[1] = 2
	base[2] = 3

	addLost(base, 10)
	fmt.Println("после addLost: base", base, "len", len(base), "base[:4]", base[:4])

	base = add(base, 30)
	fmt.Println("после base = add(base, 30): base", base, "len", len(base))
}

```
```

`addLost` записала 10 в свободную ячейку 3 общего массива: это видно через
`base[:4]`. Но длина `base` осталась 3: присваивание `s = append(s, v)`
изменило только параметр `s` внутри функции. Затем `add` записала 30 в ту
же ячейку 3 — значение 10 пропало — и вернула дескриптор длины 4, который
`main` присвоила `base`.

Итог для функций: если функция удлиняет slice, результат `append` нужно
вернуть, а вызывающему коду — сохранить. При этом запись в общие ячейки
массива может произойти и без возврата. Как уберечь от таких записей
соседние slice и как получить независимый результат, разбирает урок 4.6.

## Результат неизвестной длины

Часто длина результата выясняется только в цикле: сколько показаний
окажутся положительными, до цикла неизвестно. Такой результат накапливают:
начинают со slice длины 0 и на каждом подходящем элементе сохраняют
результат `append`.

Начать можно с объявления `var out []int`. Как у `int` нулевое значение —
0, а у `string` — пустая строка (урок 2.1), так и у slice есть своё нулевое
значение. Это значение называют nil, а slice с ним — nil-slice. Значение
nil — не число и не пустая строка. Длина и ёмкость nil-slice равны нулю,
массива у него ещё нет, а `append` принимает его как обычный slice длины 0
и выделяет массив при первом значении. Сравнивать slice с nil и отличать
nil-slice от пустого slice, созданного через `make` или литерал, учит
урок 4.7.

Второй способ — `make([]int, 0, c)`: длина 0 и ёмкость `c`, где `c` —
оценка сверху, например длина входа. Пока значений не больше `c`, по
точному правилу `append` пишет в тот же массив. Элементы результата у
обоих способов одинаковые.

Функция `evens` ниже собирает чётные числа. Прежде чем смотреть вывод,
предскажите строку для `var empty []int`, результаты обоих вызовов `evens` и
slice `withRoom` после одного `append`.

```go

### Example: `08-accumulate`

Источник: `examples/08-accumulate/`

```go
package main

import "fmt"

// evens собирает чётные числа из nums в исходном порядке.
func evens(nums []int) []int {
	var out []int
	for i := 0; i < len(nums); i++ {
		if nums[i]%2 == 0 {
			out = append(out, nums[i])
		}
	}
	return out
}

func main() {
	var empty []int
	fmt.Println("var empty []int:", empty, "len", len(empty), "cap", cap(empty))

	some := evens([]int{3, 8, 5, 2, 8})
	fmt.Println("evens с чётными:", some, "len", len(some))

	none := evens([]int{1, 7})
	fmt.Println("evens без чётных:", none, "len", len(none))

	withRoom := make([]int, 0, 4)
	withRoom = append(withRoom, 5)
	fmt.Println("make(0, 4) и одно значение:", withRoom, "len", len(withRoom), "cap", cap(withRoom))
}

```
```

Вызов `evens` без чётных чисел вернул slice длины 0: тело `if` не
выполнилось ни разу, и `out` остался таким, каким его объявили. Ёмкость
`withRoom` осталась 4: одно значение уместилось в свободную ячейку.

## Лишние нули в начале

`make([]int, n)` создаёт slice длины n, и все n элементов — нули (урок 4.4).
`append` дописывает после длины, а не заполняет эти нули. Если после такого
`make` дописать n значений, получится 2n элементов, и первые n из них —
нули.

Прежде чем смотреть вывод, предскажите все три строки: длину и элементы
каждого slice.

```go

### Example: `09-leading-zeros`

Источник: `examples/09-leading-zeros/`

```go
package main

import "fmt"

func main() {
	n := 3

	mixed := make([]int, n)
	for i := 0; i < n; i++ {
		mixed = append(mixed, i+1)
	}
	fmt.Println("make(n) и append:", mixed, "len", len(mixed))

	filled := make([]int, n)
	for i := 0; i < n; i++ {
		filled[i] = i + 1
	}
	fmt.Println("make(n) и запись по индексу:", filled, "len", len(filled))

	grown := make([]int, 0, n)
	for i := 0; i < n; i++ {
		grown = append(grown, i+1)
	}
	fmt.Println("make(0, n) и append:", grown, "len", len(grown))
}

```
```

Обе верные записи дают три элемента. Выбирают по задаче. Если длина
результата известна до цикла и каждая позиция получает значение, подходит
`make([]int, n)` и запись по индексу. Если значения появляются по одному и
их число заранее неизвестно, подходит длина 0 и `append`. Правила «одна из
двух записей всегда быстрее» нет: выбирают по тому, что известно о длине.
Ошибка — смешать записи: взять длину n из `make`, а потом дописывать через
`append`.

## Add

`Add` возвращает slice, в котором после всех элементов `s` стоит `value`.
Длина результата на единицу больше длины `s`. Вызывающий код сохраняет
возвращённый slice: `log = readings.Add(log, v)`. Причина — вызов не
меняет длину в переменной `log`: удлинённый журнал есть только в
возвращённом значении, и оно может описывать новый массив. При этом, если
у `s` хватает свободной ёмкости, результат может использовать массив `s`.

- для `s` с элементами 4, −2, 7 и `value`, равного 9, результат — 4, −2,
  7, 9 длины 4;
- для `s` длины 0 и `value`, равного 5, результат — один элемент 5.

## CollectPositive

`CollectPositive` возвращает новый slice, в котором по порядку стоят все
положительные элементы `s`. Ноль не положителен. Если положительных нет,
длина результата 0. Элементы `s` после вызова те же, что до него: функция
собирает результат в своём накопителе, а не поверх входа.

- для входа 3, −1, 0, 4, 4 результат — 3, 4, 4 длины 3;
- для входа −5, 0 результат имеет длину 0.

## Два вызова Add к одному журналу

<!-- review:caller-trace -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»: что
содержат `base`, `a` и `b` после `a := Add(base, 10)` и `b := Add(base, 20)`.
Образец ответа ниже.

Верное решение `Add` — одна строка `return append(s, value)`. У `base` длина
3 и ёмкость 5, и оба вызова дописывают одно значение: 3 + 1 <= 5, поэтому
оба переиспользуют массив `base`. Первый вызов пишет 10 в ячейку 3 и
возвращает дескриптор длины 4, который попадает в `a`. Второй вызов
получает тот же `base` длины 3 и пишет 20 в ту же ячейку 3. После него
`a` и `b` — оба 1, 2, 3, 20: `a` видит запись второго вызова, потому что
описывает тот же массив. `base` по-прежнему длины 3 и показывает 1, 2, 3:
ни один вызов не менял дескриптор в `base`.

Чтобы журнал действительно вырос, результат сохраняют в той же переменной:
`base = Add(base, 10)`, затем `base = Add(base, 20)`. Тогда второй вызов
получает дескриптор длины 4 и пишет 20 в ячейку 4, а журнал становится
1, 2, 3, 10, 20. Если нужны два независимых удлинения одного журнала,
понадобится отдельный массив для каждого; как его получить, разбирает
урок 4.6.

Скрытый тест не проверяет, в какие ячейки легли 10 и 20: он видит только
возвращённый slice. Поэтому рассуждение о том, какой дескриптор описывает
какую длину, проверяете вы сами.

## Откуда лишние нули

<!-- review:two-n -->

Второй вопрос из того же раздела: что вернёт `CollectPositive`, если
начать накопитель с `make([]int, len(s))`.

Для входа 4, −1, 6 накопитель сразу получает длину 3 и три нуля. `append`
дописывает после длины, а не на место нулей, поэтому 4 и 6 встают на
позиции 3 и 4. Результат — 0, 0, 0, 4, 6 длины 5. Нули пришли из `make`, и
их столько же, сколько элементов во входе.

Верное решение начинает накопитель с длины 0:

- `var out []int`, затем трёхчастный цикл по `s`;
- в теле `if s[i] > 0 { out = append(out, s[i]) }`;
- после цикла `return out`.

`make([]int, 0, len(s))` вместо `var out []int` тоже верно: длина та же,
0, а ёмкость лишь решает, когда `append` выделит массив. `make([]int, n)`
подходит другой задаче — когда длина результата известна до цикла и каждая
позиция заполняется записью по индексу.

## Вход без положительных

<!-- review:empty-result -->

Третий вопрос: что вернёт `CollectPositive` для входа без положительных.

Условие `s[i] > 0` ни разу не выполняется, `append` не вызывается ни разу,
и функция возвращает накопитель таким, каким его объявили, — длины 0.
Отдельная проверка не нужна. С `var out []int` накопитель — nil-slice, с
`make([]int, 0, len(s))` — пустой slice, созданный через `make`. Контракт
упражнения требует только длины 0, и тест различать их не будет; чем они
отличаются, разбирает урок 4.7.

## Удлинение без append

<!-- review:add-reslice -->

Решение берёт `r := s[:len(s)+1]`, пишет `value` в `r[len(s)]` и
возвращает `r`. Пока у `s` есть свободная ёмкость, ответ верен: `append`
тоже записал бы значение в следующую ячейку того же массива. Но на входе
без свободной ёмкости взятие `s[:len(s)+1]` выходит за `cap(s)` и
вызывает панику.

`TestAdd` получает эту панику на входах без свободной ёмкости, в том числе
длины 0, и сообщает о ней вместо результата. `append` сам проверяет ёмкость и при
нехватке выделяет новый массив, поэтому верное решение —
`return append(s, value)`.

## Значение в начале

<!-- review:add-prepend -->

Решение `return append([]int{value}, s...)` собирается и возвращает slice
нужной длины, но `value` стоит первым: дописан оказался `s` к slice из
одного `value`, а не наоборот.

`TestAdd` не проходит на каждом входе, где `s` не пустой: для 4, −2, 7 и 9
тест ждёт 9 последним. Первый аргумент `append` — slice, к концу которого
дописывают, поэтому нужен `append(s, value)`.

## Накопитель длины len(s)

<!-- review:collect-leading-zeros -->

вопросе упражнения (раздел «Откуда лишние нули»). Для пустого входа ответ

## Накопитель поверх входа

<!-- review:collect-in-place -->

Решение начинает накопитель с `out := s[:0]`. Длина у него 0, но массив —
тот же, что у входа, и ёмкость входа вся свободна для `append`. Каждый
`append` пишет положительное значение в ячейку входа: возвращённые элементы
верны, а вход испорчен.

Порчу входа обнаруживает `TestCollectPositive` на смешанном входе
3, −1, 0, 4, 4, −7, 3: результат совпадает с ожидаемым, но первые четыре
элемента входа после вызова стали 3, 4, 4, 3. Контракт требует, чтобы
вход остался прежним, а накопитель должен иметь свой массив:
`var out []int` или `make([]int, 0, len(s))`.

## Вопрос 1

Переменная `s` имеет тип `[]int`. Какие из четырёх строк компилятор примет?

1. `s = append(s, 1)`
2. `t := append(s, 1)`, если `t` дальше используется
3. `return append(s, 1)` в функции с результатом типа `[]int`
4. `append(s, 1)` отдельной инструкцией

Варианты ответа:

- A. Только 1: результат обязан вернуться в ту же переменную.
- B. 1 и 3: результат можно вернуть, но новой переменной он не достаётся.
- C. 1, 2 и 3: результат нужно использовать, а где — решает программа.
- D. Все четыре: `append` сам удлиняет `s`, и результат можно не сохранять.

Прежде чем смотреть ответ, объясните, что именно компилятор отвергает в
строке 4 и чего он не требует от строк 2 и 3.

**Правильный ответ: C.**

`append` возвращает новый дескриптор и не меняет тот, что получил, поэтому
вызов без использования результата отвергается: значение типа `[]int`
никуда не попадает. Присвоить результат новой переменной или вернуть его
из функции так же законно, как присвоить той же переменной. Вариант A
принимает привычную запись `s = append(s, x)` за единственно возможную.
Вариант B отвергает строку 2, хотя новой переменной результат присвоить
можно. Вариант D считает, что `append` удлиняет переменную на месте.

## Вопрос 2

Переменные `names` и `more` имеют тип `[]string`. Строка
`names = append(names, more)` не собирается. Какая правка допишет в конец
`names` все элементы `more` по порядку?

Варианты ответа:

- A. `names = append(names, more...)`
- B. `names = append(more, names...)`
- C. `append(names, more...)`
- D. `names = append(names, more[0])`

Прежде чем смотреть ответ, объясните, почему исходная строка не собирается
и что означают три точки после последнего аргумента.

**Правильный ответ: A.**

Без точек `more` — одно значение типа `[]string` там, где `append` ждёт
отдельные строки. Три точки дописывают каждый элемент `more` по порядку.
Вариант B собирается, но ставит элементы `more` впереди элементов `names`.
Вариант C — вызов без использования результата, его компилятор не примет.
Вариант D дописывает только первый элемент.

## Вопрос 4

У `s` длина 3 и ёмкость 4, у `empty` длина 0. Какие вызовы вернут slice на
тот же массив, что у `s`?

1. `append(s, 7)`
2. `append(s, 7, 8)`
3. `append(s, empty...)`

Варианты ответа:

- A. Только 1: без новых значений `append` всегда выделяет новый массив.
- B. 1 и 3: обоим хватает четырёх ячеек массива `s`.
- C. 1 и 2: у `s` есть свободная ячейка, значит, массив тот же.
- D. Все три: у `s` есть свободная ячейка.

Прежде чем смотреть ответ, для каждого вызова сложите длину `s` и число
дописываемых значений и сравните сумму с ёмкостью.

**Правильный ответ: B.**

Массив переиспользуется, когда `len(s) + k <= cap(s)`, где k — число
дописываемых значений. Для вызова 1 сумма равна 3 + 1 = 4, для вызова 3 —
3 + 0 = 3, и обе не больше 4. Вызову 2 нужно 3 + 2 = 5 ячеек, и `append`
выделяет новый массив. Вариант A считает вызов без значений особым случаем,
хотя правило для него то же. Варианты C и D проверяют только, есть ли
свободная ячейка, а не хватит ли её на все значения.

## Вопрос 5

Тот же `s`: длина 3, ёмкость 4. Что язык гарантирует про ёмкость после
`r := append(s, 7, 8)` и после `q := append(s, 7)`?

Варианты ответа:

- A. `cap(r)` равна 4, как у `s`, и `cap(q)` тоже равна 4.
- B. `cap(r)` равна 8, потому что при нехватке ёмкость удваивается; `cap(q)`
  равна 4.
- C. `cap(r)` не меньше 5, а точное число язык не называет; `cap(q)` равна 4.
- D. `cap(r)` равна 5, ровно новой длине; `cap(q)` равна 4.

Прежде чем смотреть ответ, скажите, какой из двух вызовов переиспользует
массив и что спецификация обещает про ёмкость в каждом случае.

**Правильный ответ: C.**

Вызов с одним значением переиспользует массив, и ёмкость остаётся 4. Вызов
с двумя значениями выделяет новый массив, а о нём язык обещает только, что
ёмкость не меньше новой длины 5. Вариант A оставляет старую ёмкость там, где
массив новый. Вариант B приписывает языку удвоение ёмкости, которого
спецификация не обещает. Вариант D тоже называет точное число, хотя язык
обещает только нижнюю границу.

## Вопрос 6

Что напечатает программа?

Варианты ответа:

- A. `nums` — 100, 2, 3, длина 3; `nums[:4]` — 100, 2, 3, 4.
- B. `nums` — 1, 2, 3, длина 3; `nums[:4]` — 1, 2, 3, 0.
- C. `nums` — 100, 2, 3, 4, длина 4; `nums[:4]` — то же самое.
- D. `nums` — 1, 2, 3, длина 3; `nums[:4]` — 1, 2, 3, 4.

Прежде чем смотреть ответ, скажите, какой дескриптор меняет

## Вопрос 7

```

Что напечатает программа и какая правка сделает результат равным 1, 4?

Варианты ответа:

- A. 1 и 4, длина 2; правка не нужна.
- B. 0, 0, 1, 4, длина 4; поможет только `make([]int, 0, n)` вместо
  `make([]int, n)`.
- C. 1, 4, 0, 0, длина 4; поможет только запись `out[i-1] = i*i` вместо
  `append`.
- D. 0, 0, 1, 4, длина 4; поможет любая из правок: `make([]int, 0, n)` или

Прежде чем смотреть ответ, назовите длину `out` сразу после `make` и
позицию, на которую `append` поставит первое значение. Объясните, откуда
берётся длина 2n.

**Правильный ответ: D.**

При n, равном 2, `make([]int, n)` даёт два нуля, а `append` дописывает

запись по индексу, хотя в этой функции она тоже подходит: длина результата
n известна до цикла.

## Вопрос 8

Функция должна вернуть отрицательные показания из `s` в исходном порядке,
и сколько их будет, заранее неизвестно. Тело цикла —
`if s[i] < 0 { out = append(out, s[i]) }`. Какие объявления `out` перед
циклом дадут верный результат?

1. `var out []int`
2. `out := make([]int, 0, len(s))`
3. `out := make([]int, len(s))`

Варианты ответа:

- A. Только 2: `append` не принимает nil-slice, ему нужен массив из `make`.
- B. 1 и 2: оба начинают с длины 0, а ёмкость решает только, где лежат
  значения.
- C. 2 и 3: нужен `make`, а длина `len(s)` в объявлении 3 — запас под
  результат.
- D. Все три: `append` пишет в конец, и начало результата не важно.

Прежде чем смотреть ответ, для каждого объявления назовите длину `out` до
цикла и результат для `s` из двух элементов −5 и 3.

**Правильный ответ: B.**

Объявления 1 и 2 начинают с длины 0, и для −5 и 3 функция вернёт один
элемент −5. У объявления 3 длина 2, поэтому получится 0, 0, −5. Вариант A не
знает, что `append` принимает nil-slice как slice длины 0. Вариант C путает
длину с ёмкостью. Вариант D забывает, что нули из `make` остаются в начале
результата.
