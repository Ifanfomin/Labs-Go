# Литералы срезов и срез от среза

Автобус идёт по маршруту из пяти остановок: Вокзал, Рынок, Парк, Школа, Депо.
Программе, которая работает с этим маршрутом, нужны две вещи:

- записать список остановок прямо в коде, сразу со значениями, а не
  заполнять элементы по одному;
- выделить участок маршрута, например остановки со второй по четвёртую, и
  работать с ним как с отдельным списком, не переписывая остановки заново.

Первую задачу решает литерал slice, вторую — выражение вида `stops[1:4]`,
которое берёт от slice кусок. В названии урока slice назван по-русски —
срезом, а «срез от среза» — это кусок, взятый от slice. Дальше везде
используется слово slice.

Понадобится то, что уже известно:

- литерал массива `[3]int{10, 20, 30}` и запись `[...]int{10, 20, 30}`,
  индексы от 0 до длины без единицы, `len` и то, что присваивание массива
  копирует все его элементы (урок 4.1);
- тип `[]int` и устройство slice (урок 4.2): переменная slice хранит не сами
  элементы, а сведения о них из трёх частей — с какого места массива,
  лежащего в основе, начинается её участок, сколько в нём элементов (длина)
  и ёмкость. В этом уроке нужны первые две части, начало и длина; зачем
  нужна ёмкость, разбирает урок 4.4. Копия slice получает те же
  сведения и видит те же элементы, поэтому запись через копию видна через
  оригинал;
- объявление через `:=` и присваивание (уроки 2.1 и 2.2).

К концу урока вы сможете:

- создать slice с известными элементами литералом и отличить его от
  литерала массива;
- отличить пустой литерал `[]int{}` от литерала с одним нулём `[]int{0}`;
- расставить запятые в литерале, записанном в несколько строк;
- по выражению `s[low:high]` назвать элементы куска, его длину и индекс `s`,
  которому соответствует каждый элемент куска, в том числе у куска, взятого
  от куска;
- починить кусок с переставленными индексами;
- предсказать, какие переменные увидят запись в элемент, и отличить
  независимый литерал от второго имени тех же элементов.

## Литерал slice

Литерал slice записывается как литерал массива без длины в квадратных
скобках: сначала тип `[]int`, затем элементы в фигурных скобках через
запятую. Литерал `[]int{10, 20, 30}` создаёт массив из трёх элементов и
slice, который описывает этот массив целиком. Этот массив и есть массив,
лежащий в основе slice. Длина slice — 3, элементы — 10, 20 и 30 в порядке
записи.

Литерал slice легко спутать с двумя литералами массива из урока 4.1. Все три
отличаются только тем, что стоит в квадратных скобках:

- `[3]int{10, 20, 30}` — массив, длина 3 записана в типе;
- `[...]int{10, 20, 30}` — тоже массив типа `[3]int`: при трёх точках
  компилятор сам считает длину по записанным элементам, здесь их три;
- `[]int{10, 20, 30}` — slice: скобки пустые, длины в типе нет вовсе.

Три точки не превращают массив в slice. `[...]` даёт массив, `[]` — slice.

Программа ниже печатает все три значения и их длины. Прежде чем смотреть
вывод, скажите, чем будут отличаться три строки.

```go

### Example: `01-literal-kinds`

Источник: `examples/01-literal-kinds/`

```go
package main

import "fmt"

func main() {
	s := []int{10, 20, 30}
	a := [3]int{10, 20, 30}
	b := [...]int{10, 20, 30}
	fmt.Println("s:", s, "длина", len(s))
	fmt.Println("a:", a, "длина", len(a))
	fmt.Println("b:", b, "длина", len(b))
}

```
```

Строки отличаются только именем переменной. Элементы и у массивов, и у slice
печатаются в квадратных скобках, длина у всех трёх равна 3. По выводу массив
от slice не отличить. Различает их тип, записанный в литерале, а от типа
зависит, что происходит при копировании.

Программа ниже присваивает массив `b` новой переменной `bCopy`, а slice `s` —
новой переменной `t`. Затем она записывает 9 в нулевой элемент через новую
переменную. Прежде чем смотреть вывод, скажите по правилам уроков 4.1 и 4.2,
изменится ли `b` и изменится ли `s`.

```go

### Example: `02-copy-or-share`

Источник: `examples/02-copy-or-share/`

```go
package main

import "fmt"

func main() {
	b := [...]int{1, 2, 3}
	bCopy := b
	bCopy[0] = 9
	fmt.Println("массив b:", b, "копия:", bCopy)

	s := []int{1, 2, 3}
	t := s
	t[0] = 9
	fmt.Println("slice s:", s, "t:", t)
}

```
```

Присваивание массива скопировало все три элемента, поэтому `b` осталась
прежней, а изменилась только копия. Присваивание slice скопировало только
сведения об элементах. `t` и `s` видят один и тот же массив, и запись через
`t` видна через `s`.

## Пустой литерал и литерал с нулём

Когда значения в фигурных скобках перечислены по порядку, без индекса с
двоеточием перед ними, длина литерала — это число значений. `[]int{}` — пустой
литерал: в скобках ничего нет, длина 0. `[]int{0}` — литерал с одним
элементом, равным нулю, его длина 1. Записи похожи, но ноль в скобках — это
элемент, а не «пусто».

Прежде чем смотреть вывод, назовите длину каждого slice.

```go

### Example: `03-empty-literal`

Источник: `examples/03-empty-literal/`

```go
package main

import "fmt"

func main() {
	empty := []int{}
	zero := []int{0}
	fmt.Println("empty:", empty, "длина", len(empty))
	fmt.Println("zero:", zero, "длина", len(zero))
}

```
```

Пустой slice печатается как пустые квадратные скобки, slice из одного нуля —
как ноль в скобках. Длины у них 0 и 1, и элемент с индексом 0 есть только у
второго.

В разделе «Первый, последний, весь и пустой кусок» встретится и кусок без
элементов: его длина тоже 0. Есть ли у пустого литерала и пустого куска
отличие, которое видно при сравнении, разбирает урок 4.7. В этом уроке у
обоих важна только длина 0.

## Литерал в несколько строк

Длинный список удобнее записать столбиком, по элементу в строке. Правило
одно: после каждого элемента стоит запятая. Это касается и последнего
элемента, если закрывающая скобка `}` стоит на следующей строке.

Причина в том, как Go читает концы строк. Если строка заканчивается, например,
именем, числом, строкой в кавычках или закрывающей скобкой, Go сам ставит в
её конце точку с запятой. Поэтому в конце обычных инструкций точку с запятой
не пишут. Запятая в этот список не входит: строка, которая заканчивается
запятой, продолжается на следующей. Строка с последним элементом без запятой
получит точку с запятой, и литерал оборвётся посередине.

В программе ниже после последней остановки запятой нет. Соберётся ли
программа?

```go
@broken missing-comma
```

Не соберётся: `syntax error: unexpected newline in composite literal; possibly missing comma or }`.
В сообщении composite literal — составной литерал: так компилятор называет
литерал с фигурными скобками. Сообщение говорит, что в таком литерале
неожиданно встретился конец строки, и предлагает два ремонта: запятую или
закрывающую скобку. Для столбика подходит запятая после `"Парк"`. Второй
ремонт — перенести `}` в конец строки с последним элементом.

В литерале, записанном в одну строку, запятая перед `}` не нужна. Если её
всё же поставить, программа соберётся, а `gofmt` эту запятую уберёт.

Внутри фигурных скобок иногда встречается запись с двоеточием, например
`[]int{3: 7}`. Число перед двоеточием — индекс элемента. Такой литерал задаёт
элемент с индексом 3, равный 7, а элементы с индексами от 0 до 2 равны нулю.
Длина литерала — наибольший индекс элемента плюс один: у `[]int{3: 7}` она
равна 4, хотя значение в скобках одно. У литерала без индексов наибольший
индекс на единицу меньше числа значений, поэтому там длина и есть число
значений. Запись с индексами полезно узнавать при чтении кода; в упражнении
этого урока она не понадобится.

## Кусок slice и полуоткрытый интервал

Литерал создаёт slice с новыми элементами. Вторая задача — взять часть уже
существующего slice. Выражение `s[low:high]` берёт от slice `s` кусок: новый
slice из элементов `s` с индекса `low` по индекс `high`. Индекс `low` в кусок
входит, а `high` — нет. Такой промежуток называют полуоткрытым интервалом:
одна граница включена, другая исключена.

Из этого правила следуют три факта, на которые опирается весь урок:

- в куске `high - low` элементов;
- индексы куска снова начинаются с нуля: элемент куска с индексом 0 — это
  элемент `s` с индексом `low`;
- элемент куска с индексом `j` — это элемент `s` с индексом `low + j`, для `j`
  от 0 до `high - low - 1`.

Квадратные скобки после имени выбирают позиции уже существующего slice.
Фигурные скобки литерала, наоборот, перечисляют значения новых элементов.
`[]int{1, 4}` — новый slice из чисел 1 и 4, а `s[1:4]` — кусок `s` из
элементов с индексами 1, 2 и 3.

Для маршрута выражение `stops[1:4]` берёт остановки с индексами 1, 2 и 3. В
таблице под каждой остановкой стоят её индекс в `stops` и индекс в куске
`middle`:

| Индекс в `stops` | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| Остановка | Вокзал | Рынок | Парк | Школа | Депо |
| Индекс в `middle` | — | 0 | 1 | 2 | — |

Прежде чем смотреть вывод, скажите, какие остановки войдут в `middle`, какой
будет его длина и что напечатает `middle[0]`.

```go

### Example: `04-route-part`

Источник: `examples/04-route-part/`

```go
package main

import "fmt"

func main() {
	stops := []string{
		"Вокзал",
		"Рынок",
		"Парк",
		"Школа",
		"Депо",
	}
	middle := stops[1:4]
	fmt.Println("весь маршрут:", stops, "длина", len(stops))
	fmt.Println("участок:", middle, "длина", len(middle))
	fmt.Println("первая остановка участка:", middle[0])
}

```
```

В кусок вошли Рынок, Парк и Школа, длина 3, то есть `4 - 1`. Депо с индексом
4 не вошло: верхняя граница исключена. `middle[0]` — это Рынок: индексы куска
начинаются заново, и нулевой элемент куска совпадает с `stops[1]`.

Литерал `stops` в программе записан столбиком, поэтому после последней
остановки стоит запятая (правило из раздела «Литерал в несколько строк»).

## Первый, последний, весь и пустой кусок

Правило полуоткрытого интервала удобнее всего проверить на краях. В программе
ниже `s := []int{10, 20, 30, 40, 50}`, и `len(s)` равно 5. Прежде чем смотреть
вывод, для каждого из пяти выражений назовите элементы куска и его длину.

```go

### Example: `05-endpoints`

Источник: `examples/05-endpoints/`

```go
package main

import "fmt"

func main() {
	s := []int{10, 20, 30, 40, 50}
	first := s[0:1]
	last := s[4:5]
	whole := s[0:5]
	empty := s[2:2]
	atEnd := s[5:5]
	fmt.Println("s[0:1] ->", first, "длина", len(first))
	fmt.Println("s[4:5] ->", last, "длина", len(last))
	fmt.Println("s[0:5] ->", whole, "длина", len(whole))
	fmt.Println("s[2:2] ->", empty, "длина", len(empty))
	fmt.Println("s[5:5] ->", atEnd, "длина", len(atEnd))
}

```
```

Сверьте ответы с таблицей:

| Выражение | Какие индексы `s` входят | Длина |
|---|---|---|
| `s[0:1]` | 0 — первый элемент | 1 |
| `s[4:5]` | 4 — последний элемент | 1 |
| `s[0:5]` | с 0 по 4 — весь slice | 5 |
| `s[2:2]` | ни одного | 0 |
| `s[5:5]` | ни одного | 0 |

Чтобы взять один элемент с индексом `i`, пишут `s[i:i+1]`: верхняя граница на
единицу больше индекса. Весь slice — это `s[0:len(s)]`. Когда `low` равно
`high`, кусок пуст. Это законный результат, а не ошибка и не «один элемент с
индексом `low`». Пустой кусок можно взять и в самом конце: выражение `s[5:5]`
законно, хотя элемента с индексом 5 у `s` нет.

## Границы индексов в этом уроке

В этом уроке и в упражнении индексы куска подчиняются условию
`0 <= low <= high <= len(s)`. В этих границах кусок всегда можно взять:
`low` не больше `high`, и `high` не выходит за длину.

Это безопасная часть правила, а не всё правило. Для массива верхняя граница
куска действительно равна длине массива. Для slice язык разрешает `high`
больше длины — вплоть до ёмкости slice. Что такое ёмкость и когда такой кусок
полезен, разбирает урок 4.4. Поэтому «`high` не больше длины» — договорённость
этого урока, а не запрет языка для slice.

Условие `low <= high` действует всегда. В программе ниже задумано взять
элементы с индексами 1 и 2, но индексы переставлены. Соберётся ли программа?

```go
@broken reversed-interval
```

Не соберётся: `invalid slice indices: 1 < 3`. Обе границы записаны числами,
поэтому компилятор сравнил их до запуска и сообщил, что верхняя граница, 1,
меньше нижней, 3. Ремонт — поставить меньший индекс первым: `s[1:3]` берёт
элементы с индексами 1 и 2. Если границы хранятся в переменных, компилятор их
не сравнивает. Переставленные границы тогда обнаружатся при выполнении, и
программа остановится с ошибкой.

## Кусок массива

Кусок можно взять и от массива, который хранится в переменной. Для массива
`a` выражение `a[1:3]` даёт slice типа `[]int`, который видит элементы `a` с
индексами 1 и 2. Элементы при этом не копируются: массивом, лежащим в основе
куска, становится сам `a`. Запись через кусок меняет массив, а изменение
массива видно через кусок.

Прежде чем смотреть вывод, скажите, какой элемент `a` изменит запись
`v[0] = 99` и что напечатает вторая строка.

```go

### Example: `06-array-view`

Источник: `examples/06-array-view/`

```go
package main

import "fmt"

func main() {
	a := [5]int{10, 20, 30, 40, 50}
	v := a[1:3]
	fmt.Println("до записи: a =", a, "v =", v)
	v[0] = 99
	fmt.Println("после v[0] = 99: a =", a, "v =", v)
}

```
```

`v[0]` — это `a[1]`, поэтому число 20 в массиве сменилось на 99. Копии не
было: `v` и `a` показывают одни и те же элементы.

Кусок берут у массива, который хранится в переменной. Литерал массива без
переменной для этого не годится. Соберётся ли программа ниже?

```go
@broken array-literal-slice
```

Не соберётся: `cannot slice unaddressable value`, то есть «нельзя взять
кусок от значения без адреса». Точный смысл слова «адрес» разбирает урок 6.6.
Практическое правило пока такое: сначала сохраните массив в переменную,
потом берите кусок от неё. То же относится к массиву, который вернула
функция: у самого результата вызова кусок не взять, у переменной с этим
результатом — можно. На литерал slice это ограничение не распространяется:
`[]int{1, 2, 3}[1:2]` собирается.

## Кусок от куска

Кусок — обычный slice, поэтому от него тоже можно взять кусок. Выражение с
двумя индексами не создаёт новых элементов. Оно создаёт новые сведения о тех
же элементах; для этого урока в них важны другое начало и другая длина.
Сведения исходного slice при этом не меняются: у него, в частности, прежние
начало и длина.

Сдвиги начала при этом складываются. Пусть `s := []int{10, 20, 30, 40, 50}`,
`t := s[1:4]` и `u := t[1:3]`. Элемент `t[j]` — это `s[1+j]`, а элемент
`u[j]` — это `t[1+j]`, то есть `s[2+j]`. Удобно выписать индексы каждого
slice отдельной строкой:

| Индекс в `s` | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| Элемент | 10 | 20 | 30 | 40 | 50 |
| Индекс в `t` | — | 0 | 1 | 2 | — |
| Индекс в `u` | — | — | 0 | 1 | — |

Программа ниже записывает 77 в `u[0]` и печатает все три slice. Прежде чем
смотреть вывод, скажите, какой элемент `s` и какой элемент `t` станут равны
77 и какими останутся длины `t` и `u`.

```go

### Example: `07-nested-view`

Источник: `examples/07-nested-view/`

```go
package main

import "fmt"

func main() {
	s := []int{10, 20, 30, 40, 50}
	t := s[1:4]
	u := t[1:3]
	fmt.Println("до: s =", s, "t =", t, "u =", u)
	u[0] = 77
	fmt.Println("после записи в u[0]:")
	fmt.Println("s =", s)
	fmt.Println("t =", t, "длина", len(t))
	fmt.Println("u =", u, "длина", len(u))
}

```
```

`u[0]` стоит в одном столбце с `t[1]` и `s[2]`: это один и тот же элемент,
поэтому 77 видно через все три slice. Длина `t` осталась 3, а `t[0]`
по-прежнему 20: выражение `t[1:3]` создало `u` и не изменило сведения `t`.

Строка индексов на каждый slice особенно полезна, когда кусок начинается не с
нулевого индекса. Номер элемента в куске и его номер в исходном slice тогда
разные, и путать их — частая ошибка.

## Кусок не копирует элементы

Видит ли новое значение те же элементы или получает свои, зависит от того,
как оно получено:

- Кусок `s[low:high]`, кусок от куска и кусок массива видят элементы
  исходного значения.
- Присваивание slice другой переменной даёт второе имя тем же элементам
  (урок 4.2).
- Каждое выполнение литерала создаёт новый массив, лежащий в основе, с
  новыми элементами. Два литерала с одинаковыми значениями независимы.

Новые сведения о slice — это ещё не новые элементы. Среди средств этого урока
независимые элементы даёт только литерал. Как скопировать элементы
существующего slice, разбирает урок 4.6.

Программа ниже создаёт `x` и `y` двумя одинаковыми литералами, а `b` —
присваиванием `b := x`. Затем она записывает 100 в `y[0]` и 9 в `b[0]`.
Прежде чем смотреть вывод, скажите, что напечатают `x`, `y` и `b`.

```go

### Example: `08-literal-independent`

Источник: `examples/08-literal-independent/`

```go
package main

import "fmt"

func main() {
	x := []int{1, 2, 3}
	y := []int{1, 2, 3}
	b := x
	y[0] = 100
	b[0] = 9
	fmt.Println("x =", x)
	fmt.Println("y =", y)
	fmt.Println("b =", b)
}

```
```

Запись через `b` изменила `x`: у них одни и те же элементы. Запись через `y`
на `x` не повлияла, хотя литералы были одинаковыми: каждый литерал создал
свой массив.

- `Window` получает `s` длиной от 0 до 10 и индексы, для которых

Другие значения не передаются и не проверяются. Проверять или исправлять
индексы `Window` не нужно: их правильность гарантирует вызывающий код.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые элементы с
ожидаемыми:

- `TestPair` — порядок и число элементов для разных пар, в том числе для

  результат второго вызова не должна менять результат первого;
- `TestWindow` — первый, последний, средний и весь кусок, пустые куски в
  начале, в середине и в конце, кусок slice из одного элемента и кусок
  пустого slice;
- `TestWindowShares` — запись в непустой результат `Window` видна через `s`
  ровно по тем индексам, которые выбрал кусок, в том числе когда кусок
  начинается не с нулевого индекса.

Тесты работают только с возвращёнными значениями: сравнивают элементы и
записывают в результат, чтобы проверить, какие элементы он делит с другими

## Pair

`Pair` возвращает новый slice из двух элементов: сначала `a`, затем `b`.
Длина результата всегда 2. Каждый вызов возвращает свои элементы: запись в
результат одного вызова не меняет результат другого.

- `Pair(3, 7)` возвращает slice из 3 и 7;
- `Pair(7, 3)` возвращает slice из 7 и 3: порядок важен;
- `Pair(0, 0)` возвращает slice из двух нулей, его длина 2.

## Window

`Window` возвращает кусок `s` с индекса `low` включительно до индекса `high`
не включая. В результате `high - low` элементов, и элемент результата с
индексом `j` — это элемент `s` с индексом `low + j`.

Результат не копирует элементы: он видит те же элементы, что и `s`. Если
вызывающий код запишет значение в элемент результата, это значение будет
видно через `s` по соответствующему индексу.

Для `s := []int{10, 20, 30, 40, 50}`:

- `Window(s, 1, 4)` возвращает элементы 20, 30 и 40;
- `Window(s, 0, 1)` возвращает один элемент 10, а `Window(s, 4, 5)` —
  один элемент 50;
- `Window(s, 0, 5)` возвращает все пять элементов;
- `Window(s, 2, 2)` и `Window(s, 5, 5)` возвращают кусок длины 0;
- после `w := Window(s, 2, 4)` и записи `w[0] = 77` элемент `s[2]` равен 77.

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые решения задач
упражнения.

## Окно: индексы и общие элементы

<!-- review:window-trace -->

Первый вопрос из раздела упражнения «Что проверяется, а что нет»:
`Window([]int{10, 20, 30, 40, 50}, 1, 4)`. Индекс 1 входит в кусок, индекс 4
— нет, поэтому результат состоит из элементов с индексами 1, 2 и 3: 20, 30 и
40. Длина `4 - 1`, то есть 3. Элемент результата с индексом 2 — это элемент
`s` с индексом `1 + 2`, то есть `s[3]`, число 40.

Второй вопрос: `Window(s, 3, 3)`. Нижняя и верхняя границы совпали, и в
полуоткрытый интервал не попал ни один индекс. Функция возвращает кусок длины
0. Это законный результат, а не ошибка и не один элемент с индексом 3.

Третий вопрос: после `w := Window(s, 2, 4)` элемент `w[1]` — это `s[3]`,
поэтому запись `w[1] = 88` делает `s[3]` равным 88. Если бы `Window` собирала
результат в новом литерале из значений `s[2]` и `s[3]`, литерал создал бы
свой массив. Запись 88 изменила бы только его, а `s` осталась бы прежней.
Такое решение не проходит `TestWindowShares`.

Верная запись — одна инструкция `return s[low:high]`. Кусок получает новые
сведения, среди которых начало с элемента `s[low]` и длина `high - low`, и
видит элементы `s`. Условие `0 <= low <= high <= len(s)` гарантирует
вызывающий код, поэтому проверять индексы не нужно.

## Пара: литерал из двух элементов

<!-- review:pair-literal -->

Четвёртый вопрос: `Pair(0, 0)` возвращает два элемента, оба равны нулю, и
длина результата 2. `[]int{0}` — один элемент, длина 1. `[]int{}` — ни одного
элемента, длина 0. Ноль в фигурных скобках — это элемент, а у литерала,
где значения перечислены по порядку без индексов, число значений в скобках и
есть длина.

Верная запись — `return []int{a, b}`. Литерал выполняется заново при каждом
вызове и каждый раз создаёт новый массив, поэтому второй вызов не трогает
результат первого.

## Один slice на все вызовы

<!-- review:pair-shared-storage -->

Решение хранит пару в переменной уровня пакета: литерал в её объявлении
выполняется один раз. `Pair` записывает в эту переменную `a` и `b` и отдаёт
её. Значения одного вызова верны, но все результаты делят одни и те же два
элемента.

Это решение не проходит `TestPair`: после записи 100 в результат второго вызова
`Pair(1, 2)` результат первого вызова тоже начинается со 100. Верная запись
создаёт литерал внутри функции, и тогда он выполняется при каждом вызове.

## Верхняя граница включена

<!-- review:window-inclusive -->

Решение берёт на один элемент больше, если за `high` ещё есть элемент, —
будто верхняя граница входит в кусок. Длина результата тогда
`high - low + 1`.

Это решение не проходит `TestWindow`: для `Window(s, 0, 1)` тест ожидает
один элемент 10, а получает 10 и 20. Верхняя граница `high` в кусок не
входит, поэтому её передают в выражение без поправки.

## Кусок без сдвига

<!-- review:window-no-offset -->

Решение правильно считает длину `high - low`, но начинает кусок с нулевого
индекса `s`, а не с `low`. Элемент результата с индексом `j` оказывается
элементом `s[j]`, а не `s[low+j]`.

Это решение не проходит `TestWindow`: для `Window(s, 4, 5)` тест ожидает
50, а получает 10. Нижняя граница куска — `low`.

## Копия вместо куска

<!-- review:window-copy -->

Решение переписывает нужные значения циклом в собственный массив и отдаёт
кусок этого массива. Значения и длина верные, поэтому `TestWindow` проходит.
Но результат видит элементы нового массива, а не элементы `s`.

Это решение не проходит `TestWindowShares`: после записи 77 и 88 в результат
`Window(s, 2, 4)` тест ожидает, что `s[2]` и `s[3]` станут 77 и 88, а `s`
остаётся прежней. Верная запись берёт кусок от самого `s`.

  концы строк там ничего не значат.
- B. Не соберётся: в конце строки с `80` Go ставит точку с запятой; нужна
  запятая после `80`.
- C. Не соберётся: запятая после последнего элемента `45` лишняя, её нужно
  убрать перед `}`.
- D. Соберётся: в столбике запятая обязательна только после последнего
  элемента, перед `}`.

Прежде чем смотреть ответ, для каждой строки литерала скажите, чем она
заканчивается и поставит ли Go в её конце точку с запятой.

**Правильный ответ: B.**

Строка с `80` заканчивается числом, поэтому Go ставит в её конце точку с
запятой, и литерал обрывается. Сборка сообщает о неожиданном конце строки в
литерале. Строки с `120` и `45` заканчиваются запятой и продолжаются. Вариант
A неверен: точка с запятой ставится и внутри фигурных скобок. Вариант C
сломает сборку ещё раз: запятая нужна и после `45`, раз `}` стоит на
следующей строке. Вариант D неверен: запятая нужна после каждого элемента.

## Вопрос 4

```go
@quiz _quiz/04-lengths
```

Какие три длины напечатает программа?

Варианты ответа:

- A. 3, 0 и 6.
- B. 4, 1 и 7.
- C. 3, 1 и 6.

Прежде чем смотреть ответ, для каждого выражения назовите индексы `s`,
которые войдут в кусок.

**Правильный ответ: A.**

Длина куска равна `high - low`. В `s[2:5]` входят индексы 2, 3 и 4, это 3
элемента. В `s[3:3]` не входит ни одного индекса, длина 0. `s[0:6]` — весь
slice из 6 элементов. Ответ B получится, если включить верхнюю границу. Ответ
C — если принять `s[3:3]` за один элемент с индексом 3.

## Вопрос 5

```go
@quiz _quiz/05-array-views
```

Что напечатает программа?

Варианты ответа:

- A. `arr` не изменится; `v[0]` равен 1, длина `v` — 4.
- B. 55 окажется в `arr[4]`; `v[0]` равен 1, длина `v` — 4.
- C. 55 окажется в `arr[3]`; `v[0]` равен 1, длина `v` — 4.
- D. 55 окажется в `arr[4]`; `v[0]` равен 3, длина `v` — 2.

Прежде чем смотреть ответ, выпишите индексы строкой для `arr`, для `v` и для
`w` и найдите столбец, в котором стоит `w[1]`.

**Правильный ответ: B.**

`v[j]` — это `arr[1+j]`, а `w[j]` — это `v[2+j]`, то есть `arr[3+j]`. Значит,
`w[1]` — это `arr[4]`. Выражение `v[2:4]` не меняет сведения `v`: у него, в
частности, прежние начало и длина. Ответ A получится, если считать, что
кусок массива копирует элементы. Ответ C — если забыть, что `v` начинается
с индекса 1 массива. Ответ D — если решить, что кусок, взятый от `v`, меняет
сам `v`.

## Вопрос 6

```go
@quiz _quiz/06-literal-alias
```

Какие элементы `x` напечатает программа?

Варианты ответа:

- A. 1, 0 и 0.
- B. 1, 2 и 3.
- C. 1, 0 и 3.
- D. 1, 2 и 0.

Прежде чем смотреть ответ, скажите для `y` и для `z`, видят ли они элементы
`x`, и объясните почему.

**Правильный ответ: C.**

`y := x` даёт второе имя тем же элементам, поэтому запись `y[1] = 0` видна
через `x`. `z` — отдельный литерал со своим массивом, хотя значения у него
те же, поэтому `z[2] = 0` на `x` не влияет. Ответ A получится, если считать
одинаковые литералы общими. Ответ B — если считать, что присваивание slice
копирует элементы, как у массива. Ответ D — если перепутать, какая из двух
переменных делит элементы с `x`.

## Вопрос 7

```go
@quiz _broken/q-reversed
```

Задумано взять две последние остановки, но программа не собирается. Какое
выражение нужно подставить вместо `stops[5:3]`?

Варианты ответа:

- A. `stops[3:5]`
- B. `stops[4:5]`
- C. `stops[3:4]`

Прежде чем смотреть ответ, назовите индексы двух последних остановок и число,
которое должно стоять после двоеточия, чтобы последний из них вошёл в кусок.

**Правильный ответ: A.**

Две последние остановки имеют индексы 3 и 4. Нижняя граница 3 входит в кусок,
верхняя 5 исключена, и `5 - 3` даёт два элемента. Сборка не прошла, потому что
обе границы записаны числами и верхняя меньше нижней. Ответ B даёт один
элемент, Депо. Ответ C тоже даёт один элемент, Школу: индекс 4 не входит.
