# Теория

# Устройство среза

Бот списка покупок получает строку, которую человек набрал руками, например
`"  купить хлеб  молоко "`. В уроке 2.14 такую строку разбивали функцией
`strings.Fields`: результат сохраняли в переменную, считали его части через
`len` и склеивали обратно через `strings.Join`. Боту этого мало. Ему нужно
взять первое слово и понять по нему команду, заменить одно слово и не тронуть
остальные, передать слова в функцию и заранее знать, увидит ли вызывающий код
её изменения.

Результат `strings.Fields` — значение типа slice; по-русски его называют
срезом. В документации Go и в сообщениях компилятора стоит английское слово
slice, поэтому дальше в тексте используется оно. Чтобы уверенно работать со
slice, нужно знать:

- как записывается тип slice и чем он отличается от типа массива;
- как прочитать и заменить один элемент и не остановить программу на пустом
  вводе;
- что хранит само значение slice и чем его длина отличается от ёмкости;
- что копирует присваивание `list := parts` и что получает функция при
  вызове;
- почему два slice нельзя сравнить оператором `==`.

Код примеров можно изменить и запустить снова.

## Тип slice записывают без длины

В документации пакета `strings` функция объявлена так:
`func Fields(s string) []string`. После списка параметров стоит тип
результата — `[]string`. Эта запись читается «slice строк»: пустые квадратные
скобки означают slice, а за ними стоит тип его элементов. Так же `[]int` —
slice целых чисел типа `int`.

Массив из урока 4.1 записывается иначе: у массива из трёх строк тип
`[3]string`, и число 3 — часть типа. В типе slice числа нет. Длина slice, то
есть число его элементов, — свойство конкретного значения, а не типа. Поэтому
результат `Fields` из трёх слов и результат из одного слова имеют один и тот
же тип `[]string`, а `[3]string` и `[2]string` — два разных типа массивов.

Прежде чем смотреть вывод, назовите для каждой из трёх строк тип, который
напечатает `%T` (урок 2.1), и число элементов.

```go

### Example: `01-type`

Источник: `examples/01-type/`

```go
// Тип slice и тип массива: число элементов входит только в тип массива.
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Fields("  купить хлеб  молоко ")
	fmt.Printf("parts: тип %T, частей %d\n", parts, len(parts))

	other := strings.Fields("чай")
	fmt.Printf("other: тип %T, частей %d\n", other, len(other))

	var days [3]string
	fmt.Printf("days: тип %T, элементов %d\n", days, len(days))
}

```
```

Та же запись встречается в сигнатурах. Функция `strings.Join` из урока 2.14
объявлена как `func Join(elems []string, sep string) string`: она принимает
slice строк любой длины и строку-разделитель и возвращает одну строку.
Сигнатура `func Sum(values []int) int` читалась бы так же: один параметр —
slice целых чисел любой длины, один результат — целое число.

## Элемент по индексу

Элементы slice пронумерованы так же, как элементы массива в уроке 4.1: первый
имеет индекс 0, второй — 1, последний — `len(parts)-1`. Выражение `parts[i]`
читает элемент с индексом `i`, и тип результата — тип элементов: у
`[]string` это `string`. Та же запись слева от `=` заменяет элемент:
`parts[1] = "батон"` кладёт на место с индексом 1 другую строку. Строку
`"хлеб"`, которая лежала там раньше, запись не меняет: строки неизменяемы
(урок 2.7). Меняется только то, какая строка стоит в этом элементе.

`fmt.Println` печатает slice так же, как массив: элементы в квадратных
скобках через пробел. В программе ниже slice после замены напечатан ещё и
через `strings.Join` со знаком `+`, чтобы границы слов были видны.

Прежде чем смотреть вывод, запишите четыре строки: первое слово, последнее
слово и slice после замены — через `fmt.Println` и через `strings.Join`.

```go

### Example: `02-index`

Источник: `examples/02-index/`

```go
// Чтение и замена одного элемента по индексу.
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Fields("купить хлеб молоко")
	fmt.Println("первое:", parts[0])
	fmt.Println("последнее:", parts[len(parts)-1])

	parts[1] = "батон"
	fmt.Println("после замены:", parts)
	fmt.Println("через Join:", strings.Join(parts, "+"))
}

```
```

## Пустой набор и проверка длины

Индекс допустим, только если он не меньше нуля и меньше длины:
`0 <= i < len(parts)`. Когда человек отправил пустую строку или одни пробелы,
`strings.Fields` возвращает slice без элементов, и его длина равна 0 (урок
2.14). У такого slice нет ни одного допустимого индекса, даже индекса 0.

Длину результата `Fields` компилятор не знает: она становится известна только
при запуске программы. Поэтому `parts[0]` собирается при любой длине, а если
элемента нет, программа во время выполнения останавливается паникой, как при
делении на ноль в уроке 2.10. Прежде чем смотреть вывод, решите, какие строки
программа успеет напечатать.

```go

### Example: `03-empty-index`

Источник: `examples/03-empty-index/`

```go
// Обращение по индексу к slice без элементов.
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Fields("   ") // человек отправил одни пробелы
	fmt.Println("частей:", len(parts))
	fmt.Println("команда:", parts[0])
	fmt.Println("готово")
}

```
```

Программа напечатала число частей и остановилась на `parts[0]` с сообщением
`panic: runtime error: index out of range [0] with length 0`. Сообщение
называет индекс 0 и длину 0: индекс не меньше длины. Последняя строка `main`
не выполнилась.

Защита — проверить длину раньше, чем читать элемент. Функция `lastWord` в
следующей программе возвращает последнее слово строки, а для строки без слов —
прочерк `"-"`. Проверка `len(parts) == 0` стоит до `parts[len(parts)-1]`,
поэтому на пустом вводе до индекса дело не доходит. Прежде чем смотреть вывод,
пройдите `lastWord` для каждого из трёх входов: какая ветка сработает и что
функция вернёт.

```go

### Example: `04-guard`

Источник: `examples/04-guard/`

```go
// Проверка длины до обращения по индексу.
package main

import (
	"fmt"
	"strings"
)

// lastWord возвращает последнее слово строки line или "-", если слов нет.
func lastWord(line string) string {
	parts := strings.Fields(line)
	if len(parts) == 0 {
		return "-"
	}
	return parts[len(parts)-1]
}

// show печатает вход и то, что вернула для него lastWord.
func show(line string) {
	fmt.Printf("%q -> %q\n", line, lastWord(line))
}

func main() {
	show("купить хлеб молоко")
	show("чай")
	show("   ")
}

```
```

Проверка обязана покрывать самый большой индекс, который читает код. Для
первого и для последнего элемента хватает `len(parts) == 0`: если есть хотя бы
один элемент, индексы 0 и `len(parts)-1` допустимы. Код, который читает
`parts[1]`, требует не меньше двух элементов, и проверка для него —
`len(parts) < 2`.

## Что хранит значение slice

Где лежат сами слова? Не в переменной `parts`. Элементы slice хранятся в
массиве — в таком же ряду ячеек, как массив урока 4.1. Его называют массивом,
лежащим в основе slice. Программа этот массив не объявляла: он появился вместе
с результатом `strings.Fields`, и своего имени у него нет. До его ячеек
программа добирается через slice.

Сама переменная `parts` хранит короткое описание того, к каким ячейкам есть
доступ. Такое описание называют **дескриптором**. В нём три части:

1. ссылка на начальный элемент — ячейку массива, с которой начинается slice;
2. длина — сколько элементов подряд, начиная с начального, доступно через
   этот slice; её возвращает `len`;
3. ёмкость — сколько ячеек массива от начального элемента до конца массива.

Данные — это строки в ячейках массива. Дескриптор данных не содержит: он
говорит, где они начинаются и сколько их можно читать. Как устроена ссылка
внутри, разбирает урок 6.6. Для предсказаний в этом уроке хватает одного
факта: два дескриптора с одной и той же ссылкой ведут к одним и тем же ячейкам.

Схема показывает `parts` из примера `01-type`:

```схема
parts:  [ ссылка | len=3 | cap=? ]
            |
            v
        +--------+------+--------+ ...
        | купить | хлеб | молоко |
        +--------+------+--------+ ...
индекс:     0        1       2
parts:  |<-------- len=3 ------->|
        |<------------ cap=? ------------ ...
```

Верхняя строка — дескриптор, ряд ячеек под ним — массив. Строка `индекс`
нумерует ячейки, а скобки под ней показывают, какие ячейки покрывают длина и
ёмкость. Многоточие справа значит, что массив может продолжаться за последним
элементом slice. Сколько там ячеек, из программ этого урока не видно, поэтому
ёмкость подписана `cap=?`. Как узнать ёмкость функцией `cap` и как получить
slice с запасом ёмкости, объясняет урок 4.4.

## Длина и ёмкость

Длина и ёмкость — части дескриптора, а не свойства строк в ячейках. Ёмкость
никогда не меньше длины: доступные элементы всегда лежат внутри массива.

Индекс проверяется по длине, а не по ёмкости. Ёмкость не добавляет элементов,
к которым можно обратиться: она только говорит, сколько ячеек массива есть от
начала slice до конца массива. Даже если массив продолжается за последним
элементом, обращение `parts[3]` к slice длины 3 остановит программу паникой, и
сообщение, как в примере `03-empty-index`, назовёт индекс и длину. Запас
ёмкости пригодится, когда slice начнут удлинять, — это темы уроков 4.4 и 4.5.

## Присваивание копирует дескриптор

Что делает `list := parts`? Копирует дескриптор: у `list` появляются свои
ссылка, длина и ёмкость с теми же значениями, что у `parts`. Массив при этом не
копируется. Ссылки одинаковые, поэтому `list` и `parts` ведут к одним и тем же
ячейкам. Запись `list[0] = "куплено"` кладёт строку в общую ячейку, и чтение
`parts[0]` находит там её же.

У массива урока 4.1 иначе: присваивание массива копирует все элементы, и
запись в копию исходный массив не меняет. Slice ведёт себя по-другому, потому
что его значение — дескриптор, а не сами элементы.

Прежде чем смотреть вывод, предскажите `parts[0]` и `list[0]` после записи и
оба slice целиком вместе с длиной.

```go

### Example: `05-alias`

Источник: `examples/05-alias/`

```go
// Присваивание копирует дескриптор, а элементы остаются общими.
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Fields("купить хлеб молоко")
	list := parts
	list[0] = "куплено"

	fmt.Println("parts[0]:", parts[0])
	fmt.Println("list[0]:", list[0])
	fmt.Println("parts:", parts, "длина", len(parts))
	fmt.Println("list:", list, "длина", len(list))
}

```
```

Состояние после записи — два отдельных дескриптора и один массив:

```схема
parts:  [ ссылка | len=3 | cap=? ]--+
list:   [ ссылка | len=3 | cap=? ]--+
                                    |
             +----------------------+
             |
             v
        +---------+------+--------+ ...
        | куплено | хлеб | молоко |
        +---------+------+--------+ ...
индекс:      0        1       2
parts:  |<-------- len=3 --------->|   cap=?
list:   |<-------- len=3 --------->|   cap=?
```

Обе ссылки ведут к ячейке 0, поэтому обе скобки начинаются с неё и покрывают
одни и те же три элемента. Скобка под рядом ячеек — тот же дескриптор, только
нарисованный короче: она начинается с ячейки, к которой ведёт ссылка, и
покрывает столько элементов, сколько указано в `len`. Дальше схемы урока
рисуют дескрипторы такими скобками.

## Новое значение для переменной

Присваивание самой переменной работает не так, как запись в элемент.
`list = strings.Fields("чай сок")` кладёт в `list` другой дескриптор —
дескриптор нового результата `Fields`. В программах этого урока каждый
отдельный вызов `Fields` возвращает slice со своими ячейками; вывод программы
ниже это показывает. Дескриптор в `parts` строка с присваиванием не трогает, и
элементы, к которым он ведёт, тоже. После неё `list` ведёт к ячейкам нового
результата, и следующая запись через `list` попадает туда, а не в ячейки
`parts`.

Коротко: `list[0] = ...` меняет элемент в ячейке, общей для обоих
дескрипторов, а `list = ...` меняет только дескриптор в переменной `list`.

Прежде чем смотреть вывод, предскажите для `parts` и для `list` элементы и
длину в конце программы.

```go

### Example: `06-rebind`

Источник: `examples/06-rebind/`

```go
// Присваивание переменной меняет только её дескриптор.
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Fields("купить хлеб молоко")
	list := parts
	list[0] = "куплено"

	list = strings.Fields("чай сок")
	list[0] = "кофе"

	fmt.Println("parts:", parts, "длина", len(parts))
	fmt.Println("list:", list, "длина", len(list))
}

```
```

Схема — пара «до» и «после» строки `list = strings.Fields("чай сок")`; между
ними меняется только дескриптор в `list`:

```схема
до:
        +---------+------+--------+ ...
        | куплено | хлеб | молоко |
        +---------+------+--------+ ...
индекс:      0        1       2
parts:  |<-------- len=3 --------->|   cap=?
list:   |<-------- len=3 --------->|   cap=?

после:
        +---------+------+--------+ ...
        | куплено | хлеб | молоко |
        +---------+------+--------+ ...
индекс:      0        1       2
parts:  |<-------- len=3 --------->|   cap=?

        +-----+-----+ ...
        | чай | сок |
        +-----+-----+ ...
индекс:    0     1
list:   |<- len=2 ->|   cap=?
```

Последняя запись программы, `list[0] = "кофе"`, попала в ячейку 0 нижнего
массива. `parts` её не видит: в конце программы у `parts` те же три элемента и
длина 3.

## Вывод не показывает общие элементы

Можно ли по выводу узнать, общие ли у двух slice элементы? Нет. `fmt.Println`
печатает только элементы, а ссылку из дескриптора не показывает. В следующей
программе `a` и `b` — результаты двух отдельных вызовов `Fields`, а `c`
получил копию дескриптора `a`. Прежде чем смотреть вывод, решите, какие из трёх
slice изменит запись `a[0] = "ок"`.

```go

### Example: `07-same-print`

Источник: `examples/07-same-print/`

```go
// Одинаковый вывод у slice с общими и с отдельными элементами.
package main

import (
	"fmt"
	"strings"
)

func main() {
	a := strings.Fields("да нет")
	b := strings.Fields("да нет")
	c := a
	fmt.Println("до записи:", a, b, c)

	a[0] = "ок"
	fmt.Println("после записи:", a, b, c)
}

```
```

До записи все три slice напечатаны одинаково. Только запись показала, что `c`
делит ячейки с `a`, а `b` — нет. Одинаковый вывод не доказывает ни того, что
элементы общие, ни того, что они отдельные. Ответ даёт происхождение значения:
копия дескриптора ведёт к тем же ячейкам, а отдельный вызов `Fields`, как
показали программы урока, возвращает slice со своими ячейками.

## Slice в параметре и в результате

Сигнатура `func F(s []int) []int` читается так: один параметр `s` — slice
целых чисел — и один результат того же типа. При вызове `F(nums)` аргумент
присваивается параметру, как при `s := nums`, поэтому `s` получает копию
дескриптора. Следствия те же, что у присваивания:

- запись в элемент параметра попадает в общую ячейку, и вызывающий код её
  увидит;
- присваивание параметру другого slice меняет только дескриптор внутри
  функции, а переменная вызывающего кода остаётся прежней.

Формулировка, что slice «передаётся по ссылке», неточна и ведёт к неверному
прогнозу: по ней присваивание параметру заменило бы и переменную вызывающего
кода. На самом деле передаётся копия дескриптора: запись в элемент вызывающий
код видит, а присваивание самому параметру — нет.

Функция `change` в программе ниже делает и то и другое. Прежде чем смотреть
вывод, пройдите три строки её тела: в какой массив попадает каждая запись и
что напечатают строки «внутри» и «снаружи».

```go

### Example: `08-param`

Источник: `examples/08-param/`

```go
// Параметр получает копию дескриптора.
package main

import (
	"fmt"
	"strings"
)

// change пишет в элемент параметра, затем присваивает параметру другой
// slice и пишет уже в него. Вызывающий код передаёт не меньше двух слов.
func change(items []string) {
	items[1] = "батон"
	items = strings.Fields("вода")
	items[0] = "сок"
	fmt.Println("внутри:", items, "длина", len(items))
}

func main() {
	parts := strings.Fields("купить хлеб молоко")
	change(parts)
	fmt.Println("снаружи:", parts, "длина", len(parts))
}

```
```

Первая запись попала в общую ячейку, и `main` видит `батон` на месте `хлеб`.
После `items = strings.Fields("вода")` параметр ведёт к ячейкам нового
результата `Fields`, и запись `сок` в `parts` не попала: строка «снаружи»
показывает прежние три элемента.

Результат типа slice — тоже одно значение-дескриптор. `return a` возвращает
копию дескриптора `a`, и вызывающий код получает доступ к тем же элементам,
что были у аргумента. Функция `longer` ниже возвращает тот из двух slice, в
котором больше элементов. Прежде чем смотреть вывод, решите, какой slice она
вернёт и чьи элементы изменит запись `picked[0] = "батон"`.

```go

### Example: `09-return`

Источник: `examples/09-return/`

```go
// Результат типа slice — копия дескриптора.
package main

import (
	"fmt"
	"strings"
)

// longer возвращает тот из двух slice, в котором больше элементов;
// при равной длине — первый. Элементы longer не меняет.
func longer(a, b []string) []string {
	if len(b) > len(a) {
		return b
	}
	return a
}

func main() {
	tea := strings.Fields("чай")
	food := strings.Fields("хлеб молоко")
	picked := longer(tea, food)
	picked[0] = "батон"

	fmt.Println("tea:", tea)
	fmt.Println("food:", food)
	fmt.Println("picked:", picked)
}

```
```

`longer` вернула дескриптор `food`, поэтому запись через `picked` видна и в
`food`, а `tea` не изменился. Отсюда практическое правило: у функции, которая
принимает slice, стоит сразу написать в комментарии, меняет ли она его
элементы, как это сделано у `longer`. Как проектировать функции целиком,
разбирает урок 5.1.

## Сравнение двух slice

Массивы урока 4.1 можно сравнивать оператором `==`, когда их элементы
сравнимы — например, строки или числа. Со slice так нельзя: типы slice
несравнимы, и операторы `==` и `!=` для двух slice не определены. Это правило о
типе, а не о содержимом: программа не соберётся, даже если элементы
одинаковые, и так же для `[]int`. Прежде чем читать дальше, решите, соберётся
ли программа ниже.

```go
@broken compare
```

Не соберётся. Сборка остановится с сообщением
`invalid operation: first == second (slice can only be compared to nil)`.
Первая часть сообщения говорит главное: `first == second` — недопустимая
операция. Слово `nil` в скобках — имя особого значения slice; что это за
значение и как с ним сравнивают, разбирает урок 4.7.

Когда нужно узнать, одинаковые ли слова в двух slice, сравнивают содержимое:
сначала длины, потом элементы с одинаковыми индексами. Функция `sameWords`
делает это циклом `for i := range len(a)` из урока 3.7. Прежде чем смотреть
вывод, решите для каждой пары, на какой проверке `sameWords` получит ответ.

```go

### Example: `10-same-words`

Источник: `examples/10-same-words/`

```go
// Сравнение двух slice по длине и по элементам.
package main

import (
	"fmt"
	"strings"
)

// sameWords сообщает, совпадают ли a и b по длине и по каждому элементу.
func sameWords(a, b []string) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range len(a) {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func main() {
	first := strings.Fields("чай сок")
	second := strings.Fields("  чай   сок ")
	third := strings.Fields("чай кофе")
	fourth := strings.Fields("чай")

	fmt.Println("first и second:", sameWords(first, second))
	fmt.Println("first и third:", sameWords(first, third))
	fmt.Println("first и fourth:", sameWords(first, fourth))
}

```
```

Готовую функцию для такого сравнения, `slices.Equal`, разбирает урок 4.16.
И `sameWords`, и `slices.Equal` сравнивают элементы, но ни одна из них не
говорит, общие ли у двух slice ячейки. Это можно определить по происхождению
значений; в примере `07-same-print` общую ячейку `a` и `c` также показывает
запись через `a` и последующее чтение через `c`.

## Итог

| Запись | Что происходит | Что видит другой slice с теми же ячейками |
|---|---|---|
| `parts[i]` | читает элемент, если `0 <= i < len(parts)`; иначе паника | — |
| `list := parts` | копирует дескриптор; массив остаётся один | те же элементы |
| `list[0] = "x"` | кладёт строку в общую ячейку | новую строку |
| `list = strings.Fields("y")` | меняет только дескриптор в `list` | прежние элементы |
| вызов `f(parts)` | параметр получает копию дескриптора | запись в элемент — да, присваивание параметру — нет |
| `return s` | возвращает копию дескриптора | те же элементы |
| `a == b` для двух slice | не собирается | — |

## FirstOr

`FirstOr` возвращает первый элемент `s`, а если элементов нет, — `fallback`.

- для `strings.Fields("купить хлеб молоко")` и `fallback`, равного

- для `strings.Fields("чай")` результат — `"чай"`;

## ReplaceFirst

`ReplaceFirst` заменяет первый элемент `s` на `value` и возвращает `s`.
Замена происходит в элементах, которые передал вызывающий код: после вызова он
видит её в своём slice. Возвращённый slice имеет ту же длину и те же элементы,
что и slice вызывающего кода после замены.

- для `parts := strings.Fields("куп хлеб молоко")` вызов
  `ReplaceFirst(parts, "купить")` возвращает slice из трёх элементов
  `купить`, `хлеб`, `молоко`, и `parts` после вызова содержит те же три
  элемента;
- для одного слова `куп` и результат, и `parts` содержат один элемент
  `купить`;
- если в `s` нет элементов, функция ничего не заменяет и возвращает `s`:
  длина результата равна 0.

## Проверка длины в FirstOr

<!-- review:empty-guard -->

Вопрос 1 из постановки: что будет без проверки и почему одной проверки
хватает. Образец ответа ниже.

Для строки из одних пробелов `strings.Fields` возвращает slice без элементов.
Допустимых индексов у него нет, поэтому `s[0]` остановит программу паникой
`index out of range [0] with length 0`. Проверка `len(s) == 0` перед
обращением отсекает ровно этот случай: если элементов нет, функция сразу
возвращает `fallback`. Функция читает только индекс 0, а он допустим уже при
одном элементе, поэтому команде из одного слова другая проверка не нужна.
Решение целиком: `if len(s) == 0 { return fallback }`, затем `return s[0]`.

## Почему вызывающий код видит замену

<!-- review:caller-sees-element -->

Вопросы 2 и 3 из постановки: что получает параметр и почему присваивание
параметру не выполняет контракт. Образец ответа ниже.

При вызове `ReplaceFirst(parts, "купить")` аргумент присваивается параметру,
и `s` получает копию дескриптора `parts`: ту же ссылку на начальный элемент,
ту же длину и ту же ёмкость. Оба дескриптора ведут к одним и тем же ячейкам.
Запись `s[0] = value` кладёт `купить` в общую ячейку 0, и `parts` видит её.
`return s` возвращает ещё одну копию того же дескриптора, поэтому у результата
и у `parts` одни и те же элементы.

Тело `s = strings.Fields(value)` и `return s` поступает иначе. Присваивание
меняет только дескриптор в параметре `s`: теперь он ведёт к ячейкам результата
`strings.Fields(value)`, где лежит одно слово. В ячейки `parts` это тело ничего
не записывает, поэтому вызывающий код замены не увидит, а у возвращённого slice
пропали остальные слова. Решение целиком: `if len(s) == 0 { return s }`, затем
`s[0] = value` и `return s`.

## Паника на пустой команде

<!-- review:firstor-no-guard -->

Решение `return s[0]` без проверки длины верно, пока в строке есть хотя бы

обращение по индексу 0 вызывает панику.

Ловит это `TestFirstOr`: сообщение называет пустой вход и текст паники.
Исправление — проверка `len(s) == 0` до обращения по индексу.

## Команда из одного слова

Ловит это `TestFirstOr` на входе из одного слова `чай`: функция вернула

## Отдельный slice с теми же словами

<!-- review:replacefirst-fresh -->

Решение, которое склеивает слова через `strings.Join`, снова разбивает их
через `strings.Fields` и меняет первый элемент уже этого результата,
возвращает верный набор слов. Но запись попала в ячейки результата
`strings.Fields`, а не в ячейки вызывающего кода. Что это разные ячейки,
показал тест: на его входах, как и в программах урока, отдельный вызов
`Fields` вернул slice со своими ячейками.

Ловит это `TestReplaceFirst`: результат совпадает с ожидаемым, а проверка slice
вызывающего кода сообщает прежнее слово. Контракт требует замены именно в
элементах вызывающего кода. Когда исходные элементы, наоборот, нужно сберечь,
делают независимую копию; как её сделать правильно, разбирает урок 4.6.

## Лишнее слово на пустом входе

<!-- review:replacefirst-empty-adds -->

Решение, которое для slice без элементов возвращает `strings.Fields(value)`,
добавляет слово там, где заменять нечего. Контракт для пустого входа —
вернуть `s` без изменений, с длиной 0.

Ловит это `TestReplaceFirst` на пустой строке и на строке из пробелов:
возвращённый slice имеет длину 1 вместо 0.

## Что говорят и чего не говорят тесты

<!-- review:tests-observe -->

Скрытые тесты вызвали каждую функцию на пяти входах и сравнили значения: для
`FirstOr` — строку, для `ReplaceFirst` — длину и элементы результата и slice
вызывающего кода после вызова. На этих входах результат принят, и это всё, что
тесты установили. Текст решения тесты не читают, поэтому объяснение, почему
проверка длины защищает индекс и почему вызывающий код видит замену, проверяете
вы сами — ответами на вопросы постановки и разделами выше.

## Вопрос 2

Схема показывает `parts` из примера `01-type`, но две части дескриптора
закрыты номерами:

```схема
parts:  [ (1) | len=3 | (2) ]

        +--------+------+--------+ ...
        | купить | хлеб | молоко |
        +--------+------+--------+ ...
индекс:     0        1       2
```

Что стоит на местах (1) и (2)?

Варианты ответа:

- A. (1) — копия трёх строк, (2) — сколько ячеек в массиве после `молоко`.
- B. (1) — ссылка на ячейку 2, (2) — сколько ячеек от ячейки 2 до конца
  массива.
- C. (1) — ссылка на ячейку 0, (2) — сколько ячеек от ячейки 0 до конца
  массива.
- D. (1) — ссылка на ячейку 0, (2) — сколько ячеек в массиве после `молоко`.

Прежде чем смотреть ответ, подпишите обе части сами и скажите, где лежат сами
строки, с какой ячейки начинается slice и откуда отсчитывается ёмкость.

**Правильный ответ: C.**

Дескриптор хранит ссылку на начальный элемент — здесь ячейку 0 со словом

конца массива. Вариант A кладёт в дескриптор сами строки, а они лежат в
массиве. Вариант B начинает slice с последнего элемента. Вариант D считает
ёмкость только после последнего элемента, а не от начала slice.

## Вопрос 3

У slice `s` начальный элемент — ячейка 0 массива из четырёх ячеек, длина `s`
равна 2, ёмкость — 4. Такой slice получают приёмами урока 4.4; здесь важно
только, что хранит его дескриптор. Что сделает инструкция `s[2] = "x"`?

Варианты ответа:

- A. Запишет `"x"` в ячейку 2: ёмкость 4 допускает индексы до 3.
- B. Остановит программу паникой при запуске: индекс 2 не меньше длины 2.
- C. Не соберётся: компилятор видит, что индекс не меньше длины.
- D. Удлинит `s` до трёх элементов и запишет `"x"` в ячейку 2.

Прежде чем смотреть ответ, скажите, какая часть дескриптора решает, допустим ли
индекс, и что тогда означает ёмкость.

**Правильный ответ: B.**

Индекс допустим, только если он меньше длины, а ёмкость лишь говорит, сколько
ячеек массива есть от начала slice. Вариант A принимает ёмкость за границу
индексов. Вариант C неверен, потому что длину slice компилятор не знает: она
становится известна при запуске. Вариант D приписывает записи по индексу
удлинение, а запись по индексу длину не меняет.

## Вопрос 4

```go
@quiz _quiz/02-second-word
```

Что произойдёт при запуске программы?

Варианты ответа:

- A. Будут напечатаны `сок`, прочерк и ещё один прочерк.
- B. Будут напечатаны `сок`, прочерк и `чай`.
- C. Будет напечатано только `сок`, затем паника на строке из одних пробелов.
- D. Будут напечатаны `сок` и прочерк, затем паника на третьем вызове.

Прежде чем смотреть ответ, для каждого вызова `second` назовите длину `parts`
и скажите, какой самый большой индекс читает функция.

**Правильный ответ: D.**

У `"чай сок"` два элемента, и `parts[1]` — это `сок`. У строки из пробелов
элементов нет, проверка `len(parts) == 0` срабатывает и возвращает прочерк. У
`"чай"` один элемент: проверка пропускает его, а индекс 1 уже не меньше длины 1,
и программа останавливается паникой. Вариант A считает, что проверка защищает и
третий вызов, вариант B — что `parts[1]` вернёт единственное слово. Вариант C
упускает, что на строке из пробелов проверка срабатывает раньше обращения по
индексу.

## Вопрос 5

Функция должна вернуть второе слово результата `strings.Fields`, а если
второго слова нет, — прочерк `"-"`. Какая проверка перед `return parts[1]` не
даст панике случиться ни на каком входе и не отбросит строку из двух слов?

Варианты ответа:

- A. `if len(parts) == 0 { return "-" }`
- B. `if len(parts) < 2 { return "-" }`
- C. `if len(parts) <= 2 { return "-" }`
- D. `if len(parts[1]) == 0 { return "-" }`

Прежде чем смотреть ответ, назовите самый большой индекс, который читает
функция, и наименьшую длину, при которой он допустим.

**Правильный ответ: B.**

`parts[1]` допустим, когда элементов не меньше двух, поэтому прочерк нужен
ровно при длине 0 и 1. Вариант A пропускает строку из одного слова, и на ней
случится паника. Вариант C отбрасывает и строку из двух слов, у которой второе
слово есть. Вариант D сам обращается к `parts[1]`, поэтому на коротком входе

## Вопрос 6

```

Что напечатает программа?

Варианты ответа:

- A. `left` — кофе и вода; `right` — хлеб и сыр.
- B. `left` — кофе и сок; `right` — хлеб и вода.
- C. И `left`, и `right` — кофе и вода.
- D. `left` — чай и сок; `right` — хлеб и сыр.

Прежде чем смотреть ответ, после каждой строки тела `touch` скажите, к чьим

**Правильный ответ: A.**

`a` и `b` получили копии дескрипторов `left` и `right`. Запись `a[0]` попала в

## Вопрос 9

Функция объявлена так: `func Scale(values []int, k int) []int`. Программа
вызывает `out := Scale(nums, 2)`, где `nums` — slice целых чисел и
`len(nums) > 0`. Что верно?

Варианты ответа:

- A. Параметры — slice целых и целое, результат — slice целых; `values`
  получает копию дескриптора `nums`.
- B. Параметры — slice целых и целое, результат — slice целых; `values`
  получает копию всех элементов `nums`.
- C. Параметры — массив целых любой длины и целое; результат — массив.
- D. Параметры — slice целых и целое; `values` — та же переменная, что `nums`,
  и `values = ...` заменит `nums`.

Прежде чем смотреть ответ, прочитайте сигнатуру вслух. Скажите отдельно, что
увидит вызывающий код через `nums`, если `Scale` запишет новое число в
`values[0]` и если присвоит самому параметру `values` другой slice.

**Правильный ответ: A.**

`[]int` — slice целых чисел, и вызов присваивает `nums` параметру `values`, то
есть копирует дескриптор. Так как `len(nums) > 0`, индекс 0 допустим: запись в

нет. Вариант B путает копию дескриптора с копией элементов. Вариант C читает
`[]int` как тип массива, хотя у массива в типе стоит длина. Вариант D
превращает параметр в саму переменную вызывающего кода.
