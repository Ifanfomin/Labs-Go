# map: создание и нулевое значение

Кофейня ведёт учёт остатков: чая осталось 3 упаковки, кофе — 5, воды — 7
бутылок. Три числа можно сложить в slice `[]int{3, 5, 7}`, но тогда про каждую
позицию нужно помнить товар: индекс 0 — чай, 1 — кофе, 2 — вода. Этот договор
живёт только в голове программиста. Если порядок товаров в списке поменяется,
код, который читает кофе как `stock[1]`, начнёт получать чужое число.

map хранит название товара рядом с числом. Значение в ней находят не по номеру
позиции, а по названию: вопрос «сколько осталось кофе?» — это обращение по
ключу "кофе". В этом уроке вы узнаете, как записать тип map, как её создать и
чем map, которую только объявили, отличается от созданной.

Понадобится уже пройденное: `var` и нулевые значения (урок 2.1), короткое
объявление `:=` (урок 2.2), `==` для чисел и строк (урок 2.6), побайтовое
сравнение строк (урок 2.14), неточность `==` для чисел с плавающей точкой
(урок 2.5), паника во время работы программы (урок 2.10), массив, который
копируется при присваивании и передаче в функцию (урок 4.1), slice как
дескриптор, копия которого ведёт к тем же элементам (урок 4.2), `make` для
slice (урок 4.4) и слово `nil` как нулевое значение slice (уроки 4.5 и 4.7).

К концу урока вы сможете:

- записать тип map и создать map литералом, вызовом `make` и пустым
  литералом;
- для map из `var`, `make` и литерала назвать длину, результат сравнения с

## Записи: ключ и значение

Тип `map[string]int` читается так: map с ключами типа `string` и значениями
типа `int`. map состоит из записей. Каждая запись — пара «ключ → значение»,
например ключ "кофе" и значение 5. Ключи в одной map не повторяются: для
каждого ключа в ней не больше одной записи. Все ключи имеют один тип, и все
значения — тоже один тип.

Общая форма типа — `map[K]V`: в квадратных скобках тип ключей `K`, после них
тип значений `V`. Типы ключей и значений могут различаться, как в
`map[string]int`, а могут совпадать: `map[string]string` сопоставляет одной
строке другую.

Главное отличие от slice — способ найти значение. Элемент slice находят по
позиции: `s[1]` — второй элемент, а позиции идут подряд от 0. Запись map
находят по ключу: остаток кофе — это значение с ключом "кофе". Номеров
позиций у записей map нет.

Литерал map перечисляет пары в фигурных скобках после типа:
`map[string]int{"чай": 3, "кофе": 5}`. В каждой паре сначала ключ, затем
двоеточие, затем значение; пары разделяются запятыми. Литерал создаёт map и
записывает в неё каждую пару как отдельную запись. Запись в уже созданную map
подробно разбирает урок 4.12. В этом уроке запись по ключу встречается только
там, где два имени обозначают одну map: в разделе «Два имени — одна map», в
вопросе 4 квиза и во втором вопросе раздела упражнения «Вопросы до написания
кода». Каждый раз это новый ключ, который записывают в уже созданную map.

Программа ниже создаёт остатки кофейни литералом, печатает map и её длину.
Встроенная функция `len` для map возвращает число записей. Прежде чем смотреть
вывод, назовите число, которое напечатает `len`. Затем сравните порядок
записей в напечатанной строке с порядком пар в литерале.

```go

### Example: `01-stock-literal`

Источник: `examples/01-stock-literal/`

```go
package main

import "fmt"

func main() {
	stock := map[string]int{
		"чай":  3,
		"кофе": 5,
		"вода": 7,
	}
	fmt.Println("склад:", stock)
	fmt.Println("записей:", len(stock))
}

```
```

`len` насчитала три записи — по одной на каждую пару литерала. `fmt.Println`
печатает map так: сначала `map[`, затем записи в виде `ключ:значение` через
пробел, в конце `]`. Кавычек вокруг ключей в напечатанной строке нет, как не
было типа и запятых в выводе массива в уроке 4.1: это вид вывода, а не литерал.

Записи в выводе стоят не в порядке литерала: вода в литерале последняя, а
напечатана первой. Откуда берётся этот порядок, объясняет раздел «Как
печатается map».

## Запятые и повторы в литерале

Литерал с несколькими парами удобно писать по одной паре на строку, как в
первом примере. Тогда запятая нужна после каждой пары, включая последнюю:
закрывающая скобка `}` стоит на следующей строке. Если весь литерал записан в
одну строку, запятая после последней пары не обязательна: записи
`{"чай": 3, "кофе": 5}` и `{"чай": 3, "кофе": 5,}` одинаково верны.

Причина — в том, как Go обходится без точки с запятой в конце строк. Если
строка кончается числом, строкой в кавычках, именем или закрывающей скобкой,
компилятор сам вставляет после этого последнего элемента невидимую точку с
запятой и считает, что здесь кончилась инструкция. Запятая в конце строки не
входит в этот список: после неё компилятор ждёт продолжения литерала.

Соберётся ли программа ниже, где после последней пары запятой нет?

```go
@broken missing-comma
```

Не соберётся. Компилятор сообщает
`syntax error: unexpected newline in composite literal; possibly missing comma or }`:
посреди составного литерала (composite literal — так называются литералы
массивов, slice и map) встретился конец строки. Сообщение подсказывает, что,
возможно, пропущена запятая или `}`. Исправление — запятая после `"кофе": 5`.

Второе правило литерала: ключи в нём не повторяются. Соберётся ли литерал, в
котором ключ "чай" записан дважды?

```go
@broken duplicate-key
```

Не соберётся: `duplicate key "чай" in map literal` — в литерале map повторён
ключ "чай". У каждого ключа может быть только одна запись, а компилятор не
выбирает за вас, какое из двух значений оставить. Исправляют повтор по смыслу
данных. Если второй "чай" — ошибка в названии другого товара, пишут верное
название. Если одна и та же пара случайно попала в литерал дважды, лишнюю
удаляют.

Компилятор находит повтор, когда ключи записаны константами, например строками
в кавычках или числами. Во всех литералах этого урока ключи именно такие.

## Нулевое значение: nil-map

Литерал сразу создаёт map. А что лежит в переменной, которую только объявили:
`var stock map[string]int`? Как и у slice (уроки 4.5 и 4.7), нулевое значение
типа map записывается словом `nil`. Такую map называют nil-map. В ней нет ни
одной записи, поэтому `len(stock)` даёт 0, а сравнение `stock == nil`
истинно.

Значение по ключу читает выражение `stock["чай"]`: имя map, а за ним ключ в
квадратных скобках. Если запись с таким ключом есть, выражение даёт её
значение. В nil-map записей нет, но чтение любого ключа из неё законно: оно
даёт нулевое значение типа значений. Для `map[string]int` это 0, для
`map[string]string` — пустая строка. Чтение ключа, которого нет в обычной
map, и способ отличить отсутствующий ключ от записи со значением 0 разбирает
урок 4.12.

Записать в nil-map нельзя: запись вызывает панику и останавливает программу,
как деление целого числа на переменную с нулём в уроке 2.10. Эту панику и её
исправление показывает урок 4.12. Здесь достаточно правила: прежде чем
записывать в map, её нужно создать — литералом или вызовом `make`, о котором
следующий раздел.

Программа ниже объявляет nil-map и ничего в неё не записывает. Прежде чем
смотреть вывод, назовите четыре значения: как напечатается `stock`, её длину,
результат `stock == nil` и значение `stock["чай"]`.

```go

### Example: `02-nil-map`

Источник: `examples/02-nil-map/`

```go
package main

import "fmt"

func main() {
	var stock map[string]int // нулевое значение типа map
	fmt.Println("склад:", stock)
	fmt.Println("записей:", len(stock))
	fmt.Println("равен nil:", stock == nil)
	fmt.Println("чай:", stock["чай"])
}

```
```

nil-map напечаталась как `map[]` — без единой записи между скобками. Длина 0
и истинное сравнение с `nil` показывают, что в переменной нулевое значение.
Чтение ключа "чай" не остановило программу и дало 0: записи "чай" нет, и
выражение вернуло нулевое значение `int`.

## Создание: make и пустой литерал

Пустую map, в которую можно записывать, создаёт встроенная функция `make` —
та же, что создавала slice в уроке 4.4. Там вызов `make([]int, 3)` получал
тип slice и длину. Для map `make` получает тип map, а длину не получает:
`make(map[string]int)` создаёт пустую map. Она не равна `nil`, записей в ней
0, и в неё можно записывать.

Литерал без пар, `map[string]int{}`, создаёт такую же пустую map, которая не
равна `nil`. Разницы в поведении между ним и `make` нет.

У `make` для map есть необязательный второй аргумент:
`make(map[string]int, 8)`. Это подсказка размера — примерно сколько записей
ожидается. Длину она не задаёт: в такой map тоже 0 записей, и записей в ней
может стать больше 8. Здесь легко ошибиться по аналогии со slice:
`make([]int, 8)` даёт slice из восьми нулей, а `make(map[string]int, 8)` —
пустую map. Как реализация Go использует подсказку, язык не уточняет; на
результат программы она не влияет.

Программа ниже создаёт четыре map: `a` объявлена через `var`, `b` создана
`make`, `c` — пустым литералом, `d` — вызовом `make` с подсказкой. Для каждой
программа печатает саму map, её длину и результат сравнения с `nil`. Прежде
чем смотреть вывод, заполните для `a`, `b`, `c` и `d` три столбца: как
напечатается, какая длина, равна ли `nil`.

```go

### Example: `03-create`

Источник: `examples/03-create/`

```go
package main

import "fmt"

func main() {
	var a map[string]int         // объявлена, но не создана
	b := make(map[string]int)    // создана make
	c := map[string]int{}        // создана пустым литералом
	d := make(map[string]int, 8) // make с подсказкой размера

	fmt.Println("a:", a, "len", len(a), "nil", a == nil)
	fmt.Println("b:", b, "len", len(b), "nil", b == nil)
	fmt.Println("c:", c, "len", len(c), "nil", c == nil)
	fmt.Println("d:", d, "len", len(d), "nil", d == nil)
}

```
```

Все четыре map напечатаны одинаково и имеют длину 0. Различает их только
сравнение с `nil`: оно истинно у одной `a`. То же вы видели у slice в уроке
4.7: пустые скобки в выводе не говорят, nil перед вами или нет. Подсказка 8 у
`d` длину не изменила.

Для записи это различие главное: в nil-map записать нельзя, а в пустую map,
созданную любым из двух способов этого раздела, можно:

| Объявление | `len` | `== nil` | чтение `m["чай"]` | запись |
|---|---|---|---|---|
| `var m map[string]int` | 0 | истинно | 0 | паника |
| `m := make(map[string]int)` | 0 | ложно | 0 | можно |
| `m := map[string]int{}` | 0 | ложно | 0 | можно |

## len считает записи

`len(m)` возвращает число записей map. Для nil-map и для пустой map результат
одинаковый — 0, поэтому по длине их не различить. Ёмкость, как у slice, у
map не спрашивают: встроенная `cap`, которая работала со slice в уроке 4.4, с
map не работает. Соберётся ли программа ниже?

```go
@broken map-cap
```

Не соберётся:
`invalid argument: stock (variable of type map[string]int) for built-in cap`
— аргумент типа `map[string]int` недопустим для встроенной функции `cap`. Для
map спрашивают только `len`.

## Два имени — одна map

В этом разделе программы записывают в map по ключу. Инструкция
`n["чай"] = 5` записывает в map `n` запись с ключом "чай" и значением 5. Слева
от `=` стоит то же выражение с ключом в квадратных скобках, что и при чтении.
Здесь записываются только ключи, которых в map ещё нет, и только в созданные
map. Что делает запись, если такой ключ уже есть, разбирает урок 4.12.

Вспомните урок 4.1: присваивание массива `b := a` копирует все элементы, и
после него два массива независимы. С map так не происходит. Присваивание
`n := m` не создаёт вторую map с копиями записей: после него оба имени
обозначают одну и ту же map. Запись через `n` меняет эту общую map, и `m` её
видит. Так же вели себя элементы slice в уроке 4.2: копия дескриптора ведёт к
тем же элементам.

Другое дело — присвоить имени новую map: `n = make(map[string]int)`. Эта
инструкция не трогает записи общей map. Она связывает имя `n` с новой пустой
map, а `m` по-прежнему обозначает прежнюю map со всеми её записями. После
этого запись через `n` попадает уже в новую map.

Программа ниже сначала повторяет опыт урока 4.1 с массивом, затем делает то же
с map. Прежде чем смотреть вывод, заполните таблицу: какие записи есть в `m` и
в `n` после `n["чай"] = 5`, после `n = make(map[string]int)` и после
`n["чай"] = 100`. Назовите и значение чтения `m["чай"]` сразу после первой
записи, и длины `m` и `n` в конце.

```go

### Example: `04-two-names`

Источник: `examples/04-two-names/`

```go
package main

import "fmt"

func main() {
	a := [2]int{1, 2}
	b := a // копия массива
	b[0] = 99
	fmt.Println("массивы:", a, b)

	m := map[string]int{"кофе": 2}
	n := m // второе имя той же map
	n["чай"] = 5
	fmt.Println("после записи через n:", m, n)
	fmt.Println("чай через m:", m["чай"])

	n = make(map[string]int) // n обозначает новую map
	n["чай"] = 100
	fmt.Println("после n = make:", m, n)
	fmt.Println("длины m и n:", len(m), len(n))
}

```
```

Таблица показывает обе переменные после каждой инструкции:

| После инструкции | `m` | `n` |
|---|---|---|
| `n := m` | кофе 2 | та же map: кофе 2 |
| `n["чай"] = 5` | кофе 2, чай 5 | та же map: кофе 2, чай 5 |
| `n = make(map[string]int)` | кофе 2, чай 5 | новая map без записей |
| `n["чай"] = 100` | кофе 2, чай 5 | чай 100 |

Массив `b` получил копию, и запись `b[0] = 99` не изменила `a`. Запись
`n["чай"] = 5` видна через `m`, и чтение `m["чай"]` даёт 5: имён два, а map
одна. После `n = make(map[string]int)` имена обозначают разные map, поэтому
запись 100 попала только в новую map, а у `m` осталось значение 5 и две
записи.

Передача аргумента в функцию работает как присваивание (урок 4.1). Поэтому
параметр типа map обозначает ту же map, что и аргумент вызывающего кода, и
запись через параметр видна вызывающему коду. Функция `addWater` ниже
записывает в свой параметр `p` запись с ключом "вода". Прежде чем смотреть
вывод, скажите, сколько записей будет в `m` после вызова и какие.

```go

### Example: `05-param`

Источник: `examples/05-param/`

```go
package main

import "fmt"

// addWater записывает в map p запись с ключом "вода" и значением 9.
func addWater(p map[string]int) {
	p["вода"] = 9
}

func main() {
	m := map[string]int{"кофе": 2}
	addWater(m)
	fmt.Println("m после вызова:", m)
	fmt.Println("записей в m:", len(m))
}

```
```

В `m` две записи: вызов добавил воду в ту же map, которую создал `main`.
Сравните с функцией `warmUp` из урока 4.1: она меняла свою копию массива, и
массив вызывающего кода оставался прежним.

Функция может и вернуть map результатом. Тип map пишут в сигнатуре так же, как
`[3]int` в уроке 4.1: `func NewStock(tea, coffee, water int) map[string]int`
возвращает map с ключами `string` и значениями `int`.

## Как печатается map

Порядок записей в выводе первого примера задаёт `fmt`: перед печатью он
сортирует записи map по ключам и печатает их в этом порядке. Строковые ключи
сравниваются побайтово, как в уроке 2.14; числовые — по величине; у ключей
`bool` сначала идёт `false`, потом `true`. В словах «вода», «кофе» и «чай»
побайтовый порядок совпадает с алфавитным, поэтому вода напечатана первой.

Сортирует `fmt`, а не сама map. Спецификация языка называет map
неупорядоченной группой элементов: map не запоминает ни порядок пар в
литерале, ни порядок, в котором записи появлялись. Поэтому напечатанная строка
ничего не говорит о том, в каком порядке записи создавались. Не говорит она и
о порядке, в котором программа обходит записи map: этот порядок язык не
задаёт, и его разбирает урок 4.14. Печать — удобный способ посмотреть
содержимое map, но не свидетельство о порядке.

Программа ниже печатает map, чьи строковые ключи записаны в литерале не по
алфавиту, и map с ключами-числами. Прежде чем смотреть вывод, запишите обе
строки по правилу сортировки. Обратите внимание на ключ 10: как число он
больше 2.

```go

### Example: `06-print-order`

Источник: `examples/06-print-order/`

```go
package main

import "fmt"

func main() {
	letters := map[string]int{"b": 2, "a": 1}
	numbers := map[int]string{10: "x", 2: "y", -1: "z"}
	fmt.Println("буквы:", letters)
	fmt.Println("числа:", numbers)
}

```
```

Строковые ключи встали в порядке байтов: a раньше b. Числовые — по величине:
−1, 2, 10. Если бы числа сравнивались как строки, "10" оказалось бы раньше
"2", но `fmt` сравнивает числовые ключи как числа.

## Сравнение map

Две map нельзя сравнить через `==` — даже когда это одна и та же map под
двумя именами. Программа ниже пытается сравнить `a` с `b`, которой присвоена
та же map. Соберётся ли она?

```go
@broken compare-maps
```

Не соберётся:
`invalid operation: a == b (map can only be compared to nil)` — map можно
сравнивать только с `nil`. Спецификация не определяет `==` для типов map, как
и для slice (урок 4.2). Отдельное правило разрешает одно сравнение —
с `nil`: `m == nil` и `m != nil` собираются для map любого типа.

Как тогда проверить, что в двух map одинаковые записи? Сравнивают длину и
значение по каждому ключу, который должен быть в map: `len(got) == 3`,
`got["чай"] == 3`, `got["кофе"] == 5` и так далее. Так устроены и скрытые
тесты упражнения этого урока. У такой проверки есть граница: чтение
отсутствующего ключа тоже даёт 0 (раздел «Нулевое значение: nil-map»), поэтому
ожидаемое значение 0 одним чтением не подтверждается. Как проверить само
наличие ключа, показывает урок 4.12.

## Какие типы годятся для ключей

Чтобы найти запись, map сравнивает запрошенный ключ с ключами, которые в ней
уже есть. Поэтому оператор `==` должен работать для любых двух значений типа
ключа. Типы с таким `==` называют сравнимыми (comparable). Полные правила
сравнимости разбирают модули 6, 8 и 10; для этого модуля достаточно двух
списков:

- подходят числовые типы, `string`, `bool` и массивы из них: массивы одного
  типа сравниваются через `==` поэлементно (урок 4.1);
- не подходят slice и map: `==` между двумя slice не собирается (урок 4.2),
  между двумя map — тоже (раздел «Сравнение map»). Сравнение с `nil` здесь
  не помогает: оно отвечает только на вопрос, равно ли значение нулевому, и
  два ключа не различает.

Соберётся ли объявление map, у которой ключ — slice?

```go
@broken slice-key
```

Не соберётся: `invalid map key type []int` — недопустимый тип ключа `[]int`.
Если по набору чисел всё же нужно находить значение, а длина набора
постоянна, ключом может стать массив: `[2]int` сравнивается через `==`.

Программа ниже хранит названия клеток игрового поля по координатам `[2]int`
и ответы по ключам `bool`. Прежде чем смотреть вывод, назовите число клеток,
название клетки с координатами 2 и 3 и строку, которую напечатает map
`answers`.

```go

### Example: `07-key-types`

Источник: `examples/07-key-types/`

```go
package main

import "fmt"

func main() {
	grid := map[[2]int]string{
		[2]int{0, 0}: "старт",
		[2]int{2, 3}: "финиш",
	}
	fmt.Println("клеток:", len(grid))
	fmt.Println("клетка 2, 3:", grid[[2]int{2, 3}])

	answers := map[bool]string{true: "да", false: "нет"}
	fmt.Println("ответы:", answers)
}

```
```

Массив `[2]int{2, 3}`, записанный заново при чтении, равен ключу из литерала:
массивы сравниваются поэлементно. В map `answers` ключ `false` напечатан
первым по правилу сортировки `fmt`, хотя в литерале стоит вторым.

Числа с плавающей точкой тоже сравнимы, и ключ `float64` язык разрешает. Но
урок 2.5 предупреждал: результат вычисления с плавающей точкой может чуть
отличаться от числа, записанного в коде, а `==` видит и такое отличие. Тогда
ключ, вычисленный иначе, может не найти запись. Программа ниже печатает, равна ли
сумма `x+y` числу 0.3, а затем проверяет, находится ли запись по ключу 0.3 и
по ключу `x+y`. Прежде чем смотреть вывод, объясните, от чего зависит, найдётся
ли запись по ключу `x+y`.

```go

### Example: `08-float-key`

Источник: `examples/08-float-key/`

```go
package main

import "fmt"

func main() {
	parts := map[float64]string{0.3: "треть"}
	x, y := 0.1, 0.2
	fmt.Println("x+y == 0.3:", x+y == 0.3)
	fmt.Println("найдено по ключу 0.3:", parts[0.3] == "треть")
	fmt.Println("найдено по ключу x+y:", parts[x+y] == "треть")
}

```
```

Сумма `x+y` оказалась не равна 0.3, поэтому по этому ключу запись не
нашлась, хотя по ключу 0.3 она есть. Язык такой ключ не запрещает, но
надёжнее выбирать для ключей целые числа, строки и массивы из них.

Для типа значений такого ограничения нет: значением может быть любой тип,
который вы знаете, — число, строка, `bool`, массив или slice. Например,
`map[string][]int` — допустимый тип: ключ `string`, значение — slice чисел.
map, значения которой — slice или другие map, разбирает урок 4.13.

## map или slice

Slice и map оба хранят много значений одного типа, но находят их по-разному.
Slice адресует значение номером позиции, и номера идут подряд от 0. map
адресует значение ключом, и ключом может быть название, слово, код.

Выбирайте map, когда естественный адрес значения — не номер позиции: остаток по
названию товара, телефон по имени, цена по коду товара. Со slice пришлось бы
помнить, какой номер у какого названия, или держать рядом второй slice с
названиями на тех же позициях и искать в нём название циклом.

Выбирайте slice, когда адреса — небольшие номера подряд, например число
посетителей по дням недели с номерами от 0 до 6. Номер тогда сам служит
индексом, и map ничего не добавляет. Если же номера большие и редкие —
например, коды 1000, 5020 и 90000, — slice пришлось бы делать длиной больше
90000 ради трёх значений, и map снова удобнее.

Урок 4.15 сравнит slice и map как таблицы данных, которые заменяют цепочку
условий.

`TestResetEmptyNotNil` проверяет именно это сравнение и отвергает nil-map с
сообщением, что в nil-map нельзя записывать.

Для вызывающего кода разница главная. Чтение из nil-map законно и даёт 0, а
первая же запись в неё вызывает панику и останавливает программу. А map из
`make` или из пустого литерала `map[string]int{}` не равна `nil`, и в неё
можно записывать сразу.

Верное решение: `return make(map[string]int)`. Пустой литерал
`return map[string]int{}` тоже верен, и тест эти решения не различает.

## Та же map вместо новой

<!-- review:same-map -->

Второй вопрос. Если `Reset` возвращает свой параметр `m`, то после
`fresh := Reset(stock)` имена `fresh` и `stock` обозначают одну и ту же map:
параметр получил ту же map, что и аргумент, а возврат отдал её обратно. Запись
`fresh["сок"] = 4` попадает в эту общую map, и в `stock` становится четыре
записи. Кроме того, «новая пустая» map на деле не пуста: в ней те же три
записи.

С массивом было бы иначе. Параметр-массив получает копию (урок 4.1), и функция
вернула бы эту копию. Запись в элемент результата изменила бы только копию, а
`stock` остался бы прежним.

Такое решение ловит `TestResetLeavesArgument`: тест записывает в результат
новую запись и видит её в переданной map. Верное решение создаёт новую map и
не возвращает `m`.

## Запятые и повторы в NewStock

<!-- review:literal-commas -->

Третий вопрос. Если пары литерала стоят по одной на строку, а закрывающая
скобка `}` — на следующей строке, запятая нужна после каждой пары, включая
последнюю. Без неё компилятор вставит невидимую точку с запятой после
последнего значения и сообщит
`syntax error: unexpected newline in composite literal; possibly missing comma or }`.

Если при копировании строк ключ "кофе" окажется в литерале дважды, сборка
остановится с тем же сообщением о повторном ключе, что в разделе теории
«Запятые и повторы в литерале», только с ключом "кофе". Исправляют по смыслу:
одна из двух пар должна стать парой `"вода": water`.

Верное решение: `return map[string]int{"чай": tea, "кофе": coffee, "вода": water}`
— в одну строку или по паре на строку с запятой после каждой пары.

## Перепутанные параметры

<!-- review:swapped-values -->

Решение пишет `"чай": coffee` и `"кофе": tea`. Ловит это `TestNewStock`: для
`NewStock(3, 5, 7)` тест ждёт чай 3 и кофе 5, а получает чай 5 и кофе 3. Число
записей верное, поэтому ошибку видно только при чтении значений по ключам.
Каждому ключу — свой параметр: "чай" — `tea`, "кофе" — `coffee`, "вода" —
`water`.

## Забытая пара

<!-- review:missing-water -->

Решение возвращает литерал только с парами для чая и кофе. Ловит это
`TestNewStock`: тест ждёт в результате три записи, а находит две. Параметр
`water` при этом никуда не записан. В литерале должна быть и пара
`"вода": water`.

## Число товаров вместо числа записей

<!-- review:fixed-count -->

Решение всегда возвращает 3, потому что `NewStock` создаёт три товара. Ловит
это `TestCount`: для nil-map и для пустой map тест ждёт 0, для map с двумя
записями — 2. `Count` получает любую map, а не только результат `NewStock`.
Число записей даёт `len(m)`, и для nil-map оно равно 0.

## Нули вместо новой map

<!-- review:zero-values-reset -->

Решение записывает в `m` значения 0 для ключей "чай", "кофе" и "вода" и
возвращает `m`. Ловит это `TestResetLeavesArgument` сразу по трём причинам.
Для nil-map запись вызывает панику. Для пустой map функция добавляет в неё три
записи, хотя переданную map менять нельзя. Для map с тремя записями
результат — та же map с тремя записями, а не пустая, и тест видит, что остатки
вызывающего кода после вызова стали другими. «Сбросить» в этой задаче значит
вернуть новую пустую map, а переданную оставить как есть.

## Вопрос 1

Три объявления создают переменные типа `map[int]bool`:

- `var seen map[int]bool`
- `marks := make(map[int]bool, 4)`
- `flags := map[int]bool{}`

Для каждой переменной назовите длину, результат сравнения с `nil`, значение
при чтении ключа 7 и то, можно ли в неё записывать. Какой вариант верен?

Варианты ответа:

- A. У всех трёх длина 0, чтение ключа 7 даёт `false`; только `seen` равна
  `nil`, и только в неё записывать нельзя.
- B. У `seen` и `flags` длина 0 и обе равны `nil`; у `marks` длина 4; чтение
  ключа 7 у всех трёх даёт `false`.
- C. Все три равны `nil` и имеют длину 0; записывать нельзя ни в одну, пока в
  ней нет ни одной записи.
- D. У всех трёх длина 0; `seen` равна `nil`, и чтение ключа 7 из неё
  вызывает панику, а у двух других даёт `false`.

Прежде чем смотреть ответ, заполните таблицу из четырёх столбцов для трёх
переменных и скажите, что задаёт число 4 в вызове `make`.

**Правильный ответ: A.**

`var` оставляет в `seen` нулевое значение — nil-map: длина 0, сравнение с
`nil` истинно. Чтение из неё законно и даёт нулевое значение `bool`, то есть
`false`; запись вызвала бы панику. `make` и пустой литерал создают пустые map,
которые не равны `nil`, и в них можно записывать. Число 4 — только подсказка
размера, длина `marks` остаётся 0. Вариант B путает подсказку с длиной из
`make([]int, 4)` и считает пустой литерал nil-map. Вариант C считает nil-map
любую пустую map. Вариант D приписывает панику чтению, а паника грозит только
записи в nil-map.

Варианты ответа:

- A. Программа соберётся, и в map останется ключ "чай" со значением 7:

- B. Программа соберётся, и в map останется ключ "чай" со значением 3: второй

- C. Программа не соберётся; третий ключ нужно заменить на "вода", чтобы в

Прежде чем смотреть ответ, назовите правило для ключей литерала и скажите,

сборка.

## Вопрос 3

Какие из объявлений не соберутся?

1. `var a map[[3]string]int`
2. `var b map[[]string]int`
3. `var c map[bool]string`
4. `var d map[map[string]int]bool`
5. `var e map[string][]int`
6. `var f map[float64]string`

Варианты ответа:

- A. 2, 4 и 5: slice и map нельзя использовать в map ни ключом, ни
  значением.
- B. 2 и 4: для типов ключей `[]string` и `map[string]int` оператор `==` не
  определён.
- C. 1, 2 и 4: массив, slice и map хранят много значений и поэтому не годятся
  в ключи.
- D. 2, 4 и 6: кроме slice и map, в ключи не годятся числа с плавающей
  точкой.

Прежде чем смотреть ответ, для каждого типа ключа скажите, определён ли для
него `==`, и отдельно назовите правило для типа значений.

**Правильный ответ: B.**

map сравнивает ключи через `==`, поэтому тип ключа должен быть сравнимым.
Для `[]string` и `map[string]int` оператор `==` не определён, и компилятор
сообщит, что это недопустимый тип ключа (invalid map key type). Вариант A
переносит правило ключей на значения, а для значений ограничения нет:
`map[string][]int` соберётся. Вариант C не учитывает, что массивы строк
сравниваются поэлементно (урок 4.1), поэтому `[3]string` годится. Вариант D
путает «разрешено» с «надёжно»: ключ `float64` язык разрешает, хотя
вычисленный ключ может не найти запись.

## Вопрос 4

```go
@quiz _quiz/q4-two-names
```

Что напечатает программа?

Варианты ответа:

- A. Шаг 1: одна запись в `prices` и две в `menu`; шаг 2: по одной; в
  `prices` только чай 40.
- B. Шаг 1: по две записи; шаг 2: по одной; в `prices` только вода 20.
- C. Шаг 1: по две записи; шаг 2: по три; в `prices` вода 20, кофе 90 и
  чай 40.
- D. Шаг 1: по две записи; шаг 2: две в `prices` и одна в `menu`; в
  `prices` кофе 90 и чай 40.

Прежде чем смотреть ответ, заполните таблицу: какие записи есть в `prices` и
в `menu` после каждой инструкции, начиная с `menu := prices`. Затем объясните,
чем `menu := prices` отличается от присваивания массива в уроке 4.1.

**Правильный ответ: D.**

`menu := prices` не копирует записи: оба имени обозначают одну map, поэтому
запись кофе видна через `prices`, и на шаге 1 у обоих по две записи. Массив

Вариант A рассуждает как с массивом из урока 4.1. Вариант B считает, что
`make` очищает общую map для обоих имён. Вариант C считает, что после `make`
имя `menu` по-прежнему обозначает общую map.

## Вопрос 5

Программа напечатала map строкой `map[вода:7 кофе:5 чай:3]`. Что можно
сказать о порядке пар в литерале, который создал эту map?

Варианты ответа:

- A. Пары стояли в том же порядке — вода, кофе, чай: печать повторяет
  порядок, в котором записи создавались.
- B. Пары стояли в обратном порядке: печать показывает первыми записи,
  которые появились последними.
- C. По этой строке порядок пар не узнать: `fmt` сортирует записи по ключам
  перед печатью.
- D. Порядок пар не важен: map хранит записи отсортированными, и обход тоже
  даст вода, кофе, чай.

Прежде чем смотреть ответ, объясните, откуда берётся порядок в этой строке и
о каком порядке она ничего не говорит.

**Правильный ответ: C.**

Порядок в строке задаёт `fmt`: перед печатью он сортирует записи по ключам,
строки — побайтово. Литерал с любым порядком тех же трёх пар напечатается
одинаково. Варианты A и B приписывают печати память о порядке создания
записей, которой у map нет. Вариант D принимает сортировку `fmt` за свойство
самой map; порядок обхода язык не задаёт, его разбирает урок 4.14.

- B. Напечатается `false`: это две разные map из двух литералов.

## Вопрос 7

Нужно хранить два набора данных:

1. баллы участников олимпиады по их логинам, например "anna" и "boris";
2. число шагов за каждый час суток, часы пронумерованы от 0 до 23.

Какую коллекцию выбрать для каждого набора?

Варианты ответа:

- A. map для обоих наборов: по ключу-часу искать не хуже, чем по логину.
- B. map для баллов и slice для шагов: адрес балла — логин, адрес шагов —
  номер часа подряд от 0.
- C. slice для баллов, где номер участника — индекс, и map для шагов по часам.
- D. slice для обоих наборов: логины можно держать во втором slice на тех же
  позициях.

Прежде чем смотреть ответ, назовите для каждого набора естественный адрес
значения и объясните выбор через него.

Балл находят по логину — это ключ-строка, и map хранит его рядом со

номеров подряд ничего не добавляет. Вариант C заставляет помнить, какой номер

map находит значение по ключу сразу.
