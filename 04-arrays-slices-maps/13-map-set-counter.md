# Карта как множество и счётчик

Организатор встречи ведёт список гостей. Ему нужно быстро отвечать на вопрос
«этот человек уже в списке?», знать, сколько людей в списке, и вычёркивать
тех, кто ушёл. Похожие вопросы возникают постоянно: сколько раз каждое слово
встретилось в тексте, какие слова имеют одинаковую длину, сколько книг
каждого автора стоит на полке каждого жанра. Все четыре задачи решает один
тип — `map`, если выбрать для него подходящий тип значения.

Понадобится пройденное: цикл `for _, w := range words` по slice (урок 4.10),
присваивание `s = append(s, x)`, в том числе к nil-slice (уроки 4.5 и 4.7),
создание map через `make` и `len` у map (урок 4.11), чтение отсутствующего
ключа, запись, `m[k]++`, `delete`, форма `v, ok := m[k]` и паника при записи
в nil-map (урок 4.12).

К концу урока вы сможете:

- использовать `map[string]bool` как множество и объяснить, почему для
  проверки хватает обычного чтения;
- считать повторы через `m[k]++` и предсказывать счёт после удаления и
  нового увеличения;
- собирать группы в `map[int][]string` и объяснять, зачем результат
  `append` записывают обратно в map;
- найти панику при записи во вложенную map и исправить её;
- выбрать форму map для задачи и объяснить выбор.

## Множество: есть ли ключ

Про гостя нужно знать одно: есть он в списке или нет. Набор значений без
повторов, для которого задают только такой вопрос, называют **множеством**.
В Go множество строк обычно записывают как `map[string]bool`: ключ — имя,
значение — всегда `true`.

С множеством делают три действия:

- **добавить**: `guests[name] = true`. Если имя уже есть, запись заменяет
  `true` на `true`, и новой записи в map не появляется;
- **проверить**: `guests[name]`. Чтение отсутствующего ключа возвращает
  нулевое значение того типа, который map хранит в значениях (урок 4.12), а
  нулевое значение `bool` — `false` (урок 2.1). Поэтому `false` и означает
  «нет в списке», и форма `v, ok` для проверки не нужна. Само чтение ключ
  в map не добавляет;
- **убрать**: `delete(guests, name)`. Если такого ключа нет, `delete` ничего
  не делает и программу не останавливает.

`len(guests)` возвращает число записей в map, то есть размер множества.

Программа ниже добавляет Аню, затем Бориса, добавляет Аню повторно, удаляет
её и пытается удалить Гошу, которого в списке не было. Прежде чем смотреть
вывод, составьте таблицу: для каждой строки с `fmt.Println` запишите те из
значений `guests["аня"]`, `guests["борис"]` и `len(guests)`, которые она
печатает. Объясните, почему чтение `guests["борис"]` на первом шаге не
увеличило длину.

```go

### Example: `01-guests`

Источник: `examples/01-guests/`

```go
// Список гостей как множество: ключ — имя, значение всегда true.
package main

import "fmt"

func main() {
	guests := make(map[string]bool)

	guests["аня"] = true
	fmt.Println("шаг 1 — аня:", guests["аня"], "борис:", guests["борис"], "len:", len(guests))

	guests["борис"] = true
	guests["аня"] = true
	fmt.Println("шаг 2 — аня:", guests["аня"], "борис:", guests["борис"], "len:", len(guests))

	delete(guests, "аня")
	fmt.Println("шаг 3 — аня:", guests["аня"], "борис:", guests["борис"], "len:", len(guests))

	delete(guests, "гоша")
	fmt.Println("шаг 4 — len:", len(guests))
}

```
```

На первом шаге Бориса ещё нет: чтение вернуло `false` и ничего не добавило,
поэтому в map одна запись. Повторное `guests["аня"] = true` перезаписало
существующую запись, и на втором шаге записей две, а не три. После `delete`
чтение Ани снова даёт `false`: удалённый ключ читается так же, как ключ,
которого никогда не было. Удаление отсутствующего Гоши длину не изменило.

## Почему в множестве хранят только true

Правило «`false` значит нет в списке» верно, пока в map лежат только
значения `true`. Если записать `guests["вера"] = false`, ключ `вера`
появится в map. Форма `_, ok := guests["вера"]` даст `ok`, равный `true`:
она отвечает на вопрос, есть ли в map запись именно с ключом `вера`.
Обычное чтение при этом вернёт хранимое `false` — то же значение, что у
отсутствующего ключа. Тогда одна и та же map отвечает на вопрос «есть ли
Вера в списке» по-разному, смотря как спросить.

`len(guests)` на этот вопрос не отвечает. `len` считает все записи map, в
том числе запись со значением `false`: после `guests["вера"] = false` длина
выросла на 1, хотя обычное чтение Веры не находит. Какие именно ключи лежат
в map, по одному числу узнать нельзя: одна и та же длина получится и когда
в map лежат Аня с Верой, и когда Аня с Гошей.

Поэтому в множестве на `map[string]bool` хранят только `true`, а убирают
элемент через `delete`, а не записью `false`. Если в map лежат и `true`, и
`false`, это уже не множество, а таблица «да или нет» для каждого ключа, и
присутствие ключа в ней проверяют формой `v, ok`.

Прежде чем смотреть вывод, ответьте для Веры и для Гоши: что вернёт обычное
чтение, чему будет равен `ok`, и сколько записей насчитает `len`.

```go

### Example: `02-stored-false`

Источник: `examples/02-stored-false/`

```go
// Что показывают обычное чтение, форма ok и len, если в множество записали false.
package main

import "fmt"

func main() {
	guests := make(map[string]bool)
	guests["аня"] = true
	guests["вера"] = false

	fmt.Println("обычное чтение — вера:", guests["вера"], "гоша:", guests["гоша"])

	_, veraOK := guests["вера"]
	_, goshaOK := guests["гоша"]
	fmt.Println("ok — вера:", veraOK, "гоша:", goshaOK)

	fmt.Println("записей в map:", len(guests))
}

```
```

Для Веры и для Гоши обычное чтение дало одинаковое `false`, хотя Вера в map
есть, а Гоши нет. Отличила их только форма `ok`: она проверяет присутствие
названного ключа, и для Веры дала `true`, а для Гоши `false`. Длина 2
показывает, что запись с `false` заняла место в map, но не говорит, чья это
запись: `len` считает все записи сразу.

Бывает множество, в котором значение не хранится вовсе:
`map[string]struct{}`. Оно экономнее по памяти, но присутствие в нём
проверяют только формой `_, ok`. Пустую структуру `struct{}` разбирает урок
6.3, а до него множество записывают как `map[string]bool` со значениями
`true`.

## Счётчик: сколько раз

Вторая задача — посчитать, сколько раз каждое слово встретилось в slice.
Ключ — слово, значение — число повторов: `map[string]int`. Для каждого слова
выполняется `count[w]++`. Эта инструкция работает как
`count[w] = count[w] + 1`: читает текущее значение, прибавляет 1 и
записывает результат под тот же ключ. Для слова, которое встретилось
впервые, чтение возвращает нулевое значение `int`, то есть 0 (урок 4.12), и
запись кладёт 1. Отдельная проверка «есть ли уже такое слово» не нужна.

Слова перебирает `for _, w := range words` из урока 4.10: индекс не нужен,
поэтому его отбрасывает `_`. Цикл только читает элементы `words` и пишет в
`count`, поэтому сам slice не меняется.

Прежде чем смотреть вывод, назовите число повторов для `кот`, `пёс` и `go`,
а также для слова `ёж`, которого в slice нет. Сколько записей будет в
`count`, и в каком виде напечатается `words`?

```go

### Example: `03-counter`

Источник: `examples/03-counter/`

```go
// Счётчик слов: map[string]int и count[w]++ для каждого слова.
package main

import "fmt"

func main() {
	words := []string{"кот", "пёс", "кот", "go", "кот", "go"}
	count := make(map[string]int)

	for _, w := range words {
		count[w]++
	}

	fmt.Println("кот:", count["кот"])
	fmt.Println("пёс:", count["пёс"])
	fmt.Println("go:", count["go"])
	fmt.Println("ёж:", count["ёж"])
	fmt.Println("разных слов:", len(count))
	fmt.Println("words:", words)
}

```
```

`кот` встретился трижды, `go` — дважды, `пёс` — один раз. Чтение
`count["ёж"]` вернуло 0 и записи не добавило, поэтому разных слов три. Slice
`words` напечатан в прежнем порядке: счётчик его не трогал.

## Удалить и посчитать заново

`delete(count, "кот")` убирает запись целиком — ключ вместе с числом. Map
не хранит удалённое значение про запас. После удаления `count["кот"]`
читается как отсутствующий ключ, то есть как 0, и следующий
`count["кот"]++` начинает счёт заново — с 1, а не с прежнего числа.

Прежде чем смотреть вывод, запишите для каждой из трёх строк значение
`count["кот"]` и `len(count)`.

```go

### Example: `04-readd`

Источник: `examples/04-readd/`

```go
// Счёт после delete и нового увеличения.
package main

import "fmt"

func main() {
	count := make(map[string]int)
	count["кот"]++
	count["кот"]++
	count["кот"]++
	fmt.Println("до удаления — кот:", count["кот"], "len:", len(count))

	delete(count, "кот")
	fmt.Println("после удаления — кот:", count["кот"], "len:", len(count))

	count["кот"]++
	fmt.Println("после нового ++ — кот:", count["кот"], "len:", len(count))
}

```
```

После удаления записи нет: и значение, и длина стали нулём. Новое
увеличение прочитало 0 и записало 1. Если прежнее число ещё понадобится,
его сохраняют в отдельную переменную до `delete`.

## Группы: map со значениями-slice

Третья задача — разложить слова по группам: в каждой группе слова одной
длины, в том порядке, в котором они встретились. Ключ — длина, значение —
slice слов этой длины: `map[int][]string`. Такая форма отвечает на вопрос
«какие элементы делят один ключ».

Длину даёт `len(w)`, а `len` строки считает байты (уроки 2.7 и 2.8). В
кодировке UTF-8 каждая русская буква в словах этого урока занимает два
байта, а латинская — один. Поэтому `len("кот")` и `len("пёс")` равны 6,
`len("ёж")` равен 4, а `len("go")` и `len("to")` — 2. Слово из трёх русских
букв попадёт в группу 6, а не 3.

Слово добавляется в группу одной инструкцией
`groups[n] = append(groups[n], w)`. Она выполняет три шага:

1. `groups[n]` читает slice группы. Если слов длины `n` ещё не было, ключа
   нет, и чтение возвращает нулевое значение типа `[]string` — nil-slice
   (урок 4.7).
2. `append` добавляет `w` в конец. К nil-slice `append` тоже добавляет:
   получается slice из одного элемента (урок 4.5).
3. Присваивание кладёт результат `append` в map под ключ `n`.

Шаг 3 обязателен по той же причине, что и в уроке 4.5: `append` возвращает
новое значение slice и не меняет то значение, которое лежит в map. Без
присваивания группа в map не появится. Проверять заранее, есть ли ключ, не
нужно: первый `append` получает nil-slice и сам делает из него группу.

Прежде чем смотреть вывод, пройдите цикл по пяти словам: для каждого слова
назовите ключ `n` и группу после присваивания. Затем назовите содержимое и
длину групп 6, 2, 4 и 3 и число групп в map.

```go

### Example: `05-group`

Источник: `examples/05-group/`

```go
// Группы слов по длине в байтах: map, значения которой — slice.
package main

import "fmt"

func main() {
	words := []string{"кот", "go", "пёс", "ёж", "to"}
	groups := make(map[int][]string)
	fmt.Println("до цикла — группа 6:", groups[6], "len:", len(groups[6]), "nil:", groups[6] == nil)

	for _, w := range words {
		n := len(w)
		groups[n] = append(groups[n], w)
	}

	fmt.Println("группа 6:", groups[6], "len:", len(groups[6]))
	fmt.Println("группа 2:", groups[2], "len:", len(groups[2]))
	fmt.Println("группа 4:", groups[4], "len:", len(groups[4]))
	fmt.Println("группа 3:", groups[3], "len:", len(groups[3]))
	fmt.Println("групп:", len(groups))
}

```
```

Первая строка вывода показывает, что до цикла группы 6 нет: чтение вернуло
nil-slice длины 0. `append` для `кот` сделал из него группу из одного слова,
`append` для `пёс` добавил слово в конец той же группы. Порядок внутри
группы совпадает с порядком слов во входе, потому что `append` всегда
добавляет в конец. Группы 3 нет: ни одно слово не занимает три байта, и
чтение вернуло пустой nil-slice.

Если забыть шаг 3 и написать только `append(m[3], w)`, программа не
соберётся: вызов `append`, результат которого никуда не записан, компилятор
отклоняет. Прежде чем читать сообщение, найдите в программе ниже строку, на
которой остановится сборка, и назовите, чего в ней не хватает.

```go
@broken no-assign
```

Сборка останавливается с сообщением
`append(m[3], w) (value of type []string) is not used`: значение типа
`[]string`, которое вернул `append`, никуда не записано. Опаснее вариант,
который собирается: `group := m[3]`, а затем `group = append(group, w)`.
Результат сохранён, но только в переменной `group`, а в map под ключом 3
группы по-прежнему нет. Такая программа молча теряет слова. Поэтому группу
всегда записывают обратно в map по тому же ключу:
`m[k] = append(m[k], w)`.

## Вложенная map: паника на втором уровне

Библиотекарь считает книги по жанрам и авторам: сколько книг Лема в
фантастике, сколько книг Кристи в детективах. Здесь ключ двухуровневый, и
оба уровня ищут по отдельности: сначала жанр, потом автора внутри жанра.
Подходит map, значения которой — тоже map: `map[string]map[string]int`.
Внешняя map по жанру возвращает **внутреннюю** map, а внутренняя по автору
возвращает число книг.

Выражение `books["фантастика"]["лем"]` выполняется в два шага, слева
направо. Сначала `books["фантастика"]` достаёт внутреннюю map. Если такого
жанра нет, это чтение отсутствующего ключа, и оно возвращает нулевое
значение типа `map[string]int`, то есть `nil`. Затем из этой map читается
ключ `"лем"`. Чтение из nil-map безопасно и возвращает нулевое значение
типа значений внутренней map, здесь 0 (урок 4.12).

Запись устроена иначе. `books["фантастика"]["лем"]++` так же сначала
достаёт внутреннюю map — `nil` — и пытается записать в неё. Запись в
nil-map вызывает панику, как в уроке 4.12, только теперь nil-map лежит на
втором уровне, и в коде её не видно. `make` для внешней map создал только
внешнюю map: внутренних map он не создаёт.

Прежде чем смотреть вывод, решите, какие строки программа успеет
напечатать и на какой строке остановится.

```go

### Example: `06-nested-panic`

Источник: `examples/06-nested-panic/`

```go

## Исправление: создать, сохранить, записать

Перед записью для нового жанра программа выполняет три действия:

1. проверяет, есть ли жанр во внешней map: `authors, ok := books[genre]`;
2. если жанра нет, создаёт внутреннюю map `authors = make(map[string]int)`
   и сохраняет её во внешней: `books[genre] = authors`;
3. записывает число во внутреннюю map: `authors[author]++`.

Действия 1 и 2 создают внутреннюю map один раз для каждого жанра. В уроке
4.11 присваивание map другой переменной не копировало записи: обе
переменные работали с одними и теми же записями. Так и здесь: после
`books[genre] = authors` внешняя map хранит map с теми же записями, что и
`authors`. Следующее чтение `books[genre]` возвращает её, `ok` равен
`true`, и `make` уже не выполняется. Запись через `authors` видна и через
`books[genre]`.

Вместо `ok` можно проверить `books[genre] == nil`: для отсутствующего жанра
чтение вернёт `nil`. Пока внешняя map не хранит `nil` в качестве значения,
обе проверки дают одинаковый результат.

Функция `addBook` в программе ниже выполняет эти три действия и печатает
строку, когда создаёт внутреннюю map. Внешнюю map она получает параметром;
по уроку 4.11 параметр работает с теми же записями, что и переменная
`books` в `main`, поэтому `main` видит всё, что записала функция.

package main

import "fmt"

// addBook увеличивает число книг автора author в жанре genre.
func addBook(books map[string]map[string]int, genre, author string) {

## Две ошибки исправления

Каждое из трёх действий нужно. Первая ошибка — пропустить проверку
(действие 1) и вызывать `make` перед каждой записью. Тогда `make` заменяет
уже сохранённую внутреннюю map новой, пустой, и прежние числа жанра
пропадают. Вторая ошибка — в действии 2 создать внутреннюю map, но не
сохранить её во внешней. Тогда запись попадает в map, до которой внешняя
map не ведёт: число видно через переменную, а через внешнюю map читается 0.

## Какую форму выбрать

Форму map выбирают по вопросу, на который она должна отвечать.

| Вопрос задачи | Форма | Главная операция |
|---|---|---|
| Встречался ли уже этот элемент? | множество `map[string]bool` | `seen[k] = true`, проверка `seen[k]` |
| Сколько раз встретился элемент? | счётчик `map[string]int` | `count[k]++` |
| Какие элементы делят один ключ? | группы `map[int][]string` | `m[k] = append(m[k], v)` |
| Какое число у пары ключей, если оба уровня ищут отдельно? | вложенная map `map[string]map[string]int` | создать и сохранить внутреннюю map, затем писать |

Во всех четырёх формах работает одно правило: чтение отсутствующего ключа
возвращает нулевое значение типа значений map. Для множества это `false`, для
счётчика 0, для групп nil-slice, к которому можно применить `append`.
Только у вложенной map нулевое значение — nil-map, в которую писать нельзя,
поэтому ей нужен явный шаг создания.

Два уровня ключа не всегда требуют вложенной map. Если внутренний уровень
отдельно не нужен, ключи можно склеить в одну строку, например
`count["фантастика/лем"]++`. Вложенная map нужна, когда с внутренней map
работают как с целым: например, узнают число авторов жанра через
`len(books[genre])`.

Счётчик и группы понадобятся в мини-проекте уроков 4.17 и 4.18: там
частоты слов собирают счётчиком, а слова с одинаковой частотой — в группы.
Все программы этого урока читали только известные ключи. Как пройти по всем
ключам map и почему порядок такого обхода не задан, разбирает урок 4.14.

`CountAll` возвращает map, в которой для каждого слова из `words` записано,

## Размер множества

<!-- review:set-size -->

Вопрос 1 из постановки: почему достаточно `true` и почему ответ — `len`.
Образец ответа ниже.

Множество отвечает только на вопрос «встречалось ли слово». Запись
`seen[w] = true` для нового слова добавляет ключ, а для уже встреченного
заменяет `true` на `true`: у одного ключа в map одна запись. Поэтому после
цикла в map ровно столько записей, сколько разных слов, и это число
возвращает `len(seen)`. Хранить `false` не нужно: отсутствующее слово и так
читается как `false`. Решение целиком: `seen := make(map[string]bool)`,
цикл `for _, w := range words` с `seen[w] = true`, затем
`return len(seen)`.

## Группа записывается обратно

присваивание. Образец ответа ниже.

Для первого слова новой длины ключа в map нет, и `groups[n]` возвращает
нулевое значение `[]string` — nil-slice длины 0. `append` к nil-slice
возвращает slice из одного слова, но значение в map сам не меняет. Только
присваивание `groups[n] = ...` кладёт новый slice в map; следующее слово той
же длины прочитает уже эту группу и добавится в её конец. Решение целиком:
`groups := make(map[int][]string)`, в цикле `n := len(w)` и
`groups[n] = append(groups[n], w)`, затем `return groups`.

## Внутренняя map: создать один раз

<!-- review:nested-repair -->

Вопросы 3 и 4 из постановки: что будет без создания внутренней map и почему
создают её один раз. Образец ответа ниже.

Если категории нет, `sales[category]` возвращает `nil`, и
`sales[category][item]++` пытается записать в nil-map: программа
останавливается паникой `assignment to entry in nil map`. Исправление —
три действия по порядку: проверить категорию через
`items, ok := sales[category]`; если её нет, создать
`items = make(map[string]int)` и сохранить `sales[category] = items`; затем
выполнить `items[item]++` и вернуть `items[item]`.

После сохранения внешняя map хранит внутреннюю map с теми же записями, что
и `items`. Следующий вызов с той же категорией получает её через
`sales[category]`, `ok` равен `true`, и `make` не выполняется. Если вызывать
`make` при каждом вызове, новая пустая map заменит сохранённую, и прежние
числа категории пропадут. Проверка `sales[category] == nil` вместо `ok`
тоже подходит: по условию существующие категории не хранят `nil`.

## Длина входа вместо числа разных слов

<!-- review:unique-len -->

Решение `return len(words)` верно, пока во входе нет повторов. На входе
`кот`, `пёс`, `кот`, `go`, `кот`, `go` оно возвращает 6 вместо 3.

Такое решение не проходит `TestUnique` на входах с повторами. Исправление —
собрать множество и вернуть его размер.

## Слова, встретившиеся один раз

<!-- review:unique-once -->

Решение, которое считает слова с числом повторов 1, отвечает на другой
вопрос: «сколько слов не повторяется». На том же входе оно возвращает 1 —
один `пёс`, — а разных слов три.

Это решение тоже не проходит `TestUnique`. Каждое разное слово нужно
посчитать один раз, сколько бы раз оно ни встретилось, и именно такое число
даёт размер множества.

## Счётчик без make

<!-- review:countall-nil-map -->

Решение с `var count map[string]int` оставляет счётчик нулевым значением
map — `nil`. Первое `count[w]++` на непустом входе вызывает панику
`assignment to entry in nil map`, а на пустом входе функция возвращает
`nil`, хотя контракт требует созданную map.

`TestCountAll` находит обе проблемы: панику на входе со словами и `nil` на
пустом входе. Исправление — `count := make(map[string]int)` до цикла.

## Запись 1 вместо увеличения

<!-- review:countall-assign-one -->

Решение `count[w] = 1` записывает для каждого слова единицу, и повторы
теряются: получается множество, в котором вместо `true` стоит 1.

`TestCountAll` не проходит на входе с тремя `кот`: в результате 1 вместо 3.
Исправление — `count[w]++`, которое читает прежнее число и прибавляет 1.

## Группа осталась в переменной

<!-- review:groupbylen-no-write-back -->

Решение `group := groups[len(w)]`, затем `group = append(group, w)`
собирается, но результат `append` попадает только в местную переменную
`group`. В map групп не появляется, и функция возвращает map без записей.

Тест `TestGroupByLen` получает ноль групп вместо четырёх. Почему нужно
присваивание в map, разобрано в разделе «Группа записывается обратно».

## Группа из последнего слова

<!-- review:groupbylen-overwrite -->

Решение `groups[len(w)] = []string{w}` кладёт под ключ новый slice из
одного слова, и каждое следующее слово той же длины заменяет прежнюю
группу. Под ключом 6 остаётся только `пёс`.

Такое решение не проходит `TestGroupByLen`: тест сравнивает содержимое
каждой названной группы. Чтобы сохранить прежние слова группы, новое слово
добавляют к ней через `append` и записывают результат обратно.

## Запись во внутреннюю nil-map

<!-- review:addsale-no-make -->

Решение `sales[category][item]++` верно, только если категория уже есть.
Для новой категории внутренняя map равна `nil`, и запись вызывает панику.

Такое решение падает в `TestAddSale` на первой же новой категории;
сообщение проверки называет вход и текст паники. Исправление разобрано в
разделе «Внутренняя map: создать один раз».

## make при каждом вызове

<!-- review:addsale-remake -->

Решение, которое при каждом вызове выполняет
`items := make(map[string]int)` и `sales[category] = items`, не падает, но
заменяет сохранённую внутреннюю map пустой. Первый вызов для категории
работает, а третий вызов `фрукты`/`яблоко` возвращает 1 вместо 2: число,
записанное первым вызовом, пропало вместе со старой внутренней map.

Такое решение не проходит `TestAddSale`, в том числе на заранее заданной
категории: там вместо −4 получается 1. Исправление — создавать внутреннюю
map только для отсутствующей категории.

## Внутренняя map не сохранена

<!-- review:addsale-not-stored -->

Решение создаёт внутреннюю map для новой категории, но не выполняет
`sales[category] = items`. Возвращённое число верное, а внешняя map так и
не узнаёт о новой категории: `sales["фрукты"]["яблоко"]` после вызова
читается как 0.

Такое решение не проходит `TestAddSale`; в сообщении проверки сказано, что
внутренняя map должна быть сохранена в `sales`. Исправление — сохранить
созданную map во внешней до записи числа.

## Что говорят и чего не говорят тесты

<!-- review:tests-observe -->

Скрытые тесты вызывают каждую функцию на нескольких входах и сравнивают
значения по известным ключам: число разных слов, число у каждого
названного слова, содержимое и порядок названных групп, числа в `sales`
после вызовов. Ещё они сравнивают число записей в возвращённых map и в
`sales` и проверяют, что slice `words` не изменился.

Если прошли все четыре теста, это значит одно: на проверенных входах
функции вернули ожидаемые значения. Про другие входы тесты ничего не
говорят. Если тест не прошёл, его сообщение называет проверку, которая не
сошлась: например, вход с полученным и ожидаемым значением, вход с текстом
паники, неверное число записей или изменённый `words`. Значит, по крайней
мере в этой проверке результат расходится с условием упражнения; разделы
выше помогают найти причину. Если код не собрался, ни один тест не
запускался, и о результатах функций ничего не известно.

Во всех этих случаях тесты не читают текст решения. Поэтому они не
устанавливают, каким способом решена задача, и не проверяют объяснения —
почему в множестве хранят `true`, зачем записывать группу обратно и почему
внутреннюю map создают один раз. Их вы проверяете сами, ответами на вопросы
постановки и разделами выше.

## Вопрос 1

Составьте таблицу: после каждой строки `main` запишите, какие имена есть в
`seen`, и значение `len(seen)`. Затем назовите четыре напечатанных значения
и объясните, почему для проверки «есть ли имя в множестве» хватает обычного
чтения `seen[k]`.

```go
@quiz _quiz/01-set
```

Возможные ответы:

- А. Ира есть, Олега и Яны нет, записей две: повтор Иры перезаписал `true`,
  а удаление Яны ничего не сделало.
- Б. Ира есть, Олега и Яны нет, записей три: повторная запись Иры добавила
  в map вторую запись с тем же именем.
- В. Программа остановится паникой на удалении Яны, потому что ключа
  `яна` в map нет и удалять нечего.

**Ответ: А.** После двух первых записей в map Ира и Олег; повтор Иры
заменил `true` на `true`, записей по-прежнему две. `delete` убрал Олега,
Петя добавил запись, удаление отсутствующей Яны ничего не изменило — в
конце две записи. У одного ключа в map одна запись, поэтому повтор длину не
меняет. Обычное чтение Олега и Яны вернуло нулевое значение `false`: в
множестве лежат только `true`, и `false` бывает только у ключа, которого
нет.

## Вопрос 2

Предскажите три напечатанных значения. Затем объясните, почему обычное
чтение `seen["олег"]` и флаг `ok` по-разному отвечают на вопрос «есть ли
Олег в списке» и почему число `len(seen)` на этот вопрос не отвечает.

```go
@quiz _quiz/02-false
```

Возможные ответы:

- А. `false`, `false` и 1: запись `false` работает как удаление, и ключа
  `олег` после неё в map нет.
- Б. `true`, `true` и 2: любая запись в map делает обычное чтение этого
  ключа истинным, даже запись `false`.
- В. `false`, `true` и 2: ключ `олег` в map есть, но хранит `false`, и
  обычное чтение не отличает его от отсутствующего.

**Ответ: В.** Запись `seen["олег"] = false` добавила ключ, поэтому
`_, ok := seen["олег"]` даёт `ok`, равный `true`: эта форма проверяет
присутствие именно ключа `олег`. `len(seen)` равен 2, потому что `len`
считает все записи map, в том числе запись со значением `false`; какие ключи
лежат в map, по этому числу не видно. Обычное чтение возвращает хранимое
`false` — то же значение, что у отсутствующего ключа, поэтому по нему Олега
в списке нет. Чтобы такого расхождения не было, в множество записывают
только `true`, а убирают элемент через `delete`.

## Вопрос 3

Предскажите четыре напечатанных значения: `count["да"]`, `count["нет"]`,
`count["может"]` и `len(count)`. Объясните, почему после `delete` и `++`
значение у `да` именно такое.

```go
@quiz _quiz/03-count
```

Возможные ответы:

- А. 4, 2, 0 и 2: map помнит удалённое число, и `++` продолжает счёт с
  прежнего значения.
- Б. 1, 2, 0 и 2: после `delete` чтение даёт 0, поэтому счёт начинается
  заново.
- В. 1, 2, 0 и 3: чтение `count["может"]` добавило в map третью запись.

**Ответ: Б.** Цикл насчитал три `да` и два `нет`. `delete` убрал запись
`да` целиком, и `count["да"]++` прочитал 0 и записал 1. Чтение
`count["может"]` вернуло нулевое значение и записи не добавило, поэтому
записей две.

## Вопрос 4

Пройдите оба цикла: для каждого слова назовите ключ `len(w)` и что
происходит с группой. Затем предскажите содержимое `byLen[4]` и `byLen[6]`
и длину `lost[4]`. Почему во втором цикле группы теряются, хотя результат
`append` присвоен?

```go
@quiz _quiz/04-group
```

Возможные ответы:

- А. `[ум ёж]`, `[лес дом]` и длина `lost[4]`, равная 2: присваивание
  переменной `group` меняет и группу в map.
- Б. `[ёж]`, `[дом]` и длина `lost[4]`, равная 0: каждое присваивание в map
  заменяет группу последним словом.
- В. `[ум ёж]`, `[лес дом]` и длина `lost[4]`, равная 0: во втором цикле
  результат `append` остался только в `group`.

**Ответ: В.** `ум` и `ёж` занимают по 4 байта, `лес` и `дом` — по 6. Для
первого слова каждой длины чтение `byLen[n]` вернуло nil-slice, `append`
сделал из него группу из одного слова, а присваивание положило её в map;
второе слово той же длины добавилось в конец. Во втором цикле результат
`append` записан в переменную `group`, а не в `lost[len(w)]`, поэтому в
`lost` групп нет.

## Вопрос 5

Какие строки напечатает программа, и где она остановится? Затем предложите
исправление для записи в `stock["сыр"]` и объясните, почему при следующих
записях в тот же товар `make` уже не нужен.

```go
@quiz _quiz/05-nested
```

Возможные ответы:

- А. Строки 1 и 2, затем паника на `++` для сыра: чтение через
  отсутствующую внутреннюю map безопасно, а запись в неё — нет.
- Б. Только строка 1, затем паника на строке 2: чтение из отсутствующей
  внутренней map тоже останавливает программу.
- В. Все три строки, в третьей число 1: `++` сам создаёт внутреннюю map,

**Ответ: А.** `stock["сыр"]` вернул `nil`; чтение из nil-map даёт 0, а
запись вызывает панику `assignment to entry in nil map`. Исправление:

## Вопрос 6

Для каждой задачи выберите форму map и объясните выбор через вопрос, на

Возможные ответы:

- А. (а) `map[string]bool` с `true` для написавших; (б) `map[int]int` с
  числом жильцов в квартире.
- Б. (а) `map[string]bool` с `true` для написавших; (б) `map[int][]string`
