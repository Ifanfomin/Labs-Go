# Теория

# Массивы

Метеостанция измеряет температуру три раза в день: утром, днём и вечером. Три
числа можно держать в трёх переменных — `morning`, `noon` и `evening`. Тогда
каждое действие пишется трижды: сумма складывает три имени, функция получает
три параметра, а пройти по таким переменным циклом нельзя — номеров у них нет.

Массив собирает эти числа в одно значение. У значения одно имя, числа внутри
пронумерованы, а их количество задано заранее и не меняется. К концу урока вы
сможете:

- прочитать тип вроде `[3]int` и назвать элементы массива сразу после
  объявления и после литерала;
- выбрать допустимый номер элемента и отличить отказ сборки от остановки
  программы во время работы;
- обойти массив циклом, в том числе массив без элементов;
- предсказать, что станет с исходным массивом и с его копией после
  присваивания, вызова функции и возврата результата;
- сравнить два массива и объяснить, почему массивы разной длины не
  сравниваются;
- прочитать массив в выводе программы и решить, подходит ли массив для данных
  задачи.

Код примеров можно изменить и запустить снова.

## Три числа в одном значении

Запись `[3]int` — тип массива. Число в квадратных скобках — длина массива:
сколько в нём значений. Значения массива называются элементами. Имя типа после
скобок — тип элемента: каждый из трёх элементов `[3]int` имеет тип `int`.
Элементом бывает и другой знакомый тип: `[7]bool`, `[2]float64`,
`[4]string`. В этом уроке элементы — целые числа.

Значение типа `[3]int` — одно значение, внутри которого по порядку лежат три
целых числа. Литерал массива записывает тип, а за ним элементы в фигурных
скобках через запятую: `[3]int{12, 15, 9}`. Короткое объявление
`temps := [3]int{12, 15, 9}` создаёт переменную `temps` типа `[3]int` — так
же, как `:=` из урока 2.2 создаёт переменную по значению справа.

Встроенная функция `len` возвращает длину массива — число его элементов. Для
строки `len` считала байты (урок 2.7). Для массива она считает элементы, и
сколько знаков занимает каждый элемент на экране, значения не имеет.

Массив можно напечатать целиком. `fmt.Println` выводит его одной строкой:
открывающая квадратная скобка, элементы по порядку через пробел, закрывающая
квадратная скобка. Типа, фигурных скобок и запятых в этой строке нет. Такая
строка — вид вывода, а не запись на Go: литерал в коде по-прежнему пишется с
типом, фигурными скобками и запятыми. Тип значения покажет `%T` из урока 2.1.

Прежде чем смотреть вывод, предскажите три строки: как напечатается массив,
сколько элементов насчитает `len` и что покажет `%T`.

```go

### Example: `01-temps`

Источник: `examples/01-temps/`

```go

import "fmt"

	temps := [3]int{12, 15, 9} // утро, день, вечер

```

из этого следует, разобрано в разделе «Длина — часть типа».

## Номер элемента

Элемент выбирают по номеру: `temps[0]` — первый элемент, `temps[1]` — второй,
`temps[2]` — третий. Номер элемента называется индексом, и счёт индексов
начинается с нуля. Поэтому у массива длины 3 индексы 0, 1 и 2, а последний
индекс на единицу меньше длины: `len(temps)-1`.

Выражение `temps[i]` ведёт себя как переменная типа элемента. Его можно
прочитать, а можно записать в него значение через `=` или `+=`. Запись меняет
только этот элемент, остальные остаются прежними. Индексом служит целая
константа или значение целого типа, например переменная `i`.

Дневной термометр ошибся на градус: вместо 15 нужно 14. Прежде чем смотреть
вывод, предскажите три строки: утреннее значение, вечернее значение и массив
после правки.

```go

### Example: `02-index`

Источник: `examples/02-index/`

```go
// Чтение и запись элемента по индексу.
package main

import "fmt"

func main() {
	temps := [3]int{12, 15, 9}
	fmt.Println("утро:", temps[0])
	fmt.Println("вечер:", temps[2])
	temps[1] = 14 // дневной термометр ошибся на градус
	fmt.Println("после правки:", temps)

```
```

Запись `temps[1] = 14` заменила только второй элемент. Утреннее и вечернее
значения остались на своих местах, и массив по-прежнему один — `temps`.

## Обход всех элементов

Три элемента можно сложить и без цикла: `temps[0] + temps[1] + temps[2]`. Но
индексом может быть и переменная. Тогда один цикл проходит по всем элементам:
на каждом проходе переменная принимает следующий индекс. Циклу нужны индексы
от 0 до `len(temps)-1`, и оба знакомых заголовка дают ровно этот ряд:

- трёхчастный цикл урока 3.5 `for i := 0; i < len(temps); i++` начинает с
  нуля и останавливается, когда `i` доходит до длины;
- цикл урока 3.7 `for i := range len(temps)` выдаёт числа от 0 до длины минус
  один.

В обоих циклах `i` — индекс, целое число, а не сам элемент. Элемент тело
берёт выражением `temps[i]`. Перебор, который выдаёт сами элементы, разбирает
урок 4.10.

Условие `i < len(temps)` берёт длину у самого массива, а не у числа 3,
вписанного в условие вручную. Если длину массива в объявлении поменять, цикл
останется верным без правки.

Прежде чем смотреть вывод, выпишите значение `i` и элемент на каждом проходе
первого цикла, а затем обе суммы. Массив уже исправлен: 12, 14 и 9.

```go

### Example: `03-sum`

Источник: `examples/03-sum/`

```go
// Сумма элементов: индексы от 0 до len-1 в двух формах цикла.
package main

import "fmt"

func main() {
	temps := [3]int{12, 14, 9}

	sum := 0
	for i := 0; i < len(temps); i++ {
		fmt.Println("i =", i, "элемент", temps[i])
		sum += temps[i]
	}
	fmt.Println("сумма:", sum)

	total := 0
	for i := range len(temps) {
		total += temps[i]
	}
	fmt.Println("сумма через range:", total)
}

```
```

Оба цикла сделали по три прохода с `i`, равным 0, 1 и 2, и получили одну и ту
же сумму 35. Прохода с `i`, равным трём, не было: условие `3 < 3` ложно, а ряд
`range 3` заканчивается на двойке.

## Индекс за границей

Индекс допустим, когда выполнено условие `0 <= i && i < len(temps)`. Для
массива длины 3 это 0, 1 и 2. Индекс 3, равный длине, уже указывает за конец
массива, а отрицательный индекс недопустим всегда. Что произойдёт при
недопустимом индексе, зависит от того, когда индекс становится известен.

Индекс-константу компилятор знает заранее и сверяет с длиной из типа. Прежде
чем читать дальше, решите, соберётся ли программа, которая печатает
`temps[3]`.

```go
@broken index-three
```

Не соберётся: `invalid argument: index 3 out of bounds [0:3]`. Запись `[0:3]`
в сообщении значит «индексы от 0 до 3, не включая 3». Отрицательная константа
в индексе тоже останавливает сборку.

У переменной-массива `len` — тоже константа: длина записана в самом типе
`[3]int`. Поэтому `temps[len(temps)]` компилятор отвергнет тем же сообщением,
что и `temps[3]`, а `temps[len(temps)-1]` — это `temps[2]`, последний элемент.

Значение индекса-переменной появляется только во время работы. Такую
программу компилятор собирает, а границу проверяет сама программа при каждом
обращении. Индекс за границей останавливает её паникой — той же остановкой во
время работы, что и деление целого числа на переменную с нулём в уроке 2.10.
Отрицательное значение индекса-переменной тоже вызывает панику.

Частая причина такой паники — условие `i <= len(temps)` вместо
`i < len(temps)`: цикл делает лишний проход с `i`, равным длине. Прежде чем
смотреть вывод, решите, сколько строк программа напечатает до остановки и
дойдёт ли она до итоговой строки.

```go

### Example: `04-off-by-one`

Источник: `examples/04-off-by-one/`

```go
// Условие <= вместо < даёт лишний проход с индексом, равным длине.
package main

import "fmt"

func main() {
	temps := [3]int{12, 14, 9}
	sum := 0
	for i := 0; i <= len(temps); i++ {
		sum += temps[i]
		fmt.Println("после i =", i, "сумма", sum)
	}
	fmt.Println("итог:", sum)
}

```
```

Три прохода отработали и напечатали суммы. На четвёртом `i` стало равно 3, и
обращение `temps[3]` остановило программу, поэтому итоговая строка не
напечаталась. Сообщение паники называет индекс и длину массива. Точный текст
сообщения выбирает среда исполнения Go; язык обещает саму панику, а не её
слова.

Правильная программа не обращается за границу, и такая паника ей не грозит:
цикл идёт с условием `i < len(temps)`, а индекс, пришедший извне, сначала
проверяют через `if` тем же условием `0 <= i && i < len(temps)`. Как
перехватить панику, разбирает урок 5.17.

## Присваивание копирует весь массив

Переменная-массив хранит свои элементы сама. Присваивание `draft := temps`
создаёт новую переменную и копирует в неё все три элемента. После этого в
программе два массива с одинаковыми элементами, и они независимы: запись в
элемент одного не меняет другой.

Прежде чем смотреть вывод, предскажите четыре строки. Сначала программа
меняет копию `draft`, затем делает ещё одну копию `saved` и только после этого
меняет исходный `temps`.

```go

### Example: `05-copy`

Источник: `examples/05-copy/`

```go
// Присваивание копирует все элементы массива.
package main

import "fmt"

func main() {
	temps := [3]int{12, 14, 9}

	draft := temps
	draft[0] = 99
	fmt.Println("temps:", temps)
	fmt.Println("draft:", draft)

	saved := temps
	temps[2] = 0
	fmt.Println("temps:", temps)
	fmt.Println("saved:", saved)
}

```
```

Таблица показывает все три массива после каждой инструкции:

| После инструкции | `temps` | `draft` | `saved` |
|---|---|---|---|
| `draft := temps` | 12, 14, 9 | 12, 14, 9 | ещё нет |
| `draft[0] = 99` | 12, 14, 9 | 99, 14, 9 | ещё нет |
| `saved := temps` | 12, 14, 9 | 99, 14, 9 | 12, 14, 9 |
| `temps[2] = 0` | 12, 14, 0 | 99, 14, 9 | 12, 14, 9 |

Каждая запись меняет один массив. Копия получает элементы в момент
присваивания, и после этого связи между массивами нет ни в одну сторону.

## Массив в параметре и в результате

Тип массива записывают в сигнатуре функции там же, где в уроке 1.7 стоял
`int`: у параметров и у результата. В сигнатуре
`func withMorning(p [3]int, v int) [3]int` параметр `p` — массив из
трёх `int`, и результат функции — тоже массив `[3]int`. Такой функции
передают массив ровно этого типа, и возвращает она массив ровно этого типа.

Передача аргумента работает как присваивание: параметр `p` получает копию
массива, который передал вызывающий код. Функция может менять элементы своей
копии, а переменная вызывающего кода от этого не меняется. Массив-результат
функция возвращает одним значением, со всеми тремя элементами, и вызывающий
код сохраняет его в свою переменную.

Функция `warmUp` прибавляет `delta` к каждому элементу своего параметра и
печатает его. Функция `withMorning` записывает новое утреннее значение в свой
параметр и возвращает его. Прежде чем смотреть вывод, предскажите четыре
строки: что `warmUp` напечатает внутри себя, что лежит в `temps` после её
вызова, что лежит в `temps` после `withMorning` и что попало в `fixed`.

```go

### Example: `06-param`

Источник: `examples/06-param/`

```go
// Параметр-массив получает копию, результат-массив возвращается целиком.
package main

import "fmt"

// warmUp прибавляет delta к каждому элементу своей копии и печатает её.
func warmUp(p [3]int, delta int) {
	for i := range len(p) {
		p[i] += delta
	}
	fmt.Println("внутри warmUp:", p)
}

// withMorning записывает v в утренний элемент копии и возвращает копию.
func withMorning(p [3]int, v int) [3]int {
	p[0] = v
	return p
}

func main() {
	temps := [3]int{12, 14, 9}

	warmUp(temps, 1)
	fmt.Println("после warmUp:", temps)

	fixed := withMorning(temps, 11)
	fmt.Println("после withMorning:", temps)
	fmt.Println("fixed:", fixed)
}

```
```

`warmUp` изменила свою копию, а `temps` осталась прежней. `withMorning` тоже
меняла только свою копию, но вернула её, и изменённый массив попал в `fixed`.
Если функция должна отдать изменённый массив, она его возвращает, а
вызывающий код сохраняет результат. Как дать функции доступ к самой
переменной вызывающего кода, разбирают уроки 6.6 и 6.7 об указателях.

## Нулевые значения и литералы

Все элементы массива существуют с момента объявления. Объявление
`var fresh [3]int` без инициализатора даёт три элемента с нулевым значением
`int`, то есть три нуля (урок 2.1).

Литерал может перечислить меньше элементов, чем длина. `[3]int{4, 7}` задаёт
первые два элемента, а третий получает нулевое значение. Больше элементов,
чем длина, литерал задать не может: сборка остановится.

Вместо числа длины в литерале можно поставить многоточие: `[...]int{4, 7}`.
Тогда длину считает компилятор — по числу элементов литерала. Получается
обычный массив фиксированной длины, тип `[2]int`: многоточие только избавило
от подсчёта. Квадратные скобки без числа и без многоточия, `[]int`, — другой
тип, slice; о нём уроки 4.2 и 4.3.

Прежде чем смотреть вывод, для каждой из трёх переменных предскажите элементы
и длину, а для двух последних — ещё и тип.

```go

### Example: `07-zero-literals`

Источник: `examples/07-zero-literals/`

// Элементы массива после var, неполного литерала и литерала с многоточием.

func main() {
	var fresh [3]int
	fmt.Println("var:", fresh, len(fresh))

	partial := [3]int{4, 7}
	fmt.Println("два из трёх:", partial, len(partial))

	counted := [...]int{4, 7}
	fmt.Println("с многоточием:", counted, len(counted))

	fmt.Printf("типы: %T и %T\n", partial, counted)
}

```
```

Третий элемент `partial` — ноль: литерал его не задал. У `counted` длина 2, а
не 3: компилятор посчитал элементы литерала. Значит, `partial` и `counted` —
массивы разных типов, хотя их литералы начинаются одинаково.

## Длина — часть типа

`%T` печатает тип вместе с длиной, потому что длина входит в тип. `[3]int` и
`[4]int` — два разных типа, так же как `int` и `string`. Из этого следуют две
вещи.

Первое: длину массива нельзя поменять. В переменной типа `[3]int` всегда
ровно три элемента, и массив из четырёх в неё не положить. Прежде чем читать
дальше, решите, соберётся ли программа, которая присваивает переменной типа
`[3]int` значение типа `[4]int`.

```go
@broken size-mismatch
```

Не соберётся:
`cannot use b (variable of type [4]int) as [3]int value in assignment`.
Сообщение называет оба типа: значение `[4]int` нельзя использовать там, где
нужен `[3]int`. Так же остановится и вызов функции с параметром `[3]int`,
если передать ей `[4]int`: передача аргумента — то же присваивание.

Второе: длина известна при сборке. Поэтому длиной массива служит только
неотрицательная целая константа, представимая значением типа `int`: число,
именованная константа или константное выражение (урок 2.11). Переменная
константой не становится, даже когда её значение видно строкой выше. Прежде
чем читать дальше, решите, соберётся ли объявление `var readings [n]int`
после `n := 3`.

```go
@broken variable-length
```

Не соберётся: `invalid array length n`. Рядом компилятор сообщит и о том, что
переменная `n` объявлена, но не используется: в длине массива переменную
использовать нельзя, а больше `n` в программе нигде не встречается.
Исправление — константа вместо переменной, и константное выражение тоже
годится. Прежде чем смотреть вывод, посчитайте длину массива
`[perDay * 2]int` и назовите его элементы.

```go

### Example: `08-const-length`

Источник: `examples/08-const-length/`

```go
// Длина массива из константного выражения.
package main

import "fmt"

const perDay = 3 // замеров в день

func main() {
	var twoDays [perDay * 2]int
	fmt.Println("длина:", len(twoDays))
	fmt.Println("twoDays:", twoDays)
}

```
```

Длина — 6: компилятор вычислил `perDay * 2` при сборке. Элементы — шесть
нулей, как у любого массива, объявленного без литерала.

## Сравнение массивов

Два массива одного типа сравнивают операторами `==` и `!=` из урока 2.6.
Массивы равны, когда равны их элементы на одинаковых позициях: первый с
первым, второй со вторым и так далее. Важны и значения, и порядок. Литерал с
недостающими элементами сравнивается вместе с нулями, которые получили
незаданные элементы.

Прежде чем смотреть вывод, предскажите четыре значения `true` или `false`.

```go

### Example: `09-equal`

Источник: `examples/09-equal/`

```go
// == и != сравнивают массивы одного типа поэлементно.
package main

import "fmt"

func main() {
	monday := [3]int{12, 14, 9}
	tuesday := [...]int{12, 14, 9}
	reversed := [3]int{9, 14, 12}
	short := [3]int{12, 14}
	full := [3]int{12, 14, 0}

	fmt.Println("== с tuesday:", monday == tuesday)
	fmt.Println("== с reversed:", monday == reversed)
	fmt.Println("!= с reversed:", monday != reversed)
	fmt.Println("short == full:", short == full)
}

```
```

`tuesday` записан через многоточие, но получил тип `[3]int` и те же элементы,
поэтому он равен `monday`. У `reversed` те же числа в другом порядке, и
поэлементное сравнение находит различие уже на первой позиции. `short` равен
`full`: незаданный третий элемент `short` — ноль.

Порядка у массивов нет: операторы `<`, `<=`, `>` и `>=` к ним не применяются.

```go
@broken order
```

Сборка остановится с сообщением
`invalid operation: a < b (operator < not defined on array)`.

Массивы разной длины — разные типы, поэтому их нельзя сравнить даже через
`==`: сборка остановится, как и при присваивании `[4]int` переменной `[3]int`.
Сравнивают только значения одного типа. Если данные разной длины всё же нужно
сравнить, сначала решают, сколько элементов важно, и держат оба значения в
массивах этой длины.

Сравнение через `==` работает для массивов с элементами знакомых типов:
чисел, `bool` и строк. Сравнение массивов с элементами других видов
разбирают модули 6, 8 и 10.

## Массив нулевой длины

Длина 0 тоже допустима: `var none [0]int`. В таком массиве нет ни одного
элемента и, значит, ни одного допустимого индекса. Особого кода для обхода он
не требует. Трёхчастный цикл проверяет `0 < 0`, получает `false` и не делает
ни одного прохода. `range len(none)` выдаёт пустой ряд, как любая нулевая
граница в уроке 3.7. Обращение `none[i]` в теле цикла собирается, потому что
индекс — переменная, и просто ни разу не выполняется.

Прежде чем смотреть вывод, предскажите обе строки: как напечатается массив
без элементов и какой будет сумма после двух циклов.

```go

### Example: `10-zero-length`

Источник: `examples/10-zero-length/`

```go
// Массив нулевой длины: ни одного индекса и ни одного прохода.
package main

import "fmt"

func main() {
	var none [0]int
	fmt.Println("элементов:", len(none), none)

	sum := 0
	for i := 0; i < len(none); i++ {
		sum += none[i]
	}
	for i := range len(none) {
		sum += none[i]
	}
	fmt.Println("сумма:", sum)
}

```
```

Массив без элементов печатается пустыми квадратными скобками. Сумма осталась
нулём, и паники нет: тело с `none[i]` не выполнилось ни разу.

## Когда выбирать массив

Массив подходит, когда число элементов — часть смысла данных и известно уже
при написании программы: три замера в день, семь дней недели, три
составляющие цвета. Тогда тип `[3]int` сам записывает это число, и компилятор
не даст передать четыре замера туда, где ждут три.

Если число элементов меняется во время работы, массив не подходит: список
покупок растёт, а число строк в файле заранее неизвестно. Длину массива не
изменить, а массив другой длины — значение другого типа. Для таких данных в Go
есть slice; его разбор начинается в уроке 4.2.

На выбор влияет и то, как массив передаётся: у каждой переменной-массива
свои элементы. Присваивание и передача в функцию копируют все элементы,
поэтому функция работает со своей копией, а не с массивом вызывающего кода.

| Данные | Число элементов | Подходит |
|---|---|---|
| Замеры утром, днём и вечером | всегда три | `[3]int` |
| Расход за каждый день недели | всегда семь | `[7]int` |
| Покупки, добавленные за день | меняется | slice, урок 4.2 |

## Копия в параметре

<!-- review:copy-in-parameter -->

Вопросы из постановки: какие индексы обходит цикл `Sum3`, чей массив получает
`Replace3` и что останется у вызывающего кода после вызова. Образец ответа
ниже.

В `Sum3` цикл с условием `i < len(a)` получает `i`, равное 0, 1 и 2, — ровно
допустимые индексы массива длины 3. С условием `i <= len(a)` появится
четвёртый проход с `i`, равным 3, и обращение `a[3]` остановит программу
паникой. Решение целиком: до цикла `sum := 0`, в теле `sum += a[i]`, после
цикла `return sum`.

`Replace3` получает в параметре `a` копию массива вызывающего кода: передача
аргумента работает как присваивание. В копии уже стоят все три элемента,
поэтому второй массив не нужен. Тело: `a[i] = value`, затем `return a`.
Запись попадает в копию, и массив вызывающего кода остаётся прежним.

Для `day` с элементами −2, 8 и 3 вызов `fixed := Replace3(day, 2, -2)`
записывает −2 в последний элемент копии. В `fixed` окажутся −2, 8 и −2, а в
`day` останутся −2, 8 и 3.

## Лишний проход с индексом 3

<!-- review:sum-one-based -->

Решение с заголовком `for i := 1; i <= len(a); i++` считает индексы с

нуля и остановиться до длины: `for i := 0; i < len(a); i++`. Индексы массива

## Потерянный последний элемент

<!-- review:sum-skip-last -->

Перед разбором сравните результат `Sum3` с условием `i < len(a)-1` с верной
суммой для массивов `[3]int{0, 0, 9}`, `[3]int{0, 0, -9}` и
`[3]int{7, -3, 0}`. Для каждого назовите пропущенный вклад.

Условие `i < len(a)-1` останавливает цикл на один проход раньше: при длине 3
тело выполнится только для индексов 0 и 1, и последний элемент в сумму не
попадёт. Паники здесь нет: сумма теряет вклад последнего элемента. Если он
положительный, результат меньше верного; если отрицательный — больше; если
нулевой — совпадает с верной суммой. Для 0, 0 и −9 получится 0 вместо −9; для
7, −3 и 0 обе суммы равны 4. Совпадение при нуле скрывает пропущенный проход:
цикл всё равно не посетил последний индекс.

Ловит это `TestSum3`: для элементов 1, 2 и 3 решение вернёт 3 вместо 6, а для
0, 0 и 9 — ноль вместо 9. Последний индекс равен `len(a)-1`, и условие
`i < len(a)` уже включает его в обход.

результаты. На этих входах решение принято — и это всё, что тесты установили.
Текст решения тест не читает: цикл по индексам и сумма
`a[0] + a[1] + a[2]` дают одинаковые числа. Поэтому форму цикла проверяете вы
сами, читая свой код.

Проверка массива вызывающего кода после `Replace3` не провалится ни у одного
собирающегося решения: параметр — копия, и запись в него до вызывающего кода
не доходит. Эта проверка показывает правило копирования в работе. Нужен ли
`Replace3` второй массив, тест не различает: решение с лишней копией тоже
будет принято.
Ответ на этот вопрос — в разделе «Копия в параметре».

Что напечатает программа?

- A. Длины 4 и 2; `a` печатается как `[5 1 0 0]`; тип `b` — `[2]int`.
- B. Длины 2 и 2; `a` печатается как `[5 1]`; тип `b` — `[2]int`.
- C. Длины 4 и 2; `a` печатается как `[5 1 0 0]`; тип `b` — `[]int`.
- D. Программа не соберётся: литерал `[4]int` обязан задать все четыре

Прежде чем смотреть ответ, назовите тип и все элементы каждой переменной.

**Правильный ответ: A.**

`[4]int{5, 1}` задаёт два элемента из четырёх, остальные два — нули, и длина
остаётся 4. `[...]int{5, 1}` получает длину по числу элементов литерала: 2,
тип `[2]int`. Вариант B теряет нулевые элементы, которые массив хранит с
момента объявления. Вариант C принимает многоточие за квадратные скобки без

## Вопрос 2

Для каждого обращения ниже написана своя программа. Она объявляет
`temps := [3]int{12, 14, 9}`, а если обращению нужна переменная, то и её:
`i := 3` или `j := -1`. Затем программа печатает обращение через
`fmt.Println`. Обращения: `temps[0]`, `temps[len(temps)-1]`,
`temps[len(temps)]`, `temps[i]`, `temps[j]`. Что произойдёт в каждом случае?

Варианты ответа:

- A. 12 и 9; три последних обращения соберутся и вызовут панику во время
  работы.
- B. 12 и 9; три последних обращения не соберутся: длину массива компилятор
  знает.
- C. Паника на `temps[0]`, а `temps[len(temps)]` даст 9: индексы считаются с
  единицы.
- D. 12 и 9; `temps[len(temps)]` не соберётся; `temps[i]` и `temps[j]` вызовут
  панику во время работы.

Прежде чем смотреть ответ, для каждого индекса скажите, константа он или
переменная и лежит ли он от 0 до len−1.

**Правильный ответ: D.**

`temps[0]` — первый элемент, 12; `len(temps)-1` — константа 2, последний
элемент 9. `len` у переменной-массива — константа 3, индекс за границей, и
сборка останавливается. `i` и `j` — переменные: программа собирается, а
обращение за границу во время работы вызывает панику. Вариант A забывает, что
`len` массива — константа. Вариант B переносит проверку при сборке на
индексы-переменные. Вариант C считает индексы с единицы.

## Вопрос 4

```go

```

Какие массивы программа напечатает для `a`, `b` и `c`?

Варианты ответа:

- A. `a` — `[100 12 3]`, `b` — `[1 2 3]`, `c` — `[1 12 3]`.
- B. `a` — `[100 2 3]`, `b` — `[100 2 3]`, `c` — `[1 12 3]`.

- D. `a` — `[100 2 3]`, `b` — `[1 2 3]`, `c` — `[100 12 3]`.

Прежде чем смотреть ответ, отметьте, в какой момент каждая переменная
получает свою копию и какие записи в неё попадают.

**Правильный ответ: C.**

`b := a` скопировал 1, 2 и 3 до правки. `bump` получила копию `a`, прибавила

## Вопрос 5

```go
@quiz _broken/compare-sizes
```

Программа должна сравнить три замера с набором из четырёх. Что произойдёт и
как это исправить?

Варианты ответа:

- A. Напечатает `false`: массивы разной длины просто не равны друг другу.
- B. Напечатает `true`: первые три элемента совпадают, а лишний элемент —
  ноль.
- C. Не соберётся: `[3]int` и `[4]int` — разные типы; оба значения нужно
  держать в массивах одной длины.
- D. Не соберётся: массивы не сравнивают через `==`; элементы нужно сравнить
  в цикле.

Прежде чем смотреть ответ, назовите тип `a` и тип `b` и предложите свою
правку.

**Правильный ответ: C.**

Компилятор отвечает
`invalid operation: a == b (mismatched types [3]int and [4]int)`: длина
входит в тип, и значения разных типов не сравниваются. Сначала решают,
сколько замеров важно. Если три, пишут `b := [3]int{1, 2, 3}`, и сравнение
собирается. Варианты A и B ждут результата от программы, которая не
собралась. Вариант D неверен: массивы одного типа сравниваются через `==`.

## Вопрос 6

Программа печатает массив `scores` с элементами типа `int` через
`fmt.Println(scores)` и выводит строку `[10 200 3]`. Что из этого следует?

Варианты ответа:

- A. В `scores` три элемента; литерал в коде пишется иначе, например
  `[3]int{10, 200, 3}`.
- B. В `scores` три элемента, и в коде он записан той же строкой, что в
  выводе.
- C. В `scores` десять элементов: `len` считает знаки строки вывода, а их
  десять.
- D. В `scores` три элемента, а запись `scores[3] = 7` добавит к ним
  четвёртый.

Прежде чем смотреть ответ, разделите строку вывода на элементы и на
оформление, которое добавил `fmt.Println`.

**Правильный ответ: A.**

`fmt.Println` выводит элементы по порядку в квадратных скобках через пробел.
Элементы `scores` — целые числа типа `int`, пробелов внутри них не бывает,
поэтому элементов три: 10, 200 и 3. Это вид вывода, а не код: литерал
пишется с типом, фигурными скобками и запятыми. Вариант B принимает вывод
за исходный текст. Вариант C считает знаки, а `len` массива считает
элементы. Вариант D забывает, что длина входит в тип: у `scores` тип
`[3]int`, индекса 3 у него нет, и такая запись не соберётся.
