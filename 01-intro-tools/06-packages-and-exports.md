# Пакеты, импорты и экспортируемые имена

В уроке 1.3 вы написали строку `import "fmt"` и вызов `fmt.Println`, пока без
объяснения. Теперь задача немного больше: программа должна напечатать слово,
переведённое в верхний регистр, и строку, у которой убраны пробелы по краям.
Готовые функции для обеих операций есть в пакете `strings`. Чтобы ими
воспользоваться, нужно понять три вещи: как подключить к файлу чужой пакет, как
вызвать его функцию и какие имена чужого пакета вам доступны. Последний раздел,
«Импорт с пустым именем», разбирает особую форму импорта: пакет подключают, но
ни одну его функцию не вызывают.

## Пакет и строка импорта

**Пакет** — группа файлов `.go` из одного каталога, которую компилятор
переводит в машинный код как одно целое. В уроке 1.3 пакет `main` состоял из
одного файла `main.go`. Пакет — ещё и граница видимости: код внутри пакета
пользуется всеми его именами, а из другого пакета доступны не все. Какие
именно, объясняет раздел «Имя с заглавной буквы — правило языка».

**Стандартная библиотека** — набор пакетов, который приходит вместе с
установленным Go. `fmt` и `strings` — пакеты стандартной библиотеки. Путь
импорта такого пакета не начинается с пути модуля, в отличие от путей пакетов
вашего модуля из урока 1.4: он короткий, просто `"fmt"` или `"strings"`.

Ниже — программа, которую вы соберёте в упражнении. Под кодом показан её вывод.

```go

### Example: `01-grouped-import`

Источник: `examples/01-grouped-import/`

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	fmt.Println(strings.ToUpper("gopher"))
	fmt.Println(strings.TrimSpace("  первый пакет  "))
}

```
```

Программа состоит из трёх частей.

**`package main`** — объявление пакета. Файл относится к пакету `main`, из
которого получается запускаемая программа (урок 1.3).

**Строка импорта в круглых скобках** — одно объявление импорта, в котором
перечислены два пути, каждый на своей строке: `"fmt"` и `"strings"`. Оно
подключает к файлу два пакета. После импорта в файле можно пользоваться двумя
новыми именами — `fmt` и `strings`. Это имена самих пакетов: имя пакета задаёт
строка `package` в его собственных файлах, а у `fmt` и `strings` оно совпадает с
путём импорта. Имя пакета и путь модуля — разные вещи, как вы видели в уроке
1.4.

**Тело `main`** — два вызова печати. В скобках первого `fmt.Println` стоит ещё
один вызов: `strings.ToUpper("gopher")`. Функция `ToUpper` из пакета `strings`
получает строку `"gopher"` и выдаёт то же слово, в котором буквы переведены в
верхний регистр. `fmt.Println` печатает то, что выдал вызов в её скобках,
поэтому первая строка вывода — слово из заглавных букв. Второй вызов устроен так
же. Функция `strings.TrimSpace` получает строку, в начале и в конце которой
стоит по два пробела, и выдаёт эту строку без пробелов по краям; пробел между
двумя словами остаётся. Как функция выдаёт результат, разбирает урок 1.7. Здесь
достаточно знать, что даёт каждая из двух функций.

Запись `strings.ToUpper` — **квалифицированный вызов**: перед именем функции
через точку стоит имя пакета. Часть `strings.` называют квалификатором. Она
говорит компилятору, в каком пакете искать функцию `ToUpper`. `fmt.Println` из
урока 1.3 — такой же квалифицированный вызов.

Строка `import "fmt"` из урока 1.3 делала то же самое: подключала пакет `fmt` и
давала файлу имя `fmt`, через которое вызывается `Println`.

## Одиночная и скобочная формы

В уроке 1.3 импорт был одиночным: слово `import` и один путь. Два пакета можно
подключить и двумя такими строками подряд. Ниже — та же программа, в которой
скобочная строка импорта заменена двумя одиночными строками. Тело `main` не
изменилось.

```go

### Example: `02-two-single-imports`

Источник: `examples/02-two-single-imports/`

```go
package main

import "fmt"
import "strings"

func main() {
	fmt.Println(strings.ToUpper("gopher"))
	fmt.Println(strings.TrimSpace("  первый пакет  "))
}

```
```

Программа собирается и печатает тот же вывод. Одиночная и скобочная формы —
две записи одного импорта с одинаковым результатом: каждая подключает к файлу
пакеты по перечисленным путям и даёт файлу их имена. Скобочная форма не
обязательна при двух пакетах, а одиночная не ограничена одним пакетом. В
официальном введении в Go скобочную форму называют хорошим стилем, и в коде на
Go она встречается чаще. Это соглашение о стиле, а не требование компилятора.

Сравните две программы ещё раз. В первой одно объявление импорта с двумя
путями, во второй — два объявления, по одному пути в каждом. Имена в обоих
файлах появились одни и те же: `fmt` и `strings`.

## Имя с заглавной буквы — правило языка

В пакете `strings` объявлено много имён. Одни предназначены для других пакетов,
другие нужны только самому `strings` для его внутренней работы. Какое имя
доступно снаружи, решает его первая буква:

- имя, которое начинается с заглавной буквы, **экспортируется**: к нему можно
  обратиться из другого пакета;
- имя, которое начинается с любого другого символа, например со строчной
  буквы, не экспортируется: им пользуется только код внутри своего пакета.

Правило относится к именам, объявленным в пакете вне функций, — например, к
функциям `ToUpper` и `Println`. Правило касается и других видов имён, но в
программах ниже оно нужно только для функций пакета.

`ToUpper`, `TrimSpace` и `Println` начинаются с заглавной буквы, поэтому ваш
пакет `main` может их вызвать. А ваша функция `main` начинается со строчной
буквы, и из другого пакета её не вызвать. Своё экспортируемое имя впервые
встретится в уроке 1.7.

Первая буква имени — правило языка, а не договорённость о стиле: её нельзя
выбрать по вкусу при вызове. Обращение к неэкспортируемому имени другого пакета —
ошибка компиляции, и программа не соберётся.

В примере ниже первый вызов записан со строчной буквы — `strings.toUpper`.
Второй вызов остался верным: так пакет `strings` в файле по-прежнему
используется, и сборка сообщает ровно об одной ошибке. Прежде чем читать
сообщение под кодом, предположите, соберётся ли программа.

```go
@broken lowercase-name
```

Сборка печатает `./main.go:9:22: undefined: strings.toUpper (but have ToUpper)`.
Начало строки называет место ошибки: файл `main.go`, строка 9, позиция 22 —
там, где после `strings.` начинается `toUpper`. Слово `undefined` значит «не
определено»: компилятор не нашёл в пакете `strings` доступного имени `toUpper`.
Слова в скобках — подсказка: доступное имя `ToUpper` в пакете есть. Исправление —
написать имя так, как его экспортирует пакет: `strings.ToUpper`.

В этом примере имени `toUpper` в пакете `strings` нет вовсе. Но и имя со
строчной буквы, которое в чужом пакете действительно объявлено, из вашего пакета
недоступно. Для разных таких имён текущий компилятор печатает разный текст
сообщения, поэтому по сообщению нельзя надёжно понять, есть ли в пакете такое
строчное имя. Исправление от этого не
меняется: вызывать можно только имя с заглавной буквы. Точная формулировка
сообщений — вывод текущей версии компилятора, язык её не обещает. Одно и то же
сообщение печатают и `go build`, и `go run .`.

## Вызов только с именем пакета

Обычный импорт — строка `import "strings"` или путь `"strings"` в скобках —
добавляет в файл одно имя: имя пакета. Имена, объявленные внутри пакета, в ваш
файл не переносятся. `ToUpper` остаётся именем пакета `strings`, и из вашего
файла к нему обращаются только через квалификатор: `strings.ToUpper`.

У объявления импорта есть и другие формы. Одну из них, импорт с пустым именем,
разбирает следующий раздел. Правило о квалификаторе из этого раздела относится
только к обычной форме импорта.

В примере ниже первый вызов записан без квалификатора, `ToUpper("gopher")`, а
второй остался квалифицированным вызовом `strings.TrimSpace`. Прежде чем читать
сообщение, предположите, на какое имя оно укажет.

```go
@broken unqualified-call
```

Сборка печатает `./main.go:9:14: undefined: ToUpper`. Позиция 14 — начало имени
`ToUpper`. Компилятор искал это имя среди имён самого файла и пакета `main`, не
нашёл и сообщил, что оно не определено. Импорт `strings` здесь не помогает: он
дал файлу имя `strings`, а не `ToUpper`. Исправление — добавить квалификатор и
записать `strings.ToUpper`.

Оба сломанных примера дают сообщение `undefined:`, но причины у них разные.
Различает их то, что стоит после двоеточия:

- `strings.toUpper` — квалификатор на месте, а доступного имени с таким
  написанием в пакете нет. Проверьте первую букву и написание имени;
- `ToUpper` без имени пакета — компилятор искал имя в вашем файле. Добавьте
  квалификатор.

В обоих примерах второй вызов верный, поэтому сборка сообщает только об одной
ошибке. Если записать без квалификатора оба вызова, файл ни разу не обратится к пакету `strings`. Тогда
сборка сообщит о трёх ошибках: пакет `"strings"` импортирован и не используется,
не определено имя `ToUpper`, не определено имя `TrimSpace`. Исправлять в таком
случае нужно вызовы, а не импорт: после добавления квалификаторов пакет снова
используется.

## Импорт с пустым именем

Пакет, к которому файл ни разу не обращается, импортировать нельзя: сборка
откажет. Это правило из уроков 1.1 и 1.3 обычно помогает сразу увидеть лишний
импорт.

Но иногда пакет нужен программе не ради вызовов его функций. Запущенная
программа вызывает `main` не сразу: сначала она подготавливается к работе (об
этом шла речь в уроке 1.3). В эту подготовку входит **инициализация**
подключённых пакетов: каждый пакет выполняет свою подготовительную работу до
того, как начнётся обычная работа программы. Иногда программе нужна именно
инициализация пакета, а не его функции. Например, по документации Go пакет `image/png` при инициализации
регистрирует в пакете `image` формат картинок PNG. После этого средства пакета
`image` умеют читать такие картинки, хотя ни одну функцию самого `image/png`
программа не вызывает.

Для такого случая есть **импорт с пустым именем**: перед путём пакета в
объявлении импорта ставят знак `_`. Знак `_` означает, что пакет не получает в
файле имени. Отсюда три следствия:

- пакет подключён к программе и проходит инициализацию, как любой
  импортированный пакет;
- в файле нет имени, через которое можно вызвать функции пакета: ни с
  квалификатором, ни без него;
- компилятор не считает такой импорт неиспользованным.

Ниже — программа, где пакет `strings` подключён с пустым именем и ни разу не
вызван.

```go

### Example: `03-blank-import`

Источник: `examples/03-blank-import/`

```go
package main

import (
	"fmt"
	_ "strings"
)

func main() {
	fmt.Println("пакет strings подключён и не вызван")
}

```
```

Программа собирается и печатает одну строку — ту, что передана `fmt.Println`.
Видимого результата инициализации `strings` в выводе нет, и программе этот пакет
не нужен. Пример показывает только форму записи и то, что компилятор её
принимает, но не пользу такого импорта.

Теперь та же программа, в которой `_ "strings"` заменено на `"strings"`. Больше
ничего не изменилось. Предположите, соберётся ли она.

```go
@broken blank-import-removed
```

Сборка печатает `./main.go:5:2: "strings" imported and not used` — «пакет
`"strings"` импортирован и не используется». Строка 5, позиция 2 — путь
`"strings"` в объявлении импорта. Две программы различаются одним знаком `_`, и
именно он делает импорт без единого вызова законным.

Итак, импорт с пустым именем выбирают, когда пакет нужен ради его
инициализации, а не ради вызовов. Это не способ заглушить ошибку о лишнем
импорте: ненужный пакет просто убирают из импорта. И это не способ вызывать
функции пакета без квалификатора: имени для вызовов такой импорт не даёт. Как
устроена инициализация пакета, курс разберёт там, где она понадобится впервые.

## Что сдать

Программу, которая печатает ровно две строки, в этом порядке:

объявление `package main` и пустая функция `main`. Строки импорта в заготовке
нет: импорт без единого вызова не собирается, а заготовка обязана собираться.
Допишите в `main.go` две вещи:

- одну скобочную строку импорта с путями `"fmt"` и `"strings"`, каждый на своей
  строке, между строкой `package main` и строкой `func main() {`;
- тело функции `main` из двух вызовов `fmt.Println`. В скобках первого вызова
  вызовите `strings.ToUpper` со строкой `"gopher"`. В скобках второго вызовите
  `strings.TrimSpace` со строкой `"  первый пакет  "`, где в начале и в конце
  стоит по два пробела.

Имена функций пишите с заглавной буквы и с квалификатором `strings.` — так, как
в разобранной программе урока.

## Что оставить без изменений

Файл `go.mod`, объявление `package main` и имя функции `main` не меняйте.
Скрытый тест лежит в том же пакете `main` и сам вызывает вашу функцию `main`.
Из другого пакета он её вызвать не смог бы: имя `main` начинается со строчной
буквы и не экспортируется. Что сообщает проверка, если заменить имя пакета или
функции, разобрано в уроке 1.3.

## Что проверяется, а что нет

Скрытый тест вызывает вашу функцию `main`, перехватывает то, что она печатает,
и сравнивает с эталоном побайтово: значение имеют текст строк, их порядок и
перевод строки после каждой из них.

Автопроверка получает две вещи: результат сборки и байты, которые напечатала
программа. Текст решения она не читает, поэтому не различает, получены эти байты
вызовами функций `strings` или иначе. Импорт, квалификатор и заглавную букву в
программе, которая вызывает функции `strings`, проверяет не тест, а компилятор:
при ошибке в них программа не соберётся, и до сверки вывода дело не дойдёт.
Программа, которая печатает обе строки готовыми литералами без пакета `strings`,
проверку тоже пройдёт: её вывод тот же, а текст программы тест не сравнивает.
Импорт и квалифицированные вызовы в этом упражнении пишете вы сами; тест их
наличие не проверяет.

## Как работать

1. Допишите код в поле кода задачи на странице упражнения.
2. Нажмите «Проверить».
3. Прочитайте ответ проверки.
4. Исправьте код и проверьте снова.

Ниже описаны два вида ответа проверки.

Сообщение сборки с местом в файле — например, `undefined: …` или
`"…" imported and not used` — значит, что компилятор отказался собирать
программу и она не запускалась. Откройте строку, которую называет сообщение, и
прочитайте его конец:

- `undefined:` и имя с `strings.` перед ним — проверьте первую букву и
  написание имени функции;
- `undefined:` и имя без `strings.` — добавьте квалификатор;
- `imported and not used` — один из пакетов в строке импорта ни разу не вызван.

Строка `--- FAIL: TestPackagesAndExportsPrintsTwoLines` и под ней сообщение
`программа напечатала …, а должна была напечатать …` значат, что программа
собралась и запустилась, но напечатала другие байты. Первый текст в кавычках —
что напечатала программа, второй — что должна была. Найдите место, где они
начинают расходиться.

Работать локально необязательно. Если Go уже установлен у вас на компьютере,
программу можно запустить и там. Для этого понадобится файл `go.mod` ровно с
таким содержимым:

```text
module lesson/packages-and-exports

go 1.27
```

Это то же содержимое, что у файла `go.mod` в заготовке. Шаги ниже рассчитаны на
то, что версия установленного у вас Go не ниже числа в строке `go`. Как узнать
версию командой `go version` и что происходит, если она ниже, объясняет
упражнение урока 1.3.

1. Создайте пустой каталог и откройте в нём терминал, чтобы этот каталог стал
   текущим.
2. Создайте в этом каталоге файл `go.mod` с содержимым, показанным выше.
3. Создайте рядом с ним файл `main.go` и скопируйте в него свой код из поля кода
   задачи.
4. В том же каталоге выполните `go run .`.

Если в коде нет ошибок сборки, команда `go run .` соберёт и запустит программу.
Сами сравните напечатанное со строками из раздела «Что сдать»: те же строки, в
том же порядке, без пробелов по краям. Скрытого теста в этом каталоге нет,
поэтому побайтово вывод сравнивает только проверка на платформе.

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## main

**Ступень 1.** Сначала определите вид ответа проверки. Сообщение сборки вроде
`undefined: …` или `"…" imported and not used` значит, что компилятор отказался
собирать программу и она не запускалась. Посмотрите, что стоит после
`undefined:`: есть ли перед именем функции имя пакета с точкой и с какой буквы
начинается само имя. Сообщение `imported and not used` значит, что один из
пакетов в строке импорта ни разу не вызван. Строка
`--- FAIL: TestPackagesAndExportsPrintsTwoLines` с сообщением
`программа напечатала …, а должна была напечатать …` значит, что программа
собралась и запустилась, но напечатала другие байты. Сравните два текста в
кавычках слева направо: так видно, где не хватает заглавных букв или остались
лишние пробелы по краям.

**Ступень 2.** Программе нужны две вещи. Первая — скобочная строка импорта, где
пути `"fmt"` и `"strings"` стоят каждый на своей строке. Вторая — два вызова
`fmt.Println`, и в скобках каждого стоит вызов функции из `strings`:
`strings.ToUpper` для первой строки вывода и `strings.TrimSpace` для второй.
Ошибка в записи этого внутреннего вызова — `toUpper` со строчной буквы или
`ToUpper` без `strings.` перед ним — останавливает сборку с сообщением
`undefined:`. Если сборка прошла, а в сообщении теста напечатанный текст содержит
строчные буквы или пробелы по краям, значит, литерал напечатан как есть, без
функции из `strings`.

# Повторение

# Разбор неверного решения

Читайте этот разбор после попытки. Решение ниже собирается и запускается, но
проверку не проходит.

## Литералы напечатаны как есть

Программа импортирует только `fmt` и печатает оба литерала из условия без
изменений: слово `"gopher"` строчными буквами и строку с двумя пробелами в
начале и в конце. Функции `strings.ToUpper` и `strings.TrimSpace` она не
вызывает. Поэтому пакета `strings` в её импорте нет: импорт без единого вызова
не собрался бы.

Эту ошибку ловит скрытый тест `TestPackagesAndExportsPrintsTwoLines`. Он
сравнивает весь вывод с эталоном побайтово. В его сообщении первый текст в
кавычках — то, что напечатала программа: слово в нём записано строчными буквами,
а вторая строка начинается и заканчивается пробелами. Второй текст — эталон.

Исправление: добавить путь `"strings"` в скобочную строку импорта и передать
литералы функциям пакета. Литерал `"gopher"` передаётся `strings.ToUpper` в
скобках первого `fmt.Println`, строка с пробелами — `strings.TrimSpace` в скобках
второго. Печатается то, что выдала функция, а не исходный литерал. После
исправления проверьте решение снова; при работе на своём компьютере сначала
запустите `go run .` и убедитесь, что пробелов по краям второй строки нет.

## Граница проверки

Программа, которая печатает обе нужные строки уже готовыми литералами, в том
виде, в каком они записаны в условии, проверку пройдёт, хотя пакета
`strings` в ней нет. Это не дефект теста: скрытый тест сравнивает только вывод,
а вывод у такой программы тот же, что у решения. Упражнение просит получить
строки вызовами `strings`, потому что учит импорту и квалифицированным вызовам.
Когда вы пишете эти вызовы, их запись проверяет компилятор, а не тест.

# Проверочные вопросы

# Проверочные вопросы

## Вопрос 1

Программа устроена как разобранная в уроке: скобочная строка импорта с путями
`"fmt"` и `"strings"` и два вызова печати. В первом вызове вместо
`strings.ToUpper("gopher")` записано `strings.toUpper("gopher")`. Второй вызов,
`strings.TrimSpace(...)`, не изменился. Что произойдёт после `go run .`?

Варианты ответа:

- A. Программа соберётся и напечатает обе строки: первая буква имени — дело
  стиля, и компилятор найдёт функцию `ToUpper`.
- B. Сборка откажет с сообщением `undefined:` у первого вызова: из другого
  пакета можно обратиться только к имени с заглавной буквы.
- C. Сборка откажет с сообщением, что `"strings"` импортирован и не
  используется: вызов со строчной буквы не считается обращением к пакету.
- D. Программа соберётся, но напечатает только вторую строку: вызов
  недоступного имени при запуске пропускается.

Прежде чем смотреть ответ, объясните, какое правило об именах чужого пакета
здесь нарушено.

**Правильный ответ: B.**

Снаружи пакета `strings` доступны только имена с заглавной буквы, поэтому
доступного имени `toUpper` компилятор не находит и сообщает `undefined:`.
Вариант A считает регистр первой буквы соглашением, хотя это правило языка и
его нарушение останавливает сборку. Вариант C не учитывает второй вызов:
`strings.TrimSpace` обращается к пакету, импорт использован, и ошибка одна.
Вариант D ждёт ошибки при запуске, но обращение к недоступному имени
обнаруживает компилятор ещё при сборке, и программа не создаётся.

## Вопрос 2

Программа та же, но первый вызов записан без квалификатора:
`ToUpper("gopher")`. Импорт обычный — путь `"strings"` в скобках, без знака перед
ним. Второй вызов, `strings.TrimSpace(...)`, не изменился. Что произойдёт после
`go run .`?

Варианты ответа:

- A. Программа соберётся: импорт переносит в файл все экспортируемые имена
  пакета `strings`, и квалификатор можно не писать.
- B. Программа соберётся: второй вызов уже обращается к `strings`, и после этого
  функции пакета доступны в файле без квалификатора.
- C. Сборка откажет с сообщением `undefined: ToUpper`: обычный импорт добавляет
  в файл только имя `strings`, а не имена функций пакета.
- D. Сборка откажет с сообщением, что `"strings"` импортирован и не
  используется: вызов без квалификатора к пакету не относится.

Прежде чем смотреть ответ, объясните, какое имя добавляет в файл обычный импорт.

**Правильный ответ: C.**

Обычный импорт даёт файлу имя пакета, а к `ToUpper` из файла обращаются только
через `strings.`. Голое `ToUpper` компилятор ищет среди имён файла и пакета
`main` и не находит. Вариант A описывает импорт, который переносит имена пакета
в файл, а обычный импорт этого не делает. Вариант B считает, что одно
обращение к пакету открывает его имена, но каждый вызов функции чужого пакета
записывается с квалификатором. Вариант D не учитывает второй вызов:
`strings.TrimSpace` использует пакет, и сборка сообщает об одной ошибке.

## Вопрос 3

Две программы с одинаковым телом `main`: в скобках `fmt.Println` вызываются
`strings.ToUpper` и `strings.TrimSpace`. В первой программе импорт записан одной
скобочной строкой с путями `"fmt"` и `"strings"`. Во второй — двумя строками
подряд: `import "fmt"` и `import "strings"`. Чем программы отличаются при сборке
и запуске?

Варианты ответа:

- A. Ничем: обе собираются и печатают одинаковый вывод, потому что обе формы
  подключают пакеты `fmt` и `strings` и дают файлу их имена.
- B. Вторая не соберётся: когда пакетов два или больше, импорт обязан быть
  записан в скобках.
- C. Вторая не соберётся: слово `import` можно написать в файле только один раз,
  а вторая строка повторяет объявление.
- D. Обе соберутся, но во второй программе квалификатор `strings.` необязателен:
  пакет на отдельной строке отдаёт файлу свои имена напрямую.

Прежде чем смотреть ответ, опишите каждую строку импорта в обеих программах:
какой путь она перечисляет и какое имя пакета появляется в файле.

**Правильный ответ: A.**

Одиночная и скобочная формы — две записи одного импорта: в разделе «Одиночная и
скобочная формы» обе программы собираются и печатают одинаковый вывод. Вариант B принимает соглашение о стиле
за требование: скобочная форма встречается чаще, но не обязательна. Вариант C
не допускает нескольких объявлений импорта в файле, хотя вторая программа
собирается. Вариант D приписывает одиночной форме другой смысл, но любой
обычный импорт даёт файлу только имя пакета.

## Вопрос 4

В программе скобочная строка импорта: путь `"fmt"` и путь `"strings"` со знаком
`_` перед ним. Тело `main` — один вызов `fmt.Println` со строковым литералом, и
к пакету `strings` файл не обращается ни разу. Соберётся ли программа? Зачем
автор программы может намеренно записать импорт с пустым именем?

Варианты ответа:

- A. Не соберётся: импорт, к которому файл ни разу не обращается, — всегда
  ошибка сборки, и знак `_` перед путём это правило не отменяет.
- B. Соберётся: такой импорт не считается неиспользованным. Его пишут, когда
  пакет нужен ради его инициализации, а вызывать функции пакета файл не будет.
- C. Соберётся: знак `_` открывает функции `strings` для вызова без
  квалификатора, поэтому компилятор считает пакет используемым.
- D. Соберётся, и назначение у знака одно: `_` выключает проверку
  неиспользованного импорта, чтобы лишнюю строку можно было не удалять.

Прежде чем смотреть ответ, объясните своими словами, чем эта строка импорта
отличается от той же строки без `_` и в каком случае автору нужна такая форма.

**Правильный ответ: B.**

Импорт с пустым именем подключает пакет, не давая ему имени в файле, и
компилятор не считает такой импорт неиспользованным. Выбирают эту форму, когда
программе нужна инициализация пакета — подготовительная работа, которую пакет
выполняет до начала обычной работы программы. В примере из раздела «Импорт с
пустым именем» пакет `strings` подключён так только для показа формы: видимого
результата его инициализации там нет. Вариант A верен для той же строки без
`_`: тогда сборка сообщает, что `"strings"` импортирован и не используется, а
знак `_` это меняет. Вариант C путает пустое имя с доступом к функциям: такой импорт не даёт файлу никакого имени для вызовов.
Вариант D верно говорит, что программа соберётся, но не называет назначения:
форму выбирают ради инициализации пакета, а ненужный импорт просто удаляют.
