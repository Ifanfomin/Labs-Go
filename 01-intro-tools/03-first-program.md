## Инструкция для нейросети

Ты получаешь материалы одного урока курса по Go.

Твоя задача — **не пересказать исходный материал целиком**, а подготовить
компактный, точный конспект, по которому студент сможет:

1. понять основные концепции урока;
2. вспомнить синтаксис и правила Go, которые здесь изучаются;
3. ответить на проверочные вопросы из раздела «Проверочные вопросы»;
4. решить типовые практические задачи по этой теме;
5. не перепутать похожие понятия и исключения.

### Правила подготовки ответа

- Сохраняй техническую точность.
- Не выкидывай правила, которые могут быть проверены в quiz.
- Особое внимание уделяй причинам: **почему ответ правильный**, а остальные
  варианты неправильны.
- Если в quiz есть конкретный сценарий, команду, код или вывод программы —
  обязательно объясни соответствующее правило.
- Не пересказывай очевидные вводные фразы и организационную информацию.
- Не добавляй информацию, которой нет в предоставленных материалах, если она
  не нужна для объяснения приведённого материала.
- Код из примеров используй как источник конкретных правил и поведения Go.
- Не нужно разбирать каждую строку примера, если это не помогает ответить
  на вопрос quiz.
- Сохраняй названия команд, функций, типов, операторов и других сущностей
  точно.
- Если есть важное исключение или типичная ошибка — вынеси её отдельно.

# Первая программа

Представьте, что нужна программа, которая при запуске печатает три строки
текста, одну под другой. В уроке 1.1 вы видели, что исходный текст на Go сначала
компилируется, а потом запускается. В уроке 1.2 вы запускали готовые программы
командой `go run .` и отличали то, что напечатала программа, от сообщений самой
команды `go`. Теперь вы разберёте такую программу по строкам, узнаете, что
нужно команде `go`, чтобы её запустить, и в упражнении допишете её сами.

Упражнение начинается с заготовки — готового проекта из двух файлов. Первый,
`go.mod`, уже заполнен; откуда он берётся и что в нём записано, разбирает урок
1.4. Второй, `main.go`, содержит объявление пакета и пустую функцию `main`. Вы
допишете в `main.go` строку импорта и тело функции.

## Программа строка за строкой

Ниже — программа, которую вы соберёте в упражнении. Под кодом показан её вывод.

```go

### Example: `01-entry-point`

Источник: `examples/01-entry-point/`

```go
// Разобранная программа урока: объявление пакета, строка импорта
// и функция main с тремя вызовами печати.
package main

import "fmt"

func main() {
	fmt.Println("Программа началась")
	fmt.Println("Точка входа называется main")
	fmt.Println("Программа завершилась")
}

```
```

Две верхние строки, начинающиеся с `//`, — комментарий, пояснение для
читателя; код программы начинается после него. Код делится на три части: к какому
пакету относится файл, каким другим пакетом он пользуется и что выполняется при
запуске.

**`package main`** — объявление пакета. Пакет — это группа файлов с кодом,
которую команда `go` собирает вместе; в проекте упражнения это обычные файлы
`.go` одного каталога. Объявление пакета стоит первой строкой кода в каждом
файле и называет пакет, к которому файл относится. Пакет в этой программе
называется `main`, и почему именно так, объясняет следующий раздел.

**`import "fmt"`** — строка импорта. `fmt` — пакет стандартной библиотеки Go, в
котором есть функция печати `Println`. Строка импорта подключает этот пакет к
файлу. После неё в файле можно написать `fmt.Println`: сначала имя пакета, затем
через точку имя функции из него. Без строки импорта имя `fmt` в файле
неизвестно, и программа не соберётся; как выглядит это сообщение, показано в
разделе «От правки до проверки». Как устроены пакеты и импорт, разбирает урок
1.6.

**`func main() { … }`** — объявление функции с именем `main`. Функция — это
именованный кусок кода. Код функции, её тело, стоит между фигурными скобками;
открывающая скобка остаётся на одной строке со словом `func`. Слово `func`, имя,
пустые круглые скобки и фигурные скобки — готовая форма; пока её достаточно
повторять без изменений. Из чего она состоит и как объявлять свои функции, разбирает урок 1.7.

**Три вызова `fmt.Println`** — тело функции `main`. Каждый вызов печатает текст,
переданный ему в круглых скобках, и сразу после текста ставит перевод строки —
невидимый символ, который завершает строку. Текст в двойных кавычках называется
строковым литералом. Русские буквы внутри кавычек допустимы: исходный текст на
Go записывается в кодировке UTF-8.

Вызовы выполняются друг за другом, в том порядке, в каком записаны. Блок «Вывод»
под программой показывает три строки ровно в порядке трёх вызовов.

## Что делает программу запускаемой

Не всякий пакет можно запустить как программу. Пакет, из которого получается
самостоятельная программа, называют запускаемым. Спецификация языка ставит ему
два условия:

1. пакет называется `main`;
2. в пакете объявлена функция с именем `main`, которая не принимает аргументов и
   не возвращает результата. В разобранной программе это видно по пустым круглым
   скобкам после имени и по тому, что между `)` и `{` ничего нет. Что такое
   аргументы и результат функции, разбирает урок 1.7.

Функцию `main` запускаемого пакета называют точкой входа. Запущенная программа
сначала подготавливается к работе, а затем вызывает `main`. Когда `main`
завершается, завершается и программа.

Нужны оба условия: верное имя функции не заменяет верного имени пакета, и
наоборот. Следующие три раздела показывают, что сообщает команда `go`, когда
нарушено одно из них. Текст этих сообщений — вывод текущей версии команды `go`,
а не часть языка: в другой версии формулировка может отличаться.

## Пакет с другим именем

Возьмите проект, в котором лежат только `go.mod` и `main.go` с разобранной
программой, и поменяйте одну строку: `package main` на `package hello`. Функция
`main` и её тело остаются прежними. Прежде чем читать дальше, предположите, что
сделает `go run .` в этом каталоге.

Команда `go` не запустит программу. Вместо вывода программы она печатает
сообщение `package lesson/first-program is not a main package` — «пакет
`lesson/first-program` не является пакетом `main`».

В сообщении стоит не `hello`, а `lesson/first-program`: так команда `go`
называет пакет по пути модуля из файла `go.mod`. Что такое путь модуля,
объясняет урок 1.4. Верное имя функции не помогло, потому что нарушено первое
условие.

Ошибки в самом коде такого файла нет. Пакет с именем не `main` команда `go`
считает не программой, а кодом, которым пользуются другие программы; как это
устроено, разбирает урок 1.6.

## Два имени пакета в одном каталоге

Команда `go` собирает обычные файлы `.go` одного каталога в один пакет. Поэтому
она требует, чтобы во всех этих файлах стояло одно и то же имя пакета. Это
правило команды `go`, а не самого языка: спецификация лишь разрешает
инструментам его вводить. Для файлов тестов, чьи имена оканчиваются на
`_test.go`, у этого правила есть особый случай; его разбирает урок 1.12.

В сломанном примере два файла. Первый, `main.go`, — разобранная программа без
изменений; его код показан ниже. Второй файл, `hello.go`, кроме комментария
содержит одну строку кода — `package hello`. Под кодом стоит сообщение, которое
печатает сборка; прежде чем его читать, предположите, на что оно укажет.

```go
@broken mixed-package
```

Сообщение `found packages hello (hello.go) and main (main.go)` означает
«найдены пакеты `hello` (в `hello.go`) и `main` (в `main.go`)». В нём названы оба
имени пакета и файлы, где они объявлены. После этих слов в той же строке идёт
путь к каталогу; он на каждом компьютере свой, поэтому в примере показано
только начало строки.

Это правило касается и упражнения. Когда платформа проверяет решение, рядом с
вашим `main.go` лежит файл скрытого теста, и в нём тоже стоит `package main`.
Если заменить имя пакета в своём файле, в каталоге окажутся два разных имени.
Поэтому проверка сообщит о найденных пакетах `hello` и `main` и назовёт ваш файл
и файл теста, а не напишет, что пакет не является пакетом `main`.

## Пакет без функции main

В примере ниже имя пакета верное, а функция `main` переименована в `start`.
Функция объявлена по тем же правилам, и других функций в файле нет. Прежде чем
читать сообщение под кодом, предположите, запустится ли такая программа.

```go
@broken no-main
```

Сборка не создаёт программу и печатает строку
`runtime.main_main·f: function main is undeclared in the main package`. Часть
строки до двоеточия — внутреннее имя, которым пользуется сама сборка; разбирать
его не нужно. Остальное значит «функция `main` не объявлена в пакете `main`».

Отсюда правило: точку входа находят по имени. Ни то, что функция единственная,
ни то, что она стоит первой, не делает её точкой входа.

В упражнении эта ошибка выглядит иначе. Скрытый тест сам вызывает функцию
`main`, поэтому после её переименования не собирается уже тест: текущая версия
команды `go` сообщает `undefined: main` — «имя `main` не определено».

## Имя файла и точка входа

В примерах урока файл с программой называется `main.go`, но это соглашение, а не условие
запуска. Команда `go` берёт в пакет обычные файлы `.go` каталога независимо от
их имён, а точку входа определяет объявление `func main`. Если переименовать
`main.go` в `program.go` и больше ничего не менять, `go run .` напечатает те же
три строки, и проверка упражнения пройдёт так же.

Это верно для обычных имён вроде `program.go`. Некоторые части имени сами
меняют, попадёт ли файл в сборку:

- файл, чьё имя оканчивается на `_test.go`, берёт только команда `go test`.
  Поэтому скрытый тест упражнения лежит в файле с таким окончанием; писать такие
  файлы вы начнёте в уроке 1.12;
- файл, чьё имя оканчивается на название операционной системы или архитектуры
  процессора, например `main_windows.go` или `main_linux.go`, компилируется
  только при сборке для этой системы или архитектуры;
- файл, чьё имя начинается с `_` или с точки, команда `go` пропускает.

Значит, выбор имени файла не влияет на запуск, пока в имени нет ни одной из этих
особенностей.

## Вывод сверяется побайтово

Проверка упражнения сравнивает то, что напечатала программа, с эталоном —
точной записью нужного вывода. Сравнение побайтовое. Текст хранится как
последовательность байтов: буква, пробел и перевод строки — всё это байты. Если
хотя бы один байт лишний, пропущен или стоит не на своём месте, вывод не совпадёт
с эталоном.

Отсюда три требования к выводу:

- каждая строка совпадает с условием символ в символ, включая пробелы;
- строки идут в том же порядке, что в условии;
- после каждой строки, включая последнюю, стоит перевод строки, и больше ничего
  не напечатано.

Перевод строки из третьего требования ставит сама функция `fmt.Println`: она
печатает его после каждого текста, в том числе после последнего. Поэтому три вызова
`fmt.Println` дают три строки, и в конце вывода стоит ровно один перевод строки.
Писать перевод строки внутри кавычек не нужно.

Скрытый тест получает только вывод программы, а не её исходный текст.
Комментарии, пустые строки между вызовами и способ записи на результат проверки
не влияют: другая запись, которая печатает те же байты, тоже пройдёт. Три вызова
`fmt.Println` — самый прямой способ: так устроена разобранная программа.

## От правки до проверки

Работа над упражнением идёт по кругу, знакомому по уроку 1.2: правка кода,
запуск, проверка. На каждом шаге сначала определите, кто написал то, что вы
видите.

Строки текста, которые напечатала ваша программа, — её вывод. Он появляется,
только если программа собралась и запустилась. Если программа не собралась,
вы увидите сообщение команды `go`, как в разделах «Пакет с другим именем»,
«Два имени пакета в одном каталоге» и «Пакет без функции main». Когда ошибка
находится в конкретной строке кода, сообщение начинается с имени файла, номера
строки и номера позиции в строке, а после двоеточия объясняет ошибку. Такое
сообщение пишет не ваша программа: до её запуска дело не дошло. Первым делом
откройте строку, которую оно называет.

Пока вы дописываете заготовку, чаще всего встречаются две ошибки. Первая —
вызовы `fmt.Println` написаны, а строка импорта забыта:

```go
@broken no-import
```

Сообщение `undefined: fmt` значит «имя `fmt` не определено»: в файле нет строки
импорта, которая подключает пакет `fmt`. Такая строка сообщения повторяется для каждого
вызова, в котором встречается `fmt`. Исправление — добавить `import "fmt"` между
строкой `package` и строкой `func`.

Вторая ошибка — строка импорта уже написана, а тело `main` ещё пустое:

```go
@broken unused-import
```

Сообщение `"fmt" imported and not used` значит «пакет `fmt` импортирован, но не
используется». Правила Go запрещают импортировать пакет и ни разу к нему не
обратиться, поэтому такая программа не собирается. Ошибка исчезнет, когда в теле появится первый вызов
`fmt.Println`.

Если программа собралась, её вывод проверяет скрытый тест — проверочный код,
который лежит рядом с вашим файлом, но вам не показан. Тест вызывает вашу
функцию `main`, перехватывает её вывод и сравнивает с эталоном. Если вывод не
совпал, сообщение теста показывает два текста в кавычках: что программа
напечатала и что должна была напечатать. Перевод строки внутри этих кавычек
записан двумя знаками `\n`; в своей программе писать их не нужно. Например,
заготовка без изменений собирается, но ничего не печатает, поэтому первый текст
в её сообщении — пустые кавычки `""`.

# Упражнение: первая программа

## Что сдать

Программу, которая печатает ровно три строки, в этом порядке:

1. `Программа началась`
2. `Точка входа называется main`
3. `Программа завершилась`

После каждой строки, включая третью, стоит перевод строки. Больше программа
ничего не печатает: ни приветствия, ни пустой строки, ни отладочного текста.

Заготовка уже содержит файл `go.mod` и файл `main.go`. В `main.go` написаны
объявление `package main` и пустая функция `main`. Допишите в `main.go` две
вещи:

- строку `import "fmt"` между строкой `package main` и строкой `func main() {`.
  Функция печати `Println` лежит в пакете `fmt` стандартной библиотеки, и строка
  импорта подключает этот пакет к вашему файлу;
- тело функции `main` — код между фигурными скобками, который печатает три
  строки.

Проще всего написать по одному вызову `fmt.Println` на каждую строку, как в
разобранной программе. Текст строк копируйте из списка выше символ в символ.

## Что оставить без изменений

Файл `go.mod`, объявление `package main` и имя функции `main` не меняйте. Если
заменить имя пакета или функции, проверка не пройдёт, и сообщения в этих двух
случаях разные:

- другое имя пакета — сообщение о двух найденных пакетах: вашем и пакете `main`
  скрытого теста;
- другое имя функции — сообщение `undefined: main` при сборке теста.

Оба случая разобраны в теории, в разделах «Два имени пакета в одном каталоге» и
«Пакет без функции main».

## Что проверяется

Проверку выполняет скрытый тест. Он вызывает вашу функцию `main`, перехватывает
то, что она печатает, и сравнивает с эталоном побайтово: значение имеют текст
строк, их порядок и перевод строки после каждой из них.

Текст решения скрытый тест не получает. Комментарии, пустые строки между
вызовами и способ записи на результат не влияют: другая запись, которая печатает
те же байты, тоже пройдёт.

## Как работать

1. Допишите код в поле кода задачи на странице упражнения.
2. Нажмите «Проверить».
3. Прочитайте ответ и определите, кто его написал: скрытый тест или команда `go`.
4. Исправьте код и проверьте снова.

Сообщение теста с двумя текстами в кавычках значит, что программа запустилась,
но напечатала не то. Первый текст — что напечатала программа, второй — что
должна была. Найдите место, где они начинают расходиться.

Любое другое сообщение пришло от команды `go`: программа не собралась и не
запускалась. Если сообщение начинается с имени файла и номера строки, откройте
названную строку и исправьте её.

Работать локально необязательно. Если Go уже установлен у вас на компьютере
(как установить Go, объясняет урок 1.2 «Установка Go и рабочее окружение»),
программу можно запустить и там. Для этого понадобится файл `go.mod` ровно с
таким содержимым:

```text
module lesson/first-program

go 1.27
```

Это то же содержимое, что у файла `go.mod` в заготовке; что означают его строки,
объясняет урок 1.4. Для локального запуска важна строка `go`: шаги ниже
рассчитаны на то, что версия установленного у вас Go не ниже числа в этой строке.

1. Создайте пустой каталог и откройте в нём терминал, чтобы этот каталог стал текущим (что такое текущий каталог, объясняет урок 1.2).
2. Выполните `go version`. Команда напечатает одну строку, и её третье слово — версия вашего Go. Номер после букв `go` в этом слове должен быть не ниже числа из строки `go` в показанном выше файле.
3. Создайте в этом каталоге файл `go.mod` с содержимым, показанным выше.
4. Создайте рядом с ним файл `main.go` и скопируйте в него свой код из поля кода задачи.
5. В том же каталоге выполните `go run .`; точка в команде означает текущий каталог.

Если версия Go подходит и в коде нет ошибок сборки, команда `go run .` соберёт
и запустит программу. Сами сравните напечатанное со строками из раздела
«Что сдать»: те же строки, в том же порядке, ничего лишнего. Скрытого теста в
этом каталоге нет, поэтому побайтово вывод сравнивает только проверка на платформе.

Если вместо запуска программы команда `go run .` печатает сообщение о версии Go,
дело в установленном у вас Go, а не в коде. Такое сообщение говорит, какая версия
Go нужна проекту, и не указывает на строку в `main.go`. Пока команда печатает
это сообщение, ошибки в `main.go` она не показывает, даже если они там есть.
Менять `main.go` из-за такого сообщения не нужно. Проверьте решение на
платформе кнопкой «Проверить» или установите подходящий Go по разделу
«Установка на свой компьютер и самопроверка» урока 1.2 «Установка Go и рабочее
окружение», повторите шаг 2, а затем снова выполните шаг 5.

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## main

**Ступень 1.** Сначала определите, кто написал ответ проверки. Если это
сообщение теста с двумя текстами в кавычках, программа запустилась. Сравните
эти два текста слева направо и найдите первое место, где они расходятся: там
строка пропущена, лишняя, стоит не на своём месте или отличается на символ.
Любое другое сообщение пришло от команды `go`: программа не собралась, и вывода
у неё ещё нет — ищите ошибку в строке кода, которую называет сообщение.

**Ступень 2.** Программе нужны две вещи: строка `import "fmt"` сразу после
`package main` и вызовы `fmt.Println` в теле `main`, по одному на каждую строку
вывода и в порядке списка из условия. Чаще всего встречается одна из двух ошибок: либо
забыт импорт, и тогда сборка сообщает `undefined: fmt`, либо текст внутри
кавычек отличается от условия на символ. Перевод строки `fmt.Println` ставит
сама, поэтому внутри кавычек его не пишут.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки. Оба решения ниже собираются, запускаются и
печатают знакомые строки — и всё равно не проходят проверку.

## Потеряна средняя строка

Программа печатает первую и третью строки, а вызова `fmt.Println` для второй
строки нет. Так бывает, когда строки набирают по памяти, а не копируют из
условия.

Эту ошибку находит скрытый тест `TestFirstProgramPrintsThreeLines`. Он сравнивает весь вывод с
эталоном целиком, а не ищет в нём отдельные строки, поэтому двух верных строк
из трёх недостаточно. В сообщении теста первый текст в кавычках короче второго:
в нём нет средней строки.

Исправление: вернуть вызов `fmt.Println` для второй строки между двумя
оставшимися вызовами. После исправления проверьте решение снова; при работе на
своём компьютере сначала запустите `go run .` и убедитесь, что строк три и
средняя стоит на своём месте.

## Вторая и третья строки поменялись местами

Все три строки напечатаны, но вторая и третья идут в обратном порядке. Набор
строк совпадает с эталоном, и длина вывода та же; отличается только порядок.

Эту ошибку находит тот же `TestFirstProgramPrintsThreeLines`. Он сравнивает вывод по
порядку, байт за байтом, поэтому расхождение находится сразу после первой
строки. В сообщении теста это видно по двум текстам в кавычках: начало у них
общее, а дальше строки идут в разном порядке.

Исправление: расставить вызовы в том порядке, в котором строки перечислены в
условии, и проверить снова. При работе на своём компьютере сначала сравните
вывод `go run .` со списком из условия строка за строкой.

## Что общего у двух ошибок

Проверка сравнивает байты и не оценивает смысл: «те же строки в другом порядке»
и «почти все строки» для неё просто другой вывод. Перед отправкой сравните свой
вывод со списком из условия по трём признакам: те же строки, тот же порядок,
ничего лишнего.

# Проверочные вопросы

## Вопрос 1

В каталоге проекта лежат только два файла: `go.mod` и `main.go` с разобранной
программой. В `main.go` вы заменили `package main` на `package hello`, а функцию
`main` и её тело не трогали. Что произойдёт после `go run .` в этом каталоге?

Варианты ответа:

- A. Программа запустится и напечатает три строки: функция `main` на месте, а
  объявление пакета только подписывает файл.
- B. Команда `go` не запустит программу и сообщит, что пакет не является пакетом
  `main`.
- C. Команда `go` не запустит программу и сообщит, что в каталоге найдены два
  разных пакета.
- D. Сборка не создаст программу и сообщит, что в пакете `main` не объявлена
  функция `main`.

Прежде чем смотреть ответ, объясните, какое из двух условий запускаемой
программы нарушено.

**Правильный ответ: B.**

Запускаемым пакет делают два условия вместе: имя `main` и функция `main` в нём.
В этом проекте нарушено первое условие, и текущая версия команды `go` сообщает
`package lesson/first-program is not a main package`. Вариант A считает
объявление пакета подписью, хотя имя пакета — одно из двух условий запуска.
Вариант C описывает каталог с двумя разными именами пакета, а здесь файл один и
имя одно; такое сообщение появилось бы, если бы рядом лежал файл с
`package main`, например файл скрытого теста при проверке. Вариант D меняет
условия местами: функция `main` объявлена, а пакета с именем `main` в каталоге
нет.

## Вопрос 2

Проект тот же: `go.mod` и `main.go` с разобранной программой. Вы делаете две
отдельные правки и после каждой возвращаете проект в исходный вид.

- Правка 1: рядом с `main.go` добавлен файл `hello.go`, в котором единственная
  строка кода — `package hello`.
- Правка 2: в `main.go` функция `main` переименована в `start`, других файлов
  не добавлялось.

Что сообщит `go run .` после каждой правки?

Варианты ответа:

- A. Правка 1 — строку, которая начинается с
  `found packages hello (hello.go) and main (main.go)`; правка 2 — строку со
  словами `function main is undeclared in the main package`.
- B. Правка 1 — строку `package lesson/first-program is not a main package`;
  правка 2 — строку со словами `function main is undeclared in the main package`.
- C. Правка 1 — ничего: в `hello.go` нет кода, кроме объявления пакета, и
  программа запустится; правка 2 — строку со словами
  `function main is undeclared in the main package`.
- D. Правка 1 — строку, которая начинается с
  `found packages hello (hello.go) and main (main.go)`; правка 2 — ничего:
  `start` — единственная функция в файле и станет точкой входа.

Прежде чем смотреть ответ, назовите для каждой правки условие, которое она
нарушает.

**Правильный ответ: A.**

После правки 1 в каталоге два разных имени пакета, а команда `go` требует одно
имя во всех обычных файлах `.go` каталога. После правки 2 в пакете `main` нет
функции `main`. Вариант B приписывает правке 1 сообщение для случая, когда пакет
каталога назван другим именем, хотя `main.go` по-прежнему объявляет пакет `main`:
рядом просто появилось второе имя. Вариант C считает файл без кода безвредным, но команда `go`
сверяет объявление пакета в каждом обычном файле `.go`, даже если больше в нём
ничего нет. Вариант D ищет точку входа по единственности функции, а её находят
только по имени `main`.

## Вопрос 3

Вы переименовали файл заготовки `main.go` в `program.go` и больше ничего не
меняли: в файле по-прежнему `package main`, строка импорта и функция `main`. Что
изменится при `go run .` и при проверке упражнения?

Варианты ответа:

- A. Ничего: команда `go` берёт в пакет обычные файлы `.go` независимо от имени,
  а точку входа определяет объявление функции `main`.
- B. Сборка не создаст программу: файл с точкой входа обязан называться
  `main.go`.
- C. Сборка не создаст программу: точку входа ищут по имени файла, а функции
  `program` в пакете нет.
- D. Ничего, и так будет при любом новом имени с окончанием `.go`: например,
  имя `main_test.go` тоже подойдёт.

Прежде чем смотреть ответ, объясните, что определяет, какая функция станет
точкой входа.

**Правильный ответ: A.**

Точку входа задаёт объявление `func main` в пакете `main`, а `program.go` —
обычное имя, поэтому файл попадает в пакет как прежде. Вариант B принимает
соглашение за правило: имя `main.go` часто встречается в примерах, но запуску
оно не нужно. Вариант C связывает точку входа с именем файла, хотя имя функции
берётся только из её объявления. Вариант D обобщает слишком далеко: файл с
окончанием `_test.go` берёт только `go test`, и для `go run .` в каталоге не
останется ни одного файла с программой.

## Вопрос 4

Программа печатает три нужные строки в нужном порядке, и текст каждой строки
совпадает с условием символ в символ. Но после третьей строки перевода строки
нет. Что покажет проверка упражнения?

Варианты ответа:

- A. Проверка пройдёт: текст и порядок строк совпали, а перевод строки в конце
  не входит в вывод.
- B. Проверка пройдёт: вывод сравнивается построчно, а невидимые символы в
  конце строк не учитываются.
- C. Проверка не пройдёт: скрытый тест читает текст решения и требует ровно три
  вызова `fmt.Println`.
- D. Проверка не пройдёт: вывод сравнивается побайтово, а без последнего
  перевода строки он короче эталона на один байт.

Прежде чем смотреть ответ, объясните, что именно сравнивает проверка.

**Правильный ответ: D.**

Скрытый тест сравнивает весь перехваченный вывод с эталоном байт за байтом, и
перевод строки после третьей строки — такой же байт эталона, как остальные.
Вариант A не считает перевод строки частью вывода, хотя `fmt.Println` печатает
его после каждого текста. Вариант B описывает построчное сравнение с очисткой
концов строк, а проверка упражнения сравнивает вывод как есть. Вариант C верно
предсказывает отказ, но называет неверную причину: тест не получает текста
решения, и другая запись с теми же байтами проходит.

## Вопрос 5

Ниже — разобранная программа, из которой удалена строка `import "fmt"`.
Остальные строки остались на месте.

```go
@quiz _broken/no-import
```

Что произойдёт после `go run .` в каталоге с этой программой?

Варианты ответа:

- A. Программа запустится и напечатает три строки: `fmt.Println` — встроенная
  команда языка, а строка импорта её только уточняет.
- B. Сборка не создаст программу: после объявления пакета обязана стоять хотя бы
  одна строка импорта, иначе файл неполный.
- C. Сборка не создаст программу: вызовы `fmt.Println` обращаются к пакету
  `fmt`, а без строки импорта имя `fmt` в файле не определено.
- D. Программа запустится, но ничего не напечатает: без строки импорта вызовы
  печати пропускаются.

Прежде чем смотреть ответ, объясните роль каждой строки полной разобранной
программы: `package main`, `import "fmt"`, `func main() { … }` и трёх вызовов
`fmt.Println`. Затем скажите, какие из этих строк зависят от строки импорта.

**Правильный ответ: C.**

Сверьте своё объяснение с полной программой из раздела «Программа строка за
строкой». `package main` относит файл к пакету `main` — пакету запускаемой
программы. `import "fmt"` подключает к файлу пакет `fmt` с функцией `Println`.
`func main() { … }` — точка входа: её тело выполняется при запуске. Три вызова
`fmt.Println` по порядку печатают тексты из кавычек, и после каждого ставится
перевод строки. От строки импорта зависят только эти вызовы: без неё сборка
сообщает `undefined: fmt` у каждого из них.

Вариант A считает печать частью языка, хотя `Println` лежит в пакете
стандартной библиотеки. Вариант B делает импорт обязательной частью любого
файла, но импорт нужен, только когда файл пользуется другим пакетом: заготовка
упражнения без вызовов печати собирается и без него. Вариант D ждёт, что сборка
молча пропустит неизвестное имя, но на неизвестное имя сборка сообщает ошибку и
программу не создаёт.
