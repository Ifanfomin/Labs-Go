# Функция: первый проход

В уроке 1.6 программа вызывала готовые функции пакета `strings`. Вызов
`strings.ToUpper("gopher")` получал строку и выдавал то же слово в верхнем
регистре, а `fmt.Println` печатала то, что выдал этот вызов. Функцию, которая
выдаёт нужную строку, можно объявить и в своём пакете.

Представьте программу, которая в разных местах здоровается с разными людьми.
Если в каждом месте заново собирать приветствие из кусков текста, формат легко
нарушить: в одном месте забыть пробел после запятой, в другом — восклицательный
знак. Своя функция решает эту задачу. Правило сборки строки записано в её теле
один раз, а каждое место программы только передаёт функции имя и получает
готовую строку.

В упражнении урока такие функции уже объявлены. Заготовка — пакет `greeting` с
тремя функциями: `Greet`, `FullName` и `Card`. Тело каждой из них пока
заглушка, которая возвращает пустую строку. Вы прочитаете готовые объявления и
замените заглушки выражениями, которые строят нужные строки. Для этого нужно
понять:

- из каких частей состоит объявление функции;
- как значение попадает в функцию и как результат возвращается обратно;
- почему функция упражнения возвращает строку, а не печатает её;
- по какому правилу аргументы вызова распределяются по параметрам;
- что сообщает сборка, когда аргумента не хватает или функция ничего не
  вернула.

Разделы «Почему main выглядит так» и «Своё экспортируемое имя» объясняют, почему
точка входа из урока 1.3 записана как `func main()` и почему функции упражнения
названы с заглавной буквы.

## Из чего состоит объявление

Ниже — программа курса с одной своей функцией, `wrap`. Функция получает слово и
возвращает его в кавычках-ёлочках, а `main` печатает результат. Под кодом
показан вывод программы.

```go

### Example: `01-declare-and-call`

Источник: `examples/01-declare-and-call/`

```go
package main

import "fmt"

func wrap(word string) string {
	return "«" + word + "»"
}

func main() {
	fmt.Println(wrap("функция"))
}

```
```

В файле объявлены две функции: `wrap` и знакомая по уроку 1.3 `main`. Обе
объявлены в пакете отдельно друг от друга: объявление `wrap` стоит рядом с
`main`, а не внутри её тела.

Первая строка объявления `wrap` читается слева направо так:

- `func` — ключевое слово, с которого начинается объявление функции;
- `wrap` — имя функции, по нему функцию вызывают;
- `(word string)` — список параметров в круглых скобках. **Параметр** — имя, под
  которым тело функции получает входное значение. Здесь параметр один: его имя
  `word`, за именем стоит тип `string`;
- `string` между закрывающей круглой скобкой и открывающей фигурной — тип
  результата. Он говорит, значение какого типа функция отдаёт коду, который её
  вызвал. У функций этого урока результат всегда один;
- фигурные скобки и всё, что между ними, — тело функции: инструкции, которые
  выполняются при каждом вызове.

Объявление само по себе ничего не выполняет. Оно описывает функцию: как её
зовут, что она получает, что возвращает и что делает. Тело `wrap` выполняется
только тогда, когда другой код вызывает `wrap`, и столько раз, сколько раз её
вызвали.

`string` — имя типа строк. Строковые литералы в двойных кавычках из урока 1.3 —
значения этого типа. В объявлении `wrap` слово `string` встречается дважды:
первое говорит, что параметр `word` получает строку, второе — что функция
возвращает строку. Что такое тип и какие ещё типы есть в Go, разбирает урок
2.1. В этом уроке других типов не будет.

Типы параметров по порядку вместе с типом результата называют **сигнатурой**
функции. Сигнатура `wrap` — один параметр типа `string` и результат типа
`string`.

Тело `wrap` состоит из одной инструкции: `return "«" + word + "»"`. После слова
`return` стоит выражение из трёх частей, соединённых оператором `+`. Когда
слева и справа от `+` стоят строки, он их склеивает: получается новая строка,
в которой сначала идут символы левой части, затем правой. Такое склеивание
называют **конкатенацией**. Части попадают в результат в том порядке, в каком
записаны: литерал с открывающей ёлочкой, значение параметра `word`, литерал с
закрывающей ёлочкой. Сам `+` ничего между частями не вставляет, даже пробела. В
результат попадают только символы литералов и символы значения `word`. В этом
уроке `+` соединяет только строки; во что обходится такое склеивание и чем его
заменяют, разбирают уроки 2.7 и 9.5.

**Инструкция `return`** завершает выполнение функции и отдаёт значение
выражения коду, который функцию вызвал. Это значение и есть результат вызова.

Теперь тело `main`: `fmt.Println(wrap("функция"))`. В нём записан вызов
`wrap("функция")` — имя функции и в круглых скобках значение для её параметра.
Значение, которое передают при вызове, называют **аргументом**. Параметр — имя
в объявлении функции, аргумент — значение в конкретном вызове. В этом вызове
аргумент — строка `"функция"`, и получает её параметр `word`.

Программа работает так:

1. `main` доходит до вызова `fmt.Println`. Чтобы напечатать значение,
   `fmt.Println` должна его получить, поэтому сначала выполняется вызов
   `wrap("функция")`.
2. Параметр `word` получает значение аргумента — строку `"функция"`.
3. Тело `wrap` склеивает открывающую ёлочку, слово и закрывающую ёлочку.
   `return` отдаёт получившуюся строку и завершает `wrap`.
4. Результат вызова `wrap` становится аргументом `fmt.Println`, и
   `fmt.Println` печатает эту строку.

Проследите по этим шагам, какое значение в какой момент есть у каждой части
программы. До вызова у параметра `word` значения нет: объявление только
называет параметр. В момент вызова `word` получает строку `"функция"` — семь
букв без кавычек-ёлочек. Выражение после `return` строит из неё новую строку:
одна ёлочка, те же семь букв, вторая ёлочка. Эту новую строку и получает
`main` как результат вызова `wrap("функция")`. Сама `main` значение не хранит и
не меняет: она сразу передаёт его в `fmt.Println`, и `fmt.Println` печатает
его и ставит перевод строки.

Тот же порядок рассуждения работает для любого аргумента. Если в `main`
написать `wrap("код")`, параметр `word` получит строку `"код"`, и функция
вернёт это слово в ёлочках. Если вызвать `wrap` два раза с разными словами,
тело выполнится два раза, и каждый вызов вернёт свою строку. Правило сборки
строки при этом записано один раз, в теле `wrap`, — ради этого функцию и
объявляют.

Печатает в этой программе `fmt.Println`, а не `wrap`: в теле `wrap` нет ни
одного вызова печати. Вызов `strings.ToUpper("gopher")` из урока 1.6 устроен так
же. У функции `ToUpper` есть параметр и результат, и слово в верхнем регистре
она не печатает, а возвращает.

Читать объявление и писать его с нуля — разные умения. В этом уроке объявления
даны готовыми: вы читаете их в примерах и в заготовке упражнения. Код примеров
на странице урока можно изменить и запустить снова. Например, замените ёлочки в
теле `wrap` другими символами или переименуйте параметр `word` сразу в списке
параметров и в теле. Такие опыты ничем не проверяются. Объявление функции с нуля
вы впервые напишете в уроке 1.12, и это будет объявление теста. Функции и пакет
своей программы в пустом каталоге вы напишете в мини-проекте 1.13.

## Вернуть, а не напечатать

У функции с результатом есть два действия, которые легко спутать: вернуть
значение и напечатать текст.

Возвращает значение инструкция `return`. Значение получает вызывающий код, и
что с ним делать, решает он: напечатать, передать аргументом в другой вызов или
склеить с другой строкой.

Печатает текст вызов `fmt.Println`. Он отправляет текст в стандартный вывод
программы — туда, откуда текст попадает в терминал после запуска и откуда его
перехватывал скрытый тест урока 1.3. Вызывающий код напечатанный текст не
получает. От вызова функции ему достаётся только то, что вернул `return`.

Отсюда распределение ролей, на котором построены функции упражнения: функция
возвращает строку, а печатает её тот код, которому нужен вывод. В примерах
этого урока печатает `main`. Возвращённую строку можно напечатать, передать
дальше или сравнить с эталоном. Скрытый тест упражнения делает последнее: он
вызывает функцию и сравнивает возвращённую строку с ожидаемой. Напечатанный
функцией текст в это сравнение не попадает.

Функция в примере ниже объявлена с результатом `string`, но в её теле нет
`return`: она только печатает слово с восклицательным знаком. Такое тело
появляется, когда печать принимают за результат. Прежде чем читать сообщение
под кодом, предположите, что напечатает программа.

```go
@broken missing-return
```

Программа не напечатает ничего: её не удастся собрать. Сборка печатает
`./main.go:7:1: missing return` — «не хватает `return`». Строка 7, позиция 1 —
закрывающая фигурная скобка тела `shout`. Компилятор дошёл до конца тела и не
нашёл инструкции, которая вернула бы объявленный результат. Вызов `fmt.Println`
внутри `shout` тоже не выполнится: сборка не создала программу, в которой он
мог бы выполниться.

Правило для тел из этого урока, в которых инструкции выполняются одна за
другой: функция, в сигнатуре которой объявлен результат, обязана закончить тело
возвратом значения через `return` с выражением. Если в
таком теле `return` нет, сборка отказывает с сообщением `missing return`.
Исправление — не ещё одна печать, а возврат строки: в теле `shout` вместо вызова
`fmt.Println` должно стоять `return word + "!"`. Печать остаётся в `main`,
которая и так передаёт результат `shout` в `fmt.Println`.

Сравните, кто что делает в двух записях `shout`. В сломанной записи роли
перепутаны. `shout` получает строку `"эй"` и сама пытается напечатать `эй!`, а
`main` ждёт от вызова `shout("эй")` строку, чтобы передать её в `fmt.Println`.
В теле нет `return`, который отдал бы строку в `main`: напечатанный текст
уходит в стандартный вывод, а не вызывающему коду, и сборка отказывает. В исправленной записи роли разведены так:

1. `main` вызывает `shout("эй")`, и параметр `word` получает `"эй"`.
2. `shout` склеивает `word` и литерал `"!"` и через `return` отдаёт строку
   `эй!` в `main`. Сама `shout` ничего не печатает.
3. `main` получает эту строку как результат вызова и передаёт её в
   `fmt.Println`.
4. `fmt.Println` печатает строку. Печатает один раз и в одном месте — в `main`.

Тот же вопрос — «кто возвращает, кто печатает» — задавайте к каждой функции,
которую читаете: у функций этого урока с результатом значение отдаёт `return`,
а печать принадлежит тому коду, которому нужен вывод.

## Свёрнутый список параметров

Параметров у функции может быть несколько. Их перечисляют в круглых скобках
через запятую, и у каждого есть имя и тип. Если у соседних параметров один и тот
же тип, его можно записать один раз, после последнего из этих имён. Функция
`pair` ниже получает две строки и возвращает их, соединённые словом «и».

```go

### Example: `02-folded-params`

Источник: `examples/02-folded-params/`

```go
package main

import "fmt"

func pair(first, last string) string {
	return first + " и " + last
}

func main() {
	fmt.Println(pair("чай", "кофе"))
}

```
```

Прочитайте первую строку объявления `pair` по тем же частям, что у `wrap`.
`func` начинает объявление. Имя — `pair`. В круглых скобках два имени через
запятую и одно слово `string` в конце. Между закрывающей круглой скобкой и
открывающей фигурной стоит второе `string` — тип результата. Значит, вызов
`pair` передаёт две строки и получает обратно одну.

Запись `(first, last string)` объявляет два параметра, `first` и `last`, и тип
`string` относится к обоим. В развёрнутой записи первая строка объявления
выглядела бы так: `func pair(first string, last string) string`. Компилятор не
различает эти две записи: в обеих два параметра типа `string` в том же порядке
и результат `string`, то есть одна и та же сигнатура. Свёрнутая запись только
убирает повтор типа. На то, как функцию вызывают и что она возвращает, выбор
записи не влияет.

Имена параметров на сигнатуру не влияют. Они нужны телу функции, чтобы
обращаться к полученным значениям. Если переименовать `first` и `last` и в
списке параметров, и в теле, сигнатура `pair` останется прежней.

Обратите внимание на литерал `" и "` в теле `pair`: пробелы вокруг «и» записаны
внутри кавычек. Оператор `+` пробелов не добавляет, поэтому без них слова
слиплись бы с «и».

В заготовке упражнения свёрнутая запись встречается дважды: `first, last string`
у `FullName` и `first, last, role string` у `Card`. Во втором случае тип
`string` относится ко всем трём именам.

## Аргументы по порядку

Когда параметров несколько, вызов передаёт столько же аргументов через запятую.
Аргументы распределяются по местам: первый аргумент получает первый параметр
списка, второй аргумент — второй параметр. В вызове `pair("чай", "кофе")`
параметр `first` получает `"чай"`, а параметр `last` — `"кофе"`.

Имена параметров в вызове не пишутся. В Go нельзя передать аргумент, назвав
параметр по имени: вызов задаёт только порядок значений. Поэтому имя параметра
не говорит, какое слово в нём окажется. Параметр `first` получит первый аргумент
вызова, каким бы словом тот ни был.

Результат вызова функции с несколькими параметрами предсказывают в три шага:

1. Сопоставьте аргументы с параметрами по местам в списке.
2. Прочитайте выражение после `return`: какие параметры и литералы в нём
   склеиваются и в каком порядке.
3. Подставьте в это выражение значения параметров из первого шага.

Для вызова `pair("чай", "кофе")` из примера выше шаги дают такой ответ. Первый
шаг: `first` получает `"чай"`, `last` получает `"кофе"`. Второй шаг: выражение
`first + " и " + last` склеивает сначала `first`, затем литерал с «и», затем
`last`. Третий шаг: в начале строки стоит слово `чай`, в конце — слово `кофе`.
Ровно это и показывает вывод примера.

При вызове значение аргумента копируется в параметр, и в теле функции эта копия
доступна под именем параметра; что из этого следует, разбирает урок 6.6.

В упражнении порядок аргументов важен у `FullName`. Скрытый тест вызывает её
дважды, и во второй раз передаёт те же слова в обратном порядке.

## Аргументов по умолчанию нет

Что будет, если аргументов меньше, чем параметров? Функция `join` в примере
ниже объявляет три параметра, а `main` передаёт ей два аргумента. Предположите,
соберётся ли программа и что получил бы третий параметр.

```go
@broken missing-argument
```

Программа не соберётся. Под кодом показано начало сообщения без места в файле.
Целиком сборка печатает три строки:

- `./main.go:10:25: not enough arguments in call to join` — «недостаточно
  аргументов в вызове `join`»; строка 10 — строка с этим вызовом;
- `have (string, string)` — «есть»: типы аргументов, которые передал вызов;
- `want (string, string, string)` — «нужно»: типы параметров, которые объявила
  функция.

Компилятор не подставляет вместо недостающего аргумента пустую строку или
другое значение. У параметров в Go нет значений по умолчанию: вызов функции с
таким списком параметров, как в этом уроке, передаёт аргумент для каждого
параметра. Ошибку находит сборка, поэтому программа не создаётся и не
запускается.

Пустая строка и пропущенный аргумент — разные вещи. Литерал `""` — строка без
символов, и это обычное значение, которое можно передать явно. Вызов
`join("а", "б", "")` передаёт три аргумента, и параметр `right` получает пустую
строку. Так же вызов `wrap("")` из первого раздела вернёт две ёлочки подряд:
параметр `word` получил строку без символов, и между ёлочками склеивать нечего.
Пропущенный аргумент останавливает сборку, а пустая строка — законный аргумент,
с которым функция работает как с любой другой строкой.

Сравните два сообщения сборки из этого урока. `missing return` указывает на
конец тела функции и говорит о результате: исправлять нужно тело. Сообщение
`not enough arguments in call to` указывает на вызов и говорит об аргументах:
исправлять нужно вызов, добавив недостающий аргумент. Номер строки в начале
сообщения показывает, куда смотреть.

Когда сборка отказала, решение «что исправлять» принимают по порядку:

1. Прочитайте начало сообщения: имя файла, номер строки и позицию. Откройте эту
   строку.
2. Посмотрите, что на ней стоит. В примере с `shout` это закрывающая фигурная
   скобка тела: ошибка связана с тем, чем тело заканчивается. В примере с `join`
   это строка в `main` с вызовом `join("а", "б")`: ошибка связана с вызовом.
3. Прочитайте текст после позиции. `missing return` значит: у функции объявлен
   результат, а тело не отдаёт значение. Добавьте в конец тела `return` с
   выражением нужного типа; ещё один вызов печати эту ошибку не исправит.
   `not enough arguments in call to` значит: вызов передал меньше значений, чем
   объявлено параметров.
4. Для недостающего аргумента сравните строки `have` и `want`. В примере в
   `have` два типа, в `want` три, значит, не хватает одного аргумента, и это
   третий — `right`. Решите, какое значение ему нужно, и допишите его в вызов.
   Если по смыслу третьей части нет, передайте пустую строку `""` явно.

После исправления запустите программу снова: если в файле есть другие ошибки,
сборка сообщит и о них.

## Почему main выглядит так

Теперь можно прочитать объявление точки входа из урока 1.3 — `func main()`. Это
такое же объявление функции, как у `wrap`: слово `func`, имя, список параметров
и тело. Список параметров пуст — между круглыми скобками ничего нет. Типа
результата нет — между `)` и `{` ничего не стоит. Значит, `main` не получает
аргументов и не возвращает результата.

Вызов `main` в программе не пишут. Её вызывает среда исполнения Go — служебный
код, который работает внутри каждой запущенной программы на Go. В уроке 1.3
говорилось, что запущенная программа сначала подготавливается к работе, а затем
вызывает `main`; этот вызов делает среда исполнения. Когда `main` завершается,
завершается и программа.

Спецификация языка требует, чтобы пакет `main` объявлял функцию `main`, которая
не принимает аргументов и не возвращает значения. Почему форма именно такая,
спецификация не объясняет. Курс объясняет её через то, кто передаёт аргументы и
кто получает результат. Аргументы функции передаёт вызывающий код, а среда исполнения вызывает
`main` без аргументов: параметрам `main` неоткуда было бы получить значения.
Результат получает вызывающий код, а после возврата из `main` программа
завершается, и принять результат некому.

В примере ниже у `main` появился параметр `name`. Предположите, что сделает
сборка.

```go
@broken main-with-params
```

Сборка печатает `./main.go:5:6: func main must have no arguments and no return values`
— «функция `main` не должна иметь ни аргументов, ни возвращаемых значений».
Позиция 5:6 — имя `main` в объявлении. В сообщении стоит слово «аргументы»,
хотя речь о параметрах объявления: спецификация тоже описывает форму `main`
словами «не принимает аргументов». Тем же текстом сборка отвергает и
объявленный результат, например `func main() string`. Форму `main` проверяет
компилятор, поэтому программа с такой `main` не создаётся, и вопрос, что получил
бы параметр `name`, не возникает.

## Вызов своей функции

Функцию своего пакета вызывают по имени, без квалификатора. В уроке 1.6 перед
`ToUpper` стояло `strings.`: функция объявлена в другом пакете, а обычный импорт
даёт файлу только имя пакета. Функция `wrap` объявлена в том же пакете `main`,
что и вызывающая её функция `main`, поэтому вызов записан просто
`wrap("функция")`.

Результат одного вызова можно передать аргументом в другой вызов. Так уже было в
`fmt.Println(wrap("функция"))`. Ниже одна своя функция пользуется другой.

```go

### Example: `03-compose`

Источник: `examples/03-compose/`

```go
package main

import "fmt"

func quote(word string) string {
	return "«" + word + "»"
}

func cite(word string) string {
	return "см. " + quote(word)
}

func main() {
	fmt.Println(cite("функция"))
}

```
```

Программа работает так:

1. `main` вызывает `cite("функция")`. Параметр `word` функции `cite` получает
   строку `"функция"`.
2. Тело `cite` вычисляет `"см. " + quote(word)`. Чтобы склеить две строки,
   нужна правая часть, поэтому сначала выполняется вызов `quote(word)`. Его
   аргумент — значение параметра `word` функции `cite`, и получает это значение
   параметр `word` функции `quote`.
3. `quote` возвращает слово в ёлочках. Этот результат становится правой частью
   `+` в теле `cite`.
4. `cite` приклеивает `"см. "` перед ним и возвращает получившуюся строку в
   `main`.
5. `main` передаёт строку в `fmt.Println`, и только здесь она печатается. Ни
   `quote`, ни `cite` ничего не печатают.

Сведите эти шаги к тому, что каждая функция получает и что отдаёт. `cite`
получает одно значение — строку `"функция"` из `main` — и отдаёт одно значение:
строку, где перед словом в ёлочках стоит `см. `. `quote` получает одно значение
— ту же строку `"функция"`, но уже от `cite`, — и отдаёт слово в ёлочках, тоже
в `cite`. Сама `main` аргументов не получает, зато получает результат
`cite` и передаёт его в `fmt.Println`. Результат `quote` до `main` отдельно не
доходит: его забирает `cite` и встраивает в свою строку. Вызовы вложены: `quote`
начинается позже `cite`, а завершается раньше, потому что `cite` ждёт её
результат, чтобы закончить своё выражение.

У обеих функций параметр назван `word`. Значение попадает в `quote` не из-за
одинаковых имён, а через аргумент вызова `quote(word)`. Если переименовать
параметр функции `quote` в её списке параметров и в её теле, результат не
изменится.

Построение функции из вызовов других функций называют **композицией**. Тот же
вывод дала бы `cite`, записанная без вызова `quote`: `return "см. «" + word + "»"`.
По выводу программы нельзя узнать, какой из двух записей получена строка:
одинаковые байты вывода ничего не говорят о том, как устроено тело функции.

Зачем тогда вызывать `quote`? Правило «слово в ёлочках» записано в одном месте.
Если ёлочки понадобится заменить другими кавычками, достаточно поправить
литералы в `quote`, и результат `cite` изменится вместе с ней. В записи без
вызова те же ёлочки повторены второй раз, и при правке одну из копий легко
забыть. Композицию выбирают ради такой поддержки кода; ни компилятор, ни
проверка вывода её не требуют.

## Своё экспортируемое имя

Все функции в примерах названы со строчной буквы: `wrap`, `pair`, `quote`,
`cite`. Их вызывает только код того же пакета `main`, поэтому экспортировать их
не нужно.

В заготовке упражнения каждый файл начинается строкой `package greeting`. Пакет
называется не `main`, значит, это не программа: `go run .` его не запустит
(урок 1.3), и функции `main` в нём нет. Функции такого пакета вызывает другой
код. В упражнении это скрытый тест.

Объявления в заготовке читаются так же, как объявление `wrap`. Возьмите
`func Card(first, last, role string) string`. Имя функции — `Card`. Параметров
три, все типа `string`, в свёрнутой записи. Результат — одна строка. Тело —
`return "" // TODO`. Функция возвращает пустую строку `""`, а текст после `//` —
комментарий, пометка для вас. Заготовка собирается именно потому, что в каждом
теле уже есть `return` с выражением. Заменять нужно выражение `""` после
`return`.

Две другие сигнатуры заготовки читаются тем же способом, и каждая отвечает на
три вопроса: сколько значений передаёт вызов, под какими именами тело их
получает и что функция отдаёт.

- `func Greet(name string) string`: вызов передаёт одну строку, тело получает
  её под именем `name`, функция отдаёт одну строку. Всё, что есть у `Greet` для
  построения результата, — значение `name` и литералы, которые вы запишете в
  выражении.
- `func FullName(first, last string) string`: вызов передаёт две строки, первая
  попадает в `first`, вторая — в `last`, функция отдаёт одну строку. В вызове
  `FullName("Иван", "Петров")` параметр `first` получает `"Иван"`, а `last` —
  `"Петров"`; если те же слова передать в обратном порядке, значения параметров
  тоже поменяются местами.
- `func Card(first, last, role string) string`: вызов передаёт три строки по
  местам `first`, `last`, `role`, функция отдаёт одну строку. В теле `Card`
  доступны не только её параметры: так же, как `cite` вызывает `quote`, код
  пакета `greeting` может вызвать `Greet` и `FullName` без квалификатора.

Какие именно строки должны получиться, записано в постановке упражнения. Из
сигнатур видно другое: из каких значений их можно собрать и что у каждой
функции результат ровно один.

Скрытый тест лежит в отдельном пакете `greeting_test` и вызывает ваши функции с
квалификатором — `greeting.Greet(...)`, так же как программа урока 1.6
вызывала `strings.ToUpper`. Из другого пакета доступны только экспортируемые
имена, то есть имена с заглавной буквы. Поэтому функции упражнения называются
`Greet`, `FullName` и `Card`: это ваши первые экспортируемые имена. Если бы
функция называлась `greet`, тест не смог бы к ней обратиться, и сборка теста
отказала бы. Как написать свой тест, разбирает урок 1.12.

# Упражнение: функции пакета greeting

## Что сдать

Заготовка — пакет `greeting`: файл `go.mod` и три файла с кодом, `greet.go`,
`fullname.go` и `card.go`. В каждом файле с кодом уже объявлена одна
экспортируемая функция с результатом `string`:

- `func Greet(name string) string`
- `func FullName(first, last string) string`
- `func Card(first, last, role string) string`

Тело каждой функции — заглушка `return "" // TODO`: функция возвращает пустую
строку. Объявления писать не нужно, они готовы. В каждой функции замените
пустую строку `""` после `return` выражением из параметров, строковых литералов
и оператора `+`, чтобы функция возвращала строку из раздела своей задачи ниже.
Комментарий `// TODO` можно удалить.

Функции только возвращают строку и ничего не печатают. Вызовы `fmt.Println` и
импорт `fmt` в этом пакете не нужны: печатать результат будет тот код, который
функцию вызывает.

## Что оставить без изменений

Не меняйте `go.mod`, строку `package greeting`, имена функций, списки
параметров и тип результата. Функции вызывает скрытый тест из отдельного пакета
`greeting_test`. Он обращается к ним с квалификатором — `greeting.Greet`,
`greeting.FullName`, `greeting.Card`, — передаёт столько аргументов, сколько
параметров в заготовке, и ждёт результат типа `string`. Поэтому:

- имя со строчной буквы тест не увидит: из другого пакета доступны только
  экспортируемые имена, и сборка теста откажет;
- если изменить число параметров, например оставить у `Card` два, вызов теста
  с тремя аргументами не соберётся: число аргументов в вызове обязано совпасть
  с числом параметров в объявлении;
- если удалить `return`, сборка откажет с сообщением `missing return`.

## Что проверяется, а что нет

Скрытые тесты вызывают ваши функции и сравнивают возвращённые строки с эталоном
символ в символ, включая пробелы и знаки препинания:

- `TestGreet` — `Greet` на двух разных именах;
- `TestFullName` — `FullName` на двух парах аргументов; во второй паре те же
  слова стоят в обратном порядке;
- `TestCard` — `Card` на двух тройках аргументов;
- `TestFunctionsDoNotPrint` — общий тест трёх функций. Он перехватывает
  стандартный вывод, вызывает `Greet`, `FullName` и `Card` и требует, чтобы
  перехваченный вывод остался пустым.

Решение, которое печатает верную строку и возвращает её же, проверку не
пройдёт: `TestFunctionsDoNotPrint` найдёт напечатанный текст. Решение, которое
печатает строку и оставляет `return ""`, провалит и тесты значений, и общий
тест.

Общий тест перехватывает только стандартный вывод — тот, куда пишет
`fmt.Println`. Поток ошибок и встроенную функцию `println` он не видит. Функциям
упражнения они не нужны, и требование «ничего не печатать» проверяется только
для стандартного вывода.

Тесты получают возвращённые значения и перехваченный вывод, но не текст
решения. Порядок записи частей выражения, свёрнутая или развёрнутая запись
параметров и то, вызывает ли `Card` другие функции пакета, проверка не
различает.

1. Замените заглушку в поле кода задачи на странице упражнения.
2. Нажмите «Проверить».
3. Прочитайте ответ проверки, исправьте код и проверьте снова.

Ниже описаны два вида ответа проверки.

Сообщение сборки с местом в файле значит, что код не собрался и тесты не
запускались. Откройте строку, которую называет сообщение. Например,
`missing return` означает, что из тела функции с результатом пропал `return`.

Строка `--- FAIL:` с именем теста и сообщение под ней значат, что код собрался,
но функция вернула другую строку или что-то напечатала. Сообщение теста значений
называет вызов, ожидаемую строку и полученную, например
`Greet("Иван"): ожидалось "Привет, Иван!" — получено ""`. Сравните две строки в
кавычках слева направо и найдите первое расхождение. Сообщение общего теста
цитирует в кавычках текст, который функции напечатали.

Пакет `greeting` — не программа: он называется не `main`, и функции `main` в
нём нет. Команда `go run .` в каталоге заготовки его не запустит (урок 1.3),
поэтому проверяйте решение кнопкой «Проверить».

## Greet

`Greet` возвращает приветствие для переданного имени:

- `Greet("Иван")` возвращает `Привет, Иван!`;
- `Greet("Ольга")` возвращает `Привет, Ольга!`.

После запятой стоит ровно один пробел, перед восклицательным знаком пробела нет.

## FullName

`FullName` возвращает два переданных слова через один пробел, в порядке
аргументов:

- `FullName("Иван", "Петров")` возвращает `Иван Петров`;
- `FullName("Петров", "Иван")` возвращает `Петров Иван`.

## Card

`Card` возвращает приветствие по полному имени и роль:

- `Card("Иван", "Петров", "гофер")` возвращает
  `Привет, Иван Петров! Роль: гофер`;
- `Card("Анна", "Смирнова", "автор")` возвращает
  `Привет, Анна Смирнова! Роль: автор`.

Начало результата — то же приветствие, которое вернула бы `Greet` для полного
имени из `FullName`. Ожидаемое решение собирает результат из вызовов этих двух
функций своего пакета. Прямое склеивание тех же частей без вызовов даёт те же
байты и тоже проходит проверку: `TestCard` видит строку, а не то, как она
собрана. Почему вызовы всё же лучше, объясняет раздел разбора «Card через свои
функции и через прямое склеивание»; читайте его после попытки.

# Подсказки

# Подсказки

Подсказки читаются по порядку: сначала первая, и только если она не помогла, —
вторая. Готового решения нет ни в одной из них.

## Greet

**Ступень 1.** Проверка сравнивает строку, которую вернула функция, и требует,
чтобы функция ничего не печатала. Посмотрите, что стоит после `return` сейчас:
пустая строка `""`, поэтому сообщение теста говорит, что получено `""`.
Сравните две строки из постановки: какая часть в них меняется вместе с
аргументом, а какая остаётся одинаковой для любого имени?

**Ступень 2.** Операция — `+` на строках: он склеивает постоянный текст и
значение параметра `name`. В постановке есть текст, который стоит до имени, и
знак, который стоит после него. Пробел после запятой — часть литерала перед
именем: сам `+` пробелов не добавляет.

## FullName

**Ступень 1.** Результат зависит от порядка аргументов: во втором вызове из
постановки те же слова переданы в обратном порядке, и в результате они тоже
переставлены. Имена `first` и `last` нужны телу, чтобы обращаться к полученным
значениям. Какое слово окажется в каждом параметре, определяет только место
аргумента в вызове.

**Ступень 2.** Операция — `+`. Между двумя параметрами стоит литерал ровно из
одного пробела. Части выражения идут в том же порядке, что параметры в
объявлении. Если
тест сообщает, что слова получились переставленными, сравните порядок
параметров в выражении с их порядком в списке параметров.

## Card

**Ступень 1.** Две другие функции пакета уже возвращают части ответа: полное имя
и приветствие для имени. Функцию своего пакета вызывают без имени пакета. Сверьте формат
из постановки с тем, что возвращают `Greet` и `FullName`. Если `TestCard` падает
вместе с `TestGreet` или `TestFullName`, сначала исправьте эти функции.

**Ступень 2.** Операции — вызовы своих функций и `+`: результат одного вызова
можно передать аргументом в другой. Контрольные символы — пробел перед словом
`Роль:` и пробел после двоеточия. Прямое склеивание тех же частей без вызовов
тоже пройдёт проверку: тест видит только возвращённую строку.

# Повторение

# Разбор неверных решений

Читайте этот разбор после попытки: в нём показаны готовые выражения для
функций упражнения.

## Печать вместо возврата

<!-- review:print-vs-return -->

Частая ошибка в этом упражнении — вызвать `fmt.Println` внутри функции. У неё
три формы, и проверка даёт на них разный ответ.

**Функции печатают строку и оставляют `return ""`.** Пакет собирается, но каждая
функция возвращает пустую строку. Падают все четыре теста: `TestGreet`,
`TestFullName` и `TestCard` получают `""` вместо ожидаемой строки, а
`TestFunctionsDoNotPrint` находит напечатанный текст.

**Функции печатают строку и возвращают её же.** Например, `Greet` сначала
передаёт приветствие в `fmt.Println`, а затем возвращает то же выражение. Тесты
значений проходят: возвращённые строки верны. Падает только
`TestFunctionsDoNotPrint`, и его сообщение цитирует перехваченный вывод. Строк в
этом выводе семь, а не три. `Greet("Иван")` и `FullName("Иван", "Петров")`
печатают по одной строке. `Card("Иван", "Петров", "гофер")` печатает пять: свою
карточку и ещё четыре строки. Она вызывает `FullName` и `Greet` дважды — один
раз для печати и второй раз для `return`, — и каждый из этих четырёх вызовов
печатает свою строку. Каждый вызов функции, в теле которой есть печать, печатает
заново.

**Функция только печатает, а `return` удалён.** До тестов дело не доходит:
сборка отказывает с сообщением `missing return`, потому что функция с
результатом обязана вернуть значение.

Исправление во всех трёх случаях одно: убрать печать из тела и оставить после
`return` выражение, которое строит нужную строку. Функция возвращает строку, а
печатать её будет тот код, которому нужен вывод.

## Card через свои функции и через прямое склеивание

<!-- review:composition-not-observed -->

Эталонное решение собирает `Card` из двух других функций пакета:
`return Greet(FullName(first, last)) + " Роль: " + role`.

Прежде чем читать дальше, проследите по этой записи вызов
`Card("Анна", "Смирнова", "автор")` и запишите ответ из четырёх шагов. В каждом
шаге назовите, какая функция получает значение, какое именно, и что она
возвращает или делает с результатом. Одной итоговой строки недостаточно: ответ
должен назвать каждое промежуточное значение и того, кто его получает.

Проверьте свой ответ:

1. `FullName` получает первые два аргумента `Card` — `"Анна"` и `"Смирнова"` — и
   возвращает `Анна Смирнова`.
2. `Greet` получает единственный аргумент — строку, которую вернула `FullName`, —
   и возвращает `Привет, Анна Смирнова!`.
3. `Card` склеивает этот результат с литералом `" Роль: "` и значением параметра
   `role`, то есть `"автор"`, и возвращает `Привет, Анна Смирнова! Роль: автор`.
4. Ни один из трёх вызовов ничего не печатает. Напечатать итоговую строку может
   тот код, который вызвал `Card`, если ему нужен вывод. Скрытый тест её не
   печатает, а сравнивает с эталоном.

Прямое склеивание — `return "Привет, " + first + " " + last + "! Роль: " + role`
— возвращает те же байты на обеих тройках теста и проходит все четыре теста.
`TestCard` видит только возвращённую строку, а не то, как она собрана. Поэтому
по успешной проверке нельзя заключить, что `Card` вызывает `Greet` и
`FullName`, и нельзя заключить обратное.

Композиция всё же лучше. Текст `Привет, ` и восклицательный знак записаны в
одном месте — в `Greet`, а пробел между именем и фамилией — в `FullName`. Если
формат приветствия изменится, правка `Greet` сразу изменит и результат `Card`.
При прямом склеивании тот же текст повторён в двух функциях, и правку легко
внести только в одну из них.

## Слова в обратном порядке

`FullName` возвращает `last + " " + first`. Результат похож на правильный: те же
два слова через один пробел. Ловит его `TestFullName`: для вызова
`FullName("Иван", "Петров")` он ожидает `Иван Петров`, а получает
`Петров Иван`. Вслед за ним падает и `TestCard`, потому что `Card` получает
полное имя от `FullName`.

Порядок слов в результате задаёт порядок частей выражения после `return`, а
значения в параметрах задаёт порядок аргументов вызова. Исправление — склеивать
параметры в том порядке, в каком они объявлены: `first`, пробел, `last`.

Постоянная строка вместо склеивания, например `return "Иван Петров"`, тоже не
пройдёт: второй вызов теста передаёт те же слова в обратном порядке и ждёт
`Петров Иван`.

## Недостающие части строки

`Greet`, которая возвращает только `name`, теряет текст до имени и
восклицательный знак после него; её ловит `TestGreet`. `Card`, которая
возвращает только `Greet(FullName(first, last))`, теряет текст ` Роль: ` и роль;
её ловит `TestCard`.

Сверяйте литералы с постановкой посимвольно: пробел после запятой,
восклицательный знак, пробел перед словом `Роль:` и пробел после двоеточия.
Если `TestCard` падает вместе с `TestGreet` или `TestFullName`, сначала
исправьте их: `Card` получает часть результата от этих функций.

# Проверочные вопросы

## Вопрос 1

Функция `hello` печатает приветствие с переданным именем и возвращает пустую
строку. Функция `main` передаёт результат вызова `hello("Иван")` в
`fmt.Println`.

```go
@quiz _quiz/01-print-and-return-empty
```

Что напечатает программа?

Варианты ответа:

- A. Одну строку — приветствие с именем: печать внутри `hello` и есть её
  результат, поэтому `main` печатает то же самое один раз.
- B. Две строки: сначала приветствие с именем, затем пустую строку.
- C. Две одинаковые строки с приветствием: первую печатает `hello`, вторую —
  `main`, которая получила напечатанный текст как результат вызова.
- D. Одну пустую строку: у функции с результатом выполняется только `return`, а
  вызов печати в её теле пропускается.

Прежде чем смотреть ответ, опишите по шагам, что происходит при вызове
`hello("Иван")` и какое значение получает `fmt.Println` в `main`.

**Правильный ответ: B.**

Во время вызова `hello` печатает приветствие, а возвращает пустую строку;
`fmt.Println` в `main` получает эту пустую строку и печатает только перевод
строки. Вариант A считает напечатанный текст результатом функции, хотя
вызывающий код получает лишь значение из `return`. Вариант C тоже принимает
печать за результат и приписывает `main` текст, которого она не получала.
Вариант D пропускает вызов печати, хотя он стоит в теле перед `return` и
выполняется при каждом вызове `hello`.

## Вопрос 2

Функция `pair` та же, что в разделе «Свёрнутый список параметров»: параметры
`first, last string`, результат — `first + " и " + last`. Но `main` передаёт
аргументы в другом порядке: сначала `"кофе"`, потом `"чай"`.

```go
@quiz _quiz/02-swapped-args
```

Что напечатает программа?

Варианты ответа:

- A. Ту же строку, что пример из раздела: порядок слов в результате задают имена
  `first` и `last`, а не порядок аргументов в вызове.
- B. Строку, в начале которой стоит `кофе`, затем ` и `, в конце — `чай`:
  первый аргумент получает первый параметр.
- C. Ничего: сборка откажет, потому что слово `"кофе"` передано в параметр,
  предназначенный для первого слова пары.

Прежде чем смотреть ответ, сопоставьте каждый аргумент вызова с параметром и
подставьте значения в выражение после `return`.

**Правильный ответ: B.**

Аргументы распределяются по местам, поэтому `first` получает `"кофе"`, а `last`
получает `"чай"`, и выражение склеивает их в этом порядке. Вариант A ищет связь
между словом и именем параметра, но в вызове имён параметров нет — есть только
порядок значений. Вариант C приписывает компилятору проверку смысла: он
проверяет число и типы аргументов, а оба аргумента — строки.

## Вопрос 3

Функция `join` объявляет три параметра типа `string`, а `main` вызывает её с
двумя аргументами.

```go
@quiz _broken/missing-argument
```

Что сделает `go run .` в каталоге с этой программой?

Варианты ответа:

- A. Соберёт и запустит программу: параметр `right` получит пустую строку, и
  напечатаны будут буквы `а` и `б` подряд.
- B. Соберёт программу, но при запуске она остановится с ошибкой: в момент
  вызова у параметра `right` нет значения.
- C. Не соберёт программу и сообщит `not enough arguments in call to join`:
  вызов обязан передать аргумент для каждого параметра.
- D. Не соберёт программу и сообщит `missing return`: без третьей строки функция
  не может вернуть результат.

Прежде чем смотреть ответ, объясните, чем пропущенный аргумент отличается от
пустой строки `""`, переданной третьим аргументом.

**Правильный ответ: C.**

У параметров в Go нет значений по умолчанию, и вызов с недостающим аргументом
сборка отвергает до запуска. Вариант A подставляет пустую строку сам, хотя её
нужно передать явно, записав `""` в вызове. Вариант B переносит ошибку на время
работы программы, но программа с таким вызовом не создаётся. Вариант D путает
сообщения: `missing return` относится к телу без `return`, а тело `join` значение
возвращает.

## Вопрос 4

Функция `main` объявлена с параметром `name string` и печатает его.

```go
@quiz _broken/main-with-params
```

Что сделает сборка?

Варианты ответа:

- A. Соберёт программу; при запуске `name` получит пустую строку, и программа
  напечатает только перевод строки.
- B. Соберёт программу, но при запуске та остановится с ошибкой: среда
  исполнения Go не передаёт `main` аргументов.
- C. Откажет с сообщением `func main must have no arguments and no return values`:
  точка входа не принимает аргументов и не возвращает значения.
- D. Откажет с сообщением `not enough arguments in call to main`: при запуске
  `main` вызывается без аргумента для `name`.

Прежде чем смотреть ответ, объясните, кто вызывает `main` и почему у неё нет
параметров.

**Правильный ответ: C.**

Спецификация требует от `main` пустого списка параметров и отсутствия
результата, и компилятор проверяет эту форму при сборке. Вариант A ждёт значения
по умолчанию, которых у параметров нет, а до запуска дело не доходит. Вариант B
верно говорит, что среда исполнения не передаёт `main` аргументов, но ошибку
находит компилятор, и программа не создаётся. Вариант D описывает вызов в вашем
коде, а вызов `main` в программе не записан: сборка проверяет объявление.

## Вопрос 5

В программе две функции с одинаковыми телами: `pair` со свёрнутым списком
`first, last string` и `pairLong` с развёрнутым `first string, last string`.
Функция `main` вызывает обе с аргументами `"чай"` и `"кофе"`.

```go
@quiz _quiz/03-two-forms
```

Что напечатает программа и почему?

Варианты ответа:

- A. Две одинаковые строки: у обеих функций одна сигнатура — два параметра типа
  `string` и результат `string`, а свёрнутая запись только убирает повтор типа.
- B. Ничего: сборка откажет, потому что в одном пакете нельзя объявить две
  функции с одинаковой сигнатурой.
- C. Ничего: сборка откажет у `pair`, потому что в свёрнутой записи тип `string`
  относится только к `last`, а у `first` типа нет.
- D. Две разные строки: в свёрнутой записи оба параметра `pair` получают первый
  аргумент, а в развёрнутой каждый получает свой.

Прежде чем смотреть ответ, объясните, сколько параметров и какого типа объявляет
каждая из двух записей.

**Правильный ответ: A.**

Тип после последнего имени относится ко всем именам перед ним, поэтому обе
записи объявляют два параметра типа `string`, и обе функции склеивают одни и те
же аргументы одинаково. Вариант B путает имя с сигнатурой: в пакете нельзя
дважды объявить одно имя, а одинаковая сигнатура у функций с разными именами
допустима. Вариант C читает тип только у ближайшего имени. Вариант D
смешивает запись типа с распределением аргументов: каждое имя в списке — свой
параметр, и аргументы по-прежнему распределяются по местам.
