## Инструкция для нейросети

Ты получаешь материалы одного урока курса по Go.

Твоя задача — **не пересказать исходный материал целиком**, а подготовить
компактный, точный конспект, по которому студент сможет:

1. понять основные концепции урока;
2. вспомнить синтаксис и правила Go, которые здесь изучаются;
3. ответить на проверочные вопросы из раздела «Проверочные вопросы»;
4. решить типовые практические задачи по этой теме;
5. не перепутать похожие понятия и исключения.

### Правила подготовки ответа

- Сохраняй техническую точность.
- Не выкидывай правила, которые могут быть проверены в quiz.
- Особое внимание уделяй причинам: **почему ответ правильный**, а остальные
  варианты неправильны.
- Если в quiz есть конкретный сценарий, команду, код или вывод программы —
  обязательно объясни соответствующее правило.
- Не пересказывай очевидные вводные фразы и организационную информацию.
- Не добавляй информацию, которой нет в предоставленных материалах, если она
  не нужна для объяснения приведённого материала.
- Код из примеров используй как источник конкретных правил и поведения Go.
- Не нужно разбирать каждую строку примера, если это не помогает ответить
  на вопрос quiz.
- Сохраняй названия команд, функций, типов, операторов и других сущностей
  точно.
- Если есть важное исключение или типичная ошибка — вынеси её отдельно.

# Раскладка кода по файлам и подпакетам

В уроке 1.7 все функции программы лежали в одном файле `main.go`. Пока функций
две или три, так удобно. Теперь представьте программу, которая печатает
карточку человека: приветствие по имени и роль. В ней уже три правила: как
строится приветствие, как оформляется роль и как из них собирается карточка. К
ним добавляется `main`. Когда таких правил становится больше, в одном файле
трудно найти нужное место. Поэтому код раскладывают по нескольким файлам, а
обособленную часть программы — в отдельный пакет в подкаталоге.

От того, где лежит функция, зависит, как записан её вызов. Функцию из
соседнего файла вызывают иначе, чем функцию из подкаталога: для функции из
подкаталога нужна строка импорта, и путь в ней записывают целиком. В каждой
раскладке важно одно и то же: какие имена видны без импорта и когда перед
именем функции нужно имя пакета.

Для этого понадобятся факты из трёх предыдущих уроков. Из урока 1.4: путь
модуля — строка после `module` в `go.mod`, и с него начинается путь импорта каждого пакета модуля. Из
урока 1.6: пакет — группа файлов `.go` из одного каталога, которую компилятор
переводит как одно целое; из другого пакета доступно только имя с заглавной
буквы, и вызывают его с именем пакета перед точкой. Из урока 1.7: как читать
объявление функции и почему функцию своего пакета вызывают просто по имени.

Код в этом уроке писать не нужно: все деревья файлов уже готовы, под кодом
каждого примера показан его вывод или сообщение сборки. Из каждого примера на
странице показан только файл `main.go`. Какие ещё файлы и подкаталоги лежат
рядом, перечисляет комментарий над строкой `package`. Содержимое остальных
файлов описано в тексте: все они короткие, по пять–семь строк.

## Один пакет — несколько файлов

В каталоге примера `01-two-files` лежат два файла:

- `main.go` — функция `main`, её код показан ниже;
- `greeting.go` — функция `greeting`.

Файл `greeting.go` на странице не показан, поэтому вот всё его содержимое.
Первая строка — `package main`. Дальше идёт объявление
`func greeting(name string) string`. Тело состоит из одной инструкции:
`return "Здравствуйте, " + name`. Прочитайте его так же, как функции урока 1.7:
параметр `name` получает строку, а функция возвращает эту строку, приклеив
перед ней слово приветствия, запятую и пробел. Импортов и вызовов печати в
файле нет.

В `main.go` функция `main` вызывает `greeting("Иван")` и передаёт результат в
`fmt.Println`. Строки импорта для `greeting` в этом файле нет, объявления
`greeting` тоже нет. Прежде чем смотреть вывод, предположите, соберётся ли
программа.

```go

### Example: `01-two-files`

Источник: `examples/01-two-files/`

```go
// В каталоге два файла одного пакета main: main.go и greeting.go.
// Функция greeting объявлена в соседнем файле; импорт для неё не нужен.
package main

import "fmt"

func main() {
	fmt.Println(greeting("Иван"))
}

```
```

Программа собирается и печатает приветствие для имени Иван. Вызов
`greeting("Иван")` записан так же, как вызов `wrap("функция")` в уроке 1.7, где
обе функции лежали в одном файле: только имя функции, без импорта и без имени
пакета перед точкой. Имя `greeting` начинается со строчной буквы, и это тоже не
помешало. Работу программы объясняют два правила.

**Какие файлы составляют пакет.** Оба файла лежат в одном каталоге, и оба
начинаются строкой `package main`. Команда `go` собирает обычные файлы `.go`
одного каталога в один пакет; это правило вы видели в уроке 1.3. Там же вы
видели, что два разных имени пакета в одном каталоге дают отказ сборки.
Документация Go так и описывает пакет: набор исходных файлов одного каталога,
которые компилируются вместе. Сама спецификация языка каталогов не требует.
Она только разрешает реализации требовать, чтобы все файлы пакета лежали в
одном каталоге, и команда `go` такое требование ставит.

**Где видно объявление.** По спецификации языка имена, объявленные в пакете
вне функций, доступны во всех файлах этого пакета. Функция `greeting`
объявлена вне других функций, значит, её имя видно и в `greeting.go`, и в
`main.go`. Для имён два файла одного пакета ведут себя как один текст,
разрезанный на две части: разрез не создаёт новой границы.

У этого сравнения есть предел: строка импорта действует только в том файле,
где записана. `main.go` импортирует `fmt`, потому что сам вызывает
`fmt.Println`. `greeting.go` ничего не печатает и потому ничего не
импортирует. Если бы функции в `greeting.go` понадобился пакет `fmt`, в этом
файле нужна была бы своя строка импорта.

Сколько пакетов в каталоге, определяют по строкам `package`, а не по числу
файлов. Два файла со строкой `package main` в одном каталоге — один пакет
`main`. Имя файла пакет не задаёт: `greeting.go` не создаёт пакет `greeting`,
это просто ещё один файл пакета `main`. Урок 1.3 уже показывал, что имя файла —
соглашение, а не условие сборки. «Первого» файла у пакета тоже нет. Команда
`go run .` получает каталог — точка означает текущий каталог — и собирает
все обычные файлы `.go` из него вместе.

Зачем тогда делить пакет на файлы? На вызовы между файлами разделение не
влияет, это и показал пример. Оно нужно людям, которые читают код: в
`greeting.go` лежит одна тема — правило приветствия, и её легко найти по имени
файла. Как разложить пакет по файлам, решает автор программы.

## Файл нельзя импортировать

Легко решить, что функцию из другого файла нужно подключать так же, как пакет
`fmt`: раз функция объявлена в `greeting.go`, этот файл надо импортировать в
`main.go`. Проверьте эту модель на тех же двух файлах. В сломанном примере
`import-file` файл `greeting.go` — точная копия файла из `01-two-files`. Файл
`main.go` отличается одной строкой: в скобочном импорте рядом с путём `"fmt"`
записан путь `"greeting.go"`. Прежде чем читать сообщение под кодом,
предположите, что сделает сборка.

```go
@broken import-file
```

Сборка отказывает. Сообщение `no required module provides package greeting.go`
значит «ни один требуемый модуль не предоставляет пакет `greeting.go`». В
полном выводе перед ним стоит место ошибки `main.go:8:2`: восьмая строка файла,
на которой записан путь `"greeting.go"`.

Прочитайте сообщение по словам. Слово `package` показывает, что искала команда
`go`: не файл, а пакет. Строку в кавычках после `import` она читает как путь
импорта, то есть как полное имя пакета из урока 1.4. По пути импорта команда
ищет пакет и модуль, в котором этот пакет лежит. Модуля, который
предоставлял бы пакет с путём `greeting.go`, не нашлось, и команда сообщает
именно об этом. Файл `greeting.go`, который лежит рядом с `main.go`, в этом
поиске не участвует: путь импорта называет пакет, а не файл. Точный текст
сообщения — вывод текущей версии команды `go`, язык его не обещает.

Что написать вместо такого импорта? Ничего. Если убрать из `main.go` путь
`"greeting.go"`, файл станет устроен так же, как `main.go` в `01-two-files`, и
программа соберётся. Функции соседнего файла того же пакета доступны по имени
без строки импорта. Импорт нужен только для другого пакета. Путь в нём тоже
называет пакет и заканчивается каталогом пакета, а не именем файла. Как
строится такой путь, объясняет раздел «Путь импорта: путь модуля плюс каталог».

## Подкаталог — другой пакет

Второй способ разложить код — подкаталоги. Каталог примера `02-profile`
устроен так:

- `main.go` — пакет `main`, код файла показан ниже;
- `profile/` — подкаталог с файлами пакета `profile`:
  - `greeting.go` — функция `Greeting`;
  - `card.go` — функция `Card`;
  - `label/` — подкаталог внутри `profile` с файлом пакета `label`:
    - `label.go` — функция `Label`.

Главное правило раздела: подкаталог с файлами `.go` — это другой пакет.
Команда `go` собирает в пакет обычные файлы `.go` одного каталога и не берёт в
него файлы из подкаталогов. Поэтому файлы из `profile/` не входят в пакет
`main` каталога `02-profile`. По той же причине `label.go` не входит в пакет
`profile`, хотя лежит внутри его каталога. У каждого каталога свой пакет, и
файлы каждого пакета начинаются своей строкой `package`.

Каталог, в котором лежат файлы пакета, называют **каталогом пакета**. Пакет,
каталог которого лежит внутри каталога другого пакета того же модуля,
называют **подпакетом**. В примере каталог `profile` лежит внутри каталога
пакета `main`, а каталог `label` — внутри каталога пакета `profile`. Значит,
`profile` и `label` — подпакеты. Слово «подпакет» говорит только о том, где
лежат каталоги. Подпакет — самостоятельный пакет, а не часть пакета из
каталога выше. Вложенность каталогов не даёт ни одному из двух пакетов
особого доступа к именам другого — это правило из урока 1.4.

Файл `label.go` на странице не показан. Его первая строка — `package label`.
Дальше идёт объявление `func Label(role string) string`, а тело —
`return "[" + role + "]"`: функция возвращает переданную роль в квадратных
скобках. Имя `Label` начинается с заглавной буквы, потому что функцию
вызывает код другого пакета — `profile` (урок 1.6).

Подкаталог называется `label`, и пакет в нём тоже называется `label`. Так
принято: имя пакета обычно совпадает с именем его каталога. Но это
соглашение, а не требование. Имя пакета задаёт строка `package` в его файлах.
В уроке 1.4 был пример, где в каталоге `tags` лежал пакет `labels`.

Файл `card.go` соединяет два пакета. Его первая строка — `package profile`.
Следующая строка кода — импорт:
`import "lesson/code-layout/examples/02-profile/profile/label"`. Дальше идёт
объявление `func Card(name, role string) string` со свёрнутым списком
параметров из урока 1.7. Тело функции —
`return Greeting(name) + " " + label.Label(role)`.

В теле два вызова, и записаны они по-разному:

- `Greeting(name)` — без имени пакета. Функция `Greeting` объявлена в соседнем
  файле `greeting.go` того же каталога, а оба файла начинаются строкой
  `package profile`. Это один пакет, как `main.go` и `greeting.go` в первом
  примере.
- `label.Label(role)` — с именем пакета перед точкой. Функция `Label`
  объявлена в подкаталоге, то есть в другом пакете. Строка импорта в `card.go`
  подключила этот пакет к файлу и дала файлу имя `label`: так пакет назван в
  своей строке `package label`. Через это имя и записан квалифицированный
  вызов.

Файл `greeting.go` из каталога `profile` устроен как `greeting.go` первого
примера, с двумя отличиями. Его первая строка — `package profile`, а имя
функции начинается с заглавной буквы: `func Greeting(name string) string`.
Тело то же самое: `return "Здравствуйте, " + name`.

Осталось прочитать `main.go`. Он импортирует два пакета скобочной формой из
урока 1.6: `"fmt"` и путь пакета `profile`. Пустая строка между путями на
импорт не влияет. Тело `main` вызывает `profile.Card("Иван", "гофер")`. Этот
вызов тоже записан с именем пакета перед точкой, потому что `Card` объявлена в
другом пакете. Прежде чем смотреть вывод, соберите строку по описаниям
файлов: что вернёт `Greeting`, что вернёт `Label` и как их склеит `Card`.

```go

### Example: `02-profile`

Источник: `examples/02-profile/`

```go
// В каталоге файл main.go, подкаталог profile с файлами greeting.go и card.go
// и вложенный подкаталог profile/label с файлом label.go — три пакета.
package main

import (
	"fmt"

	"lesson/code-layout/examples/02-profile/profile"
)

func main() {
	fmt.Println(profile.Card("Иван", "гофер"))
}

```
```

Программа печатает одну строку: приветствие для имени Иван, пробел и роль
`гофер` в квадратных скобках. Три пакета работают как одна программа: `main`
вызывает `Card` из пакета `profile`, а `Card` вызывает функции своего пакета и
пакета `label`. Весь путь вызовов разобран в разделе «Дерево, которое вы ещё
встретите».

## Путь импорта: путь модуля плюс каталог

Строки импорта в `main.go` и `card.go` длинные, но составлены они по правилу
урока 1.4. В каждой две части.

Первая часть — путь модуля. У всех примеров урока один `go.mod`: он лежит в
каталоге `examples/`, и строка `module` в нём — `lesson/code-layout/examples`.
Этот файл — ближайший `go.mod` для всех каталогов примеров урока, включая
сломанные, и для их подкаталогов: своего `go.mod` ни в одном из них нет.
Значит, `examples/` — корень модуля, и путь импорта любого пакета в этом
дереве начинается с `lesson/code-layout/examples`.

Вторая часть — путь каталога пакета от корня модуля. Отсчитывают его именно
от каталога с `go.mod`. Не от каталога примера и не от файла, в котором
записан импорт. Каталог пакета `profile` на диске — `examples/02-profile/profile`.
От корня модуля это `02-profile/profile`.

Части соединяют косой чертой:

- путь модуля — `lesson/code-layout/examples`;
- путь каталога от корня модуля — `02-profile/profile`;
- путь импорта — `lesson/code-layout/examples/02-profile/profile`, ровно
  строка из `main.go`.

Для пакета `label` путь каталога от корня модуля — `02-profile/profile/label`.
Путь импорта — `lesson/code-layout/examples/02-profile/profile/label`, как в
`card.go`. Обратите внимание: `card.go` лежит прямо над подкаталогом `label`,
но его строка импорта всё равно начинается с пути модуля. Путь импорта не
зависит от того, какой файл импортирует пакет. Если бы пакет `label`
понадобился файлу `main.go`, строка была бы той же.

Путь импорта, который начинается с пути модуля и продолжается путём каталога
пакета от корня модуля, в этом уроке называется **полным путём импорта**. У
каждого пакета модуля такой путь один. Части пути разделяет прямая косая
черта в любой системе (урок 1.4).

По полному пути команда `go` находит пакет так. Она ищет модуль, путь
которого стоит в начале строки. Здесь это `lesson/code-layout/examples`. Затем
она проверяет, есть ли пакет в каталоге модуля, который назван остатком строки,
— в `02-profile/profile`. Отсюда понятен и отказ из раздела «Файл нельзя
импортировать». Строка `greeting.go` не начинается с пути модуля, поэтому
модуля, который предоставлял бы такой пакет, у команды нет.

Короткий путь вроде `"profile"` не называет пакет вашего модуля. Без пути
модуля записывают пути пакетов стандартной библиотеки — `"fmt"` или
`"strings"` (урок 1.6). Путь пакета вашего модуля всегда начинается с пути
модуля. По той же причине не годится `"02-profile/profile"`: каталог указан
верно, но первой части нет.

Последний элемент пути импорта — имя каталога, а не имя пакета. В примере они
совпадают, но квалификатор `label.` в `card.go` берётся из строки
`package label`, а путь — из расположения каталога (урок 1.4).

Полный путь импорта своего пакета составляют в три шага:

1. От каталога пакета поднимитесь вверх до ближайшего `go.mod` и прочитайте в
   нём строку `module`.
2. Запишите путь от каталога с этим `go.mod` до каталога пакета, разделяя
   каталоги косой чертой.
3. Соедините путь модуля и путь каталога косой чертой.

## Относительных импортов нет

Кажется, что к соседнему подкаталогу можно указать путь короче: `./label`.
Точка здесь означает каталог, в котором лежит сам импортирующий пакет, а
дальше путь ведёт в его подкаталог `label`. Такой путь называют
**относительным**: он отсчитывается от места, где записан, а не от корня
модуля.

В сломанном примере `relative-import` лежат `main.go` и подкаталог `label` с
тем же файлом `label.go`, что в `02-profile`. Пакет на месте. Рабочая строка
импорта в этом примере была бы полным путём:
`import "lesson/code-layout/examples/_broken/relative-import/label"` — путь
модуля плюс путь каталога, как в предыдущем разделе. В `main.go` вместо неё
записан путь `"./label"`, других отличий нет. Прежде чем читать сообщение,
предположите, найдёт ли сборка пакет `label`, который лежит рядом.

```go
@broken relative-import
```

Сборка отказывает с сообщением
`"./label" is relative, but relative import paths are not supported in module mode`.
Оно значит: «`"./label"` — относительный путь, а относительные пути импорта в
модульном режиме не поддерживаются». Модульный режим знаком вам по уроку 1.2:
в нём команда `go` собирает пакеты как части модулей, и по умолчанию он
включён.

Пакет `label` лежит ровно там, куда указывает `./label`, и всё равно не
подключается. Значит, отказ вызван не отсутствием пакета, а формой пути:
команда `go` в модульном режиме не принимает относительный путь импорта.
Исправление — записать полный путь импорта.

У правила есть граница: так ведёт себя команда `go` в модульном режиме.
Спецификация языка сама не решает, как толковать путь импорта: это она
оставляет реализации. О работе без модулей урок ничего не утверждает. Для
пакетов вашего модуля вывод простой: путь в строке импорта всегда полный.

## Своё имя через границу пакета

В дереве `02-profile` вызовы проходят через границы двух видов, и правила для
них разные.

**Между файлами одного пакета** границы для имён нет. Имя, объявленное в
пакете вне функций, видно во всех файлах пакета — с любой первой буквой и без
имени пакета перед точкой. Два примера урока показывают это с двух сторон:

- в `01-two-files` функция `greeting` названа со строчной буквы, и `main.go`
  вызывает её из соседнего файла;
- в `02-profile` файл `card.go` вызывает `Greeting(name)` из соседнего
  `greeting.go` без квалификатора.

Заглавная буква в имени `Greeting` для этого вызова не нужна. Если назвать
функцию `greeting` и в объявлении, и в вызове, `card.go` вызовет её по тому
же правилу, что в `01-two-files`. Правило заглавной буквы легко перенести с
пакета на файл и решить, что соседнему файлу видны только заглавные имена. Это
ошибка: граница видимости — пакет, а не файл.

**Между разными пакетами** действует правило урока 1.6. Из другого пакета
доступно только имя с заглавной буквы. При обычной форме импорта, которую
разбирал урок 1.6, такое имя вызывают только с именем пакета перед точкой.
Поэтому в `card.go` записано `label.Label(role)`: функция объявлена в другом
пакете, её имя начинается с заглавной буквы, и перед именем стоит имя пакета.
Если бы имя функции в `label.go` начиналось со строчной буквы, `card.go` не
смог бы её вызвать. Если бы в `card.go` перед `Label` не было имени пакета,
сборка отказала бы, как в уроке 1.6 она отказала программе с вызовом
`ToUpper` без `strings.`.

**Модуль не отменяет границу пакета.** Пакет `label` лежит в том же модуле,
что `profile`: у них один `go.mod` и один путь модуля в начале путей импорта.
Одним пакетом это их не делает. Модуль — область `go.mod` из урока 1.4: он
задаёт начало путей импорта и версию языка для своих пакетов. Пакет — единица
видимости из урока 1.6: он решает, какие имена доступны без квалификатора. В
одном модуле бывает много пакетов, и между любыми двумя из них действует
граница пакета: импорт, заглавная буква, квалификатор.

**Вложенный каталог тоже не исключение.** Каталог `label` лежит внутри
каталога `profile`. Это не даёт пакету `profile` особого доступа к именам
`label`, а пакету `label` — к именам `profile`. Пакет `profile` пользуется
пакетом `label` так же, как пользовался бы любым другим пакетом.

К каждому вызову полезно задать один вопрос: где объявлена функция?

- В файле того же пакета — в том же каталоге, со строкой `package` с тем же
  именем. Тогда функцию вызывают просто по имени, и первая буква имени может
  быть любой.
- В другом пакете — в другом каталоге, в том числе в подкаталоге. Тогда в
  файле с вызовом нужна строка импорта с полным путём, имя функции должно
  начинаться с заглавной буквы, а вызов пишут с именем пакета перед точкой.

## Дерево, которое вы ещё встретите

Соберите разобранное на одном дереве — примере `02-profile` вместе с корнем
модуля. Такая раскладка — пакет `main` и пакеты в подкаталогах одного модуля
— понадобится и дальше: к ней вернутся урок 1.10, где читают документацию
пакета с подпакетом, и мини-проект 1.13. Остальные каталоги примеров урока в
списке опущены.

- `examples/` — корень модуля `lesson/code-layout/examples`:
  - `go.mod` — файл со строкой `module lesson/code-layout/examples`;
  - `02-profile/` — каталог пакета `main`:
    - `main.go` — импортирует `fmt` и
      `lesson/code-layout/examples/02-profile/profile`;
    - `profile/` — каталог пакета `profile`:
      - `greeting.go` — импортов нет;
      - `card.go` — импортирует
        `lesson/code-layout/examples/02-profile/profile/label`;
      - `label/` — каталог пакета `label`:
        - `label.go` — импортов нет.

Пакетов в дереве три, по одному на каталог с файлами `.go`: `main` в
`02-profile`, `profile` в `profile` и `label` в `label`. В пакете `profile` два
файла, в двух других пакетах — по одному.

Кто кого импортирует, видно по строкам импорта, а они записаны в файлах.
`main.go` импортирует `profile`. `card.go` импортирует `label`. `greeting.go` и
`label.go` не импортируют ничего. Импорт даёт имя только своему файлу: в
`main.go` нет строки импорта пакета `label`, поэтому нет и имени `label`, и
вызвать оттуда `label.Label` нельзя. Результат `Label` попадает в `main` только
через `Card`.

Вот весь путь вызовов, который дал вывод примера:

1. `main` вызывает `profile.Card("Иван", "гофер")`. Вызов квалифицирован:
   `Card` объявлена в другом пакете. Параметр `name` получает `"Иван"`,
   параметр `role` — `"гофер"`.
2. В теле `Card` стоит вызов `Greeting(name)`, без квалификатора: `Greeting`
   лежит в соседнем файле того же пакета. Функция возвращает приветствие для
   имени Иван.
3. Там же стоит вызов `label.Label(role)`, с квалификатором: `Label` лежит в
   подпакете `label`, который импортирует `card.go`. Функция возвращает роль
   `гофер` в квадратных скобках.
4. `Card` склеивает приветствие, литерал `" "` с одним пробелом и роль в
   скобках. Получившуюся строку `return` отдаёт в `main`.
5. `main` передаёт строку в `fmt.Println`, и только здесь она печатается. Ни
   `Card`, ни `Greeting`, ни `Label` ничего не печатают.

Почему `go.mod` на всё дерево один? По правилу урока 1.4 пакет принадлежит
модулю ближайшего `go.mod`, если идти вверх от каталога пакета. Ни в
`02-profile`, ни в `profile`, ни в `label` своего `go.mod` нет. Для всех трёх
каталогов ближайший — `examples/go.mod`. Поэтому три пакета входят в один
модуль `lesson/code-layout/examples`, и их пути импорта начинаются с одного
пути модуля. Пакеты размещаются внутри области модуля, и новый пакет в
подкаталоге не требует нового `go.mod`. Общее начало путей при этом не
сливает пакеты: граница пакета действует и внутри одного модуля. Где
относительно модуля лежит git-репозиторий, разбирает урок 1.11.

## Вопрос 1

В каталоге лежат `main.go` и `greeting.go`, оба начинаются с `package main`.
Что нужно написать в `main.go`, чтобы позвать функцию `greeting` из
`greeting.go`?

Варианты ответа:

- A. Строку `import "greeting.go"`: функция объявлена в другом файле, и этот
  файл нужно подключить к `main.go`.
- B. Строку импорта с полным путём модуля и именем файла в конце: так команда
  `go` найдёт файл внутри модуля.
- C. Ничего, кроме самого вызова `greeting("Иван")`: файлы одного пакета видят
  объявления друг друга без импорта.
- D. Вызов `greeting.greeting("Иван")`: перед точкой нужно указать файл, в
  котором объявлена функция.

Прежде чем смотреть ответ, объясните, что объединяет `main.go` и `greeting.go`
и что называет путь импорта.

**Правильный ответ: C.**

Оба файла лежат в одном каталоге и объявляют пакет `main`, поэтому это один
пакет, и имя `greeting` доступно в `main.go` без импорта и без квалификатора.
Вариант A делает единицей импорта файл, но путь импорта называет пакет, и такая
строка не собирается, как в примере `_broken/import-file`. Вариант B тоже
вписывает файл в путь, а путь импорта кончается каталогом пакета, и функции
своего пакета импорт вообще не нужен. Вариант D ставит перед точкой имя файла,
хотя квалификатор — имя другого пакета, а функцию своего пакета вызывают без
него.

## Вопрос 2

Сколько пакетов в каталоге из двух файлов `main.go` и `greeting.go`, если оба
начинаются с `package main`?

Варианты ответа:

- A. Два пакета: каждый файл `.go` образует свой пакет.
- B. Один пакет `main`: пакет задаёт строка `package`, а обе строки называют
  одно имя.
- C. Два пакета, `main` и `greeting`: имя второго пакета берётся из имени файла.
- D. Смотря как запустить: пакетом станет тот файл, который `go run` возьмёт
  первым.

Прежде чем смотреть ответ, назовите строку файла, по которой вы определили
пакет, и скажите, что меняет имя файла.

**Правильный ответ: B.**

Обычные файлы `.go` одного каталога с одинаковой строкой `package` команда `go`
собирает в один пакет, сколько бы файлов ни было. Вариант A считает пакеты по
файлам, хотя пакет определяет строка `package`, а не число файлов. Вариант C
выводит пакет из имени файла, но имя файла пакет не задаёт: `greeting.go` —
просто файл пакета `main`. Вариант D ищет «первый» файл, а `go run .` получает
каталог и собирает все его обычные файлы `.go` вместе.

## Вопрос 3

Модуль `lesson/code-layout/examples`; в каталоге `02-profile` лежит `main.go`,
а в подкаталоге `02-profile/profile` — файлы с `package profile`. Каталог

- D. `import "lesson/code-layout/examples/02-profile/profile"`: путь модуля и

**Правильный ответ: D.**

Полный путь импорта — путь модуля плюс путь каталога пакета от корня модуля,

`lesson/code-layout/examples`.

## Вопрос 5

Пакет `label` лежит в подкаталоге вашего же модуля, и `card.go` импортирует

**Правильный ответ: B.**

Подкаталог — другой пакет, поэтому `card.go` пишет `label.Label(role)`, а

файл того же пакета `profile`. Вариант A путает границы: модуль — область
`go.mod`, а пакет — область имён, и один модуль их не сливает. Вариант C
приписывает заглавной букве лишнее: она делает имя доступным из другого пакета,
но не убирает имя пакета перед точкой. С импортом из варианта D программа не
соберётся вовсе: на относительном пути команда `go` отказывает, как в примере
`_broken/relative-import`.
